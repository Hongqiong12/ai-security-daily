# "保真"应当是硬约束，"让被测方失败"才是优化目标 —— 这个位次不能反

## 一、背景与问题

### 动机

多轮 agent 的评测依赖 **LLM 模拟用户**。但被训成助手的 LLM **过度配合、多样性低**，于是评测系统性**高估**了 agent 的鲁棒性——测出来的和上线后的表现有明显落差。

已有两条修补路线：

1. **在用户话语上微调**（Naous et al., 2025）——确实能让测得的 agent 性能显著下降；
2. **手工设计非协作行为**（Shim et al., 2026）——也能打出性能缺口。

但两者的共同问题是：**策略是预先定义、高度工程化的**，因此**覆盖不到用户行为空间的其余部分**，给出的仍然是**乐观估计**。

### 核心科学问题

**能不能自动搜出"难缠但合法"的用户行为，同时保证用户的目标没被改掉？**

作者把这条界线划得很清楚，而且这条界线正是全文的方法论核心：

> 我们要建模的是**一个可能很难打交道、但不是恶意、也不在做越狱**的真实用户。

这个区分很重要：**对抗 ≠ 恶意**。前者是"在合法范围内把边界推到最紧"，后者是"越出合法范围"。

### 为什么这篇对我们要紧

我们的工作里有一个**结构完全同构**的问题：**`reject_tag` 样本的多样化改写**——要求"保持风险标签不变，同时提升表达多样性"。

这是一个**约束优化**问题：

- **约束**：风险标签不变（等价于本文的"目标保持 / goal preservation"）
- **目标**：让下游模型失败，或至少让样本分布更宽（等价于本文的"降低 task success"）

而我们的实际做法通常是**反过来**的：先想"怎么改写得更安全/更标准"，再看"顺带保住标签没有"。**位次反了**。

本文给出的范式是：**保真是硬约束（进罚项），失败是优化目标（进主项）**。落到公式上就是

$$R_{\text{adv}}(\tau,x,\pi) = -\frac{1}{m}\sum_{j=1}^{m}S_j(\tau,x)\;-\;\beta\big(1-C(\tau,x,U_\pi)\big),\quad \beta>0$$

主项是"完成度越低分越高"，罚项是"不合法就扣分"。**这一行就是整篇论文的方法论。**

## 二、核心方法

### （0）问题形式化

任务实例 $x=(g, s_0, V)$：$g$ 是用户目标描述，$s_0$ 是初始环境状态，$V$ 是结果校验器。被测 agent $\mathcal{A}$ 与模拟器 $U$ 在环境 $E$ 中交互，一条 rollout $\tau$ 产出完整轨迹（用户轮、agent 消息、工具调用、工具观测、中间状态、终态）。主任务完成分由终态的确定性函数 $V$ 算出。

**优化的变量只有一个：对抗规划器的指令 $\pi$。** 被测 agent、环境、模拟器架构、rollout 预算全部固定。

### （1）三层模拟器架构

**① 目标状态追踪器（goal-state tracker）**

把用户目标 $g$ 分解成有限个子目标 $G(g)=\{\gamma_1,\dots,\gamma_m\}$，每轮给每个子目标打一个状态：

$$q_{t,i}\in Q=\{\text{NOT\_ATTEMPTED},\ \text{IN\_PROGRESS},\ \text{COMPLETED},\ \text{FAILED},\ \text{USER\_ERROR}\}$$

得到目标状态账本 $r_t=\mathcal{T}_\theta(h_t,G(g))=\{(\gamma_i,q_{t,i})\}_{i=1}^m$。

注意 `USER_ERROR` 是**独立的一档**——用户自己犯错和 agent 失败被显式分开了。这一档是"保真"能够被度量的前提。

**② 对抗轮次规划器（adversarial turn planner）** ← 唯一被优化的部件

给定 $r_t$、对话历史 $h_t$、规划指令 $\pi$，采样轮级意图：

$$z_t\sim P_\theta(z_t\mid h_t,r_t,\pi)$$

$z_t$ 指定这一轮用户该做什么：提供哪些内容、索要哪些信息、用什么人设和语气、**注入什么用户侧错误**、以及是否终止对话。

**③ 对话生成器**

把计划verbalize成自然话语：$u_t\sim\mathcal{D}_\theta(u_t\mid z_t)$。

关键设计：**给定轮级计划后，话语与完整历史条件独立**。⇒ 有状态推理全在规划器，生成器只负责表面自然度。这是一次干净的职责分离，也是"改规划而不改话术"能生效的原因。

### （2）有效性判据（validity）：两分量

这是全文第二个关键设计。**把"agent 失败"和"用户轨迹无效"分开，是这个优化问题能不能成立的核心难点**——否则优化器会学会用无效对话刷低分。

有效性拆成两块：

1. **目标信息覆盖（goal-information coverage）**：对每个任务实例可以构造必传信息项集合 $I(g)$，agent 要成功就必须被告知这些；轨迹必须真的把这些传过去；
2. **行为有效性（behavioural validity）**：用户行为要在"真实用户会做"的范围内（不是恶意、不是越狱）。

合成一个指示函数 $C(\tau,x,U_\pi)\in\{0,1\}$，进罚项。

### （3）遗传 prompt 优化

对**每个任务实例独立**优化（per-example，不是学一个全局 prompt）：

$$\pi^\star_x\in\arg\max_{\pi\in\Pi}\ \mathbb{E}_{\tau\sim P(\cdot\mid x,\mathcal{A},E,U^\pi)}\big[R_{\text{adv}}(\tau,x,\pi)\big]$$

候选规划器 prompt 用**遗传循环**演化：LLM 生成的 mutation / crossover 算子 + 基于适应度的选择。适应度信号来自三处：

- rollout 轨迹（trace）
- **粒度化的任务完成信号**（不只是终态 0/1，而是每个子任务 $S_j$ 的 0/1）
- 有效性反馈

作者明确说这是"worst-case 交互搜索"而不是"学一个通用用户 prompt"。**这个定位很重要**——它意味着结果依赖预算，不能当成 agent 的绝对能力值。

## 三、技术细节

### 目标函数里的粒度化设计

除终态成功 $S(\tau,x)$ 外，任务还可暴露**中间完成分**：

$$s(\tau,x)=\big(S_1(\tau,x),\dots,S_m(\tau,x)\big),\quad S_j\in\{0,1\}$$

$S_j$ 衡量 agent 是否完成了第 $j$ 个必需子任务。用处：agent 部分完成时（满足了部分约束、走完一步预订、补回一个必填字段但最终没过校验器），**仍有梯度信号**。

⇒ 这是把"稀疏 0/1 终局奖励"变成"稠密子任务奖励"的标准做法，也是我们在 RL 改写里可以借的：**不要只用"最终一致性分数"，要有中间层信号**。

### 实验规模

- 数据集：**MultiWOZ** + **τ-bench 的 retail 与 airline 两个域**
- 每基准 **50 个任务**，每任务 $n=5$ trials，$k=4$（算 pass^4）
- 被测 agent：**三个前沿模型**（gpt-5.4-nano / kimi-k2.6 / gemini-3.8-flash）
- 对比：标准模拟器 + **四种手工非协作行为**（emotional / fragment / tangential / unavailable，来自 Shim et al. 2026）
- **优化预算：每任务 20 条 rollout**
- **不训任何模型**，纯 prompt 优化

## 四、实验与结果

### 主结果（节选，pass^4 越低说明越难/暴露越多缺口）

**τ-bench retail**

| 用户模拟器 | gpt-5.4-nano pass^4 | kimi-k2.6 | gemini-3.8-flash | IGA |
|---|---|---|---|---|
| standard | 0.076 | 0.320 | 0.320 | 0.860 / 0.900 / 0.960 |
| NC emotional | 0.064 | 0.168 | 0.392 | 0.460 / 0.940 / 0.920 |
| NC fragment | 0.052 | 0.168 | 0.572 | 0.640 / 0.740 / 0.856 |
| NC tangential | 0.120 | 0.180 | 0.620 | 0.500 / 0.600 / 0.780 |
| NC unavailable | 0.044 | 0.200 | 0.544 | 0.640 / 0.960 / 0.800 |
| **StressSim（本文）** | **0.000** | **0.000** | **0.100** | **0.900 / 0.920 / 1.000** |

**MultiWOZ**（节选，gemini 列最能说明问题）

| 模拟器 | pass@1 | pass@4 | pass^4 | IGA |
|---|---|---|---|---|
| standard | 0.940 | 0.944 | 0.940 | 0.920 |
| NC unavailable | 0.652 | 0.960 | 0.160 | 0.980 |
| **StressSim** | 0.856 | 0.980 | **0.620** | **1.000** |

### 三条要一起读的结论

**结论一：把评测压到地板，而"保真"几乎不掉。**

- τ-bench 上 pass^4 最多降 **69%**（gemini-3.8-flash）、**62%**（gpt-5.6-sol）
- MultiWOZ 上 gemini pass^4 从 0.944 → 0.620（−34%）
- 而 **IGA（首次尝试被判有效的比例）保持在 0.900–1.000**，作者说目标保持性能"最多掉 10%"

⇒ **约束和目标被同时满足了。** 这不是"用更毒的 prompt 换更低的分数"，而是"在合法范围内找到最难的那条路"。

**结论二：手工策略在不同模型上方向不一致，自动搜索不会。**

看 τ-bench retail 的 gemini 列：`NC fragment` 把 pass^4 拉高到 0.572、`NC tangential` 拉到 0.620——**比 standard（0.320）还高**。也就是说**手工设计的非协作行为在某些模型上反而让 agent 表现更好**（可能是触发了更谨慎的策略）。

而 StressSim 在三个模型上**方向一致**（0.000 / 0.000 / 0.100）。

⇒ **"手工构造困难样本"这件事在跨模型时不可迁移；按实例搜索可以。**

**结论三：预算是连续旋钮，不是固定参数。**

敏感性分析：**预算继续加，task success 继续掉**。⇒ 对抗强度是**可调的**，任何"我们测出 robustness = X"的结论都必须附带**预算**才成立。

这一条对我们是硬约束：**我们的 badcase 生成/改写强度也必须报预算**，否则不同轮次的数字不可比。

## 五、局限性

1. **任务型对话，不是内容安全**。目标是 task success（能否完成预订/退款），不是"是否违反内容政策"。**迁移的是框架，不是指标。**
2. **每实例独立优化 ⇒ 成本线性于实例数**。50 任务 × 20 rollouts = 1,000 次 rollout。放到我们 7W 样本上不可能全量做，只能做**子集搜索 + 模板复用**——但"模板能否迁移到新实例"这篇没验证（它是 per-example 的）。
3. **有效性判据靠人工构造**：$I(g)$ 必传信息项集合是任务特定的，每个新域都要重建。我们的等价物是"风险标签不变"，这个判据本身也需要构造（且比 $I(g)$ 更难，因为它是**语义**判据不是信息项清单）。
4. **只报 IGA（首次有效比例），没报"有效轨迹里的语义漂移程度"**。一个轨迹可以"信息项都传了"但仍然把用户目标谈歪了。**IGA 是粗粒度闸门，不是保真度量。**
5. **（补充）被测 agent 是黑盒调用**，没有机制层面的诊断。它告诉你"这里会崩"，不告诉你"为什么崩"。
6. **（补充）三个被测模型里两个是 nano/flash 级**。前沿大模型的绝对缺口可能小得多，跨规模的可比性未验证。

## 六、复现指南

### 迁移的核心：把"目标保持"换成"标签保持"，把"降低 task success"换成"提升表达多样性/降低模型置信度"

| 论文概念 | 我们的等价物 |
|---|---|
| 用户目标 $g$ | 原样本的风险标签 + 意图描述 |
| 子目标 $\{\gamma_i\}$ | 标签的构成要件（如 PORN 需同时具备"裸露/性行为"+"可见性"；VULG 需具备"侮辱指向"+"攻击性表达"） |
| 目标信息覆盖 $I(g)$ | **要件保持检查**：改写后每一要件是否仍可读出 |
| 行为有效性 | 仍是"真实用户会说的话"（不引入新风险类目、不变成另一类违规） |
| $S_j$ 子任务完成分 | 下游分类器对**原始标签**的置信度（越高说明越"好识别"= 我们的目标应让它**适度下降但不能翻类**） |
| $R_{\text{adv}}$ | $-\text{condfidence}_{\text{orig}} - \beta\cdot(1-\text{label\_preserved})$ |
| 规划器 $\pi$ | **改写策略指令**（改这个，不改样本本身） |
| rollout 预算 | 每条样本的改写尝试次数 |

### 最小实施（一条脚本，零训练）

**Step 1｜把标签拆成要件**

对每个易混类目写 2–4 个要件。例：
- `PORN` = {① 性暴露/性行为描述 ② 指向可见主体 ③ 非医学/教育语境}
- `VULG` = {① 侮辱性称谓或攻击性表达 ② 有明确指向对象}
- `VULG-HINT-EDGE` = ① + ② 都满足，但 ① **只以暗示形式出现**

**这一步做不好，后面全部失效**——因为"标签不变"必须落到可检验的要件上，不能停在"读起来还是那个意思"。

**Step 2｜构造罚项**

改写 $y$ 的有效性：
$$C(y)=\mathbb{1}\big[\text{所有要件在 } y \text{ 中仍可读出}\big]\wedge\mathbb{1}\big[\text{未引入新风险类目}\big]$$

第二个条件必须显式检查（用一个独立的分类器扫 $y$ 是否命中其他类），否则优化器会把 PORN 样本改写成 VULG 样本——**标签"没变"是因为它换了个类**。

**Step 3｜遗传循环（每实例 20 次尝试）**

- 初始种群：4–6 条改写指令变体（不同的人称、不同的多样性引导、不同的"软化/暗示"强度）；
- 适应度：$-\text{condfidence}_{\text{orig}}(y) - \beta(1-C(y))$，$\beta$ 取 2–3；
- 每轮：取 top-2，让 LLM 做 mutation（换一个改写策略维度）+ crossover（合并两条指令）；
- 保留**最优且 $C(y)=1$** 的那条输出。

**Step 4｜报三个数，缺一不可**

| 指标 | 含义 | 判据 |
|---|---|---|
| **要件保持率**（IGA 的等价物） | $C(y)=1$ 的比例 | 应 **≥90%**；低于此说明约束太紧或要件写错 |
| **原标签置信度下降** | 模型对原标签的平均置信度变化 | 下降说明改写真的"变难"了，不是只换了词 |
| **跨类翻车率** | 改写后模型判成**另一个违规类**的比例 | **必须单列**。这个数高说明我们在制造跨类噪声，不是在造 hard negative |

**Step 5｜预算敏感性（必须做，20 分钟）**

同一条样本跑 5 / 10 / 20 次尝试，画"尝试次数 vs 原标签置信度"曲线。**结论必须附预算**，否则不可比。

### 一个反直觉但重要的操作建议

**不要**先"想一个更自然的改写"再看标签有没有变。要**先把要件写成可判定的谓词，再让优化器去找"满足谓词但最难判"的表达**。

这就是本文最核心的那个位次：**保真是罚项（硬），变难是主项（软）**。反过来做，优化器会心安理得地牺牲保真，因为主项一直有收益。
