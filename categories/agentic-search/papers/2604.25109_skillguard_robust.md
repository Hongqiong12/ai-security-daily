## 一、背景与问题

### 动机

Skill 生态的真正风险不在“某一行 prompt 有没有恶意”，而在于一个 skill package 往往是**多文件、跨角色、跨引用的攻击载体**。如果审计只看 `SKILL.md` 或者把整个包压平成一段长文本，最容易漏掉的恰恰是跨文件攻击链：
- 高优先级 override 指令藏在 reference 文档里；
- 外传行为伪装成备份、同步、handoff；
- 远程 helper / installer 伪装成正常 bootstrap。

### 核心科学问题

能否把 skill 预加载审计从“长文本判别”升级为真正的**package-level security auditing**：先恢复文件结构与角色，再做链级风险判断，并在语义等价改写下保持稳定？

### 直觉洞见

这篇论文真正抓住的问题是：skill 安全不是 prompt 安全的加长版，而是**包级结构安全**。如果你不先把文件之间的角色和主导关系恢复出来，后面的 LLM judge 再强也容易把 malicious 压成 suspicious。

## 二、核心方法

作者提出 **SkillGuard-Robust**，是一条四阶段审计链，而不是一个“把所有文件塞给大模型问一句是不是恶意”的黑盒分类器。

### （1）Stage I：Structured Evidence Extraction

按文件角色（skill-md / script / reference / repo-context）抽取结构化风险证据，如：
- override
- concealment
- external transfer
- tool execution
- remote bootstrap

然后用角色感知的 noisy-or 聚合成包级风险底座。

### （2）Stage II：Selective Semantic Verification

不是所有包都调用强 verifier，只在**不确定样本**上触发语义验证：
- 风险分数落在边界区间；
- 或 bootstrap / tool 信号强，但 override / transfer 证据不足。

### （3）Stage III：Conflict-Aware Chain Arbitration

把结构化证据与语义验证结果融合成链级风险，并显式区分：
- transfer 主导 → 更可能是 malicious
- bootstrap 主导 → 更可能是 suspicious

### （4）Stage IV：Anchor-Consistency Consolidation

利用 anchor–rewrite 关系修复标签不一致：
- 如果 anchor 仍被压成 suspicious；
- 但多个语义等价 rewrite 已稳定判成 malicious；
- 且 cluster 中无 benign，置信度足够高；
- 则把 anchor 一并提升到 malicious。

这一步是整篇论文最重要的“防漂移”设计。

## 三、技术细节

### SkillGuardBench 关注的三类攻击链

1. **Hidden override**：把高优先级指令藏在附属文档或次级说明中  
2. **Disguised transfer**：把外传伪装成同步、归档、交接  
3. **Remote bootstrap**：把远程依赖、脚本、存储桶、relay 伪装成初始化依赖

### 三分类决策

- **benign**：可自动加载
- **suspicious**：应阻止自动加载，交人工审核
- **malicious**：存在明确攻击意图或决定性跨文件攻击链

### 关键固定参数

正文给出的固定设置：
- semantic-chain yes threshold = **0.60**
- minimum package-floor confidence = **0.70**
- anchor consolidation 至少需要 **2 个 malicious rewrites**

### 工程特征

- 只有 **semantic verification** 需要额外远程成本
- 结构提取、链级仲裁、一致性修复都可本地执行
- 重点不是把每个包都“看得更深”，而是**只把成本花在真正不确定的地方**

- 总样本：**581** 个 package-level 样本

样本类型：
- clean：**253**

五个主视角：
- Main：**401**
- All-HO：**404**
- Int.-stress：**344**
- Boundary：**284**
- Ext.-eco：**254**

### baseline

论文重点比较：
- PEB
- Granite Guardian
- Llama Guard 3 / 4
- Prompt Guard
- Qwen2.5-7B / 14B
- BundleJudge

其中主文最常拿来对比的是：
- **Qwen2.5-14B (full-package)**

### 主要结果 1：只看 SKILL.md 明显不够

以 Qwen2.5-14B 为例：
- **skill-md-only → full-package**
  - Overall Exact：**63.95 → 78.91**
  - Risk Exact：**5.88 → 52.94**
  - Rewrite Exact：**9.76 → 43.90**

以 PEB 为例：
- Overall Exact：**61.90 → 80.27**
- Risk Exact：**17.65 → 76.47**
- Attack Exact：**12.20 → 68.29**
- Risk Malicious Recall：**0 → 66.67**

这组结果直接证明：**skill 审计必须看完整 package，不能把它当 prompt 审计。**

### 主要结果 2：SkillGuard-Robust 在 held-out 与生态外迁移上都明显领先

- **SkillGuard-Robust**
  - Overall Exact：**97.30**
  - Risk Exact：**93.28**

#### Ext.-eco（254）

  - Overall Exact：**89.28**

  - Overall Exact：**93.72**

### 主要结果 3：最核心误差不是“没挡住风险”，而是“把 malicious 压成 suspicious”

作者定义 **collapse gap = Flagged Accuracy − Risk Malicious Recall**。  
以 Qwen2.5-14B(full-package) 为例：
- Main：**11.40**
- All-HO：**37.35**
- Int.-stress：**32.74**
- Boundary：**20.83**
- Ext.-eco：**15.00**

而 SkillGuard-Robust：
- Main：**0.00**
- All-HO：**1.18**
- Int.-stress：**0.00**
- Boundary：**0.00**
- Ext.-eco：**0.00**

这组数字是全文最关键的证据。很多强 baseline 已经会“挡住风险包”，但仍然会把真正 malicious 压缩成 suspicious，导致审计结论不够硬。SkillGuard-Robust 基本解决了这个塌缩问题。

## 五、局限性分析

1. **风险样本仍有相当一部分来自 sanitized reconstruction**，更适合比较方法优劣，不适合估计现实生态中的真实恶意比例。  
2. **benchmark 与方法共同演化风险仍在**：部分 batch 带有早期开发/诊断关联。  
3. **suspicious 与 malicious 的边界带有部署语境相关性**：不同组织的容忍策略不同。  
4. **仍依赖强 verifier**：更大规模开放生态迁移下，外部 verifier 的稳定性仍是瓶颈。  

我的判断是，这篇论文最大的价值不只是做了个新框架，而是把 skill 审计的错误来源拆得足够细：**结构丢失、局部语义不确定、链级冲突、anchor–rewrite 漂移**。这比“再加一个更大 judge”更有工程意义。

## 六、复现指南

### 最小复现路径

1. 构造 package-level benchmark，而不是单文件 benchmark。  
2. 先做文件角色划分与结构化风险特征抽取。  
3. 对边界样本触发 selective semantic verification。  
4. 做链级仲裁，并实现 anchor–rewrite consistency 修复。  
5. 评估：
   - Overall Exact Accuracy
   - Risk Exact Accuracy
   - Risk Malicious Recall
   - Rewrite Exact Accuracy
   - Attack Exact Consistency

### 最值得复现的部分

如果只挑一件事，我建议复现：
- **collapse gap** 的对比

因为它最能体现本文真正解决了什么：
- 不是简单把包“多挡一点”；
- 而是把**malicious 判对**这件事真正拉起来。

### 对 Agentic 安全的启示

这篇论文值得回填到 benchmark 索引，不只是因为它做了 SkillGuardBench，而是因为它明确把 skill 审计推向了一个新抽象层：
- **skill security = package structure + chain semantics + rewrite robustness**

这比传统 prompt injection 审计明显更贴近现实 MCP / skill 生态。
