## 一、背景与问题

### 动机

网页 agent 的 prompt injection 研究过去大多默认模型能看见 HTML、DOM 或抽取后的纯文本。但真实世界里越来越多 browser / computer-use agent 直接看**网页截图**。这带来一个结构性变化：
- 攻击不再只是文本层面的；
- 防守也不能再只靠 DOM/HTML 规则；
- 而直接上大 VLM 做整页理解，延迟和显存开销又太重。

### 核心科学问题

能否只基于网页截图，在不改 agent 内部策略、不访问 DOM/HTML、不额外吃 GPU 显存的前提下，做一个**足够轻量、足够快、还足够有效**的 prompt injection 检测器？

### 直觉洞见

作者抓住了一个很实用的观察：被注入的网页截图往往同时留下两类痕迹：
- **视觉痕迹**：结构更平滑、局部异常更弱纹理；
- **文本痕迹**：带有动作导向的控制语句、凭证请求或跳转诱导。

也就是说，这里不一定需要“大模型理解整页语义”，而可以先做一层更便宜的风险筛查。

---

## 二、核心方法

### （1）VSI：Visual Stability Indicator

先从截图本身抓低层视觉异常。作者认为恶意网页内容会让局部结构分布变得异常平滑，因此用梯度方差来估计页面的“视觉异质性”。

### （2）CPR + OCR：把隐藏文本重新挖出来

很多攻击文本藏在近白背景、低对比区域里，原图 OCR 直接漏掉。作者先做 **Contrast-Polarity Reversal (CPR)**，对接近白色区域做选择性反色，再分别对：
- 原图
- 反转图
做 OCR，合并两路文本。

### （3）APD：Action-Oriented Pattern Detection

对 OCR 文本不做重型语义推理，而是直接找动作导向模式，例如：
- interaction triggers
- credential requests
- link invitations
- 覆盖用户原任务的控制语句

### （4）总体定位

SnapGuard 不是端到端替代 agent，而是一个 **pre-action guardrail**：在 agent 真正点击/执行之前，先判这张截图是否高风险。

## 三、技术细节

### VSI 公式

给定截图 x，先转灰度并计算每个像素的空间梯度 ∇x_(i,j)。  
视觉稳定性指标定义为：

ϕ(x) = E[||∇x_(i,j)||²] − (E[||∇x_(i,j)||])²

含义：
- ϕ(x) 越大 → 页面局部结构更丰富，偏正常
- ϕ(x) 越小 → 页面更平滑，偏可疑

阈值从 benign 集上估计，固定：
- **α = 0.05**
- **VSI threshold = 4450**

### CPR 设置

- 灰度阈值：**γ = 240**
- 对近白区域反色后再 OCR
- 文本融合：
  - T(x) = OCR(原图) ∪ OCR(反转图)

### 模块级耗时

| 模块 | 平均时间 |
|------|---------:|
| VSI | 0.021s |
| CPR + OCR | 1.788s |
| APD | 0.001s |
| 总计 | **1.810s** |

这说明：**真正的瓶颈几乎全在 OCR，检测逻辑本身非常轻。**

### 复杂度与部署特征

- VSI：O(HW)
- 无需训练大型视觉模型
- **0 额外 GPU 显存开销**
- 不依赖 DOM/HTML
- 不改 agent 内部状态

## 四、实验设置与结果

### 数据与 benchmark

对齐 **WAInjectBench**：
- benign：**948**
- malicious：**2185**
- 覆盖 **8 种攻击**：
  - EIA
  - WebInject
  - Pop-up
  - WASP
  - VWA-emb
  - VWA-shot
  - VPI-BU
  - VPI-CU

训练型 baseline 额外使用：
- **1000 benign**（COCO 2017 val）
- **1000 malicious**（JailGuard 数据）

### baseline

图像侧：
- Embedding-I
- JailGuard
- LLaVA-1.5-7B
- LLaVA-1.5-7B-FT
- GPT-4o-prompt

文本侧：
- Embedding-T
- KAD
- PromptGuard
- DataSentinel
- PromptArmor

### 主结果

| 方法 | Avg FPR ↓ | Avg TPR ↑ | F1 ↑ | Time(s) | Memory(MB) |
|------|----------:|----------:|-----:|--------:|-----------:|
| Embedding-I | 0.25 | 0.44 | 0.52 | 0.04 | 591 |
| JailGuard | 0.28 | 0.08 | 0.12 | 6.12 | 13840 |
| LLaVA-1.5-7B | 0.00 | 0.00 | 0.00 | 0.19 | 13875 |
| LLaVA-1.5-7B-FT | 0.04 | 0.13 | 0.23 | 0.18 | 13594 |
| GPT-4o-prompt | 0.00 | 0.55 | 0.71 | 14.50 | — |
| **SnapGuard** | **0.09** | **0.66** | **0.75** | **1.81** | **0** |

### 关键解读

- **效果**：F1 **0.75**，优于 GPT-4o-prompt 的 **0.71**
- **速度**：**1.81s vs 14.50s**，大约 **8× 更快**
- **显存**：**0 额外 GPU 开销**

这篇论文的亮点不是“绝对最强”，而是**性价比极高**。

### 按攻击类型的 TPR（SnapGuard）

- EIA：**0.80**
- WebInject：**0.53**
- Pop-up：**0.70**
- WASP：**0.71**
- VWA-emb：**0.75**
- VWA-shot：**0.13**
- VPI-BU：**0.82**
- VPI-CU：**0.81**

说明它对多数攻击有效，但对 **VWA-shot** 这类场景明显更难。

### 消融实验

| 变体 | Avg TPR ↑ | Avg FPR ↓ | F1 ↑ |
|------|----------:|----------:|-----:|
| Full | **0.66** | **0.09** | **0.75** |
| w/o VSI | 0.49 | 0.05 | 0.56 |
| w/o CPR | 0.57 | 0.08 | 0.64 |
| w/o APD | 0.37 | 0.18 | 0.56 |

最关键的结论：**APD 是最不能删的模块**，但 VSI 和 CPR 也都提供了显著增益。

## 五、局限性分析

1. **当前只是 detector，不是完整闭环防御**：作者自己也说未来要和 action filtering / risk-aware decision making 联动。  
2. **主要针对单帧截图**：对动态网页、多步交互时序的建模还不够。  
3. **OCR 是主要瓶颈**：总耗时里 **98.8%** 在 CPR + OCR。  
4. **APD 含规则工程成分**：面对新表达方式，需要持续扩展 pattern 库。  
5. **并非所有攻击都覆盖得同样好**：如 VWA-shot 的 TPR 只有 **0.13**。  

我的判断是，这篇论文很适合放进 Agentic survey 里作为“工程可部署 guardrail”代表，因为它证明：**截图场景并不一定只能靠更大更慢的 VLM 守。**

## 六、复现指南

### 最小复现路径

1. 获取 WAInjectBench 风格数据。  
2. 实现三模块 pipeline：
   - VSI
   - CPR + OCR
   - APD
3. 固定：
   - α = 0.05
   - threshold = 4450
   - γ = 240
4. 评估 F1 / TPR / FPR / latency / memory。  
5. 复现实验时优先对比：
   - GPT-4o-prompt
   - PromptArmor
   - Embedding-I

### 为什么值得复现

如果只复现一个数字，我建议先验证：
- **SnapGuard F1 = 0.75**
- **GPT-4o-prompt F1 = 0.71**
- **1.81s vs 14.50s**

因为这组结果最能体现论文的真正贡献：**不是更聪明，而是更可部署。**
