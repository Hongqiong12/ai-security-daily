# 编辑会擦掉你嵌进去的东西——连"保真约束"都救不回来，去掉它反而更好

**论文主页**: https://arxiv.org/abs/2611.07632
**领域**: 指令式图像编辑中的用户归因水印 · 编辑感知训练 · 保真约束的副作用
**作者**: Xiaodong Wu, Xiangman Li, Jianbing Ni, Rongxing Lu
**机构**: 皇后大学（Queen's University, Kingston, Canada）
**发布日期**: 2026-11-05（v1，cs.CV）
**分类**: defense / i2i
**模态归属**: T+I2I 链路中的信息保持 · 编辑前后"看不见的差异"

---

## 一、背景与问题

### 动机

图像编辑服务记录"谁请求了这次编辑"，但**编辑后的图本身不含这个信息**。一旦被下载、分享、二次编辑，服务方就无法从图里认出请求者。

一个自然的做法是**事后加用户水印**——但从图里能认出用户，不代表关联关系能扛住**再编辑一次**。而抗压缩、抗缩放训练出来的水印，在生成式编辑器**重建图像内容**时会坏掉。

已有工作（VINE、Robust-Wide、SafeMark）走两条路：改进编辑下的消息恢复，或者训练编辑器主动保留已有水印。它们的训练目标是**消息恢复**，再把恢复出的消息匹配到用户。

本文的论点：**归因的最终目标不是恢复消息，是区分请求者**。这两件事不等价——因为"消息恢复率"是对单条消息的度量，而"归因"要的是**在竞争用户之间把分数拉开**。

### 为什么对我们是必读

因为它把 **"编辑前后"** 这件事做成了一门可测量的学问，并且给出了一个反直觉的结论：

> **把保真约束拿掉，归因反而更准。**

这条对我们直接相关：我们的改写器一直把"语义保真"当作硬约束。这篇说明，**保真约束与"保住信息"是竞争关系，不是互补关系**。

### 三条论断

1. **在编辑通路里训练（把编辑器放进梯度的回路）**能提升归因，收益 0.167–0.477。
2. 但**收益只在"被编辑之后"显现**——编辑前的准确率几乎不动（0.983 → 0.980）。
3. **约束项不是越多越好**：去掉一致性损失，三个域的归因准确率**全部上升**。

## 二、核心方法

### 2.1 架构：一个编码器 + 一个检测器 + 一个固定编辑器

```
原图 x ──[identifier encoder]──> 带水印图 x_w ──[固定权重编辑器 E]──> 编辑后图 E(x_w)
                                                                        │
                                                     [shared detector] ──┴──> 特征 f
                                                                                │
                                                        与用户参考向量 {u_i} 比对 ──> 用户 ID
```

关键设计：**编码器与检测器共享，编辑器参数冻结**。梯度穿过编辑器回传到编码器——所以编码器学到的是"**能穿过这个编辑器活下来的水印**"，而不是"能穿过 JPEG 活下来的水印"。

### 2.2 三组损失的分工

| 损失 | 约束什么 |
|---|---|
| $\mathcal{L}_{\text{out}}$ | **输出端归因**：编辑后还能不能认出用户（主目标） |
| $\mathcal{L}_{\text{cons}}$ | **一致性**：带水印图与其编辑输出的嵌入余弦对齐 |
| $\mathcal{L}_{\text{car}}$ | **载体失真**：水印残差的 $\ell_1$ 幅度（硬残差界） |
| $\mathcal{L}_{\text{sim}}$ | **编辑保真**：限制对输入图与原定编辑的改动 |

论文原文对 $\mathcal{L}_{\text{sim}}$ 的措辞值得抄下来："保真损失**限制对输入图像以及原定编辑的改动**。"

⇒ **这是一个双目标约束：既不许改动"不该动的"，也不许改掉"该动的"。** 这与我们改写器的"保真 vs 有效"张力结构完全相同。

### 2.3 每个域 × 每条指令一套模型

"每个图像域和每条编辑指令使用一个单独训练的模型，在注册用户之间共享。"

- 三个域：CelebA-HQ（人脸）、AFHQ-Dog（狗脸）、CUB-200-2011（鸟）
- 每个域 **30 条编辑特征**（如"改发色"、"加眼镜"、"变成猫"）
- 共 **90 个域-特征设置**，都通过 InstructPix2Pix 编辑

### 2.4 两种归因方法（用于分离"架构"与"训练"）

| 方法 | 做法 |
|---|---|
| **原型匹配** | 检测器输出嵌入，与 $N$ 个用户参考向量比最近邻 |
| **二值解码** | 100 bit 码字 + 最近码字解码（并列则记为错） |

存储/计算：原型库 + 用户嵌入表需 $O(N(d+d_u))$；一次检测后算全部用户 logit 需 $O(Nd)$。**其他网络参数与 $N$ 无关。**

## 三、技术细节

### 3.1 一个苛刻但公平的对照设计（2×2）

RQ2 要分离"训练穿没穿过编辑器"这个因素。做法：固定特征（CelebA-HQ 金发 / AFHQ 生气 / CUB 冠羽），四个变体**共享编码器与检测器骨干、训练数据、worker 数、随机种子、170 轮**，每轮图像配额相同。

- 有编辑器暴露：穿过 InstructPix2Pix 训练
- 无编辑器暴露：**关掉所有依赖编辑的损失**

每个条件用原型匹配或 100 bit 解码。

### 3.2 四条编辑通道（RQ1）

| 通道 | 性质 |
|---|---|
| InstructPix2Pix | **训练通道** |
| sd-turbo img2img，strength 0.2 | 未见过 |
| sd-turbo，strength 0.3（pix2pix 式配置） | 未见过 |
| ChordEdit | 未见过 |

### 3.3 载体分辨率是个隐形变量

主对比用 **256 像素载体**（TraceMark / TrustMark / RoSteALS 的原生分辨率）。VINE-R 与 Robust-Wide 的原生是 **512 像素**，所以论文做了一个四特征对照，把它们放回 512。

**这个对照的结果是全文最刺眼的一组数字**（见 §4.3）。

### 3.4 评测口径的诚实边界

论文自己写："这些比较使用**训练池**中的图像。**它们不测量对留出图像的泛化。**"

⇒ 这是一条硬限制：所有归因准确率都是**训练分布内**的。

## 四、实验与结果

### 4.1 与已发布水印比（Table II，256 px）

| 通道 | 结论 |
|---|---|
| sd-turbo | TraceMark 平均为最强基线的 **1.9×** |
| sd-turbo（p2p 式） | **4.2×** |
| ChordEdit | **5.0×** |
| **InstructPix2Pix（训练通道）** | **TraceMark 输**：RoSteALS 0.955–0.986 vs TraceMark 0.806–0.901 |

**最后一行的意义**：在"训练时见过的那条通道"上，一个**没穿过编辑器训练**的方法赢了。说明"编辑感知训练"的收益**不是全面提升，而是补上了未见过通道的塌陷**。

ChordEdit 上仍然很难：域均值只有 **0.230–0.427**。

### 4.2 训练穿过编辑器的净收益（RQ2，2×2 对照）

| 指标 | 值 |
|---|---|
| 六个组合（3 特征 × 2 归因方法）**全部提升** | 是 |
| 提升幅度 | **0.167 – 0.477** |
| 平均提升（原型匹配） | **0.339** |
| 平均提升（二值解码） | **0.219** |
| 归因方法之差（原型 − 二值） | 有编辑暴露 **+0.096** / 无编辑暴露 **−0.024** |

⇒ 归因方法的选择比"是否穿过编辑器训练"影响**小得多**。

### 4.3 分辨率对照：0.062 → 0.997

把 VINE-R 与 Robust-Wide 放回它们原生的 512 像素，在三条未见通道上：

| 方法 | 256 px（默认） | 512 px（原生） |
|---|---|---|
| VINE-R | 0.062 | **0.997** |
| Robust-Wide | 0.165 | **0.982** |

**同一个方法，加 14–16 倍。** 而 TrustMark 和 RoSteALS 在 512 下变化不大。

⇒ 论文的措辞很克制："这个对照**不测量 TraceMark 自己对分辨率变化的响应**，那需要重训。" 但结论已经足够硬：**跨方法比较若不把载体分辨率对齐，得到的排序是分辨率排序，不是方法排序。**

### 4.4 收益只在编辑之后显现

把同一批训练变体用在**未编辑的带水印输入**上：

| 归因方法 | 编辑前 | 编辑后（IP2P） |
|---|---|---|
| 原型（有 / 无编辑暴露） | 0.983 → **0.980** | 0.420 → **0.920** |
| 二值（有 / 无编辑暴露） | 0.983 → 0.877 | 0.410 → 0.757 |

**编辑前：0.983 对 0.980，差 0.003。编辑后：0.420 对 0.920，差 0.500。**

⇒ 这是本文对评测方法学最重要的一条：**"两个模型在原始分布上一样好"，完全不能推出"在变换后一样好"。** 如果我们的评测只在"改写前"或"改写前的 prompt 分布"上比较，会得出"两个改写器等效"的错误结论。

### 4.5 约束项消融：去掉一致性，反而更好（Table III）

| 域 | 完整 | $-\mathcal{L}_{\text{car}}$ | $-\mathcal{L}_{\text{cons}}$ | $-\mathcal{L}_{\text{out}}$ |
|---|---|---|---|---|
| CelebA-HQ | 0.927 | 0.944 | **0.963** | 0.743 |
| AFHQ-Dog | 0.854 | 0.850 | **0.885** | 0.593 |
| CUB-Bird | 0.818 | 0.839 | **0.905** | 0.613 |
| **均值** | **0.866** | 0.878 | **0.918** | 0.650 |

三件事同时成立：

1. **去掉 $\mathcal{L}_{\text{out}}$（主目标）→ 塌到 0.650。** 主目标是必需的。
2. **去掉 $\mathcal{L}_{\text{car}}$（载体失真）→ 0.878，略高于完整版。** 载体失真约束几乎没用，甚至轻微有害。
3. **去掉 $\mathcal{L}_{\text{cons}}$（一致性）→ 0.918，比完整版高 5.2 点，三个域全部上升。**

而论文的配套测量解释了机制：去掉 $\mathcal{L}_{\text{cons}}$ 使**嵌入余弦对齐下降 0.009–0.026**，但**识别准确率上升**。

⇒ **"对齐得更好"和"分得更开"是两件事。** 余弦相似度是一个绝对量，而归因是一个**相对量**（要在竞争用户之间拉开 margin）。把绝对量当优化目标，会牺牲相对量。

### 4.6 换指令（Table IV）

固定 InstructPix2Pix，只换评测时的指令（8 个已训模型 × 3 条同域指令，24 对，每对 200 张封面）：

| 量 | 值 |
|---|---|
| 带标记输出平均 | **0.635** |
| 范围 | **0.120 – 0.975** |
| 无标记输出平均 | **0.009** |

极差说明了问题：**"加眼镜"训练的模型在"变微笑"上能到 0.975，在"变动漫"上只有 0.680；"变微笑"训练的模型在梵高风格编辑上只有 0.120。**

论文自己说："这些结果**证明了某些请求可以复用**，但**没有建立对任意指令的可靠恢复**。"

### 4.7 同等编辑幅度，不同结果

在几乎相同的 latent 位移下：**IP2P 0.866 vs SDXL-Turbo 0.430**。

在 SDXL-Turbo 上，TraceMark 超过 RoSteALS（0.249），但**低于 VINE-R（0.922）与 Robust-Wide（0.648）**。

⇒ **"编辑强度"不是"编辑破坏性"的好代理。** 位移一样，破坏力差一倍。

## 五、局限性

### 5.1 论文自述

- **全部评测在训练池图像上，不测留出泛化。**
- **每个域 × 每条指令一套模型**（90 个），工程上不可扩展；换个分辨率要重训。
- 注册表扩容时要**重训可学习组件**。
- 只测到 **500 用户**。
- ChordEdit 上 0.230–0.427，**远未可用**。
- $\mathcal{L}_{\text{sim}}$ 保留，所以"编辑保真项对归因的贡献无法隔离"（论文明确指出这个消融做不到）。

### 5.2 本报告补充的三条

1. **"去掉一致性更好"这条不能直接搬到改写器上。** 他们的任务是"嵌入一个信号并保住它"，一致性约束的作用是"让嵌入在编辑前后不变"——但归因只需要"区分度"，不需要"不变"。**我们的改写器需要的是"意思不变"，那是语义层面的要求，与这个结论不同构**。可迁移的是**方法学**：任何"绝对相似度"指标都必须配一个"相对区分度"指标，否则会优化错方向。

2. **它的"用户归因"与我们的"改写溯源"是同一个问题的两个变体**。若未来我们需要"这条改写是谁请求的、改了哪一版"，这篇的架构（前缀嵌入 + 冻结变换 + 事后检测）是可用的模板。

3. **90 个模型这个设计是硬伤**。它使得"换指令泛化"只有 0.635，而工程上无法为每条指令训一个模型。**真正可用的方向是"一个模型 + 指令条件"，本文没做**。

## 六、复现指南

### 6.1 依赖与入口

- 需要可训练的编辑模型（InstructPix2Pix 级别即可，256 px）。
- 需要"用户注册表"概念——对我们不适用，但"版本指纹"可类比。

### 6.2 最小可迁移实验：改写器的"编辑前后"对照（1 天，零训练）

**这是本文对我们最直接的一条。**

现状：我们评估改写器，通常在**同一批 prompt 上**比较"改写前/改写后"的指标。

本文的教训：**"在原始分布上一样好"完全不能推出"在变换后一样好"**（0.983 vs 0.980 → 0.420 vs 0.920）。

做法：

1. 取两个改写器版本 A、B（或"有改写/无改写"）。
2. 在**原始 prompt 分布**上各跑一遍，报风险分数与语义保真 —— 预期两者接近。
3. 把两版输出**各自送进图生图编辑链路**，再测一次风险分数与指令遵循。
4. **报两个差值**：原始分布上的差 $\Delta_{\text{pre}}$、编辑链路后的差 $\Delta_{\text{post}}$。

**判据**：
- 若 $\Delta_{\text{pre}} < 0.05$ 而 $\Delta_{\text{post}} > 0.15$ ⇒ **我们现有 A/B 看板的结论建立在错误的分布上**，必须加"链路后"一列；
- 若 $\Delta_{\text{post}}$ 与 $\Delta_{\text{pre}}$ 同向同量 ⇒ 链路无放大，可以继续用原始分布评估（省钱）。

### 6.3 派生实验：绝对相似度 vs 相对区分度（半天）

本文的 $-\mathcal{L}_{\text{cons}}$ 消融（0.866→0.918，同时余弦对齐下降）说明：**优化绝对相似度会牺牲相对区分度**。

做法：我们的三维评测里，"语义保真"通常是一个**绝对相似度**（如 embedding cosine）。加一个**相对量**：

- 从评测集里构造"同义改写对"（应判为等价）与"近义但改了意图对"（应判为不等价）；
- 报两个分布的重叠度（AUC）。**这才是区分度。**

**判据**：若同义对与改意图对的 AUC < 0.7，说明"语义保真"这个绝对分数**没有区分能力**，不能用来做门控。

### 6.4 评测要点

- 跨方法比较**必须对齐分辨率/载体强度/编辑幅度**，否则比的是配置不是方法。
- 报"归因/识别准确率"时必须说明是**训练分布内**还是留出。
- 归因类指标必须报**竞争集大小**（本文：500 用户 87.5%；100 用户下另一套数）。
