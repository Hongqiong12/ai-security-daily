## 一、背景与问题

### 动机

很多 T2I prompt rewrite 的根本问题不是“不会写长句子”，而是**不会判断哪些细节一旦补进去，就会在视觉上偏离原意**。文本上看似合理的补全，到了图像空间里可能变成过度脑补、错误物理关系、错误遮挡、错误计数。

### 核心科学问题

能否把 prompt rewriting 从“纯文本润色”升级为“**借助视觉锚点验证的意图保留改写**”，先看模型会画成什么，再反过来修 prompt？

### 为什么这篇论文重要

如果说 PromptEnhancer 更像“reward-aware industrial rewriter”，FaithRewriter 则更像“**intent-preserving rewrite 的方法学底座**”。它直面了你现在最关心的问题：**怎么防止 rewrite 过度脑补，怎么让语义保真不只停留在文本相似度。**

---

## 二、核心方法

### （1）视觉失败外化

FaithRewriter 不直接改写，而是先做一轮故意偏详细的改写 T1，再用冻结的 T2I 模型生成图像 I1。这样原始 prompt 中潜在的“视觉误解”会被外化出来。

### （2）结构化诊断与修正

多模态模型再检查 I1 是否违背原始 prompt T0，重点诊断六类失败：
- 空间逻辑与遮挡
- 属性绑定
- 物理动力学
- 计数与几何
- 否定与缺失
- 隐性概念

在此基础上生成修正后的 T2，并要求同时满足：
- 修复已识别错误
- 保留原始意图

### （3）循环验证

对修正后的 T2 再次出图 I2，并做三项硬校验：
- 修复验证
- 意图保留
- 反向回归（不能引入新错）

只有三项都通过，样本才被留下。

### （4）偏好蒸馏

最终构造 `(T0, Twin, Tlose)`：
- `Twin = T2`：通过视觉验证的 winner
- `Tlose = T1`：文本流畅但视觉有问题的 hard negative

再用 DPO 把这种视觉判断蒸馏回文本 rewriter。

---

## 三、技术细节

### FaithRewriter 真正创新在哪里

它的关键创新不在“用了 MLLM”，而在于它把 prompt rewrite 训练流程重写成：

```text
原始 prompt T0
   ↓
初始改写 T1
   ↓
生成视觉锚点 I1
   ↓
基于 I1 诊断失败类型
   ↓
修正出 T2
   ↓
再出图 I2 做闭环验证
   ↓
用 (T2 > T1) 做 DPO 蒸馏
```

也就是说，它把“语义保真”从纯文本相似度，提升成了**视觉可实现性 + 原意不漂移**。

### 两阶段训练

- **SFT**：3 epoch，学习率 1e-5
- **DPO**：3 epoch，学习率 5e-6，β = 0.1

支持的学生模型包括：
- LLaMA3.1-8B
- Qwen3-8B-Base
- Hunyuan-7B-Instruct

### 数据构造强度

每个候选样本大约需要：
- 2 次 T2I 调用
- 2 次 MLLM 调用

虽然离线成本不低，但部署后只需要纯文本 rewriter，因此在线成本可控。

## 四、实验设置与结果

### 主结果 1：FaithT2I-Test 上显著优于纯文本重写

在 Qwen3-8B 学生模型上：

| 设置 | Gemini VQA | GPT-4o VQA | Qwen3VL VQA | CLIP | FID |
|------|-----------:|-----------:|------------:|-----:|----:|
| 原始 prompt | 62.12 | 60.28 | 64.39 | 0.752 | 23.94 |
| 纯文本基线 | 68.78 | 69.40 | 75.65 | 0.828 | 22.63 |
| **FaithRewriter** | **74.80** | **73.71** | **78.91** | **0.847** | **22.19** |

相对纯文本重写，VQA 进一步提升约 **6–8 个点**。

### 主结果 2：SpatialGenEval 上对困难项提升更明显

整体分数：
- 原始 prompt：**63.09**
- **FaithRewriter：70.83**
- 提升：**+7.74**

子项里最关键的是：
- 遮挡：**+10.10**
- 比较关系：**+8.68**
- 空间推理：**+5.55**

这说明它不是只会“补形容词”，而是真的改善了复杂视觉约束的可执行性。

### 主结果 3：跨生成器泛化明显

VQA 提升：
- FLUX-dev：**55.12 → 67.25**（+12.13）
- Hunyuan Image：**60.15 → 72.84**（+12.69）
- Qwen-Image：**62.12 → 74.80**（+12.68）

### 主结果 4：用户研究最优

用户排序里：
- 原始 prompt 平均排名：**3.55**
- 纯文本基线：**2.36**
- **FaithRewriter：1.41（最佳）**

### 对当前业务的直接启发

如果迁到安全 rewrite，这篇论文至少给了你三条硬启发：
1. **别只比较文本前后，要把 rewrite 真的丢进图像模型看终态**；
2. **winner/loser 最好来自视觉闭环，而不是人工主观臆断**；
3. **最容易坏的不是显式危险词，而是空间、计数、否定、隐性概念这些结构性约束。**

## 五、局限性分析

1. **它不是 safety-specific 论文**：重点在 intent preservation，不在风险降低。  
2. **离线数据构造成本较高**：需要多次 T2I + MLLM 调用。  
3. **依赖特定生成器外化错误**：若基模型本身太强或太弱，外化信号可能失真。  
4. **没有直接处理 NSFW 风险锚点**：需要你自己把风险 taxonomy 接进去。  
5. **在线系统若不保留视觉闭环，只蒸馏文本模型，后续仍可能发生分布漂移。**

## 六、复现指南

### 环境依赖

```bash
pip install torch transformers accelerate
```

### 最小复现步骤

1. 对原始 prompt 生成一个较详细的初始 rewrite。  
2. 用冻结 T2I 模型出图作为视觉锚点。  
3. 用 MLLM 诊断失败类型并修 prompt。  
4. 再次出图并执行三项闭环验证。  
5. 用 winner/loser prompt 对做 DPO 蒸馏。

### 对当前业务的最小迁移版本

如果只迁一件事，我建议迁它的**视觉闭环采样**：
- 从高风险 prompt 里抽一小批样本；
- 对不同 rewrite 方案实际出图；
- 再决定哪种 rewrite 真正“更安全且更保真”。

这比只在文本层面打分，可信很多。
