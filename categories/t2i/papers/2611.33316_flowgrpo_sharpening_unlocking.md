# RL 涨的分不是「学会了」：Flow-GRPO 的按技能 pass@k 解剖，把 0.63→0.95 拆成「锐化」与「解锁」

## 一、背景与问题

### 动机：把「一个总分」拆成「每个技能各自的覆盖曲线」

Flow-GRPO 把 SD3.5-M 的 GenEval 从 **0.63 抬到 0.95**，通行解读是「模型学会了组合生成」。本文追问：**这 0.32 分里，有多少本来就在 base 模型的样本里？** 方法是共享噪声种子下的 **pass@k**，一次只看一个技能，且用训练中未出现的 prompt。

这不是措辞之争，而是修法之争：**如果涨分只是「锐化」（sharpening，把已有成功样本的概率质量集中），那么推理侧 best-of-k + verifier 就能买到，不必重训；只有「解锁」（unlocking，base 在任意预算下都解不出）才需要训练侧动数据配比与奖励。**

### 与本仓库主线的关系（四重命中）

1. **GRPO 改写主奖励信号**：项目现状「安全率作为主指标」（devcloud `grpo1102_125`），本文给出对该读数的**可证伪分解协议**——安全率上涨必须报「是锐化还是解锁」，否则可能只是在重排已有样本。
2. **reward hacking / 奖励上界**：作者明确「reward gains 若只报一个数，会把两种机制混成一个基准分」，与 11-09 GARM「奖励上界从真实正例分布量出」形成上下游：**先判机制，再定上界**。
3. **三维评测 / 整体-分层背离**：GenEval 是六技能聚合分，本文证明**聚合分把两种相反机制平均掉了**（Tab.2：四个技能 pass@32 动 ≤0.013，空间关系 pass@32 +0.31）。这正是 `aggregate-vs-macro divergence` 在 RL 增益上的形态。
4. **算力约束**：锐化可在推理侧买（k 倍采样成本），解锁才需训练。对 6 节点→5 节点的现实，这条决定了 D2 的 GRPO 对照该不该启动重训。

## 二、核心方法

### 2.1 两个可操作定义（本文最可迁移的部分）

设 $n=32$ 共享种子、$p@1$ 为单次成功率、$p@n$ 为覆盖上界（ceiling），$k^*$ 为 base 的 `pass@k` **首次追平** post-trained 模型 `pass@1` 的最小 k。

| 标签 | 判据 | 机制 | 该去哪修 |
|---|---|---|---|
| **锐化 sharpening** | 存在 $k^*\le n$，且 ceiling 上升 ≤0.02 | 只重排组内已有成功；policy gradient 抬高已被奖励轨的似然 | **推理侧**：采样数 + verifier |
| **解锁 unlocking** | 不存在 $k^*\le n$，ceiling 明显上升；零覆盖 prompt 被救 | 需要跨 prompt 共享方向累积，改数据分布 | **训练侧**：训练配比、奖励结构 |

作者给了四条可证伪推论（Sec.3）：① 锐化不需要新覆盖；② 解锁若真是「关系词一个开关」，应在 prompt 间同步出现（实测不是）；③ 锐化会降低组内多样性，解锁则先抬 ceiling 后抬 pass@1；④ 未正则化模型会出现「奖励看不见的漂移」。

### 2.2 为什么必须按技能拆

GenEval 奖励是**分级**的（graded）：关系 prompt 上「画出两个物体」给 0.75，「摆对位置」才给 1。作者证明这个分级把关系技能**劈成两个因子**——前者属 two-object 技能、是锐化（base 在 128 样本里 89% 能画出两个物体），后者才是解锁。**一个标量奖励把两个机制焊在一起，于是怎么改奖励都会顾此失彼。**

## 三、技术细节

### 3.1 实验设置

| 项 | 值 |
|---|---|
| 主干 / 算法 | SD3.5-M；Flow-GRPO（G=24、rank 32、25 steps、带 KL）；另跑 no-KL 与 40 steps 对照 |
| 评测 | 553 个官方 GenEval prompt，**全部与训练 prompt 不相交**；每 prompt 32 共享种子；strict 与 official 双判据 |
| 深采样 | 关系技能另抽 128 样本/prompt（100 prompts）估 base `pass@128` |
| 训练中对照 | Run A（全技能 14k）/ Run B（仅关系）/ 对象留出（50 个训练中出现 vs 9 个未出现） |
| 适配器 dial | LoRA scale λ=0/0.25/0.5/0.75/1，看 `pass@1` 与 `pass@16` 谁先动 |

### 3.2 关键控制

- **同一 judge 既是奖励又是评测判据**，作者专门讨论「锐化可在同一 judge 下用 k 倍采样买到」，避免把「换了个尺子」当能力提升；
- 官方/严格双规则复现（Table S1：strict 0.65→0.94，official 0.63→0.95，与已发表数吻合）；
- 报 95% bootstrap 区间（按 prompt）、seed noise floor、LoRA dial 的 ceiling 领先性；
- 文本渲染另测 200 held-out 引用字符串 prompt，用 `1−min(d,ℓ)/ℓ` 编辑距离奖励。

## 四、实验与结果

### 4.1 主表（Table 2，strict，n=32）

| 技能 | base p@1 | RL p@1 | base p@32 | RL p@32 | k* | 判定 |
|---|---|---|---|---|---|---|
| Single object | — | 0.98 | — | — | 4 | 锐化 |
| Two objects | 0.50 | **0.95** | 0.99 | 0.99 | **10** | 锐化（ceiling 不动） |
| Counting | 0.55 | 0.95 | 1.00 | 1.00 | 12 | 锐化 |
| Colors | 0.72 | 0.95 | 1.00 | 1.00 | 4 | 锐化 |
| **Position（空间关系）** | **0.16** | **0.94–0.96** | **0.76** | **1.00** | **>32** | **解锁（Δceiling +0.31）** |
| Attribute binding | 混合 | 0.79 | — | +0.08 | 8 | 混合 |

四个锐化技能：post-trained 的 `pass@1`（0.98/0.95/0.94/0.89）恰好是 base 用 **4/10/8/5** 个样本能达到的水平，`pass@32` 最多动 **0.013**。**一句话：一个 post-trained 样本值 4–10 个 base 样本，但 base 的 32 样本上界一分没涨。**

### 4.2 解锁臂的硬读数

- 关系技能 base `pass@1=0.16 → RL 0.94`，`pass@32 0.76→1.00`；
- **31 个零覆盖关系 prompt（base 在 32 样本里一次都没解出）中，RL 后 93% 被解出**，且「base 曾解出」与「从未解出」两组的 RL 成功率几乎相同（0.95 vs 0.96）——**RL 不再依赖 base 的先验覆盖率**；
- **深采样 128 个 base 样本仍买不到**：base `pass@k` = 0.16/0.25/0.36/0.48/0.60/0.72/0.81/**0.89**（k=1…128），**全程低于 RL 的 pass@1 0.94**；
- 按 base 成功率分档，relations 的成功率 0.93/0.91/0.97/0.95/1.00 **与 base 先验无关**，而其余五技能从 0.31 单调升到 0.97（严格依赖先验）——两条曲线形状截然不同，却都被算进同一个 0.63→0.95。
- best-of-4 在其余五技能回收 **76%**、best-of-16 回收 **90–95%** 的增益；在 relations 只有 **41%**（Table S9）⇒ 锐化确实可在推理侧买，解锁不能。

### 4.3 三条机制对照

1. **LoRA dial**：四个锐化技能 `pass@1` 随 λ 单调升而 `pass@16` 几乎不动；关系技能 **`pass@16` 先动（0.60→0.82→0.96→1.00→1.00）而 `pass@1` 后动（0.16→0.33→0.59→0.86→0.94）** ⇒ ceiling 领先是解锁的指纹。
2. **训练顺序**：Run B（仅关系训练）显示 **锐化先到、且到处都到（含训练中未见过的对象）；解锁晚到、且按对象逐个到**。「早期奖励上涨不构成技能已获得的证据」。
3. **no-KL 对照**：无 KL 时关系与其余技能对 base 先验的依赖性都减弱（0.31→0.55），但出现「奖励看不见的漂移」（Fig.1 底部：未正则化模型丢掉正则版已锐化的 prompt）⇒ 这是 reward hacking 的可视化样本。

### 4.4 文本渲染（Sec.5）

`pass@1 0.19→0.64`，但分级奖励显示短串与长串解锁幅度不同（0.11 / 0.26）；mean reward 0.54→0.92，**同一技能里锐化与解锁并存** ⇒ 按「技能」拆还不够，长尾要按「难度档」再拆一层。

## 五、局限性与迁移边界

- **只测一个 base（SD3.5-M）+ 一个算法（Flow-GRPO）+ 一个奖励（GenEval）**；作者明说 deficit 结构、数据配比与 headroom 都会改变两类机制的占比。
- **无人工评测**，judge 既是奖励又是验收 ⇒ 与 11-26「验收装置本身要先被验收」冲突；迁移到安全率时必须把 judge 换成人工双盲 + 独立安全分类器。
- **GenEval 六技能里四个没有 headroom**（base 32 样本几乎全解）⇒ 结构上无法观测解锁，不能反推「RL 只会锐化」。
- **不涉 NSFW / 政治 / 跨语言 / I2I 双通路**，无 TTFT、量化、serving setup 数据。
- **不可迁的量级**：0.63/0.95、4–10、93%、0.31 都是 GenEval 专属；**可迁的是协议**：`k*`、Δceiling、零覆盖拯救率、best-of-k 回收率、ceiling-领先性五项。
- **对本项目的边界**：安全率作为主奖励时，若涨分主要是锐化，则「继续加 GRPO 训练」是错修法，应转 best-of-k + verifier；但若改写器要把「模糊高风险 prompt」改到模型从未见过的分布外，**那是解锁，只能靠训练/数据**。二者必须先用 `k*` 分开再决策。

## 六、复现指南

1. **最小复现（0 GPU 训练）**：取 50 条高危 prompt，对现网改写器输出与 base 输出各采 n=32 共享种子，按「文本无害 / 出图无害 / 原子要件保留」三个技能分别算 `pass@1`、`pass@32`、`k*`、Δceiling、零覆盖拯救率。
2. **判据**：若 `k*≤32` 且 Δceiling ≤0.02 ⇒ **锐化**，把预算转推理侧 best-of-k + 图审 verifier；若 `k*>32` 且 ceiling 明显上升 ⇒ **解锁**，才进训练侧（数据配比 / 奖励结构）。
3. **必配对照臂**：① 同一改写后 prompt 的 best-of-4 / best-of-16 回收率；② LoRA dial（λ=0/0.25/0.5/0.75/1）看 ceiling 是否领先；③ no-KL / 无正则臂查「奖励看不见的漂移」；④ 训练早期 ckpt（锐化先到）与后期 ckpt（解锁晚到）分列。
4. **防作弊**：把 DSC 三版对照（11-23）、「换判据」对照臂（30117 Seurat relabel 0.94→0.19）、非目标属性引入率（HinT 59%–74%）塞进同一张面板；奖励验证面板必须冻结 judge 配置指纹 + 检测器版本 + serving setup。
5. **留痕**：每版本登记 `k* / Δceiling / 零覆盖拯救率 / best-of-k 回收率 / 奖励器版本 / 评测集重叠审计版本` 六元组；`Δaggregate>0 而 Δmacro<0` 即判子类劣化被掩盖。

---

**对本项目的落点（一句话）**：**「安全率涨了」不是一个结论，先报 `k*` 与 Δceiling 判锐化还是解锁**。锐化就别重训（改 best-of-k + verifier），解锁才动训练配比——这是 D2「GRPO 与 SFT 线奖励设计对比」的前置闸门，且零训练、一天可出结论。
