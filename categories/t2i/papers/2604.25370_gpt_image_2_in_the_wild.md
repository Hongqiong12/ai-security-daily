## 一、背景与问题

### 动机

GPT-image-2 刚上线时，研究界最缺的不是“更多 demo 图”，而是**一份真实世界用户到底在怎么用它的公开样本集**。实验室 API 测出来的是能力上限，但社交媒体上流传的图像更接近真实部署：题材分布、语言分布、分辨率重采样、平台 provenance 丢失、文本排版场景，这些都只有在野外数据里才看得见。

### 核心科学问题

能否在模型发布首周，快速构建一个高精度、可公开、可用于检测/归因/溯源研究的 GPT-image-2 真实世界数据集，并系统回答三个问题：
1. 用户都在拿它画什么；
2. 平台传播后 provenance 还剩多少；
3. 这种真实世界分布和实验室生成分布差多远。

### 直觉洞见

这篇论文真正有价值的地方，不是“抓了 1 万张图”，而是它证明了一个对 provenance 研究很不舒服的现实：**Twitter/X 在传播链路里会把 C2PA / EXIF / XMP 等元数据基本剥光。**也就是说，真实世界里的 provenance 问题，不是“你有没有打水印”，而是“平台是否允许这个水印活着到达下游”。

## 二、核心方法

### （1）首周抢救式数据收集

作者围绕 Twitter/X recent search API 的 7 天窗口限制，设计了一个必须“立刻抓”的 pipeline。目标不是全量召回，而是**高精度确认哪些图是用户明确自报用 GPT-image-2 生成的**。

### （2）六类多语言查询策略

查询覆盖：
- #GPTImage2 这类 hashtag
- “ChatGPT + prompt” 表达
- 英文创作表达
- 日文创作表达
- 中文创作表达
- 一个 broad anti-noise 查询

这套设计的核心不是语言覆盖本身，而是减少“讨论新闻”与“真正创作”之间的混淆。

### （3）两阶段确认机制

先用**多语言规则启发式**把样本分成：
- confirmed
- rejected
- uncertain

再对 uncertain 样本使用 **Playwright + Chromium** 自动检查 Twitter/X 页面里的 **Made with AI badge**，把平台侧信号引入 provenance 确认链路。

### （4）构建后不止做存档，还做真实使用分析

最终 10,217 张 confirmed 图像被进一步做：
- 语言分布分析
- 主题分类
- OCR 文本检测
- 人脸与人口属性估计
- CLIP embedding 聚类

所以这篇论文既是 dataset paper，也是在做一版“GPT-image-2 真实世界使用画像”。

## 三、技术细节

### 数据构建流程

- 原始抓取：**27,662** 条 image records
- 媒体过滤后：**26,515** 条 photo records
- Stage 2 去重后：**14,154** 条 unique image records
  - confirmed：**4,187**
  - rejected：**396**
  - uncertain：**9,571**
- 最终高置信 confirmed 数据集：**10,217** 张图像

### 查询与 API 细节

- 使用 **Twitter API v2 recent search endpoint**
- 付费层级：**Basic**
- 成本：**$0.005 / tweet read**
- 分页上限：**100 条 / 页**
- 统一查询操作符：
  - **has:images**
  - **-is:retweet**

作者专门强调：使用 has:images 而不是 has:media，把视频缩略图污染从约 **13%** 降到 **1.5%**。

### badge 验证自动化

- 浏览器工具：**Playwright / Chromium**
- 请求间隔：**3–5 秒**
- 每页等待渲染：**12 秒**
- 遇到登录墙或超时则跳过

### 内容分析模型

- 主题分类：**CLIP ViT-L/14 zero-shot**
- OCR：**EasyOCR（中英）**
- 人脸分析：**InsightFace buffalo_l**
- 聚类：**CLIP embedding + UMAP + HDBSCAN**
  - UMAP：cosine metric, k = **30**, min-dist = **0.05**
  - HDBSCAN：min cluster size = **15**

## 四、实验设置与结果

### 主要结果 1：首周真实世界数据规模已经很大，但高精度确认很难

- 原始 image records：**27,662**
- 最终 confirmed：**10,217**
- 去重后 Stage 2 中 confirmed 比例：**29.6%**
- 各查询精度差异很大：
  - hashtag 查询确认率最高：**94%**
  - broad anti-noise 查询确认率只有：**9%**

这说明一个很现实的问题：**弱语义搜索几乎注定把“在讨论 GPT-image-2”与“真的用 GPT-image-2 画图”混在一起。**

### 主要结果 2：平台传播会直接掐断 metadata provenance

作者明确观察到：Twitter/X CDN 上传后基本会剥离图片中的 **EXIF / XMP / C2PA** 元数据。  
对 provenance 研究来说，这比任何单模型检测结果都重要：**现实平台会主动把你上游辛苦埋进去的可验证元数据抹掉。**

在 uncertain 样本里，成功加载页面后：
- **53.7%** 带有 **Made with AI** badge

也就是说，平台侧 badge 在真实世界里比传统 metadata 更像“幸存下来的 provenance 信号”。

### 主要结果 3：GPT-image-2 的真实世界主场景不是“艺术图”，而是“图文排版图”

主题分类显示：
- **文字/图文类**：**33.2%（3,387）**
- **幻想/超现实**：**24.9%（2,542）**
- **写实人像**：**14.2%（1,453）**
- **动漫/插画**：**10.9%（1,109）**
- **产品/UI mockup**：**9.8%（1,000）**

这很关键，因为它说明 GPT-image-2 的风险画像和传统“AI 艺术模型”不一样：**它在真实世界里大量用于生成带文本、带排版、可直接传播的信息图和海报。**

### 主要结果 4：文字能力是首周最强可见信号之一

- **82.0%** 图像含有可机器识别文本（8,383 / 10,217）
- 含文本图像中，OCR 检出的文本区域数中位数：**29**

这说明 GPT-image-2 在真实世界的一大吸引力不是“更美”，而是**终于能把字画得可用**。

### 主要结果 5：传播链路会严重改写原始分辨率分布

长宽比分布：
- 竖图：**53.5%（5,461）**
- 横图：**38.0%（3,882）**
- 方图：**8.6%（874）**

但只有：
- **2,484** 张仍保留 GPT-image-2 原生输出分辨率

其余：
- **7,733** 张已经被 Twitter CDN 重采样

这对检测和归因研究是个强提醒：**真实平台图像分布不是模型原生分布，而是“模型输出 × 平台重压缩 / 重采样”后的混合物。**

### 主要结果 6：使用者语言分布具有明显跨语种特征

- 英文：**40.3%（4,117）**
- 日文：**32.8%（3,355）**
- 中文：**19.2%（1,959）**
- 法文：**2.5%（258）**
- 其他：**5.2%（528）**

这说明 GPT-image-2 的早期爆发不是单英语生态现象，而是明显跨语种扩散。

## 五、局限性分析

1. **这不是 Twitter/X 上所有 GPT-image-2 图像的全量全集**，而只是 search-indexed pool。  
2. **高精度换来低召回**：大量 silent creators 会落进 uncertain，而不是被确认为 positive。  
3. **badge 不是完美真值**：用户可能 opt-out，平台标签也可能延迟或缺失。  
4. **正文里有若干计数口径混用**：例如 uncertain 池与最终 confirmed 的部分数字，需要注意 record-level 与 image-level 是否混在一起。  
5. **人脸年龄/性别估计只适合做粗画像，不适合做严格人口结论**，尤其在动漫/插画样本上偏差可能更大。  

我的判断是，这篇论文的“方法新意”不算重，但它对 **T2I provenance / social deployment / benchmark realism** 的价值很高，因为它把研究视角从 API 实验台真正拖到了现实平台上。

## 六、复现指南

### 复现步骤

1. 使用 **Twitter API v2 recent search** 在模型发布首周抓取公开图文帖。  
2. 保持查询设计偏高精度，优先抓“明确创作声明”而不是泛搜模型名。  
3. 先做多语言规则分类，再用 **Playwright** 自动检查 **Made with AI** badge。  
4. 对 confirmed 数据做：
   - 主题分类
   - OCR 可读性检测
   - 人脸分析
   - CLIP 聚类

### 建议优先复现的两块

- **badge 检查自动化流程**：这是整篇论文最接近现实平台 provenance 的关键步骤；
- **分辨率与文本分布统计**：最能快速复现“真实世界分布不同于 API 实验分布”这一核心结论。

### 对 T2I 安全研究的启示

这篇论文值得进入 benchmark 索引，不是因为它提供了更强的模型，而是因为它把真实部署里的几个关键约束正式拉上台面：
- **平台会删 metadata**
- **大量图像会被二次压缩 / 重采样**
- **真实使用场景高度偏向文本排版与传播内容**

如果后续要做 T2I detection / provenance / watermark benchmark，这类“野外分布”数据集会越来越重要。
