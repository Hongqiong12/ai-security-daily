# LoRA 溯源签名: 只用出图的内在维度，黑盒判断"服务端跑的是原模型还是被改过的 LoRA"

**论文主页**: https://arxiv.org/abs/2610.36933
**领域**: 扩散模型 LoRA 适配的模型溯源 / 黑盒假设检验 / 内在维度签名
**作者**: Tobias Cheung, Mohan Dantam, Marc Juarez, Rik Sarkar
**机构**: **University of Edinburgh**（Cheung / Juarez / Sarkar）+ **University of Oxford**（Dantam），受 Edinburgh International Data Facility 与 GAIL Fellow 支持
**发布日期**: 2026-10-27（v1，cs.LG；Manuscript received 2026-09-30）
**分类**: defense
**模态归属**: 文生图（T2I）— 输出侧溯源与问责，**"输入侧改写不动权重"这一主张的合规侧配套**

## 一、背景与问题

### 动机

LoRA 让"改一个基础模型"变得极其便宜：**少量图 + 低算力**。这件事的副作用是——**把基础模型改成违规用途，也变得极其便宜**。

两个具体场景：

| 场景 | 攻击者的主张 | 审计员要回答的问题 |
|---|---|---|
| **I. IP 保护** | "我这个 API 跑的是别的模型/自研模型"（实际是违反许可的 LoRA 微调版） | 目标是"完全无关的模型"吗？ |
| **II. 问责** | "我的 API 跑的就是原版开源模型"（实际被 LoRA 微调去生成违规内容） | 目标**就是**那个原版基础模型吗？ |

场景 II 正是我们这条线最相关的：**有人拿开源底模加 LoRA 做 NSFW 生成，然后把责任推给底模提供方**。底模方需要一种手段证明"这不是我"。

### 现有方法的两个硬假设

1. **需要标签**（用标注数据训一个归因分类器）；
2. **需要闭集**（在一份已知候选模型名单里做归属）。

作者指出这不符合现实：审计员面对的是**开放世界**——可能的适配和替代模型集合都是未知的。

### 核心科学问题

**只用黑盒查询（给出 prompt、收回图像），能不能判断这个服务端跑的是"底模"、"底模的 LoRA 适配"、还是"完全不同的模型家族"？**

### 为什么这篇对我们重要

我们的核心部署主张是"**不改生成模型，靠输入侧热更新**"。这个主张有一个隐含的合规优势：**权重没被动过，所以溯源/审计这条线上我们是干净的**。这篇提供的正是"证明权重没被动过"的黑盒方法——**它不需要我们开放权重，只需要我们（或审计员）能反复查询出图**。

同时它也给了我们一个必须接受的限制：**它的失效案例（Food101）恰恰说明了这类方法的下界**——如果 LoRA 微调的数据分布与底模太接近，签名就分不出来。而 NSFW 微调恰恰**可能**落在"与底模分布接近"的那一侧（因为底模本身就能画人），这对场景 II 的可用性是一个真实威胁。

## 二、核心方法

### （1）先做白盒分析：LoRA 对速度场的扰动确实小

作者先不急着给黑盒方法，而是先证明"这件事在原理上可行"。对底模 $\theta_{\text{base}}$ 的输出 $x_0$ 加噪 $m$ 次得到 $\{x^{(j)}_{t=1}\}$，把各模型的 score 向量堆成矩阵 $S_\theta = [s_\theta(x^{(1)}_1,1) \cdots s_\theta(x^{(m)}_1,1)]$，用两个量比较：

- **方向对齐**（Frobenius 余弦）：$\text{Cosine}(S_{\text{base}}, S_{\text{target}}) = \dfrac{\langle S_{\text{base}}, S_{\text{target}}\rangle_F}{\|S_{\text{base}}\|_F \|S_{\text{target}}\|_F}$
- **相关结构对齐**（Gram 差，算子范数）：$\dfrac{\|G_{\text{base}} - G_{\text{target}}\|_{\text{op}}}{\|G_{\text{base}}\|_{\text{op}}}$，$G = S^\top S$

白盒实验（无条件 DDPM 猫模型 + LSUN-Bedroom LoRA + 两个 negative 模型）显示：**LoRA 对底模 score 场的扰动明显小于 negative 模型的扰动**。在文本条件模型（SD v1.5 + CheXpert LoRA）上进一步发现：**self-attention LoRA 的扰动 < cross-attention LoRA < both**；但用 **LoRA 域 prompt** 生成时，三种注入方式的扰动程度变得接近。

**这个细节对我们有直接含义**：扰动大小**依赖你用什么 prompt 去问**。用原域 prompt 问，差异小；用适配域 prompt 问，差异被抹平。所以审计的 query 设计不是无关紧要的细节，而是决定成败的一步。

### （2）黑盒化：把 score 向量换成"内在维度直方图"

黑盒下只能拿到终点 $x_0$，拿不到 score 向量。作者的桥是**生成流形（generative manifold）**的概念：

> 每个模型 $\theta$ 生成的图集中在其生成流形 $\mathcal{M}_\theta$ 附近。这个流形**不是数据流形**——理论上反向过程收敛到数据流形，实际模型只给出近似反向过程，模型行为取决于架构、容量、优化目标。

在流形附近，score 向量近似正交指向流形（属于法丛），所以**样本法向 score 向量的张成空间的补维数 = 局部切空间维数 = 局部内在维数**。内在维数可以用样本本身估（MADA 估计器），不需要 score 向量。

于是：**对一个 query 生成一批图 → 逐点估局部内在维数 → 直方图就是该模型的局部签名**。签名之间的比较变成分布比较。

### （3）假设检验：两个问题，两套 query 构造

**Problem I（负判别：目标是否在 $\mathcal{N}_{\text{base}}$ 里）**
- query $q$：在底模训练数据里做 k-means，**取最接近某个簇心的那条 caption**（在底模 tokenizer 的嵌入空间里做）；
- 参考集：**100 个**底模签名；零校准集：**2000 个**底模签名；预设定阈值 **p < 0.001**（2000 个样本下接近可分辨的最小 p 值，且能最小化"误拒一致签名"的概率）。

**Problem II（底模判别：目标是否**就是** $\mathcal{P}_{\text{base}}$）**
- 前提：先由 Problem I 排掉 negative；
- query $q$：**用 anchor image（违规输出的样例）经 caption 生成器反推**——审计员从"非法内容的样子"倒推该问什么；
- 每个 LoRA 域有自己的参考 prompt，所以每个域要一套独立的参考集与零校准集。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 底模 | **Stable Diffusion v1.5** |
| LoRA 适配域 | **Food101**（社媒食物图）、**Pokémon**（动画角色）、**WikiArt**（绘画）、**CheXpert**（胸片，只用正位 AP/PA）、**EuroSAT**（Sentinel-2 卫星图） |
| caption 生成 | BLIP-2 Flan-T5-XL，通用 prompt "Describe the image"（Food101 / Pokémon / WikiArt）；CheXpert 用 "A frontal chest X-ray image"；EuroSAT 用 "A satellite image of a residential area" |
| LoRA 训练 | 每域 1000 样本（Pokémon 全量 833）；**rank 16**（自+cross attention）；10000 iters；batch 8；lr $10^{-5}$ |
| 采样 | 确定性调度器，guidance 6.5，LoRA scale 1.0 |
| Negative 控制组 | DeciDiffusion v1.0、PixArt-α-512、**SD v2.1、SDXL、SD v3.5 medium**（后三个是同族，故意选接近的当难负例） |
| 签名规模 | 每模型 **5 组 × N=1000 张**；MADA 邻域 $k=50$ |
| 阈值 | p < 0.001 |
| 基线 | Nataraj19（颜色统计）、Wang20（学习特征）、Giudice21（频域）、Ha26（CLIP 特征分布）、**PCA-64 Wasserstein**（匹配的参考集控制） |
| 基线适配 | 归因类基线需要标注：每候选模型 1000 张标注图；Problem II 用 **leave-one-domain-out**（被评 LoRA 域排除在训练外）；逐图预测按 1000 张一批做多数票聚合 |

**消融**：LoRA rank {8, 16, 32, 64}；LoRA scale {0.3, 0.7, 1.0, 1.5}。

## 四、实验与结果

### Problem I（负判别）

Fig.7 显示：**所有未修改的底模（不同随机种子）签名都接近参考集**，p 值 > 0.001 判为未修改；**大多数 LoRA 模型 p < 0.001 判为已修改**。

**唯一的失败是 Food101**——被判为与底模相似。

### Problem II（底模判别）

在开放世界、留一域（leave-one-domain-out）设定下，本文方法**全面超过所有基线**：**AUROC 1.000，F1 0.943**。

### 与基线对比（Table III）

| 方法 | Problem I AUROC | Problem I F1 | Problem II AUROC | Problem II F1 |
|---|---|---|---|---|
| Nataraj19（颜色统计） | 1.000 | 0.889 | 0.600 | – |
| Wang20（学习特征） | 1.000 | 0.889 | – | – |
| Giudice21（频域） | 0.840 | 0.889 | **0.400** | 0.666 |
| Ha26（CLIP 特征） | 0.992 | 0.718 | 0.690 | 0.687 |
| PCA-64 Wasserstein | 0.680 | 0.666 | 0.600 | 0.833 |
| **Ours（内在维度签名）** | 0.855 | 0.800 | **1.000** | **0.943** |

**这张表最值得读的是"错位"**：

1. **有监督的归因方法在 Problem I 上碾压（AUROC 1.000），但在 Problem II 上崩到 0.400–0.690**。原因是它们的特征（颜色统计、频域、学习特征）**不能迁移到训练时没见过的 LoRA 域**。Giudice21 的 AUROC 0.400 意味着**比随机猜还差**。
2. 本文方法在 Problem I 上不如有监督基线（0.855 vs 1.000），作者自己直说"supervised attribution baselines achieve the best performance"——**没有掩盖**。
3. 本文方法赢在 **Problem II，也就是"开放世界 + 留一域"这个更真实的设定**：它**不需要标注数据、不需要训练**，只需要底模。

⇒ **一句话**：有监督归因在闭集上更强，但在开放世界上不可用；**弱信息 + 假设检验反而更鲁棒**。

## 五、局限性

1. **Food101 失败**。LoRA 域与底模分布太接近时签名分不出来。作者没有给出"什么时候会失败"的先验判据——**这是方法可用性的最大缺口**。
2. **只测 LoRA（rank 16 默认）**。全量微调、其他 PEFT 变体、以及"专门为逃避审计而定制的适配"都未测。作者在结论里承认"the efficacy in those scenarios remains to be determined"。
3. **需要每个 query 生成 1000 张图 × 5 组**，且 Problem II 每个 LoRA 域要独立参考集 + 2000 个零校准签名。**这是很重的审计成本**（2000 × 1000 = 2M 张图的校准集）。
4. **威胁模型假设攻击者用默认 LoRA 流程**。一个知道这套方法的对手，只要在 LoRA 里加一点分布拉近的约束，签名就可能失效——**论文没有做自适应攻击**。
5. **阈值 p < 0.001 是预设的**，2000 个零校准样本下"接近可分辨的最小 p 值"——**这个阈值是被校准集规模限制住的，不是被风险容忍度决定的**。
6. 评测只在 SD v1.5 + 五个域上；LoRA rank/scale 消融在附录，未进入主表。
7. **"生成流形"的术语使用被作者自己标注为不严格**（流形维数应恒定，而这里假设逐邻域变化）——概念上是一个 subspace 而非 manifold。

## 六、复现指南

### 可复现部分
- 全部依赖公开：SD v1.5、diffusers、MADA 估计器、BLIP-2 Flan-T5-XL、五个公开数据集。
- **LoRA 训练完全标准化**（rank 16 / 10k iters / bs 8 / lr 1e-5），5 个域都能自己复现。
- **白盒 score 场分析（Fig.2–4）不需要训练**，只需要前向；这是最快的验证入口。

### 关键实现顺序（建议）
1. **先算扰动随 prompt 域的变化**（半天，零训练）：拿我们的底模 + 一个已知的 NSFW LoRA，分别用**原域 prompt** 和 **NSFW 域 prompt** 各生成一批，量 score 对齐。**判据：如果换成 NSFW 域 prompt 后扰动被抹平（论文说三种注入都接近），那说明"用违规样例会反推 query"这条路对我们场景不可靠。**
2. **再测 Food101 式失效**：拿一个"和底模分布接近"的 NSFW LoRA（底模本来就能画人像），看签名能否分开。**这一步直接回答"方法在我们场景能不能用"**，比复现全部五个域更值。
3. **最后才做完整假设检验管线**（100 参考 + 2000 零校准）。

### 迁到我们业务的具体做法
- **合规叙事**：我们"不改权重"的部署方式，天然适配 Problem II 的"自证清白"方向——**可以主动提供黑盒审计接口**（给定 query 返回 N 张图），把"我没改模型"变成一个可被第三方验证的断言，而不是一句承诺。
- **反向使用（攻防视角）**：这套方法**也能用来审计竞品/第三方 API**——判断某个"自研模型"是不是套了开源底模的 LoRA。对内容安全治理这条线，这是识别"换皮"服务的手段。
- **对我们最该记的一条**：**"能用什么 prompt 去问"决定了审计能不能成**。用适配域 prompt 问会把差异抹平。这条与我们的图审 AB 评测是同一个病——**评测 query 的分布选择，会直接决定结论**。
- **不要照搬的**：Problem II 的 2000×1000 校准集，成本不现实。真要用，应该改成**小样本校准 + 序贯检验**。

---

**一句话判断**：这是一篇**方法边界比方法本身更有价值**的论文——它证明了"LoRA 对底模的扰动可被黑盒检测"，也证明了"这个检测在有监督归因面前并不更强（Problem I 0.855 vs 1.000）"，真正的价值在**开放世界设定下的鲁棒性（Problem II AUROC 1.000 vs 基线 0.400–0.690）**。对我们：**它是"输入侧改写不动权重"这条主张的合规侧配套证据**，但 Food101 的失效提醒我们——**当适配域与底模太像时，溯源会失效，而 NSFW 恰恰可能是那种"太像"的域。**
