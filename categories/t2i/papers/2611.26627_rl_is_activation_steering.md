## 一、背景与问题

### 动机：RL 后训练真的学到了「依赖输入的复杂变换」吗

文字渲染、组合摆放这些能力天然是 **prompt-dependent** 的，通行假设是：要提升它们，必须学一个随输入变化的复杂变换（LoRA / 全量微调）。本文用**刻意简陋**的参数化去证伪：在冻结 base 的每个 block 输出上，加一小组**固定 steering vectors**——**对每个 prompt、每个 token、每个 seed 都完全相同**。

如果这么一个「与输入无关」的常数偏移就能复现 RL 的绝大部分奖励增益，那么「RL 学到了 prompt-specific 策略」这个叙事就不成立；**奖励涨分与策略容量之间被划出一道可量化的鸿沟**。

### 与本仓库主线的关系（四重命中）

1. **GRPO 主线的策略容量上界**：与同日 `2611.33316`（Flow-GRPO 按技能 pass@k）构成**独立双证据**——一个从「样本覆盖」说涨分多为锐化，一个从「参数自由度」说涨分多为常数偏移。两条都指向：**不要把奖励上涨自动记成「改写策略变强了」**。
2. **低算力约束（6 节点→5 节点）**：steering vectors 仅 **0.29M 参数 / 288,768 个**，是 rank-32 LoRA 18.8M 的 **1/65**；且拟合过程**不需要奖励模型、不需要采样**（velocity matching）。这是本项目「低算力下安全模型训练」最省的一条改进路径，与 11-26 HinT（+<4% 训练时间、零推理开销）同族。
3. **reward hacking / 奖励上界**：拟合目标**不含奖励**（只对齐 RL-tuned 模型的速度预测），却恢复 90–96.3% 奖励增益 ⇒ 奖励信号与「真正学到的东西」不是一回事，与 11-09 GARM 的「上界从真实正例量出」互补。
4. **量化 / 加速不劣化**：steering 是推理期加在 block 输出上的常数，天然对 fp8/fp4 与 batch 组成敏感 ⇒ 任何上线都要补「生成侧 + 判定侧 serving setup 指纹」。

## 二、核心方法

### 2.1 参数化

对每个 block ℓ、条件/无条件分支、时间步 bin、img/txt 流各设一个常数向量 $s_{\ell,\text{str},p,k}$，加到该 block 输出上：**同一向量广播给该 stream 的所有 token**（Fig.2）。SD3.5-M 共 188 个向量、0.29M 参数。

**关键理论关系**（Sec.3.2）：LoRA 更新 $\Delta W = ba^\top$ 其实是「固定方向 b × 输入相关权重 $a^\top z_i$」。本文把那个权重**钉成常数** ⇒ **steering vector 是 LoRA 的输入无关特例**。所以这不是两个不同的东西，而是**同一个自由度谱系的两端**。

### 2.2 拟合：velocity matching，目标里没有奖励

收集 RL-tuned 模型生成的样本，把同一 noisy state / prompt / step 同时喂给冻结 base（+steering）与 RL-tuned 模型，最小化两者**下一步速度预测**的差（Eq.2）。两个模型权重全程冻结。**拟合不需要奖励模型、不需要采样循环**（Table S1 对照）。

### 2.3 三条对照臂

| 对照 | 目的 |
|---|---|
| `s_mean`（mean-difference，无训练） | 最简单的输入无关变化，作为下界 |
| 只用 1 个 / 4 个 step bin（8 个保留 83–94% 能量） | 检验是否只是「多存了几个向量」 |
| **只训练 steering vectors 跑 Flow-GRPO** | 若常数向量 + RL 反超权重 RL，则策略容量假设彻底不成立 |

**六个 image 模型统一落在 90.0–96.3%**；`s_mean` 只恢复 12.2%（GenEval）到 79.0%（HPSv2.1）⇒ **不是「随便一个常数方向」都行，拟合的 scale 与注入位置才是关键**。Wan2.1 的 111.9% 表示拟合版在该奖励上**超过** RL checkpoint 本身（不等于复现了 checkpoint 的行为）。

### 3.3 反超对照（Sec.1 / 4.6）

冻结生成器、只对 steering vectors 跑 Flow-GRPO，达到 OCR-tuned 增益的 **104.6%** 与 **103.6%**——**权重侧 RL 没有比「常数偏移 + RL」多买到什么**。作者由此把结论写死为：policy-gradient RL 后训练的增益，在 diffusion transformer 里**不需要新的 input-dependent 变换**。

## 四、实验与结果

- **六个 image ckpt 恢复 90.0–96.3%**，两个 video ckpt 89.8% / 111.9%；**六个公开 video RL ckpt 里只有两个在对比奖励上相对 base 有正增益**（作者据此把 video 结论严格限到这两个）。
- **参数量**：188 个向量 = 288,768 参数 = rank-32 LoRA 的 **1.5%**（65× 更少）；推理期只需一次逐 block 加法。
- **时间步稀疏化**：4 个 step bin 保留 83–94% 能量，1 个 bin 给出几乎相同的奖励增益 ⇒ 不是靠堆向量。
- **mean-difference 基线最弱处是 GenEval（12.2%）**：GenEval 是组合/关系奖励，最需要「输入相关」的能力，但拟合后仍恢复 95.9% ⇒ 连最不该被常数解释的技能也被解释了。
- **论文明确的边界**：拟合向量**模仿 RL checkpoint 的行为**，不是被直接教去最大化 OCR / 偏好；奖励分全程留作 held-out 检验。作者禁止把「恢复 90%」读成「RL 只做了这一步」或「所有任务都能这样解」。

## 五、局限性与迁移边界

- **不涉任何安全语义**：八个奖励全是质量 / OCR / 组合 / 偏好，**无 NSFW、政治、误杀率、拒答、改写**；「安全率」是否被常数向量复现，本文不能回答，需要自建对照。
- **只在 diffusion transformer / rectified-flow 上验证**，未覆盖统一生成-编辑双通路、I2I 编辑指令、2B 级小改写模型。
- **无 TTFT / e2e / TPOT / fp8-fp4 / 跨硬件 / serving setup 数据**；拟合向量对量化与 batch 的敏感性未测（与 11-25 batch 非确定性、11-26 8-bit 非 batch-invariant 直接相关）。
- **拟合需要拿到 RL-tuned ckpt 的生成样本**，线上「只有 base + 改写器」的场景不能直接用。
- **可迁的是协议，不是量级**：90–96.3% 是这些奖励专属；可迁的是「用输入无关参数化做下界对照，把奖励涨分拆成『常数可解释部分』与『必须输入相关的部分』」。
- **对本项目最重的一句**：如果 2B 改写模型的安全率提升主要落在「常数可解释部分」，那 `grpo1102_125` 的收益上限受**奖励稀疏 / 策略容量**限制，而不是「模型不够大」；此时加数据、加训练轮次都是错修法，该改的是奖励密度（twin 速度差 / 逐 token 条件差，HinT）与验收单位。

## 六、复现指南

1. **零训练下界对照（1 天）**：固定 200 条「改写后文本无害但被打击」样本，对现网改写器与 SFT 基线各算安全率；再构造一个「对全样本施加同一常数改写偏移」的臂（如统一加同一句安全前缀 / 同一 risk-anchor 替换表），看能解释多少安全率差。**若常数臂解释 >80%，则 GRPO 增益不是输入相关策略。**
2. **配套 `k*` 闸门**：与 `2611.33316` 同步跑 `pass@k` / Δceiling / 零覆盖拯救率，两个维度（样本覆盖、参数自由度）交叉判定「锐化 / 解锁 / 常数偏移」。
3. **奖励密度对照**：把标量安全率 vs twin 速度差 / 逐 token 条件差（HinT）并列，检查 `grpo1102_125` 是否因奖励稀疏而受限；配 DSC 三版对照与「换判据」对照臂防 reward hacking。
4. **不劣化验收（八栏）**：若 steering 类改动上线，必须报生成侧语义完整性、判定侧逐对翻转、分层 F1 与安全率、测量仪器项、判定侧 batch 不变性、非目标属性引入率、serving setup 指纹、检测器版本。
5. **留痕**：ckpt / 向量数 / 注入 block 与 step bin / 拟合样本来源 / 奖励器版本 / 评测集重叠审计版本，全部进 6 版本看板。

---

**对本项目的落点（一句话）**：**先把「安全率涨了多少」拆成「常数就能解释的部分」与「必须输入相关的部分」**；前者说明 GRPO 收益上限由奖励密度决定，不该继续堆训练，后者才是改写策略真正学到的东西。与同日 Flow-GRPO 按技能解剖构成 D2 的双闸门。
