## 一、背景与问题

### 动机：水印方案要同时满足四件互相拉扯的事

一个可部署的内容水印必须：**低 FPR 下判定准**、**内容保真处理下鲁棒**、**不可检测（undetectable）**，还要**抗伪造**。第四条常被忽略：只要攻击者拿到**一张带水印的图 + 一个代理模型**，就能把水印印到任意图片上，或重新生成带同款水印的内容——从而把有害内容错误归因给某个模型，或让真实照片看起来像 AI 生成。

论文进一步指出一个"判定 vs 事件"的缺口：

> 水印方案不该只 **reject** 伪造，还应该 **report** 伪造。**一次被当成"未加水印"而拒掉的伪造，不会留下任何尝试痕迹**——它和海量本来就没水印的自然图混在一起，事后无法审计。

### 与本仓库主线的关系

- 直接对应输出侧「image watermark / provenance / AIGC detection」与「编辑后水印存活率」；
- 更关键的是它与 11-10 NotaryMark 的「判定 100% 而信息 60.69%」构成**同族但不同层**的第二个证据：NotaryMark 说的是"判对了但读不出是谁"，本篇说的是"判对了但没记录发生过"⇒ **判定、信息、事件是三个独立的量**；
- 对「策略命中事件审计 / guardrail observability」有直接方法迁移价值。

## 二、核心方法

### 2.1 Tripwire-WM：把语义提交进"符号水印没用的那一维"

| 项 | 做法 |
|---|---|
| 观察 | 基于符号（sign-based）的水印只用初始潜噪声的**符号**，**幅度（magnitude）是空闲信道** |
| 核心 | 用 **distribution-preserving embedding** 把生成图的**语义提交（commit）到初始潜噪声的幅度**上 |
| 伪造检测 | 伪造图能带上一个**有效水印**，但它的 commitment 与图内容对不上 ⇒ 检测器**既拒绝、又报告为伪造** |
| 基座 | PRC watermark 与 Gaussian Shading++，**可证明保持二者的不可检测性** |
| 配套 | 语义哈希网络 + 净化一致性检查（PC check）+ 参考域检查（防幅度替换伪造） |

关键在于：**判定水印合法 ≠ 内容与水印绑定**。伪造者能复制水印，但复制不了"这张图与这份提交一致"这个关系。所以检测器多出一个输出维度——不是二值 flag，而是 `accept / reject / reject+alert`。

### 2.2 为什么外部异常检测器不行

论文实测两类外部 detector：一类（G-Cos）在 MS-COCO 上只标出 **19.7–24.0%** 的 reprompting 伪造；另一类（PGID-F）只标出 **18.6–39.7%**；而且它们在常见处理后会把真图误报。**它们站在水印之外，看不到提交关系**。

## 四、实验与结果（MS-COCO，论文口径）

### 4.1 伪造抵抗主结果

| 场景 | Tripwire-WM | SemBind（SOTA 对照） |
|---|---|---|
| **imprinting 伪造**（用 owner 自己的模型作代理） | **接受 0%**，且**全部被报告为伪造** | 最高接受 **55.0%** |
| **reprompting 伪造** | 最多接受 **1.8%** | 最高接受 **46.2%** |
| 真图（10⁻⁶ FPR） | **≥99%** 接受 | — |

对照基线：SemBind 在 MS-COCO 上仍接受**最高 46%** 的 reprompting 伪造，且**被它拒掉的伪造丢失水印、与海量无水印自然图不可区分**——正是"拒了却不报告"的缺口。

### 4.2 外部异常检测器（论文 5.2/5.3）

- G-Cos：只标出 **19.7–24.0%** 的 reprompting 伪造；
- PGID-F：只标出 **18.6–39.7%**；
- 二者在常见内容保真处理后都会误报真图。

⇒ **"加一层外部检测器"不解决归因问题**，与 11-10 Jev「加二级复审在匹配预算下并不更好」是同一条工程教训的另一个实例。

### 4.3 附带结论

鲁棒性与基座方案持平（Table 2），画质用 FID / CLIP 单独报（Table 3），并**可证明保持不可检测性**——这三条把"安全性提升是否靠牺牲效用换来"钉死了。

## 五、局限性

1. **绑定的是"生成时的语义提交"，不是任意编辑链**：论文测的是失真/再生/imprinting/reprompting 攻击，未覆盖"多轮指令式编辑后水印存活率"这一本项目最关心的形态——**编辑后存活率仍需自建 AB**（对应业务 H4）。
2. **依赖初始潜噪声可达**：对闭源 API 只给图不给潜变量、或经过重编码/截图的传播路径，commitment 是否可验证未在射程内。
3. **语义哈希网络自身是攻击面**（Table 5）：需要 PC check 等额外机制，方案不是单点而是组合。
4. **不覆盖输入侧**：完全是输出侧/溯源侧，与 prompt 改写、类目阈值无关。
5. **"report" 只到事件层**：报告的是"发生了伪造尝试"，不含"谁、出于什么意图"的责任归因。

## 六、复现指南

**论文复现**
1. 取 PRC / Gaussian Shading++ 基座，在 MS-COCO 上生成带水印图；实现幅度层的 distribution-preserving 提交与语义哈希网络。
2. 固定 **10⁻⁶ FPR** 选 operating point，报真图 acceptance。
3. 分别构造 imprinting（SD 2.1 / SD 1.5 代理）与 reprompting 伪造，报 **acceptance / Unverified / alert** 三列（不是单列 acceptance）。
4. 跑 Table 2 的失真/再生攻击与 Table 3 的 FID / CLIP；做 Table 4/5 的幅度替换与哈希网络攻击对照。
5. 验证不可检测性（论文给出可证明结论，实验侧按基座方案口径对照）。

**本项目迁移建议（零训练 / 推理为主，1 天）**

| 动作 | 做法 | 判据 |
|---|---|---|
| **图审 AB 拆成"判定 / 信息 / 事件"三栏** | 判定：TPR/FPR/误杀；信息：细类目混淆矩阵、PORN/VULG 边界 F1、L2_30 叶子准确率；**事件：拦截/改写/申诉/复核的落表率与可追溯 ID** | 判定接近满分而事件栏缺失 ⇒ **策略命中事件审计是空的**，线上归因无法复盘 |
| **"拒了也要留痕"** | 所有被挡下的样本（含被当成"未加水印/未命中策略"的）写一条结构化事件，带版本、阈值、规则指纹 | 与"仅记拦截成功"相比，可复盘样本比例下降 >20% ⇒ 现有看板存在 46% 式的隐性黑洞 |
| **编辑后水印存活率分档（H4 沿用）** | 按编辑强度轻/中/重分档测检出率，同时报 FID 代理 | 轻编辑档就掉到 <90% ⇒ 方案比公开方法更脆，需换绑定维度 |
| **"加一层"必须先证伪** | 若考虑加外部异常检测器兜底，先按匹配 FPR 预算对照 | 参照本篇 G-Cos 19.7–24.0% / PGID-F 18.6–39.7% 与 Jev 的 0.7 点差：**不显著就不加层** |
| **低 FPR 写进验收口径** | 图审/水印所有主结果锚定固定 FPR 并报四元组（阈值、规则、划分、代价比） | 换 FPR 口径结论翻转 ⇒ 历史版本对比作废重算 |

## 附：对业务主线的三句话

1. **判定、信息、事件是三个量**：11-10 NotaryMark 给"判定 100% 而信息 60.69%"，本篇给"拒了伪造却没留证据"，合起来要求图审 AB 至少三栏，而不是一个 TPR。
2. **"加一层外部检测器"再次被证伪**：G-Cos 只标 19.7–24.0%、PGID-F 只标 18.6–39.7%，且会误报真图；真正有效的是把绑定做进生成过程（幅度信道），这与"改写后的 prompt 必须落在生成器认得的分布里"同构。
3. **输出侧与输入侧互补且失效方向相反**：本篇只管已生成图的溯源与伪造，管不了逐条请求的可回滚改写；反过来输入侧也管不了已经流出去的图。⇒ 与权重侧概念擦除一起构成三层，不能相互替代。
