## 一、背景与问题

### 动机

指令式图像编辑（"把两只猫删掉"、"把四头牛换成羊"）已经能出视觉上很可信的图，但**数量正确性**一直被跳过。原因不是没人关心，而是**评测工具本身坏在那一步**：

1. **整体相似度指标（CLIP / DINO / LPIPS / FID）对实例计数不敏感**。MagicBrush 一脉的评测只看全局观感，多一个少一个几乎不掉分。
2. **当前主流的 VLM/MLLM judge 循环论证**。VIEScore、I2EBench、ImgEdit-Bench、KRIS-Bench、CompBench 都让 VLM 打分；而 VLM 本身就是差计数器（准确率随物体数量与种类崩塌、漏小编辑、打分不可靠）。**I2EBench 与 KRIS-Bench 甚至专门设了 counting 维度，却用 GPT-4V / GPT-4o 来判——把被测量的缺陷直接装进了尺子里。**
3. **没有"实例对应"概念**。当模型把两个人中的一个变成第三者，或删掉原物体后在别处画上目标物，judge 依然报成功。

所以作者的主张很硬：**数值编辑必须被验证，不能被评判（verified, not judged）**。

### 核心科学问题

给定源图 $I$、编辑图 $\hat I$、指令（操作 + 类别 + 数量 $N$），如何**不借助任何模型的主观判断**，确定：
- 目标类别**恰好**出现 $N$ 个新实例？（count fidelity）
- 原有同类实例**没有被覆盖/删除**？（original-category conservation）
- 目标区域外的场景**没有被改动**？（scene consistency）

### 为什么这篇对我们重要

我们的**图生图改写链路当前分流命中 0/0%**——这条链路的根本问题不是"改写不出来"，而是**"改完之后怎么算改对了"没有定义**。ABACUS 给出的是一个**完全不依赖 judge 的验证范式**：关掉模型意见，用检测器共识 + 全景真值 + 匈牙利匹配，把"编辑是否忠实"降解成可复现的几何与计数问题。这正是 I2I 语义保真评测缺的那块地基。

## 二、核心方法

### （1）三个操作、三层难度、一套协议

| 操作 | 语义 | 成功定义 |
|---|---|---|
| **Add** $N$ | 增加 $N$ 个类别 $c$ | 新增实例数 = $N$，且原有 $c$ 一个不少 |
| **Remove** $N$ | 删除 $N$ 个类别 $c$ | 被删实例数 = $N$，且没有幻觉新增 |
| **Change** $N$: $c_1 \to c_2$ | 把 $N$ 个 $c_1$ 改成 $c_2$ | **同一批实例原地变形**（位置重合），而不是"这儿删、那儿画" |

**难度不是拍的**，而是三分量复合分（各自秩归一化到 [0,1] 后相加）：
- 前景覆盖率（前景像素占比）
- 目标数量上限（$N_{\max}$）
- 目标物体尺度占比（越小越难）

按三分位切成 easy / medium / hard。作者的**非循环性检验**做得漂亮：不进入难度分的场景属性（实例数、类别数、拥挤度）仍能分开三档，且模型性能在三档上单调下降。

### （2）Benchmark 构造：五步，且"真值来自标注不来自模型"

1. **源与真值计数**：COCO 图 + COCONut 全景掩码 → 每个 {图, thing 类} 得到实例数 $N_{\text{GT}}$。
2. **检测器验证的可删性审计**：RF-DETR 与 Co-DETR 双检测器在**原图**上都必须检出 ≥1 个该类实例（真值被独立确认，不是"假定"）；再用**经典 Navier-Stokes inpaint**（非生成式）把该类区域抹掉，两检测器都必须检出 0。**只有这一步通过的 pair 才入池**——这保证"计数是真的"且"删得干净"。
3. **可加性检查**：Qwen3.6-27B 判断场景是否有可见位置再放一个该类实例。
4. **最优可加数**：同模型估计自然可插入的最大实例数，得 $N_{\max}$。
5. **指令生成 + 人工复核**：$N$ 从 $[1, N]$ 或 $[1, N_{\max}]$ 均匀采样；**每条样本两名标注员复核、第三人仲裁**，确认编辑可行且难度档正确。

关键纪律：**VLM 只在造数据时提建议，永不设定真值、永不判编辑**；双检测器审计只在**源图**上跑，与编辑图评测完全隔离，所以"基准选样"不会抬高任何模型的分数。

规模：**10,944 条指令 / 3,845 张 COCO 源图**（平均 2.85 条/图），覆盖全部 80 类、72 个 change 配对；Add 3,896 / Remove 3,794 / Change 3,254。

### （3）Judge-free 评测：四阶段管线

以 Add 为主线（Remove 是其镜像，Change 是两者耦合）：

**阶段 1 · 新实例发现（Novelty Discovery）**
- 取两路定位：$I$ 的全景掩码；SAM 3（presence-gated，以类别名为 prompt，presence 分数过阈才留掩码）在 $I$ 与 $\hat I$ 上分别分割。
- 用**抗漂移的复合几何分**匹配源实例与编辑后实例：

$$S_{ij} = \text{IoU} \cdot \text{contain} \cdot \text{size-ratio} \cdot \text{contour}$$

  其中 contour 项来自 Hu 矩形状匹配，且**除非两质心距离小于图像对角线的一个比例，该项被门控为 0**（防止远距离误配）。
- 全局一对一分配用**匈牙利算法**，只有 $S_{ij}$ 与掩码内像素相似度同时过阈才保留匹配 → 被匹配的是"原有实例"，未匹配的是"新实例候选"。
- 因为全景标注本身不全，每个候选回查 SAM 3 的源图分割：若源图里已有高置信对应物，就改判为"原有"而非"新增"（**真值修复**）。
- 五个阈值一次性固定、**从不调参**；敏感性扫描显示 4 个是惰性的，最敏感的一个最多影响 ≤1 个百分点的吻合率。

**阶段 2 · 干净图构建（Clean-image Construction）**
把已匹配的"保留场景"用**Non-Local Patch-Based inpainting（非生成式）**擦掉，再把新实例区域合成回来。这样即使新物体挡在旧物体前面或与之重叠，也能被单独计数。**这是"重叠场景"能算对的关键一步。**

**阶段 3 · 双检测器表决（Detection）**
RF-DETR 与 Co-DETR 在干净图上跑，对每个 SAM 定位的新掩码各自回答"是否有一个 $c$ 的框与它重叠"，**两者都同意才确认**。注意表决是"每个检测器各自与 SAM 区域对齐"，而不是"两个检测器互相对框"——这样能救回两检测器都看到但框略有差异的物体，同时仍挡住单检测器的类别误报。

**阶段 4 · 歧义消解（Ambiguity Resolution）**
仅对检测器未确认的极少数候选（约 6% 实例），Real-ESRGAN 超分 + 带上下文裁剪，交给受约束的 verifier（Qwen3.6-27B）回答唯一一个是/否问题"框里是不是 $c$？"。**它只确认类别，不计数、不判编辑成败。**

### （4）评分：三个因子相乘，且故意不留余地

$$\text{Score} = \text{CF} \times \text{SC} \times \text{OC}$$

- **CF（count fidelity）** = 计数上的 Dice 系数（precision 项与 recall 项调和平均），$N_{\text{real}} = N_{\text{req}}$ 时恰为 1，多加与少加对称受罚。
- **OC（original-category conservation）** = $1 - \frac{N_{\text{destroyed}}}{N_{\text{orig}}}$。专抓 CF 看不见的作弊：**通过重生/搬移一个原有实例来"凑够数量"**。
- **SC（scene consistency）** = 结构项与外观项的调和平均。结构项用稠密光流（静态背景→0 流→满分，任何位移/扭曲指数衰减）；外观项用多尺度 SSIM。**先把新物体区域用原像素盖回去**，所以它只测背景。

**为什么必须相乘**：作者做了对照——用简单平均时，"什么都不做"的编辑器几乎追平最好的模型；乘积则直接把它踢出去。同时"改坏背景换对数量"和"覆盖旧物体换对数量"都拿不到分。

Change 的评分是 Remove+Add 的耦合：只有**被删的 $c_1$ 与新增的 $c_2$ 位置重合**才算真正的原地变形 $T$，分母同时惩罚"没 $c_1$ 的地方画了 $c_2$"和"删了 $c_1$ 没补 $c_2$"。**这直接否决了"这里删、那里画"的假成功。**

## 三、技术细节

| 组件 | 具体选型 | 备注 |
|---|---|---|
| 全景真值 | COCONut | 承认其残余缺陷，管线设计上容忍并修复 |
| 检测器 | RF-DETR + Co-DETR | 双检测器共识；单检测器会被类别误报拖死 |
| 概念分割 | SAM 3（presence-gated） | 以类别名为 prompt，分数过阈才保留，挡幻觉掩码 |
| 实例匹配 | 复合几何分 + 匈牙利算法 | 掩码重叠/包含/尺度比/Hu 矩轮廓，带质心距离门控 |
| 非生成式填充 | Non-Local Patch-Based Inpainting、Navier-Stokes | **刻意不用生成式**，保证不引入新内容 |
| 场景一致性 | 稠密光流 + 多尺度 SSIM，调和平均 | 彩色对但扭曲 → 低分；不扭曲但变色 → 低分 |
| 类别歧义 | Qwen3.6-27B（约束式是/否） | 仅覆盖约 6% 实例，消融显示贡献最小（0.82→0.79） |
| 人类验证集 | 600 图（Seedream 4.0 生成，覆盖 79/80 类） | 真值标"编辑图里真实目标数"，**不标 prompt 里的 $N$** |

**一个必须记住的方法论细节**：验证集的人工真值标的是**编辑图里实际有几个目标物体**，而不是 prompt 里要求的 $N$。因为编辑模型经常给不对数量，若拿 $N$ 当真值，就等于**奖励"鹦鹉学舌报出 $N$"的评测器**，把编辑器的失败算成评测器的成功。

## 四、实验与结果

### 4.1 评测器与人类计数的一致性（600 图）

| 评测器 | Easy | Medium | Hard | Overall |
|---|---|---|---|---|
| Grounding-DINO（单开放词表检测器） | 0.37 | 0.26 | 0.23 | **0.28** |
| Qwen3.6-27B（thinking 模式，纯 VLM 计数） | 0.71 | 0.54 | 0.45 | **0.55** |
| **ABACUS** | **0.89** | **0.82** | **0.76** | **0.82** |

单个开放词表检测器（正是 EdiVal-Agent 用来打 count-change 分的那个）**比纯 VLM 还差**——重复框、合并框、幻觉框一起上。这是"为什么必须双检测器共识"的直接证据。

全 Score 的其它因子也逐项对齐人类：OC 相关 0.97（平衡准确率 0.90）、change 对应性 0.95、SC 与人工场景一致性评分 ρ=0.87、总分与人工总评 ρ=0.88；整体与"双标注员人类天花板"相差约 **0.10**，且该差距在各难度档上平坦。

### 4.2 跨编辑器稳定性（每个编辑器 200 张编辑图，取自同一批源图，配对设计）

| 编辑器 | ABACUS | 纯 VLM | 单检测器 |
|---|---|---|---|
| Seedream 4.0 | 0.83 | 0.54 | 0.25 |
| Gemini 2.5 Flash Image | 0.81 | 0.53 | 0.24 |
| GPT-Image-1 | 0.81 | 0.51 | 0.23 |
| Qwen-Image-Edit | 0.80 | 0.47 | 0.22 |
| FLUX.1 Kontext | 0.80 | 0.43 | 0.20 |
| Step1X-Edit | 0.80 | 0.41 | 0.18 |
| BAGEL | 0.79 | 0.37 | 0.16 |
| **均值（std）** | **0.81 (0.013)** | 0.47 (0.065) | 0.21 (0.033) |

**这是全文最有说服力的数字**：编辑器从强到弱，ABACUS 只动 0.04（σ=0.013），纯 VLM 塌 0.17，单检测器塌 0.09。**评测器不该跟着被评对象一起变差。** ABACUS 的排名与人类一致（Spearman ρ=0.96）。

### 4.3 七个编辑器的排行榜（Overall：CF / SC / OC / Score）

| 模型 | CF | SC | OC | **Score** |
|---|---|---|---|---|
| Seedream 4.0 | 0.60 | 0.79 | 0.66 | **0.31** |
| Gemini 2.5 Flash Image | 0.59 | 0.77 | 0.64 | **0.29** |
| GPT-Image-1 | 0.56 | 0.75 | 0.62 | **0.26** |
| Qwen-Image-Edit | 0.42 | 0.69 | 0.55 | **0.16** |
| FLUX.1 Kontext | 0.39 | 0.67 | 0.53 | **0.14** |
| Step1X-Edit | 0.34 | 0.64 | 0.50 | **0.11** |
| BAGEL | 0.30 | 0.62 | 0.47 | **0.09** |

最强系统也只有 **0.31**。分解来看：**CF 是最弱因子，OC 次弱，SC 一直很高**——即"背景保留得挺好，但该数的东西数不对，还顺手把原有的同类物体覆盖了"。在 cell 级（操作 × 难度）上更惨：Change-Hard 档 Seedream 只有 0.14，Gemini 0.12，BAGEL 0.03。

### 4.4 消融

| 移除组件 | 精确计数吻合率 |
|---|---|
| 完整 ABACUS | **0.82** |
| 去掉一对一匹配（源掩码就地复用） | **0.36**（−46 pt，最致命） |
| 去掉干净图隔离 | ≈0.72（−10） |
| 去掉真值修复 | ≈0.72（−10） |
| 只留单检测器 | ≈0.72（−10） |
| 去掉约束式 VLM verifier | 0.79（−3，贡献最小） |

"去掉一对一匹配"崩塌到 0.36 的机制值得记：编辑器的小幅位移/缩放会让源掩码"盖不住任何东西"，于是被保留的旧物体**没被掩掉、被重新算成新增**。**这就是"匹配"而不是"分割"才是这个问题的核心。**

## 五、局限性

1. **闭集限制**：设计上限定在 80 个 COCO thing 类。judge-free 确认需要固定检测器词表，词表外检测器直接返回空。稀有类要换开放词表检测器，而开放词表检测器**恰恰是计数不可靠的那个**（本文自己量化的）。
2. **只测"数量 + 场景 + 原类保留"，不测"选了哪几个实例"**。当 $N < N_{\text{orig}}$ 时，任何合法的 $N$ 子集都算满足指令。
3. **不测属性/位置约束**：指令被刻意写得极简（"add $N$ {category}"），目的是只探计数能力，不掺空间推理与属性绑定。作者把它列为下一步。
4. **FID/画质不在评测范围内**：作者明确说"艺术风格保真 deliberate out of scope"。
5. **构建依赖人工复核**：10,944 条样本每条两人复核 + 仲裁，成本不低，难以周级刷新。
6. **SC 的光流项对大幅 legit 变形敏感**：若编辑本身就该改变背景（如换景），SC 分会不公允。

## 六、复现指南

### 6.1 复现要点

```
1. 数据：COCO + COCONut 全景掩码；每 {图,类} 过双检测器可删性审计（原图 ≥1、inpaint 后 =0）
2. 造数据：Qwen3.6-27B 只做"可加性/可加数"建议；指令模板极简；两人复核 + 仲裁
3. 评测：SAM3(presence-gated) 分割 + 匈牙利匹配（复合几何分 + 质心门控）
        → 干净图（非生成式 inpaint）→ RF-DETR/Co-DETR 双表决 → 极少数走约束式 VLM 是非题
4. 评分：Score = CF × SC × OC（乘积，非均值）
5. 验证：真值标"编辑图实际数量"，绝不标 prompt 里的 N
```

### 6.2 复现风险点

- SAM 3 / RF-DETR / Co-DETR 三个模型的版本必须固定，否则匹配阈值需重调（作者强调阈值一次性固定不重调，换版本会破坏这个前提）。
- "干净图"必须用**非生成式** inpaint；换成生成式会引入新内容，把新增计数污染。
- 光流项对分辨率敏感，评测分辨率要与训练时一致。
- 600 图人类验证集由 Seedream 4.0 生成，换编辑器后需重跑一致性验证（虽然 5.2 已证明稳定性，但那是在同一批源图上）。

### 6.3 对我们最有用的最小实验（I2I 编辑改写链路的"先定义对错"）

**背景**：我们的图生图改写分流命中 0/0%——大概率不是模型不行，是**没有可判定的成功定义**，于是没人敢打开这条链路。

**建议动作（零训练，一到两天）**：

1. **从我们已有的编辑指令里抽 300 条**，只保留"数量/增删改"可判定的那部分（"把背景两个人去掉"、"把短袖换成长袖"），人工标"编辑图里目标类实际有几个"作为真值——**不要标指令里的数字**。
2. **跑三个判据做交叉对照**：① 现成的 VLM judge（我们图审模型复用作 judge）；② 单检测器计数；③ ABACUS 式"检测器共识 + 实例匹配"。
3. **判据**：如果 ①③ 的判定在 300 条上分歧 > 25%，说明我们现有 judge 在数不清的事情上给分，**I2I 链路的评测尺子本身就是不可用的**；此时应先补尺子，再谈分流命中率。
4. **顺带的副产品**：SC（光流 + SSIM）那一项可以直接拿来当"I2I 改写是否只动了该动的地方"的硬指标——**这恰好是编辑指令改写最需要的"局部改动保真度"**，比整图相似度有用得多。

### 6.4 与"可验证奖励"的关系（对我们 RL 改写的直接含义）

作者在引言里顺手提了一句很关键的话：因为 ABACUS 是 judge-free、确定性、基于检测证据的，**它可以直接当 RLVR 的可验证奖励**，去后训练编辑器的精确计数——而"学出来的 VLM 奖励会噪、会被 hack"。

这对我们 RL 改写奖励的启示是：**能换成"可验证判据"的维度，就不要用学出来的奖励模型。** 我们现在的图像一致性奖励（Qwen-Image 类）本质是学出来的偏好分，而"改写后画面里该有的主体是否还在、该删的是否真删了"是有几何判据的——这部分应该从奖励里剥出来，做成硬约束而不是软奖励。
