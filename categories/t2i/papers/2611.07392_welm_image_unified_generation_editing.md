## 一、背景与问题

### 动机

这不是一篇安全论文。它是**一份大厂统一生图模型的完整工程账本**，而它对本项目的价值恰在此处：**它把"我们每天在调的那些东西"（类目粒度、加权、门槛、奖励、数据配比、延迟）全部落到了可复现的数字上**，并且是在真实消费级产品（微信）的部署约束下。

论文要解决的问题是：一个模型同时做文生图、指令式编辑、多参考合成，并且**单卡部署**。

三件工程事实决定了它的技术选型：

| 约束 | 具体数字 | 后果 |
|---|---|---|
| 部署形态 | 微信大规模消费级应用，**单 GPU** | 参数量可以大，激活量必须小 |
| 分辨率 | 原生 **1.5K** | 长序列 → 必须做上下文并行 |
| 任务异质性 | 生成 / 编辑 / 多参考是有冲突的优化目标 | 不能让理解通路污染生成通路 |

### 为什么值得读

因为它把三件我们长期当成"约定"的事写成了数字：

1. **数据过滤算子不做二值门，做属性提取器**——"这些过滤算子同时充当属性提取器，而不只是二值门。它们的细粒度质量、分辨率、安全与内容信号被保留下来，用于下游采样、路由、混合构建与分布诊断。"
2. **高频类目的通过率上涨不能掩盖长尾失败**——必须有分维度记账。
3. **编辑奖励用乘性门，不许用加权和补偿**——这条直接对应我们 10-29 提的 E1（三维聚合改几何平均）。

### 三条论断

1. 统一生成与编辑的关键不是共享参数，而是**共享一个交织序列接口**，让多任务退化成序列训练问题，从而复用成熟的 LLM 训练栈。
2. 奖励设计的核心矛盾是**异质维度不可比**：必须先在 rollout 组内分别归一化再聚合，且必须有一个维度充当**乘性门**而不是可补偿项。
3. 数据侧的收益来自**结构**（知识锚定词表 + 大规模视觉聚类），不是来自堆量——5B 原始池筛到 0.6B，靠的是覆盖率与平衡度两个正交坐标。

## 二、核心方法

### 2.1 统一交织序列 + MoT-MoE

文本、参考图、目标 latent 被拼成**一条交织序列**。骨干是 Mixture-of-Transformers（MoT）：共享注意力，但理解通路与生成通路各有独立参数，以"限制优化干扰"。

MoE 提供稀疏容量：**31.7B 存储参数，每个目标 latent token 激活约 5.4B 生成参数**。

这个数字对本项目有意义：**"大模型"在部署时可能只激活 1/6**——所以"我们没有算力训大模型"这个判断，需要先问"激活量是多少"。

### 2.2 数据引擎：覆盖率 × 平衡度

```
原始池 ~5B 图（内部 + 互联网 + 公开集 + 授权集）
   ↓ 分辨率阈值 / 模糊与清晰度 / 去重 / 安全过滤
精编池 ~0.6B（保留率 12%）
   ↓ 知识锚定语义词表（让具名视觉概念可寻址）
   ↓ 大规模视觉聚类（把"没有名字但外观一致"的图分组）
任务数据：T2I / 指令编辑 / 多参考 / 理解（含 VQA）
   ↓ 训练期评测回流 → 过滤、采样、混合比例
```

两个细节必须单独记：

**（a）安全过滤只是四个算子之一，且它的输出不丢弃。**
原文："低分辨率、模糊、重复、**不安全**以及其他低质量样本被移除，**色情或其他性明确 NSFW 内容在下游标注与训练之前被排除**。"

但紧接着一句更重要："过滤算子同时充当属性提取器，而不只是二值门。"

⇒ **对我们的直接含义**：图审模型的分数不应该只用来做"过/不过"的开关。**保留连续分数**，下游可以做采样加权、路由、混合构建、分布诊断。我们现在的 `sft_train.image_only` 只输出类别，等于把一个连续信号压成了一个比特。

**（b）保留集的构成是可审计的。**
保留的 0.6B 图里 **59.74%** 落在 1024 及以上分辨率组。这个数字之所以值得记，是因为它说明**过滤后的池子有明确的分布画像**，而不是"筛完就不知道剩了什么"。

### 2.3 编辑奖励：一道乘性门 + 三态判定

这是全文对我们最有价值的一段。

**数据侧**：把编辑指令分 **27 类动作（27 editing action types）**，用这个分类法过滤训练数据。难度分档 easy / medium / hard 目标配比 **3 : 5 : 2**，并且**在每个动作类内部再剔除难度两端**——成功率接近 0 的（太难）和接近饱和的（太易）。

原文："这种过滤保留了更有信息量的样本，它们提供更强的学习信号。"

⇒ 这就是**主动学习挑差异样本**的工业实现：不是"挑不确定的"，是"**剔除两端极端，保留中间带**"。

**奖励侧**：离线用 VLM 为每条指令生成一份 checklist，覆盖三个维度：

| 维度 | 记号 | 判定 |
|---|---|---|
| Prompt following | $r_P$ | 是否执行了指令 |
| Consistency | $r_C$ | 非目标区域是否保持 |
| Visual quality | $r_Q$ | 视觉质量 |

每条判据的状态是**三态**：`pass` / `fail` / `not-assessable`。失败判据额外带 mild / medium / severe 三级严重度。扣分由"判据重要性 × 失败严重度"联合决定，从固定分预算里减，再归一化到 $[0,1]$。

聚合是**乘性门**：

$$r_{\text{edit}} = r_P \times (0.4 + 0.4 r_C + 0.2 r_Q)$$

原文理由："这防止高一致性或高视觉质量补偿执行编辑指令的失败。"

**注意 $r_P$ 不在括号里。** 它是门，不是项。$r_C$ 与 $r_Q$ 在括号内可互相补偿（权重 0.4 / 0.2），$r_P$ 一旦塌了就整体塌。**"不可补偿"只给了一个维度，其余维度仍可补偿**——这是一个比"全改几何平均"更细的设计。

### 2.4 T2I 奖励：四路异质奖励 + 组内分别归一化

四个独立训练的 VLM 奖励：图文对齐、美学、文字渲染、视觉自然度。用 **GDPO** 在 rollout 组内**分别**归一化每个维度，再聚合。

对齐奖励是 rubric 式的（RubricRL 风格），四个设计点：

1. **rubric 构建是 image-blind 的**——先看 prompt 造 rubric，再看图。且同一 prompt 的所有 rollout 复用同一份 rubric，保证组内同标准。
2. rubric 从**受控判据池**实例化，池子按实际重要的对齐维度组织：物体存在与计数、渲染文字、属性、空间关系、动作、否定、风格/布局约束。
3. 每条 prompt、每条判据都带**维度标签**。整条流水线离线跑完，因此标签可用于**类别感知采样**与"按当前模型的失败模式系统性重采样离线语料"。
4. 原文最关键的一句："**由于通过率按维度分别追踪，高频类目的收益不能掩盖长尾类目的持续失败。**"

聚合方式也值得记：判官看到的是**同一 prompt 的全部 rollout 作为一个组**，而不是逐条打分。理由是"组内评分提供共享比较语境，降低跨调用校准方差"。

### 2.5 prompt 筛选：按"可学性"留，不按"难度"留

在线训练前先做离线 rollout，估计每条 prompt 的复合奖励**均值与方差**，然后：

- 保留**均值落在目标区间内**的 prompt（既不是已经解决，也不是稳定失败）；
- 且**方差超过阈值**（组内有对比信号）。

⇒ "把 RL 更新集中在可学习的样本上，它们能提供有信息量的组内对比。"

这解决了 RL 里一个真实问题：**全对的 prompt 与全错的 prompt 都提供零梯度**。

### 2.6 编辑 RL 的两个训练技巧

- **中度 CFG 做 rollout，但把无条件分支排除出训练目标**——"提高奖励可靠性与训练稳定性"。
- 采样步数减半以加速。
- 两个 RL 分支（T2I / 编辑）收敛后，用 **噪声感知的 on-policy 蒸馏**合并成单一 student 检查点，消除推理时切换 adapter 的需要。

## 三、技术细节

### 3.1 影像 tokenizer 与 3D RoPE

- VAE 独立训练，报告重建与生成两套指标。
- 统一 **3D RoPE**，且**与预训练文本 RoPE 兼容**：交织轴分配 + 视觉 token 坐标单独定义。这是"能直接吃预训练 LLM 权重"的前提。
- 训练用 **token packing + FSDP + Ulysses 上下文并行**，支持打包到 **64K token** 的上下文；MoE 留了专家并行（EP）的口子，但**报告配置里 EP size = 1**。

### 3.2 延迟账本（Table 4，单卡 H20，1024×1024 输出）

| 模型 | 步数 | T2I 1024×1024 | 编辑 1 图 | 2 图 | 3 图 | 4 图 |
|---|---|---|---|---|---|---|
| Qwen-Image-2512 | 50 | 67.13 | — | — | — | — |
| Qwen-Image-Edit-2511 | 40 | — | **133.04** | 233.24 | 360.18 | 510.64 |
| Qwen-Image-Edit-2511-Lightning | 4 | — | 7.52 | 12.82 | 19.56 | 27.35 |
| SenseNova-U1-8B-MoT | 50 | 16.99 | 18.30 | 19.91 | 21.55 | 23.44 |
| HunyuanImage-3.0-Instruct-Distil † | 8 | 12.20 | 16.79 | 21.97 | 27.65 | — |
| **WeLM-Image** | 50 | 56.99 | 67.71 | 78.43 | 89.24 | 100.18 |
| **WeLM-Image-Turbo-8step** | 8 | **4.98** | 6.78 | 8.78 | 10.92 | **13.17** |

读这张表必须注意三件事，论文自己都写了：

1. **† Hunyuan 那一行是 4 卡张量并行**，per-instance 延迟对应 4 倍加速器成本。
2. **Lightning / Turbo 是 guidance-free（`true_cfg_scale = 1`），每步一次前向；标准配置用 CFG，每步两次。** ⇒ "步数"这个数字会**低估**两类配置之间的真实算力差，低估约 2 倍。
3. 这些结果"刻画的是发布时的推理设置，而不是隔离架构效率"。且模型跑的是 PyTorch 原生 scaled dot-product attention，**没有 kernel 加速、量化、步缓存、图编译** ⇒ 数字是"未优化上界"。

### 3.3 分辨率扩展性

1024×576 → 1024×1024，像素数涨 **1.78×**，而：

| 模型 | 延迟增长 |
|---|---|
| **WeLM-Image** | **1.73×** |
| Qwen-Image-2512 | 1.87× |
| Z-Image | 1.85× |

⇒ 增长倍数低于像素增长倍数，说明成本"接近线性于 token 数"而不是超线性。这对"多参考输入"是关键——**编辑的代价随输入图数量增长，而不是随画布增长**。

### 3.4 编辑动作分类法的用途

27 类动作同时服务三件事：数据过滤（按类配额）、checklist 生成（以动作标签为任务级语境）、奖励路由。原文："生成器以对应的动作标签为任务级语境，使其能够定义针对该编辑类别的评估维度与判据。"

⇒ **类目粒度不是为了统计，是为了给判官提供语境。** 这是本轮另一篇（Reweighting）的反面：**类目标签用错了会把误差搬来搬去；用对了是给判官省一次推理。**

## 五、局限性

### 5.1 论文自述

- **延迟未优化**：无 kernel 加速、量化、步缓存、图编译 ⇒ 数字是上界不是下界。
- **闭源模型排除在排名外**，只作参照。
- **MICo 的 7.97 分缺口**未给解释。
- **Turbo 的降级在多图任务上更明显**，未给原因。

### 5.2 本报告补充的三条

1. **安全只是一句话。** 全文关于安全的内容只有"NSFW 内容在下游标注与训练之前被排除"这一句，加上"过滤算子保留细粒度安全信号"。**没有任何安全评测、没有 NSFW 漏过率、没有对抗测试。** ⇒ 这是头部公司公开的统一生图技术报告里，**安全部分的全部篇幅**。这个"篇幅为零"本身是一个信号：**工业界把安全当作数据管线的一个前置算子，不当作模型能力**。

2. **"过滤算子保留分数"这句话没有给出任何下游用法。** 论文说信号"被保留下来，用于下游采样、路由、混合构建与分布诊断"，但没有一个实验显示这样做比二值门好。⇒ 这是一条**设计原则，不是实证结论**。迁移时要说清是"原则"不是"证据"。

3. **GDPO 的归一化细节未披露。** "在 rollout 组内分别归一化"——是 z-score 还是 min-max？是否用组内极差？这决定了它对异常值的鲁棒性。**无法复现**。

## 六、复现指南

### 6.1 依赖与入口

无需代码即可迁移的部分（本报告的主要用法）：**奖励聚合成式、难度分档策略、prompt 筛选规则、分维度记账要求**。

需要模型才能复现的部分：**全部 benchmark 数字**（31.7B 存储参数量，单卡 5.4B 激活，需 H20 80GB 级别）。

### 6.2 最小可迁移实验（零训练）

**目标**：验证我们的编辑评测是否存在"可补偿"问题。

1. 取现有图生图评测的 2000 条样本（1979 有效），按现有维度拆成三项：指令遵循、非目标区域保持、视觉质量。
2. 用现有 judge 分别打分，得到 $r_P, r_C, r_Q$。
3. 计算三种聚合：
   - 现用：加权和 $w_1 r_P + w_2 r_C + w_3 r_Q$
   - 乘性门：$r_P(0.4 + 0.4 r_C + 0.2 r_Q)$
   - 几何平均：$(r_P r_C r_Q)^{1/3}$
4. **报三个数**：① 三种聚合下的排名翻转率；② $r_P < 0.3$ 但总分 > 0.7 的样本数（这些是"没改对但被补偿"）；③ 当前 6 个模型版本的排序在三种聚合下是否一致。

**判据**：若"$r_P < 0.3$ 且总分 > 0.7"的样本 > 5%，说明现有评测**允许"没执行指令"被"没破坏原图"补偿掉**——这正好是 I2I 改写 0/0% 的一种可能解释（改写后指令没被执行，但图没变所以"一致性"满分）。

### 6.3 数据构造要点（若能拿到编辑模型）

- 27 类动作分类法可先借用作**我们自己的编辑指令类目树**（当前 I2I 侧只有粗粒度分流）。
- 难度配比 3:5:2，且**每类内部剔除两端**。落地方法：对每条指令跑 N 次编辑，按成功率分档，成功率 <5% 与 >95% 的剔除。
- checklist 用**三态**（pass / fail / not-assessable）。`not-assessable` 是关键——它把"判不了"从"判错"里分离出来。

### 6.4 评测要点

- **不要只报 macro 均分**。论文自己的 Table 10 显示，同一模型 HarmB 96.4 而 WildG 71.9。
- **报告"分维度通过率"**，且必须能看出长尾维度有没有在动。
- guidance-free 与 CFG 的步数不可直接比。若要做延迟对比，必须注明每步前向次数。
