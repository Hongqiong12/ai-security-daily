## 一、背景与问题

### 动机

指令式编辑模型**不是可互换的**。同一张图 + 同一条指令，不同模型出来的结果差得很远，而且**哪个模型最好会随样本变**：擅长创意全局改风格的可能破坏细节与空间结构，擅长精确局部操作的可能做不好全局一致的变换。同时它们的**推理时延差一个量级**（4B 的 FLUX Klein 到 20B 的 Qwen-Image-Edit 到 80B 的 HunyuanImage-3.0-Instruct）。

于是"固定用一个默认模型（通常是最大最强的那个）"这件事在工程上是纯浪费：简单请求白烧算力，难请求又没被分到最合适的。

### 核心科学问题

给定 $(I, t)$ 和候选池 $\{M_1..M_K\}$，在**生成之前**选一个 $M_k$。难点是：**选的时候你还不知道每个候选会打成什么样**。

### 为什么这篇对我们重要

我们的**图生图改写分流命中 0/0%** —— 现状大概率是靠规则/关键词判断"这条指令该走编辑还是走文生图"，而规则在指令空间里没有分辨率。EditJev 给的是一条完全不同的路：**不做二分类，而是在候选池上做"样本级偏好打分"**，且用 **pairwise ranking** 而不是绝对分回归或单选生成。

对分流的直接迁移是：**把"是否属于编辑指令"改成"编辑器 vs 生成器"两候选的偏好排序问题**。这样输出的是一个可比较的分数 + 校准过的不确定性，而不是一个硬阈值。**分流 0/0% 的根因往往是没有分数、只有阈值**。

## 二、核心方法

### （1）问题形式化

路由策略 $\pi: (I, t, \{M_k\}) \to k$。每对 $(I,t)$ 上候选 $k$ 的真实质量为 $q_k(I,t)$、平均端到端时延为 $\ell_k$。目标是质量-时延折中——但**推理时 $q_k$ 不可见**。

### （2）System One：一次前向出定长分数向量

与传统 MLLM 路由器（自回归吐出模型名 + 后处理解析）不同，EditJev 直接输出数值分数：

1. 用固定模板把"编辑请求 + 候选模型列表"渲染成 prompt $x$；
2. MLLM 骨干编码，取**最后一个非 padding token** 的隐状态 $h$ 作为请求表示：

$$h = H_\theta(x)_{[L]} \in \mathbb{R}^d$$

3. 轻量偏好头 $g_\phi$ 映射成候选池上的分数向量：

$$s = g_\phi(h) \in \mathbb{R}^K$$

**没有自回归解码、没有模型名生成、没有响应解析。** 这就是 "System One"（快、结构化决策）的含义。

### （3）时延感知选择

把每个候选的平均时延归一化成"速度分"：

$$\text{speed}_k = \frac{\ell_{\max} - \ell_k}{\ell_{\max} - \ell_{\min}}$$

最终选择：

$$k^\* = \arg\max_k \big( s_k + \lambda \cdot \text{speed}_k \big)$$

$\lambda$ 是**推理时可调、免训练**的质量-时延旋钮。

### （4）训练：用离线候选输出造 pairwise 偏好

对每个训练请求，**把全部候选都跑一遍**（离线），用 MLLM 评测器按 VIEScore 四维打分（编辑成功、该保留的保留、自然度、无伪影），各 0–10：
- 语义一致性 $s_{\text{sc}}$ = min(编辑成功, 保留)
- 感知质量 $s_{\text{pq}}$ = min(自然度, 无伪影)
- 聚合质量 $q_k = \sqrt{s_{\text{sc}} \cdot s_{\text{pq}}}$（几何平均）

只保留**分差 ≥ 阈值 δ** 的有序对（δ 过滤掉近似并列、排序不可靠的对）：

$$\mathcal{P}(I,t) = \{(i,j) : q_i - q_j \ge \delta\}$$

**Pairwise ranking 损失**：

$$\mathcal{L} = \sum_{(i,j)\in\mathcal{P}} \max\big(0,\; \delta' - (s_i - s_j)\big)$$

配合 minibatch 聚合。

**为什么用排序不用回归或单选**（作者给了消融）：
- **MSE 回归**要求路由器预测评测器的**绝对分尺度**，学习问题更难；
- **MCQ 生成**把监督压成"唯一最优模型"一个标签，丢掉了其余候选之间的偏好关系；
- **排序**只依赖可靠的相对偏好，且一次请求能贡献**多个**有效对。

## 三、技术细节

| 项 | 设置 |
|---|---|
| 路由骨干 | **Qwen3-VL-4B-Instruct**，**冻结**，只训 LoRA + 线性偏好头 |
| 候选池 | FLUX.2 Klein 4B / FLUX.2 Klein 9B / FLUX.1-Kontext-dev / OmniGen2 / Qwen-Image-Edit（K=5） |
| 评测器 | GPT-5.1（主），按 VIEScore 四维 |
| 训练数据 | ImgEdit 737 条 + GEdit-En 606 条请求 |
| 分差阈值 δ | ImgEdit 与 GEdit-En 各自设定（正文以符号给出） |
| 时延测量 | NVIDIA RTX PRO 6000，官方推理配置，20 条请求平均 |
| 路由开销 | **94 ms / 请求**（本地推理，5 次平均） |
| 打分粒度 | 整图 + 随机裁剪区域都过同一个 [CLS] 头（裁剪让局部缺陷占比变大） |
| 基线 | 4 个通用 MLLM 路由器（GPT-5.5 / Gemini-3.7-Flash / GLM-5.3-Flash / Kimi-K3）+ Jev（System One 基线） |

**一个反直觉的实现细节**：路由骨干从 2B → 4B → 32B，总体分是 **4.5898 / 4.6002 / 4.5898** —— **更大骨干没有更好**。这说明路由任务要的是"请求-候选适配"的低维判别信号，不是更强的通用推理。对我们是好消息：**路由层可以是小模型**。

### 4.1 ImgEdit（9 个编辑类别）

关键对比：**比最强固定模型高 0.052，比最强 MLLM 路由器（GPT-5.5）高 0.212，而路由开销只有它的 1/126。**

| 方法 | ImgEdit (s) | GEdit-En (s) |
|---|---|---|

即 **2.55× / 1.46× 加速，且质量同时更高**。机制：偏好分接近时选更快的，质量优势足够大时选更慢的。

### 4.4 消融

| 变体 | Overall |
|---|---|
| MSE 回归 | 4.5545 |
| MCQ 生成 | 4.5491 |
| **Pairwise ranking（本文）** | **4.6002** |

**"去掉图像输入"只掉 0.029** —— 这个数字很值得警惕：说明在这个设置下，**路由决策的绝大部分信息在指令文本里，图只贡献很小一部分**。对"分流"任务的含义是：如果只做"编辑 vs 生成"的粗分流，**指令文本可能就够**；但要做"该选哪个编辑器"，图仍然必要。

### 4.5 时延旋钮（免训练调参）

λ 从 0 扫到 1：平均端到端时延从 26.79 降到 17.73 s（−33.8%），总体分从 4.5966 只降到 4.5667。主设置 λ 取中间值，得分 4.5916 / 22.33 s。

## 五、局限性

1. **候选池固定为 5 个、且是"有序列表"**。加/减候选需要重训偏好头（输出维度跟着 K 变）。
2. **偏好监督来自 MLLM 评测器（VIEScore 式）**。评测器的偏差会原样进入路由器——**这条链路的"分数不可信"问题没有被解决，只是被搬到了上游**。上周 Attractive Faces 那篇正好证明这类偏好分的语义与行为可以脱节。
3. **时延是静态均值**，不看当时的 GPU 负载/队列；生产环境需要动态时延。
4. **只做"选哪个编辑器"，不做"要不要编辑"**。分流本身不在论文范围内——这是我们要自己接的一步。
5. **提升幅度小**：ImgEdit +0.052 / GEdit +0.061，虽然稳定但离"质变"远。它的真正价值在**时延**（2.55×）与**开销**（94 ms）。
6. **消融显示图像输入贡献很小**（−0.029），削弱了"多模态路由"的叙事强度。

## 六、复现指南

### 6.1 复现要点

```
1. 骨干：Qwen3-VL-4B-Instruct 冻结；LoRA + 线性偏好头（输出维度 = 候选数 K）
2. 监督：每个训练请求跑满全部候选 → GPT-5.1 按 VIEScore 四维打分
        → q = sqrt(min(编辑成功,保留) * min(自然度,无伪影))
        → 只保留 q_i - q_j >= δ 的有序对
3. 损失：hinge ranking，δ' 为 margin
4. 推理：s = head(h_last)；k* = argmax(s_k + λ·speed_k)；λ 免训练可调
5. 时延：同硬件、官方配置、≥20 请求平均；路由开销单列
```

### 6.2 复现风险点

- 必须**离线跑满候选池**才能造监督，K 越大成本线性涨；候选池变更需重训。
- 评测器版本必须固定（论文用 GPT-5.1），换版本会改变偏好标签。
- δ（分差阈值）决定有效对数量与噪声，太小引入不可靠对、太大样本不够。
- 时延必须在目标硬件上实测，不能引用论文数字（论文是 RTX PRO 6000）。

### 6.3 对我们最有用的最小实验（I2I 分流 0/0% 的架构级修法）

**现状诊断**：分流命中 0/0% 说明现有判定**在所有样本上都判"不是编辑"**（或反之）。这类全 0/全 1 的失效几乎总是同一个原因：**判据是阈值型规则，而分数本身没有分辨率**。

**建议动作（改判据，不改模型，约两天）**：

1. **把分流从"分类"改成"两候选排序"**：候选 = {编辑器, 生成器}。用 EditJev 的结构——**同一条指令文本（+ 原图，如果有）编码成隐状态，接一个 2 维偏好头**。训练标签不用人工标，用**离线结果反推**：同一条指令分别走编辑器与生成器，用现成的图像一致性奖励 + 人工抽检 200 条判"哪条路的结果更符合意图"。
2. **关键改动：输出分数而不是布尔**。分流层必须吐出 $s_{\text{edit}} - s_{\text{gen}}$ 这个可比较的量，再叠一个业务侧的成本项（编辑器更贵/更慢就加惩罚），最后才做 argmax。**这一步就能让 0/0% 变成一条可调的 ROC 曲线**，而不是一个死掉的开关。
3. **判据**：如果改造后分流仍恒为单侧，说明**特征层面就没有区分信号**（指令文本被编码成了同一个方向）——此时问题不在阈值，要回去查指令分布（是不是所有样本的指令都长得一样），而不是继续调模型。
4. **顺带的低成本验证**：论文的"去掉图像输入只掉 0.029"提示，**先只用指令文本做分流基线**，若已经能分开，就不必上多模态；分不开再加图。**别一上来就上大模型。**

### 6.4 关于"路由层要小"的工程含义

2B / 4B / 32B 骨干得分 4.5898 / 4.6002 / 4.5898，**32B 没有更好**。在训练集群从 6 节点缩到 5 节点的现实下，这条结论直接可用：**分流/路由这一层用 2–4B 小模型 + LoRA 就够，算力应该留给改写主模型与图审主模型。** 路由层不该成为第五个吃卡的组件。
