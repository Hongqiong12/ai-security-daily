# DICE / Haste Makes Waste: 加速本身就是安全旋钮 —— 少步蒸馏把擦除方向转掉了

**论文主页**: https://arxiv.org/abs/2610.36665
**领域**: T2I 少步蒸馏安全性 / 权重侧概念擦除在蒸馏模型上失效的机制 / 推理步数作为隐性安全参数
**作者**: Lior Ziv, Mahmood Sharif
**机构**: **Tel Aviv University**（IEEE S&P 2027 接收）
**发布日期**: 2026-10-27（v1，cs.CV / cs.CR）
**分类**: attack + defense
**模态归属**: 文生图（T2I）— 权重侧安全治理，**与输入侧改写的互补关系与失效边界**

---

## 一、背景与问题

### 动机

工业 T2I 上线都在加速：FLUX Schnell（LADD 蒸馏）、SD3.5 Turbo（ADD 蒸馏），1–4 步出图。加速带来的是延迟下降，**但安全性从来没被当成一个随速度变化的量来测过**。

这篇问的是一个没人系统问过的问题：**把 50 步压到 4 步，安全率会不会跟着掉？**

答案是会，而且掉得比想象中多。更麻烦的是第二层：**就算你在少步模型上做概念擦除，擦除也失效了**——而且失效的原因不是"超参没调好"，是**擦除方向本身被蒸馏改掉了**。

### 核心科学问题

1. 少步学生模型 vs 全步教师，不安全生成率差多少？
2. 推理步数（一个纯工程参数）对安全率的影响有多大？
3. 现成的擦除方法（ESD / EraseAnything / UCE / SPEED）为什么在少步模型上不好使？
4. 如果擦除方向本身坏了，能不能改条件让它重新可用？

### 为什么这篇对我们重要

我们这条线的核心论点是"**不改生成模型、输入侧热更新改写**"。这个论点长期缺一个硬证据：**权重侧擦除到底在哪失效**。这篇给出了一个非常具体的答案——

**擦除失效不是"效果不够好"，是擦除的梯度方向在蒸馏后被旋转了。** SD3.5 Turbo 的擦除方向与教师方向的余弦相似度只有 **0.30**，FLUX Schnell 只有 **0.07**。方向都反了，步长调得再准也没用。

同时它给出一个我们上线必须知道的数：**推理步数是一个隐性安全参数**。把 FLUX Dev 从 50 步降到 16 步，NudeNet 不安全率从 0.2562 涨到 0.2808；降到 8 步时，CLIP 与"nudity"概念的相似度涨约 9%。**这意味着"为了省算力降步数"这个决定，本身是一次安全回退**，而且它不会出现在任何安全评审里。

## 二、核心方法

全文分三段：先测现象，再诊断机制，最后给方法（DICE）。

### （1）测：教师 vs 学生，以及"步数旋钮"

**模型对**：SD3.5 Large（教师）vs SD3.5 Turbo（学生，ADD）；FLUX Dev（教师）vs FLUX Schnell（学生，LADD）。因为 Schnell 的教师未公开，作者**自己用 SCFM 在 FLUX Dev 上蒸了一个 FLUX SCFM**，得到一个教师已知的受控对。

**不安全 prompt**：用 **NSFW-56k** 的随机 1K 子集（NSFW-1k），理由很实际——**I2P 的显式度不够**（"a lack of explicitness"），在不够显式的数据上测 NSFW，天花板会被数据本身压住。I2P 结果放附录。

**检测器**：NudeNet（CNN）+ SD-Checker（CLIP 系），论文称两者互相一致且与人类标注一致。

**新增指标 @k（这篇的评测贡献）**：对每个 prompt 用 $k=5$ 个不同种子各生成一张，**只要有一张被判不安全就记为不安全**。理由：真实攻击者会反复试。这个指标比单次检测率更接近实际风险，也让"少步模型多样性下降"的干扰被绕开（少步模型可能只是方差变小，@5 把"至少一次"暴露出来）。

**质量**：HPSv2（不用 FID，理由：prompt-conditioned、基于大规模人类偏好、更适合评 T2I）。FID / CLIP-S 在附录 COCO-30k 上另报。

### （2）诊断：三条独立证据指向同一个原因

**证据 A — 速度场变敏感（Lipschitz）**
对潜变量 $z$ 与权重 $\theta$ 分别估局部 Lipschitz 常数：

$$\mathbb{E}_{x_0 \sim \mathcal{D}}\left[\max_i \frac{\|v_\theta(z,\varnothing,t) - v_{\theta+\Delta_i}(z,\varnothing,t)\|}{\|\Delta_i\|}\right],\quad \Delta_{i,\ell} \sim \mathcal{N}(0,I)\ \text{按块归一化到}\ \epsilon\|\theta_\ell\|$$

配对 Lipschitz 比（学生/教师，中位数）：

| 模型族 | 对比 | $\text{lip}_z$ | $\text{lip}_\theta$ |
|---|---|---|---|
| FLUX | Dev vs Schnell | **4.78** | **4.37** |
| FLUX | Dev vs SCFM（轻蒸馏） | 1.01 | 1.07 |
| SD3.5 | Large vs Turbo | 1.81 | 2.32 |

而且**少步模型的敏感性在高噪声端（$\sigma_t \approx 1$）最大**，与全步模型的趋势相反。

**证据 B — 擦除方向被旋转且被放大**
概念方向 $\delta = v(z,c) - v(z,\varnothing)$，教师对应 $\delta^* = v^*(z,c) - v^*(z,\varnothing)$。用**真实图**（LAION-Pop）构造 off-policy 潜变量，1000 个 image-timestep 对，$\sigma_t$ 在 $[0,1]$ 均匀采：

| 学生 | 与教师 $\delta^*$ 的余弦 | 幅值膨胀 |
|---|---|---|
| SD3.5 Turbo | **0.30** | ≈ 1.2–3.9× |
| FLUX Schnell | **0.07** | ≈ 2–5× |
| FLUX SCFM（轻） | 0.64 | ≈ 1.4× |

关键补充：四个速度场 $\|v(z,c)\|$、$\|v(z,\varnothing)\|$、$\|v^*(z,c)\|$、$\|v^*(z,\varnothing)\|$ 的**范数相近**——所以 $\delta$ 的膨胀不是"预测变大了"，而是**条件项与无条件项相互抵消变差了**。

**证据 C — CFG 烘焙是主因**
FLUX Dev / FLUX SCFM 把 guidance scale 当网络输入，可以直接扫：FLUX Dev 从 CFG 1.0 提到 3.5，$\|\delta\|$ 从 **17.8 涨到 64.1（约 3.6×）**；FLUX SCFM 从 CFG 1.0 的 18.6 涨到 CFG 5.0 的 **90.2**。**单纯提高 guidance 就复现了少步模型的膨胀**。

机制解释很干净：少步模型（ADD/LADD）把 CFG 烘焙进条件分支，于是 $v(z,c) \approx v^*(z,\varnothing) + \omega(v^*(z,c) - v^*(z,\varnothing))$，**而 $v(z,c) \not\approx v^*(z,c)$**。形成 $\delta$ 的两条分支被蒸馏改得不一样（无条件分支在 LADD/SCFM 里根本没被直接训），**而 ESD 恰恰假设这两条分支一起被优化**。

### （3）DICE：为少步模型重写的擦除

选**蒸馏后擦除**（post-distillation）这条路线，理由两条：教师模型不需要可获得（FLUX Schnell 的教师就不公开）；每加一个要擦的概念不用重跑一次昂贵的蒸馏。

三个损失加权和：$\mathcal{L}_{\text{DICE}} = \mathbb{E}_{c,t,z}[\mathcal{L}_{\text{esd}} + \lambda_1 \mathcal{L}_{\text{attn}} + \lambda_2 \mathcal{L}_{\text{gen}}]$

- $\mathcal{L}_{\text{esd}}$：保留 ESD 抑制目标（作者的解释：诊断显示速度与擦除不是本质冲突，**冲突出在优化条件上**）；
- $\mathcal{L}_{\text{attn}}$：沿用 EraseAnything 的注意力图抑制，直接压概念 token 的注意力质量，作为**不依赖 ESD 方向的第二条擦除通路**；
- $\mathcal{L}_{\text{gen}} = \|v_\theta(z,c,t) - v_{\theta^*}(z,c,t)\|_2^2$：**对擦除前的少步 checkpoint 自蒸馏**，初始值为 0，只在漂移时产生梯度。

两个配套改动直击诊断出的两个病：

**① 直通路径潜变量构造（治方向退化）**

$$z = x_0 + \sigma_t(x_1 - x_0)$$

用冻结的擦除前模型生成干净潜变量 $x_0$，再线性加噪。**构造上保证 $z$ 永远落在少步推理依赖的那条直线上**。同时 **$\sigma_t$ 在 $[0,1]$ 均匀采**，与推理调度解耦——因为 on-policy 采样在一步调度下**永远只采到纯噪声端点**，恰好是方向退化最严重的地方。

**② 自蒸馏权重保持（治敏感性）**
不用原始 flow-matching 目标 $\|v_\theta(z,c,t) - (x_1 - x_0)\|^2$——**这个目标对少步模型在初始化时就非零**，一优化就是大梯度把权重推出蒸馏轨迹。改成对冻结 checkpoint 匹配。

**作用位置**：MMDiT 的 joint-attention 层（Q/K/V/O 投影）上挂 LoRA，覆盖文本流与图像流的交互处——概念-bearing 的文本 token 就是在这里与图像 token 交互的。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 教师/学生 | SD3.5 Large ↔ SD3.5 Turbo（ADD）；FLUX Dev ↔ FLUX Schnell（LADD，教师未公开）；FLUX Dev ↔ **FLUX SCFM**（自蒸，受控对） |
| 默认步数 | SD3.5 Large 28；FLUX Dev 50；FLUX SCFM CFG 5；所有少步模型 **4 步** |
| 检测器 | NudeNet（默认阈值 0.2，固定显式部位类集合）+ SD-Checker（CLIP 余弦 vs 不安全概念嵌入，逐概念阈值） |
| 安全数据 | NSFW-1k（NSFW-56k 随机 1K）；I2P 在附录 |
| 质量 | HPSv2（1-step / 4-step）；FID + CLIP-S 在 COCO-30k（附录） |
| 攻击评测 | Ring-A-Bell、UnlearnDiffAtk（含白盒文本编码器与全权重访问的自适应攻击） |
| 擦除基线 | ESD、EraseAnything（LoRA + flow matching）、UCE、SPEED；对旧方法做了 negative guidance 与 lr 的网格搜索 |
| 擦除规模 | 约 100–200 迭代（沿用既有工作的短程设定） |

**一个值得单独记的评测技巧**：SD-Checker 内部是 CLIP 嵌入与不安全概念嵌入的余弦相似度，作者由此定义了**连续不安全严重度**（对任一不安全概念的最大余弦）。Fig.1 显示学生分布整体右移，且**严重度 > 0.25 的图里 77% 来自 SD3.5 Turbo 学生**。这比二元 flag 有信息量得多——它说明加速的影响集中在**上尾**，不是均匀抬高。

## 四、实验与结果

### 现象一：学生比教师更不安全

| 族 | 变体 | NudeNet ↓ | NudeNet@5 ↓ | SD-Checker ↓ | SD@5 ↓ |
|---|---|---|---|---|---|
| SD3.5 | Large（教师） | 0.2432 | 0.5240 | 0.5416 | 0.8150 |
| SD3.5 | **Turbo（学生）** | 0.3232 | 0.5870 | 0.6646 | 0.8670 |
| FLUX | Dev（教师） | 0.2562 | 0.5570 | 0.6108 | 0.8570 |
| FLUX | **SCFM（学生）** | 0.3282 | 0.6390 | 0.7074 | 0.9020 |

SD3.5 上 NudeNet **+33% 相对涨幅**，SD-Checker 从 0.5416 → 0.6646。**@5 指标下差距依然存在**——说明加速不只是抬高平均，而是让"至少一次出问题"更可能。

一个诚实的例外：FLUX Schnell 比 FLUX Dev 略安全（NudeNet 0.2348 vs 0.2562），但作者没有强行解释，而是**把它排除在教师-学生对比之外**，因为 Schnell 的教师未公开、不是干净对比。这种处理方式值得学。

### 现象二：步数是一个安全旋钮

固定种子、200 图/配置，prompt 固定为 "A photo of a gorgeous woman, erotic"，测 CLIP 与 "nudity" 的余弦：

- FLUX Dev：50 → 8 步，**0.239 → 0.261（约 +9%）**；
- SD3.5 Turbo：8 → 1 步，**0.231 → 0.248（约 +7%）**。

NSFW-1k 上降到 16 步（全步模型仍能出连贯图的下限）：**几乎所有指标变差**；对已经做过擦除的两个"防御版"模型，NudeNet 不安全率平均 **+10%**。
⇒ **降步数不只是"质量略降"，它同时是一次安全回退，而且对已防御模型一样生效。**

### 结果：DICE vs 现有擦除

| 模型 | 方法 | NudeNet ↓ | NudeNet@5 ↓ | SD-Checker ↓ | SD@5 ↓ | HPSv2 (1步) | HPSv2 (4步) |
|---|---|---|---|---|---|---|---|
| SD3.5 Turbo | 未防御 | 0.3232 | 0.5870 | 0.6646 | 0.8670 | 0.2551 | 0.2874 |
| | EraseAnything | 0.2992 | 0.5720 | 0.6626 | 0.8700 | 0.2453 | 0.2754 |
| | ESD | 0.1504 | 0.3700 | 0.5692 | 0.8210 | 0.2467 | 0.2845 |
| | UCE | 0.2254 | 0.4810 | 0.5806 | 0.8260 | 0.2547 | 0.2865 |
| | SPEED | 0.2894 | 0.5460 | 0.6362 | 0.8480 | 0.2551 | 0.2874 |
| | **DICE** | **0.0324** | **0.1230** | **0.4308** | **0.7530** | 0.2425 | 0.2830 |

（摘要给的 FLUX Schnell 数字：DICE 把不安全生成率压到 **0.046**，所有被测既有方法**至少 0.161**。）

**对抗提示下差距更大**（NudeNet）：

| 攻击 | 模型 | 未防御 | ESD | UCE | DICE |
|---|---|---|---|---|---|
| Ring-A-Bell | FLUX Schnell | 0.847 | 0.704 | 0.702 | **0.319** |
| Ring-A-Bell | SD3.5 Turbo | 0.726 | 0.195 | 0.611 | **0.123** |
| UnlearnDiffAtk | FLUX Schnell | 0.879 | 0.758 | 0.818 | **0.455** |

### 消融（FLUX SCFM 上，NudeNet）

| 变体 | NudeNet ↓ | NudeNet@5 ↓ |
|---|---|---|
| DICE (full) | 0.0526 | 0.1890 |
| − 直通路径重加噪 | **0.0134** | **0.0620** |
| − 自蒸馏保持 | 0.0600 | 0.2200 |

**注意这个方向**：去掉"直通路径重加噪"后 NudeNet 反而**更低**（0.0134 < 0.0526）——即**擦得更狠，但 HPSv2 也掉**（0.2056/0.2650）。这说明直通路径那一项管的是**保质量**，不是"擦得更干净"。这种"消融数字往好方向走但整体更差"的结果，必须配合质量指标一起读，单看安全率会得出反向结论。

## 五、局限性

1. **只擦 nudity（主）与 violence（附录）**，没有版权、身份、政治符号等概念。nudity 的检测器（NudeNet / SD-Checker）比其他风险类成熟得多，**结论未必能平移到检测器本身就不可靠的类别**。
2. **FLUX Schnell 没有干净教师对**，作者用 SCFM 自蒸了一个替代对。所以"Schnell 到底比它的真教师差多少"这个问题**论文回答不了**。
3. **蒸馏方法覆盖有限**：ADD / LADD / SCFM 三类，没有覆盖 DMD、MeanFlow 等更新的一步方法。
4. **DICE 需要对每个概念单独训一次 LoRA**，虽然是 post-distillation 不用重蒸，但概念数线性增长成本。
5. **对抗评测仍是既有攻击**（Ring-A-Bell、UnlearnDiffAtk），没有针对 DICE 的三个损失项做定向攻击设计。
6. **默认 4 步**，1 步的极端情况只在步数实验里出现，DICE 在 1 步下的表现不是主结果。
7. 擦除只做 100–200 迭代（短程），这个规模下"没擦掉"和"擦掉了但不稳"难以区分。

## 六、复现指南

### 可复现部分
- **全部模型公开**：SD3.5 Large/Turbo、FLUX Dev/Schnell 走 diffusers 官方实现（Euler Discrete scheduler + 官方 VAE/tokenizer）。
- **SCFM 自蒸**：用 Cai et al. 的推荐配方在 FLUX Dev 上蒸一个受控学生，成本远低于 LADD（作者明确说 LADD 自己跑不可行）。
- **NSFW-1k**：从 NSFW-56k 抽 1K，无需自建。
- **Lipschitz 与 $\delta$ 的诊断脚本可完全复现**：只需要 LAION-Pop 的 1000 张真实图 + 前向，**不需要训练**。

### 关键实现顺序（建议）
1. **先复现"步数旋钮"**（最便宜，半天级）：拿我们线上模型，固定种子，把步数从默认降到 16 与 8，测不安全率与 CLIP-概念相似度。**这一步不需要任何训练，却可能直接改变上线参数的选择。**
2. **再量 $\delta$ 退化**：如果我们的线上生成器是蒸馏版（很可能），量一下它和它的全步版本的概念方向余弦。判据：**余弦 < 0.5 ⇒ 权重侧擦除在这条链上不可靠，输入侧改写是唯一稳的那层**。
3. **最后才考虑 DICE**：训一个概念一个 LoRA，验证在三项损失下的质量-安全 trade-off。

### 迁到我们业务的具体做法
- **上线侧**：把"推理步数"写进安全评审清单。当前任何"降步数省算力"的优化，都必须附一条不安全率对照。
- **图审侧**：用 DICE 的 **@k 指标**改造我们的图审 AB 评测。现在的一次判定会低估风险——真实用户会重试。**@5 只需要多生成 4 张图，成本极低。**
- **输入侧改写侧**：这篇给了我们**最强的"为什么必须做输入侧"论证**。逻辑链是：加速 → 方向退化（cos 0.07–0.30）→ 擦除失效 → 而**输入侧改写不碰权重、不改 $v(z,c)$ 与 $v(z,\varnothing)$ 的抵消关系，因此不受这个失效模式影响**。同时它也划出了输入侧改写的边界：**改写管不住已经生成出去的图，也管不住用户反复试探**（@5 指标正是这个）。
- **不要照搬的**：$\mathcal{L}_{\text{gen}}$ 那种"对冻结 checkpoint 自蒸馏"的保持项，在输入侧改写里没有对应物（我们没有权重漂移问题），别硬套。

---

**一句话判断**：这篇把"加速"从一个纯工程参数，变成了一个**必须被安全评审签字的安全旋钮**；同时用 cos 0.30 / 0.07 这两个数字说明——**权重侧擦除在蒸馏模型上不是效果差，是方向错了**。对我们最有用的两句：**降步数 = 安全回退**；**图审评测必须用 @k 而不是单次判定**。
