## 一、背景与问题

### 动机：T2I 加速器只在「Overall」上报一个数

Speculative decoding / feature reuse / step skipping 之类加速器，通行做法是报**全量 prompt 池的平均加速比 + 平均质量分**。但不同渲染要求（文字、计数、纹理、透视、常识……）对「跳过多少目标模型计算」的容忍度完全不同。本文构造 **1,400 prompts × 7 rendering topics × 2 难度**的均衡基准，强制三件事同时报：**latency / target work / quality**，并按 topic 拆开。

### 与本仓库主线的关系（四重命中）

1. **整体指标与分层宏平均背离（aggregate-vs-macro F1 divergence）**：本文是「聚合分掩盖子类劣化」在**推理加速侧**的现成公开评测集，可直接照搬进 6 版本迭代看板的背离检出。
2. **推理加速 / 量化不劣化验证**：项目现状 1105 权重 TTFT ≤110ms / e2e ≤160ms、qwen3.5 Pro5000 二阶段量化、fp8/fp4 降本。本文给出**「省了多少计算 ≠ 快了多少」**的硬证据（ADT-Tree −42.0% work → 仅 1.0889× 加速）。
3. **per-category threshold / operating point**：SpeCa 阈值从 5 提到 9，latency ratio 4.284→5.134 而 Easy 档质量 +0.0383 / Hard 档 −0.0517 ⇒ **一个全局阈值在不同难度上方向相反**，与 11-26 TIDE Theorem 2（part-agnostic 规则无法保证异构预算）同构。
4. **三维评测 / 指标口径**：alignment 与 preference 分数可以和 prompt 约束满足**不一致**（一个 evaluator 复现了聚合涨，另一个却在 text topic 上掉）⇒ 呼应「验收装置本身要先被验收」。

## 二、核心方法

### 2.1 T2ISpec 基准

| 项 | 值 |
|---|---|
| prompts | **1,400**（7 topics × 2 难度；每 topic 100 easy + 100 hard；另 700 用于外部泛化） |
| 七个 topic | 由渲染要求归纳：文字 / 计数 / 属性 / 纹理 / 透视 / 常识 / 空间关系等 |
| 统一协议 | **paired Target-only** 对照；同时报 latency、target model work、quality（Q，{0,0.5,1} 三档 × 三判据均值） |
| 方法池 | AR: LANTERN / LANTERN++ / CSD / SJD / GSD / SCD / MC-SJD / VVS 等；diffusion: TaylorSeer / SpeCa / ASD / diffusion speculative sampling 等 |
| 统计 | 每 topic 200 prompts、Overall 1,400；95% bootstrap CI；median paired latency ratio |

### 2.2 TopicRoute（免重训插件）

分类器预测 prompt 所属 rendering topic，按 topic 选择后端 / 控制已有加速器的超参，**不重训生成器**；六组配对的几何平均加速 **1.0308×**，且在外部 DrawBench prompts 上可迁移。

## 三、技术细节

### 3.1 三条主发现（Sec.1 明列）

1. **Aggregate results hide large differences between topics**；
2. **Alignment / preference scores 与 prompt 约束满足可以不一致**；
3. **大幅削减 target work 只换来有限 latency 收益**。

### 3.2 topic 级离散度（Fig.1 / Table 1）

- 相对各方法 Overall 比值，**AR 方法的 topic 偏离范围 ±20%，diffusion/flow ±4%**——即「同一个加速器在不同 topic 上的实际加速能差两成」；
- PathSpec 跨 topic **2.8283–3.8270×（35.31% 相对跨度）**，CSD **1.5617–1.9846×（27.08%）**；
- **ADT-Tree 把 target work 砍掉 42.0%，Overall latency ratio 只有 1.0889×**；在 Janus-Pro 上其 Overall criterion **0.0000**、latency ratio **0.9949**，却掩盖了 **text +0.0233 / commonsense −0.0242** —— **两个方向相反的 topic 变化被平均成零**。
- LANTERN++ 在 LlamaGen 512² 上 3.2163×，各 topic 4.2519–4.8069×；GSD 在 Janus-Pro 上 5.0195×，topic 4.7079–5.4098×。

### 3.3 阈值 / 难度 / 指标三组分歧（Sec.4）

| 对照 | 读数 | 含义 |
|---|---|---|
| SpeCa base threshold 5→9 | latency ratio **4.284→5.134**，Easy **+0.0383** / Hard **−0.0517** | 单一阈值跨难度方向反了 |
| 同 latency ratio 0.969 | Easy **+0.0042**、Hard **−0.0129** | 平均「没变」，分层在退 |
| VVS Easy/Hard ratio 1.030/1.037 | 质量增益 Hard 更大 | 加速比相同而收益分布不同 |
| 换 evaluator | 一个复现聚合涨、另一个在 text topic 掉 | 装置本身是变量 |

作者结论段写死：**「topic 比较揭示 latency 变化、质量回退与指标分歧，而大幅削减 target work 可能只带来有限 latency 增益」**。

## 四、实验与结果

- **TopicRoute**：六组配对几何平均 **1.0308×**，其中五组降低 topic disparity；外部 DrawBench prompts 可迁移；**quality 变化依 backend / topic / metric 而变**（不承诺质量不劣化）。
- **11 类方法 × 21,000 张图**（338 组配置）同 prompts / topics / metrics 对照。
- **长 horizon 反噬**：提高基础阈值或延长 drafting horizon 会增加 work 却不改善 latency，且激进缓存会在**个别 topic** 上掉质量——这些成本在 Overall 上不出现。
- **统计严谨**：bootstrap CI、paired median ratio、target-only 配对、外部集迁移，全部按 topic 分层报。

---

## 五、局限性与迁移边界

- **只测加速与渲染质量，不涉任何安全语义**：无 NSFW / 政治 / 误杀率 / 拒答 / 输入改写 / 出图侧内生风险；「quality 不劣化」不等于「安全率不劣化」。
- **未报 TTFT / e2e 绝对值 / TPOT / 超时率 / 降级率**，也没有 fp8/fp4、跨硬件、serving setup 指纹 ⇒ 迁移到 1105 权重验收口径需自行补齐。
- **TopicRoute 只有 1.0308× 量级**，且明确「quality 变化依配置而变」，不能当作通用提速方案。
- **topic 分类由 classifier 预测**，路由本身引入一个可能 misroute 的新判定层（与「加一层就要配独立生效指标」一致）。
- **可迁的是协议，不是数字**：±20%/±4%、42.0%→1.0889× 属该基准专属；可迁的是「**按渲染/类目分层 × 难度分档 × paired target-only × latency/work/quality 三列同时报 × 换 evaluator 对照**」这套验收骨架。

## 六、复现指南

1. **把 6 版本迭代看板的加速列改成七格**（零训练）：对每一次量化 / 加速配置，按「一级类目 × L2_30 × 难度」出 `Δaggregate` 与 `Δmacro`，报 `Δaggregate>0 而 Δmacro<0` 的格子；**只看 Overall 加速比的版本不予上线**。
2. **三列强制同报**：latency（TTFT/e2e/TPOT）、省下的计算量（work / FLOPs / 步数）、质量与安全（安全率、分层宏平均 F1、逐样本判定翻转率）。**省了 42% 计算只快 9% 这类落差必须显式列为风险项**。
3. **阈值方向检查**：对每个候选阈值，分别在 Easy/Hard、中/英/中英混合三档报增益方向；**出现方向相反即判该阈值不可全局下发**，改 per-category operating point（延续 TIDE Theorem 2）。
4. **换 evaluator 对照**：至少两个独立评分器 + 人工共识，冻结 judge 示例集与配置指纹；只换流量比例不换尺子、不换执行环境。
5. **事件留痕**：ckpt / 量化器与 bit 宽 / batch / GPU / 缓存方法 / 步数 / 阈值规则 / 评测集重叠审计版本 / 检测器版本 / serving setup 指纹，缺任一不可声称可复现。
6. **灰度一致性**：shadow → canary → 全量每一步冻结同一评测单位与聚合口径，观察模式与生效模式分列；TopicRoute 式新路由层要单列「misroute 率」这一独立生效指标。

---

**对本项目的落点（一句话）**：**「加速了多少」也必须按类目/难度拆开报，且必须配「省了多少计算」与「安全率/分层 F1 掉没掉」两列**；ADT-Tree −42% work→1.0889×、Overall 0.0000 掩盖 text +0.0233 / commonsense −0.0242，是 `Δaggregate` vs `Δmacro` 背离检测最干净的公开模板，直接服务量化/加速上线前的不劣化验收。
