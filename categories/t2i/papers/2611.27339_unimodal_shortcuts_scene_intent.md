## 一、背景与问题

### 动机：风险长在「场景 × 意图」的合取上，而 benchmark 允许只看一边

论文用一句话把问题钉死：问「怎么端上这道菜」，配新鲜食材的照片无害、配变质食物的照片有害，而问「描述一下这份变质的菜」又无害。**风险是场景（scene）与用户意图（intent）的合取，不是任一模态的加和**。只读场景的监控器会对良性问题过度拒答，只读措辞的监控器会漏掉用中性措辞写的有害动作。

问题在于：**在这类 situational safety benchmark 上拿到高准确率，不能证明模型的安全表示同时编码了场景和意图**——因为 benchmark 的标签往往能由单一模态预测出来。作者称之为 **unimodal shortcut**，并给出双侧条件依赖诊断：需要 `I(Y;I|U)>0` 且 `I(Y;U|I)>0`（已知意图时图仍有信息，已知图时意图仍有信息）才可能测到联合态；任一为 0，标签就由另一边决定。

### 与本仓库主线的关系

这是 11-23 收录的 EditSafetyBench（UIR 87.1% vs UNR 24.2%，「编辑器在读文字没在读图」）**在表示层的机制性解释**：上轮证明部署系统没读图审输出，本轮证明连用来验收的公开 benchmark 都不需要读图。三条直接对应：

- **I2I 0/0% 第四/第五种归因**：分流只读文本通路，可能是因为训练与验收数据本身就允许文本单通道通关；
- **输入改写有效性上界**：如果评测集存在单模态捷径，「改写后文本无害」这个判定不能推出「图文联合状态安全」；
- **推理加速不劣化验证**：缓存探针的延迟数字给出了图审侧「加一层」的匹配预算口径。

## 二、核心方法

### 2.1 三层证据链（每一层堵住上一层留下的解释）

| 步骤 | 做什么 | 堵住什么解释 |
|---|---|---|
| ① 五个公开 benchmark 结构审计 | 查标签是否由图身份 / 低层像素统计 / 图盲探针决定 | 「模型没学到」 |
| ② 同图反义配对 | 同一张照片配 benign / harmful 两种请求，去掉图捷径 | 「benchmark 没奖励意图」 |
| ③ 2×2 四路对称控制 | 安全/危险场景 × 观察/动作请求交叉，每组恰一个不安全格 | 单模态规则上界锁死在 0.500 |
| ④ 拆开编码 vs 联合编码 | 把单独编码的图/文状态拼接后探针，与中间层联合探针对比 | 「可解码 = 有融合机制」 |
| ⑤ 部署评测 | 图像不相交切分 + 跨 benchmark 迁移 + prefill 延迟 | 「能当上线筛子」 |

### 2.2 四路控制的设计要点

- 控制集覆盖 **578 张经像素筛查的 MSSBench 场景 + 606 条请求**，构造出 **2,400** 条 `2×2 scene-action` 记录；同图反义配对另建 **198 共享场景 / 396 图-文记录**。
- 每个四路组里**恰有一个不安全格**，因此固定意图切片内文本规则无信息、固定场景切片内图规则无信息：任何单模态监控器的上界被**构造性**钉在 **50.0% 固定切片 AUROC / 50.0% 组排序准确率 / 5/6≈0.833 池化 AUROC**，条件熵 **0.50 bit**。
- Ridge 探针 `λ=10`，深度按训练 AUROC 选，`κ0.05` 取良性校准 95 分位；四个深度 L1–L4 逐层探。

## 三、技术细节

### 3.1 五个公开 benchmark 的捷径类型（Table 2，论文口径）

| 数据集 | 样本 | 图 | 请求 | 像素可分 AUROC | Ĥ(Y\|I) | 图查找上界 | 主捷径 |
|---|---|---|---|---|---|---|---|
| VSCBench | 1788 | 1751 | 257 | 0.5929 | 0.00 | 1.00 | 见过的图 |
| MSSBench | 1200 | 578 | 598 | 0.5861 | 0.00 | 1.00 | 身份 / 未见过的图 |
| MOSSBench type 2 | 76 | 76 | 38 | 0.8947 | 0.00 | 1.00 | 像素统计 |
| VLGuard | 1558 | 999 | 1397 | 0.9890 | 0.716 | 0.721 | 像素统计 |
| MMSafeAware | 1452 | 445 | 1421 | 1.0000 | 0.045 | 0.999 | 像素 / 身份 |
| 同图反义配对（本文） | 396 | 198 | 389 | 0.5000† | 1.00 | 0.50 | 文本侧 |
| 2×2 scene-action（本文） | 2400 | 578 | 606 | n/a | 0.50 | 0.83 | 设计上无 |

† 由构造决定：每张图同时带两个标签。作者特别提醒 **Ĥ(Y|I)=0 不一定同义**：MSSBench 的 578 张图全部多请求且不换标签（真身份捷径），VSCBench 里 1751 张只有 29 张多请求（零值主要是单例造成的假象）——这正是本仓库「分母里混了两种东西就不能做决策」的又一实例。

### 3.2 抽掉 prompt 反而更好（最反直觉的一行）

在图像决定的公开集上，把 prompt 移除，重训探针的 AUROC 最高**升 0.2018**（SmolVLM2 + MSSBench）；16 个配置里 **15 个 ΔAUROC ≤ 0**；图像不相交切分下 **12/16 ≤ 0**，四个正值都 < +0.02（最大 **+0.0167**），负值可到 **−0.0954**。⇒ 在这些套件上，prompt 除了图之外**没有可测的排序贡献**；固定探针的翻转只是激活位移，不是意图信息。

### 3.3 从图捷径到词捷径，再到联合态

- **图盲探针**：VSCBench / MSSBench 上，只看池化视觉 token、不读 prompt 的探针排未见过的图达 **0.8756–0.8990 AUROC**。
- **同图反义词捷径**：拿一张**纯灰画布**当图、只读文本的探针，在 Qwen3-VL-8B L2 达 **0.9645 AUROC**（图 1 报 0.9645–0.9846），SmolVLM2-2.2B 达 **0.9360**；与联合探针 0.9390 / 0.9066 **持平或更高**。即「文本自己就决定了标签」，联合探针的高分不能归功于看了图。
- **四路控制才有真信号**：中间层联合探针 L2 达 **0.958**（Qwen3-VL-8B）/ **0.930**（SmolVLM2-2.2B）组排序准确率，对 **0.500** 的单模态上界；固定 prompt 下 AUROC **0.9577 / 0.9366**，固定图下 **1.0000 / 0.9859**；单模态探针实测 **0.486–0.514 / 0.493–0.500**，与理论吻合。L1–L4 比较把信号定位在**中间层**（联合排序 0.958–0.965）。
- **可解码 ≠ 有融合**：把分别编码的图/文状态**拼接**后再探，仍有 **0.930 / 0.859**，已经恢复大部分信号 ⇒ 不需要模态在模型内部交互，也就不能用「探针可解码」当融合机制的证据。

## 四、实验与结果

| 观察 | 数 | 含义 |
|---|---|---|
| 五个公开情境 benchmark | **5/5** 存在单模态捷径 | 高分不能读成联合理解 |
| 图盲探针排未见过的图 | **0.8756–0.8990** AUROC | 图身份捷径可泛化 |
| 灰画布纯文本探针（同图对） | **0.9645–0.9846** AUROC | 词捷径比联合探针还高 |
| 四路控制单模态上界 | **0.500** 组排序 / **0.833** 池化 | 构造性锁死 |
| 中间层联合探针 | **0.958 / 0.930** | 合取是线性可解码的 |
| 拼接分别编码状态 | **0.930 / 0.859** | 可解码不蕴含融合 |
| 图像不相交切分 | 12/16 ΔAUROC≤0，最大正 +0.0167 | 去掉 prompt 反而更稳 |
| **跨 benchmark 迁移探针** | **掉到 0.48–0.67 AUROC** | 「编码了正确信息」≠「可靠筛子」 |
| 缓存探针延迟（batch=1） | **0.234 ms** vs 独立安全 pass **95.82 ms**（45.27 / 76.05 / 95.82 分位对照） | 便宜得几乎免费 |
| 端到端 prefill | 在 **68.0 ms** 上只加 **0.36%** | 可挂在生成链路上 |

**作者的核心结论（原文口径）**：可靠的多模态安全评测，需要**在把准确率读成联合理解的证据之前，先用控制把单模态捷径排除掉**；廉价缓存探针虽然几乎不花钱，但在图像不相交与跨 benchmark 条件下召回下降，因此**不能单独当上线筛子**。

## 五、局限性

1. **只测冻结表示**（Qwen3-VL-8B、SmolVLM2-2.2B 两个 backbone），不测 SFT/RL 后的安全行为，也不测部署态图审模型；「线性可解码」到「决策层真的读了」之间还差一层。
2. 四路控制来自 **MSSBench 的 578 张场景**，是**观察/动作请求**的二档设计，不覆盖 PORN/VULG 边界、政治 L2_30 层级、也不覆盖中英混合或 DSC 式承诺分散语用形态。
3. **跨 benchmark 迁移 0.48–0.67** 说明探针本身泛化差；本文是诊断工具而非可部署护栏，作者明确没有评估 HiddenDetect / 安全注意力头等已有内部监控器在其协议下的表现。
4. 延迟数字是**单个 batch=1 的探针**，不含缓存命中失效、并发、跨硬件迁移（P800 / Pro5000 类）与量化后的漂移，不能直接当本项目 TTFT/e2e 达标证据。
5. 全文讲的是「请求侧风险判定」，不是「已生成图的审核」；改写链路的改写后文本无害性判定与出图侧内生风险错位，本文没有数据。

## 六、复现指南

**最小可用改造（零训练，1 天）**：把本项目图生图评测集（2000 条 / 1979 有效）按本文 2×2 思路重打成四格——`源图 safe/unsafe × 指令 观察/动作`，每格报改写分流命中率、图审分、人工双盲残留率。再补三个对照探针：① 冻结源图只换指令（测词捷径）② 冻结指令只换图（测图捷径）③ 灰图纯文本探针。

**判据（可直接抄）**：
- 灰图纯文本探针 AUROC **≥0.90** ⇒ 现有评测集存在词捷径，**「改写后文本无害」不能作为联合安全验收**；
- 固定图切片 AUROC ≈0.50 而固定指令切片 ≈0.50 ⇒ 分流确实在单通道上跑，与 EditSafetyBench 的 UNR 格互为验证；
- 任何新指标上线前，先算「单模态探针」与「拼接探针」两个退化基线（本仓库 11-06「全 0 / 全 1」纪律的多模态版），若不低于联合探针则该指标作废。

**推理侧验证口径**：若把缓存探针挂进图审链路，必须同时报 `prefill 增量 %`、`batch=1 绝对延迟`、**图像不相交切分召回**、**跨评测集 AUROC**、以及量化（fp8/fp4）前后的安全率与分层 F1——本文 0.36% 是「探针便宜」的证据，不是「链路不劣化」的证据。

**依赖**：Ridge 探针 `λ=10`；`κ0.05` 取良性校准 95 分位；深度按训练 AUROC 选；**必须用图像不相交切分**而非请求分组切分（后者会把同一张照片同时放进训练与测试）。
