## 一、背景与问题

### 动机

T2I 模型越来越强，但复杂 prompt 下仍常见三类老问题：
- 属性绑定错位
- 否定条件失效
- 组合关系理解不稳

过去很多 prompt rewriter 只是把句子写得更长、更流畅，却没有真正针对生成器的失败模式优化。

### 核心科学问题

能否训练一个**独立于生成器、可泛化到任意预训练 T2I 模型**的 CoT rewriter，并用显式、细粒度、可解释的 reward model 去驱动它，而不是靠粗糙的 CLIP / ImageReward 打总分？

### 为什么这篇论文重要

这是目前公开可见、又带明显工业背景的输入侧 rewrite 方法之一。它直接告诉你：**好的 rewriter 不是润色器，而是 failure-mode aware 的上游控制器。**

---

## 二、核心方法

### （1）两阶段训练：SFT → GRPO

PromptEnhancer 先做 SFT，让 rewriter 学会输出链式分析和结构化改写；
然后再用 GRPO，在冻结的 T2I 模型上通过生成结果反向优化 rewrite 策略。

### （2）AlignEvaluator：细粒度奖励模型

论文最关键的设计是 **AlignEvaluator**：
- 它不是泛用美学打分器；
- 而是专门针对 T2I 常见失败模式构造显式反馈。

官方材料显示，该 taxonomy 覆盖 **24 个 key points**，来源于对 T2I 失败模式的系统分析。

### （3）CoT Rewriter 与 Generator 解耦

作者强调：
- rewriter 不必与生成器共同训练；
- 只要 reward 足够贴近生成失败结构，rewriter 就能迁到不同模型；
- 这让输入侧 rewrite 成为可插拔模块，而不是某个专有模型附属品。

### （4）人类对齐 benchmark

论文还配套构建了高质量的人类偏好 benchmark，用于评测“改写后是否更接近用户真正意图”。

## 三、技术细节

### PromptEnhancer 真正有价值的地方

它最有价值的不是“会改写”，而是它把 rewrite 训练拆成了一个更合理的闭环：

```text
用户 prompt
   ↓
CoT rewriter 生成多个候选 reprompt
   ↓
冻结的 T2I 模型出图
   ↓
AlignEvaluator 基于细粒度 failure taxonomy 打分
   ↓
GRPO 更新 rewriter
```

这意味着：rewriter 学到的不是语言流畅度，而是**哪些改写更容易被生成器正确执行**。

### 24 个 key points 的意义

官方材料明确指出，这 24 个 key points 来自对 T2I 常见失败模式的系统归纳。对你的业务，这非常重要，因为它提供了一个现成思路：
- risk anchor 不一定按词划分；
- 更有效的做法是按**失败模式 / 约束点**划分；
- rewrite judge 也应该按 failure taxonomy 输出，而不是只给 overall score。

### 工业可迁移性

项目页强调它服务于 HunyuanImage 2.1，但方法本身是通用 rewriter。对当前业务最有价值的抽象是：
- 上游分析器（CoT）
- 结构化 reward taxonomy
- 生成器无关的 rewrite policy

## 四、实验设置与结果

### 论文公开可确认的结果信号

从论文摘要与项目页可确认：
- PromptEnhancer 在 **HunyuanImage 2.1** 上验证；
- 对复杂语义与组合挑战的 image-text alignment 有显著提升；
- 覆盖 photorealism、digital art、abstract geometry、multilingual text-in-image 等多类场景；
- 配套新的人类偏好 benchmark，用于更细粒度评估。

### 为什么即使数字不全，它仍值得纳入

因为这篇论文在方法论上非常对路：
1. **把 rewrite 与 generator 解耦**，降低部署耦合度；
2. **把 reward 显式绑定到 failure taxonomy**，而不是靠单一偏好分；
3. **让 rewriter 直接为生成执行性负责**，不是仅为文字漂亮负责。

### 对当前业务的直接启发

如果把 PromptEnhancer 迁到安全改写场景，我建议直接改造它的 reward taxonomy：
- `risk_reduced`
- `subject_preserved`
- `style_layout_preserved`
- `follow_preserved`
- `overrewrite_penalty`

这比“安全 / 不安全”二分类更像真实上线系统。

## 五、局限性分析

1. **它本身不是 safety paper**：重点是 fidelity 与执行性提升。  
2. **公开页面没有给出最浓缩 headline 数字表**：需要从 PDF / 补充材料继续细读。  
3. **在高风险 prompt 上是否会放大危险表达**，论文没有正面解决。  
4. **依赖 reward model 质量**：如果 taxonomy 不对，rewriter 会朝错误方向优化。  
5. **当前更多是在复杂 prompt fidelity 上验证**，对 NSFW 灰区语义保真改写仍需重训和重标。

## 六、复现指南

### 环境依赖

```bash
pip install torch transformers accelerate diffusers
```

### 最小复现步骤

1. 准备 `(用户 prompt, reprompt)` 的 SFT 数据。  
2. 用冻结的 T2I 生成器出图。  
3. 训练 AlignEvaluator，对生成失败模式打结构化分数。  
4. 用 GRPO 优化 rewriter。  
5. 在复杂语义、否定、组合、布局场景上做人类评测。

### 对当前业务的最小迁移版本

即便不复现整套 PromptEnhancer，也建议先学它的**reward taxonomy 思路**：
- 先把 rewrite 常见失败类型列全；
- 再决定模型怎么学；
- 否则 rewriter 最后只会学会“把句子写长”，而不是“把风险改掉且不伤意图”。
