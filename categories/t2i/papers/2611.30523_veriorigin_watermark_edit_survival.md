## 一、背景与问题

### 动机：通用水印只会答「是不是」，不会答「哪里被改了」「原图能不能拿回来」

文本引导编辑模型（FLUX.1 / SDXL / Adobe Firefly 等）几秒钟就能按 mask 改掉图中任意区域并再分发，因此图像保护需要三件事同时成立：

| 能力 | 现有范式 | 缺口 |
|---|---|---|
| **Provenance（溯源）** | 鲁棒水印（JPEG/噪声/模糊下读回 payload） | 已成主流 |
| **Tamper localization（篡改定位）** | EditGuard / GenPTW 等 versatile watermark | 与鲁棒水印分家，且不能无损恢复 |
| **Lossless recovery（无损恢复）** | 鲁棒可逆水印 RRW | 能 bit-exact 恢复，但定位不了篡改区 |

作者指出**三者在既有方法里从未统一**：既有的「判定」能过，但「信息」（哪里被改）与「事件凭证」（原图可无损取回）缺位。这正是本仓库自 11-10 NotaryMark 起反复记录的「判定 / 信息 / 事件三栏」缺口。

### 与本仓库主线的关系（三重命中）

1. **用户方向 (2) 明确点名「编辑后水印存活率」**：这是本轮唯一直接给出**多种编辑/失真的水印位准确率**的工作，且用 TGIF2（文本引导 inpainting 编辑集）做评测，正对「编辑后水印存活率」而非仅常规失真。
2. **判定 / 信息 / 事件三栏第一次被同一个模型同时满足**：payload accuracy（判定）、F1/IoU 定位（信息）、bit-exact 无损恢复（事件凭证）——可直接照搬到图审 AB 与被挡样本的结构化事件设计。
3. **出图侧内生责任边界**：水印/溯源是**输出侧**通路，管不了输入改写，也管不了生成过程；与权重侧概念擦除、输入侧热更新改写、生成过程干预构成互补四层（边界第十三轮）。

## 二、核心方法

### 2.1 XOnet：CNN 可逆编码器，不用 flow-based 架构

- 由 **Xnet / Onet** 两个标准 CNN 水印子网络通过 **cross residual prediction** 实现可逆性；支持任意分辨率，便于规模化。
- 与主流 flow-based invertible network 路线分道，理由是后者在复杂失真下的鲁棒性与定位精度受限。

### 2.2 两阶段训练 + 推理期顺序嵌入

1. 第一阶段优化**水印分支**（鲁棒 payload 提取 + 无损通道 bit-exact 恢复）；
2. 第二阶段优化**篡改定位分支**（可训练的 tamper-sensitive residual）；
3. 推理时 cover image 依次经过 **watermarking → tamper residual embedding**。
- 有损通道（JPEG/噪声/模糊/裁剪）下：读 provenance + 定位篡改区；**无损通道下：bit-exact 恢复原 cover，做完整性认证**。

### 2.3 为什么「去掉 payload」是对照臂

论文 Table 1/2 都报 `Ours w/ wm` 与 `Ours w/o wm` 两行——后者丢掉 payload，专门用来量**水印载荷对定位精度造成的代价**（最多 2.3 F1 点）。这是本仓库一直强调的「每条约束配独立生效指标」的一个干净实现。

## 三、技术细节

### 3.1 实验设置

| 项 | 值 |
|---|---|
| 评测集 | CocoGlide、COVERAGE、CASIA v2.0（clean localization）；TGIF2（100/500 test pairs，10 种定位条件、9 种 payload 条件） |
| 编辑/篡改源 | GLIDE inpainting on COCO；TGIF2 覆盖 **6 个 inpainting 模型中的 5 个**（FLUX.1 schnell / dev / Fill dev、SD2、Adobe Firefly） |
| 指标 | 定位 F1 / IoU；payload bit accuracy；视觉质量 PSNR / SSIM / LPIPS |
| 对照 | GenPTW、EditGuard、CRMark、MBRS、TrustMark、InviMark、Stable Signature 等 |
| payload | 100 bit（对照多为 64 bit）；优化器恒定 lr $1\times10^{-4}$ |

### 3.2 Clean 定位（Table 1，F1/IoU）

| 方法 | CocoGlide | COVERAGE | CASIA v2.0 |
|---|---|---|---|
| **Ours w/ wm** | **0.995/0.990** | **0.995/0.991** | **0.974/0.950** |
| Ours w/o wm | 0.995/0.990 | 0.995/0.991 | 0.973/0.948 |
| GenPTW | 0.961/0.927 | 0.954/0.929 | 0.858/0.812 |
| EditGuard | 0.899/0.825 | 0.947/0.901 | 0.862/0.770 |

CASIA v2.0 上 masks 覆盖达图像 **96%**，作者指出因此所有方法都掉点，属口径说明（不是模型缺陷）。

### 3.3 编辑/失真后存活率（本轮最该记住的两张表）

**Table 2 定位（TGIF2，F1/IoU）**：JPEG QF90 **0.960/0.929** → QF80 **0.931/0.884** → QF70 **0.869/0.793**；Gaussian noise σ22 **0.989/0.980**、σ23 0.981/0.964；GenPTW 对应 QF90 仅 0.855/0.774，EditGuard 在 blur/noise 上塌到 **0.360/0.220**。

**Table 4 payload bit accuracy（从伪造图读回）**：

| 条件 | Ours w/ wm | GenPTW | EditGuard | MBRS |
|---|---|---|---|---|
| tampered（无额外失真） | **1.000** | 0.993 | 0.999 | 0.918 |
| JPEG 90 / 80 / 70 | **0.995 / 0.984 / 0.949** | 0.988/0.982/0.974 | 0.929/0.883/0.848 | 0.917/0.916/0.917 |
| Gaussian noise σ8/22/23 | **1.000/0.998/0.998** | 0.977/0.900/0.895 | 0.955/0.736/0.724 | 0.940/0.926/0.925 |
| resize 0.75 / 0.5 / 0.35 | **0.995/0.999/0.999** | 0.970/0.994/0.994 | 0.998/0.982/0.177 | 0.897/0.916/0.902 |
| random crop 30% | **0.993** | 0.990 | 0.999 | 0.826 |

**payload 代价**：`w/o wm` 在若干格更优（如 QF70 0.892 vs 0.869），作者明示载荷最多花掉 **2.3 F1 点**——即「判定 / 信息」两栏之间有一个可量化的小额税。

### 3.4 视觉质量（Table 3）

VeriOrigin 在 512² 下 PSNR 与 EditGuard 相近，但 **LPIPS 约为其 1/20**；可逆水印（CRMark/TrustMark/InviMark/MBRS）在 256² 上报 39.6–42.7 dB，分辨率不同不可直接比。⇒ 又一处「分辨率/分母不钉死就不能跨方法比」，与 11-09 的「先钉分母」纪律一致。

## 四、实验与结果

### 4.1 结果判读

- **编辑后水印存活率有明确下界**：TGIF2 覆盖 5 个 inpainting 模型，JPEG70 + 高斯噪声 σ23 + resize 0.35 三档下 payload 仍 ≥0.949，显著优于 EditGuard 在噪声/缩放下的崩塌（0.724 / 0.177）。这是本项目「按编辑强度轻/中/重分档测水印检出率」可直接引用的公开基线。
- **「判定 100% 而信息六成」的镜像**：`tampered` 条件下 payload 1.000，但定位 F1 需另报（Table 1/2），且 clean 与失真档差异大。⇒ 水印方案若只报「检出率 100%」，等于把「能不能定位、能不能恢复」两栏藏起来。
- **无损通道的 bit-exact 恢复**把「事件凭证」补齐：被挡/被改样本可以取回原 cover 做审计，这正是 11-23「所有被挡样本都要写带版本/阈值/规则指纹的结构化事件」所缺的物证层。
- **两阶段训练的约束型取舍**：先水印后定位，payload 只花 ≤2.3 F1 点；与 11-10「分层消融里单目标互相拆台、赢的是 trade-off」同族。

### 4.2 与 11-25 四层归因的关系

权重残留（SAE-Audit）、生成过程（GuideCache）、执行环境（batch 非确定性）、验收装置（overlap / 评测集重叠）四层都在**生成与判定侧**；VeriOrigin 是第五层——**输出凭证层**，只能证明「这张图从哪来、哪里被改、原图是什么」，不能阻止风险内容被生成。⇒ 任一层单独宣称内容安全已解决即判越界（边界第十三轮）。

## 五、局限性

1. **主动保护（proactive）前提**：需要在图像发布前嵌入水印/残差，对**已经流出的无保护图**无效；商用 API 未必允许写入。
2. **不区分良性编辑与恶意编辑**：作者原文点名现有方法「cannot tell a benign edit from a malicious one」，只定位不判意图 —— 与本项目 PORN/VULG 边界判定不能互替。
3. **无损恢复只在 lossless channel**：一旦重编码 / 降采样 / 截图，就退回有损通道，只剩 provenance + localization；与用户「编辑后水印存活率」的真实线上链路（多次分享）仍有差距。
4. **未报推理延迟 / 吞吐 / 量化 / 跨硬件**：两阶段训练与顺序嵌入的成本没进表，无法对齐线上 SLO。
5. **未覆盖视频 / i2v/t2v 落表**：TGIF2 虽含视频帧来源，但评测是单图；AIGC 全模态策略命中事件里 i2v/t2v 字段仍需自建。
6. **未测输入改写 / 生成过程干预**：纯输出侧，不参与 2,700+ 条出图侧内生风险的归因。

## 六、复现指南

### 6.1 论文复现

XOnet（Xnet/Onet cross residual）两阶段训练，lr $1\times10^{-4}$；CocoGlide / COVERAGE / CASIA v2.0 报 clean F1/IoU；TGIF2 报 10 种定位条件 + 9 种 payload 条件；同时报 `w/ wm` 与 `w/o wm`、PSNR/SSIM/LPIPS、无损通道 bit-exact 校验。**必做三条对照**：① 载荷代价（w/o wm）；② 跨分辨率（256² vs 512² 分母钉死）；③ 编辑强度分档。

### 6.2 本项目最小复现（推理为主，1 天，D4 输出侧图审与溯源）

1. **按编辑强度分档测水印存活率**：轻/中/重三档（局部小改 / 主体替换 / 大区域重绘 + 重编码 + 降采样），每档 100 条，报 payload 位准确率 + 定位 F1/IoU + 无损恢复成功率三栏。**判据**：轻编辑档就 <90% ⇒ 方案比公开基线（tampered 1.000 / JPEG70 0.949）更脆，不予上线。
2. **判定 / 信息 / 事件三栏进图审 AB**：现有「风险判定通过率」之外，加「篡改区域定位 F1」「被挡样本可恢复率」两栏；判定 ≥95% 而信息 <70% ⇒ 撤回「图审已达标」。
3. **结构化事件补物证**：所有被挡样本（含被当成「未命中策略」的）写带版本 / 阈值 / 规则指纹 / **原图可恢复标志**的事件；与 11-23 Tripwire-WM「拒了却没记录」的教训成对。
4. **责任边界写死**：3,000 条 case 的 2,700+ 条源于出图侧内生风险 ⇒ 水印/溯源只承担「输出凭证」，**不承担降风险**；不得因水印上线而回退生成过程干预的优先级。

**上线口径**：任何水印/溯源版本上线须报 payload 位准确率（分编辑强度/失真档）、定位 F1/IoU、无损恢复率、e2e 与嵌入/读出延迟、TTFT/超时率；shadow → canary 只换流量比例，冻结评测单位与 serving setup 指纹。
