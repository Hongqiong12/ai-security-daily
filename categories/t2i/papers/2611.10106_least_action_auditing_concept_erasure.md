# 擦除验收一直测错了对象：最小作用势垒量的是"冻结生成器还剩多少概率"，不是"这条 prompt 还调不调得出来"

## 一、背景与问题

### 动机：prompt attack 测的不是残留概率

概念擦除（concept erasure / unlearning）发布的是**开放权重**：ESD、UCE、RECE、SLD 这类方法改完权重后直接部署。领域对它们的验收几乎全部走 **conditioning 接口**：

> 重新 prompt 模型，看目标概念还出不出来；或者用对抗 prompt 搜索（UnlearnDiff、CCE、Ring-A-Bell、MMA-Diffusion、RECORD）去"钓"它。

论文一句话点破：

> *"A prompt attack tests whether one conditioning string still retrieves the erased concept. It does not measure the probability that the frozen generator still assigns to that concept."*

即：**「不再响应目标 prompt」≠「目标概念从生成动力学里被移除」**。一个被擦除的模型可以完全拒绝目标 prompt，同时仍把可观的概率质量留在「生成该概念」的事件上。一旦换一个 prompt 分布（真实流量 / I2P 式非显式 prompt / 图像条件），概念就重新出现。

### 与本仓库主线的关系

本仓库从 10-28 起连续九轮加固「权重侧 vs 输入侧」边界，结论一直是：**擦除做的是"这次画不出来"，不是"不知道"**。这篇第一次给出了一个**直接测量"还剩多少概率"的工具**，而且用它把四种标准擦除器在 NSFW nudity 上的泄漏率排出可复核的顺序。这正好服务任务里第 (4) 条要求：**明确指出权重侧范式与输入侧热更新改写的互补关系与各自失效边界，而非替代关系**。

## 二、核心方法

### 2.1 最小作用势垒（least-action barrier）

把冻结的反向扩散过程看成一个随机动力系统。定义 detector-defined concept event $\mathcal{E}$（例如「检测器判定这张图含 nudity」）。

$$\Delta S_{\text{rob}} = \inf_{u}\, \text{control cost}(u) \quad \text{s.t. 过程被驱动到 } \mathcal{E}$$

论文证明（Boué–Dupuis 变分表示）：**这个最小控制代价等于把模型条件化到事件 $\mathcal{E}$ 的路径空间 KL 散度，也就是事件的负对数概率** $-\log P(\mathcal{E})$。

因此：

| 势垒 | 含义 |
|---|---|
| 高 $\Delta S_{\text{rob}}$ | 概念事件在当前生成动力学下是稀有事件 ⇒ 擦除深 |
| 低 $\Delta S_{\text{rob}}$ | 概念仍然常见、只需很小代价就能到达 ⇒ 只是被"压住响应" |

### 2.2 与 prompt attack 的关键差别

| 维度 | prompt attack | least-action auditing |
|---|---|---|
| 搜索变量 | conditioning string | 反向过程上的控制轨迹 |
| 是否需对抗 prompt | 需要 | **不需要** |
| 是否需重训 | 不需要 | **不需要** |
| 测什么 | 接口可达性 | 冻结生成器的残留概率 |
| 输出 | 二值 / ASR | 连续势垒（nats），可排序、可校准 |
| 验收对象 | 「这条 prompt」 | 「这个 checkpoint」 |

### 2.3 双检测器共识终端

为避免「用一个自己也不懂概念的探测器去测概念」，终端用 **CLIP（优化指标）∧ DINOv2（独立共识）** 的 soft-AND：CLIP 优化出的 indicator 必须让独立的 DINOv2 nearest-centroid 检测器也同意概念真的回来了，才算到达事件。

部署泄漏的 ground truth 由**完全不参与审计的检测器栈**（NudeNet / ResNet-50 / ViT）在每模型 1,500 张新样本上计数 ⇒ **detector-disjoint**，避免自己验证自己。

## 三、技术细节

| 项 | 设定 |
|---|---|
| 基座 | Stable Diffusion v1.4（四种擦除器都发布该骨干的权重） |
| 审计网格 | 18 个 (concept, mechanism) 单元，跨物体类与 NSFW nudity；机制表共 31 个 erased models |
| 审计指标 | CLIP ViT-L/14；共识 DINOv2 nearest-centroid（nude 正质心 vs clothed-person） |
| 求解 | 在部署的 sampler 上解（含 classifier-free guidance、概念 prompt），不换采样器 |
| 泄漏计数 | 每模型 1,500 fresh samples，exact 置信区间 |
| Prompt 体制 | 显式 prompt vs I2P 的 sexual-category 非显式对抗 prompt（同 sampler / CFG / 检测器） |
| 算力 | 单项审计在单张消费级 32GB GPU 上可做；全程 A100 级 |

**三个容易被忽略的设计**

1. **校准不跨尺度迁移**：在 2-D 高斯混合扩散上校准好的数值，到 SD 尺度不保真；但 **rank 稳定**（Figure 7：势垒随优化预算变化而幅度变，排序不变）。⇒ 论文所有结论都用排序/相关，不用绝对 nats 跨配置比较。
2. **势垒由早期高噪声步承担**（Figure 8）：控制代价集中在大噪声阶段。这与 11-10 LeNO「初始噪声是唯一可调输入」、TailSteer「尾部单点校正」构成同一条机制线索。
3. **修复也用同一批轨迹**：审计找到的 instanton（最可能到达概念事件的路径）直接给出 closed-form patch 的方向，不需要重新训练。

## 四、实验与结果

### 4.1 势垒预测部署泄漏（核心表）

- 18 个 (concept, mechanism) 单元，池化 **Spearman ρ = −0.76，p = 5×10⁻⁴**（势垒越高，外部独立检测器数出的泄漏越少）。
- **每个被审计概念内，势垒更高的擦除器泄漏更少：18/18**（零反例）。
- leave-one-concept-out 校准能正确排序留出单元。

### 4.2 NSFW nudity 上四种标准擦除器的顺序

| 擦除器 | $\Delta S_{\text{rob}}$ | 部署泄漏率 |
|---|---|---|
| **UCE** | 3.9 | **16.4%** |
| **ESD** | 75.5 | **9.8%** |
| **RECE** | 224.5 | **1.4%** |
| **SLD**（Safe Latent Diffusion） | ≈ 0 | **85.5%**（显式 prompt 下） |

SLD 是最扎眼的一行：它是**推理期引导**而非权重擦除，在它调参时用的 I2P 式非显式 prompt 附近表现还行，换到显式 prompt 体制泄漏率摆到 85.5%。论文把这个称为 **prompt-regime sensitivity**（Figure 3c）——**同一个 checkpoint 的"安全率"取决于拿哪套 prompt 测**。

这条直接对应本项目「同一 Prompt 跨版本生成的风险漂移」以及「评测集口径版本号必须进看板」：换 prompt 分布就换结论，与换模型版本一样危险。

### 4.3 审计还能直接产出修复

| 修复 | 结果 |
|---|---|
| UCE nudity leakage | **16.2% → 0 / 1,500** |
| RECE church leakage | 降 **3.3×** |
| 对照：方向数匹配的随机编辑 | **失败** |

⇒ 势垒不是只做诊断，它定位到的方向是**可操作的修复方向**；而「随便改同样数量的方向」无效，说明定位本身有信息量。这与 10-28「先定位再擦除」（LoCo / Concept Acupuncturist）是同一条线索的定量版。

### 4.4 局限性的自我约束

论文明确写了「势垒幅度是 budget-indexed，rank 稳定」，并给出 church/RECE 的 leak–collateral frontier（Table 5）：修复在四个预注册判据里只过了 2 个（barrier 不降低、胜过两个基线），没过绝对阈值与 collateral 门槛。**作者没有把部分成功写成全面成功**——这一点本身值得学进本项目的报告纪律。

## 五、局限性

1. **只在 SD v1.4 上验证**：四种擦除器共同发布该骨干权重，因此可比；但没有扩到 SDXL / FLUX / DiT / 统一生成-编辑模型。BK-SDM-small（蒸馏 U-Net）上做了一个跨架构 sanity check，结论「重复 SD v1.4 的模式」，但只是单点。
2. **事件定义依赖检测器**：$\mathcal{E}$ 由 CLIP∧DINOv2 共识定义。换一套检测器 / 换业务类目定义（如本项目的 PORN/VULG 边界、政治 L2_30），势垒数值与排序都可能变；论文把 detector-disjoint 做在「泄漏计数」侧，没做在「事件定义」侧。
3. **绝对值不可跨配置比较**：只有排序与相关是稳的。若把 3.9 / 75.5 / 224.5 当成可下发的阈值会出错。
4. **不覆盖输入侧热更新**：审计与修复都是权重/轨迹侧，上线后逐条请求的可回滚、可分业务配置那一层完全不在射程内。
5. **I2P 式 prompt 的体制敏感性被指出但没给出解法**：论文只报告「换体制结论会变」，没有提出体制无关的验收量。

## 六、复现指南

**论文复现**

1. 取 SD v1.4 + 四种擦除器公开权重（ESD / UCE / RECE / SLD）。
2. 定义概念事件：CLIP ViT-L/14 优化 indicator，DINOv2 nude-vs-clothed nearest centroid 作独立共识。
3. 在部署 sampler（含 CFG）上解最小控制问题，得 $\Delta S_{\text{rob}}$；扫描优化预算确认 rank 稳定。
4. 独立检测器栈（NudeNet / ResNet-50 / ViT）在 1,500 fresh samples 上数泄漏，算 Spearman ρ 与 per-concept 顺序。
5. 用 instanton 方向做 closed-form patch，配方向数匹配的随机编辑作阴性对照。

**本项目迁移建议（零训练，1 天，写进方案即可）**

| 动作 | 具体做法 | 判据 |
|---|---|---|
| 补一条「权重侧验收」口径 | 若未来引入任何擦除/SFT 权重变更，除 prompt 级 ASR 外，强制报「换 prompt 体制后的泄漏率」（显式 / 非显式 / 图像条件三套） | 三套体制泄漏率最大差 >20 点 ⇒ 该版本不能只按单一评测集验收 |
| 给图审 AB 加 detector-disjoint 原则 | 审计用的检测器与验收用的检测器必须不同栈 | 同栈验收分数显著高于异栈 ⇒ 存在自证循环 |
| 明确互补而非替代（写死） | 权重侧管「上线前把概念概率压低」；输入侧热更新改写管「上线后逐条可回滚、可分业务配置」；输出侧图审管「已经生成出去的图」 | 任一层单独宣称"内容安全已解决"即判为越界 |

## 附：对业务主线的三句话

1. **权重侧范式第十轮加固，第一次有了"残留概率"的连续量**：prompt attack 只是接口可达性，$\Delta S_{\text{rob}}$ 才逼近"模型还知道多少"，且 18/18 排序零反例、ρ=−0.76 可复核。
2. **SLD 的 85.5% 与 I2P/显式体制摆动，是"换分母就换结论"的又一个硬证据**：跨版本对比必须先冻结 prompt 口径。
3. **互补关系写死，不能相互替代**：擦除管上线前权重治理与极少数不可逆概念；输入侧改写管上线后逐条热更新与分业务阈值；图审管已生成的图。三者的失效方向互不覆盖。
