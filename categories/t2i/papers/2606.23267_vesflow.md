## 一、背景与问题

### 动机

Flow matching 正在成为新一代 T2I 主干，但传统安全方法大多建立在两种假设上：
- 可以在很多 denoising steps 里反复纠偏；
- 或者可以通过 CLIP prompt embedding 操作把危险概念从条件侧挪走。

这两件事在 few-step flow matching 里都开始失效：步数太少，轨迹纠偏空间不够；而现代 T5 类文本编码器又让“危险语义”不再集中在少数 embedding 维度里。

### 核心科学问题

能否不改 prompt、不改模型权重，而是在 few-step flow matching 的**速度场**层面直接进行安全干预，同时尽量不伤 benign prompt 的图像保真？

### 对当前业务的重要性

这篇论文不做输入侧 rewrite，但它对你的价值很直接：它说明**“保留原 prompt + 在生成动力学里修正风险”**是可行的。这能反过来帮助你界定 rewrite 的边界：哪些风险必须在输入侧消解，哪些可以留给生成侧控制面处理。

## 二、核心方法

### （1）VESFlow：直接编辑速度场

作者的核心判断很干脆：既然 flow matching 学的是 marginal velocity，那安全干预也应该直接落在 velocity 上，而不是继续绕道 trajectory 或 embedding。

VESFlow 用安全评分器的梯度构造一个修正项，把当前速度场往“更安全的后验方向”推：
- prompt 本身保持不变；
- 模型权重保持不变；
- 只在采样时修改速度场。

### （2）自适应强度控制

修正项不是固定大小，而是根据当前安全评分自适应放大：
- 越不安全，修正越强；
- 越靠前的生成阶段，修正越重要；
- 这样能更贴合 few-step regime 的真实需求。

### （3）VESFlow+：安全方向拉近 + 不安全方向推远

在基础版上，作者进一步构造：
- 向安全条件速度场靠近；
- 同时远离不安全条件速度场。

这让 VESFlow+ 从“保守纠偏”变成“显式拉开安全-不安全边界”。

### （4）风险评分过滤器

论文额外做了一层很工业的设计：
- 先用风险分数判断 prompt 是否危险；
- 只有高风险 prompt 才启用速度编辑；
- 良性 prompt 直接走原始采样链路。

这一步很重要，因为它把“安全方法”从纯论文技巧，推进到了真实部署思路。

## 三、技术细节

### 为什么 few-step 时代传统方法会失效

作者对现有基线的诊断很到位：
- **轨迹级方法**（如 SGF）依赖多步累计；步数少时纠偏效果被压扁；
- **嵌入级方法**（如 STG、SAFREE）默认危险概念在文本条件侧有清晰可减的方向，但新编码器里语义已更分散。

### 关键公式直觉

VESFlow 的核心是构造安全条件后验下的速度修正：
- 用安全评分器梯度给出“往哪里更安全”；
- 用 `(1 - g(x))^-1` 控制“不安全时加大力度”；
- 用 `t / (1 - t)` 让早期阶段获得更强干预。

直觉上，它像是在采样最早几步就把轨道掰正，而不是等图像已经基本成形时再补救。

### 关键基线

论文比较的主要方法包括：
- **SGF**：轨迹级负引导
- **STG**：动态 prompt embedding 调整
- **SAFREE**：投影离开有害概念子空间
- **Semantic Surgery**：语义校准向量减法

这组基线刚好覆盖了当前常见安全干预路线，因此结果具有较强代表性。

## 四、实验设置与结果

### 主结果 1：在 8-step FLUX.1-lite 上，安全性显著提升

**FLUX.1-lite (8 步)**：
- 基线 Ring-A-Bell ASR：**64.6%**
- **VESFlow**：**26.6%**
- **VESFlow+**：**1.3%**

MMA-Diffusion 上：
- 基线：**66.5%**
- **VESFlow**：**5.2%**
- **VESFlow+**：**0.3%**

同时：
- FID：**26.55**（优于基线 27.13）
- CLIP：**0.264**（基本不变）

### 主结果 2：在 4-step MeanFlow 上仍然有效

这是这篇论文最关键的一点，因为 few-step 才是它真正要打的场景。

**MeanFlow (4 步)**：
- 基线 Ring-A-Bell ASR：**70.9%**
- **VESFlow**：**15.2%**
- **VESFlow+**：**6.3%**

MMA-Diffusion：
- 基线：**41.7%**
- **VESFlow**：**7.5%**
- **VESFlow+**：**6.8%**

同时：
- FID：**24.59** vs 基线 **24.71**
- CLIP：**0.262**，与基线一致

这几乎就是论文最有说服力的地方：**安全性大幅提升，而 benign 保真几乎不掉。**

### 主结果 3：风险过滤让“只在危险时出手”成为可能

论文表明：
- 对 benign prompt，不做编辑时效果不变；
- 引入风险过滤后，可以把额外计算只留给高风险 prompt；
- 推理时间约 **2.16 秒**，高于基线 **0.95 秒**，但明显优于 STG 的 **3.61 秒**。

### 对你当前业务的直接启发

如果迁到输入侧 rewrite，这篇论文最有价值的不是 velocity 公式本身，而是这三个抽象：
1. **保留原 prompt 是一条合法目标，不一定必须全面改写**；
2. **风险 gating** 应该先做，再决定是否进入更重的 rewrite；
3. **安全提升与语义保真** 可以被设计成显式 trade-off，而不是二选一。

## 五、局限性分析

1. **它不是输入侧 rewrite 方法**：更像生成侧 runtime intervention。  
2. **依赖安全评分器质量**：评分器偏差会直接传到 velocity 修正。  
3. **参数仍需调优**：例如 `t_max` 对稳定性较敏感。  
4. **主打 few-step flow matching**：对传统多步扩散模型的迁移价值有限。  
5. **无法单独解决语义包装型越狱**：对“表面 benign、实则危险”的 prompt 仍需要上游理解与 rewrite。

## 六、复现指南

### 环境依赖

```bash
pip install torch diffusers transformers accelerate
```

### 最小复现步骤

1. 准备 flow matching T2I 模型（如 MeanFlow / FLUX 系列）。  
2. 接入安全评分器，得到生成过程中的风险分数与梯度。  
3. 在高风险 prompt 上启用 velocity editing。  
4. 分别在 Ring-A-Bell、MMA-Diffusion 上测 ASR，并同步记录 FID / CLIP。  
5. 验证风险 gating 对 benign prompt 的开销削减效果。

### 对当前业务的最小迁移版本

即便你不复现整个 VESFlow，也建议借它的 routing 思路：
- 先做轻量风险判别；
- 低风险 prompt 不改写；
- 高风险 prompt 再进入 heavier rewrite / sanitization；
- 这样比“全部 prompt 一律重写”更接近真实生产系统。
