# 输入侧还有第二条路：不改文字，改嵌入

**论文主页**: https://arxiv.org/abs/2611.00819

**分类**: defense / inference-time

## 一、背景与问题

### 动机

当前所有输入侧干预都默认一个前提：**要改就改文字**。改写器输出一条新 prompt，再送进生成模型。

ODC 提出另一条路：**文字一个字都不动，改的是这条 prompt 在文本编码器里的嵌入。**

它的目标不是安全，而是"语义漂移"——生成图与 prompt 对不上，属性绑错、物体漏了、关系错了。但它的机制恰好是我们做"风险锚点外科替换"想要的那套东西：**识别偏差方向 → 取正交分量 → 词表检索 → 秩缩减剔除**。

### 四条论断

1. 语义漂移可以在**推理时**修正，不需要重训，不需要用户多给输入。
2. 漂移向量里真正有害的，是**与 prompt 本身嵌入正交**的那一部分——即"prompt 没要求、模型自己加进来"的概念。
3. 正交分量可以用**词表检索**离散化成一组词，再回到编码器空间做代理。
4. 概念移除不该硬减，应该用**QR 分解 + 相对幅值阈值**做自适应秩缩减。

### 与改写路线的关系（本文没有明说，但很关键）

| 路线 | 改什么 | 可解释性 | 可审计性 | 热更新 |
|---|---|---|---|---|
| Prompt Rewrite | 文字 | 高（人可读） | 高（diff 两段文字） | 高 |
| **ODC 式嵌入修正** | 向量 | 低（中间量） | 需额外记录（检索到的词集可作审计痕迹） | 高 |

**它把"改写"从自然语言层下沉到表征层**：不用再纠结"换成哪个同义词"，直接在方向上去掉。代价是失去了人类可读的审计线索——除非像 ODC 一样把方向再检索回词。

## 二、核心方法

### 六步流程

| 步 | 做什么 |
|---|---|
| 1 | 用原始 prompt 生成初始图 I₀ |
| 2 | 在共享 VLM 空间算 I₀ 与 prompt 的**漂移向量** v_drift |
| 3 | 取 v_drift 对 v_text 的**向量拒绝**（正交分量）v_orth，并用自定义词表检索 top-k 词集 S_orth |
| 4 | 把 S_orth 里的词用 T2I 文本编码器重嵌入，softmax 加权池化得 (E_orth, e_orth) |
| 5 | **自适应秩缩减概念移除**：QR 分解找 E₂ 的语义基，保留相对幅值 > ζ=1% 的主方向，从 E₁ 中剔除 |
| 6 | 用修正后的嵌入重新生成 |

### 关键公式

投影：v_proj = (v_drift · v_text / ‖v_text‖²) · v_text
正交分量：**v_orth = v_drift − v_proj**

词表检索：s(w) = cos(v_orth, e_w)，取 top-k 构成 S_orth。
softmax 加权：βᵢ = exp(s(wᵢ)) / Σⱼ exp(s(wⱼ))。

秩缩减：E₂ᵀ = QR，取相对幅值 > ζ=1% 的基向量作为"语义有意义"的方向。

### 一个设计判断值得抄

**先取正交分量，再减。** 不是"把漂移向量整个减掉"——那样会把 prompt 本身要求的内容一起减掉。减去投影，等于只减"prompt 没要求的部分"。

这个思路可以一比一搬到风险锚点：**风险方向 = 整条 prompt 嵌入里与"安全意图子空间"正交的那部分**。减去正交部分，等于保留用户意图、只去掉风险增量。

## 三、技术细节

### 三个可验证的量

| 量 | 数值 | 含义 |
|---|---|---|
| 秩缩减阈值 ζ | **1%** | 相对幅值低于主方向 1% 的基向量视为噪声 |
| 词表检索 top-k | 论文未给单一值（附录 G 给了检索结果样例） | 检索集是方向的离散代理 |
| 收益幅度 | **+1.4 ~ +1.7 CLIP** | 嵌入手术的天花板很低 |

### 为什么用 QR 而不是 SVD

QR 给的是**正交基**，可以直接判断"哪个方向上有能量"；而且对 batch×seq×hidden 的张量可以逐 batch 元素做，不需要全局矩阵分解。工程上比 SVD 便宜，代价是基不按方差排序，需要靠相对幅值阈值 ζ 来筛。

### 组件的作用（消融）

- **VLM 选择**：换不同 VLM backbone，收益一致 → 不是过拟合 BLIP2 的嵌入空间。
- **正交修正**：去掉"取正交分量"这一步（直接减整条漂移）会掉点 → 正交化是有效成分，不是装饰。

## 四、实验与结果

### Table 1：主结果（COALBench-300 / PartiPrompts）

| 方法 | COALBench-300 SDXL CLIP / BLIP | PartiPrompts SDXL CLIP / BLIP | FLUX.1 schnell COAL CLIP |
|---|---|---|---|
| Vanilla | 30.33 / 0.6078 | 30.83 / 0.6030 | 29.45 |
| CFG-Sweep (12.0) | 30.45 / 0.6083 | 31.13 / 0.6040 | – |
| Negative Prompt | 30.33 / 0.6078 | 30.83 / 0.6030 | 29.46 |
| Negative Prompt BoT | 31.19 / 0.6096 | 31.74 / 0.6051 | 29.89 |
| **ODC** | **31.80 / 0.6121** | **32.50 / 0.6074** | **29.92** |
| ODC BoT | **32.29 / 0.6127** | **32.99 / 0.6082** | 30.45 |

### Table 2：与 SOTA 对比（T2I-CompBench complex）

| 方法 | BLIP-VQA ↑ | UniDet ↑ | CLIP ↑ | 3-in-1 ↑ |
|---|---|---|---|---|
| SDXL | 0.442 | **0.025** | 0.293 | 0.3294 |
| A&E（Attend-and-Excite） | 0.436 | 0.023 | 0.290 | 0.3259 |
| ToMe | 0.468 | 0.022 | 0.292 | 0.3417 |
| **ODC** | **0.494** | 0.020 | **0.300** | **0.3572** |

### 四个必须单独拎出来的数

1. **+1.47 CLIP（30.33 → 31.80）**：这是"在嵌入空间做方向手术"能达到的语义修正幅度。放在 0–100 的 CLIP 分上，是 1.5 个点。
2. **UniDet 0.025 → 0.020（−20%）**：空间检测指标**反向**。语义对齐涨了，空间关系掉了。任何单指标报喜的做法在这里会翻车。
3. **A&E 29.54 < Vanilla 30.33**：一个专门做注意力引导的方法，**比不改还差**。说明"更用力地对齐"不等于"更对齐"。
4. **ODC BoT 32.29 > ODC 31.80**：best-of-two 还能再涨 0.5。说明单次嵌入手术有方差，需要选。

### 收益的量级怎么读

CLIP 分 30 → 32 是 **+5%** 相对提升，但在下游人眼可见度上属于"有改善、不算翻盘"。作者的定性图显示属性绑定改善明显，但空间关系无改善甚至变差。

**这是"表征层外科手术"的真实天花板**：它能精准去掉一个方向，但去不掉整条链路上的损失。

## 五、局限性

1. **收益小且不均匀**：CLIP/BLIP 涨，UniDet 掉。没有单一指标能同时改善。
2. **需要先跑一次生成**：要算漂移必须有 I₀，所以推理成本至少 ×1.5（BoT 是 ×2 以上）。
3. **依赖 VLM 判漂移**：VLM 判错的漂移方向会带进修正，产生新的偏差。
4. **词表是外挂的**：S_orth 的质量取决于词表覆盖；词表里没有的概念，检索不到，也就修不了。
5. **完全不涉及安全类目**：没有任何风险概念、NSFW、政策判定。安全侧迁移需要自建"风险方向词表"。
6. **单图、无时序**：不涉及多图或视频一致性。

## 六、复现指南

### 最小复现路径（按对我们的价值排序）

1. **零成本实验：把"风险锚点"做成方向而不是词**。取 200 条高危 prompt 与它们的改写版本，分别编码，算 ΔE = E(改写) − E(原始)；对每类风险（PORN / VULG / 政治 L2_30）求平均方向。如果类内平均方向的余弦相似度 > 0.5，说明"风险方向"是可估计的——那就存在一条不依赖文字改写的干预路线。**这一步只需要编码器，不需要生成。**
2. **对照实验：文字改写 vs 嵌入修正 vs 两者叠加**。同一批 prompt，三条路各跑一次，报语义保真/安全分/指令遵循三维。判据：如果嵌入修正的安全收益 ≥ 文字改写的 60% 且语义保真更高，说明现有改写链路有相当一部分工作在"用文字近似一个方向"。
3. **加正交约束**：如果保留改写路线，把"改写增量 ΔE"分解成"沿意图方向"+"正交方向"两部分，只惩罚正交部分。这比整条改写加安全惩罚更精准。

### 关键超参

| 参数 | 取值 |
|---|---|
| ζ（秩缩减阈值） | 1%（相对幅值） |
| 词表规模 | 论文自建大规模检索词表（视觉概念 + 通用短语） |
| BoT | 2 候选取 CLIP 高者 |

## 附：与业务的三条硬对应

1. **给"输入侧改写"提供了替代机制的对照基线**：以后任何改写收益，都该问一句"这是文字带来的，还是方向带来的"。
2. **给风险锚点替换提供了精确的形式化**：锚点不是"某个词"，是"嵌入空间里的某个方向"；替换不是"换词"，是"减去在风险方向上的投影"。这比词表替换稳健，因为它不依赖同义词库是否覆盖。
3. **给"改写可审计"提了要求**：嵌入修正天然不可读，若要上线必须把"检索回的词集 S_orth"作为审计痕迹落库——否则线上策略命中归因会断。
