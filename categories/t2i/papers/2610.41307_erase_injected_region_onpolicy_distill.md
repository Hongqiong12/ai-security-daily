# 拦住了，不等于拿掉了

**论文主页**: https://arxiv.org/abs/2610.41307

**机构**: **华南理工大学**
**发布日期**: 2026-10-30（v1，cs.CR）
**分类**: defense
**模态归属**: T+I2I 输入侧（图像作为不可信输入通道）· 原位锚点擦除 · 残留依赖度量

## 一、背景与问题

### 动机

多模态间接提示注入（multimodal IPI）和普通越狱不一样：**恶意指令藏在一份"同时包含用户任务所需信息"的媒体里**。

这句话的每个字都重要。如果一张图只有攻击内容，那直接拒掉就行。难的是这张图**既是攻击载体，又是任务证据**——你要读它，但不能听它的话。

论文把这个困境量化成了一个我们很少单独看的量：

> **现有防御能"拦住"，但同时也废掉了模型对那份媒体的使用能力。**

它把 ARGUS（多模态 IPI 专用的 SOTA）拉出来当对照，得到的现象是：**两边都把攻击拦住了，但只有 ERASE 把用户的问题答对了。**

### 我们为什么该看这篇

三个层次，从具体到抽象。

**① 它是"外科式原位替换"在图像空间的版本。** 我们的输入侧改写做的是：**在一段 prompt 里，把风险锚点换掉，其余语义不动**。ERASE 做的是：**在一张图里，把注入区域换成空白，其余像素不动**（图像用白块、音频用静音、视频用黑帧）。

这不是类比，这是**同一个动作在两种模态上的实现**。它解决的那个矛盾——"改动必须足够彻底才能消风险，又必须足够克制才不伤语义"——正是我们改写模型每天在权衡的东西。

**② 它给了一个"残留依赖"的度量，而不是只看拦截率。** 这是全文最硬的一招，下面细说。

**③ 它的训练范式是"参考视图蒸馏"，对应我们的"改写前后配对监督"。** 冻结的基座模型读擦除视图当 teacher，学生读被攻击视图，在**自己采样的轨迹**上对齐全词表分布。这是一个"用干净版当参考，让模型在脏输入上输出干净行为"的配方——可以直接搬到"用原 prompt 当参考，让改写模型在被改 prompt 上保持原意"。

### 核心问题

1. 攻击被拦住了，模型还在多大程度上被注入内容牵着走？
2. 能不能只擦掉注入的部分、保住周边的结构？
3. 这样训练出来的防御，会不会把通用能力也一起削掉？

## 二、核心方法

### （1）威胁模型：七元组

论文沿用 Lu et al. (2026) 的设定，每个样本是一个 7 元组：

`(x_u, m, x_i, t, y_u, y_i, φ)`

- `x_u` 用户原始指令
- `m` 非文本模态的外部数据（图 / 音频 / 视频）
- `x_i` 攻击者注入的指令
- `t` 触发短语（诱导模型执行 `x_i`）
- `y_u`, `y_i` 分别是 `x_u` 与 `x_i` 的参考答案
- `φ` 把 `x_i` 注入 `m` 的模态相关方式

**攻击者的能力被严格限制：只能往 `m` 里写，拿不到 `x_u`，改不了权重。** 这个约束很重要——它保证了"擦除"在原理上可行（注入内容是外来的、有界的）。

判定口径也很值得注意：**"部分执行 `x_i` 也算攻击成功"**。这比"完全执行才算"严得多，也是为什么后面的 ASR 能压到接近 0 而不显得作弊。

### （2）第一阶段：原位擦除视图

对每个被攻击的媒体 `m̃`，构造 `m_erase`：

| 模态 | 擦除方式 |
|---|---|
| 图像 | **白色补丁**覆盖注入区域（矩形） |
| 音频 | **静音**替换注入时间段 |
| 视频 | **黑帧**替换注入时间段 |

三个"不动"：

- **不动周边内容**（保空间/时序结构）
- **不动用户指令**
- **不要求部署时知道注入区域在哪** —— 原文：*"Training uses the injected region to build the reference; **deployment requires no region metadata or erasure**."*

最后这一条是工程上的关键：**擦除只发生在训练时造参考，推理时不需要检测器。** 这点和我们"改写只在输入侧，不动生成模型"的思路是同构的——都不在推理链上增加一个必须精确的模块。

### （3）第二阶段：在策自蒸馏

- **Teacher**：冻结的基座模型，读**擦除视图** `m_erase` + 用户指令。
- **Student**：可训练（LoRA），读**被攻击视图** `m̃` + 用户指令。
- **Student 自己 rollout 一条轨迹**，在每个共享前缀上，用**全词表 KL** 对齐 teacher 的完整下一 token 分布。

为什么是"全分布"而不是"采样 token"？因为 teacher 的分布里包含了**"该怎么用周边信息回答用户问题"**这件事，只对齐采样到的那个 token 就丢掉了。消融也证实了这点（见第四节）。

形式上是 on-policy self-distillation：teacher = student 自己 + 额外信息（这里是"没有注入"这个特权信息）。论文明确把它归类为 **privileged information** 设定。

### （4）诊断量：注入依赖 `I`

这是我认为最该被单独拿出来讲的部分。

**光看 ASR 不够。** 攻击被拒了，模型可能只是"输出被后置过滤器改掉了"，内部仍然被注入内容主导。所以论文定义了一个直接测"被牵着走多少"的量：

> 在同一个已生成输出前缀下，比较模型在 **被攻击视图** 与 **擦除视图** 上的下一 token 分布，取 **KL 两个方向的平均**。

`I` 越低 = 对注入的依赖越弱。

这个量的好处是：**它不需要标签，不需要攻击成功与否，只需要一对视图。** 它是一个纯"反事实对照"量——把注入拿掉，输出分布变多少。

## 三、技术细节

### 训练配置

| 项目 | 配置 |
|---|---|
| 基座 | Qwen2.5-Omni-3B / Qwen2.5-Omni-7B |
| 微调方式 | **LoRA** |
| 硬件 | 多卡 A800 |
| 目标函数 | 全词表 token 级 KL（teacher-first 方向） |
| 训练数据 | 良性媒体来自 VTQA（图）/ Clotho-AQA（音频）/ MSR-VTT（视频）；注入任务训练用 Stanford-Alpaca，验证用 GLUE，测试用随机字符串输出指令 |

### 评测指标（四个，缺一不可）

| 指标 | 含义 | 方向 |
|---|---|---|
| `UIA_clean` | 干净媒体上答对用户指令 | 越高越好 |
| `UIA_inject` | **被攻击媒体上**答对用户指令 | 越高越好 ← 这个最容易被忽略 |
| `AIA` | 攻击指令被完成的准确率 | 越低越好 |
| `AIF` | 攻击指令被跟随率（**含部分跟随**） | 越低越好 |

`UIA_inject` 是整篇的眼睛。很多防御只看 `AIA/AIF` 降了多少，不看 `UIA_inject` 掉了多少——一降一升，净收益可能是负的。

### 消融：监督信号与 KL 方向

在 Qwen2.5-Omni-3B 上（音频 / 图像两列）：

| 监督方式 | 音频 UIA_inject | 音频 AIA | 图像 UIA_inject | 图像 AIA |
|---|---|---|---|---|
| **全分布，teacher 先** | **0.601** | 0.000 | **0.541** | 0.000 |
| 只用采样 token | 0.531 | 0.000 | 0.441 | 0.000 |
| 全分布，student 先（reverse KL） | 0.588 | 0.000 | 0.513 | 0.000 |

**三种都做到 AIA = 0。** 差别全在 `UIA_inject`：只用采样 token 会掉 **7.0 点（音频）/ 10.0 点（图像）**。

这句话的普适含义：**当"拦截"这个指标已经饱和时，剩下的差异全在"保住多少"上；而这时监督信号的粒度决定了一切。**

### 擦除视图 vs 干净视图（参考怎么造）

同样在 3B 上，把 teacher 的输入从"原始干净媒体"换成"原位擦除媒体"：

| 参考类型 | 音频 UIA_inject | 音频 OOD 均值 | 音频 WER | 图像 UIA_inject | 图像 WER |
|---|---|---|---|---|---|
| **擦除视图** | 0.601 | 0.578 | **0.088** | **0.541** | **0.082** |
| 干净视图 | 0.610 | 0.554 | 0.221 | 0.526 | 0.097 |

两者 AIA 都是 0。但**擦除视图把 OOD 均值从 0.554 抬到 0.578、WER 从 0.221 降到 0.088**（音频），图像上 `UIA_inject` 还高 1.5 点。

原因：**原位擦除保住了被攻击输入的空间/时序结构**，所以 teacher 的分布更接近学生实际面对的输入分布；换成原始干净媒体，结构对不上，蒸馏目标偏了。

## 四、实验与结果

### （1）主结果：拦截率全部接近 0，差别全在"保住了多少"

Qwen2.5-Omni-3B，音频（最清晰的一组）：

| 方法 | `I`（注入依赖） | UIA_inject |
|---|---|---|
| 无防御 | **6.26** | 0.673 |
| ARGUS（SOTA，推理时干预） | **5.15** | 0.717 |
| Meta-SecAlign | 0.432 | 0.083 |
| **ERASE** | **0.0095** | **0.601** |

论文原话：*"On 3B audio, ERASE reaches 60.1% attacked-input accuracy compared with ARGUS's 33.1%, within 0.5 points of the undefended clean-input level."*

横过来读这张表，有两个数必须并排看：

**① ARGUS 的 `I` = 5.15，无防御是 6.26。** 也就是说：**ARGUS 把攻击拦得几乎干净了（ASR≈0），但注入对输出的影响只从 6.26 降到 5.15——只降了 18%。** 模型仍然被牵着走，只是牵到的地方不再"算攻击成功"。

这就是标题那句话的来源。**"拦截"是在输出空间量的，"依赖"是在分布空间量的。前者可以通过后置过滤刷到 0，后者不能。**

**② Meta-SecAlign 的 `I` 很低（0.432）但 UIA_inject 崩到 0.083。** 依赖没了，能力也没了。**低依赖不是好事的充分条件。**

**③ ERASE 落在 0.0095 / 0.601。** 依赖降 99.8%，`UIA_inject` 只比无防御掉 7.2 点，且距无防御的**干净**输入水平仅 0.5 点。

三个模态的 `I`（3B）：音频 6.26→**0.0095**；图像 1.16→**0.0030**；视频 3.41→**0.011**。ARGUS 对应 5.15 / 0.27 / 0.617。

### （2）OOD 能力保留

| 组 | 音频均值 | 图像均值 | 视频均值 |
|---|---|---|---|
| Base | 参照 | 参照 | 参照 |
| **ERASE** | 组内最高或并列 | 组内最高或并列 | 组内最高或并列 |
| Meta-SecAlign | 更高 | 更高 | 更高 |
| ARGUS | **GSM8K 上图像/音频变体分别拒答大量响应** | 同 | 同 |

**ARGUS 的 OOD 问题很典型**：它在注入基准上表现好，但换到 GSM8K 这类良性任务上，后置过滤开始**误拒**——论文原文说它的过滤"does not transfer reliably beyond the injection benchmark"。

**这是一个我们极熟悉的失效模式：后置过滤器在训练分布内表现优雅，出了分布就变成误杀机器。** 对应到我们的图审，就是"上线后误杀率 5.2%"这类数字的同类成因。

### （3）改动落在哪里：选择性纠偏

论文按"基座模型的注入敏感度"给输出位置分箱，测训练带来的改变量：

- ERASE 在**更敏感的位置改变更大**（3B 音频四分位：从最低敏感位到最高敏感位，均值改变量显著上升）；
- Meta-SecAlign 在**最不敏感的四分位也大幅改变**——即"该改的改了，不该改的也改了"。

这与 `UIA_inject` 的对比是同向的：**改得准，所以保得住。**

## 五、局限性

### 论文自述的（很诚实）

1. **前提是"注入区域可分离"。** 原文：*"ERASE constructs training references assuming that the injected region can be separated from benign content... Injected instructions may overlap or be mixed with task-relevant content, and erasure in these cases may also remove information needed for the user's task."*
2. **没测自适应攻击。** 攻击者若知道你在原位擦除，可以把注入拆散到多处、或写进语义里（而不是一个矩形块）。
3. **依赖注入位置是"连续区域"的假设。** 图像=矩形、音频/视频=时间片段。像素级弥散式注入不在射程内。

### 我们迁移时必须补的三条

**① "可分离"这个前提，在我们场景里恰好是最脆的一环。**

我们的风险锚点常常**和合规语义交织**。比如一句"医院走廊里穿病号服的女性"——"病号服"是中性词，"女性"是中性词，但组合在特定语境下可能是 VULG 边缘。**这里没有一块可以整块挖掉的白区。**

这正是我们 PORN/VULG 边界问题的同一个结构：**风险不在某个 token 上，在两个 token 的关系上。** ERASE 的擦除之所以干净，是因为注入内容在那份媒体里是"外来的、成块的"。文本里的风险锚点常常不是。

**② 它的 `I` 度量可以直接搬，但要换对照物。**

它比的是「被攻击视图」vs「擦除视图」的分布 KL。我们可以比：

> **`KL( P_model(· | 原 prompt) ‖ P_model(· | 改写后 prompt) )`**

如果这个 KL 很小，说明改写"几乎没改变模型的理解"——**语义保真**。如果这个 KL 很大而风险分降了，说明改写是靠"把意思改掉"换来的安全。

这比现在用的"embedding 相似度 / BLEU / LLM 打分"都要硬：**它是行为空间的差，不是文本空间的差。**

**③ "部分跟随也算成功"这个口径要抄。**

我们的安全判定现在只有"违规/不违规"两档。加上"部分达成风险意图"这一档，能区分"完全没听懂风险"和"听懂了但没做成"。这两类在业务上的处置完全不同（前者是漏过，后者是该给更硬的拒绝）。

## 六、复现指南

### 最小可跑版本（不用多模态，纯文本通道即可验证机制）

1. **造 200 条"文本版注入"样本**：一段正常内容 + 一段夹在中间的恶意指令 + 一个"部分执行"的判据。
2. **造擦除视图**：把那句恶意指令整段替换为等长的中性填充（不是删除——**保持长度和结构**，这点照抄论文的"white patch 而非裁剪"）。
3. **两种 teacher 参考对照**：A = 原始干净文本；B = 原位替换后的文本。看哪种作为蒸馏目标效果更好（论文预测 B 更好，因为结构对齐）。
4. **测三个量**：ASR、`UIA_inject`（被注入后仍答对用户问题）、`I`（两视图的对称 KL）。
5. **判据**：如果 A 与 B 的 ASR 都是 0，但 B 的 `UIA_inject` 明显更高 → **"原位替换"优于"换成干净版"这个结论在我们的文本场景也成立**，可直接用于改写对的设计（改写应"就地换词"，而不是"整句重写"）。

### 实现坑

| 坑 | 处理 |
|---|---|
| 只看 ASR 就收工 | 必须同时报 `UIA_inject`，否则"全拒答"会被当成满分 |
| 擦除用"删除"而非"替换" | 长度/结构变了，teacher 分布对不上，蒸馏目标偏 |
| 推理时还要检测注入区域 | 那就退化成"再训一个检测器"，工程上不可接受；照论文做法：**只在训练时用** |
| `I` 用单向 KL | 论文用双向平均；单向会偏向某一侧模式坍塌 |
| 位置分箱不查 | 不查就不知道是"选择性纠偏"还是"无差别压制" |

### 一句话工程结论

**训练时用"干净对照视图"造监督信号，推理时不增加任何模块——这个形态和我们"输入侧改写、不动生成模型"完全一致，可以整条搬。**
