## 一、背景与问题

### 动机：一致性判据必须能区分「必要修改」与「意外改动」

指令式编辑的老问题是**改了不该改的地方**：局部细节被悄悄换掉（Fig.1A）、全局空间结构漂移（Fig.1B）。现有 reward model 要么看不见细微视觉变化，要么**分不清「指令要求的修改」与「顺带发生的破坏」**，于是给 RL 的优化信号本身就不可靠。作者一句话点破：**增大模型规模并不必然带来可靠的一致性判断**（与 11-24「验收装置本身要先被验收」同族）。

### 与本仓库主线的关系（四重命中）

1. **I2I 编辑指令语义保真 / 0/0% 归因**：项目「图生图改写分流命中 0/0%」，长期缺一个能判「改写/编辑是否保住了非目标区域」的验收量。本文给出**成对准确率**口径：同一源图 + 同一指令下，两个编辑结果比谁更好地保住非编辑内容。
2. **图像一致性奖励（Qwen-Image 类）**：方向(4) 点名的「图像一致性奖励」第一次有工业界实现，且**直接挂到 Qwen-Image-2.1 上做 RL**，与 `grpo1102_125` / SFT 多版本线可对照。
3. **语义保真度量 / 三维评测**：把「语义保持」从单一相似度拆成**局部细节 + 全局语境 + 编辑意图对齐**三路证据，且训练期用额外证据、推理期只用指令 + 全图（**零推理开销的证据注入**）。
4. **风险知识召回 / 降级兜底**：双教师 + 梯度路由（按与 Score-MSE 梯度的对齐度选教师、双负则跳过蒸馏）是「多路召回取谁、命中冲突怎么办」的一个干净可迁移实现，呼应 11-16 安全指令库的「指令 ≤3 条直拼、>3 条排序取 top3」与「拼接/超时降级留事件」。

## 二、核心方法

### 2.1 双教师 On-Policy Self-Distillation（OPSD）

| 组件 | 输入 | 作用 |
|---|---|---|
| **学生** | 编辑指令 + 源图 + 编辑图 | 输出一致性分数 + 推理，受 Score-MSE（对人工保真分回归）监督 |
| **Local teacher** | 源图/编辑图的**匹配裁剪**（局部放大 + 掩码） | 抓细粒度物体细节变化 |
| **Joint teacher** | 匹配裁剪 + **全图对** | 判断局部变化**是否符合编辑意图**（该改 / 不该改） |
| 推理期 | **仅学生**（指令 + 全图） | 额外局部证据只在训练用 ⇒ 零推理开销 |

### 2.2 两个防「教师把学生教坏」的机制

1. **Score-Constrained Teacher Calibration**：教师分数分布用 **minimum-KL 投影** 校准到「参考分误差 ≤ 预算 0.01」的约束下（Eq.$q^*=\arg\min_{q\in\Delta_S} D_{KL}(q\|q_j)$ s.t. 期望 scoring error ≤ b），只做最小改动，避免直接蒸馏教师预测把 scoring bias 传下去。**误差预算 0.01、蒸馏强度 λ=0.95**。
2. **Score-Guided Gradient Routing**：每个 batch 计算各教师蒸馏梯度与 Score-MSE 梯度的**内积/余弦对齐度** $R_j$，选对齐度最高的教师；**两者都为负则跳过本次蒸馏更新**（不是硬选一个，而是允许「都不采纳」——这正是降级兜底该有的形态）。

## 三、技术细节

### 3.1 数据与训练

| 项 | 值 |
|---|---|
| 训练数据 | 从开源编辑数据构造，含配对的「必要修改 / 意外改动」样本；教师视图含 zoomed + masked crops |
| 评测 | **EditReward-Bench**（subject manipulation / appearance / scene restructuring / advanced editing）、**EditReward-Compass**（general / dynamic / multi-image / complex）、**EBench-18K**（OOD） |
| RL 验证 | 以 **Qwen-Image-2.1** 为 policy，在 GEdit-Bench-v1 / v2 / KRIS-Bench 上对比不同 reward model 的 RL 效果 |
| 学生规格 | PreserveReward-9B / **-27B** |
| 关键超参 | 校准误差预算 0.01；λ_dist=0.95；定位过滤器剔除不准的 crop |

### 3.2 消融（Table 3，EditReward-Bench pairwise accuracy %）

| 变体 | Obj. | App. | Scene | Adv. | **Avg.** |
|---|---|---|---|---|---|
| Base (Qwen3.5-9B) | 37.70 | 41.80 | 37.20 | 40.90 | **39.80** |
| Score-MSE only | 54.30 | 75.90 | 64.80 | 69.70 | 67.30 |
| Local Teacher only | 64.00 | 72.50 | 78.20 | 75.70 | 72.40 |
| Joint Teacher only | 64.90 | 78.50 | 75.00 | 74.40 | 73.50 |

## 四、实验与结果

### 4.1 人类偏好对齐（Table 1，pairwise accuracy %）

| 模型 | EditReward-Bench | EditReward-Compass | EBench-18K |
|---|---|---|---|
| Qwen3.5-9B（学生底座） | 39.80 | 39.22 | 56.70 |
| EditScore-7B / -72B | 59.10 / 58.60 | 53.16 / 58.18 | 64.37 / 64.16 |
| UnifiedReward-2.0-9B | 59.00 | 54.45 | 66.76 |
| GPT-6.1-Sol（闭源） | **82.70** | 79.74 | 77.94 |
| **PreserveReward-9B** | **80.60** | 78.93 | 76.61 |
| **PreserveReward-27B** | **84.70** | **84.60** | **80.73** |

**9B 超过所有开源 reward model 与多数更大 VLM（含 Gemini-3.1-Pro 73.30）**；27B 在三个 benchmark 全面第一，且后两者是 OOD 评测。相对 Qwen3.5-9B：**+40.80 / +39.71 / +19.91 点**。

### 4.2 RL 微调验证（Table 2，Qwen-Image-2.1 为 policy）

| Reward | GEdit-v1 Overall | GEdit-v2 Overall | KRIS Overall |
|---|---|---|---|
| Base（无 RL） | 8.86 | 8.83 | 3.67 |
| EditScore-7B | 8.93 | 8.92 | 3.62 |
| RationalRewards-8B-Edit | 8.47 | 8.29 | 3.33 |
| UnifiedReward-2.0-9B | 8.57 | 8.21 | 3.85 |
| **PreserveReward-9B** | 8.95 | 8.94 | 3.86 |
| **PreserveReward-27B** | **8.99** | **9.02** | **4.07** |

**关键反例**：EditScore-72B（−0.16）、RationalRewards（−0.39）、UnifiedReward（−0.29）在 GEdit-v1 上**做了 RL 反而不如 Base**，而 KRIS-Bench 上 UnifiedReward 却涨（3.85）——**同一个 reward 在不同 benchmark 上方向相反** ⇒ 这正是「奖励器本身没被验收」的实证，与 11-26 Measurement Artifacts「仪器项可反转符号」同构。

### 4.3 校准与路由动力学（Fig.3 / Fig.4）

- 校准后期望 scoring error 压进 0.01 预算内，且 KL 散度很小（最小改动）；
- 局部细节样本倾向选 local teacher，复杂意图样本倾向选 joint teacher；两教师梯度冲突时按 $R_j$ 取大者，双负则跳过。

## 五、局限性与迁移边界

- **纯视觉一致性，不涉任何安全语义**：无 NSFW / 政治 / 误杀率 / 拒答 / 输入改写；「该改 vs 不该改」是编辑意图，不是风险锚点。
- **不覆盖统一生成-编辑双通路**（只测编辑），未验证同一份改写 prompt 同时作用于生成与编辑两条通路的情形。
- **无跨语言**（编辑指令默认英文/通用），无法回答 2B 改写模型英文 ASR 漂移。
- **无延迟 / 量化 / serving setup 数据**；虽然推理期只用学生，但未报 TTFT/e2e 与 fp8-fp4 后成对准确率漂移。
- **教师是 VLM，_calibration 依赖人工参考分**；若迁移到安全分类，参考分需换成人工双盲有害性标注，且必须保留「双负跳过」而非退化成硬选 top-1（呼应 TIDE Theorem 3 弱命中部件保留）。
- **可迁的是形态，不是量级**：84.70% 等数字属编辑一致性专属；可迁的是「局部证据 + 全局语境双路 → 按与参考目标梯度对齐度路由 → 冲突可整体跳过 → 教师分布按误差预算校准」这条链路。

## 六、复现指南

1. **0/0% 归因的现成验收量（零训练，1 天）**：从 2000 条图生图评测集抽 200 条，把「编辑前后其余保持原样」改成**成对一致性判定**（同一源图 + 同一指令，比两个改写/编辑输出谁更少动非目标区域），按「局部细节 / 全局结构 / 意图对齐」三栏分别报，避免一个总分把三栏平均掉。
2. **奖励器验收前置**：D2 的 GRPO 面板在换任何 reward model 前，先跑「Base vs 该 reward 的 RL」在**至少两个评测集**上的方向一致性；若出现 Table 2 那样 GEdit 掉而 KRIS 涨，先判奖励器不合格，不进 ckpt 对比。
3. **召回降级兜底对照**：把 §2.2 的梯度路由移植成三臂——「硬取 top-1」「按对齐度选」「双负整体跳过 + 事件留痕」，报三臂的误杀率 5.2% / 漏过率 3.42% 与命中条目变化率；**允许「都不采纳」应显著降低误杀**。
4. **I2I 改写面**：固定一份改写后 prompt 分别走生成通路与编辑通路，报两通路的三栏一致性差；差 >15 点 ⇒ 不能共用一份改写（延续 11-26 D5）。
5. **不劣化留痕**：若一致性奖励上线，报分层宏平均 F1、`Δaggregate`/`Δmacro`、逐样本判定翻转率、检测器/奖励器版本、serving setup 指纹八栏。

---

**对本项目的落点（一句话）**：**「语义保真」必须能判「该改的改了、不该改的没动」，而不是一个整体相似度**；双教师 + 梯度路由 + 「都不采纳」的降级形态，可直接搬进 I2I 0/0% 归因与风险知识多路召回的兜底设计，且是 11-26 之后**工业界首次给出 Qwen-Image-2.1 上可验收的一致性奖励**。
