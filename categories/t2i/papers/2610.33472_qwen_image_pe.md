## 一、背景与问题

### 动机

工业 T2I 的输入侧改写（prompt enhancement, PE）解决的是一个很实际的问题：**用户请求太短，把大量视觉决策留白**。用户写"一罐桃子气泡水的产品照"，模型得自己决定打光方向、主体占幅、留白位置、材质高光——这些决定直接决定出图能不能用。

已有 PE 方法的共同取向是**语义对齐**：把用户意图保留住、补充清楚、别加戏。本文的取向不同——它认为 PE 真正缺的能力是**视觉设计（visual design）**，即"用什么方式呈现请求的内容"，并把它拆成四个可评分维度：

| 维度 | 具体内容 |
|---|---|
| **Lighting** | 光源方向、明暗对比、衰减、材质反光 |
| **Composition** | 主体位置与占比、视觉层次、平衡、景深分层 |
| **Layout** | 文字/图形/内容模块的对齐、间距、留白、排版层级 |
| **Detail** | 材质纹理、局部结构、环境细节、有信息量的内容 |

作者提出的核心论点是：**这四个维度在"正向扩写"范式里学不到**，因为正向扩写的监督信号来自语言模型自己的分布，而语言模型没有"什么样的图好看"的梯度。

### 核心科学问题

如何为"输入侧改写"这件事**构造一个来自图像侧的监督信号**，使得改写器学到的不是"把话说长"，而是"把图变好"？

### 为什么这篇对我们重要

对我们这条线，这篇的价值不在"prompt enhancement"，而在**它是本周期唯一一份公开的、完整可复现的工业级 T2I 输入侧改写训练配方**，而且是 Qwen 团队自己发的。它给出的两阶段结构与奖励构造方式，和我们做**安全改写**的两阶段（SFT + RL）在形式上完全同构，差别只在目标函数：它优化视觉设计，我们优化安全。**方法学可以整体搬，只换奖励。**

同时它给出一个必须记下的负面事实：**头部公司在 T2I 输入侧改写上公开发表的，全部是 enhancement，没有一篇是 safety。** 安全改写这条线在工业界是黑箱。这既是我们的窗口，也意味着没有现成配方可抄——只能从 enhancement 的配方里改造。

## 二、核心方法

### （1）两阶段：先造"来自图像"的监督，再用组内比较精修

**Stage 1 — CRD（Caption-Based Reverse Distillation，基于描述的反向蒸馏）**

这一步的巧思在**把监督方向反过来**。正向 PE 是 `用户请求 → 扩写 prompt`，监督来自人工标注或强模型蒸馏。CRD 走的是 `好图 → 稠密描述 → 当作改写目标`：

1. 拿一批**本身设计良好**的图；
2. 用稠密 captioner 为每张图生成描述（描述里天然携带打光、构图、排版、细节）；
3. 把"用户请求"当输入、"稠密描述"当目标，做 SFT。

这样改写器的监督信号**绕过了语言模型的先验，直接从图像侧获得**。作者给了一个分布层面的证据：在 t-SNE 里，Qwen-Image-PE-397B 的 prompt 嵌入与真实 T2I 训练 caption 分布重叠度（MAUVE **0.290**）远高于正向扩写（**0.032**）——即它输出的 prompt 更像"真实能被 T2I 模型吃下的 caption"，而不是"人类写得更漂亮的话"。

**Stage 2 — GDR（Groupwise Design Reward，组内设计奖励）**

这一步是本文对我们最有价值的部分。流程：

1. 对同一个用户请求，采样 $G$ 个改写候选 prompt；
2. 每个候选各生成 1 张图 → 共 $G$ 张候选图；
3. **把这 $G$ 张图拼成一张网格图**，交给一个多模态 judge；
4. judge 在**显式设计 rubric** 下打分，且**每个候选的得分以整组为条件**（conditioning each candidate's scores on the full group）；
5. 设计分 + 一个 alignment reward 合成总奖励，优化改写器，**T2I 主干全程冻结**。

三个设计决定值得单独拎出来：

- **网格化（grid）而不是逐张评**：把 $G$ 张图放在同一张画布上，judge 的视觉上下文被强制对齐，消除了"逐张评时每张图的绝对分数受呈现顺序/上下文影响"的问题。
- **组内条件化（groupwise conditioning）**：judge 看到的是"这一组里谁更好"，而不是"这张图值几分"。这从根上把奖励从**绝对尺度**换成**相对排序**。
- **只训改写器，冻结生成器**：与我们"不改生成模型、输入侧热更新"的部署约束完全一致。

### （2）规模化的三个轴，其中一个是"信息密度"

作者报告 PE 沿三个轴 scale：**训练数据量、模型规模、信息密度（information density）**。并且强调一个非对称结论：**足够的信息密度是有效增强的前提条件（prerequisite）**——密度不够时，堆数据和堆模型都无效。

这一条对我们有直接含义：安全改写器的训练数据如果只是"把风险词换掉"的浅层改写，语义信息密度低，scale 不上去；必须先保证改写样本携带足够的场景/属性/意图信息，扩数据才有意义。

### （3）泛化：学到的是设计原则，不是某个生成器的 caption 习惯

两个变体在**四个额外 T2I 主干**上都超过原始请求，且在 **HunyuanImage-2.1** 与 **FLUX 3 Image Klein** 上超过这两个主干的**原生 prompt enhancer**——而训练时并未接触这些主干的训练 caption。

## 三、技术细节

### 模型与初始化

| 项 | 配置 |
|---|---|
| 397B 变体 | 初始化自 Qwen3.5-397B-A17B |
| 9B 变体 | 初始化自 Qwen3.5-9B |
| 训练阶段 | SFT（CRD）→ RL（GDR） |
| RL 阶段生成器 | Qwen-Image-2.1，**冻结** |
| 发布 | Qwen-Image-PE-9B 开源（HF: Qwen/Qwen-Image-2.1-PE-T2I） |

### 奖励的三段式

$R = R_{\text{design}}(\text{grid}) + \lambda \cdot R_{\text{align}}$

- $R_{\text{design}}$：多模态 judge 在显式 rubric（Lighting / Composition / Layout / Detail）下对网格图逐候选打分，**组内条件化**。
- $R_{\text{align}}$：保证改写没有漂移出用户请求（保真约束）。这个角色对应我们改写里的"语义保真"项。
- 关键点：$R_{\text{design}}$ 是**组内相对**的，$R_{\text{align}}$ 是**绝对**的。作者把"能不能区分好坏"交给相对项，把"有没有跑题"交给绝对项——**两种奖励各管一件事，不混在一个标量里**。

### 评测

主评测 **Qwen-Image-Bench**（Li et al., 2026），固定 Qwen-Image-2.1 主干，报告 Overall + 分维度（visual design / aesthetics / image quality / human preference）。

## 四、实验与结果

| 结论 | 数据 |
|---|---|
| 397B 相对原始请求提升 | **+7.81** Overall（Qwen-Image-Bench，Qwen-Image-2.1 主干） |
| 9B 相对所有对比 PE 基线 | **Overall 全部超过** |
| 分布对齐（MAUVE vs 真实 T2I caption） | 本文 **0.290** / 正向扩写 **0.032**（约 9×） |
| 跨主干泛化 | 4 个额外 T2I 主干全部超过原始请求 |
| 超过原生 enhancer | HunyuanImage-2.1、FLUX 3 Image Klein 两处 |

**结论口径说明**：本文只报告 Overall 相对提升与 MAUVE，未给出各维度绝对值表；本精读不外推未给出的分维度数值。

### 一个必须注意的评测结构

它把"改写好"定义成**在固定生成器下的出图质量**，而不是"prompt 本身写得好"。这意味着：**改写器的好坏不能脱离生成器评测**。对我们的安全改写是同一个道理——不能只评"改写后的 prompt 看起来安全"，必须评"改写后的 prompt 生成出来的图安全且仍然表达原意"。

## 五、局限性

1. **完全没有安全目标**。四个设计维度里没有"安全性/合规性"这一维，rubric 也不含风险概念。它证明的是"输入侧改写可以训得很好"，不是"输入侧改写可以做安全"。
2. **奖励依赖强 judge**。GDR 的上限完全由多模态 judge 的 rubric 理解能力决定；judge 一旦对某个维度不敏感（如"细节丰富"与"画面干净"混淆），奖励就会把噪声当信号。作者没有做 judge 侧的消融/审计。
3. **组内比较需要 $G$ 次生成**。$G$ 张图 + 网格 judge，单步 RL 的推理成本是 $G$ 倍。这对我们的算力约束（5 节点）是一个实打实的门槛。
4. **评测只在 Qwen-Image-Bench 主榜 + 若干主干**，没有跨人类标注员一致性检验，也没有对"改写是否改变了用户真实意图"的独立度量（alignment reward 的内部实现未展开）。
5. **训练数据未公开**（只放模型）。CRD 依赖"设计良好的图 + 稠密 caption"，这套数据管线无法复现。

## 六、复现指南

### 可复现部分
- **9B 模型已开源**，可直接跑推理做基线对比。
- **CRD 管线可自建**：任意 T2I 模型 + 任意稠密 captioner（如 Qwen3-VL）+ 一批高质量图，即可构造 `(用户请求, 稠密描述)` 对。成本主要在 captioner 推理，不需要人工标注。

### 关键实现顺序（建议）
1. 先只做 CRD，不接 RL。判据：改写后 prompt 的**嵌入分布**是否向真实 T2I caption 靠拢（MAUVE 或简单的分布距离）。这一步不依赖生成器评测，最便宜。
2. 再加 GDR，但**先把 $G$ 压到 4**，网格用 2×2。判据：组内排序与人工偏好的一致率；若 $G=4$ 时排序一致性已经饱和，加 $G$ 不值。
3. alignment reward 单独做消融：关掉它看改写漂移率，确认它管的是"跑题"而不是"质量"。

### 迁移到安全改写的具体做法
- 把 rubric 的四个设计维度换成**风险维度 + 保真维度**：风险维度（PORN / VULG / 政治 L2_30）走组内相对打分；保真维度（意图是否保留、非目标属性是否变动）走绝对阈值门控。
- CRD 的反向思路可直接借用：**从"安全且意图保真的成品对"反推改写目标**，而不是让模型自由扩写。即：拿一对 `(原风险 prompt, 人工改写后的安全 prompt)`，把后者当 SFT 目标——这本质就是我们 reject_tag 改写数据的构造方式，只是本文证明了它可以系统化地做成"反向蒸馏"。

---

**一句话判断**：这是本周期唯一一份工业级 T2I 输入侧改写训练配方，方法学可整体搬到安全改写，**唯一要换的是奖励**；而它把"能不能区分好坏"交给组内相对项、把"有没有跑题"交给绝对项的分工，正好是修我们奖励失明的正确拆法。
