## 一、背景与问题

### 动机：审计 judge 缺少独立真值

VLM-as-a-judge 已经是图像编辑 benchmark 的默认验收通道（VIEScore、Kris、ImgEdit、EditReward 等）。但**审这些 judge 本身**极难，因为真实编辑图没有受控真值：

> 一张编辑后的图里，「要求的变化」「编辑器自己的伪影」「非预期副作用」「模糊的成功程度」四件事**缠在一起**，无法分离。judge 判错时，你不知道是它没看懂编辑，还是编辑本身就没做对。

论文因此把问题重述为：**judge evaluation, not editor evaluation**——要测的是判定器的感知能力，不是被测模型的质量。

### 与本项目的关系

本项目有三条线直接吃到这篇：

1. **输出侧图审 AB 双模型对比**：如果两个候选图审模型在真实评测集上差 2 点，而 judge 模板本身换个图文顺序就能动 14.1 点，那这个「2 点」没有意义。
2. **I2I 改写语义保真评测**：当前图生图改写分流命中 0/0%，历史归因之一是「判据无分辨率」。这篇给了一个**造受控真值评测集**的可复制配方（Blender 参数化 + 事实/反事实三元组）。
3. **评测集构建与多版本回归**：合成真值上的 judge 排名与两个真实图人类偏好基准 **ρ=0.95 / 0.71**，说明低成本合成审计能迁移到真实评测，不必每次都重标。

## 二、核心方法

### 2.1 合成真值：1,382 对 Blender 前后图

- **1,382** 个 before/after 图像对，全部在 Blender 里程序化渲染。
- **9 类编辑**（由真实用户请求归纳）：scale、removal/addition、material、movement、shape、rotation、articulation、lighting、camera（camera 含 zoom / view 两个子型）。
- **精确真值来自 3D 场景参数**：每个编辑是「对受控场景的一次已知干预」，因此「指令是否被正确执行」是**由构造决定**的，不需要人标。
- 视角约束：只保留编辑对象清晰可见的视角，避免 judge 输在「找针」而不是「看编辑」。

### 2.2 事实 / 反事实三元组

把 judge 当**二值验证器**（这条指令被正确执行了吗），配三类反事实：

| 反事实 | 构造 | 测什么 |
|---|---|---|
| **Directional** | 把核心编辑参数逻辑取反（左→右、大→小、开→关） | judge 是否感知**方向/状态**，而非只察觉"有变化" |
| **Cross-Edit-Type** | 指令描述另一种视觉易混的编辑（camera zoom ↔ object scaling） | judge 是否分辨**改的是哪一类** |
| **Wrong-object / No-edit** | 错对象 / 完全没改 | judge 是否被"看起来不同"骗到 |

⇒ **把"判对"拆成若干可独立归因的条件**，与本仓库 11-02 的 Condition-Decomposed、11-04 的原子要件是同一条方法线索。

### 2.3 25 个 judge 配置

按三种打分范式分组：generative scoring（VIEScore / Kris / ImgEdit 等）、proprietary 模型、probabilistic scoring（log-probability、reranker）。开源与闭源并列报，但**闭源只作参考**，主结论在可复现的开源配置上。

## 三、技术细节

| 项 | 设定 |
|---|---|
| 数据规模 | 1,382 对 before/after；9 类编辑 |
| 人类校验 | 5 名参与者 × 100 道多选题，验证合成编辑感知上无歧义 |
| MC Acc. | 把正确指令排在同源所有错误指令之上的准确率，**chance = 21%** |
| 主指标 | AUROC（factual vs counterfactual 的二值验证） |
| 配置数 | 25 个 judge 配置 |
| 一致性检验 | 与 GenAI-Bench / EditRewardBench 的 judge 排名做 Spearman 相关 |
| 提示格式 | 固定 template / image placement / scoring，显式报告 image–text ordering 的影响 |

**三条工程纪律（论文明确写进 recommendations）**

1. 判据真值必须**独立于**被审系统；
2. 报 judge 分数前先报 judge 自身的 AUROC；
3. **标准化并报告 prompt 格式**——单这一项就能移动 AUROC 最多 14.1 点。

## 四、实验与结果

### 4.1 主表（Table 1，Overall AUROC %，节选）

| Judge | 基座 | Overall | MC Acc. |
|---|---|---|---|
| VIEScore | LLaVA-OV-7B | **51.9** | 21.9 |
| VIEScore | Qwen3-VL-4B | 51.5 | 13.8 |
| VIEScore | Qwen3-VL-8B + Think | 64.1 | 30.8 |
| VIEScore | Qwen3-VL-32B | 65.3 | 32.3 |
| VIEScore | Qwen3-VL-32B + Think | 70.7 | 41.1 |
| VIEScore | Gemma-4-31B | 74.3 | 45.0 |
| Kris | Gemma-4-31B | 72.9 | 46.4 |
| ImgEdit | Gemma-4-31B | 74.6 | 46.8 |
| **VIEScore** | **GPT-4o** | **69.0** | 35.8 |
| VIEScore | GPT-4.1-mini | 67.4 | 32.7 |
| VIEScore | Gemini-2.5-flash | 72.8 | 44.6 |
| VIEScore | GPT-5.4 | 77.9 | 49.5 |
| VIEScore | GPT-5.6-sol | 88.5 | 71.5 |
| VIEScore | Opus 5 | 83.5 | 61.9 |

**三条硬结论**

1. **广泛使用的 VIEScore + GPT-4o 只有 69.0% AUROC**；微调过的专用 judge **51.7–66.3%**——开源微调 judge 大体在随机线附近挣扎。
2. **空间类编辑是系统性盲区**：GPT-4o 的 shape 54.5 / rotation 53.7；LLaVA-OV-7B 的 shape 仅 **39.4**（低于随机）。
3. **简单的 log-probability baseline 超过若干更复杂的 judge**——又一条「加复杂度不如换打分规则」的证据。

### 4.2 反事实类型分解（Table 2，VIEScore/LLaVA-OV-7B）

| Directional | Cross-type | Wrong obj. | No edit | Sem. 均值 |
|---|---|---|---|---|
| 52.9 | 53.5 | 52.5 | 51.6 | 53.0 |

四类反事实**全部贴近 50% 随机线**。⇒ 弱 judge 不是"某类编辑不会"，而是**几乎不具备二值验证能力**；它的分数在多数情况下不携带关于"指令是否被执行"的信息。这对 I2I 改写链路是最直接的一条警示：**若用这类 judge 判定"改写是否生效"，0/0% 很可能只是尺子没有分辨率**。

### 4.3 提示格式与真值可迁移性

- **image–text ordering 最多移动 14.1 点**；Table 5 显示把图像放在指令文本之后，对两个模型的 AUROC 都有实质提升。
- 尽管只用合成数据，judge 在 EditJudge-Bench 上的排名与两个**真实图**人类偏好基准相关 **ρ = 0.95 和 ρ = 0.71**（Table 3）；Table 4 给出 11 个共享配置在三份基准上的 Spearman 排名一致性。
- ⇒ **受控合成审计揭示的失效模式，与真实评测里的失效模式是同一批**；这使「先审计 judge、再跑业务 AB」成为低成本可执行的顺序。

## 五、局限性

1. **合成图 ≠ 真实生成图**：Blender 渲染没有生成模型的伪影、纹理不一致与幻觉；论文用 ρ=0.95/0.71 论证排名可迁移，但没有论证**绝对 AUROC 可迁移**。69.0% 不能直接读成"真实图审准确率 69%"。
2. **只测二值验证，不测分级严重度**：本项目的 L1–L4 递进、PORN/VULG 边界、政治 L2_30 层级都属于序数/细粒度判定，二值 AUROC 覆盖不到（这是本轮 2611.11847 / 2611.10472 等工作的射程）。
3. **9 类编辑不含安全类编辑**：没有「把违规元素改掉」这类指令，因此「改写是否消除风险」的判据仍需自建。
4. **人类校验规模小**：5 人 × 100 题，只用于验证合成编辑感知无歧义，不足以支撑 judge 与人类的一致性结论。
5. **闭源模型分数受版本漂移影响**：GPT-4o / GPT-5.x / Opus 5 的分数是特定时点快照，跨版本对比必须带配置指纹。

## 六、复现指南

**论文复现**

1. 用 Blender 搭受控 3D 场景，按 9 类编辑参数化生成 before/after；保留场景参数作真值。
2. 为每条事实三元组配 Directional / Cross-Edit-Type / Wrong-object / No-edit 反事实。
3. 固定 judge template、image placement、scoring rule；跑 25 个配置，算 Overall AUROC 与 MC Acc.（chance 21%）。
4. 单独跑 image–text ordering 两种顺序，报差值。
5. 用 GenAI-Bench / EditRewardBench 上同样 11 个配置的排名算 Spearman，验证合成集排序可迁移。

**本项目迁移建议（零训练，1–2 天，优先级最高）**

| 动作 | 具体做法 | 判据 |
|---|---|---|
| **给图审 AB 加"尺子自检"前置步骤** | 在跑双模型 AB 前，先用 200 条带人工真值的边界样本测两个 judge 各自的 AUROC + 两种图文顺序差值 | 图文顺序差 >5 点 ⇒ 现有 AB 差值不可信，先冻结 prompt 格式再重跑 |
| **I2I 改写链造受控真值小集** | 仿 Blender 三元组：同一源图 + 指令 + 方向反 / 改错对象 / 没改 三个反事实，200–300 条 | 若现有 judge 在四类反事实上都贴近 50% ⇒ **0/0% 是判据无分辨率，不是改写没生效**，先修判据再谈命中率 |
| **把 judge 自身指标进 6 版本看板** | 每个模型版本记录 judge 版本 / prompt 模板 / 图文顺序 / 该版本 judge AUROC | 跨版本对比时若 judge 配置变化 ⇒ 标记为不可比，不进趋势线 |
| **用简单 baseline 做下限** | 加一条 log-probability 基线进 AB | 复杂 judge 未显著超过基线 ⇒ 复杂度没带来信息 |

### 附：对业务主线的三句话

1. **图审 AB 必须先验尺子**：广泛采用的 VIEScore/GPT-4o 只有 69.0% AUROC，且换个图文顺序差 14.1 点；AB 里 2 点的模型差异在这个噪声下不成立。
2. **I2I 0/0% 又多一条可证伪归因**：判据本身在四类反事实全贴随机线，说明"改写生效与否"这个判定可能根本没有分辨率——这是零训练 1 天就能验的。
3. **合成真值可迁移（ρ=0.95 / 0.71）**：不必每次重标真实图，先造受控小集审 judge，是评测集构建里最省算力的一条。
