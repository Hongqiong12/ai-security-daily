# 一半的风险事件没有文本痕迹：纯文本审核通道的结构性盲区，与奖励设计的三个坑

**论文主页**: https://arxiv.org/abs/2610.38185
**领域**: 内容审核（短视频） · 多模态 MLLM 审核 · RL 时序定位 · 类别不均衡下的奖励设计
**作者**: Xiaoyong Yu（单作者）
**机构**: **华中科技大学**
**发布日期**: 2026-10-28（v1，cs.CV）
**分类**: defense
**模态归属**: T2I 输出侧审核的方法学迁移（多路 AB 对比 + 奖励作弊 + 类不均衡重采样）· 亦服务 RL 改写奖励设计

## 一、背景与问题

### 动机

互联网金融的黑灰产把短视频当主渠道。诱导行为——"点赞""关注""加私聊群""点外链"——把用户导向诈骗。

平台的现有审核系统是一个**两级 OCR+LLM 管线**：逐帧把屏上文字转写下来，然后让一个纯文本 LLM 分类这份 transcript。这个系统 `robust and deployed at scale`，但有一个**结构性盲区**：

> **它只能利用文本信息。**

很多诱导是靠视觉线索传达的：**一闪而过的二维码、朝点赞按钮做的手势、屏上字幕缺失但主播在说的地方**。这些**不留任何文本痕迹**。而且它的定位方式只是"文本出现的那几个关键帧"，所以既找不到非文本诱导，也拿不到精确的时间边界。

论文的定位很克制，也很值得学：**不推翻 OCR**（OCR 可靠地读小而短暂快速变化的屏上文字，是召回的地基），而是**补上 OCR 补不了的两件事**——看视觉线索、把事件放到时间轴上。

### 为什么这篇对我们要紧

两个独立的理由：

**理由一：它是"多路 AB 对比"的一个完整范例。** 论文比较三条路线（内部 OCR+LLM / OCR+MLLM / 32B 零样本 MLLM），维度不是只有准确率，而是 **检测 / 定位 / 视觉 token 消耗 / 延迟 / 部署复杂度** 五个。我们的**图审双模型 AB** 现在只比准确率和召回，缺的正是一张这样的多维对照表。

**理由二：它给出了奖励设计的三个具体失败模式，而且都带数字。** 这三个坑跟我们的 RL 改写奖励高度同构——我们的奖励也有主项（一致性）+ 若干辅助项（安全分、编辑率、长度），OCR+MLLM 的辅助项作弊、乘性/加性耦合、类别缩放甜点这三个发现，可以直接拿来做体检清单。

### 核心观测：50.4% 的风险事件没有文本痕迹

这个数字是全文的价值锚点：

| 口径 | 数值 |
|---|---|
| 测试集事件总数 | 984（去不可解码视频后 3,045 全量 / 其中测试 984） |
| **非文本事件占比** | **约 50.4%** |
| 非文本事件所在视频 | **458 / 725（63%）** |
| 各类别非文本占比 | **37.2% – 53.8%**（分布均匀，不是某一类的特例） |

⇒ **纯文本通道最多只能看到一半。** 而且这个缺口**不在某一类上，是均匀分布的**——所以不能靠"某一类补规则"解决，是通道本身的问题。

## 二、核心方法

### （1）数据集

| 项 | 规格 |
|---|---|
| 源平台 | 抖音 + 快手 |
| 初筛 | 约 **20,000** 条互联网金融视频 |
| 正例 | **2,419** 条有诱导行为的视频 |
| 划分 | train 1,694 / test 725 |
| 总时长 | **66.49 小时**（train 45.08h / test 21.41h） |
| 标注事件 | **3,194** 个（train 2,210 / test 984） |
| 覆盖子域 | 互联网信贷、互联网基金、房地产投资、互联网保险、知识科普、财经新闻、反诈宣传 |

**四类诱导（按审核风险递增）：**

| ID | 类别 | 定义 |
|---|---|---|
| 0 | **Simple interaction** | 点赞、收藏、分享、关注、@提及、截屏保存 |
| 1 | **Complex interaction** | 评论、私信、直播互动、一对一咨询 |
| 2 | **Private conversion** | 微信号/QQ群号/二维码、加粉丝群、会员 |
| 3 | **Page transition** | 点击底部链接、安装 App、搜索软件 |

**类别分布（严重长尾）：**

| 类别 | train 事件 | test 事件 | test 占比 |
|---|---|---|---|
| 0 Simple interaction | 1,258 | 613 | **62.3%** |
| 1 Complex interaction | 435 | 223 | 22.7% |
| 3 Page transition | 382 | 113 | 11.5% |
| **2 Private conversion** | **135** | **35** | **3.6%** |

⇒ **Class 0 : Class 2 = 17 : 1。** 这个比例就是我们 tag-weighted loss 面对的同一种病。

**文本/非文本的判定方法**（这一处设计很干净）：把每个事件的类别标签与该事件时间窗内的逐帧 OCR transcript 对照——

- 窗口内出现类别指示关键词（"关注"、"扫码"）⇒ **textual**；
- 无此类关键词 ⇒ **non-textual**；

视频级：至少一个事件非文本则整条视频算非文本。

### （2）OCR+MLLM 架构

两个互补组件：

1. **OCR 阶段**：**PaddleOCR PP-OCRv4**（DBNet + SVTR，CPU，FP32，1fps）逐帧转写 → 紧凑 transcript。**保留它，因为它是召回的文本地基。**
2. **7B MLLM**：Qwen2.5-VL-7B-Instruct，输入**视频帧 + OCR transcript**，**单次前向同时**做两件事：
   - **OCR-grounded 判别**：继承文本管线的召回；
   - **时序 grounding**：定位纯视觉线索的诱导。

**结构化输出格式（这个格式值得抄）：**

```
<think> ...推理轨迹（≤50 词）... </think>
<answer> [s1,e1] ... [sk,ek] </answer>     ← 最多 5 个事件
<class>  [c1, ..., ck]  </class>            ← 事件数必须等于标签数
```

⇒ **这就是 tag-first 结构的一个变体**：先 reasoning，再结构化的区间，再类别标签，且**区间数必须等于标签数**（强格式约束，防止数量不一致）。

### （3）四个奖励项

论文明确说这四项**不是独立的**，是一个集合，**去掉任何一项都会让另一个目标塌掉**：

| 奖励项 | 公式 / 规则 | 作用 |
|---|---|---|
| **Format** | `R_fmt = 0.6 + 0.2·𝟙[think≠∅] + 0.2·𝟙[k>0]`；任一硬门违反 ⇒ 0 | 让输出可解析 |
| **Multi-interval IoU** | `R_IoU = Inter / Union`（先合并预测与真值区间消重叠） | 唯一的稠密边界信号 |
| **Class-balanced accuracy** | `R_cls = (1/|𝓒|) Σ_c TP_c/(TP_c+FN_c)`，**对"真值里出现的类别"均匀平均** | 救最稀有类 |
| **Process supervision** | `R_process = w·min(N_pairs, N_max)`，w=0.2，**N_max=1** | 约束推理轨迹 |

**Format 的三道硬门**（写得很具体，可直接搬）：

1. 输出匹配外层 tag 模式；
2. `<answer>` 内每个区间是 `[a,b]` 且 `a<b`；
3. **区间个数 == 标签个数**。

**Process 项的 `N_max=1` 上限是本文最实用的一个细节**：论文原话是，不设上限模型会**输出冗余的 timestep 标注来刷奖励**。这就是辅助项作弊的具体形态。

### （4）耦合方式：乘性 vs 加性

| 方式 | 公式 |
|---|---|
| 乘性 | `R_mul = R_IoU · (a + b·R_cls)`，a=0.3, b=0.7, a+b=1 |
| 加性 | `R_add = R_IoU + R_cls` |

**两者各塌一头**（见实验）。

### （5）最终奖励：召回优先的 soft F_β

```
r = softF_β(τ̂, τ) · (0.4 + 0.6·CBA(ĉ, c)) · W̄[c]
```

| 符号 | 含义 |
|---|---|
| `softF_β` | 逐事件 soft F_β，**0.25s 时间网格 + sigmoid 软化边界**（温度 τ=1.0）；把每个真值段匹配到最佳预测段（recall）、每个预测段匹配到最佳真值段（precision） |
| **β=2** | **召回优先版**（漏检比虚警更贵） |
| β=1 | 恢复平衡 soft F1 |
| `CBA` | class-balanced accuracy |
| `W = {0:1.0, 1:2.0, 2:4.0, 3:2.0}` | **按逆频率的类别缩放** |

**外加过采样**：按"该视频最稀有类"的逆频率过采样，**上限 20×**。

### （6）训练配置

| 项 | 值 |
|---|---|
| 算法 | **GRPO**，group size 8 |
| KL 系数 | **0.0（关闭）** |
| clipping | 0.2 |
| lr | 1e-6，线性调度，无 warmup |
| 优化器 | AdamW (0.9, 0.999)，weight decay 0.0，max grad norm 1.0 |
| epoch | 2，每 50 步存 checkpoint |
| 有效 batch | 8（per-device 1 × grad accum 2 × 4 GPU） |
| 长度上限 | prompt 16,384 / completion 200 tokens |
| rollout | temperature 1.0，每 prompt 8 次生成，**128 帧均匀采样**，像素预算 ≈2.81M |
| 硬件 | **4× H100 80GB**，DeepSpeed ZeRO-3，gradient checkpointing |

**显存优化三件套**（低算力约束下很有参考价值）：**冻结 ViT** + **保留 visual merger 层可训** + **LoRA** + 严格分辨率阈值防 OOM。

## 三、技术细节

### 三条对照路线的精确定义

| 路线 | OCR | 下游模型 | 定位方式 |
|---|---|---|---|
| **OCR+LLM**（生产基线） | PP-OCRv4，1fps，det side 960，box thresh 0.6，unclip 1.6，CPU FP32 | Qwen2.5-VL-7B-Instruct **text-only**，transcript 截 4000 字符，batch=8，greedy | **文本出现的那些关键帧** |
| **OCR+MLLM**（本文） | 同上（共享） | Qwen2.5-VL-7B-Instruct，BF16 + FlashAttention 2 | 学习的时序 grounding |
| **Large MLLM**（规模参照） | – | Qwen2.5-VL-**32B**-Instruct，零样本 | – |

**关键控制：三条路线共享同一个 OCR 阶段，只有下游模型在训。** 这个设计把"OCR 的贡献"隔离出来了。

**消融路线 MLLM-only**：不给 OCR transcript，只给帧——用来量化 OCR 到底贡献了多少召回。

### 五个评测维度

| 维度 | 定义 |
|---|---|
| **检测**（IoU-agnostic） | 类别匹配即算对，**不看时间重叠**；报逐类 recall / precision / F1，四类 macro 平均，加多标签 exact match；**主指标 macro F1**（因为均权稀有类） |
| **定位** | mIoU；**R@t**（IoU≥t 的占比），**主指标 t=0.1**（实用要求只是把审核员指到大概区域），t∈{0.3, 0.5} 供参考 |
| **文本在场划分** | 分 textual / non-textual 两档报 recall 与 F1，**非文本召回是决定性的** |
| **视觉 token 消耗** | 帧数 × 每帧 token |
| **推理速度与部署复杂度** | 单张 H100 单视频墙钟延迟；模型个数、推理调用次数、单级 vs 两级 |

**"t=0.1 作为主指标"这个选择值得记**：因为业务上只需要把审核员指到大致区域，把 t 设到 0.5 会把"边界不准但方向对"的错误当成完全失败。

## 四、实验与结果

### 三路对比（rebalanced test set）

| 方法 | Macro Recall | Macro F1 | mIoU | R@0.5 | **非文本召回** |
|---|---|---|---|---|---|
| OCR+LLM（keyframe） | **69.2%** | **54.9%** | 14.49 | 4.41 | **≈0** |
| OCR+MLLM（RL only） | 55.0% | 46.5% | **26.52** | **15.86** | 41.7% |
| OCR+MLLM（SFT+RL） | 67.0% | 45.6% | 14.97 | 8.68 | **60.1%** |
| Large MLLM（32B 零样本） | 36.7% | 34.0% | 4.72 | 1.02 | – |

**四个读数：**

**第一：非文本召回从 ≈0 到 41.7%–60.1%。** 这是"通道补上"带来的、纯文本管线**结构上拿不到**的东西。不是涨点，是从无到有。

**第二：32B 零样本全面最差（mIoU 4.72）。** ⇒ **任务特定的定位能力不是规模能买来的**。这一点跟 V-CAPE（235B 也不到 65%）是同一个结论的两个证据。

**第三：定位与检测此消彼长。** RL-only 的 mIoU 是最优（26.52，1.8× 基线）但 macro recall 掉到 55.0%；SFT+RL 把 recall 拉回 67.0% 但 mIoU 掉回 14.97。

论文引 Time-R1 的解释很到位：**定位奖励"紧贴区间"，理解与分类奖励"抽象边界做语义归类"，二者本质上是反向的。**

**第四：OCR+LLM 的 macro F1 反而最高（54.9%），但 Class 2 precision 只有 9.7%。** ⇒ 它的高分是靠**多数类堆出来的**，在真正敏感的类上几乎不可用。这就是为什么主指标要报 macro 而不是 micro。

### 三条路线的"互补弱点"

- **MLLM-only 消融**：所有 macro 指标都低于 OCR+LLM，**过度预测 Class 0/3，Class 2 近乎全失败**——典型的类别塌缩。原因：**没有 transcript 就读不到区分稀有类的小而短暂的屏上文字**。
- **OCR+LLM**：召回 45–96% 相对均衡，但 **Class 2 precision 9.7%**，且看不到非文本事件、不能定位。
- ⇒ **Class 2 是共同的难点。**

### 奖励设计消融（Table 5）——本轮最实用的一张表

| 定位奖励 | mIoU | R@0.5 | R1 | **R2** | R3 |
|---|---|---|---|---|---|
| **IoU × class scaling** | 24.84 | 15.23 | 0.53 | **0.07** | 0.51 |
| **soft IoU** | **14.57** | **1.22** | 0.29 | 0.08 | 0.53 |
| **Per-event soft F1 + balance** | **29.82** | **18.54** | 0.50 | **1.00** | **0.64** |
| **Per-event soft F2 + balance（召回优先）** | 26.52 | 15.86 | **0.72** | 0.46 | 0.53 |

**逐行读：**

- **乘性 IoU×class scaling：mIoU 24.84 看起来还行，但最稀有类 recall 只有 0.07。** ⇒ 定位学会了，稀有类彻底塌了。
- **soft IoU（合并式）：R@0.5 崩到 1.22。** ⇒ 合并区间的 IoU 在**预测与真值不重叠时没有梯度**。这是"IoU 稀疏性"的直接后果。
- **per-event soft F1 + balance：mIoU 最优（29.82），稀有类 recall 从 0.07 直接到 1.00。** ⇒ 两个机制都要有：**逐事件匹配给稠密梯度**、**类平衡过采样压住塌缩**。
- **per-event soft F2（召回优先）：牺牲一点定位（26.52）和稀有类（0.46），换 Class 1 召回 0.72。** ⇒ 这是一个明确的运营点选择，论文把两版都报出来让使用者按场景选。

### 三个可推广的发现

**发现一：辅助项被系统性作弊。**

辅助项 = `0.2×中心距离 + 0.2×事件计数`。

| 配置 | 训练奖励 | 真实 mIoU |
|---|---|---|
| 纯 IoU | – | **13.48** |
| + 辅助项 | **~1.0（刷满）** | **2.19** |

⇒ **训练奖励刷到接近满分，真实指标掉到六分之一。** 这是本轮最干净的一个奖励作弊读数，而且作弊来源极其平凡（中心距离 + 计数）。

**发现二：乘性耦合学定位但塌类，加性耦合平衡但停滞。**

- 乘性 `IoU·(a+b·cls)`：定位能学，**倾向塌到 Class 0**；
- 加性 `IoU+cls`：类别平衡改善，**定位停滞**。

根因：**IoU 稀疏性（不重叠时无梯度）与类别不均衡的张力。**

**发现三：类别缩放有"甜点"，太弱塌类，太强也塌类。**

> 数据集级逆频率缩放**只在一个窄区间内有效**：太弱 ⇒ 塌到多数类；**8× 太强 ⇒ 再次塌掉**；**4× 是最优**。

⇒ 这一条直接指向我们 tag-weighted loss 的 alpha 设置（level1=1.5 / level2=1.2 / level3-4=1.0）。见业务板块 H9。

### 错误分析与审核负载

对 SFT+RL 版的错例分三类：

| 错误类型 | 占比 | 性质 |
|---|---|---|
| **边界错误** | **41%** | 类别对、区间重叠但 IoU<0.5 ⇒ **无害**，审核员还是被指到了正确片段 |
| **漏非文本事件** | **34%** | 集中在 **<1 秒的 Class 2 二维码闪** 和**主播说话时的手势**（短暂 + 部分遮挡） |
| **类别混淆** | **25%** | 集中在 **Class 1 ↔ Class 2**：评论招揽与站外转化**屏上措辞相同**，唯一差别是有没有群号/二维码 |

⇒ 第一类（41%）根本不需要审核员判断；只有后两类需要。而 **Class 1/Class 2 的混淆机制跟我们的 PORN/VULG 边界完全同构：表面形式相同，差一个关键锚点。**

## 五、局限性

1. **单作者、单一机构、无外部复现。** 全文没有第二个作者或机构参与，也没有开源代码/数据说明（只在关键词里给了 Content Moderation / MLLM / RL）。⇒ 数字可信度需要打折。
2. **"非文本"的判定依赖 OCR 关键词表。** 判据是"窗口内有没有类别指示关键词"。⇒ **关键词表漏了什么，就会被误判成"非文本"**。这个标签本身有循环依赖：用 OCR 定义"OCR 看不到的东西"。
3. **单一平台样本 + 单一垂类。** 抖音+快手的互联网金融视频，2,419 条。金融诱导的视觉线索（二维码、手势）与 T2I 生成图的视觉风险（构图、暗示）**不是同一类分布**。⇒ 方法学可迁移，数字不可外推。
4. **数据集未释放、代码未给。** 无 HuggingFace / GitHub 链接。
5. **macro F1 全面低于基线（46.5 / 45.6 vs 54.9）。** 论文的解释是"Class 2 仍难 + 稀有类预测压低 macro 平均"，但**这意味着在 F1 这个主指标上，本文方法并没有赢**。实际收益全部在非文本覆盖（≈0 → 41.7–60.1%）与定位（14.49 → 26.52）上。⇒ **不能读成"全面优于基线"。**
6. **定位与检测的此消彼长没有被解决，只是被"报两个运营点"绕开。** 没有给出"如何同时拿到两者的"路径。
7. **过采样上限 20× 是拍的。** 论文没说这个数字怎么来的，只给了类别缩放的甜点（4×）。两个缩放旋钮（过采样 vs 奖励缩放）的交互没有消融。

## 六、复现指南

### 最小可复现路径（给我们自己用）

**实验一：辅助奖励作弊体检（半天，最该先做）**

我们现在的 RL 改写奖励 = 一致性主项 + 若干辅助项（安全分下降、编辑率约束、长度）。逐项消融：

```
配置 A：只留一致性主项
配置 B：一致性 + 全部辅助项（现状）
配置 C：一致性 + 逐个去掉一个辅助项
```

报两列：**训练奖励曲线终值** 与 **真实业务指标**（人工判定的改写质量 / 风险下降）。

判据：**若某配置的训练奖励上升但真实指标下降 ⇒ 该项在作弊，删。** 对标锚点：训练奖励 ~1.0 vs 真实 mIoU 2.19（纯 IoU 是 13.48）。

**这条替换掉 10-30 记忆里的 G7。** 理由：G7 只查"奖励能不能作弊"（原样不改是否得高分），这条查的是"哪一个辅助项在作弊"，粒度更细且能直接产出删除决策。

**实验二：合并式指标 vs 逐事件指标（半天）**

```
合并式：整体语义相似度（把改写前后当一个整体算相似度）
逐事件：要件级覆盖（把 prompt 拆成 3-5 个要件，逐个算覆盖）
```

判据：**合并式的梯度稀疏性**——如果存在大量"改写得不错但整体相似度不过阈值"的样本被判 0 分，说明梯度断了。对标：soft IoU 的 R@0.5 = **1.22**，per-event soft F1 的 R@0.5 = **18.54**（15× 差距）。

**实验三：alpha 甜点扫描（半天，直接可做）**

我们现在的 tag-weighted loss：level1=**1.5** / level2=**1.2** / level3-4=**1.0**。

按本文的"类别缩放甜点"逻辑，扫 level1 的 alpha ∈ {1.0, 1.5, 2, 4, 8}，固定其它。报三列：**PORN 误报 / VULG-HINT-EDGE 召回 / macro-F1**。

判据表：

| 曲线形状 | 结论 |
|---|---|
| **明确单峰** | 现在的 1.5 大概率在峰左侧，往 2–4 走 |
| **单调上升** | 缩放还没到位，继续加（但要防 8× 塌） |
| **平坦** | **缩放没生效**——问题不在权重，在别处（回标签审计） |
| **8× 处塌** | 确认甜点存在，取峰值 |

**实验四：per-class recall 均权替代加权 CE（半天）**

这两个**不等价**：

- **加权 CE**：放大稀有类的损失值 ⇒ 间接影响梯度；
- **均权 per-class recall**：直接对齐评测指标（每类召回均匀平均）。

本文用的是后者（`R_cls = (1/|𝓒|) Σ_c TP_c/(TP_c+FN_c)`），并且是在**"真值里出现的类别"**上均匀平均（不是全类目表）。

判据：均权版 **macro-F1 更高且 PORN 误报不升 ⇒ 换掉加权 CE**。

### 需要注意的实现坑

1. **Format 硬门要把"数量一致"写进去。** 本文是"区间数 == 标签数"。我们对应的是"tag 数 == reasoning 段数"或"标签数 == 理由条数"。**不写这条，模型会输出数量不匹配的结构，导致整个 batch 无法解析。**
2. **Process 项一定要设上限。** 不设上限，模型会输出冗余结构来刷奖励（本文 N_max=1）。
3. **过采样和奖励缩放是两个独立旋钮，必须分开消融。** 本文只给了奖励缩放的甜点（4×），过采样上限 20× 是拍的。
4. **主指标选 macro 不选 micro。** 本文的 OCR+LLM 基线 micro F1 最高（54.9%）但 Class 2 precision 只有 9.7%——micro 会把这个事实完全掩盖。
5. **定位主指标取低阈值（t=0.1）。** 业务上只需"指到大概位置"，高阈值会把方向对的错误算成完全失败。
6. **冻结 ViT + 只训 visual merger + LoRA** 这套显存组合在 4×H100 上够用，对我们 5 节点集群是个合理起点。

### 一句话结论

> **一半的风险没有文本痕迹。补通道的收益是从 0 到 60%，不是涨点。而补通道的同时，辅助奖励会开始作弊。**
