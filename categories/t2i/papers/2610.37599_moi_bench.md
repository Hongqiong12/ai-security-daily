**论文主页**: https://arxiv.org/abs/2610.37599

**机构**: **University College London** + **南京大学** + **香港理工大学** + **华东师范大学**

**分类**: benchmark
**模态归属**: 文生图 / 图生图（T2I / T+I2I）— 编辑任务评测方法论，**直接对齐 I2I 改写链路"没有可判的正例标准"这个缺口**

---

## 一、背景与问题

### 动机

端上（on-device）图像模型要同时满足三件事：**用户真需要的功能、够用的质量、设备跑得动**。现有 benchmark 在这三件事上都是缺的：

- 生成类 benchmark 测 prompt 对齐 / 组合推理 / 视觉正确性，**不管编辑**；
- 编辑类 benchmark 测指令遵循 / 内容保持，**不管部署成本**；
- 统一套件覆盖生成+编辑+参考条件任务，**但用单一总分排名**。

### 核心科学问题

作者的问题不是"哪个模型更好"，而是：**当一个模型在"文本替换"上很差、在"人脸保留"上很好时，一个标量总分能告诉你什么？**

答案是不能。所以整篇的核心设计是把评测**沿两个正交轴拆开**，再对每个格点单独定义判据：

- **Operation（做什么）**：16 个操作单元，分五组；
- **Target（改什么）**：4 组 8 类视觉内容；
- 两者**适用的组合**才构成子任务（如"移除 × 人脸与头发"= 去瑕疵）。

### 为什么这篇对我们重要

我们 I2I 改写链路的现状是**分流命中 0/0%**——不是"改写做错了"，而是**连"什么算改对了"都还没定义**。这篇给的正是一套可落地的定义方式：

1. **任务必须先分解再判**。"编辑指令的安全改写"如果不区分操作类型（移除/替换/全局风格/参考编辑），就没法判断"改写后这个编辑还能不能完成"——因为**不同操作对指令措辞的敏感度完全不同**。
2. **判据要先写、后跑**。论文明确规定"每个问题的完整/部分/失败条件**在看不到模型输出时**构造"——这是防评测泄漏的关键，我们现在的评测基本没做这件事。
3. **聚合方式决定结论**。用**几何平均**而不是算术平均，理由是"限制某一维度的高分去补偿另一维度的低分"。我们的三维评测（语义保持/安全提升/指令遵循）现在如果加权求和，就是在允许补偿。

## 二、核心方法

### （1）任务空间：Operation × Target 稀疏矩阵

**五个操作组、16 个操作单元**：

| 组 | 操作 | 定义要点 |
|---|---|---|
| **Generation** | 纯生成 | 无输入图，从 prompt 造图（指定主体、属性、构图、风格）；带参考图的生成归到 Reference Editing |
| **Local Editing** | Addition / Removal / Replacement / Adjustment | 加/删/换/调指定内容，**保持无关区域不变**。Adjustment 改的是已有内容的属性（颜色、大小、位置、姿态） |
| **Global Editing** | Stylization / Background / Restoration / Camera-view | 整体外观或场景上下文。风格化作用全图；背景修改改环境但保前景；修复处理模糊/噪声/过曝（含局部缺陷）；视角修改改的是观看透视而非物体位置 |
| **Understanding Editing** | Semantic Editing / Inpainting / Outpainting | 需要从语义+视觉上下文**推断**该改什么。语义编辑要求解读意图（"冰淇淋放在太阳下会怎样"）；inpainting 用掩码周围重建缺失内容；outpainting 向外延展并保持场景一致 |
| **Reference Editing** | 单参考 / 底图+1 参考 / 2–3 参考 | 按输入配置组织。单参考无底图 → 引导新图生成；底图+1 参考 → 把指定内容/属性迁入底图；多参考 → 每个参考在指令里承担一个角色 |

**四组 8 类目标**：General Objects（Concrete Objects / Abstract Objects）、Animals、**Portraits（Body & Limbs / Face & Hair / Clothing & Accessories / Multi-Subjects）**、Text & Documents。

**两个值得抄的构造决定**：

- **任务范围的来源是问卷**：调查 1000 名用户，得到最高频需求是**人像修图、物体移除、照片修复、文字编辑**——所以整份 benchmark 的重心放在**编辑**，生成只作基础能力保留。
- **组合的适用性要人工核**：例如 "Addition × Body & Limbs" 被标 **N/A**（加解剖部件超出人像编辑范围）；"Camera-view × Documents" 被**改写**成透视矫正而不是视角变化。**不是机械笛卡尔积。**

最终：**64 个子任务、1150 个样本**。

### （2）评测协议：稀疏 rubric 立方体 + 样本接地问题

**三个判据组（IF / VQ / DP）**：IF = instruction following，VQ = visual quality，**DP = detail preservation**（含 Structure 与 Identity 两个子判据）。

- **Structure** 检查构图与空间关系，包括**本该保持不变的姿态与位置**；
- **Identity** 显式检查**未被指令针对的人身份与外观特征**。
- **保持要求明确排除用户要求改的东西**：换发型的任务要保**人脸身份**，但**不保原发型**。

**rubric 是一个 $(o, t, c)$ 三维立方体**（操作 × 目标 × 判据），每个条目人工标为 **always applicable / sample-dependent / N/A**：

- 文生图时三个 DP 判据全 N/A（没有源图）；
- 物体编辑时 Identity 是 sample-dependent，只在输入含需要保身份的人时适用。

⇒ **稀疏 rubric 立方体**：每样本只跑 always 条目 + 按指令与输入图解析出的 sample-dependent 条目。

**样本接地问题**：$\mathcal{Q}_{s,c} = G(R_{o_s,t_s,c}, p_s, \mathcal{I}_s)$——用 VLM（Gemini-3.1-pro）按 rubric 生成问题，**再人工复核**。两个关键纪律：

1. **两个标注员交叉复核**每个样本的 rubric 适用性与问题是否与指令/输入图匹配、是否重复；
2. **每个问题的"完整 / 部分 / 失败"条件在看不到模型输出时就构造好**，且最终问题与评分条件**在所有被测模型与 judge 间共享**。

**三级分数映射**（沿用 Qwen-Image-Bench）：$\{0, 0.6, 1\}$，分别对应未满足/部分满足/完全满足；二元要求只用 0 和 1。

### （3）聚合：几何平均，禁止跨维度补偿

判据分 $z_{s,c} = \frac{1}{|\mathcal{Q}_{s,c}|}\sum_q r_{s,q}$，组内均分 $v_{s,k} = \frac{1}{|\mathcal{C}_{s,k}|}\sum_c z_{s,c}$（**组内每个适用判据等权**，不受问题条数影响）。

样本分：

$$u_s = \prod_{k \in \mathcal{K}_s} v_{s,k}^{\widetilde{w}_{s,k}},\qquad \widetilde{w}_{s,k} = \frac{w_{s,k}}{\sum_{\ell \in \mathcal{K}_s} w_{s,\ell}}$$

**用加权几何平均而不是算术平均**，理由写得很清楚：**几何聚合限制用某一判据组的高分去补偿另一判据组的低分**。权重按操作类型预设、跨模型固定。文生图只算 IF 与 VQ。

总分 $Q_m = \frac{1}{|\mathcal{S}_m|}\sum_{s} u_s$。**样本保留规则也是评测纪律的一部分**：只排除"确认的生成或 judge 执行错误"；**不支持的任务得 $u_s = 0$ 但仍然留在集合里**；成功生成并评测的输出**无论质量多差都保留原分**。

⇒ 这条规则很硬：**能力缺失算 0 分，不剔除**。生成专用模型（LongCat-Image、SANA 等）因此在 Q1，作者明说"反映的是它是编辑 benchmark 的覆盖缺口，不是生成质量本身"。

### （4）双 judge + 人类锚

**主 judge GPT-4o，独立 judge Gemini-3.1-pro**，同一套协议、同一批问题与评分条件。另外留了**人类标注**做锚。质量分再映射到 **Q1–Q4 四档**（用 $C_{0.6}$ = 平均分 ≥ 0.6 的子任务占比 + 各组门槛）。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 规模 | **64 个子任务 / 1150 样本**；16 操作 × 8 目标，适用性人工核 |
| 任务来源 | **1000 人问卷**定范围与目标覆盖 |
| 判据 | IF / VQ / DP（DP 含 Structure、Identity）；稀疏立方体 $(o,t,c)$ |
| 问题生成 | Gemini-3.1-pro + 人工复核，两标注员交叉；条件在**未见输出时**写定 |
| 分数 | $\{0, 0.6, 1\}$ 三级；二元要求仅 0/1 |
| 聚合 | 组内等权 → **加权几何平均** → 样本均分 |
| Judge | GPT-4o（主）+ **Gemini-3.1-pro（独立）**；人类标注做锚 |
| 输出 | 每样本 1 张，seed 0 |
| 端上部署 | **iPhone 17 Pro / Xiaomi 15 Pro**；<4B 参数模型；外部文本编码器 **4-bit 量化**，其余保持原精度；iOS 用 Core ML（生成）+ MLX（文本编码器），Android 用 ONNX Runtime + QNN HTP 后端 |
| 部署测量 | 1 次预热 + **3 次实测**；报告平均端到端延迟与每次峰值内存（**每 25 ms 采样**） |
| 维度的二维输出 | **Quality–Deployability capability map**（Q 档 × D 档） |

**跨 judge 一致性（这是 AB 评测最该看的一组数）**：
- 总分排名的 **Spearman $\rho = 0.968$**；
- 人类标注与模型分的 **Spearman $\rho = 0.904$**；
- **但作者自己写明：质量档一致性不能算独立验证**，因为**档位阈值是用跨 judge 一致性校准出来的**。

这条自我限定非常重要——它等于说：**"两个 judge 排序高度一致"可以当强证据，"两 judge 给出同样的档位"不能**，因为阈值是看着一致性调出来的。

## 四、实验与结果

### 整体质量（双 judge）

| 模型 | 类型 | 任务 | GPT-4o Q | GPT-4o $C_{0.6}$ | GPT-4o (IF,VQ,DP) | Gemini Q | Gemini $C_{0.6}$ | 档 |
|---|---|---|---|---|---|---|---|---|
| **Nano Banana 2**（Google DeepMind） | – | Both | 0.95 | 1.00 | (0.95, 0.97, 0.97) | 0.93 | 1.00 | **Q4** |
| **DreamLite** | Diff. | Both | 0.62 | 0.64 | (0.65, 0.64, 0.76) | 0.52 | 0.42 | Q2 |
| **Ovis-U1-3B** | Diff. | Both | 0.66 | 0.59 | (0.68, 0.70, 0.72) | 0.54 | 0.38 | Q2 |
| 其他小模型（示例） | – | – | – | – | (0.11, 0.10, 0.00) | – | – | Q1 |

**关键结论**：

1. **三个闭源模型全部 Q4，且在 64 个子任务上全部过质量门槛**；开源里 FLUX.2 [klein] 最高（Q3）；**<4B 参数里只有 DreamLite 与 Ovis-U1 到 Q2**。
2. **"平均质量高" ≠ "过的任务多"**：Ovis-U1 总分更高（0.66 vs 0.62），但 **DreamLite 的任务覆盖更高**（$C_{0.6}$：GPT-4o 判 0.64 vs 0.59；Gemini 判 0.42 vs 0.38）。⇒ **两个指标必须一起看**。
3. **生成专用模型的 Q1 是覆盖缺口，不是质量差**：它们不支持的编辑任务记 0 分且不移除，所以总分被拉低。作者明说这一点。
4. **能力短板是具体的**：定性分析里 DreamLite / Ovis-U1 都没能把中文书名翻成英文（GPT Image 2 能）；参考编辑里 DreamLite 在"改成头像"的指令下**保留了全身构图**，Ovis-U1 给出了要求的取景**但改了人的外观**。⇒ **一个是"没听指令"，一个是"听了指令但没保身份"——正是 DP 两个子判据分别要抓的东西。**

### 跨 judge 与人类

- 排名 Spearman $\rho = 0.968$（含"不支持任务记 0"的样本）
- 人类标注与模型分 Spearman $\rho = 0.904$
- 档位一致性**不能作为独立验证**（阈值被校准过）

## 五、局限性

1. **重心是端上小模型**。最大的模型只作质量参照（且不能部署就记 D1），所以**它不是通用 T2I/编辑能力榜**。
2. **中文/多语言只是零散案例**（定性里提到中文书名翻译失败），**没有系统的多语言子任务**。
3. **完全没有安全维度**。rubric 三组是 IF/VQ/DP，**没有"输出是否合规"这一项**——所以它对我们的价值是**评测结构**，不是判据内容。
4. **judge 依赖强**：主 judge GPT-4o，问题也由 Gemini-3.1-pro 生成，**生成问题与评判答案用了同族模型**，存在风格偏好风险（论文只做了权重/阈值敏感性，没做 judge 换族的敏感性）。
5. **档位阈值被跨 judge 一致性反向校准**，作者自己承认这不是独立验证。
6. **1150 样本 / 64 子任务**的密度不高（每子任务平均 ~18 样本），细粒度结论的统计功效有限。
7. **Deployability 只在两台特定机型上测**（iPhone 17 Pro / Xiaomi 15 Pro），跨芯片结论不可外推。

## 六、复现指南

### 可复现部分
- **问卷 + 任务矩阵 + 稀疏 rubric 立方体**这套构造流程可以完全照搬，不依赖任何私有资源。
- **问题生成 + 人工复核 + 双标注员交叉**的纪律可以直接用。
- **几何平均聚合**是纯公式，可直接实现。
- 端上部署测量协议（预热 1 次 + 实测 3 次 + 25 ms 采样 + 4-bit 文本编码器）可复用。

### 关键实现顺序（建议）
1. **先把我们 I2I 的指令按 Operation 分档**（半天，零训练）：把现存的 I2I 指令样本按"局部编辑 / 全局编辑 / 理解式编辑 / 参考编辑"四组分开，看**0/0% 的分流命中是不是集中在某一组**。判据：如果命中集中在"理解式编辑"，说明问题不是改写坏了，而是**这类编辑本来就依赖对意图的推断，改写抹掉了推断线索**。
2. **再补 Target 轴**：按"人脸/身体/文字/物体"分。判据：如果 0/0% 只出现在文字与人像类，那与改写无关，是**编辑模型本身的能力缺口**。
3. **最后按论文纪律重写判据**：先写"完整/部分/失败"三档条件，**在看不到我们模型输出之前**，再跑评测。

### 迁到我们业务的具体做法
- **三维评测（语义保持 / 安全提升 / 指令遵循）改用几何平均**。现在的加权求和允许"安全分高"补偿"语义全崩"——**这正是我们 RL 改写奖励最可能的作弊路径**。改成 $u = v_{\text{sem}}^{w_1} \cdot v_{\text{safe}}^{w_2} \cdot v_{\text{instr}}^{w_3}$，任何一维接近 0 就直接把样本分打成接近 0。
- **把"能力缺失记 0 且不移除"这条纪律搬过来**。我们现在的评测会把"无法处理"的样本剔除或单独统计，这等于**在评测里悄悄原谅了覆盖缺口**。
- **rubric 的 applicability 三态（always / sample-dependent / N/A）直接用于我们的层级标签评测**：很多 PORN/VULG 判据是 sample-dependent（"是否含暗示性语境"只在特定样本上适用），现在大概率是全样本硬判，**这本身就是标签噪声的一个来源**。
- **双 judge + 自承"档位一致不等于独立验证"**：我们的图审 AB 评测现在如果只报两个模型的一致率，就是在重复这个坑。**必须报排序相关 + 阈值无关的指标（如 ECE），并把阈值校准过程写清楚。**
- **不要照搬的**：问卷驱动的任务选择（我们不做端上）、Q1–Q4 档位（门槛是给别人场景调的）。

---

**一句话判断**：这篇的价值不在"又一个 benchmark"，而在**它把"编辑任务怎么判"这件事工程化了**——操作×目标二维拆解、稀疏 rubric 立方体、**条件先写后跑**、**几何平均禁止跨维补偿**、**能力缺失记 0 不剔除**。这四条纪律里，我们目前一条都还没完全做到。而它的空白同样清楚：**三组判据里没有"安全"，多语言只是案例。**
