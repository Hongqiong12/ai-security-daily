## 一、背景与问题

### 动机

图像编辑已经从“能不能改”进入“改得是否遵循指令、是否保住原图语义、是否仍然自然”阶段，但现有 edit reward model 大多像一个粗粒度打分器：只给一个整体分数，很难回答“到底哪条编辑要求没做到”。这对工业安全尤其麻烦，因为输入侧 prompt rewrite / safe rephrasing 最终也需要一个可靠 judge 去衡量：风险是否下降、主体是否保留、语义是否漂移。

### 核心科学问题

能否把图像编辑奖励模型从“黑盒总分器”升级为“可解释验证器”，先逐条核验编辑要求，再把这种 verifier-style reward 反向用于强化训练图像编辑模型，从而同时提升 instruction following 与 semantic consistency？

### 直觉洞见

普通 reward model 更像一个只会说“这张图 7 分”的评委；而 Edit-R1 想做的是一个“逐项验收员”：先把需求拆成“哪些必须改、哪些必须保留、质量有没有坏”，再给总分。对你的 T2I 安全改写业务，这种思路很关键，因为真正缺的往往不是改写器，而是**能解释为什么这次改写既更安全又没过改写**的 verifier。

## 二、核心方法

**（1）Edit-RRM：验证式推理奖励模型（Verifier-based Reasoning Reward Model）**

作者提出 Edit-RRM，不再直接给单个整体分数，而是把编辑指令拆成三类 principle：
- **Keep**：原图中哪些内容必须保持；
- **Follow**：哪些显式修改必须完成；
- **Quality**：图像整体视觉质量是否仍可接受。

模型会先逐条 reasoning，再输出点式 reward，因此奖励本身带有显式验证结构。

**（2）Cold-start SFT：先把 verifier 训出来**

作者先构建大量 `(编辑图像, 原图, 指令, principle set)` 四元组，用 VLM 产生 CoT + score，再用外部 VLM 复核 reasoning 质量，筛出更可靠的轨迹做 SFT。这个阶段的目标不是直接最优奖励，而是让 reward model 先具备“会拆解、会核验、会解释”的基本能力。

**（3）GCPO：让推理型 reward model 吃下 preference data**

传统 preference optimization 更适合 pairwise 胜负，而 Edit-RRM 输出的是带 reasoning 的点式评分。为解决这个不匹配，作者提出 **GCPO (Group Contrastive Preference Optimization)**：
- 对 winner / loser 图像各采样多条 reasoning + score；
- 在组间比较 winner-losser ratio reward；
- 在组内计算 advantage；
- 用 clipped objective 更新 reward model。

这一步的价值在于：把“生成式 reasoning reward”与“人类偏好对”真正接上了。

**（4）下游 RL：用 verifier reward 反向强化编辑模型**

训练好 Edit-RRM 后，作者把它当作不可微 reward，用 **GRPO / Flow-GRPO** 优化下游图像编辑模型（如 FLUX.Kontext、Qwen-Image-Edit）。于是整体 pipeline 变成：

```text
编辑指令
   ↓
principle decomposition
   ↓
Edit-RRM 逐条核验 + 评分
   ↓
GRPO / Flow-GRPO
   ↓
更强 instruction following 的图像编辑模型
```

**关键设计差异**：不是继续训练一个更强 scorer，而是把 reward model 本身升级成 verifier。这对“语义保持 / 安全提升 / 指令遵循损失”三维评测特别有启发。

## 三、技术细节

### Principle-based reward 形式化

给定原图 x、编辑指令 u、编辑结果 y，作者先构建原则集合：

P(u) = {p_keep, p_follow, p_quality}

奖励模型不再直接输出单一分数，而是先对每条原则生成 reasoning，再聚合为总分：

R(y, x, u) = Agg({r_i | r_i = Verify(y, x, u, p_i)})

其中：
- `Verify` 表示逐原则核验；
- `Agg` 表示把多条局部验证结果汇总成整体 reward。

这相当于把 reward 从“一个黑盒标量”重写成“结构化审核过程 + 最终标量”。

### 冷启动数据构建

作者从公开编辑 benchmark 采样 **20 万**样本：
- **10 万随机样本**；
- **10 万困难样本**，重点覆盖多步编辑、细粒度修改、隐式语义理解与精确空间控制。

再由多个编辑模型生成候选结果，包括：
- FLUX.Kontext
- BAGEL
- SeedEdit3.0

最终得到约 **200 万**个四元组样本，用于生成 reasoning 轨迹与 SFT 训练数据。

### GCPO 目标

GCPO 的核心不是简单 winner > loser，而是对多条 reasoning 轨迹做组间/组内联合优化。可抽象写成：

L_GCPO = L_group-contrast + λ · L_advantage + clip(Δ)

直觉上：
- `L_group-contrast` 保证 winner 组整体优于 loser 组；
- `L_advantage` 在组内强化更优 reasoning 轨迹；
- `clip(Δ)` 控制更新不要过激。

### 下游 RL 关键超参

- 优化算法：**Flow-GRPO**
- **group size = 24**
- **KL penalty β = 0.04**
- 奖励模型底座：**Qwen-VL-2.5**
- 奖励模型规模：**3B / 7B**
- 下游编辑模型：**FLUX.Kontext / Qwen-Image-Edit**

### 对当前业务的直接启发

如果把这套方法迁到 T2I prompt rewrite，可以把 reward 拆成三组：

σ_total = α · σ_safe + β · σ_semantic + γ · σ_follow

其中：
- `σ_safe`：风险是否真实下降；
- `σ_semantic`：主体、风格、构图是否保住；
- `σ_follow`：改写后的 prompt 是否仍能驱动模型按意图生成。

这正是你要的“三维评测”雏形。

## 四、实验设置与结果

### 数据集与评价指标

**奖励模型评测**：
- 内部 benchmark：约 **5000** 个参考图像+编辑指令；
- 公共 benchmark：**EditRewardBench**；
- 指标：偏好预测准确率（↑）。

**下游编辑模型评测**：
- 数据集：**GEdit-Bench-EN**；
- 指标：
  - **SC**：Semantic Consistency（↑）
  - **PQ**：Perceptual Quality（↑）
  - **O**：Overall，SC 与 PQ 的几何平均（↑）
- 自动评测器：**GPT-4.1**。

### 主结果 1：奖励模型本身显著优于 scorer 基线

| 方法 | 内部 benchmark Acc (↑) | EditRewardBench (↑) | 说明 |
|------|------------------------:|--------------------:|------|
| Seed-1.5-VL | 79.3 | — | 强闭源 VLM 基线 |
| Seed-1.6-VL | 77.2 | — | 强闭源 VLM 基线 |
| Qwen-7B (Think+Verify SFT) | 75.4 | 73.3 | 仅 SFT |
| EditScore-7B + inference scaling | — | 72.7 | scorer-style 奖励模型 |
| **Edit-RRM 7B (SFT + GCPO)** | **82.2** | **78.2** | verifier-style reward 最优 |

### 主结果 2：下游编辑模型 instruction following 明显改善

**FLUX.Kontext**：

| 版本 | SC (↑) | PQ (↑) | O (↑) |
|------|-------:|-------:|------:|
| 原始模型 | 6.27 | 7.25 | 5.77 |
| **+ RL-RRM (7B)** | **6.86** | 7.20 | **6.24** |

也就是说，整体分数 **5.77 → 6.24**，主要提升来自 instruction / semantic consistency，而质量几乎没明显牺牲。

**Qwen-Image-Edit**：

| 版本 | SC (↑) | PQ (↑) | O (↑) |
|------|-------:|-------:|------:|
| 原始模型 | 7.94 | 7.78 | 7.45 |
| **+ RL-RRM (7B)** | **7.99** | 7.76 | **7.50** |

平均提升不大，但在难类目上更明显：**Motion Change** 类别的 SC 从 **4.01 → 4.62**，相对提升约 **15.2%**。

### 人类评测

- RL 后的 **FLUX.Kontext** 相比原始版本：**GSB = +23.2**。

### 消融结论

| 设置 | 效果 | 说明 |
|------|------|------|
| 仅 SFT reward model | 中等 | 能学会 verifier 语言，但 preference 对齐不足 |
| scorer-style reward | 较弱 | 解释性与稳定性都不够 |
| GCPO + verifier | 最优 | 组间比较与结构化 reasoning 共同起作用 |
| 用 reward 反向训编辑模型 | 明显提升 | 尤其改善 instruction following 难项 |

### 关键发现

- verifier-style reward 明显优于粗粒度 scorer；
- 结构化 reward 尤其适合难编辑任务，而不是只改善 easy case；
- “可解释核验”本身就是一种更适合工业上线的评测与训练接口。

## 五、局限性分析

1. **仍然不是安全专用 reward**：论文优化的是 instruction following 与 semantic consistency，而不是 NSFW 风险降低，因此不能直接当安全改写 judge 上线。  
2. **依赖强 VLM 生成与复核 reasoning**：冷启动数据和外部验证都比较重，成本不低。  
3. **公开复现门槛偏高**：当前未公开代码，GCPO 的具体工程细节需要从论文反推。  
4. **评测器仍可能带偏**：即使 verifier 比 scorer 更细，也仍受上游 VLM 偏见与奖励设计影响。  
5. **主要验证在 image editing，不是 T2I rewrite**：迁到文本改写场景时，需要重写 principle taxonomy 与 reward 定义。

## 六、复现指南

### 环境依赖

```bash
pip install torch transformers accelerate diffusers datasets peft
```

### 核心代码框架

```python
class EditRRM:
    def __init__(self, vlm):
        self.vlm = vlm

    def decompose(self, instruction):
        return {
            "keep": extract_keep_rules(instruction),
            "follow": extract_follow_rules(instruction),
            "quality": ["naturalness", "artifact_free"]
        }

    def verify(self, src_img, edited_img, instruction):
        principles = self.decompose(instruction)
        traces = []
        for key, rules in principles.items():
            traces.append(run_reasoning_check(self.vlm, src_img, edited_img, instruction, key, rules))
        return aggregate_score(traces), traces
```

### 复现步骤

1. 准备编辑数据与原图-指令-候选编辑结果三元组。  
2. 构建 principle decomposition 流程，把指令拆成 keep / follow / quality。  
3. 用强 VLM 生成 reasoning + score，再用第二个 verifier 过滤低质量轨迹。  
4. 先做 SFT，得到能稳定输出 verifier reasoning 的初始奖励模型。  
5. 准备人工偏好对，复现 GCPO 训练 reward model。  
6. 把 reward model 接到 GRPO / Flow-GRPO，优化下游编辑模型。  
7. 若迁到 T2I 安全改写，优先替换原则集合为：风险下降 / 主体保持 / 风格构图保持 / 指令遵循。

### 对当前业务的最小迁移版本

最值得先复现的不是整套 RL，而是 **verifier taxonomy**：
- 原 prompt 作为 anchor；
- rewrite prompt 作为 candidate；
- judge 分别输出 `risk_reduced`、`semantic_preserved`、`follow_preserved`；
- 先把三维评分器做稳，再考虑是否把它接到训练或数据筛选。
