## 一、背景与问题

### 动机：改写器在「修一个词」时，顺手把整个场景换掉了

输入侧安全改写的核心设定是「语义保真」：只外科式替换风险锚点，不改用户原意。本文从 T2I 自蒸馏角度给出了这套设定**在表示层为什么不成立**的第一份机制级证据。

论文场景是「模型从自己的失败里学习」：VLM critic 看到生成图不满足 prompt（例如「four brown monkeys」只画出三只），返回一份修订后的 prompt 作为 self-teacher 的条件。作者发现：critic 为了把修复说清楚，会把 10 词中位长度的原始 prompt 扩写成 **22–25 词**的完整场景描述，并在 **59%–74%** 的修订里加入用户从未要求的场景、光照、措辞（"warm, golden sunset light"）。

**关键读数**：只替换失败的 span 会让 prompt 保持不变（因为原句本来就已经写明了想要的修复），因此「有意义的修订必须扩写整个场景」——而扩写本身就把未经要求的语义带了进来。用这种整句改写做监督，学生模型把 critic 的场景偏好**内化成视觉习惯**：在受控的 sunset-favoring critic 下，两种基线的 sunset 出现率从 **2.2% 涨到 80%+**（冻结 teacher），teacher 每轮从学生更新时 **2 轮内达到 98–100%**；而 HinT 保持在 **4% 以下**。

### 与本仓库主线的关系（三重命中，本轮头条）

1. **输入侧改写的「语义保真」被证伪到机制层**。本仓库连续 19 周记录「输入侧安全改写方法零供给」；本篇虽非安全改写器，却是**第一篇正面解释「整句式 rewrite 为什么必然污染语义」的头部公司工作**，且给出可操作的修复形态：把监督信号从「改写后的文本」换成「同一模板下两个 slot 填值的差」。
2. **风险锚点外科替换的边界**。论文明确写道：**文本编码器会把单个 slot 的编辑传播到周围所有 token**（双向/因果注意力），因此「只改一个锚点」在 embedding 层并不局部——这正是本项目「外科式替换风险锚点 + 尽量不改变原意」假设的物理约束。修法不是更严格地约束改写器输出，而是**对齐 slot 外 token states**（论文 Sec 3.3）。
3. **改写有效性上界的责任边界**。11-24/11-25 已把重心从「加严输入改写」转向出图侧；本篇补上了输入侧那一半：**即使改写文本本身完全无害、字面改动极小，经过文本编码器后也会扩散成全局条件变化**，进而改变出图。⇒ 3,000 条 case 的归因里应新增「改写引入的表示层漂移」一栏，与出图侧四层并列。

**与 11-25 主题的接续**：上一轮是「钉死了输入，也钉不住出图」。本篇往前一步：**连「输入只改了一处」这件事，在表示层都不成立**。

## 二、核心方法

### 2.1 把「修正」从「改写」里分离出来：Hindsight Twins

critic 除给出观测错误 $a$ 与目标修复 $f$ 外，额外返回一份**带槽位的修订模板** $T$。用同一个模板填两次：

- 填上修复 → 修订 prompt $r = T(f)$；
- 填上观测到的错误 → **hindsight twin** $\tilde r = T(a)$，这是一份「失败样本本来就满足」的、 critic 措辞的描述。

两者**只在槽位处不同**，槽位外的词完全一致。把 teacher 的速度差 $\Delta_{\text{twin}} = \bar v_\theta(r) - \bar v_\theta(\tilde r)$ 加到原 prompt 的锚点速度上，共享的整场景改写被**相消**，只留下修复信号。作者称此为「蒸馏修正，而不是改写」。

### 2.2 必须再对齐「槽位外的 token states」

由于文本编码器把单 slot 编辑传播到全句，$r$ 与 $\tilde r$ 在槽位外的隐状态并不严格相同，直接相减会让 critic 加的 scenery 从差里漏回来。HinT 因此额外约束两个 twin 在槽位外的 token 表示一致（Sec 3.3），相消才干净。

### 2.3 为什么不用「用户措辞的 hindsight 对比」

把用户原 prompt 与「只改一个词的用户措辞版」对比也是 span-local 的，但缺少场景上下文，**训练不稳定**：FLUX.2-klein 上 EMA GM 崩到 10.4（HinT 25.4）。这是「最小改动 ≠ 最好监督」的直接证据，对本项目改写强度下沉有反面参考价值。

### 2.4 与 RL / 标量奖励的对照

DiffusionNFT（以「每轮满足问题的比例」为标量奖励的 on-policy RL）在 Tab. 3 落后 HinT **21.6 点**；即便给四倍 rollout 仍落后 11.0 点。作者结论：**速度蒸馏提供比标量奖励密集得多的监督**。这是本项目 GRPO 线「安全率作为主奖励」的重要对照——奖励稀疏时，改写策略学不到局部修复。

## 三、技术细节

### 3.1 实验设置（可复现口径）

| 项 | 值 |
|---|---|
| 主干 | Qwen-Image-2512（Qwen2.5-VL 文本编码器）、SD3.5-M（CLIP+T5）、FLUX.2-klein-base-4B（Qwen3）；均为 rectified-flow |
| 训练 | LoRA adapters；GenEval2 800 prompts 拆 400 训练 / 400 held-out，每 prompt 4 图；Qwen-Image 4 轮 × 60 updates，SD3.5-M 与 FLUX.2 各 6 轮 |
| critic | 所有方法共用 Qwen3-VL-32B；主指标 Soft-TIFA GM（Qwen3-VL-8B judge）+ 跨家族 InternVL3.5-38B（J2）+ detector-based GenEval 防同族偏置 |
| 权重 | 报 EMA（decay 0.98）与 final-round（Cur.）两套；3–4 seeds（HinT 与 cross-author pair）、2–3 seeds（其余基线） |
| 公平性 | 同 prompts / critic / rollout 预算 / LoRA rank / 更新计划；每个基线单独调自己的 teacher rule、EMA、对比尺度 |
| 开销 | 失败 rollout 上 HinT 与 cross-author pair 同为 3 次 teacher pass，比 positive teacher 训练时间 **+<4%**，**推理零开销** |
| 习惯探针 | sunset / cold-light / vintage-film 三种注入习惯的 critic；1,146 条 re-noised 首轮失败样本做速度空间分解 |

### 3.2 基线（每个都在隔离一个组件）

| 基线 | 做法 | 结局 |
|---|---|---|
| Positive self-teacher | 直接用 $v_\theta(r)$ 监督，不滤除改写 | 几乎不提升 alignment，吸收 critic 习惯 |
| Cross-author pair | $v_\theta(r) - v_\theta(h)$，$h$ 为用户措辞 hindsight | 有效但改写仍在，多轮后衰减/崩 |
| User-worded hindsight | $v_\theta(c) - v_\theta(h)$，纯局部、无场景 | FLUX.2 上训练崩溃（10.4 EMA GM） |
| SFT on revised prompt | 样本级：从 $r$ 重生成、通过 critic 的留下来微调 | 落后 HinT 6.7–16.8 GM |
| DiffusionNFT | 标量奖励 on-policy RL | 落后 21.6 点（Tab. 3） |

### 3.3 速度空间分解（诊断而非方法）

1,146 条 re-noised 失败样本上：整句改写的更新方向与「改写漂移」$\Delta_{\text{drift}}$ 对齐（$\cos(\Delta_{\text{pos}}, \Delta_{\text{drift}})$ 高），而 twin 与用户措辞局部修复只在高噪声区与 hindsight 对齐。⇒ **整句改写信号里压倒性的是漂移，不是修复**。这条分解把「为什么改写监督无效」从经验观察变成可测量的量。

## 四、实验与结果

### 4.1 主结果（Table 1，held-out GenEval2，Soft-TIFA GM）

| 方法 | Qwen-Image-2512 EMA | SD3.5-M EMA | FLUX.2-klein EMA |
|---|---|---|---|
| Base model | 33.9 | 19.6 | 23.5 |
| Positive teacher | 33.5 | 21.4 | 20.0 |
| Cross-author pair | 40.9 | 29.1 | 27.3 |
| User hindsight | 43.2 | 24.8 | **10.4（崩溃）** |
| **HinT** | **45.3** | **30.7** | **25.4**（Cur. 26.3） |

相对 base 提升 **+11.4 / +11.1 / +1.9 点**（FLUX.2 当前权重 +2.8，第 12 轮 EMA +7.9）；比 cross-author pair 在 Qwen-Image / SD3.5-M 上高 **4.4 / 1.6 点**，在 FLUX.2 上虽 6 轮 EMA 落后（25.4 vs 27.3），但当前权重更强且多轮后反超（pair 随轮次衰减）。Tab. 3（800 disjoint grammar prompts 训练、全 800 GenEval2 测试）HinT 达 **49.0 GM，超 base 17.2 点**。

### 4.2 零样本迁移（Table 2，未触碰的 benchmark）

| 主干 | GenEval（base → HinT） | OneIG-Bench（base → HinT） |
|---|---|---|
| Qwen-Image | 73.9 → **77.3** | 82.9 → **84.1** |
| SD3.5-M | 67.3 → **74.1** | 73.1 → **76.1** |
| FLUX.2 | 76.4 → **77.5** | 79.1 → **80.0** |

三种不同文本编码器上都涨，说明「相消共享改写」不是某个编码器的特性。

### 4.3 习惯吸收对照（本轮最扎的一组数）

- 三种注入习惯的 critic 下，两种基线产生 **45–97 个百分点**的习惯接管，却只有极小甚至负的 GM 增益；HinT 在**接近零接管**下抬 GM。
- sunset 出现率：基线从 **2.2% → 80%+**（冻结 teacher 第 5 轮）／**98–100%（2 轮内，teacher 随学生更新）**；**HinT < 4%**。
- **消融反证**：把改写加回 HinT 的目标，习惯立刻回来且 alignment 不涨；单纯 prompt critic「克制改写」挡不住注入习惯；强制最小编辑则牺牲 alignment 增益。⇒ 三条独立路径都指向「问题在监督单位，不在改写器话术」。

### 4.4 结果判读（对本项目的含义）

**判定 / 信息分栏的又一形态**：GM 这类对齐分能稳住，但「场景取向」这一维被悄悄换掉——与 11-10 NotaryMark（TPR 100% ↔ BA 60.69%）、11-25 GuideCache（图像级分不动而文本被改写）同族。⇒ 「语义保真」必须配一个**专门的非目标属性探针**（本文的 sunset probe），不能从总分推断。

## 五、局限性

1. **不是安全改写工作**：目标是组合对齐（数量、属性、关系），critic 加的是光照/场景偏好，不是 NSFW / 政治风险锚点。机制同构（改写污染表示层）但**迁移到内容安全需自己补风险判定翻转率与非目标属性探针**。
2. **需要一个「观测错误 + 目标修复 + 槽位模板」三元组**：线上输入改写只有原始 prompt 与改写结果，没有显式 slot 标注；要用需先做锚点定位（可接本仓库词级风险锚点表 2611.02348）。
3. **依赖 critic 质量**：论文用 Qwen3-VL-32B 并做了模拟 critic 错误鲁棒性测试，但小尺寸 judge 的可靠性未覆盖；与本项目 2B 改写模型现状有代差。
4. **只测三种 rectified-flow 主干**：未覆盖统一生成-编辑模型、真 CFG DiT、I2I 编辑通路；「一份改写 prompt 同时作用于生成与编辑两条通路」不在本文范围。
5. **没报推理延迟 / TTFT / 量化档**：推理零开销指不额外加 teacher pass（训练时已消化），但没有 fp8/fp4、batch、serving setup 指纹。
6. **FLUX.2 上 6 轮 EMA 反而低于 cross-author pair**（25.4 vs 27.3），作者靠「当前权重更强 + 后轮反超」解释——这是**按聚合选 ckpt 会挑错**的又一实例，需按版本×轮次留痕。

## 六、复现指南

### 6.1 论文复现

固定 Qwen-Image-2512 / SD3.5-M / FLUX.2-klein 三主干 + Qwen3-VL-32B critic；GenEval2 400/400 拆分、同 LoRA rank 与 rollout 预算；五基线各自调参；同时报 EMA 与 Cur.、Soft-TIFA GM / J2 / detector-based GenEval / GE / OneIG / ImageReward / HPSv2.1。**必做三条对照**：① 把改写加回目标（习惯是否回归）；② 三种注入习惯 critic；③ 1,146 条失败样本的速度空间分解（$\cos(\Delta_{\text{pos}},\Delta_{\text{drift}})$ vs $\cos(\Delta_{\text{twin}},\Delta_{\text{hind}})$）。

### 6.2 本项目最小复现（零训练，1 天，本轮最优先）

**目的**：验证「外科式替换风险锚点」在本项目改写模型上是否真的局部。

1. **建非目标属性探针**（照搬 sunset probe 形态）：从改写前后 prompt 里选 3 类显式属性——场景/光照、主体数量、语气极性——各 50 条，人工标「是否属于用户原意」。对现有 SFT 改写线与 GRPO 版各跑 200 条改写对，报 **非目标属性引入率**（改写新增且人工判非原意的比例）。判据：>10% ⇒ 现有「语义保真」指标（相似度 / edit_char_ratio / 锚点覆盖率）结构性漏报，立即补这一栏进验收。
2. **槽位对照臂**：把 100 条高危 prompt 做三版——(A) 现行整句改写、(B) 只替换风险锚点词、其余逐字不动、(C) 同一模板填「风险锚点」与「中性替代词」两版构成 twin。三版同 seed 出图，报风险判定差与原子要件保留率。**判据**：(B) 相对 (A) 风险不升而保真更好 ⇒ 改写强度应下沉；(C) 与 (B) 判定差 <5 点 ⇒ 单 slot 改动已被编码器扩散，需按 HinT 思路做「槽位外表示一致性」体检而非继续调改写器。
3. **奖励密度对照（RL 线）**：把 GRPO 的「安全率」标量奖励与「改写前后逐 token 条件差」密集信号对照，报同等 rollout 预算下的安全率与语义保真。**判据**：标量奖励显著落后 ⇒ devcloud `grpo1102_125` 的收益上限主要受奖励稀疏限制，不是策略容量不够。
4. **跨语言补臂**：中 / 英 / 中英混合三档各跑 1–3，报分语言非目标属性引入率；英文档显著更高 ⇒ 2B 改写模型英文 ASR 飙升可能部分来自「英文改写扩写幅度更大」，中英合并训练前先看这个量。

**上线不劣化验收口径**：任何新改写版本须同时报分语言安全率、分层宏平均 F1、逐样本判定翻转率、**非目标属性引入率**、TTFT/e2e 与 serving setup 指纹；只报聚合安全率微涨的一律不进看板。
