## 一、背景与问题

### 动机

这是本轮唯一一篇**头部公司公开的输入侧改写工业配方**，而且它把我们最关心的三件事写在同一份文档里：**改写怎么训、奖励怎么设计、评测怎么拆**。

论文的核心论点只有一句：

> **视频生成质量是多模态理解能力在 data → conditioning → alignment → evaluation 整条链路上的投影。**

推论：**观察到的生成失败不是诊断。** 同一个症状可能来自四类完全不同的原因 ——

| 症状 | 可能的真实病灶 |
|---|---|
| 该出现的东西没出现 | caption 漏了这条监督 |
| 顺序/时序错 | conditioning 表征丢了时间结构 |
| 运动呆板 | 奖励模型偏好"平滑但静止" |
| 分数虚高 | 评测器根本没测被要求的那件事 |

这个"失败不可直接归因"的立场，和我们做 I2I 分流 0/0% 归因时的困境是同一个问题。

### 四条论断

1. **瓶颈从渲染转向语义控制。** 视觉保真提升不会自动带来正确的动作、镜头语言、参考绑定。
2. **数据效率取决于描述密度。** DiT 的训练样本数远少于语言模型，扩规模补不上这个差距，所以"每单位时长视频的文本描述密度"是数据效率的中心指标。
3. **成熟的 DiT 有个"甜点区"，agentic 方法帮它到达。** 单改写模型容量有限，且"既要保真又要修矛盾"是互相冲突的目标，应该拆给两个模块。
4. **评测要跟着任务走。** 一个聚合分说不了病灶在哪，评测协议要任务特定、拆成可直接观察的准则。

## 二、核心方法

### （1）Prompt Enhancement 的双模块拆法

| 模块 | 层级 | 职责 | 什么时候跑 |
|---|---|---|---|
| **Agentic PE** | 内容层 | 剧情连贯化（修矛盾）+ 检索 Top-5 优质 caption 当创作证据 | 推理期，在 basic PE **之前** |
| **Basic PE** | 语言层 | 把请求**翻译成 caption 方言**（格式/词表/句式） | 最后一道，永远由它写最终条件 |

这个拆法的理由是：**"保真"要求别动用户写的东西，"合理"要求动它。** 放在一个模型里就是硬冲突。Agentic PE 在**剧情层**动，Basic PE 只做**语言层**翻译，两边各有各的目标函数。

### （2）Basic PE 的三层对齐

论文明确说，只对齐**格式**是不够的：

| 层级 | 具体要求 | 不对齐会怎样 |
|---|---|---|
| **Format** | 主体、动作、场景、镜头、光、音频按 caption 字段顺序；镜头时间戳；任务档位长度 | 长度、槽位顺序漂移 |
| **Lexicon** | 用 caption 流水线的镜头/光/动作术语 | 通用 LLM 会写 "a breathtaking cinematic shot slowly reveals the scene" —— 落在分布外 |
| **Sentence patterns** | 陈述句、现在时、实体显式 | 会写 "As if time itself had paused, she gazes outward, lost in distant memories" —— 抒情，不在 caption 分布里 |

> **"Matching format alone leaves the other two levels free to drift."**

### （3）数据是**反向构造**的

不从"用户 prompt"出发，而从"**优质视频的 caption**"出发：

1. 拿真实视频的 caption 当目标
2. 让 teacher 模型写"什么样的用户 prompt 会产生这个 caption"
3. 合成 prompt 按**真实流量统计**采样：目标长度、语言混合、语域、错字率、省略槽位集合，都从日志里采
4. **拒绝"泄漏 caption 骨架"的 prompt**（比如按 caption 顺序列出每个动作阶段），否则 PE 会学成复制而不是补全

这一条对我们是直接可搬的：**如果我们用"风险改写"的正例训练改写模型，正例应该从"安全输出的描述"反推回"用户可能怎么问"，而不是从用户 prompt 正推。**

### （4）三阶段训练

| 阶段 | 用什么信号 | 需要渲染吗 |
|---|---|---|
| Stage 1: Caption 对齐 SFT | 优质视频 caption + 反向构造 prompt + F/R/V 三验证通过的配对 + RAG 配对 | 否 |
| Stage 2: **文本级 RL** | 保真（checklist）/ 合理（空间图 + 交互图）/ 生动（技法库命中数） | **否** |
| Stage 3: **DiT-in-the-loop RL** | 视觉质量 / 运动质量 / 文本对齐（checklist） | 是 |

Stage 2 用 GRPO，**保真项门控其他项**：违反显式要求就不给生动分，防止拿意图换奇观。

## 三、技术细节

### 三个可验证的量

| 指标 | 怎么算 | 关键设计 |
|---|---|---|
| **Faithfulness（保真）** | 把用户 prompt 拆成原子要求 checklist（实体/属性/数量/动作/空间关系/镜头指令/引用文本/音频/参考绑定/排除项），逐条判"满足/违反/未涉及" | **违反比遗漏权重更高；"加了一条与某项矛盾的内容"算违反** |
| **Reasonableness（合理）** | 逐句增量建两张图：**空间图**（相对位置/接触/包含/视角）+ **交互图**（施事/动作/受事/前置条件/结果状态）；每句对照两图和世界知识 | 冲突要**报出引入它的那一句** |
| **Vividness（生动）** | 按表演/镜头/光色/节奏/声音五轴抽表达元素，对照由优质视频编成的**技法库**，命中数计分 | **每轴去重且设上限；只有通过合理性检查的元素才计数**（堆术语不涨分） |

合理性的例子值得记：*"男人把杯子放桌上，走向门口；他开门时喝了一口"* —— 空间图把杯子放桌上、人放门口，最后这个交互**缺了它的受事对象**。生成器只能二选一：复制一个杯子，或者让杯子瞬移。**两种都会变成artifact。** 这就是"文本不合理"如何直接变成"视觉一致性失败"的机制解释。

### 奖励模型的双轨设计

| | General Reward Model (GRM) | Decision Reward Model (DRM) |
|---|---|---|
| 目的 | 可解释、可定位的批评 | 快速多维打分 |
| 输出 | 结构化批评 + **缺陷证据管**（时间区间 + 逐帧框）+ 定序评分 | K 个细粒度问题的答案（选项字母 logits） |
| 训练 | 冷启 SFT（1:10 视觉-LLM 学习率比 + 20% Stage1 replay）→ GRPO（8 rollouts，可验证奖励） | 决策头热身 → 单点+成对统一 SFT → 对称性校准 |
| 关键 | 奖励由四项可检查项门控：定序评分校准 / 缺陷存在正确性 / **tag-set F1** / 时空 mIoU | **所有答案槽固定在 prefix 里**，一次 prefill 答 K 个问题 |

**"Charge a judge for what it misses"** —— 这是 GRM 的工程精髓：只惩罚"报错了"会奖励"少报"，所以**对未被匹配的 ground-truth 缺陷也罚**，让漏报和错报等价。

**"Decide in the prefix, not in the decode"** —— DRM 的精髓：把答案槽固定在 prompt 里，K 个问题一次 prefill；因为槽位在 prefix 而非自回归解码，**前面的答案不会泄进后面的字段**。这个机制同时降延迟和**消掉答案顺序带来的捷径**。

### 对称性校准（这一条可以直接搬）

因果/线性注意力和 M-RoPE 会引入**视频顺序的位置偏差**；而且同一维度的 worse / better 两个字段可能互相矛盾。朴素做法是交换顺序跑 2–4 遍再平均 —— 代价翻倍。

Kling 的做法：**把两种极性放进同一个 prefill**，训练时用
1. worse 字段与"选项交换后的 better 字段"之间的**非对称 KL**
2. 原包与顺序交换包之间的**跨序 Bradley–Terry 损失**

推理时加**置信门控**：只在低 margin 的 case 上跑交换版。结果：**多遍精度、接近单遍延迟**。

## 四、实验与结果

### Table 13：PE 各组件的累计贡献（本文最该记住的一张表）

文本指标是 1–5 分均值与"≥4 分占比"；视频指标是四个 benchmark 的总分。

| 设置 | Faithful 均/≥4 | Reason 均/≥4 | Vivid 均/≥4 | StoryEval | T2AV | AVE | MultiRef |
|---|---|---|---|---|---|---|---|
| SFT，随机源 caption | 4.02 / 75.42 | 3.95 / 69.17 | 3.72 / 62.33 | 65.42 | 70.15 | 56.2 | 4.6137 |
| + 优质视频源 | 4.00 / 74.92 | 3.92 / 68.08 | **4.03 / 72.58** | 66.87 | 70.60 | 56.7 | 4.6224 |
| + F/R/V 数据验证 | 4.27 / 80.83 | 4.18 / 74.33 | 4.11 / 75.08 | 71.93 | 73.07 | 57.9 | 4.6591 |
| **+ 文本级 RL** | **4.45 / 86.67** | 4.31 / 79.25 | 4.25 / 79.83 | 75.58 | 75.34 | 58.4 | 4.7012 |
| + DiT-in-the-loop RL | **4.38 / 83.50** | **4.42 / 83.67** | 4.23 / 81.42 | 76.46 | 75.91 | 59.3 | 4.7163 |
| Agentic：+ 剧情精修 | 4.41 / 84.58 | **4.67 / 91.92** | 4.26 / 82.25 | 77.53 | 76.03 | – | 4.7249 |
| Agentic：+ 检索 Top-5 | 4.36 / 82.17 | 4.65 / 91.42 | **4.44 / 87.33** | 77.72 | 75.68 | – | 4.7158 |

### 五个必须单独拎出来的数

1. **文本级 RL 是性价比最高的一步，而且不需要渲染。**
   Faithfulness 4.27 → **4.45**（≥4 占比 80.83 → **86.67**），Reasonableness 4.18 → 4.31，Vividness 4.11 → 4.25。全程**不渲染一帧**。
2. **接上生成器之后，保真掉了。**
   Faithfulness 4.45 → **4.38**（≥4 占比 86.67 → **83.50**），而 Reasonableness 反而升 4.31 → 4.42。
   **这就是"用生成器奖励换保真"的实测代价。** 论文自己的解释是：DiT-in-the-loop RL 抬高下限、压低上限（"raises the floor and lowers the ceiling"）—— PE 学会了回避复杂编排、大镜头运动、密集交互，因为这些正是 artifact 风险最高的描述。
3. **加"优质视频源"这一步，生动涨、保真和合理都掉。**
   Vividness 3.72 → 4.03（+0.31），但 Faithfulness 4.02 → 4.00、Reasonableness 3.95 → 3.92。**这里存在一个显式的三维取舍，不是"全都变好"。**
4. **剧情精修和检索各管一维，互相拆台。**
   剧情精修把 Reasonableness 推到 **4.67 / 91.92**（全场最高），但 Vividness 只到 4.26；检索把 Vividness 推到 **4.44 / 87.33**（全场最高），但 Faithfulness 掉到 4.36 / 82.17。**没有任何一个配置在三维上同时最好。**
5. **"排除项"有明确的改写规则。**
   Caption 只描述"看得见的东西"，所以 PE 把 "no people" 改写成 "an empty street with unobstructed pavement"；**没有正向等价物的排除项**，走负条件字段或采样期拒绝。**这一条对我们处理"不许出现 X"型 prompt 是直接可用的规则。**

### 评测协议设计（第八节）

论文专门讲"暴露打分捷径"的协议。三条对我们直接有用：

1. **纯文本代理可以提前筛掉候选**：text-only encoder screening 和 text-level PE verifier 能在昂贵的端到端训练前过滤。
2. **"可靠的文本编码器来自感知训练，而不是更强的语言能力"** —— 这条反直觉：不是换个更强的 LLM 当 encoder 就行。
3. **按任务给评测分类**（Table 19）：captioning / T2V / 参考条件 / 关键帧 / 编辑，各有各的核心目标、主要失效模式、代表工具。**一个聚合分说不了病灶在哪。**

## 五、局限性

1. **它是技术报告，不是受控实验。** 没有随机种子重复、没有置信区间，Table 13 是"累计加组件"的单条曲线，**无法分离组件间的交互**。
2. **"高质量/优质视频"的选择标准涉及美学与运动分**，但具体阈值与选择比例没公布，**不可复现**。
3. **视频模态，不是图像。** caption 的字段（镜头时间戳、音频、多镜头切分）图像里没有；直接照搬到 T2I 会引入不需要的复杂度。
4. **奖励模型是在自家数据上训的**，Table 17/18 的对手是 API 模型，**版本会漂移**。
5. **DiT-in-the-loop 的"上限下降"没有量化指标**，只有定性描述（"most impressive outputs become less impressive"）。论文自己把它列为开放问题。
6. **安全问题几乎没谈。** 全文的 "safety" 只出现在"评测协议要暴露捷径"的语境里，**没有任何 NSFW / 内容审核 / 风险改写的内容**。这是一份**能力向**的工业报告，不是安全向的。

## 六、复现指南

### 环境
- 冻结的 DiT + 冻结的 text encoder（Stage 3 需要）
- caption 池（用于反向构造与检索索引）
- 三个 judge：保真 checklist / 合理图检查 / 生动技法库
- GRPO 实现

### 最小复现路径（按对我们的价值排序）
1. **先做"保真 checklist"这一个 judge**（半天到两天，零训练）。把用户 prompt 拆成原子要求，逐条判满足/违反/未涉及，**违反权重高于遗漏，加一条矛盾内容算违反**。这一个改动就能让"改写后语义保真"从一个人工印象变成一个可归因的分。
2. **再做文本级 RL**（需要训练，但不需要渲染）。奖励 = 保真门控 × (合理 + 生动)。这是论文里性价比最高的一步（保真 +0.18，≥4 占比 +5.84）。
3. **最后才考虑 DiT-in-the-loop**，并且**必须同时监控保真**：论文显示这一步保真从 4.45 掉到 4.38。

### 关键超参
- Stage 1 数据：反向构造 + 按真实流量统计采样 + 拒绝"骨架泄漏" prompt
- Stage 2：GRPO，**保真项门控**其他项 + 一个分布项惩罚超出 caption 长度/词表区间的输出
- Stage 3：8 rollouts/视频（对应 GRM），视频级奖励 = 视觉质量 + 运动质量 + 文本对齐 checklist
- DRM：K 个槽位固定在 prefix，option-letter 随机化 + 字段置换 + 只对 placeholder 算 loss
