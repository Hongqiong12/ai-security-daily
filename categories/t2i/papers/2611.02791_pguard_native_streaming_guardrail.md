**论文主页**: https://arxiv.org/abs/2611.02791
**领域**: 多模态护栏 / 原生流式安全检测 / 分业务粒度阈值下发 / 两级级联部署
**作者**: PGuard Team

**发布日期**: 2026-11-02（v1，cs.CL）
**分类**: defense / industrial
**模态归属**: 多模态（图-文）安全基座 · 输出侧图审 · 阈值 operating point 管控

---

## 一、背景与问题

### 动机

流式生成成了主流服务形态，安全判定必须从"生成完再审"变成"边生成边审"。现有两条路都有硬伤：

| 路线 | 代表 | 硬伤 |
|---|---|---|
| 外部护栏 | Qwen3Guard、Llama Guard、WildGuard | 额外推理开销；**判定与 backbone 内部表征脱节**；生成完才能判，已经露出去了 |
| 原生护栏 | GradSafe、SIREN、NExT-Guard、HiddenDetect | 多数只做 prefill 或只做输出，不是真流式；变体设计未与 serving 框架对齐 |

PGuard 的定位是**把安全从"外部依赖"变成 backbone 的内置能力**：直接读中间层 residual stream 做 token 级检测，**不改推理路径、不改生成行为**。

### 四条论断

1. 安全信号可以从 backbone 自己的中间表征里读出来，不必外挂一个模型。
2. 层不是固定的——**动态层门控**学出来，不同 backbone 集中在不同层。
3. **流的形态很重要**：last-token（stateless）与 EMA-attention / GRU 在"稳定性"上差一个档，这一档直接决定能不能做早拦截。
4. 阈值必须**按类目分别标定**，且要能在部署时下发。

## 二、核心方法

### （1）三层结构

| 层 | 做什么 |
|---|---|
| 多层隐状态抽取 | 在选定的 3 层上抓 residual stream（Qwen3.5-9B → 20/24/28；122B-A10B → 32/36/40 或 36/40/44） |
| 动态层门控 | 学一组跨层的加权聚合，权重随训练演化，不同 backbone 落在不同层子集 |
| 表征建模 | 三种变体：**stateless（last-token）** / **EMA-attention（多尺度因果）** / **GRU** |

### （2）多任务训练 + 九个风险维度

训练数据按 **A–I 九个风险维度**组织：

A Crimes · B Hate · C Health · D Ethics · E Privacy · F Cyber · G Extremism · H Inappropriate · I Minors

**每个维度下再分子类目**，每个子类目有自己的阈值 τ_{c,y}。附录 B 的表 19 把这张表完整公开了——这是本文对我们最有价值的部分。

### （3）流式判定

- **逐 token 风险分 + verdict**
- **采样打分**：每 p=10 个 token 打一次（任意 token 到下一个打分点最多等 9 步）
- **两级部署（two-tier）**：原生变体对**全流量**做 token 级打分；**只有被标记的内容**才升级到外部推理护栏做细粒度裁决

### （4）算法-系统协同

四个优化：selective guard scoring（只算需要的）、parallel prefill execution、non-blocking guard execution、fused guard computation。落到 SGLang 0.5.11。

## 三、技术细节

### 三个可验证的量

| 量 | 数值 | 含义 |
|---|---|---|
| 端到端开销 | **0.82–2.26%**（Qwen3.5-122B-A10B + SGLang） | 原生比外挂便宜一个量级 |
| 捕获层数 | **3 层** | 不需要每层都抓 |
| 采样间隔 p | **10 token** | 延迟与覆盖的折中 |

### 阈值表：本文最该被逐行读的部分

附录 B 表 19 按 **(变体, backbone, 阶段 Q/R, 输入 T/VL)** 分块，每块给 9 个维度 × 各子类目的阈值百分比。**共 12 个配置块，每块 29 个阈值。**

同一模型 Qwen3.5-9B，EMA 变体：

| 配置 | 29 个阈值的范围 | ≤11% 的个数 | 恰为 10% 的个数 |
|---|---|---|---|
| **Q-T（文本 query）** | 10 – 74 | 4 | 2 |
| **Q-VL（图-文 query）** | 10 – 39 | **25** | **24** |

**图-文输入的 29 个阈值里，24 个恰好压在下限 10%，最高只有 39；同模型文本 query 的阈值中位在 40 以上、最高 74。**

这不是"图-文要更严"这么简单。阈值被压到下限，通常意味着两件事之一：

1. 该模态下模型的风险分整体偏低，必须把阈值降到地板才能达到目标召回 —— **分数分布被系统性压低**；
2. 该模态下分数**区分度差**，任何高于下限的阈值都会让召回掉到不可接受 —— **排序不好**。

无论哪一种，结论都是同一句：**图-文输入这一侧的 operating point 不能从文本侧平移过来，也不能用共享阈值。**

### 前缀稳定性：为什么必须用序列变体

在 S-Eval 上统计"被判违规的样本里，有多少含有至少 k 个连续 token 风险分 > 0.5"：

| 变体 | k=20 | k=50 |
|---|---|---|
| EMA 类 | **>95%** | **~93%** |
| stateless（last-token） | – | **60–69%** |

stateless 变体有 30–40% 的"命中"只是单点抖动，不是持续风险。**如果用 stateless 做早拦截，会大量误停。**

### 早拦截

| 累计比例 | 幅度 |
|---|---|
| 前 10% token 内首次标记 | **86.3%** |
| 前 20% token 内首次标记 | **92.3%** |

对照：只在生成完再判的检测器，拦截点恒为 1.0。也就是说**原生流式能把暴露窗口砍掉 80% 以上**。

## 四、实验与结果

### 主结果

| 项 | 结果 |
|---|---|
| 文本平均 F1（Qwen3.5-9B） | **0.836**，接近专用外部护栏 |
| benchmark 覆盖 | **30+**（文本安全、多模态安全、越狱、网络与 CBRN、多语言、真实流量） |
| 声称 | 原生护栏中的 SOTA |

### 过度拒答（XSTest / OR-Bench，query 侧）

| 模型 | Stage | XSTest | OR-Bench | Avg |
|---|---|---|---|---|
| Qwen3Guard-Gen-8B | Q+R | 12.88 | 7.71 | 10.29 |
| Qwen3Guard-Stream-8B | Q+R | 10.46 | 4.50 | 7.48 |
| WildGuard-7B | Q+R | 1.07 | 8.64 | 4.86 |
| PolyGuard-Qwen-7B | Q+R | 3.82 | 8.72 | 6.27 |
| SIREN (Llama-3.1-8B) | p+d | 25.75 | 19.07 | **22.41** |
| NExT-Guard (Qwen3-8B) | p+d | 18.51 | 16.24 | **17.38** |
| **PGuard-lasttok (Qwen3-8B)** | p+d | 14.55 | 16.15 | 15.35 |
| **PGuard-ema (Qwen3-8B)** | p+d | 10.06 | 2.18 | **6.12** |
| **PGuard-ema (Qwen3.5-9B)** | p+d | 14.49 | 12.77 | 13.63 |
| PGuard-ema (Qwen3.5-9B) **response 侧** | p+d | 1.38 | 7.02 | **4.20** |

**同一方法不同变体，query 侧误杀从 6.12% 到 16.09%——差 2.6 倍。** 这不是"模型好坏"，是**表征建模方式**（是否保留时序）决定的。

### 真实良性流量拦截率（最接近线上的一条）

| 流量 | query 侧 | response 侧 |
|---|---|---|
| 文本（Alpaca / WildChat） | **3.69 – 5.05%** | **2.32 – 2.80%** |
| 多模态（ShareGPT4V / LLaVA-Instr / MMStar） | **0.11 – 0.60%** | **0.07 – 0.18%** |

内部对比：Qwen3Guard 两个版本文本 query 侧 6.73% / 5.17%，WildChat 单集就 13.02% / 9.95%。**PGuard 在真实流量上的误拦更低，且在 WildChat（最"脏"的集合）上优势最大。**

### 五个必须单独拎出来的数

1. **0.82–2.26%**：百亿级 backbone 上加原生护栏的端到端开销。这是"在线可部署"与"只能离线跑"的分界。
2. **6.12% vs 16.09%**：同方法最优/最差变体的 query 侧过度拒答，差 2.6 倍。**变体选择比模型选择更影响误杀。**
3. **24/29**：图-文输入下压在下限的阈值个数。**这是"图审阈值不可从文本侧迁移"的硬证据。**
4. **86.3%**：有害响应在前 10% token 内被拦下的比例。
5. **0.11–0.60%**：多模态真实流量的 query 拦截率。比文本流量低一个量级——不是更安全，是**检测更无力**（见上条：阈值压地板）。

### 一个必须指出的内部张力

论文同时报告了两个方向相反的事实：

- 图-文 query 的阈值**几乎全压下限**（说明极敏感）
- 多模态真实流量的拦截率**只有 0.11–0.60%**（说明极不敏感）

两者并不矛盾，但合起来说明：**图-文侧的风险分分布是"低分密、高分少"——大多数样本挤在低位，模型给出高分时几乎确定有问题，但区分度差。** 所以阈值只能压地板，而压了地板也没拦多少。**这是校准问题 + 排序问题叠加，不是阈值问题。**

## 五、局限性

1. **非生成模态**：PGuard 是 MLLM 的护栏，**不直接覆盖扩散模型的生图输出**。图审侧迁移的是"读中间表征 + 按类目下发阈值"这套工程范式，不是直接把模型搬过去（扩散模型没有 token 流）。
2. **阈值表不可跨模型搬迁**：12 个配置块的阈值差异极大（如 Q-T 的 A 维度在第一格是 65/36/54/42/53，在 gru Qwen3.5-122B 那格是 71/82/77/78/28）。阈值明显吸收了各变体自身的分数分布偏移——**换模型、换变体、换 backbone 都必须重标**。
3. **9 个维度不等于我们的类目树**：A–I 是通用风险维度，没有 PORN/VULG 这种中国业务常见的边界混淆对，也没有政治/敏感地区的 L2_30 层级口径。
4. **未报"漏过率"的类目分解**：只报平均 F1，没有逐类目的 precision/recall 分解。
5. **F1 0.836 是平均值**：平均 F1 会掩盖最差类目。我们线上 77.64% 一级一致率的痛点在长尾，平均值参考价值有限。
6. **单模态限制**：图像输入只按"图-文 query"处理，没有纯图（image-only）路径。

## 六、复现指南

### 最小复现路径（按对我们的价值排序）

1. **把阈值表按"配置块 × 类目"落成一张可下发的表**（半天，零训练）。现在如果我们只有"全局一个阈值"或"一级类目一个阈值"，先做一件事：把每个叶子类目的分数分布打出来（分位数 5/25/50/75/95），看**当前共享阈值在各叶子类目上分别落在什么分位**。这一步会把"误杀 5.2% / 漏过 3.42%"直接摊到类目上，看出到底是哪几个格子贡献的。
2. **按类目做 operating point 校准**（1 天，零训练）。对每个叶子类目，在验证集上扫阈值，画 PR 曲线，按"误杀 ≤ 目标 / 漏过 ≤ 目标"求可行域。若某类目**没有可行点**（PR 曲线整体在约束外），说明该类目不是阈值问题，是排序问题——直接进标签审计。
3. **两级级联上线**（工程 1–2 周）。原生轻量打分流，只有被判高风险或低置信的才升级到重模型。这正好对上"按一级/二级/叶子类目勾选 + 阈值下发"的接入台设计：**每一级都有自己的 operating point**。
4. **把"变体差 2.6 倍"这条记进方法论**：任何"误杀降了多少"的汇报，必须同时报"用的哪个变体/哪个配置"。否则数字无法跨轮比较。

### 关键超参

| 参数 | 取值 |
|---|---|
| 捕获层 | 3 层（相对深度约 0.6–0.75 处） |
| 采样间隔 p | 10 token |
| 两级阈值 | 原生层按类目下发；升级层单独一套 |

## 附：与业务的三条硬对应

1. **"部署时按类目下发阈值 + 处置动作"这句话，就是接入台的产品定义**。PGuard 证明这东西可以做到 0.82–2.26% 开销，也就是说我们的按叶子类目勾选+阈值下发不是过度设计，是工业标准做法。
2. **图-文阈值 24/29 压地板，是对"图审为什么误杀高"最直接的解释之一**：不是模型不准，是**该模态下的分数分布根本没有可用的中间 operating point**。这条与 GOAL 那篇的"深层表示重叠"可以接起来看——两个机制指向同一个后果。
3. **两级级联 + 按类目阈值，正好是"误杀 5.2% / 漏过 3.42% 联合优化"的工程载体**：单阈值不可能同时压两个指标，但"一线宽 + 二线严"的两级可以——一线放宽（降误杀），二线只对一线标出的做严判（保漏过）。
