## 一、背景与问题

### 动机

布局引导文生图（layout-guided T2I）已经不只是视觉控制问题，而是在真实工业场景里直接关系到“语义是否按要求表达、空间关系是否按要求落位”。但现有评测通常要么只看文本对齐，要么只看局部位置精度，导致模型看起来“像是对了”，却无法回答：它到底是理解错 prompt、摆错位置，还是两者都错。

### 核心科学问题

能否构建一个统一 benchmark，同步评估 layout-guided T2I 的**语义对齐**与**空间对齐**，并在 closed / open 两种设定下给出同一套可解释、可排序、可复用的评测协议？

### 直觉洞见

这篇论文最重要的不是再发一个“更大 benchmark”，而是把 layout 任务里的两种错误拆开：
- 图像内容生成对了，但对象没摆到该在的位置；
- 位置差不多，但对象属性、颜色、关系理解错了。

对你的 prompt rewrite 业务，这很像把“安全性”和“语义保持”拆开分别测：如果只看一个总分，你很容易把“改安全了但语义漂了”和“语义对了但风险还在”混成同一类样本。

## 二、核心方法

**（1）C-Bench：闭集布局评测（Closed-set Benchmark）**

作者先用自动化 pipeline 合成一个高可控 benchmark：
- **Prompt Generation Engine (PGE)** 自动生成文本指令；
- **Layout Generation Engine (LGE)** 自动生成对应 bounding boxes。

这样可以明确控制评测样本到底在考什么，而不是让真实数据的噪声掩盖模型能力差异。

**（2）O-Bench：开集真实评测（Open-set Benchmark）**

仅靠合成测试还不够，所以作者再用真实视觉指代数据构建 O-Bench，强调开放场景泛化。其核心价值是：让 benchmark 不只在“干净实验室”成立，而能观察模型碰到真实 caption 与真实布局时是否仍稳定。

**（3）双通道评测：文本对齐 + 布局对齐**

作者分别定义：
- **Text-Alignment Score**：图像是否满足 prompt 语义；
- **Layout-Alignment Score**：生成对象是否落在正确位置。

最后再用统一分数整合两者，既保留可解释性，又保留排序能力。

**（4）Unified Score：把 semantic 与 spatial 真正绑在一起**

作者使用调和平均把文本对齐与布局对齐组合成一个统一指标。这个设计的好处是：只要其中一维很差，总分就会被显著拉低，避免模型在某一维特别强时掩盖另一维的致命短板。

## 三、技术细节

### Closed-set 任务构造

C-Bench 共覆盖 **7 类**布局控制挑战：
1. object binding
2. color binding
3. attribute binding
4. object relationship
5. small bboxes
6. overlapped bboxes
7. complex compositions

这些任务本质上对应两类错误源：
- **semantic binding error**：对象/颜色/属性理解错；
- **spatial grounding error**：框位、相对位置、小目标/重叠目标摆错。

### Benchmark 规模

- **C-Bench**：**3,328** 条指令；
- **O-Bench**：基于 Flickr30k Entities test set，下采样得到 **3,319** 条 prompts；
- 每条样本生成 **8** 张图；
- 共评测约 **319,086** 张图像；
- 对比 **6** 个布局引导模型。

### Text-Alignment Score

作者使用 **TIFA**：
- 由 LLM 从 prompt 生成问答；
- 再由 VQA 模型回答这些问题；
- 比较答案一致性，得到文本语义对齐得分。

这一步可理解为：把 prompt 拆成一串可验证问题，避免只看 CLIP 相似度这种过粗指标。

### Layout-Alignment Score

作者使用 **OWLv2** 做零样本目标检测：
- 检测图中对象；
- 将预测框与目标 layout 框计算 **IoU**；
- 在多个阈值 k ∈ {0, 0.1, ..., 1} 上计算 **Acc@k**；
- 对整条 Acc@k 曲线求 **AUC**。

这使得布局评测不再依赖单一阈值，而是观察模型在不同容忍带下的整体表现。

### Unified Score

统一分数采用文本对齐与布局对齐的调和平均：

S_unified = 2 · S_text · S_layout / (S_text + S_layout)

它和 F1 类似：只有 semantic 与 spatial 两维都过关，总分才会高。

### 对你当前业务的迁移意义

如果把这套结构迁到 prompt rewrite，几乎可以直接得到一个三维评测骨架：

S_total = HarmonicMean(S_safe, S_semantic, S_follow)

其中：
- `S_safe`：风险下降程度；
- `S_semantic`：主体/场景/属性是否保真；
- `S_follow`：改写后模型是否仍按用户意图生成。

CoBench 的真正价值不在 layout 本身，而在它证明了：**复杂生成任务可以也应该被拆成多维、结构化、统一汇总的指标体系。**

## 四、实验设置与结果

### 数据集与评价指标

- **C-Bench**：闭集、自动生成、可控布局任务；
- **O-Bench**：开集、真实描述、真实框位；
- **文本指标**：TIFA-based Text-Alignment（↑）；
- **布局指标**：OWLv2-based Layout-Alignment AUC（↑）；
- **统一指标**：Unified Score（↑）。

### 被评测模型

1. MIGC
2. BoxDiff
3. GLIGEN
4. Attention Refocusing
5. Cross-Attention Guidance
6. Stable Diffusion（无布局控制基线）

### C-Bench 主结果

| 方法 | Unified Score (↑) | 排名 | 说明 |
|------|------------------:|------|------|
| **MIGC** | **0.7082** | 1 | 语义与布局都最稳 |
| BoxDiff | 0.6537 | 2 | 训练自由方法中较强 |
| GLIGEN | 0.6143 | 3 | 带布局训练的强基线 |
| Attention Refocusing | 0.6070 | 4 | 文本尚可，布局略弱 |
| Cross-Attention Guidance | 0.3747 | 5 | 布局拖后腿明显 |
| Stable Diffusion | 0.2522 | 6 | 无布局能力基线 |

### O-Bench 主结果

| 方法 | Unified Score (↑) | 排名 | 说明 |
|------|------------------:|------|------|
| **MIGC** | **0.7548** | 1 | 开放场景仍稳 |
| GLIGEN | 0.7517 | 2 | 与 MIGC 非常接近 |
| BoxDiff | 0.7410 | 3 | 泛化表现不错 |
| Attention Refocusing | 0.7305 | 4 | 整体可用 |
| Cross-Attention Guidance | 0.5370 | 5 | 开集下仍明显落后 |
| Stable Diffusion | 0.4505 | 6 | 仅文本语义基础能力 |

### 人工验证

作者额外验证自动评测协议的可靠性：
- **TIFA vs 人工语义判断**：在 **640** 张图上总体一致性较好；
- **OWLv2 vs 人工框位判断**：在 **448** 张图上也较接近。

这一步很关键，因为很多 benchmark 的问题不是指标定义，而是自动评测器本身不可信。CoBench 至少正面处理了这个问题。

### 消融与诊断结论

| 观察点 | 结论 |
|--------|------|
| complex compositions | 最难，几乎所有模型都明显掉分 |
| 目标数量增多 | 性能系统性下降 |
| 文本 vs 布局 | 当前瓶颈主要在布局对齐而不是文本理解 |
| 训练式 vs 推理式方法 | 带布局训练的方法通常更稳，但训练自由方法在部分设定仍有竞争力 |

### 关键发现

- 当前 layout-guided T2I 的真正短板不是“画不出来”，而是“摆不准”；
- 单看文本相似度会严重高估模型能力；
- 统一指标要建立在多维可解释指标已经拆开的基础上，否则总分没有意义。

## 五、局限性分析

1. **仍聚焦 layout-guided generation**：它补齐的是 semantic-spatial fidelity，而不是直接测 NSFW 风险与安全性。  
2. **自动评测依赖 TIFA 与 OWLv2**：虽然做了人工校验，但 detector / VQA 误差仍会传导到总分。  
3. **覆盖的仍是 bounding-box 级控制**：更复杂的 style、tone、隐式语义安全触发未纳入。  
4. **模型族谱有限**：目前主要评测传统 layout-guided diffusion methods，对更强闭源工业模型的横向比较还不充分。  
5. **无法直接替代人工安全评估**：它更适合作为结构化 fidelity benchmark，而不是最终安全上线门槛。

## 六、复现指南

### 环境依赖

```bash
pip install torch diffusers transformers pillow scipy openmim
pip install tifa owlvit datasets accelerate
```

### 核心代码框架

```python
class UnifiedSemanticSpatialEval:
    def text_score(self, prompt, image):
        qa_pairs = build_tifa_questions(prompt)
        answers = run_vqa(image, qa_pairs)
        return grade_answers(qa_pairs, answers)

    def layout_score(self, objects, target_boxes, image):
        pred_boxes = owl_detect(image, objects)
        return auc_over_thresholds(pred_boxes, target_boxes)

    def unified(self, text_s, layout_s):
        return 2 * text_s * layout_s / (text_s + layout_s + 1e-8)
```

### 复现步骤

1. 从作者仓库下载 **C-Bench / O-Bench** 及官方评测脚本。  
2. 选择若干 layout-guided diffusion baselines，保持统一分辨率与随机种子设置。  
3. 每个 prompt 生成多张样本，复现实验中的多 seed protocol。  
4. 分别计算 text-alignment、layout-alignment，再算 unified score。  
5. 若迁到 prompt rewrite 任务，把 objects / boxes 替换为 risk anchor / semantic anchor，对应重写为三维分数框架。  
6. 用少量人工校验样本检查自动 judge 是否稳定，否则总分不可直接用于上线。

### 对当前业务最值得复现的部分

最值得借的不是布局任务本身，而是 **“先拆维度，再做统一总分”** 的评测哲学。对 prompt rewrite，可以先做：
- 风险下降分；
- 语义保持分；
- 指令遵循分；
- 最后再做 harmonic aggregation。

这比直接让单一 LLM-as-Judge 给一个 overall score 要靠谱得多。
