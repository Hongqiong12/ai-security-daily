## 一、背景与问题

### 动机

T2I 越狱评测早就不是“给几条 prompt 跑一下 ASR”这么简单。真正影响结果的是整条 pipeline：prompt transformation、图像生成配置、安全过滤器版本、多模态 judge、阈值、seed、采样器，任何一个环节不一致，都会让论文之间的结果失去可比性。

### 核心科学问题

能否把“复现一篇 T2I jailbreak 论文”从人工拼脚本、拼环境，变成一种**标准化、可审计、可持续进化**的 paper-to-pipeline 过程，让新老攻击方法都能在统一协议下复现、比较和持续维护？

### 对当前业务的重要性

这篇论文对你现在做的输入侧 safety rewrite 极其关键，因为它提醒了一件很容易被忽略的事：**rewrite 的评测对象不是单个改写文本，而是整条控制链**。如果不把上游改写器、生成器、安全过滤器、judge 放到一条统一 pipeline 里，所有“风险下降”结论都可能是伪稳健。

## 二、核心方法

### （1）PixJail-Attack：论文到攻击模块

作者先把“某篇越狱论文”转成一个统一契约下的攻击模块。

三类角色协同完成：
- **Planner**：读论文、读参考代码、读历史记忆，生成结构化攻击规范；
- **Implementer**：根据规范合成可运行攻击模块；
- **Auditor**：检查模块与论文设定、统一契约、输出工件是否一致，不一致就回滚修正。

### （2）PixJail-Eval：论文到评测管线

在得到攻击模块后，系统再自动搭建对应评测 pipeline：
- 提取数据集、受害模型、采样配置、judge、过滤器、指标；
- 将攻击模块与标准运行时组件拼接成可执行 pipeline；
- 通过一致性检查器验证“这条 pipeline 是否真的对应论文设定”。

### （3）统一契约 C = (X, Θ, Y, A)

作者把 T2I 越狱评测形式化为四元组：
- **X**：输入模式（原始任务、恶意意图、seed、元数据）；
- **Θ**：超参数空间（攻击预算、采样器、judge 配置、过滤策略）；
- **Y**：输出模式（变换后的 prompt、生成图像、judge 判定）；
- **A**：可审计工件（中间 prompt、日志、配置、图片、最终报告）。

这一步的价值非常大：它把“论文方法”从 narrative description 变成了**可对齐、可比较、可回放**的工程对象。

### （4）Memory Bank：自进化复现记忆库

PixJail 不是一次性复现器，而是持续积累：
- 论文摘要
- 攻击家族演进图
- 可复用模板
- 失败案例
- 历史工件版本

后续复现新方法时，可以直接复用过去经验，而不是每次从零开始。

## 三、技术细节

### 统一评测为什么是“pipeline 级”问题

作者明确指出，T2I 越狱结果高度依赖以下系统变量：
- prompt 预处理与 transformation
- 负提示与采样器配置
- 安全检查器版本
- MLLM judge 的阈值与模板
- 随机种子与图像数量

这意味着：

```text
同一攻击思路
  ≠ 同一攻击效果
除非 pipeline 所有环节都被显式固定
```

### 覆盖的攻击方法

PixJail 共复现 **11** 个代表性 T2I jailbreak 方法：
- **有代码方法 7 个**：SneakyPrompt、MMA-Diffusion、DACA、Ring-A-Bell、JPA、JailFuzzer、DiffZOO
- **无代码方法 4 个**：HTS、PGJ、R2A、Low-Effort

时间跨度覆盖 2023-05 到 2026-04，基本囊括当前公开 T2I 越狱主脉络。

### 复现误差与效率

- **平均误差**：2.1%
- **中位数误差**：0%
- **有代码方法平均误差**：1.2%
- **平均审计迭代**：2.56 次
- **平均复现时间**：778 秒（约 13 分钟）
- **总计算预算**：48 GPU 小时

这说明它不是“看起来能跑”，而是真的把复现误差压到了可接受范围。

### 标准化评测矩阵

作者进一步在统一协议下比较多种攻击在不同目标模型上的效果：
- SD v1.4 平均 ASR：65.4%
- SD v1.5 平均 ASR：66.6%
- SDXL 平均 ASR：74.7%
- GPT-image-2：多数方法 < 4%

最重要的不是某一个 ASR，而是它把“论文自报成绩”变成了**跨方法、跨模型、跨评测器的统一矩阵**。

## 四、实验设置与结果

### 主结果 1：论文匹配复现足够稳定

- SneakyPrompt、JailFuzzer 达到 **0% 误差**；
- DiffZOO 误差 **0.6%**；
- Low-Effort 误差 **0.3%**；
- Ring-A-Bell 误差 **3.2%**；
- MMA-Diffusion 误差 **4.2%**；
- 无代码方法里 R2A 偏差较大，达到 **16.1%**，说明“只看论文描述复现”仍有上限。

### 主结果 2：Memory Bank 明显提升复现质量

在 JailFuzzer 消融里：
- 无 Memory 最终得分：**8.16**
- 有 Memory 最终得分：**9.10**
- **相对提升 11.5%**

细分提升：
- 功能保真：+8.0%
- 技术正确性：+12.5%
- 可复现性：+15.8%

### 主结果 3：统一协议揭示了模型间真实差异

在标准化评测里：
- 开源扩散模型，尤其 **SDXL**，整体更容易被攻破；
- 闭源 **GPT-image-2** 防线显著更强；
- 这说明“论文在单模型上的高 ASR”不能直接外推到生产系统。

### 对你当前业务的直接启发

如果把 PixJail 的抽象迁移到 prompt rewrite 评测，最值得借的是这条结构：

```text
原始 prompt
  → rewrite / sanitization
  → image model
  → safety filter
  → multimodal judge
  → unified metrics + auditable artifacts
```

也就是说，你真正需要的不只是 rewrite judge，而是 **rewrite-to-image pipeline benchmark**。

## 五、局限性分析

1. **它评的是越狱复现，不是 rewrite 防御本身**：对你的业务属于评测基建启发，而不是现成防御算法。  
2. **复现质量仍受论文完整性影响**：无代码、弱描述方法偏差明显更大。  
3. **统一评测依赖 judge 与过滤器的标准化**：如果 judge 本身偏差大，统一协议也会带偏。  
4. **当前重点仍在越狱家族**：对输入侧 safe rewrite 的专门 benchmark 还没真正建立起来。  
5. **工业闭源系统可观测性不足**：面对真实服务时，仍可能拿不到完整过滤链与内部配置。

## 六、复现指南

### 环境依赖

```bash
pip install torch transformers diffusers accelerate pillow pydantic
```

### 最小复现思路

1. 为每篇攻击论文提取：输入、搜索预算、目标模型、judge、过滤器。  
2. 统一定义攻击接口：`attack(prompt, cfg) -> transformed_prompt`。  
3. 统一定义评测接口：`eval(method, model, judge, filter) -> metrics + artifacts`。  
4. 将中间产物全部落盘，保证任何一轮实验都可回放。  
5. 若迁到 rewrite 业务，把攻击模块替换为 rewrite 模块，并保留统一 contract。

### 对当前业务的最小迁移版本

最值得先做的不是重造一个 Agent，而是先学 PixJail 的**工件治理**：
- 保存原始 prompt / rewrite 后 prompt / 图像 / judge 输出 / 失败原因；
- 把每次 rewrite 实验都变成可追溯工件；
- 这样后续才能比较不同 rewrite 策略，而不是只比一个总分。
