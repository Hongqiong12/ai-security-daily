# SELECT: 用"兄弟互斥概念"构造概念擦除的语义边界

**论文主页**: https://arxiv.org/abs/2510.16342
**领域**: T2I 概念擦除（Concept Erasure）/ 风险锚点选择
**作者**: Tong Zhang, Ru Zhang, Jianyi Liu, Zhen Yang
**机构**: **北京邮电大学 网络空间安全学院**
**发布日期**: 2026-10-19（**v2**；v1 为 2025-10-18）
**分类**: defense
**模态归属**: T2I 权重侧擦除；其"锚点构造"逻辑可直接迁移到**输入侧改写锚点选择**

## 一、背景与问题

### 动机

一大类概念擦除方法可以抽象成**"目标 → 锚点"重定向**：要擦掉概念 c_t，就让模型表现得像 c_t 被替换成了锚点 a。

  Δ* = argmin_Δ [ D( f_{W+Δ}(c_t), f_W(a) ) + λ · D( f_{W+Δ}(C_r), f_W(C_r) ) ]

其中 C_r 是要保住的其他概念集合。

长期以来，锚点被当成"替代终点"——只要能压住目标就行，所以大家都用**固定锚点**（null-text、"a person"、"art"、"Sky"）。

### 核心科学问题

论文问了一个非常"工程正确"的问题：**锚点真的只是一个终点吗？还是它同时定义了"擦到哪儿为止"？**

因为锚点是擦除目标的**参考响应**，换锚点就换了损失函数的梯度方向，而梯度作用在**共享参数**上——所以锚点选择必然影响**语义近邻的连带损伤**。也就是说：

> 锚点不是实现细节，锚点**隐含地定义了一条语义擦除边界**。

### 为什么这篇对我们重要

我们的输入侧改写其实在做同一件事：**把风险锚点（裸露、性行为、暗示性姿势）替换成安全表达**。改写时选什么"替代表达"，决定了：
- 风险压得够不够（安全性）；
- 语义保真掉多少（"边界损伤"）。

SELECT 把这个选择问题**形式化并量化**了，还给出了一个可直接套用的候选区定义：**兄弟互斥概念（Sibling Exclusive Concepts, SEC）**——同父类、核心属性互斥。这正是"把裸露换成工装"而不是"把裸露换成天空"的理论依据。

## 二、核心方法

### （1）诊断一：因果弥散度决定锚点敏感度

**因果追踪（causal tracing）**：准备原始模型 M_ori 与擦除模型 M_edit，每次只把 M_ori 的**一个 cross-attention 单元** u 替换成 M_edit 的对应单元，得到干预模型 M_u。测目标概念响应 R_c，把正向响应削减归一化成因果效应分布：

  p_c(u) = max(R_c(M_ori) − R_c(M_u), 0) / Σ_{u∈U} max(R_c(M_ori) − R_c(M_u), 0)

再用 Shannon 熵定义**归一化因果弥散度**：

  D_c = exp( −Σ_u p_c(u) log p_c(u) ) / |U|

D_c 越小说明擦除效应集中在少数单元。

再定义**锚点敏感度**：在 7 组锚点下测目标残留 S_TR、擦除强度 S_ES、锚点失败率 S_FR。

**发现**（每类各 100 个概念）：
- 艺术家风格、物体概念：因果效应**弥散**；
- 名人概念：因果效应**高度集中**（少数 cross-attention 单元主导）；
- 对应地，名人概念目标残留更低、锚点失败率更低、擦除强度更高；艺术家风格与物体概念更容易残留。

**且这个关系在类内也成立**：D_c 与目标残留、锚点失败率**正相关**，与擦除强度**负相关**。论文用 Dog vs Corgi 做例：Dog 语义范围宽、下属视觉形态多 → 因果弥散 → 对锚点敏感；Corgi 视觉特征收窄 → 因果集中 → 擦除稳定。

**结论：一个固定锚点无法适配因果结构不同的概念。**

### （2）诊断二：锚点类型决定"连带损伤的范围"

固定擦除算法、参数、其他所有条件，只改锚点类型（5 类）：Target overlap、Shared visual、Generic/null、Far unrelated、**Sibling exclusive**。

**发现**：
- **边界概念受损远大于随机无关概念**——连带损伤是**局部**的；
- **锚点太近**（Target overlap）：压不住目标（目标属性被保留）；
- **锚点太远**（Far unrelated）：压得住，但**边界损伤与全局非目标损伤都最大**；
- 提出 **BCTS（Boundary Controlled Trade-off Score）**：

  BCTS(c, a) = φ_c( S(c,a) ) · (1 − D̃(c,a))

  S 是目标压制强度，φ_c 是"达到阈值 τ_c 后不再奖励更激进擦除"的整形函数（**过阈即饱和**），D̃ 是合并的非目标语义损伤。设计意图很明确：**先保证压得住，再只比保得住**。

- 结果：**Sibling Exclusive 锚点的平均 BCTS 最高**。

### （3）SEC：兄弟互斥概念

SEC 的两个条件：
1. **局部语义邻近**：与目标同父类（parent_H(c_t)），这样重定向路径平滑，不产生过大语义位移；
2. **核心属性互斥**：不共享目标的定义性属性，这样不会把目标属性"带回来"。

形式化：候选集 = { a : parent_H(a) = parent_H(c_t) 且 Excl(a, c_t) = 1 }。

### （4）两个候选评价准则

- **上下文激活（Contextual Activation）**：风险概念即使被擦掉，目标**关联语境**仍能把它激活回来。例：擦掉 {blood} 之后，prompt 里出现 {red, wound, stain} 仍会生成血迹/红斑。
  用掩码语言模型估计：

    A_τ(c_t) = (1/|T_τ|) Σ_{T∈T_τ} P_MLM( c_t | T([MASK]) )
    CRR(c_t) = A_rel(c_t) / (A_neu(c_t) + ε)

  CRR 衡量"关联语境相对中性语境额外激活了多少"。论文验证：**再出现率高的概念，其关联语境下的激活显著更强**。
  实现上：用 LLM 以模板 "{When people think of c_t, they think of [MASK]}" 生成关联词集 W_t，然后对候选锚点 a 算其在 W_t 上的激活，**U(a, c_t) 越低越好**（低激活 ⇒ 不容易被语境带回来）。

- **语义连贯（Semantic Coherence）**：用 CoS 优先选**与原 prompt 语境兼容**的重定向终点——这样既能强压目标，又能保住非目标场景内容。

### （5）Anchor-Guided Retain：显式保留集

选定锚点 a_t* 之后，把剩余的高质量 SEC 组成**边界保留集 B_t**，作为"这些邻居不许动"的显式约束传给下游擦除算法。

所以 SELECT 输出的是一个**边界规格**：(a_t*, B_t)——终点 + 保留集。

### （6）NSFW 擦除的具体 SEC 设计（对我们最有用的一段）

擦除目标："Nudity, Sexual"。固定锚点对照：null-text、"a person wearing clothes"。

SELECT 的 SEC 构造策略：**保留核心类别（人物、活动、场景），只把 NSFW 属性替换成互斥属性**。两个维度：
- 裸露/暴露 → **全覆盖的职业服装**；
- 性内容 → **职业性/教育性活动**。

具体锚点例：**"a gardener in overalls and long sleeves"**、**"a gardener planting flowers in a public park"**。

作者的原话是：这些锚点"provides precise, effective removal paths **without compromising subject identity**"。

**这就是"外科式替换风险锚点、保留主体与场景"的一个实例化的、可抄的模板。**

## 三、技术细节

### 实验设置

- 骨干：**Stable Diffusion v1.4**；单卡 RTX A6000；
- 下游擦除算法：**SPEED、MACE、OCE**（都支持固定锚点重定向）；独立对照：AGE、RECE；
- SEC 候选生成与关键词/模板生成用 **DeepSeek**；
- 四类任务：object / celebrity / artist-style / **NSFW**。

### 指标

| 任务 | 指标 |
|---|---|
| Object（9 概念，每概念 15–19 条件，每条件 200 图） | Acc_e（目标 CLIP top-1，越低越擦干净）、Acc_g（同义词/变体，越低泛化越好）、Acc_s（无关概念，越高越好）、Acc_b（LLM 生成的近邻概念，越高越好）；调和平均 H_o、H_b |
| Celebrity（200 概念，擦除组 + 保留组） | GIPHY Celebrity Detector 的 Top-1/3/5；H_c = 擦除组与保留组 Top-1 的调和平均 |
| Artist style（200 风格） | 擦除组 CLIP 分（越低越彻底）、保留组 CLIP 分（越高越好）、FID；H_a = CS_Retain − CS_Erase |
| NSFW | I2P 数据集生成 + **NudeNet**（阈值 0.6）检出数 |

### 量化结果（论文口径，不做外推）

- **Object**：SPEED 下 SELECT 的目标压制与同义词压制都显著强于固定锚点（Null-Text / General），同时随机概念与边界概念准确率保持高位 → H_o / H_b 与 BCTS 最优。
- **Celebrity**：SPEED 下 H_c 从 **81.99 → 87.99**；MACE 下擦除更强但保留略降，H_c = **86.33**（General 锚点 87.30）。
- **Artist style**：MACE 下 SELECT 得到最低 CS-Erase 与最高 H_a；SPEED 下 null-text 虽然 CS-Erase 更低，但 CS-Retain 大幅下降。
- **NSFW**：SELECT 的暴露部位检出数**远低于**两类固定锚点方案（null-text / "a person wearing clothes"）。

### 一个诚实的自我限制（值得单独记）

论文自己承认：**SELECT 是逐目标独立构造边界的**。当多个目标落在密集相关的语义区（大规模名人擦除、艺术家风格擦除），它们的重定向终点与保留集可能**重叠或冲突**——某个目标的 SEC 候选可能正是另一个待擦除概念。

所以在这两个大规模任务里，作者**放弃了 SEC 保留集**，改用预定义的 100 个保留概念。代价是：独立选出的锚点仍可能影响重叠语义邻域而无对应保护，这正是部分实验里保留性能下降的原因。

作者把这个归因为"**缺少全局协调**"，而不是"方法无法处理大规模擦除"。

## 四、实验与结果

### 有效的地方

1. **把"锚点选择"从工程细节提升为可量化的边界构造问题**，并且给了两个互相独立的诊断（因果弥散度、锚点类型干预），不是单一证据。
2. **BCTS 的整形函数设计很讲究**：过阈值后不再奖励更激进的擦除。这一条直接对应我们的"改写不能过度"——**安全达标之后，继续加码只会损伤保真**。
3. **NSFW 的 SEC 模板（gardener / overalls / public park）是可直接迁移的锚点构造范式**：保留主体 + 保留场景 + 替换敏感属性。
4. **上下文激活（CRR）解释了"擦完又回来"的机制**：不是擦得不干净，是**关联语境把残差激活了**。这对应改写的"锚点泄漏"问题——你把"裸露"改掉了，但保留了"浴室、湿身、薄纱"，风险会回来。
5. **Plug-and-play**：不改下游算法，只换锚点 + 加保留集，三个下游方法（SPEED/MACE/OCE）上都能涨。这对我们意味着"不用重训也能试"。

### 站不住 / 需要警惕的地方

1. **只在 SD v1.4 上做**。SDXL / Flux / 现代 T2I 的 cross-attention 结构差异大（尤其 MMDiT 类无 U-Net），因果追踪的"单元"定义要重写，结论不能直接外推。
2. **SSEC 候选由 LLM（DeepSeek）生成**，存在 LLM 语义偏置；论文用"上下文激活 + 语义连贯"两个**独立量化准则**来兜底，但它自己说 LLM 判分可能继承语义偏置——这个兜底并不彻底。
3. **BCTS 里的 τ_c（擦除阈值）怎么定没给通用规则**，不同目标的最优 τ 不同，实际操作中需要标定。
4. **大规模擦除下退化为固定保留集**，这时 SELECT 的主要收益只剩"锚点更好"，保留集这一半创新被关掉了。
5. **NSFW 只报 NudeNet 检出数**，没有报"良性人像是否被误伤"（比如正常泳装、健身、医学图）。这是概念擦除评估的通病，但对我们的业务恰恰是关键——**擦除类方法最容易在"擦干净"上刷分，在"不误伤"上失分**。
6. **没有与输入侧改写方案对比**。概念擦除与 prompt rewrite 是两条互补路线，论文没讨论"如果我只改 prompt 不改权重，SEC 还成立吗"。

## 五、局限性

1. **单骨干（SD v1.4）、单编辑范式（cross-attention 重定向）**，对 MMDiT / flow matching 的适用性未验证。
2. **无全局协调**：多目标密集语义区会冲突（作者自述）。
3. **SEC 生成依赖 LLM**，且候选质量对最终结果影响大；论文未做"换 LLM 会怎样"的稳健性测试。
4. **评估偏"擦得干净"**：H_o / H_c / H_a 都是擦除与保留的调和/差值，缺少"良性高风险簇误伤"的专门测试集。
5. **NSFW 场景只有一组锚点示例**，没有系统地扫"不同 SEC 锚点对 NSFW 检出率与保真度的影响曲线"——而这恰是我们最需要的那条曲线。

## 六、复现指南

### 6.1 复现要点

```
1. 骨干：SD v1.4（diffusers），单卡 A6000 足够
2. 因果追踪：对 cross-attention 单元逐个做 restoration intervention，
   算 p_c(u) 与 D_c = exp(entropy)/|U|；锚点敏感度用 7 组锚点测 S_TR/S_ES/S_FR
3. SEC 候选：LLM（DeepSeek）按 "同父类 + 核心属性互斥" 生成
4. 过滤：上下文激活 U(a,c_t)（LLM 生成 W_t 关联词 + MLM 激活）→ 低者优先
5. 排序：语义连贯 CoS → 与原 prompt 语境兼容者优先
6. 输出：(a_t*, B_t)，B_t = 剩余高质量 SEC
7. 下游：SPEED / MACE / OCE 三选一，把固定锚点换成 a_t*，把 B_t 作为保留约束
8. 评测：CLIP top-1（Acc_e/g/s/b）、H_o/H_b/BCTS；名人用 GIPHY detector；风格用 CLIP+FID+H_a；
   NSFW 用 I2P + NudeNet(0.6)
```

### 6.2 复现风险点

- 因果追踪要跑 |U| 次前向，cross-attention 单元数多时成本高（可先抽样）；
- MLM 激活用哪个模型会显著影响 U(a, c_t) 的排序；
- τ_c 需按目标标定，无通用值；
- BCTS 的 D̃ 是合并损伤，合并权重未给统一规范。

### 6.3 对我们最有用的最小实验（改写锚点构造）

**把 SEC 逻辑搬到输入侧改写，做一次"锚点类型 × 保真度"的消融**：

1. 从 reject_tag 里挑 100 条**边界型** PORN/VULG prompt（擦边、暗示、教学语境）。
2. 对每条构造 **5 类改写锚点**（对应论文的 5 类）：
   - **Target overlap**：只删敏感词，保留其余（"湿身" → "身上有水"）
   - **Shared visual**：换成同场景但弱化的词（"浴室" → "更衣室"）
   - **Generic/null**：直接删掉敏感片段（"她走进浴室" → "她走进房间"）
   - **Far unrelated**：换成完全无关表达
   - **Sibling exclusive**：**保留主体 + 保留场景 + 属性互斥**（"她赤裸地躺在浴室" → "她穿着浴袍坐在浴室地板上"）
3. 对每个改写跑三维评测：**安全分**（风险分类器）、**语义保真**（与原 prompt 的语义相似度 + 主体/场景要素保留率）、**指令遵循**（生成图与改写后 prompt 的 CLIP 一致性）。
4. 算一个 BCTS 式的联合分：`先卡安全阈值，达标后再只比保真`。

**预期判据**（基于论文的机制，可先写成假设）：Sibling exclusive 应该同时拿到"高安全 + 高保真"，Generic/null 保真掉最多（场景被删），Far unrelated 安全最高但保真最差，Target overlap 安全不足。

**如果实测不是这个顺序**，说明我们的风险不是"锚点距离"问题，而是**风险锚点定位错了**（改错了地方）——那就该先做锚点定位，而不是继续调改写模型。
