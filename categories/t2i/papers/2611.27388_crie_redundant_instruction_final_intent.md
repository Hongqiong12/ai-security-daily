## 一、背景与问题

### 动机：用户会「改口」，而编辑器会照单全做

复杂编辑请求常常一条指令里含多个对象、属性、空间关系，还会**修订或撤销前面的要求**（"把红椅换成蓝椅…不，还是换成灰色办公椅；另外把刚才那个花瓶取消"）。两种朴素做法都坏：

- **直接一次性编辑**：编辑器读不出修订后真正要什么，意图丢失；
- **拆成多步顺序执行**：早期被撤销的编辑已经落到图上，视觉错误逐轮累积，后续难以回滚。

作者的关键洞察：**先把修订历史解析成一个「最终编辑目标（final editing target）」**，让 planning 与 verification 共享同一个目标，这样被撤销的请求根本不会变成视觉编辑。

### 与本仓库主线的关系（三重命中）

1. **I2I 编辑指令语义保真 / 编辑指令改写**：本轮 I2I 改写面的第二篇直接相关供给。对本项目「同一份改写 Prompt 同时作用于生成与编辑两条通路」的落点：应先做**意图归一化**（撤销/修订折叠），再谈风险锚点替换，否则改写的是一份已经过时的意图。
2. **I2I 0/0% 的第九种可证伪归因 —— 判据本身没有可判的正例**。论文 Table 1 最扎的一行：**五个编辑后端在 CRIE-S 上「完整编辑成功率」全部 0.0%**。这不是模型全坏，是**「完整成功」这个判据在直接编辑下没有分辨率**（对象/属性/关系单维都有 54–84 分，唯独全要件联合为 0）。⇒ 与 10-27 ABACUS「先定义改对了算不算安全」、11-08「0/0% 可能是没有可判的正例标准」完全同构，本轮第一次有公开 benchmark 给出实测。
3. **中性 prompt 语义取向漂移 / 用户侧误伤体感**：「冗余指令 + 撤销」是典型的中性表述，字面无风险但意图会翻转。⇒ 跨语言/中英混合改写鲁棒性里的「中性 Prompt 语义取向漂移」对照臂，可直接用 CRIE-S 的修订历史构造。

## 二、核心方法

### 2.1 CRIE-S：10,000 条带「精确最终意图」标注的冗余编辑指令

- 每条含**成对的冗余请求**、原子编辑记录、以及**精确 final intent 标注**（不是只标动作，是标「修订后到底要什么」）。
- 评测按三个原子维度 + 一个联合维度：**对象正确性 O. / 属性准确率 A. / 空间关系准确率 R. / 完整成功 S.**（全部要件同时满足才算）。
- 作者说明 $|V^*|=5$ 量级的最终目标，并刻意保留修订历史使任务不只是「恢复最终意图」。

### 2.2 CRIE-Agent：先折叠意图，再执行，再验证重做

1. **Intent Agent**：微调 **Qwen3-VL-8B-Instruct**，把修订历史合并成 object-level final intent；撤销的请求不进入执行集。
2. **Reference-first blocks**：把待执行对象按依赖分组（$k=2$），先建立被引用对象再建依赖它的对象，避免空间关系挂空。
3. **Verification → 完整重执行**：验证器同时控制停止、候选选择与**从源图完整重执行**（带条件 layout hints），防止失败尝试的视觉错误被带进下一轮。⇒ 与 TIDE 的「按部件预算」互补：TIDE 管「别把细微编辑冻没」，CRIE 管「别把过时意图执行出来」。

### 2.3 为什么「拆步」不够

论文 Table 2 比较 single-step / multi-step 与 instruction-splitting、reorganization 基线：拆步能保住部分原子维度，但**保留 obsolete edits 与视觉错误**，完整成功仍 0–1.0%。⇒ 「多步」不是修法，**意图归一化 + 从源图重执行**才是。

## 三、技术细节

### 3.1 主结果（Table 1，CRIE-S test set）

| 后端 | O. 对象 | A. 属性 | R. 关系 | **S. 完整成功（直接编辑）** |
|---|---|---|---|---|
| Qwen-Image-Edit 2511 | 54.4 | 69.1 | 57.1 | **0.0** |
| **Qwen-Image-2.1** | 57.9 | **83.6** | 69.9 | **0.0** |
| FLUX.2-klein-4B | 54.1 | 76.4 | 65.4 | **0.0** |

**CRIE-Agent 把完整成功从 0% 抬到 27.5–50.0%**：Qwen-Image-2.1 **50.0%**、FLUX.2-klein-4B **27.5%**；五个后端上 O./A./R. 全部随 CRIE-Agent 提升。既有编辑 agent 在 CRIE-S 上完整成功 **0–1.0%**。

### 3.2 消融（Table 2 / Fig.5）

逐次加 Intent Agent → +Verification → +layout hints → +block grouping，定性图显示对象与空间错误逐步消失；作者报告「分割/重组织基线不如按 final intent 共同引导 planning 与 verification」。

### 3.3 关键口径：三维各自不低，联合为 0

对象 54–58、属性 69–84、关系 57–70，**但四者同时满足为 0**。这是「整体指标与分层宏平均背离」的镜像形态：分层看还行，联合判据直接归零。⇒ 报「方向覆盖数」而不是 0/1，正是 10-29 提出的 I2I 四步归因第①步（$K=4\sim8$）——本轮拿到了公开实测支撑。

## 四、实验与结果

### 4.1 结果判读

- **判定单位决定有没有供给**：把「完整成功」换成「方向覆盖数」（$K$ 个要件里成立几个），0% 立刻变成有分辨率的分布。⇒ 0/0% 里至少有一部分是**判据无分辨率**，不是改写器没写好。
- **验证器不是装饰**：从源图完整重执行 + 条件 layout hints 是防止错误累积的关键；对本项目「改了没生效」与「No-op」分开监控有直接借鉴（回滚 vs 未命中是两类事件）。
- **与 TIDE 合起来的 I2I 改写面**：TIDE 证明「单一全局阈值先杀细微编辑部件」（Theorem 1/2），CRIE 证明「不做意图折叠会把过时请求写进图」。⇒ 一份改写 prompt 若同时作用于生成与编辑两条通路，必须先过「意图归一化 → 部件级分档 → 双通路分报」三步，否则两条通路会各自丢不同的要件。

### 4.2 迁移到本项目的 0/0%

**第九种可证伪归因**：改写分流的**验收判据没有可判的正例**——「命中/未命中」是二值且要求全要件同时成立，等价于 CRIE-S 的 S.=0.0%。零训练检验（1 天）：把 2000 条评测集（1979 有效样本）的 I2I 指令抽 200 条，人工标「主体 / 操作 / 目标区域 / 撤销项」四要件，按 $K$ 报**方向覆盖数**与「0 个要件读出 / 全部要件读出 / 均匀」三档占比。判据：三档里「全部要件读出」占比高 ⇒ 下游编辑能力问题，不是改写问题；「0 个要件读出」占比高 ⇒ 改写抹掉意图。

## 五、局限性

1. **不是安全工作**：CRIE-S 的「冗余/撤销」是意图复杂度，不含 NSFW / 政治风险锚点；「撤销项」可类比「中性 prompt 取向漂移」，但不是同一分布。
2. **Intent Agent 需微调 Qwen3-VL-8B**：本仓库 2B 改写模型现状不一定扛得住 8B 级意图解析；零训练替代方案是先用规则/词表做撤销词折叠。
3. **只报英文或单一语言口径**：论文未明确跨语言/code-switching 评测，与用户「中英混合鲁棒性」缺口不能直接互证。
4. **未报推理延迟 / 量化 / serving setup**：多轮验证 + 从源图重执行会显著拉长 e2e，与 TTFT ≤110ms / e2e ≤160ms 的线上 SLO 冲突，本文无数据。
5. **未覆盖统一生成-编辑模型双通路共用一份改写**：CRIE-Agent 只走编辑通路；用户关切的「同一份改写 Prompt 同时作用于生成与编辑」仍需自建对照。
6. **完整成功仍只到 27.5–50.0%**：说明「意图折叠」是必要非充分条件，不能当作已解决 I2I 语义保真。

## 六、复现指南

### 6.1 论文复现

CRIE-S 10,000 条（训练/测试拆分按论文）；Qwen3-VL-8B-Instruct 微调 Intent Agent；五个编辑后端；$k=2$ reference-first blocks + 从源图完整重执行；同时报 O./A./R./S. 四栏。**必做三条对照**：① 直接一次性编辑（应得 S.=0）；② 拆步执行（应保留 obsolete edits）；③ 去掉 verification 的重执行（错误累积）。

### 6.2 本项目最小复现（零训练，1 天，D5 与 D6 共用）

1. **四要件重打标（针对 0/0%）**：2000 条评测集抽 200 条，人工标「主体 / 操作 / 目标区域 / 撤销项」，改报**方向覆盖数**而非 0/1；按「0 个 / 全部 / 均匀」三档定归因（判据见第四节）。
2. **意图折叠前置对照**：同一批指令做「原样 / 规则折叠撤销项 / 折叠 + 分部件强度」三版，跑现有分流，报改写命中率与原子要件保留率。判据：折叠后命中率显著升 ⇒ 0/0% 里有过时意图被当有效请求。
3. **中性 prompt 取向漂移臂（D6）**：构造「含撤销/修订但字面中性」的中 / 英 / 中英混合三版，跑现有分类器看分数分布是否系统性偏移；叠加 HinT 的非目标属性引入率一起报。
4. **双通路对照（统一生成-编辑模型改写面）**：固定一份改写后 prompt，分别走生成通路与编辑通路，报两通路风险判定差与四要件保留率差。判据：差 >15 点 ⇒ 不能共用一份改写，须按通路分流下发。

**上线口径**：多轮验证与重执行会抬 e2e，灰度前必须报 TTFT / e2e / TPOT / 超时率 / 降级率，并把「回滚事件」与「未命中事件」分列进策略命中审计；shadow → canary 只换流量比例，冻结评测单位与 serving setup 指纹。
