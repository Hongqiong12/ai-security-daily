# Copying As Defense: 编辑安全的真机制是注意力竞争 —— 为什么"让模型忘掉原图"是错的

**论文主页**: https://arxiv.org/abs/2610.35566
**领域**: 指令式图像编辑（I2I）安全 / 主动防护（proactive defense）/ 多模态 DiT 注意力机制
**作者**: Salma Abdel Magid, Sanghyuk Chun, Eric Slyman, Kushal Kafle, Olga Russakovsky
**机构**: **Adobe Research** + **Princeton University**
**发布日期**: 2026-10-26（v1，cs.CV）
**分类**: defense
**模态归属**: 图生图（指令式编辑）— 编辑链路安全，且从机制层解释了"指令侧改写为什么会失效"

## 一、背景与问题

### 动机

一张照片发出去之后，任何人都能拿它去指令式编辑器（Flux Kontext、FIBO Edit）上做非自愿篡改：换脸、换装、改姿态、生成不在场的场景。主动防护的思路是：**发布前在原图里加一层不可见扰动**，让后续编辑失败。

已有方法（DeContext 为代表）的直觉很自然：**如果输出"看不见"原图，就改不动原图**，所以去压掉 target→reference 的注意力，叫"去上下文化"。

本文说：**这个方向反了，而且不仅不够，还有反作用。**

### 两个失效机制（本文最重要的概念产出）

**(1) Mass redistribution（注意力质量重分配）**

softmax 注意力每一行的和恒为 1：

$$\sum_{k\in C} A_{q,k} + \sum_{k\in T} A_{q,k} + \sum_{k\in R} A_{q,k} = 1$$

其中 $C$ = 文本 token，$T$ = 待生成画布 token，$R$ = 参考图 token。

于是**压掉参考图的注意力，等价于把概率质量送给文本和画布**——而这两条恰恰是"指令遵循"和"生成"的通路。一个被成功"去上下文化"的编辑器，仍然可以靠文本指令凭空画出一张新图。**输出不再贴着原图，但恶意指令照样被执行。**

**(2) Token coverage（token 覆盖不足）**

图像级的平均抑制，对**主体占 token 比例小**的图不管用。作者给了直接证据：

| 场景 | 主体 token 占比 | 抑制效果 |
|---|---|---|
| 面部特写 | **92%** | 有效（脸中心编辑被破坏） |
| 全身照 | **31%** | **失效**（"愤怒"表情、"红色比基尼"两项编辑都成功） |

全身照里人脸只占参考 token 的一小部分，**图像级平均一摊，身份区域就被稀释掉了**。

### 为什么这篇对我们重要

我们这条线做的是**指令侧安全改写**（把风险编辑指令改成安全表达）。CaD 从机制上给了我们一个此前没有的、可检验的失效解释：

**编辑器的行为是"参考图注意力"与"文本注意力"之间的一场零和竞争。** 那么：

- 指令改写得**越软、越模糊**（为了安全）→ 文本侧 grounding 变弱 → 模型把注意力挪回参考图 → **直接复制原图，编辑不成立**；
- 指令改写得**越硬、越具体**（为了编辑成功）→ 文本侧 grounding 变强 → 但也很可能**把风险内容重新指定出来**；
- 这个 trade-off 的斜率，**取决于主体在参考图里占多少 token**。

这正好是我们 I2I 改写分流命中 **0/0%** 的一个结构性候选原因：**不是改写器不行，是"软改写"在注意力层面等于"取消编辑"。** 下面第五节给出可落地的检验方案。

## 二、核心方法

### 核心反转：不要让它忘，要让它抄

作者做了因果干预实验（controlled attention interventions），结论很干净：

- **强制** target query 在**少数几个早期 double-stream block** 里把注意力压到参考图上 → 模型**复现输入**（甚至是一张有损复制），而不是执行编辑；
- 反过来，**显式移除**参考注意力 → 模型照样生成新图；
- 换成**全黑参考图**，同样的定性区别仍成立：强制 target→reference 得到黑图本身，抑制该注意力则模型自由生成。

所以"防护成功"的定义不该是**遗忘（forgetting）**，而该是**复制（copying）**。

### CaD（Copying as Defense）

对每个 target query，在**一小撮早期 double-stream block** 里，把 target→reference 的注意力质量往 1 推：

$$\mathcal{L}_{\text{CaD}} = -\sum_{b \in \mathcal{B}_{\text{early}}} \sum_{q \in T} \sum_{k \in R} A^{(b)}_{q,k}$$

三个性质直接来自这个目标函数的设计：

1. **注意力归一化让参考图直接与文本、画布竞争** —— 压住指令遵循**不需要预先知道恶意指令是什么**（这点对我们的"未知风险指令"场景非常关键）。
2. **目标是 per-token 的** —— 身份区域（脸）不会被图像级平均洗掉，直接解决 token coverage 失效。
3. **只动早期层** —— 前向可以在最后一个受保护 block 处截断，反向只穿过浅层，**不用对十亿参数编辑器求全梯度**，成本大幅下降。

### 与 DeContext 的关系

不是"更强的一版抑制"，而是**反号**。DeContext 最小化 target→reference 注意力；CaD 最大化它。二者目标函数方向相反，失效机制也相反：DeContext 败在 mass redistribution + token coverage，CaD 恰好把这两点变成自己的增益来源。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 威胁模型 | $x_{\text{adv}} = x + \delta$，$\|\delta\|_\infty \le \epsilon$；攻击者拿 $x_{\text{adv}}$ + 编辑指令 $c$（必要时带 mask）交给编辑器 $G$ |
| 优化 | 标准逐图对抗优化 + 投影梯度上升 |
| 编辑器 | **FLUX.1 Kontext-dev**、**FIBO Edit**（后者用结构化 JSON prompt） |
| 数据集 | **InpaintGuardBench**、**BodyBench**（全身照专测） |
| 扰动预算 | $\epsilon \in \{4, 8, 12, 16\}/255$ |
| 优化步数 | 基线 800 步 / 本文 1000 步 |
| 评价指标 | Edit Success Rate（ESR）、PickScore、CLIPdir、ArcFace、LPIPS、PSNR、单步中位耗时 $T_S$、总防护耗时 $T_P$ |
| ESR 判定 | **Qwen3-VL-30B-A3B-Instruct**，联合看原图 + 编辑图 + 指令 + 期望编辑描述；要求"实现了指定变换 + 保留无关内容与身份 + 无明显伪影"三条同时满足 |

**一个方法论细节值得抄**：ESR 不是"看起来变了没有"，而是**四项联合判定**（变换达成 × 无关内容保留 × 身份保持 × 无伪影）。这比我们常见的"打一个分"要严格得多。

## 四、实验与结果

主表（$\epsilon = 12/255$，ESR 越低防护越强）：

| 编辑器 | 数据集 | 未防护 | PhotoGuard | DeContext | Diff-PGD | **CaD** |
|---|---|---|---|---|---|---|
| FLUX Kontext | InpaintGuardBench | 0.820 | 0.780 | 0.210 | 0.520 | **0.160** |
| FLUX Kontext | BodyBench | 0.816 | 0.818 | 0.249 | 0.442 | **0.051** |
| FIBO Edit | InpaintGuardBench | 0.800 | 0.823 | 0.597 | 0.527 | **0.183** |
| FIBO Edit | BodyBench | 0.818 | 0.813 | 0.664 | 0.476 | **0.564** |

关键读数：

- **平均 ESR 81.4% → 24.0%，相对降 70.6%**；相对最强基线 DeContext（43.0%）再降 **44.3%**。
- FLUX Kontext + BodyBench 上降到 **5.1%**，同时 CLIPdir 掉到 **0.0359**（次优防护方法是 0.2574）——**语义变化方向几乎完全被掐断**，不只是"画坏了"。
- **成本更低**：Flux Kontext 上单步中位 **0.647 s** vs DeContext 1.232 s；总防护 **10.78 min** vs 16.43 min（约 **1.8–2.0×** 加速）。
- 扰动可感知性相当（LPIPS 0.31–0.39 vs 基线 0.34–0.43，PSNR 28.7–29.8 vs 29.4–30.1），**没有用更大的扰动换效果**。
- $\epsilon$ 从 4 到 16 全程领先（Fig. 4），不是单点调参的产物。

### 一个被顺手证伪的点

Fig. 3 第三行：DeContext 保护后的图里，**原主体身份已经不见了，但"无条件下生成"的内容照样出来了**。这是 mass redistribution 的教科书式表现——防护"成功"地让模型忘了原图，代价是把画布完全交给了文本。

## 五、局限性

1. **只做图像侧防护，不做指令侧**。它防的是"别人拿我的图去改"，不是"我的指令有风险"。对我们的 I2I 改写是**机制参考**而非**方法替代**。
2. **白盒假设**。梯度要穿过编辑器，开源的 FLUX Kontext / FIBO 可做，闭源 API 编辑器（Gemini 2.5 Flash Image、GPT-Image-1）不适用。作者未讨论黑盒迁移性。
3. **需要逐图优化**。1000 步/图，$T_P$ 仍是十分钟量级；大规模发布场景（每天百万图）成本不可接受。
4. **FIBO 上效果明显弱**（BodyBench 0.564，只比 Diff-PGD 的 0.476 差一点——其实更差）。作者归因于 FIBO 的架构差异，但没有给出机制层面的解释，也没做 block 选择的消融（究竟几个 block、哪几个 block 最优，附录之外证据不足）。
5. **未评估"部分成功"**。ESR 是二值判定，但真实风险场景里"改了一点但没改到位"可能已经构成伤害（例如只把上衣换掉）。这一点对非自愿影像尤其重要。

## 六、复现指南

### 依赖
- 开源编辑器：FLUX.1 Kontext-dev（HF）、FIBO Edit（checkpoint 公开）
- 评测 judge：Qwen3-VL-30B-A3B-Instruct
- 数据集：InpaintGuardBench、BodyBench（文中引用，需自行按引用取）
- 单卡 A100 可跑（只反传早期 block，成本已大幅降低）

### 最小实现顺序
1. **先复现注意力干预实验**，不要直接训扰动。取 20 张图，手动把某几个早期 double-stream block 的 target→reference 注意力置高，看是否出现"复制输入"。这一步是**验证机制**，几小时可完成，且不需要数据集。
2. 再实现 per-token 目标 + 早期 block 截断反向。判据：单步耗时是否显著低于 DeContext（本文给的是 0.647 vs 1.232 s）。
3. 最后扫 $\epsilon \in \{4,8,12,16\}/255$ 看 LPIPS–ESR 曲线是否稳定领先。

### 迁移到我们的 I2I 改写链路（本文最大价值）

**可直接借用的判据：把"主体 token 占比"当成 I2I 改写链路的先验分层变量。**

具体做法（零训练，脚本级）：

1. 取当前 I2I 分流漏掉（即被判为"不需要改写"、实际有风险）的 200 条样本，用 **SAM 3 / 全景分割**算每条指令涉及的**目标主体在参考图中占的 token 比例**（像素占比近似即可）。
2. 按 92%（面部特写类）/ 31%（全身类）这两个锚点分三档（>70% / 40–70% / <40%）。
3. 分档统计"改写后编辑是否仍然成立"。**判据**：若 <40% 档的编辑失败率显著高于 >70% 档，则说明我们的软改写在这类图上等价于"取消编辑"，**0/0% 不是模型能力问题，是改写强度与 token 覆盖的结构性错配**。
4. 对应的改法不是"改得更软"，而是**给软改写配一个"保持目标区域 grounding"的约束**：改写只替换风险属性词，但必须保留"主体 + 动作 + 区域"三元组的显式引用（例如把"把她的裙子改成红色比基尼"改为"把她的裙子改成红色连衣裙"——保留了 `她的裙子` 这个 per-token 锚点，只换属性）。

**这一条把我们的 I2I 改写从"语义层改写"推进到"注意力层可控改写"**，也是本文最直接可用的东西。

---

**一句话判断**：它没有给我们一个新的改写方法，但给了我们一个**能解释 0/0% 的机制**——编辑成立与否，是参考图注意力与文本注意力的零和分配，而软改写恰好把票投给了参考图。修法不是改得更软，是保留 per-token 锚点。
