## 一、背景与问题

### 动机

T2I 安全里的老问题一直没真正解决：概念擦除确实能降低不安全内容生成，但很容易出现**过度擦除**——危险概念删掉了，连 prompt 里本来无害、又必须保留的语义也一起塌掉，最后变成“安全了，但也没用了”。

### 核心科学问题

能否把 concept erasure 从“粗暴压制危险概念”升级为“**同时最小化不安全内容、最大化良性语义保真**”的问题，并且让这种机制在 I2I 场景里也成立？

### 对当前业务的重要性

这篇论文和你的主线非常贴：它本质上是在回答“**如何只删风险锚点，不误伤安全语义**”。这和输入侧 prompt rewrite 的目标几乎同构，只不过它做的是模型侧擦除，而你做的是输入侧改写。

## 二、核心方法

### （1）CER：双目标奖励

ForceForget 用强化学习优化 concept erasing reward（CER）：

- **安全奖励**：尽量压低不安全内容生成；
- **对齐奖励**：尽量保留 harmful prompt 中本来无害、仍有价值的语义。

论文最关键的判断是：如果只优化安全，模型会退化；如果只优化保真，又擦不干净。必须把两者放进同一个奖励函数里联合求解。

### （2）Safe Adapter：局部调节文本条件

作者没有对整条文本条件大动干戈，而是在 cross-attention 里只对部分 token 做轻量调节：
- 前部 token 走标准 LoRA 投影；
- 末尾少数 token 走 Safe Adapter；
- 目标是让模型“只改危险相关表达，不打烂整条条件语义”。

### （3）BLIP + 过滤语义词：提取安全语义保留目标

对齐奖励不是拍脑袋定义的，而是：
- 先用 BLIP 从生成图像中抽取描述；
- 过滤掉敏感词；
- 再用 CLIP 对齐“安全描述”与目标条件，例如 `a photo of person wearing cloth`。

这一步非常像你要做的 risk-anchor surgery：**不是完全删 prompt，而是先把可保留的安全语义抽出来，再围绕它做约束。**

## 三、技术细节

### 双奖励联合目标

论文把 CER 写成：

```text
CER = λ1 · r_safe + λ2 · r_align
```

其中：
- `r_safe` 由 NudeNet 风险得分构造；
- `r_align` 由 BLIP 描述 + 过滤后的 CLIP 对齐组成；
- 默认 `λ1 = λ2 = 1`。

### Safe Adapter 为什么有效

作者的工程判断是：
- 不安全概念通常在 prompt 前部更显式；
- 如果直接改这些显式 token，容易把整句语义一起打乱；
- 反而在末尾 token 上施加轻量调节，更有机会保住整体语义完整性。

### I2I 迁移性

论文特别强调：
- 很多 T2I 擦除方法迁到 I2I 会明显失效；
- ForceForget 的局部调节策略在 I2I 上表现更稳；
- 说明**局部、结构化的控制**比全局压制更适合多任务图像生成体系。

## 四、实验设置与结果

### 主结果 1：安全性显著提升

在 I2P 数据集（4703 张图像）上：
- **NRR = 97.96%**
- 裸露相关检测部位总数仅 **6** 个
- 男性乳房 / 男性生殖器 / 臀部等关键类别均做到 **0**

### 主结果 2：对抗鲁棒性强

在红队测试中：
- Ring-A-Bell：**100% NRR**
- P4D：**100% NRR**
- MMA：**99.63% NRR**

这意味着它不只是对普通 prompt 安全，而是对现有主流越狱工具也有相当韧性。

### 主结果 3：语义保真没有被一刀切牺牲

在 COCO-30K 上：
- **CLIP = 30.53**
- 原始 SD v1.4 为 **30.63**
- **FID = 26.73**

也就是说，安全性大幅提升的同时，整体文本对齐与图像保真几乎没崩。

### 主结果 4：人物内容仍然保得住

在 110 位名人、2750 张图像的人物内容保留测试上：
- **GCD 识别准确率 = 90.7%**

这条结果很重要，因为很多 safety 方法的问题不是“擦不掉”，而是“把人物相关能力也一起擦坏了”。ForceForget 至少证明它没有把人物生成完全做残。

### 主结果 5：I2I 场景也成立

- 裸露初始图像输入：**96.4% NRR**
- 干净初始图像输入：**100% NRR**

这说明它对编辑链路也有效，而不是只在 T2I 上成立。

### 对当前业务的直接启发

如果把 ForceForget 的抽象迁到输入侧 rewrite，最值得借的不是 RL 本身，而是这三个动作：
1. **把可保留安全语义显式抽出来**；
2. **风险锚点局部替换，而不是全句重写**；
3. **安全分数和语义保真分数必须联合优化，而不是先后串行补救**。

---

## 五、局限性分析

1. **仍是模型侧擦除，不是输入侧 rewrite**。  
2. **对齐奖励依赖 BLIP 与 CLIP，语义提取质量决定上限**。  
3. **主要围绕裸露/NSFW 概念展开**，对更抽象风险类别仍需验证。  
4. **没有把三维评测显式做完**：安全与保真有了，但“指令遵循损失”仍不够完整。  
5. **机构与实现细节公开度有限**，完整复现仍需较强工程推断。

## 六、复现指南

### 环境依赖

```bash
pip install torch diffusers transformers accelerate peft
```

### 最小复现步骤

1. 选择 SD v1.4 / SD v1.5 作为底座。  
2. 为 cross-attention 加入 LoRA + Safe Adapter。  
3. 用 NudeNet 计算安全奖励。  
4. 用 BLIP + 过滤词典 + CLIP 构造对齐奖励。  
5. 在 I2P、Ring-A-Bell、MMA 上同时评安全性与保真度。  
6. 额外测 I2I 场景，不要只停留在 T2I。

### 对当前业务的最小迁移版本

如果只迁一件事，我建议迁它的**双奖励思路**：
- 风险下降分；
- 语义保真分；
- 两者同权或近似同权联合评测。

否则 rewrite 很容易走向“看起来更安全，但把 prompt 真正想表达的东西也改没了”。
