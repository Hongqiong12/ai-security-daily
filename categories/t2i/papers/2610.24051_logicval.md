# LogicVal: A Logic-Formalized Benchmark for Constraint Satisfaction in Text-to-Image Generation

**arXiv**: https://arxiv.org/abs/2610.24051
**领域**: cs.AI
**作者**: Savitha Sam Abraham, Marjan Alirezaie, Hossein Rahnama
**机构**: City St George's, University of London · Toronto Metropolitan University · Flybits Labs · MIT Media Lab
**发布日期**: 2026-10-16
**分类**: benchmark（把 T2I 评测写成逻辑约束满足问题，无参考图）
**关键词**: 约束满足 / 答案集编程 ASP / clingo / 场景图抽取 / 组合泛化 / 指令遵循损失的形式化度量

---

## 一、背景与动机

### 一句话核心

> 现有 T2I 评测用 MLLM 打分或 CLIP 相似度，**没有对"图像必须满足哪些性质"做形式化声明**。于是"指令遵循"只能被软性估计，不能被证明。

LogicVal 的做法：把 prompt 写成一个**逻辑约束集合** $C$，把图像解析成一个**场景图** $\widehat S(I)$，然后问求解器：

$$\widehat S(I) \models C\ ?$$

**这是布尔答案，不是相似度分数。** 而且不需要参考图——任何满足 $C$ 的图像都算对。

### 为什么这对"指令遵循损失"是关键

我们现在的三维评测里，"指令遵循损失"是最弱的一环：

| 现在的做法 | 问题 |
|------------|------|
| CLIP / CLIPScore 相似度 | 对数量、否定、空间关系几乎不敏感 |
| MLLM 打分（Soft-TIFA 类） | 打分尺度漂移，不可复核 |
| 人工 | 太贵，无法回到训练回路 |

LogicVal 提供第三条路：**形式化 → 可判定 → 可自动化 → 可回放**。这是唯一能进训练回路的"指令遵循"度量形态。

### 与前作的关系

CLEVR-POC（Abraham et al., 2024）已经定义了域（8 色 / 3 形状 / 2 材质 / 2×2 区域）。LogicVal 的增量是**把"要满足什么"从自然语言 prompt 里显式抽出成 ASP 约束**，从而让评测变成 SAT 判定。

## 二、核心方法

### 2.1 三段式流程

```
① 逻辑规格 C（ASP 约束，来自 71 个模板实例化）
   → ② 语言化：确定性 verbaliser 渲染成自然语言 prompt（短 / 长两种寄存器）
      → ③ T2I 模型生成图像 I
         → ④ 场景图抽取 Ŝ(I)（GSAM 检测 + CLIP 判属性 + 空间接地）
            → ⑤ clingo 判定 Ŝ(I) ⊧ C ?
```

### 2.2 九类约束（三个表达力层级）

| 层级 | 类 | 约束形态 |
|------|-----|----------|
| **Object-level** | C1–C3 | 单对象的存在 / 全称 / 条件约束 |
| **SubGraph-level** | C4–C7 | 多对象关系：存在（C4）、条件（C5）、量词交替 $\exists\forall$（C6）、$\forall\exists$（C7） |
| **Cardinality-level** | C8–C9 | 满足某模式的对象数 vs 常数（C8）/ vs 另一模式（C9） |

**71 个 ASP 约束模板**，可组合：一条 prompt 可含 $m \in \{1, 3, 6\}$ 条来自不同类的约束，由求解器联合检查。

### 2.3 两个非常值得学的工程细节

**细节一：反空真条款（anti-vacuity clause）。**
对于全称约束（"所有蓝色物体都是圆柱"），必须额外加一条"至少存在一个蓝色物体"。否则图像里**没有蓝色物体**时，命题在逻辑上真——模型什么都不画也能得满分。

> ⚠️ **这是形式化评测的经典陷阱，也是最容易被漏掉的一条。** 我们做"改写后必须保留 X 属性"这类约束检查时，同样要防"X 根本没出现所以约束被空真满足"。

**细节二：UNSAT 是自然涌现的，不需要人造。**
单条约束很少自相矛盾；多条组合时经常矛盾。所以 UNSAT 样本是组合过程的自然后果。

**UNSAT 的正确输出是"画空场景"**——这让"识别不可满足"本身成为一个能力维度。

### 2.4 确定性 verbaliser

同一约束渲染成**短 / 长两种寄存器**（长的显式写出量词作用域）。这提供了一个干净的对照：**同一逻辑内容、不同语言表达**，可以直接测"模型是被语言表达骗了，还是没理解逻辑"。

## 三、技术细节

### 3.1 Benchmark 构成（509 条 prompt）

| 包 | 数量 |
|----|------|
| 1SAT | 355 |
| 1UNSAT | 25 |
| 3SAT | 25 |
| 3UNSAT | 10 |
| 6SAT | 25 |
| 6UNSAT | 69 |
| **合计** | **509** |

场景大小 $n \in \{3,\dots,9\}$ 个对象。

### 3.2 评测实现

- **检测**：GSAM + CLIP，抽出每个对象的形状 / 颜色 / 材质 / 边界框
- **空间接地**：由边界框推出 `left / right / front / behind`；同区域对象按反对称、逆、传递公理自由排序
- **判定**：`clingo` 求解，输出 SAT / UNSAT 匹配情况

### 3.3 被评模型

GPT-Image-2 · Gemini-3-Pro-Image · FLUX.1-dev · Qwen-Image

（覆盖闭源商用与开源，全部是 2026 年在役主力）

## 四、实验与结果

### 4.1 四个关键数字

| 现象 | 数值 |
|------|------|
| 最优模型在**单对象-属性**约束上的准确率 | **98%** |
| 同一模型在**复杂条件多对象关系**约束上的准确率 | **53%** |
| 最优模型单约束 prompt 准确率 | **84%** |
| 同一模型多约束同时满足的准确率 | **20%** |
| 最优模型正确识别 UNSAT（不可满足）prompt 的比例 | **23%** |

**读法：**

1. **单约束 → 多约束，准确率从 84% 崩到 20%（掉 64 个点）。** 组合泛化不是"略微下降"，是**断崖**。
2. **UNSAT 识别只有 23%**：模型基本不会说"这个要求没法满足"，它会硬画一张。
3. 复杂逻辑（$\exists\forall$ 交替）只有 53%，而简单属性绑定 98%——**表达能力越强，越依赖逻辑而非模式匹配**。

### 4.2 LogicVal 自身与人类判断的一致性

在 CLEVR 上，LogicVal 的 **ROC-AUC 0.88–0.98**（对齐人类判断）。

⚠️ **口径提醒**：这是"LogicVal 判定 vs 人类判定"的一致性，不是"模型准确率"。不要混用。

### 4.3 为什么这个结果对我们重要

我们的改写 pipeline 面对的是同一类问题：**改写后的 prompt 里，"必须保留什么"是一组约束**（主体、数量、属性、关系、场景）。

LogicVal 的两个数字直接给出了预期：

- 如果我们的保真评测用 **CLIP 相似度**：它连"数量对不对""否定词有没有生效"都测不出来，**等于没测组合约束**；
- 如果改用**逐约束核验**：单约束能到 84%+，组合约束必须单独报，**不能用平均分掩盖 20% 的崩盘**。

## 五、局限性

1. **域极窄**：CLEVR 只有 8 色 / 3 形状 / 2 材质 / 2×2 区域，**与真实图像语义差距巨大**。结论不能直接外推到开放域。
2. **依赖场景图抽取的准确性**：GSAM + CLIP 的属性/关系识别错误会直接变成"约束违反"，**评测误差与模型错误混在一起**。论文给的 ROC-AUC 0.88–0.98 是在 CLEVR 这种干净渲染图上。
3. **只测显式、可形式化的约束**：美学、语义氛围、隐含意图完全测不到。**安全语义（如"擦边"）根本无法形式化**。
4. **规模小**：509 条 prompt，不足以做统计稳健的模型排序。
5. **短/长寄存器差异的分析偏弱**：提供了这个对照，但没有充分展开"语言表达 vs 逻辑理解"的归因。

## 六、复现指南

### 6.1 资源

```
求解器：clingo（ASP）
检测：GSAM（分割）+ CLIP（属性分类）
域：CLEVR（8 色 / 3 形状 / 2 材质 / 2x2 区域 / 4 空间关系）
模板：71 个 ASP 约束模板（论文附录 B）
benchmark：509 条 prompt（6 个包：1/3/6 × SAT/UNSAT）
```

### 6.2 我们能用它做什么（不是照搬，是借形）

**不能做的**：用 CLEVR 逻辑测 NSFW。安全语义不可形式化。

**能做的三件事：**

| 借什么 | 怎么用 | 价值 |
|--------|--------|------|
| **约束集合 + 逐条判定** | 把"改写必须保留的属性"写成 list（主体/数量/动作/场景/关系），逐条核验，**不允许平均分** | 立刻能定位"改写丢了哪一项" |
| **反空真条款** | 每条保留约束加"该项必须实际出现"的前置检查 | 防止"没画出来所以没违规"的假通过 |
| **UNSAT 意识** | 改写后 prompt 若自相矛盾（如"穿着衣服的裸体"），应输出"改写失败"而不是硬改 | 减少无效改写 |

### 6.3 复现风险点

- clingo 的求解性能随约束数指数增长，$m=6$ 时需注意；
- GSAM + CLIP 的属性识别在真实图像上远差于 CLEVR 渲染图，**换域前必须重测检测器精度**；
- UNSAT 样本只有 69+10+25=104 条，占比低但结论权重高，需报置信区间。
