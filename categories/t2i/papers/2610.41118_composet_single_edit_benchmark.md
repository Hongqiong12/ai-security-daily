# 编辑评测的对照组设计错了，87% 的信号是"整张图不一样"

**论文主页**: https://arxiv.org/abs/2610.41118
**领域**: T+I2I 指令式编辑评测 / 视觉-语言组合性 / 单点编辑基准
**作者**: Laure Delisle, Pietro Perona
**机构**: California Institute of Technology（Perona 组）
**发布日期**: 2026-10-30（v1，cs.CV）
**分类**: benchmark / i2i
**模态归属**: T+I2I 编辑评测集构造 · 编辑指令语义保真度量

---

## 一、背景与问题

### 动机

指令式编辑的评测长期靠"配对图对比"：给 base 图和编辑后图，看模型能不能选中正确的那张，或者算 CLIP/BLIP 相似度。

论文量了一件事：**这些 benchmark 里的配对图，平均有 97% 的像素在变。**

这意味着配对之间同时变了场景、布局、内容、风格。模型只要捕捉到"整张图不一样"就能答对，根本不需要理解"到底改了哪一个属性"。作者的原话：

> 这样的配对不隔离组合性：结果被全局图像差异混淆。

对我们意味着什么：**如果 I2I 编辑评测集里 base 与 edit 的像素差异中位数在 90% 量级，那么这个评测集能测"编辑有没有发生"，测不了"编辑有没有改对"**——而后者才是安全改写要保的东西。

### 七条设计准则

论文给出了受控 benchmark 的七条准则（自然场景、多物体、单点编辑、每 base 多 foil、编辑类型覆盖、caption 多档长度、可解释评分）。其中两条直接击中我们：

1. **单点编辑（single controlled edit）**：base 与 foil 只差一个被命名的属性。
2. **每个 base 配多个 foil（~22 个）**：把"场景难"与"编辑难"分开——一条 base 只配一个 foil 的 benchmark 做不到这个分离。

### 四条论断

1. 现有组合性 benchmark 的分数是**设计混淆的产物**，不是能力度量。
2. 规模提升只带来边际改善（CLIP B/32 4.4% → SigLIP-2 SO400M 13.9%，仍在随机线以下）。
3. **文本侧**硬负样本训练**不迁移**到图像侧 foil。
4. caption 越长越难，稠密重描述预训练（DreamLIP）是唯一稳住的一支。

## 二、核心方法

### （1）Benchmark 结构

| 维度 | 取值 |
|---|---|
| instance 数 | **1,776** |
| base 场景 | **80**（自然多物体实拍感场景） |
| 每 base 的 foil 数 | **~22** |
| 编辑类型 | **16 种**，归为 **4 个语义类别** |
| caption 长度档 | **3 档**（短/中/长） |
| base–foil 平均像素变化 | **8%**（对比既有 benchmark 的 **97%**） |

4 个语义类别大致是：Identity & Appearance（颜色/材质/属性）、Spatial（空间关系/前后/上下）、Quantity（计数）、Activity & State（动作/状态）。

### （2）评分协议：双向 4 次比较

对每个 (base, foil) × (caption_base, caption_foil)，模型做 4 次比较：image→text 与 text→image 两个方向各 2 次。要求**双向都对**才算过（strict bidirectional）。这一步很关键：单向评分会被"固定介词偏置"污染——

> CLIP-B/32 把 `on` 认对的比例 92.2%，把 `under` 认对只有 22.3%。

也就是说，单向分数里混着一个巨大的先验偏置项。

### （3）Group 分数与随机线

Group 分数 = 4 次比较全对的样本比例，随机线 **16.67%**（1/6）。

### （4）质量控制

- **scene-clustered bootstrap**（B=10,000，按 80 个 base 场景聚类重采样）给置信区间，因为同一场景的 22 个 foil 不独立。
- **generator drift audit**：核查图像生成器版本漂移是否污染配对。
- **pixel-deviation 分析**：逐编辑类型报告实际像素变化，证明"单点"不是宣称而是量出来的。

## 三、技术细节

### 三个可验证的量

| 量 | 数值 | 为什么重要 |
|---|---|---|
| base–foil 像素变化 | **8%**（vs 既有 97%） | 这才是"单点编辑"的操作定义 |
| 22 个 dual-encoder 的 Group 分数上界 | **15.55%** | 全部低于 16.67% 随机线 |
| scene-clustered bootstrap 对 Wald CI 的加宽 | **27–71%** | 不聚类会把区间算窄一半 |

### 一个必须看的方法细节

聚类 bootstrap 加宽 CI 27–71% 之后，**22 个模型的上界仍然全部低于随机线**（最大 15.55%）。这条比"全部低于随机"本身更有信息量：它不是统计功效不足导致的"没测出差异"，而是**测出了系统性的低于随机**。

低于随机不是"没学会"，是**系统性反向**——模型在受控单点对比上倾向于选错。作者未完全解释这一点，但附录 E 指出 dual-encoder 存在介词级固定偏置，这可能是反向的来源之一。

## 四、实验与结果

### Table 3（节选 14 个代表模型，10 个 benchmark）

| 模型 | **CompoSET** | Winoground | BiVLC | What's Up | ColorSwap | MMVP | SugarCrepe |
|---|---|---|---|---|---|---|---|
| 随机线 | 16.7 | 16.7 | 16.7 | 16.7 | 16.7 | 50.0 | 50.0 |
| CLIP B/32 | **4.4** | 7.5 | 47.2 | 2.2 | 8.7 | 8.1 | 68.1 |
| CLIP B/16 LAION-2B | **7.8** | 8.2 | 53.3 | 1.1 | 19.3 | 12.6 | 70.7 |
| SigLIP B/16 | **10.2** | 10.2 | 59.6 | 1.6 | 30.7 | 23.0 | 74.7 |
| SigLIP-2 SO400M/14 | **13.9**（最好） | 15.2 | 49.5 | 4.2 | 39.7 | 31.1 | 79.4 |
| NegCLIP B/32（文本侧硬负样本） | **7.0** | 8.0 | 55.3 | 4.1 | 14.0 | 12.6 | 83.4 |
| DreamLIP B/16（稠密重描述） | **13.7** | 11.5 | 53.9 | 5.4 | 61.0 | 16.3 | 74.4 |
| DFN H/14 | **10.8** | 11.0 | 59.4 | 3.5 | 45.0 | 30.4 | 84.0 |
| MetaCLIP-2 H/14 | **8.9** | 11.0 | 48.3 | 1.6 | 20.7 | 17.0 | 80.2 |

**同一模型在不同 benchmark 上的落差**：SigLIP-2 SO400M/14 在 CompoSET 上 13.9%（低于随机），在 BiVLC 上 49.5%，ColorSwap 39.7%，MMVP 31.1%。

### 五个必须单独拎出来的数

1. **13.9% vs 16.67%**：最好的 dual-encoder 比随机线低 2.8 个点。不是"接近随机"，是"稳定低于随机"。
2. **97% → 8%**：把配对图的像素变化压到 8%，分数从"看似在进步"掉到"全军覆没"。
3. **7.0% < 7.8%**：NegCLIP 用文本侧硬负样本微调，在 CompoSET 上**比它的 base（CLIP B/16 LAION）还差 0.8 点**。文本侧负样本不迁移到图像侧 foil。
4. **14.6% → 12.4%**：SigLIP-2 SO400M 从短 caption 到长 caption 掉 2.2 点；CLIP B/16 LAION 掉更多（9.1% → 6.5%）。
5. **27–71%**：不按场景聚类的 CI 会窄这么多。我们的评测集如果按"一条指令一条样本"独立算 CI，同样会窄。

### 失败集中在哪

Spatial、Quantity、多数 Activity & State 编辑几乎全崩；只有 Identity & Appearance 里的少数编辑有非平凡表现。

**这个分布形态很关键**：颜色/材质类编辑（"把红车改蓝"）保得住，空间/计数/动作类全崩。原因是前者只需在局部区域做属性替换，后者需要维持**跨物体的绑定关系**。

### 生成式 VLM 与 frontier API 切片

作者对开放权重生成式 VLM 用 caption 对数似然打分、对 frontier API 用配对选择加选项顺序对消，结论是"前沿 VLM 能恢复更多信号，但只在逐 query 打分时"——即**不能把它当预索引检索器用**。这一片被明确标为 caveated slice，不与 dual-encoder 做头对头。

## 五、局限性

1. **只测 dual-encoder**：主结果对生成式模型不直接可比；生成式切片样本量小、协议不同。
2. **80 个 base 场景**：场景级聚类后有效的独立单元只有 80 个，对细粒度编辑类型的子分析功效有限（16 种编辑类型 × 80 场景，部分格子很稀）。
3. **低于随机的成因未定论**：论文指出介词偏置可能是来源之一，但没有做因果归因实验。
4. **图像是合成的**：base 场景虽追求自然主义，仍由生成器产出，存在 generator drift 风险（作者做了审计，但无法完全排除）。
5. **不涉及安全**：这是组合性/语义保真评测，不含任何风险类目。

## 六、复现指南

### 环境

- 代码：https://github.com/laure-delisle/CompoSET
- 数据：https://huggingface.co/datasets/CompoSET/CompoSET
- 许可：数据 CC BY-SA 4.0，代码见仓库

### 最小复现路径（按对我们的价值排序）

1. **先算我们自己的 1,979 条 I2I 评测集的像素变化中位数**。如果中位数在 80–95% 区间，说明它和"97% 的旧 benchmark"是同一类，那么当前 0/0% 的命中率有一半是评测集设计造成的假象。这一步只要几十分钟，不需要任何模型。
2. **照 CompoSET 改造 200 条子集**：一条原始指令配 3–5 个单点 foil（只改主体/只改场景/只改操作/只改目标区域），其余完全不动。看同一模型在这 200 条上的"方向覆盖数"是否从 0 变成非 0。
3. **把双向评分加进评测**：现在如果只做"输出图 vs 目标描述"的单向相似度，会混入固定偏置。加"指令方向"与"反向指令"两次，报 strict 双向通过率。
4. **CI 用场景/指令聚类 bootstrap**：按"同一原图/同一指令族"聚类重采样，不要按样本独立算。

### 关键超参

| 参数 | 取值 |
|---|---|
| foil 数 / base | ~22（我们做子集时 3–5 够用于方向覆盖） |
| 随机线 | 1/(2×编辑类别数) 视协议而定，双向协议下 16.67% |
| bootstrap | scene-clustered, B=10,000 |
| caption 档位 | 3 档（短/中/长），长短差 2.2 点 |

## 附：与业务的三条硬对应

1. **直接对应 I2I 分流 0/0% 的第一层归因**：先量评测集的像素变化中位数，把"评测集测不出方向"与"改写抹掉意图"分开。这是零成本、当天可做的归因。
2. **直接对应 1,979 条评测集的结构改造**：从"一条指令配一个目标"改成"一条指令配多个单点 foil"，这样"方向覆盖数"才有分辨率（K=4 时 1 个方向成立即 25%，指标立刻从 0/1 变成 0–100%）。
3. **反面教训**：文本侧硬负样本（把指令里的词换掉）不迁移到图像侧 foil。我们的 I2I 改写 hard negative 如果只在指令文本上做扰动，很可能同样不迁移——hard negative 必须在**图像侧**构造（同一指令、不同源图）。
