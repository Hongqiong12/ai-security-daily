## 一、背景与问题

### 动机：缓存加速只被图像级分验收，而出图侧语义可以整体换掉

DiT 的特征缓存（feature caching）是标准加速手段，做法是复用若干步的预测、跳过重算。业界验收缓存用的是 **ImageReward / CLIP Score / FID / LPIPS** 这类图像级指标——这些指标检查「像不像、好不好」，**不检查模型写出来的内容是否还是原来那份**。论文把这件事做成可证伪命题：在渲染长文本的 DiT 上，缓存**静默改写**了文本。

**核心读数**：Z-Image 上 TaylorSeer 在 **2.9× fewer FLOPs** 时把 word accuracy 从 **62% 压到 46%**（正文另处按 0.621→0.464 记），而 **ImageReward 与 CLIP Score 几乎不动**。也就是说，一个「看起来无损」的加速链路，把出图侧的关键语义改写了，而现有验收装置对此完全失明。

### 与本仓库主线的关系（三重命中）

1. **输入改写有效性上界的第二层机制**。11-24 的 AnimalFarm 给出「两名标注员保守筛查过的输入，仍 92.1% 出图、95.9% 带仇恨」，是**跨三通路的现象级证据**；本篇给出**机制级解释**：即使 prompt 一个字没动，生成过程内部（缓存对跳步的预测）也会改写输出语义。⇒ 本项目 3,000 条改写后仍被打击 case 中 2,700+ 条「改写后文本无害但出图有害」，除生成器分布外，还多了一条**推理侧执行路径**的归因。
2. **推理加速 / 量化不劣化验收**。用户侧 1105 权重 TTFT ≤110ms / e2e ≤160ms、fp8/fp4 量化降本、P800 迁移，本文证明「FLOPs 降了、图像级分不动」不等于「输出语义没换」。**验收必须补语义级指标**，且必须报加速配置指纹。
3. **跨语言 / 中英混合**。评测集含 **320 条英文与中文 prompt**（Z-Image 全量）与 160 条子集（Qwen-Image）；文中明确「guidance term 占比在英文与中文 alike 为控制组的 **1.66×**」，且 GuideCache「对中文的恢复多于拉丁文本」。⇒ 中英两档在**同一加速配置下退化与恢复幅度不同**，不是单一语言结论。

**与 11-24「代理量脱钩」主题的接续**：昨天六篇是「聚合分数稳、判定全换」；本篇是「图像级质量分稳、**出图内容本身**被换」，且诊断量（Qwen3-VL judge 对方法的排序 Kendall τ=0.72）也抓不住幅度 —— **脱钩再往输出侧深入一层**。

## 二、核心方法

### 2.1 把缓存误差沿 CFG 分解

真 CFG 的输出是 `v̂ = v_uncond + w·(v_cond − v_uncond)`，其中 **guidance term = v_cond − v_uncond**。作者把缓存外推误差沿两条分支拆开，发现文本 token 上 guidance term 占输出的比重是背景 token 的 **1.66×**（中英一致），而缓存对这一项的外推最差 —— 误差被 guidance scale `w` 放大，于是文本先坏，背景看起来还好。

### 2.2 GuideCache：只对「guidance 误差大」的 token 重算两个分支

- 用 **guidance share ρ** 作为选 token 的信号（误差按比例分配），在每步只重算 `r` 比例的 token 的 **条件 + 无条件两条分支**，其余继续用缓存。
- 关键设计约束来自消融：**只重算条件分支不够**（见第三节），必须两分支一起，因为信号是它们的**差**。
- `r ∈ {5%,10%,20%,30%}`，按概念/分辨率重校准 `ε̄_ref`。

### 2.3 为什么「少走几步」比「缓存跳步」更保语义

同等算力下把采样步数从 50 降到 17，几乎能保住全部文本，恢复 **83% 丢失的 prompt fidelity / 90% 丢失的 word accuracy**。⇒ 损失不是「算力不够」，而是**缓存怎么预测被跳过的那几步**。这条对照把「加速」与「改写输出」之间的因果钉死，是本轮最可迁移的实验设计。

## 三、技术细节

### 3.1 实验设置（可复现口径）

| 项 | 值 |
|---|---|
| 主干 | Z-Image 6B、Qwen-Image 20B，1024²，默认 50 步，真 CFG |
| 文本评测 | LongText-Bench：Z-Image 全 320 条中英 prompt；Qwen-Image 固定 160 条子集；各 2 seeds |
| 图像质量评测 | DrawBench 200 条 |
| 设计选择 | 固定 48 条 development 子集，自带 full-compute 参考；**所有设计选择只在该子集做**，其余 prompt 上复现增益 |
| 对照缓存 | FORA（0 阶）、TaylorSeer（1/2 阶）、ToCa / TeaCache / FasterCache（作者移植到 Z-Image） |
| 指标 | word accuracy（OCR）、prompt fidelity、ImageReward、CLIP Score、FID、LPIPS、FLOPs 倍数 |

### 3.2 消融：误差信号必须来自「两个分支的差」

Table 3（Z-Image development，TaylorSeer 17 anchors，`r=30%`，word accuracy）：

| 变体 | word accuracy | 读法 |
|---|---|---|
| Plain cache | 0.386 | 基线 |
| **Unconditional only** | **0.235** | 比不用 GuideCache 还差 |
| Conditional only | 0.481 | 有效但不足 |
| Both branches | **0.532** | 最好 |
| OCR boxes（oracle） | 0.511 | 用真值框反而不如按误差选 |
| Guidance share ρ | 0.516 | 与 oracle 同量级，不需外部标注 |
| Full compute | 0.540 | 上界 |

⇒ **只重算无条件分支会主动破坏文本**；这与「负向 prompt / CFG 安全引导」的直接关系：安全引导项承载的正是条件文本的信息，动它必须成对动。

### 3.3 架构决定退化幅度（跨模型、跨语言）

- Qwen-Image 把每个 token 的 guided output 按 conditional norm 重缩放，等于**封顶** `‖w·e_g‖`，因此同样缓存下丢文本更少；**关掉重缩放后 word accuracy 损失翻倍（0.169 vs 0.084）**，退化幅度回到 Z-Image 水平。
- 分辨率越低越脆：512² 的 word accuracy 损失 **−0.220** vs 1024² 的 **−0.172**。
- 文本区误差是背景的 **3–4×**；缓存只改写了 full-compute 正确字符串中约 **8%**，但改的都是承载语义的关键串；按 ρ 选中的 token 有 **77%** 落在文本区内。
- 中文恢复多于拉丁文本，Qwen-Image 呈同一顺序 ⇒ **跨语言对照不能只报聚合 word accuracy**。

## 四、实验与结果

### 4.1 主结果（正文明确陈述的读数，表格列不做外推）

| 配置 | FLOPs | Z-Image word accuracy | 说明 |
|---|---|---|---|
| Full（50 步） | 1.00× | 0.621 | 上界 |
| TaylorSeer（17 anchors） | 2.94× 更少 | **0.464** | ImageReward / CLIP 几乎不动 |
| TaylorSeer + GuideCache `r=10%` | 2.46× 更少 | **0.606**（46%→61%） | 恢复约 **91%** 丢失的 word accuracy |
| TaylorSeer + GuideCache `r=20%/30%` | 2.14×/1.89× | 0.608 / 0.612 | 收益饱和 |
| Qwen-Image 同配置 | 2.41× | 恢复约 **73%** | 架构不同，恢复幅度不同 |

### 4.2 高倍加速下「不修就崩」

13 anchors（3.85× FLOPs）时，TaylorSeer 的 word accuracy 掉到 **0.124（Z-Image）/ 0.057（Qwen-Image）**；加 GuideCache `r=10%` 回到 **0.388 / 0.334**。Table 2 里 TaylorSeer（一阶）13 anchors 的 plain cache 为 **0.213**，`r=20%` → **0.617**、`r=30%` → **0.637**（full compute 0.645）。⇒ **加速倍率越高，语义越不是「轻微下降」而是断崖**，且必须靠 guidance 项修复。

### 4.3 结果判读

- **判定 / 信息分栏的又一实例**：ImageReward、CLIP Score 判「通过」，OCR 判「内容被改写」。与 11-10 NotaryMark（TPR 100% ↔ BA 60.69%）同族，但这次是**生成过程**而非水印。
- **图像级安全分同样可疑**：若图审只读整图质量/语义代理量，缓存改写文本类风险会像本文一样被放过。
- **约束型指标第三次以上胜出**：`r=5%` 就拿到大部分收益（2.64× 时 0.464→0.586），继续加预算收益饱和 ⇒ 该按「误差份额」分配而不是「加更多预算」。

## 五、局限性

1. **只适用真 CFG**：GuideCache 需要分别评估条件与无条件分支，**不适用于 guidance-distilled 模型**；而线上为压 TTFT 常用蒸馏/少步模型，这条限制直接决定可落地范围。
2. **只查字符不查排版**：文本由 OCR reader 评分，「check the characters but not the typography」。
3. **没测风险语义**：实验对象是渲染文本正确性，不是 NSFW / 仇恨 / 政治风险。机制同构（guidance 项承载条件文本信息、缓存改写它），但**迁移到内容安全需要自己补一轮风险判定翻转率**，不能直接引用 word accuracy 当安全率。
4. **未报延迟**：只报 FLOPs 倍数，没有 TTFT / e2e / TPOT，无法直接对齐线上 SLO。
5. **未覆盖统一生成-编辑模型 / I2I 通路**：只测两个 T2I DiT；本项目 I2I 改写分流 0/0% 的链路缺口不能靠本文回答。
6. **验收装置自身**：Qwen3-VL judge 对方法排序与 OCR 一致度 τ=0.72 —— 说明 VLM-as-judge 能排方法，**但排不出幅度**；AB 看板仍需专门语义级量。

## 六、复现指南

### 6.1 论文复现

固定 Z-Image 6B / Qwen-Image 20B、1024²、50 步真 CFG；跑 FORA / TaylorSeer(1,2 阶) / ToCa / TeaCache / FasterCache；GuideCache 按 `r` 与 guidance share ρ 选 token、重算两分支；文本用 LongText-Bench 中英 320/160 条各 2 seeds，图像质量用 DrawBench 200 条；同时报 word accuracy、prompt fidelity、ImageReward、CLIP、FID、LPIPS 与 FLOPs 倍数。**必做的三条对照**：① 同等算力只减步数；② 只重算条件 / 只重算无条件 / 两分支都重算；③ 中英分栏。

### 6.2 本项目最小复现（零训练，半天～1 天）

**固定同一份改写后 prompt**（把输入改写这个变量钉死，沿用 11-24 A3 的约束），跑三臂：

| 臂 | 配置 | 必报 |
|---|---|---|
| ① | 全量生成（full compute，batch=1） | 图审风险判定 / 原子要件保留率（主体·属性·关系）/ word accuracy / e2e |
| ② | 线上加速配置（缓存 / 少步 / fp8-fp4） | 同左 4 项 + 配置指纹（缓存方法、步数、bit 宽、batch） |
| ③ | ② + 仅在 guidance 误差大的 token 重算两分支 | 同左 |

**判据**：① 与 ② 的图像级质量分差 <2% 而**原子要件保留率或风险判定翻转 >10 点** ⇒ 现有加速链路在做静默语义改写，**必须补语义级验收，且不得只报 TTFT/e2e 达标**；③ 显著优于 ② ⇒ 出图侧生成过程干预（不动输入、不动权重）是主修法，而非回退去加严输入改写。

**跨语言补充**：三臂各跑中 / 英 / 中英混合三档，**禁止只报聚合**；若英文档退化幅度显著高于中文，与 2B 改写模型英文 ASR 飙升合并归因（是输入侧语言覆盖问题，还是生成过程 guidance 项的语言敏感）。

**上线不劣化验收口径**：在 shadow / canary 每一档都要冻结「缓存方法 + 步数 + bit 宽 + batch + GPU 型号」指纹，报分语言安全率、分层宏平均 F1、逐样本判定翻转率、TTFT/e2e/超时率 —— 缺任一不可声称「量化/加速后不劣化」。
