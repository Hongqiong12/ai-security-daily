## 一、背景与问题

### 动机：bit-string 水印在"平均合谋"下会塌

图像指纹（image fingerprinting）给每个分发副本嵌一个用户专属水印，泄漏时可追责。核心威胁是 **averaging collusion**：多个接收者把各自带不同标记的副本做平均，把每个单独标记压掉。

离散 bit-string 水印尤其脆弱——**平均会把 bit evidence 推向模糊决策区**。论文的关键判断不是「信号变弱」，而是：

> 只要还用「逐 bit 比对」这个判定统计量，平均攻击就一定能把证据推到不可判；换统计量比加强嵌入更根本。

### 与本项目的关系

| 业务线 | 对应点 |
|---|---|
| 输出侧溯源（编辑后水印存活率） | photometric / geometric / averaging 三类变换下的 TPR |
| 内容安全分类的 **per-category threshold tuning / 误杀率 5.2% 硬约束** | **解析 per-key FPR 控制**（不是网格搜阈值） |
| coverage churn（覆盖率不变但判定集合在换） | Table 6：**TPR 0.992↔0.991 几乎不动，exact-set 0.974→0.624** |
| 图审 AB 双模型对比 | 配对设计：同一批带标记输出，只换 matcher |

## 二、核心方法

### 2.1 从 bit 匹配换成方向匹配

把每个用户 key 映射为**近正交的高维单位向量**（1024 维），用提取出的水印方向与 key 的**余弦相似度**判定归属。

理想情况下 $K$ 个用户做平均：

$$\text{归一化平均} \;\Rightarrow\; \text{每个合谋者保留约 } 1/\sqrt{K} \text{ 的余弦信号}$$

而无关 key 的相似度集中在 0 附近。⇒ 合谋人数增加时信号按 $1/\sqrt{K}$ 衰减（可预测），而不是 bit evidence 那样直接塌到模糊区。

### 2.2 shifted-Beta 零分布 → 解析 per-key FPR 控制

高维随机方向的球面几何给出余弦相似度的 **shifted-Beta 零分布**。论文：

1. 在**未加水印的图**上验证零模型是否成立；
2. 验证通过后，从零分布**解析地**算出阈值，实现 per-key false-positive-rate control；
3. 在含 $N$ 个注册 key 的部署里，给定家族级误报预算 $\alpha$ 做保守的 FWER 控制。

⇒ 这是本轮最值得搬到「类目阈值下发」的一点：**阈值不是从验证集网格搜出来的，而是从零分布的解析式算出来的，且先验证零模型是否成立**。对照 11-10「五种阈值规则代价 274→473.5」。

### 2.3 训练

神经水印 encoder + centered extractor，用 **JND masking**（恰可察觉差异掩蔽）约束可见性，配 **progressive curriculum** 依次覆盖 photometric → geometric → collusion 鲁棒性。

## 三、技术细节

| 项 | 设定 |
|---|---|
| 维度 | 1024 |
| 负载 | 100-bit payload（Table 3），ECC / OSD-0 软判决解码 |
| 数据集 | MS-COCO、OpenImages、AI-generated images |
| 基线 | SS-DCT/SS-DFT、TrustMark、ChunkySeal 等（**只比 post-hoc 水印，生成过程内嵌水印不在评测范围**） |
| 鲁棒性变换 | 光度（噪声 / 亮度 / 色彩偏移 / 降采样）、几何（翻转 / 旋转等）、平均合谋 |
| 主指标 | single-key TPR @ 固定 FPR；**strict all-colluder TPR**（一次试验需检出全部合谋者才算成功）；exact-set recovery；precision / recall / No-FA |
| 质量 | PSNR / LPIPS |

**评测口径的严格之处**：`strict all-colluder TPR` 要求「全部且仅全部」真合谋者被检出。一个方法可以在 single-key TPR 上满分，却在 strict all-colluder 上归零——这正是 11-10 记下的「判定与信息必须分栏报」的又一实例。

## 四、实验与结果

### 4.1 主表（Table 1，MS-COCO）

| 方法 | Dim | PSNR | LPIPS | Clean | Photo. | Geo. | K=2 | K=3 | K=4 |
|---|---|---|---|---|---|---|---|---|---|
| **VectorMark** | 1024 | **40.29** | **.041** | **1.00** | **1.00** | **.985** | **1.00** | **1.00** | **.996** |
| SS-DCT (Cox'97) | 1024 | 34.25 | .198 | — | — | — | — | — | — |

⇒ **质量更好（PSNR +6.04、LPIPS 降到 1/4.8）而合谋归因近乎满分**。离散 bit 基线在 single-key 检测上还有分，一旦要求 strict all-colluder 就归零。

### 4.2 注册规模与误杀预算（Table 4）

在大注册表 + 合谋设定下：**precision 0.999 / all-colluder TPR 0.990 / exact-set recovery 0.980**，经验 **FWER = 0.011**（名义 1% 预算）。

⇒ 这是本仓库少见的「**误杀率约束被实测验住**」的例子：不是报一个 FPR，而是报经验 FWER 与名义预算的差。可直接照搬到「误杀率 5.2% 硬约束」的看板口径。

### 4.3 最关键的一张表：只换打分规则（Table 6）

**同一批带标记输出，PSNR 完全相同（40.28），只换 matcher：**

| 方法 | Score | TPR | **exact-set** | PSNR |
|---|---|---|---|---|
| **VectorMark** | **Soft cosine** | **.992** | **.974** | 40.28 |
| VectorMark | Hard agreement | .991 | **.624** | 40.28 |
| ChunkySeal | Logit cosine | .949 | .441 | 44.70 |
| ChunkySeal | Hard agreement | .923 | **.002** | 44.70 |

**TPR 0.992 → 0.991（几乎不变），exact-set recovery 0.974 → 0.624（掉 35 点）**。ChunkySeal 更极端：0.441 → 0.002。

⇒ 这是 11-08「Coverage Hides Churn」之后**第二次、且给出配对对照的独立实测**：**只看 TPR/召回这类"率"，完全看不见判定集合被换掉**。对本项目直接的含义是：多版本回归看板不能只报误杀率/漏过率两个率，必须同时报「判定集合的 churn」。

### 4.4 消融与攻击

- 维度 / 合谋训练消融里，某项使 TPR 从 **0.234 → 0.650**；但更大 $K$ 时严格检出会**急剧下降**，说明 $1/\sqrt{K}$ 的衰减在高合谋人数下仍是硬边界。
- **scheme-adaptive subspace removal**（按 patch 估计残差方向并减去）是有效攻击；但更强的攻击在抹掉水印的同时明显损伤 PSNR（可见质量代价）——与 AnyBreak 的「绕过有成本」同构。
- Table 3 报 raw codeword sign accuracy / 单遍 ECC / 两遍盲 ECC 三列，**把"判定存在水印"与"读得出是哪位用户"分开报**。

## 五、局限性

1. **图像指纹 ≠ 生成侧水印**：这是分发副本的 post-hoc 标记，不是扩散采样过程内嵌的水印；论文明确把生成内嵌方法排除在评测范围。因此「编辑后水印存活率」的结论只能迁移到**输出侧后处理水印**，不能外推到生成器内嵌水印（后者见 TRACEMARK / NotaryMark）。
2. **零模型依赖未加水印图的验证**：shifted-Beta 解析阈值的前提是零分布在部署数据上成立；分布漂移后需重新验证，否则「解析控制」失效且不自知。
3. **平均合谋只是攻击面之一**：论文自己测了 subspace removal，未覆盖再生 / 重编码 / 截图 / 打印翻拍等链路。
4. **per-key 而非 per-category**：FPR 控制是按「用户 key」做的，直接搬到「业务类目」需处理类目间相关与重叠组（后者见本轮 2611.10472 Group-Conditional CRC）。
5. **不解决输入侧**：水印管"已经生成出去之后"的归因，对"这条 prompt 该不该改"没有任何管辖权。

## 六、复现指南

**论文复现**

1. 训练 encoder / centered extractor：JND masking + photometric→geometric→collusion 三阶段 curriculum。
2. 在**未加水印**图上验证 shifted-Beta 零模型，解析设定 per-key 阈值并配 FWER 预算。
3. 三类鲁棒性 + $K$ 用户平均合谋，报 single-key TPR / strict all-colluder TPR / exact-set / precision / recall / 经验 FWER。
4. **必做 Table 6 配对对照**：同一批输出，soft cosine vs hard agreement 两列并报。

**本项目迁移建议（零训练 / 半天到 1 天）**

| 动作 | 具体做法 | 判据 |
|---|---|---|
| **6 版本看板加 churn 列** | 除误杀率 / 漏过率外，报相邻版本的「判定集合 Jaccard / 撤销率 / 新增率」 | 率变化 <1 点但 Jaccard <0.8 ⇒ 是判定集合在换，不是模型变好 |
| **per-category 阈值改解析式** | 对每个叶子类目，先在确定的无害样本上验证分数零分布形态，再从分位数解析算阈值；与网格搜阈值并列报 | 两者 operating point 差 >10 点 ⇒ 现行网格阈值受验证集组成污染 |
| **把"检出"与"读得出"分栏** | 图审 AB 同时报「是否判违规」与「是否判对具体叶子类目」 | 前者高后者低 ⇒ 图审只在做二分类，L1–L4 等级输出未真正实现 |
| **输出侧水印补编辑后存活率** | 在 i2v/t2v 与 I2I 编辑落表后，对编辑前后各测一次 strict 检出 | 编辑后掉 >30 点 ⇒ 溯源链路需要在编辑后重嵌 |

### 附：对业务主线的三句话

1. **Table 6 是本轮最硬的一张表**：TPR 0.992→0.991 而 exact-set 0.974→0.624，证明「率不变、集合全变」在输出侧同样成立，多版本回归看板必须加 churn。
2. **阈值可以从零分布解析算出来并验住**（经验 FWER 0.011 vs 名义 1%），为「误杀率 5.2% 硬约束」提供了一条比网格搜更可审计的定法。
3. **判定与信息必须分栏**：strict all-colluder 归零而 single-key 满分，对应图审「判违规」与「判对叶子类目」是两件事，不能用同一个数交差。
