## 一、背景与问题

### 动机

"用奖励引导扩散采样"（reward guidance）是工业出图流水线里很常见的一层：不重训生成器，只在采样时沿着奖励模型的梯度走，把输出推向"更符合偏好"的方向（美观分、人像偏好、文本对齐分）。

它需要对**价值函数** $V(z_t, t) = \mathbb{E}[r(z_0) \mid z_t]$ 求梯度。两种主流估计：

| 方法 | 在哪读价值 | 记号 |
|---|---|---|
| **DPS** | 在**一步去噪估计**上读（$\hat z_0$） | $s = 0$ |
| **StitchVM** | 在**当前噪声态**上读（学习价值模型） | $s = t$ |

### 核心发现（本文最锋利的一句）

作者说：**这两种估计的误差，本质上是同一个东西——后验协方差，而它随"对干净样本的不确定性"增长，也就是随噪声升高而变大。**

因此二者**都在高噪声处最不准**——而高噪声处恰恰是**样本的粗结构（coarse structure）被决定的阶段**。

翻成业务语言：**奖励模型在最该判"这张图到底画了什么"的时刻，读数最不可信。** 而当噪声降下来、读数变准时，粗结构已经定了，改不动了。

### 为什么这篇对我们重要

我们的 RL 安全改写，奖励来自"改写后 prompt 生成的图与原 prompt 生成的图的一致性"（Qwen-Image 一脉的一致性评分）。这条奖励链有一个从未被审视的假设：**奖励读数在哪个表征层/哪个去噪阶段取，是无所谓的。**

VaLoP 说不是。它给了一个可检验的误差结构：误差 $\propto$ 后验协方差 $\propto$ 不确定性。而安全恰恰是**粗结构层面**的属性（姿态、构图、身体在画面里的位置与占比、是否出现某类对象）——**这些都在高噪声阶段定型**。

所以本文对我们的价值不是"又一种引导算法"，而是：**它给了我们一个判据，去问我们的奖励到底在估什么、在哪一步估、误差有多大。**

## 二、核心方法

### 一句话：把价值挪到"下一步"去读，再把梯度拉回来

既然误差随噪声升高而增大，那就**去一个噪声更小的状态读价值**——**向前看一个采样步**（$z_s$，$s < t$），在那里不确定性更小；然后把那个梯度**拉回**当前状态 $z_t$。

这就是 **Value Gradient Lookahead and Pullback（VaLoP）**。

### 关键的理论结构：两端是一族，中间多一项

把 $s$ 当连续参数看：
- $s = t$ → 退化成 StitchVM（在当前噪声态读）
- $s = 0$ → 退化成 DPS（在去噪估计读）
- **中间 $s$** → 需要一项额外修正，即**穿过生成器的修正项（correction through the generator）**

也就是说，DPS 和 StitchVM **不是两个对立的方法，而是同一族的两端**，而两端各自只在自己的理想情形下精确：
- $s = t$ 对**精确价值模型**精确；
- $s = 0$ 对**线性奖励 + 精确去噪器**精确。

**一般情形下两端都不是最优。** 这一句直接否掉了"选一个阵营"的做法。

### 工程落地：VaLoP 与 VaLoP-Fast

| 变体 | 修正项怎么算 | 成本 |
|---|---|---|
| **VaLoP** | 一次 vector-Jacobian product（VJP）穿过生成器 | 每步多一次生成器反传，**无需额外训练** |
| **VaLoP-Fast** | 一个小 head 摊销掉这个修正；**每个生成器训一个 head（用 HPSv2 价值训），所有奖励共用** | 只需一次价值模型反传（与 StitchVM 同级），**不需要生成器反传** |

VaLoP-Fast 的"一个 head 跨奖励复用"有一个干净的理由：head 学的是"从 $g_s$ 到 $\xi_t$"的映射，而这个映射**属于生成器**，不属于奖励——所以换奖励不用重训。

### 关键超参：$s = 0.6t$

作者实测：在 T2I 上，HPSv2 与 PickScore 的收益在 $s = 0.8t$ 到 $0.6t$ 之间达到峰值，向两端都下降。默认取 **$s = 0.6t$**，理由是平衡"$s$ 越小编界越紧"与"$s$ 越小第二项从 0 走向 DPS 误差"这两股力。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 生成器 | SD3.5-Medium、SD3.5-Large、FLUX.1-dev |
| 奖励 | HPSv2、CLIP、CLIP+MLP aesthetic predictor、PickScore、ImageReward |
| 图像 benchmark | DrawBench、GenEval（$1024^2$） |
| 机器人扩展 | SmolVLA on LIBERO、$\pi_{0.5}$ on RoboCasa（critic-guided） |
| 步长控制 | 幅度匹配（magnitude matching）：把每步位移归一化到与 StitchVM 梯度同范数，保证**同等步长下比较**，避免"多走了几步所以更好"的假增益 |
| 成本测量 | 单张 $1024^2$ 在 H100 上的耗时与峰值显存 |

**一个方法论细节值得记**：它做了幅度匹配——所有方法每步位移范数对齐到 StitchVM。**这是奖励类论文里最容易缺的一步**：不做幅度匹配，任何"更强引导"的方法都会因为实际走了更远而看起来更好。

## 四、实验与结果

- **主结论**：跨多个 T2I 模型与奖励，VaLoP / VaLoP-Fast 在**目标奖励**上稳定优于 DPS 与 StitchVM；VaLoP-Fast 的成本与"学习型价值引导"（StitchVM）相当。
- **一个反向证据值得注意**：基线在把目标奖励推高的同时，**牺牲了其他 held-out 指标**——在 aesthetic 与 CLIP 两个奖励下，除一项外**全部低于未引导模型**。即"奖励涨了，图整体变差了"。这正是奖励不完整时的典型症状。
- **修正项的贡献可分离**：T2I 上"相对 StitchVM 的 HPSv2 增益大部分来自那个 correction 项"（Tab. 4）——说明"向前看但拉回不做修正"（只导 $g_s$）是不够的，它忽略了 $z_s$ 怎么随 $z_t$ 变。
- **跨模态成立**：同样的 lookahead 在机器人策略上也成立，VaLoP-Fast 在 LIBERO / RoboCasa 上成功率最高。

**口径说明**：本文主表是分模型、分奖励、多指标的明细表，未给"单一平均提升百分点"这一口径；本精读不构造该数字。

## 五、局限性

1. **是采样期引导，不是策略优化**。我们是 RL 训练改写策略，奖励只用于打分，不参与每步采样梯度。**方法本身不能直接搬**，能搬的是"奖励在哪读"这一层洞察。
2. **单作者、无独立复现**。35 页、理论推导完整，但没有第三方验证，也没有与更近期的强基线对比。
3. **奖励仍是"给定"的**。全文假设奖励函数本身可信，只解决"怎么更准地估它的梯度"。**奖励定义错了（比如只测画质不测安全），这篇帮不上。**
4. **$s = 0.6t$ 是扫出来的超参**，不是推导出来的。换奖励/换生成器是否还成立，作者只给了趋势（Fig. 4），没给跨奖励的稳定性分析。
5. **安全场景完全未涉及**。所有奖励都是美观/偏好/对齐，没有一个是"是否合规"。

## 六、复现指南

### 可复现部分
- VaLoP（不用训）可直接实现：一步 lookahead 得到 $z_s$，在 $z_s$ 上算价值、求梯度、用一次 VJP 拉回 $z_t$。
- 成本测量脚本简单：单张 $1024^2$ 在 H100 上跑，对比 DPS / StitchVM / VaLoP / VaLoP-Fast 的耗时与峰值显存。

### 迁移到我们的奖励链（三件事，按性价比排）

**① 先做"奖励读取位置"的审计（半天，最关键）**

我们现在的一致性奖励是在**最终像素**上算的。VaLoP 的结论提示：这等价于在 $s = 0$ 附近读，而那里的读数**已经被高噪声阶段的粗结构决定**——也就是说，最终图像的一致性分数里，混入了大量"去噪过程本身的随机性"，而不是"改写是否保留了原意"。

做法：对同一对 `(原 prompt, 改写 prompt)`，**固定种子跑 20 次生成**，看一致性分数的方差。**判据**：若同 prompt 同种子的分数标准差 > 跨改写对的平均差，则奖励信噪比不足，任何 RL 都会学到噪声。

**② 把奖励从"终局读"改成"中途读 + 终局门控"（1–2 天）**

在去噪 60% 处（$s \approx 0.6t$ 的类比）附加一个**部分去噪潜变量的一致性读数**，作为主奖励；终局像素一致性只作为**门控**（保底，不参与梯度）。理由：粗结构（安全属性所在层）在中途已经定型，此时读数误差最小。

**③ 幅度匹配（规则级，半天）**

抄它的 magnitude matching：每次策略更新的 KL/位移量对齐到基线，否则"新奖励更好"可能只是"走得更远"。我们的 RL 若换了奖励函数，必须先做这一步再比。

### 不能迁移的部分（要说清）
VaLoP 解决的是"已知奖励、如何更准地估梯度"。我们的问题是"**奖励定义本身不完整**"（第十周反复出现的结论：奖励分不清画质与内容）。**前者是估计误差，后者是设定误差，VaLoP 对后者无效。**

---

**一句话判断**：这篇最值钱的不是算法，是一句可用的判据——**奖励的误差结构是后验协方差，在噪声最高、粗结构定型的阶段最大**。它提醒我们：一致性奖励读在终局像素上，读到的很可能不是"意图保真"，而是"去噪随机性"。
