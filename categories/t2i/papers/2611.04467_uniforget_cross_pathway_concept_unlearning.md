## 一、背景与问题

### 动机

统一多模态模型（UMM，如 BAGEL、Janus-Pro）把"生成图"和"看懂图"放进同一个权重。现有概念擦除方法全部是**单通路**的：

- **生成侧编辑器**（UCE、TIME 等）改的是生成分支，目标是"别画出这个概念"
- **理解侧编辑器**（GD、KL 等）改的是理解分支，目标是"别认出这个概念"

论文问的是一个很朴素、但此前没人系统测过的问题：

> 在一个统一模型上，**只擦一条通路，另一条通路会跟着忘吗？**

答案是不会，而且差距大到离谱。

### 三个先要说清的概念

| 概念 | 定义 | 为什么必须分开 |
|---|---|---|
| **联合遗忘（joint forgetting）** | 同一次修改后，**生成侧和目标识别侧同时**达到遗忘判据 | 单独看任一侧都会把"局部压制"误读成"已擦除" |
| **严格遗忘（strict forget）** | 遗忘的同时，输出仍是一张连贯、质量正常的图 / 一句有信息量的回答 | 把图退化成噪声也能"不画出目标"，但那是崩了不是忘了 |
| **邻近概念保留（neighbor preservation）** | 与目标**同类、外观或功能相近但身份不同**的概念必须仍能被生成与识别 | 擦"埃菲尔铁塔"不该把"东京塔"一起擦掉 |

第三条是最容易被跳过的：一般擦除论文只看"目标忘了没"和"FID 崩了没"，不看**同类邻居**。而实际业务里"擦 PORN 带崩 VULG"正是这一类问题。

### 核心问题

1. 单通路方法在统一模型上能达到多少联合遗忘？
2. 生成侧与理解侧的修改能不能在**一个 checkpoint 里协调**？
3. 联合遗忘要付多少能力代价？代价付在**目标**上还是**邻居**上？

## 二、核心方法

### （1）UUBench：一个把"忘了"拆成六格的诊断基准

30 个目标概念 × 三类（人物 / 地标 / 物体，每类 10 个），每个目标配 **2 个同类邻近概念**（如埃菲尔铁塔 ↔ 东京塔、黑池塔），共 60 个邻居、**720 张参考图**（每实体 3 张已见 + 邻居共 180 已见 / 300 留出）。

六个指标各自的分母是不同的**合格集**（这一点很关键，见第三节）：

| 指标 | 含义 | 通路 |
|---|---|---|
| **TF** Target Forget | 生成的目标图里不再出现目标身份 | 生成 |
| **SF** Strict Forget | TF 成立，**且**图连贯、质量合格 | 生成 |
| **NR** Neighbor Retention | 生成的邻居图里邻居身份仍在 | 生成 |
| **SR** Strict Neighbor Retention | NR 成立，**且**图连贯、质量合格 | 生成 |
| **TU** Target Utility | 对目标图的**非身份**提问回答正确（"这是什么颜色/材质"） | 理解 |
| **NU** Neighbor Utility | 对邻居图的非身份提问回答正确 | 理解 |

论文明确写了偏序：**SF ≤ TF、SR ≤ NR**。也就是说"严格"版本永远是"宽松"版本的下界 —— 任何只报 TF/NR 的表格都在系统性地高估自己。

### （2）UniForget：生成侧编辑 + 理解侧低秩更新

生成侧沿用已被验证的 TIME 风格编辑（外加 GD 式的组合），理解侧是一个 **LoRA 低秩更新**（论文明确写 "with understanding-side low-rank updates"），两者合成到一个 checkpoint。

理解侧的目标函数由三项组成（累计消融的顺序即论文推荐的堆叠顺序）：

1. **身份重定向 + 邻居保留**：目标提示词的状态被推向"类别泛称"的输出方向，邻居提示词的状态被钉在原始输出上。形式上是把 $K_p$（目标 + 邻居 + 类别泛称提示词的状态）与 $V_p = W K_p$（原始输出）配对，让目标答非身份、邻居答身份。
2. **成对偏好（Pairwise preference）**：目标图配**名字无关**的回答、邻居图配**带名字**的回答，构成 20 个模板的提示词库。
3. **Masked KL + Anti-collapse**：防退化，压制塌成一种回答。

生成侧的数据构造有三个消融项（Full / Last-token / Single-template / Neighbors-only），其中 **Neighbors-only**（只把邻居提示词当保留约束、丢掉类别泛称与其他非目标提示词）会让 NR 从 98.1% 掉到 90.4%（BAGEL）、从 92.9% 掉到 85.7%（Janus）。也就是说：**"别忘邻居"不够，还得有"泛称兜底"**。

## 三、技术细节

### 指标分母必须分开（这是这张表最值得学的地方）

论文对每个指标定义了各自的合格集：目标生成记录只在"目标集合格"上算，邻居生成记录只在"邻居集合格"上算，理解侧同理。**不共用分母**。这样做的好处是：一个方法不能靠"把某类样本整体判废"来虚报分数。

### 组合强度 ρ 的扫描

ρ 是理解侧更新的强度。默认选 0.4。扫到 0.6 时 BAGEL 的 DF 从 80.0% 上升；Janus 上把 1.0 提到 1.2 只把 DF 从 92.7% 抬到 **93.3%**，但 TU 从 **75.6% 塌到 55.0%**。这是一条典型的**收益饱和 + 代价继续涨**的曲线：0.2 的强度换来 0.6 点遗忘，代价是 20.6 点效用。

### 多概念扩展（最硬的一条失效边界）

单 checkpoint 承载的概念数 N ∈ {1, 5, 10, 20, 30}：

| 侧 | N=1 → N=30 | 备注 |
|---|---|---|
| 生成侧 | TF 全程 **100.0%** | 目标压制不随 N 衰减 |
| 生成侧 | NR 只剩单概念值的 **81.5%（BAGEL）／41.8%（Janus）** | 邻居被连带擦掉 |
| 生成侧 | GenEval 掉到 **39.2% / 32.7%** | 通用生成能力崩 |
| 理解侧 | DF **80.0% → 51.2%（BAGEL）／92.7% → 37.1%（Janus）** | 遗忘率随 N 崩塌 |
| 理解侧 | MMBench 几乎不动 | 通用理解不崩 |

**同一张表里，生成侧是"擦得掉但带崩邻居"，理解侧是"不带崩但擦不干净"。** 这是两种完全不同的失败形态，用一个总分看会互相掩盖。

| BAGEL-7B-MoT | Base | 0.0 | 0.0 | 100.0 | 100.0 | 0.0 | 21.6 | 96.7 | 83.0 | 0.0 | 0.0 |
| | UCE（生成侧） | 83.3 | 83.3 | 100.0 | 100.0 | 4.0 | 52.7 | 79.1 | 75.9 | **4.0** | 3.2 |

### 四条必须记住的读法

1. **生成侧编辑器"压制"很强、"遗忘"很弱。** TIME 在 BAGEL 上 TF 100.0，DF 只有 24.0 —— 模型不画了，但被问到时照样认得出。**"生成不出来了"和"不知道了"是两件事。**
2. **直接组合几乎不涨。** TIME+GD 在 BAGEL 上是 31.3，只比 TIME 单独 24.0 高 7.3 点；在 Janus 上是 41.3 vs 28.0。**把两条单通路方法拼起来，不等于联合遗忘。**
3. **UniForget 的收益主要来自理解侧，代价也主要落在它上面。** DF 从 31.3 抬到 80.0，但 TU 从 91.8 掉到 72.2 —— 掉了 19.6 点"目标图的非身份效用"。这是**"忘得太狠，把描述能力也一起忘了"**。
4. **严格指标会撕开宽松指标。** BAGEL 上 NR 98.1 看着漂亮，SR 只有 84.6；Janus 上 NR 92.9、SR 73.2。**每五个被保住的邻居里有一个是"保住了但图糊了"。**

### 通用能力的代价

| 项 | BAGEL | Janus |
|---|---|---|
| GenEval | 72.7 → **63.4** | 78.9 → **70.1** |
| DPG-Bench | 83.4 → 79.9 | 83.1 → **74.2** |
| 某理解项 | 85.5 → **77.7** | 35.0 → 34.6（基本不动） |

论文自己的判断是：**生成能力在跨通路擦除中更脆弱**。

## 五、局限性

1. **只测了两个骨干（BAGEL-7B-MoT、Janus-Pro-7B）**，都是 7B 量级。更大模型或非 MoT 架构的结论未验证。
2. **30 个目标概念全是"有专名的实体"**（人物、地标、物体）。**风险概念（NSFW、暴力）没有专名**，无法直接套用这套"目标 / 邻居"结构 —— 这是它对我们最大的不可迁移处。
3. **多概念扩展下理解侧崩塌得很早**（N=30 时 37.1%），论文没有给出可行的补救，只标注为 "remain challenging"。
4. **对抗鲁棒性只在附录给了 prompt 攻击与图像扰动**（Table 12/13），主文没有正面讨论"擦除后能不能被提示词打回来"。
5. **UUBench 的 720 张参考图规模很小**，30 目标 × 3 张已见图，邻居的留出图更少。统计功效有限。
6. **"遗忘"的判据依赖自动判定器**（身份识别 + 非身份问答），判定器本身的误差没有做敏感性分析。

## 六、复现指南

### 环境
- BAGEL-7B-MoT、Janus-Pro-7B 权重
- 生成侧：TIME 风格编辑；理解侧：LoRA 低秩更新
- UUBench 数据：30 目标 + 60 邻居 + 720 图；目标/邻居/泛称提示词三套

### 最小复现路径
1. **先造"六格表"而不是"一个分"**：TF/SF/NR/SR/TU/NU 各自的分母分开。**这一步不需要任何训练**，只要把你的现有评测按这六格重算一遍，就能知道自己过去高估了多少。
2. **跑 base 与"单通路"两组**，确认在你自己的模型上"生成侧强压制 / 弱遗忘"的现象是否成立。这是整篇的前提。
3. **再加理解侧低秩更新**，按 身份重定向 → 成对偏好 → Masked KL → Anti-collapse 的顺序累加，每一步记录 DF/TU/Collapse 三个数。
4. **最后做 N 扫描**（1/5/10/20/30），这是决定"能不能上生产"的那张图。

### 关键超参
- 组合强度 ρ 默认 **0.4**；扫 0.4 / 0.6 / 1.0 / 1.2
- 理解侧偏好模板库 **20 个模板**
- 生成侧消融必须包含 **Neighbors-only**（缺它 NR 会掉 7.7–7.2 点）

### 迁移到我们业务的注意事项
- **不要照搬"目标/邻居"到风险类目**：PORN 没有专名，它的"邻居"是 VULG 的暗示档，不是同义实体。可迁移的是**六格记账法**，不是具体的数据构造。
- **不要用 DF 当单一验收指标**：Janus 上 DF 92.7 而 SR 73.2、TU 75.6，三个数指向三种不同的"擦坏了"。
- **要抄的那一条**：`SF ≤ TF`、`SR ≤ NR` 的偏序 —— 任何"宽松指标"都必须同时报它对应的"严格指标"。

## 附：权重侧 vs 输入侧的边界（本轮第三块拼图）

| 事实 | 出处 | 含义 |
|---|---|---|
| 生成侧擦除 TF 100% 但 DF 24–31% | 本文主表 | **"画不出来"不等于"不知道"**，权重侧擦除的可验证范围比宣称的窄 |
| N=1 → 30，理解侧 DF 92.7% → 37.1% | 本文 6.3 | 权重侧擦除**随概念数线性崩塌**，不可线性扩展 |
| 生成侧擦除把邻居 NR 连带打到 41.8% | 本文 6.3 | 权重侧**没有"只擦这个不擦那个"的精度** |
| 输入侧改写可以在**运行时**逐条决策、逐条回滚 | —（业务事实） | 权重侧做不到"这条改写、那条放行" |
| 权重侧一次改完，对所有后续请求生效 | —（业务事实） | 输入侧做不到"全局一致"，只做到"逐次一致" |

**结论：两者不是替代关系，是不同的失效边界。** 擦除管"模型根本不该会"，改写管"模型会但这次不该用"。而这轮的三个数字说明：擦除连"根本不该会"这一半都没做到 —— 它做到的是"这次画不出来"。
