## 一、背景与问题

### 动机

AIG-NCII（AI-generated non-consensual intimate imagery）和 AIG-SC（AI 生成的性内容）不是同一件事。区分的轴只有一根：**是否描绘了一个真实人物的身份，且未经同意**。

论文要回答的不是"NCII 怎么生成"——那已经在别处被研究过。它问的是一个更麻烦的问题：

> **一个只做"合法的性内容"的社区，其共享的技术资源，是怎么被复用到"性暴力"上的？**

方法是定性内容分析：抓 **139 篇 CivitAI 上的 R+ 级指南**（guides，即"how-to"长文），编码其工作流架构、概念引入方式、以及对伦理边界的讨论。

### 我们为什么必须看这篇

**这是本轮 319 篇候选里唯一一篇直接讨论 NSFW 的论文。** 全池扫描 `NSFW|nude|porn|sexual|obscene|vulgar|intimate`，只命中这一篇。

而它给出的结论，正好落在我们最疼的地方——**PORN / VULG 边界混淆，以及 `VULG-HINT-EDGE` 这个"最差类别"**。

它说的事情可以一句话概括：

> **这类风险不是一个部件（某个词、某个 LoRA、某个工具），而是一组配置（性内容概念 × 身份概念 × 参数）。**
>
> 所以任何"找部件"的检测方式——关键词黑名单、按名字查、按工具查——在结构上就漏。

这句话如果成立，那我们在做的是：**用一个找部件的分类器，去判一个由配置构成的风险。** 这解释了为什么"调阈值 / 调 alpha / 补同类数据"三个动作全部无效。

### 核心问题

1. NCII 相关目标在 AIG-SC 指南里以什么形式出现？（RQ1）
2. AIG-SC 工作流的架构是什么，性概念（S）与身份概念（I）分别怎么被引入？（RQ2）
3. 指南怎么讨论"引入 NCII 使能概念"这件事的治理与伦理？（RQ3）

## 二、核心方法

### （1）分析单位：工作流（workflow），不是工具

论文的方法论立场很明确，而且值得抄：

> *"models or applications must be evaluated for AIG-NCII abusability in the workflows in which they will reasonably be used, not evaluating a base model 'in a vacuum'."*

这个立场的依据来自安全工程的既有经验：**全系统（workflow）评测比单点评测覆盖更全**——就像隐私侧信道和软件 fuzz 都要在真实系统上跑。

对应到我们：**我们的输入侧审核评的是"一句 prompt"，而不是"一次生成请求在工作流里的位置"。** 用户可以通过多轮对话、参考图、历史上下文把配置逐步搭起来，而每一轮的 prompt 单独看都干净。这是同一个方法论错误。

### （2）两个概念轴：S 与 I

论文把 NCII 的构成拆成两个正交的概念集：

- **S（sexual）**：性内容概念——解剖术语、行为描述、风格标签、模型/adapter 选择。
- **I（identity）**：身份概念——真实人物、可辨识特征、以及"如何在不点名的情况下指定一个人"。

然后按**基础工作流 / 高级工作流**两条路径，逐个组件标出 S 与 I 是怎么被塞进去的。

### （3）身份概念的引入方式（这是全文最实用的部分）

论文编码出几条 I 的引入路径，其中两条对我们直接有用：

**I1：用解剖词汇绕过"性"的模糊性。**
指南里直接教怎么写身体部位——原文举例：*"terms like 'labia majora', 'labia minora', 'clitoral hood', 'vulva', 'erect penis' and 'vagina' provide clear guidance"*。

这一条的含义是：**精确的医学/解剖术语是"高保真"提示词，不是"高风险"提示词**。我们的词表如果按"露骨程度"打标签，会把医学语境和滥用语境打成一类——这正是 PORN 过度预测的一个来源。

**I2：likeness prompting ——不点名地指定一个人。**

这是论文命名的技术，也是最该被我们记住的一条。指南教的原文：

> *"refer to the movie/series name and the fictional character's name … without using their [real] name, so they AI wont use their exact image, but at least get its inspiraration by the attriutes"*

> *"the long standing rule to not use [the name of real public identities] for any NSFW content"*

**用一个虚构角色的名字 + 作品名 + 属性描述，去逼近一个真实人物的长相。** 名字层面完全合规，语义层面完全指向真人。

论文对现有防御的判决很直接：

> *"we identify an evasion technique, which we term likeness prompting, whereby attackers generate text prompts describing sexualized, identifiable personas such that they could be fed to a model to generate AIG-NCII **while evading input/output filters that may only detect the use of a specific individual's name** or the upload of content depicting that individual."*

**"只检测特定名字"的过滤器，被"描述属性"绕开。** 这不是精度问题，是**检测对象的类别错了**：过滤器在查"符号"，风险在"指称"。

**I3：把"人"换成"角色"。** 论文记录：用户 *"intentionally modify their word choices to evade detection, such as using the word 'character' in place of 'person'"*。

### （4）可信度方法：八轮 IRR 直到收敛

编码可信度的做法值得记：每一轮随机抽 **15 篇**指南，两名编码员独立编码，对每个 code 算 **Cohen's κ**；不一致的讨论解决、必要时改 codebook；**若某 code 没达到高一致性，再抽 15 篇重复**。**八轮**后所有 code 达到高一致性。期间改过的 code 在**全量数据上重编**。

这是一个可直接抄的标注质控流程：**小批量、多轮、以 κ 为停止条件、codebook 可改、改后全量重编。**

## 三、技术细节

### 数据与规模

| 项目 | 数值 |
|---|---|
| 分析对象 | CivitAI **R+ 级指南 139 篇** |
| 平台特性 | CivitAI 被公认承载了不成比例的性内容，是 AIG-SC 社区的资源枢纽 |
| 编码一致性 | 8 轮 IRR，每轮 15 篇，Cohen's κ，最终全部 code 达高一致性 |
| 明确讨论 NCII 流程的指南 | **1 篇** |
| 编码体系 | S 轴（性概念）+ I 轴（身份概念）+ 治理/伦理讨论 |

### 两条工作流路径

**基础工作流**：文生图 + 提示词（可能加负向提示词）→ 出图。这条路径的 NCII 能力靠**纯提示词配置**达成。

**高级工作流**：改基座（换 checkpoint）→ 训 adapter（LoRA）→ 多步流程（图生图、inpaint、参考图绑定）。这条路径靠**组件组合**达成。

**关键结论：NCII 不是"一个被禁的工具"，而是"一组配置选择"。** 原文：

> *"AIG-NCII is not enabled by novel technology that can be independently regulated, but by a set of configuration choices (e.g., models, model adapters, inputs) that creators make when setting up otherwise innocuous generation or training workflows."*

### 现有防御为什么失效（三条，逐条对应我们的组件）

| 失效原因 | 论文依据 | 对应我们的哪个组件 |
|---|---|---|
| **名字检测被属性描述绕过** | likeness prompting | 黑名单 / 实体匹配 |
| **开源权重一旦发布无法收回** | 工作流主要依赖 open-weight 及微调衍生版 | —（外部环境） |
| **LoRA 可低成本把被刻意移除的概念装回去** | 低成本训练技术使超定制模型可本地训 | 概念擦除（权重侧） |

第三条直接命中权重侧防御的边界：**擦除把概念从基座里移掉了，但 LoRA 能把它装回来，且在本地。** 这不是"擦除做得不够好"，是"擦除的治理范围止于权重发布"。

### 一个操作层的实测（顺带很有说服力）

研究团队在抓取过程中向平台/NCMEC 报告了：

- **2 篇**疑似 AIG-CSAM → NCMEC
- **1 篇**鼓励生产 NCII（本身不含 NCII）→ CivitAI
- **4 篇**含真实身份（非私密）描绘 → CivitAI

**三周后，7 篇里只有 1 篇被移除。**

这个数字不是重点，重点是它说明的机制：**内容侧处置的时延，往往远大于生成侧的时延。** 对应我们线上：一旦漏过一张图，处置窗口是以天计的，不是以秒计的。所以"输出侧图审漏过率 3.42%"这个约束的真实成本，比它看起来大。

## 四、实验与结果

这是一篇定性研究，没有 benchmark 式的表。它的"结果"是四个结论，我按对我们有用程度排序。

### 结论一：NCII = S 概念 × I 概念 的**组合**，不是某个部件

> *"the two composable pieces of NCII are sexual concepts and identity concepts."*

论文甚至用了一个很准的类比：**枪支管制**——"组成一把枪的零件，在什么时刻具备了产生伤害的能力？"

**对我们的直接含义**：`VULG-HINT-EDGE` 这类"暗示性边缘"样本，本质上就是 S 轴中等 + I 轴缺失/模糊的组合。它不是"标错了"，而是**在一个按部件分类的类目体系里，它没有对应的格子**。

这与我们 11-02 的结论完全一致（"它在这个类目体系里没有定义"），但这篇给出了原因：**类目体系是"部件清单"，而风险是"配置空间"。**

### 结论二：现有输入/输出过滤器在结构上失效，不是精度不足

> *"even though foundation model providers attempt to curb abuse by adding defenses, like input/output filtering, these are largely ineffective."*

理由不是"过滤得不够准"，而是**过滤在查符号，攻击在指称**。

**对我们的直接含义**：任何以"关键词命中"为主要特征的 PORN 判定，都会在"属性描述型"输入上系统性漏过。而这类输入在我们的漏过率（3.42%）里占多少，目前**没有测过**。

### 结论三：治理只能加"摩擦"，不能禁"部件"

论文明确：*"There is no single or set of components that can be outright banned."* 它建议的方向是加摩擦（friction），并把监管问题准确描述为：**「一个工作流是从哪一刻起"演化"成了 NCII 工作流」**。

**对我们的直接含义**：这解释了为什么"分级处置"比"一刀切拒绝"更符合现实——**因为边界本身是渐变的，一刀切必然要么误杀要么漏过。**

### 结论四：法律/合规侧正在往"身份"这个轴上压

论文提到 EU 要求开发者主动测试"reasonably foreseeable misuse"，以及丹麦提出"个人对其生成的形象拥有版权"的立法设想。

**对我们的直接含义**：**监管重心在往 I 轴（身份）移动，而我们的类目重心在 S 轴（性内容）。** 这是个方向性风险——如果只盯 S 轴，会在 I 轴上留下整片空白。

### 数量的诚实说明

论文只找到 **1 篇**明确描述 NCII 流程的指南（139 篇里）。它自己反复声明：**不知道这些指南被 NCII 施加者实际使用的程度**。这是一个定性威胁建模，不是流行度测量。引用时不能把它说成"NCII 已经普遍通过 X 方式实现"。

## 五、局限性

### 论文自述的

1. **单平台**（CivitAI），且该平台本身已被清理过一轮；残留内容可能不代表全生态。
2. **只分析公开指南**，看不到私域/邀请制社区。
3. **无法测使用率**——指南存在 ≠ 被使用。
4. **编码是人工的**，虽然有 8 轮 IRR，但仍是小样本定性。
5. **伦理限制导致数据获取有偏**：团队主动避免系统性反向搜图（隐私顾虑），靠研究者既有知识判断，这会漏掉不常见的身份类型。

### 我们解读时必须守住的边界

**① 它是"输入侧威胁建模"，不是"检测方法"。** 它告诉你风险怎么构成，不告诉你模型怎么训。把它当成"方法论文"会失望；当成"类目定义论文"才有价值。

**② 它的结论不能反推"所有 VULG 都是 NCII"。** NCII 的核心是**身份 + 未经同意**。我们的 VULG 大部分与身份无关（粗俗、侮辱、低俗暗示）。**两轴框架可以借用，但 I 轴的权重不能直接照搬。**

**③ 它的"过滤失效"结论针对的是"只查名字"的过滤器。** 我们的分类器不是纯黑名单，是训过的模型。所以它的判决对我们**部分**成立：**在"属性描述型绕过"这一类输入上成立，在"显式露骨"这一类上不成立。**

## 六、复现指南

### 不 replicate 论文，而是 replicate 它的**分析框架**

这篇不需要"复现"。它值得复现的是那张**两轴分解表**，用在我们的类目体系上。

**步骤：**

1. **抽 300 条 VULG-HINT-EDGE + PORN 边界样本**（各 150）。
2. **给每条打两个独立的分**（不要打成一个"风险分"）：
   - **S 轴**：性内容强度（0 无 / 1 暗示 / 2 明确描述 / 3 露骨）
   - **I 轴**：身份指向（0 无 / 1 泛化人设 / 2 可辨识属性组合 / 3 指名真实人物）
3. **画 2×4 的格子，填样本数**。
4. **看分布形状**，按下面的判据决定路线：

| 观察 | 推论 | 动作 |
|---|---|---|
| 样本集中在 **S≥2 且 I=0** | 这些是"纯性内容"，与 NCII 无关 | 不应按 NCII 处置；检查是否被 PORN 过度预测 |
| 样本集中在 **S=1 且 I≥2** | 这些是"性暗示 × 身份指向" = 真 NCII 型 | **当前类目体系里没有这一格** → 建议新增类目而非调阈值 |
| 样本在 S 轴上均匀、I 轴几乎全 0 | `VULG-HINT-EDGE` 的问题在 S 轴的中段判据 | 需要 S 轴的分段定义（对应 FVH-Bench 的条件分解） |
| S 与 I 都低但仍被判 VULG | **过度预测**，是误杀源 | 直接进误杀复核队列 |

5. **额外做一件事：测"属性描述型绕过"**。抽 50 条含真实/虚构人物指向的样本，把"名字"替换成"作品名 + 角色名 + 属性描述"（即 likeness prompting），重跑分类器，看判定变化率。

   - 判据：**变化率 > 20% ⇒ 我们的分类器在查符号不在查指称**，这是结构性漏洞，阈值调不动。

### 实现坑

| 坑 | 处理 |
|---|---|
| 把 S 和 I 合成一个分 | 就回到了"部件清单"思维，白做 |
| I 轴只看"有没有人名" | 那正好是论文说会被绕过的口径；要看"属性组合是否唯一指向" |
| 用 NCII 结论直接改 VULG 定义 | VULG 大部分与身份无关，会引入新误杀 |
| 把 139 篇的定性结论说成流行度 | 只有 1 篇明确描述流程；论文自己反复声明 |
| 忽略处置时延 | 报告 7 篇三周删 1 篇；漏过的真实成本远大于漏过率本身 |

### 一句话带走

**把风险从"一张词表"改写成"一组坐标（S, I）"，然后去数格子里有多少样本——这一步不需要训任何模型，但它能立刻告出我们类目体系的空洞在哪。**
