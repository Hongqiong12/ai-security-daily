## 一、背景与问题

### 动机：仇恨表达绕过了「主体必须是人」这个隐含前提

用拟人化非人角色指代特定人群是有历史脉络的仇恨表达（纳粹宣传把犹太人画成鼠/章鱼，到近期社媒上的 AI 生成图）。现有仇恨图像检测器几乎都建立在**以人为中心**的线索上，于是当主体是猫、兔、狐、猪、LABUBU 时，检测器会把仇恨图判成良性。作者做第一份系统研究，同时审计**生成侧**（模型会不会画）与**检测侧**（画出来拦不拦得住）。

### 与本仓库主线的关系

这是本轮**最直接命中「输入改写有效性上界 + 出图侧内生风险」归因的一篇**：

- 源场景经**保守人工筛查**（两名标注员独立接受才保留），即输入侧已相当"干净"；但生成系统仍对 **92.1%** 的计划查询出图，其中 **95.9%** 含仇恨内容 ⇒ **改写后文本无害 ≠ 出图侧无害**，与本项目「3,000 条改写后仍被色情 400 打击 case 中约 2,700+ 条源于出图侧内生风险」同构，是公开文献里第一次给出跨三通路的量化对照。
- 三条生成通路（T2I / **image editing** / 多轮会话）在同一份场景上并行评测，正好对应「统一生成-编辑模型下同一份改写 Prompt 同时作用于生成与编辑两条通路」的改写面。
- 检测器微调用了 **SFT + GRPO**，奖励四分项（正确性 0.7 / 格式 0.1 / checklist 覆盖 0.1 / 目标群体识别 0.1），与本项目 RL 改写线的奖励设计可成对比较。
- **口径纪律**：论文明确写 `1−G/Q` 是 non-generation，**包含被跳过的多轮查询，不能解释为模型拒答率**——直接可用于本项目「假安全拒答体感」与 over-refusal 归因。

## 二、核心方法

### 2.1 三通路 × 五角色 × 八模型的析因设计

| 项 | 设定 |
|---|---|
| 角色类型 | 5 种（Cat / Rabbit / Fox / Pig / LABUBU） |
| 生成任务 | 3 类：**T2I**、**Edit（图像编辑）**、**MT（多轮会话式生成）** |
| 计划查询 | **14,250**（12,900 次生成尝试 + MT 预留 2,700 查询） |
| 运行 | 3 次；T2I `350×8×3=8,400`，Edit `150×7×3=3,150`，MT `150×3×3=1,350` |
| 源场景 | 保守筛查：两名标注员**独立接受**才保留；跨模型/角色/任务复用同一批场景 |
| 仇恨定义 | 采用 Anthropic 的 hateful-content 定义 |
| 检出指标 | AnthroHate-Image **4,370** 张仇恨图；另建 held-out 测试集 **3,495 仇恨 + 3,650 良性** |

**MT 是逐轮汇总而非只看终局图**，这点与本项目「图文联合状态 / 完整消息」验收同源：多轮里每一轮的图都算暴露。

### 2.2 三条修复路线（成本递增）

1. **Prompt Enhancement（零训练）**：在 system prompt 里补写「仇恨内容可能如何出现」，并要求模型**分步骤推理：如果把非人角色换成人，这个场景是否算仇恨**。这是把「主体类型」这一捷径从判定条件里显式拆掉。
2. **Depiction Reversal（training-free 管线）**：分类前先把非人角色映射回人类表征，三次模型调用，F1 **0.962**。
3. **微调检测器**：LoRA rank 32、lr 2×10⁻⁵、3 epoch SFT（结构化推理轨迹：描述图 → 把非人描绘替换为人 → 判断），再 **GRPO 2 epoch / 8 rollouts / lr 1×10⁻⁵**，单次调用完成，F1 **0.979**。

## 三、技术细节

### 3.1 生成侧：连最强商业模型也几乎不设防

- **92.1%** 计划查询出图、**95.9%** 含仇恨内容。
- **GPT Image 2** 在 T2I / Edit / MT 三通路分别产出 **66.6% / 68.0% / 75.3%** 的仇恨输出 ⇒ **多轮会话通路最弱**，且三通路差异本身就是「同一份策略不能跨通路共用」的证据。
- 论文把 `1−G/Q` 定义为 non-generation 并**明确拒绝**把它当拒答率（含跳过的 MT 查询、无法归因到安全过滤）。这一条对本项目的误杀率口径尤其重要：**"没出图"不等于"被拒"**。

### 3.2 检测侧：五个检测器全线失守（Table 2/3，召回 %）

| 检测器 | T2I | Edit | MT | Overall |
|---|---|---|---|---|
| **GPT-5.5** | 70.6 | 76.6 | 82.1 | **73.9** |
| Gemini 3.1 Flash | 62.7 | 72.9 | 78.5 | 67.7 |
| Q16 | 50.9 | 65.8 | 67.4 | 57.0 |
| Claude Haiku 4.5 | 36.4 | 48.3 | 56.4 | 42.5 |
| LlavaGuard v1.2 7B | 19.3 | 37.5 | 46.6 | **28.0** |

按角色拆分 GPT-5.5：Cat 72.7 / Rabbit 75.1 / Fox 69.3 / Pig 74.2 / LABUBU 78.1。⇒ **最强的检测器也漏掉约四分之一**，多数检测器不足 58%。作者归因于**依赖以人为中心的线索**：当主体是非人角色，检测器把它判为良性。这是与 27339 同族的「单模态/单属性捷径」，只不过捷径换成了主体类别。

### 3.3 修复结果（Table 4，held-out 3,495 + 3,650）

- Baseline 最强 GPT-5.5：recall **0.761** / F1 **0.864**；LlavaGuard v1.2 **0.288 / 0.447**。
- **Prompt Enhancement**：四个 VLM 检测器召回全部提升，LlavaGuard **28.8% → 64.4%（+35.6 点）**；Gemini 3.1 Flash 达 0.814 / 0.897。**零训练、零权重改动**，只改判定 prompt 里的推理结构。
- Depiction Reversal F1 **0.962**；微调检测器 F1 **0.979**，跨角色召回 **96.6%–98.2%**；**LABUBU 完全不进微调训练**，仍达 **96.6%** ⇒ 学到的不是角色词表，而是「换成人类语境后是否构成仇恨」这个可迁移判据。

### 3.4 标注分歧口径

13,124 张图上初始分歧 **521** 张，多数投票后判 **345 仇恨 / 176 非仇恨**；分歧集中在**颜色选择、非人角色穿着等暗示性线索**，而绞索、奴隶市场背景等显式仇恨道具几乎不产生分歧。⇒ **PORN/VULG 边界类问题的分歧是「暗示强度」而非「是否出现」，与本项目 `VULG-HINT-EDGE` 的第五种解释（定义层 / 承诺形式）一致。**

## 四、实验与结果

| 观察 | 数 |
|---|---|
| 计划查询 / 生成尝试 | **14,250 / 12,900** |
| 出图率 / 出图中含仇恨 | **92.1% / 95.9%** |
| GPT Image 2 三通路仇恨产出 | **66.6% / 68.0% / 75.3%** |
| 仇恨图数据集 | **4,370** 张 |
| 最强检测器召回 | **73.9%**（GPT-5.5）；多数 **<58%**；最差 **28.0%** |
| 零训练 Prompt Enhancement | LlavaGuard **28.8%→64.4%** |
| 两条修复 F1 | **0.962 / 0.979** |
| 未见角色泛化 | LABUBU **96.6%** |
| 标注分歧 | **521 / 13,124**，判仇恨 345 |

**最该抄进方案的一句**：作者没有把「提高检测器能力」当主结论，而是指出**判定条件被主体类别这个代理量带偏**；最便宜的修复是**在判定 prompt 里显式要求把非人主体反事实还原成人再判**（零训练拿 +35.6 点）。

## 五、局限性

1. benchmark 聚焦**清晰可解释**的仇恨场景（严格定义 + 保守人工筛查），作者自承「诊断性证据」，**不代表线上真实分布**；真实场景的多样性、暗示性表达未覆盖。
2. 同一批源场景**跨模型/角色/任务复用**，为一致性牺牲了独立性；仇恨定义沿用 Anthropic 口径，未做跨文化/跨地区对照（对照 CuRSE-Bench 的 English-only 局限）。
3. **未覆盖中英混合 / 非中文 prompt**，未测 DSC 式承诺分散语用形态；只测仇恨类，未测 PORN/VULG 边界与政治 L2_30 层级。
4. 是**系统级黑盒审计**：拆不开输入过滤 / 生成过程 / 输出复审各占多少，因此「92.1% 出图」不能直接读成「输入侧改写无效」——但与本项目 2,700+ 条 case 归因方向一致。
5. 检测器微调的 GRPO 奖励是人工设计的四分项，**未做 reward hacking 对照**（未验证「不改/照抄」能否拿高分），迁移到改写奖励前必须补 G7 式前置面板。
6. 未测编辑后水印存活率与跨版本风险漂移；未报推理延迟、TTFT 与量化后分层 F1。

## 六、复现指南

**零训练第一优先（半天）**：拿本项目图审 AB 的边界样本（尤其 `VULG-HINT-EDGE` 与 PORN 混淆类），在判定 prompt 里加一条**反事实还原指令**——「若把主体替换为人类/显式语境，是否仍构成风险」，跑同一批样本量判定翻转率与误杀率变化。判据：召回显著升而误杀不升（**双约束 5.2% / 3.42%**）⇒ 现有图审在读主体类别而非语义，属定义层问题，**改类目定义无效**。

**三通路对照（1 天，零训练）**：固定一份改写后 prompt，分别走 T2I / I2I 编辑 / 多轮生成，报三通路的风险判定差与原子要件保留率差。判据：差 **>15 点** ⇒ 不能共用一份改写，必须按通路分流下发（对齐统一生成-编辑模型的改写面与 I2I 0/0% 归因）。

**输出侧归因实验（对应 3,000 条 case）**：把「改写后文本无害但被图审打击」的样本按本文口径拆三栏——① 文本复核仍有害 ② 文本无害、图审判定有害（主体/场景代理量）③ 文本无害、图审放行但人工双盲判有害。**不再加严输入改写**，把重心放到 ②③ 的出图侧判定与生成过程干预。

**奖励面板（RL 线）**：把 GRPO 四分项与本项目安全率主奖励并排，补 `原样 / 微改 / 真改写` 三版对照与平均改动字符数监控；判据：原样一致性分显著高于真改写 ⇒ 奖励可作弊，先停训练。

**依赖与口径**：召回/F1 必须在**同一份 held-out 平衡集**上算；多轮任务按逐轮输出汇总；`non-generation` 不得写成拒答率；跨角色泛化必须留**完全未见过的角色**做留出（本文用 LABUBU）。
