## 一、背景与问题

### 动机：加速用的「单一跳过阈值」，等价于对整张图下一次判定

免训练的图像编辑加速器（ToMeSD / ToCa / RAS / RegionE / TeaCache / TaylorSeer / SpotEdit 等）普遍做法是：**token 的预测不再变化就冻结它**。问题在于，一条指令常常要求**多个编辑**——「把左边红椅换成灰色办公椅、自行车换成摩托、绿沙发换成蓝色布艺扶手椅……」。放沙发会让大量 token 大幅移动，而给小杯子改色只让少量 token 轻微移动。**一个为速度调过的全局阈值，会先冻结那些「慢而细」的编辑，于是用户要求的小改动直接消失**（论文 Fig.1 红框）。

作者把这件事从经验观察提升为**定理**：任何 part-agnostic（不看指令部件）的冻结规则，都无法保证每个部件的误差预算（Theorem 1/2）。

### 与本仓库主线的关系（四重命中）

1. **I2I 指令式图像编辑的安全改写 / 编辑指令语义保真**：本仓库连续 19 周记录「I2I 编辑改写零供给、改写分流命中 0/0%」。本篇给出一个直接可迁移的机制：**按整体下一次判定（全局阈值）会结构性漏掉最细微的编辑部件** —— 与本项目「误杀是硬约束、改写强度应尽量下沉而非直接拒答」的线上取向完全同构。
2. **per-category threshold tuning / 分级处置策略**：TIDE 的「每个指令部件自己的 compute budget」是「按类目各自阈值」在生成过程层的对应物。Theorem 2 证明「看不到部件的规则无法保证异构预算」⇒ **分级不是调参偏好，是数学必要**。
3. **改写强度分级下沉的量化对照**：单一全局阈值在 **89% 的 MICE-Bench 图像**上破坏至少一个编辑的预算；改 per-part 后少丢 **48%（MICE-Bench）/ 最高 77%** 的编辑，且速度不降反升（2.09× → 2.20×）。⇒ 「分档不会更慢」有了实测。
4. **推理加速不劣化验收 / 出图侧生成过程干预**：与 11-25 GuideCache（缓存经 CFG guidance 静默改写文本）同族，但干预对象是**编辑部件**而非文本 token；且不动输入、不动权重、免训练，正是用户方向 (2) 要的第二条降风险通路。

## 二、核心方法

### 2.1 TIDE（Training-free Instruction-aware Drift-based Editing）三阶段

1. **Regions（部件定位）**：前 $s$ 步密集计算，用**非平衡最优传输（unbalanced optimal transport）**把每个图像 token 绑定到指令里的某个 part $k(i)$，依据是编辑器自身的注意力——**不需要掩码、分割器或外部 VLM**。求解耗时 **4.2 ms**。
2. **Freezing（按部件冻结）**：从 $s$ 步起，只有当某 token 的 drift $\delta_{i,j}$ **相对于它自己所属 part 的漂移分布**足够小时才冻结，并把该 token 沿直线路径推到 endpoint 估计（Proposition 1：精确直线路径冻结）。
3. **Sparse engine**：只计算未冻结 token。

### 2.2 三条定理（本轮最可迁移的理论部分）

| 定理 | 结论 | 对本项目的翻译 |
|---|---|---|
| **Theorem 1** | 全局阈值有「精确代价」：必然先破坏 drift 最小的部件 | 单一误杀率/单一改写强度对长尾精细意图结构性不公平 |
| **Theorem 2** | part-agnostic 规则**无法保证**异构 per-part 预算；决策必须看到部件身份 | 分级处置/per-category 阈值不是优化项，是可证伪的必要条件 |
| **Theorem 3** | 非平衡最优传输能保住 argmax 会丢掉的弱部件 | 风险知识/指令召回不能只取 top-1，需保留弱命中 |
| Proposition 1 | 冻结 token 对其 part 引入的误差 $\propto (h_j/t_j)\delta_{i,j}$ | 改写/跳过的误差应按部件幅度归一，而非绝对值 |

### 2.3 为什么 drift 本身不够

论文的诊断很硬：**「token 的 drift 不 reveal 它服务于哪个 edit」**，所以只看 token 自身 drift 的规则无法分离部件。信息其实**已经在编辑器里**（联合序列的注意力把每个图像 token 与指令词连起来），只是没被用来分预算。⇒ 「加更多算力 / 调更细的阈值」救不了，要换**判定单位**。

## 四、实验与结果

### 4.1 结果判读

- **「更快」与「少丢」不冲突**：TIDE 在六个 benchmark 上都是最快，同时 Drop 最少。⇒ 「为了保语义必须牺牲延迟」这个默认假设在本设定下不成立，可直接照搬去回答用户 TTFT ≤110ms / e2e ≤160ms 与语义保真的双约束。
- **分方向报**：全局阈值下 Drop 集中在「小幅、慢收敛」的编辑（改色、小物件），大件编辑反而保住。⇒ 这正是用户「误伤集中在长尾精细意图」的体感；**必须按部件分档报，聚合 Drop 会掩盖**。
- **判定单位换了，模型没换**：TIDE 免训练、不改权重、不改输入指令，只改「冻结判定的单位」。这是 11-23「验收的作用层级装错，比模型不够强更常见」的第五次独立验证。

### 4.2 对 I2I 0/0% 的落点（第八种可证伪归因）

前七种：判据无分辨率 / 改写没写好 / 改写抹掉要件 / 分流只读文本通路（UNR 格）/ benchmark 允许单模态通关 / 编辑前后对照被 batch 非确定性污染 / 粗粒度路由的结构性 overlap。

**本轮新增第八种：单一全局判定粒度**。若 I2I 改写分流是「对整条指令下一次是否改写的判定」，那么按 Theorem 2 它**结构上无法保证**多编辑指令里每个部件的预算——0/0% 可能不是改写器弱，而是**判定单位太粗，把细微编辑部件整体判没了**。零训练检验：把 2000 条评测集（1979 有效样本）按「指令部件数 K」分档（K=1/2/4/8），报每档命中率与「方向覆盖数」；若命中率随 K 单调下降 ⇒ 第八种归因成立，修法是**按部件出带分数的多候选排序**而非重写改写器。

## 五、局限性

1. **不是安全工作**：优化目标是「编辑完成率」，不是 NSFW / 政治风险；「per-part budget」迁移到风险改写需自己定义「part = 风险锚点」并补风险判定翻转率。
2. **绑定依赖编辑器自身注意力**：只在 in-context editor（FLUX.2 / Qwen-Image-Edit 类联合序列）验证；对「文本改写器 → 冻结的生图模型」这种跨模块链路，注意力不可直接读取。
3. **Theorem 的前提是误差可加且有 per-part 预算**：内容安全里的「漏过」不是可加误差（一个部件漏过即整体失败），需重新推导。
4. **未报 fp8/fp4 量化 / 跨硬件迁移**：只有 4/28/50 步与单 GPU；Table 8 有第二块 GPU 的算力对照，但无 serving setup 指纹字段。
5. **VLM judge 本身是代理量**：Drop 由 VLM 判定，虽有人工复核，但未做 11-24「judge 配置指纹 + 多次抽样」那套体检。
6. **未测统一生成-编辑模型下「同一份改写 prompt 双通路」**：只测编辑通路。

## 六、复现指南

### 6.1 论文复现

FLUX.2 Klein 4B（4 steps）/ Klein Base（28 steps）/ Qwen-Image-Edit-2511（50 steps，真 CFG 4.0）；6 个 benchmark；$s=4,R=8,\tau=1.5$ 固定；同时报 Spd / Drop / LPIPS / Done% / 人工复核 / seed noise floor。**必做三条对照**：① 同速全局阈值；② 去掉最优传输改 argmax（验 Theorem 3）；③ 按编辑部件数分档报 Drop。

### 6.2 本项目最小复现（零训练，1 天，D5 优先）

1. **K 分档检验（针对 0/0%）**：把 2000 条图生图评测集按指令部件数 K=1/2/4/8 分档，现有分流逐档报「命中率 / 方向覆盖数 / No-op 率 / 改了没生效率」。判据：命中率随 K 单调降 ⇒ 单一全局判定粒度是主因。
2. **带分数的多候选排序**：把分流输出从「是否改写」改成「每个风险锚点部件一个强度分 + 2 候选排序」，贴 70% 灰度现状先只改输出格式、不重训。
3. **改写强度下沉对照**：三臂——整句改写 / 只替换风险锚点 / per-part 分档强度，同 seed 出图，报风险判定差与主体·属性·关系原子要件保留率。判据：分档强度臂风险不升而保真更好 ⇒ 支持「能改则不拒」。
4. **加速不劣化验收**：把 TIDE 的 Spd/Drop/LPIPS/Done 四栏与 11-25 的「生成侧语义完整性 / 判定侧逐对翻转 / 分层 F1 与安全率 / serving setup 指纹」四栏合并成一张表；加速臂相对原样的判定翻转 >3% ⇒ 先修执行环境再谈别的。

**上线口径**：任何 I2I 改写链路上线须冻结同一份评测单位、batch/精度/硬件、judge 配置指纹，shadow → canary → 全量只换流量比例；分语言、分一级类目、分 L2_30 各报安全率与分层宏平均 F1，`Δaggregate>0 而 Δmacro<0` 不予上线。
