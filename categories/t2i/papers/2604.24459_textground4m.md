## 一、背景与问题

### 动机

当下 T2I 工业模型越来越多地被用来生成海报、卡片、UI mockup、知识图和带文字的宣传物料，真正难的已经不是“画一张好看的图”，而是**把 prompt 里要求的文本内容正确写出来，并放到对的位置上**。现有数据集普遍缺少 span 级文本-布局对齐标注，所以模型即便语义大致对，也常在文字准确性、位置一致性和复杂版式上失真。

### 核心科学问题

能否构建一个大规模、prompt 对齐、span 级、带 bounding box 的文本渲染数据集，并设计一套无需改推理接口的轻量监督方式，让 T2I / AR 生成模型显著提升**文本正确性 + 布局一致性 + prompt 覆盖度**？

### 直觉洞见

TextGround4M 把“图里有字”这个问题从弱监督感知任务，硬拉成了一个可训练、可评测的结构化问题：
- prompt 里哪些字必须出现；
- 每段字应该落在哪个区域；
- 生成结果到底漏了、写错了，还是放错了。

对你的 T2I 输入侧安全业务，这篇论文的重要性在于：真实世界的高风险场景越来越偏 **OCR-rich、layout-rich、可传播内容**。如果 rewrite 评测仍只关注裸视觉内容，而不关注文本渲染与位置一致性，就会漏掉大量真实风险终态。

## 二、核心方法

**（1）TextGround4M：4.1M 规模的 prompt-grounded 文本渲染数据集**

作者从公开数据源 + CommonCrawl 网页挖掘中构建 **4.1M** 高质量样本，每个样本都显式对齐：
- prompt/caption 中被引号包裹的文本 span；
- 图像中 OCR 提取到的文本框；
- span 与 bbox 的对应关系。

这让“文字内容”和“文字位置”第一次被同时纳入大规模监督。

**（2）Qwen2.5-VL + PaddleOCR 的双模态对齐流程**

作者使用：
- **Qwen2.5-VL** 生成细粒度 caption，并显式标出图中可见文本；
- **PaddleOCR** 提取词级文字与框位。

然后通过精确匹配、部分重叠匹配、模糊字符串匹配，把句级描述和词级 OCR 结果对齐起来。

**（3）训练时加监督、推理时不加负担**

针对自回归图像生成模型，作者提出一种很实用的训练方式：
- 训练时，在 image tokens 后追加 **text span tokens + bbox tokens**；
- 推理时，仍然只生成 image tokens，不要求用户提供布局输入，不改推理流程。

这点很像给模型塞进一种“隐性结构监督”，但不改变用户接口。

**（4）TextGround-Bench：按难度分层的评测集**

作者构建 **TextGround-Bench**，把样本分成：
- Easy
- Medium
- Hard

区分依据是：
- 文本框数量 N_box；
- 单段文本最大 token 数 W_max。

这避免了只在简单单词或单框场景上报漂亮分数。

## 三、技术细节

### 数据构建规模与来源

- 原始图文对：**11.7M**；
- 最终保留：**4.1M** 高质量样本；
- 其中：
  - **3.9M** 来自公开数据集；
  - **0.2M** 来自网页挖掘。

公开数据整合自 **10 个**数据源，网页部分则通过 GPT-4o 生成分层 query，到 CommonCrawl 中挖富文本、复杂布局图像。

### 对齐流程

给定 caption 中的引号文本集合 S 和 OCR 检出的词框集合 B，作者需要建立映射：

M: S → B

这个映射通过三阶段完成：
1. exact match
2. partial overlap match
3. fuzzy string match

最终得到 prompt-grounded spans 与 bbox 对齐关系。

### 过滤规则

为保证质量，作者做了多轮过滤：
- 图像宽或高 < **256** 直接去掉；
- 长宽比不在 **[0.67, 1.5]** 去掉；
- OCR 文本区域面积占比 < **10%** 去掉；
- OCR 置信度 < **0.7** 去掉；
- 若超过 **70%** OCR spans 无法匹配到 caption 中标注文本，则样本丢弃。

此外，为降低 trivial case 比例，作者还对 1-bbox / 2-bbox 样本做了额外下采样。

### 训练目标

作者对 AR T2I 模型采用联合目标：

L = L_img + α · L_text

其中：
- `L_img`：图像 token 自回归损失；
- `L_text`：文本 + bbox token 自回归损失；
- 默认 **α = 1**。

关键点在于：文本内容和布局位置都被编码成额外 token 监督，但只出现在训练阶段。

### Benchmark 难度划分

- **Easy**：N_box ≤ 2 且 W_max ≤ 4
- **Medium**：
  - N_box ≥ 3 且 W_max ≤ 4，或
  - N_box ≤ 2 且 W_max ≥ 5
- **Hard**：N_box ≥ 3 且 W_max ≥ 5

这相当于把复杂度同时分解为“版式复杂度”和“文本复杂度”。

### 评价指标

1. **CLIP Score (CS)**：图像与 prompt 全局语义一致性（↑）
2. **Accuracy (Acc)**：OCR 文本词级精确匹配率（↑）
3. **F1**：词级精确率/召回率调和平均（↑）
4. **CER**：字符错误率，越低越好（↓）
5. **Layout IoU**：OCR 框与参考框平均 IoU（↑）
6. **Prompt Coverage (PC)**：被成功渲染并匹配到的 prompt spans 占比（↑）

其中 PC 的形式化定义为：

PC = |S_matched| / |S_total|

这对工业业务很重要，因为它直接回答“prompt 里要求出现的文本，到底有多少真正被画出来了”。

## 四、实验设置与结果

### 数据集与训练设置

- 底座模型：**Janus Pro 1B**
- 训练资源：**128 张 V100**
- 分辨率：**512 × 512**
- batch size：**512**
- 训练步数：**60k**

### 主结果 1：TextGround4M 让文本与布局指标同时抬升

| 难度 | 方法 | Acc (↑) | F1 (↑) | CER (↓) | IoU (↑) | PC (↑) |
|------|------|---------:|-------:|---------:|---------:|-------:|
| Easy | Janus Pro 1B | 10.85 | 10.00 | 89.86 | 0.80 | 7.22 |
| Easy | **Ours** | **34.10** | **33.30** | **83.02** | **7.93** | **30.80** |
| Medium | Janus Pro 1B | 4.48 | 5.52 | 88.72 | 0.27 | 3.33 |
| Medium | **Ours** | **21.90** | **27.75** | **81.23** | **4.32** | **19.09** |
| Hard | Janus Pro 1B | 1.46 | 2.24 | **89.95** | 0.00 | 1.07 |
| Hard | **Ours** | **4.53** | **7.33** | 90.57 | **0.80** | **6.09** |

尽管 Hard 难度依然不理想，但文本准确率、布局 IoU、Prompt Coverage 都明显改善。这说明数据与监督方式至少把模型从“几乎不会做”拉到了“有结构性提升”。

### 主结果 2：闭源模型在复杂文本渲染上仍明显领先

论文指出 **GPT-4o** 在复杂文本渲染与覆盖度上仍遥遥领先，例如：
- Easy **PC = 84.91**
- Medium **PC = 82.61**
- Hard **PC = 83.53**

Hard 场景下还达到：
- **Acc = 77.90**
- **F1 = 65.43**
- **IoU = 8.44**

也就是说，工业闭源模型在多文本、多区域、复杂排版上依然比开源模型高出一个台阶。

### 主结果 3：仅加文本监督不够，bbox 监督更关键

| 监督方式 | 结论 |
|----------|------|
| Vanilla Fine-tune | 提升有限 |
| Text Only | 只能略提文本正确性 |
| Bbox Only | 对布局和总体效果改善明显 |
| **Text + Bbox** | 在 Medium / Hard 上最稳健 |

这很值得记住：在文本渲染任务里，**空间监督常常比文本内容监督更关键**。因为很多失败不是“不会写这个词”，而是“不会把这段字放到该放的位置”。

### 主结果 4：训练 token 放在 image tokens 后面更实用

作者比较了两种顺序：
- Pre-Image
- Post-Image（作者方案）

虽然 Easy 场景 Pre-Image 在部分指标上略高，但 **Post-Image** 在 Hard IoU 上更稳，而且与真实推理流程完全一致，因此工程上更可取。

### 关键发现

- 文本渲染问题必须同时评估“写没写对”和“放没放对”；
- 复杂场景的关键瓶颈往往是布局对齐，而非单纯 OCR；
- 对现实业务来说，Prompt Coverage 是一个非常有价值的上游指标，因为它直接衡量 prompt 条件是否被真正执行。

---

## 五、局限性分析

1. **仍聚焦文本渲染与布局，而非直接安全性**：它没有直接测 NSFW 风险降低，但为真实部署内容的 fidelity 评测提供了关键底座。  
2. **自动标注依赖 Qwen2.5-VL 与 PaddleOCR**：弱标注质量上限受这两类工具约束。  
3. **Hard 场景仍然很难**：即便有数据和监督，复杂多文本布局的绝对性能依然偏低。  
4. **主要针对 AR T2I 模型**：向 diffusion 或纯编辑模型迁移时，训练接口不一定完全一致。  
5. **Prompt Coverage 仍无法替代真正的语义安全判断**：文本写出来了，不代表图像整体意图就安全。

## 六、复现指南

### 环境依赖

```bash
pip install transformers datasets pillow paddleocr accelerate huggingface_hub
```

### 核心代码框架

```python
class TextGroundTrainer:
    def encode_targets(self, image_tokens, spans, bboxes):
        text_tokens = encode_text_spans(spans)
        box_tokens = encode_bboxes(bboxes)
        return image_tokens + text_tokens + box_tokens

    def loss(self, pred_img, gt_img, pred_textbox, gt_textbox, alpha=1.0):
        return autoregressive_loss(pred_img, gt_img) + alpha * autoregressive_loss(pred_textbox, gt_textbox)
```

### 复现步骤

1. 从 GitHub / Hugging Face 下载 **TextGround4M** 与项目页给出的 benchmark 资源。  
2. 准备支持自回归 token 训练的 T2I 基座模型。  
3. 复现文本 span + bbox token 的附加监督。  
4. 分别跑 Easy / Medium / Hard 三档评测，重点看 Acc、F1、IoU、PC。  
5. 若迁到工业海报 / OCR-rich 安全业务，可额外加入：风险词覆盖率、敏感短语位置遵循率、文本渲染可读性。  
6. 对 prompt rewrite 任务，建议把“改写后 prompt 是否仍会渲染原本关键文本要素”作为单独 fidelity 维度。

### 对当前业务的直接迁移点

这篇论文最值得直接拿走的不是模型结构，而是两个评测思想：
1. **Prompt Coverage**：改写后，原 prompt 的关键文本意图到底保留了多少？
2. **Layout-aware fidelity**：对于带排版、卡片、海报类高风险场景，安全改写不能只看语义，还要看文字位置与视觉组织是否被误伤。

如果未来要做“模糊高风险 prompt 的语义保真改写”，TextGround4M 给出的其实就是一块很实用的现实终态评测底板。
