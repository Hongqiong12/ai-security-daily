# 换检验救不了错的定义：三种相依推断全部停在 0.030，只有换"被认证的风险"才到 0.009

## 一、背景与问题

### 动机

LTT（Learn-then-Test）现在是风险受控策略选择的标配：给一个候选策略族 $\Theta=\{\theta_1,\dots,\theta_M\}$（每个 $\theta$ 可以是置信阈值、预测集宽度、弃权规则、告警阈值、干预规则），对每个策略检验"风险是否超标"，再做多重比较校正，得到一个**同时被认证的可行域**。

它的标准形式认证的是**固定的总体风险**：从校准集估一个 $\hat R$，然后检验 $H_j: R(\theta_j)>\alpha$。

论文指出的问题只有一句，但很致命：

> "In sequential deployment, losses may instead be dependent and nonstationary, so the risk of a fixed policy can evolve with the observed history."

**换成我们的语言**：误杀 5.2% 这个数是从历史流量上估的一个总体量。但线上流量在漂移（PSI 在动）、策略上线会改变后续流量的构成（我们拦了什么，下一批就少了什么）。**一个固定策略的风险不是常数，它随历史演化。** 用"固定总体风险 ≤ α"认证出来的阈值，认证的是过去那个分布，不是明天那个分布。

### 三条论断

1. 应该认证的不是"固定总体风险"，而是**沿部署流平均的"可预测风险"**（average predictable risk）：每一步的损失，以"做决定时已知的信息"为条件。
2. 条件中心化把"经验风险 − 目标"变成一个**鞅差序列**，于是相依性被保留在**目标**里，而波动仍可用鞅工具做推断。
3. **只换推断方法（HAC / block bootstrap / 集中不等式）几乎没用**；必须换**被认证的量**。

## 二、核心方法

### 2.1 从边际风险到可预测风险

设策略 $\theta$ 在第 $n$ 步的损失 $L_n(\theta)\in[0,B(\theta)]$，$Y_n$ 在决策之后才揭示。定义一步可预测风险：

$$p_n(\theta) := \mathbb{E}\left[L_n(\theta)\mid \mathcal{F}_{n-1}\right]$$

**它随历史与运行环境变化**，这正是与固定总体风险的区别。

**平均可预测风险**：

$$R_{\text{pred},N}(\theta) := \frac{1}{N}\sum_{n=1}^{N} p_n(\theta)$$

IID 且同均值时 $p_n(\theta)\equiv R(\theta)$，退化为标准 LTT 目标。**所以它不是另一个指标，是标准指标的推广。**

### 2.2 为什么可以检验

令 $Z_n(\theta)=L_n(\theta)-p_n(\theta)$。因为 $\mathbb{E}[Z_n\mid\mathcal{F}_{n-1}]=0$，$\{Z_n\}$ 是鞅差序列，于是

$$\hat R_N(\theta)-R_{\text{pred},N}(\theta)=\frac{1}{N}\sum_{n=1}^{N}Z_n(\theta)$$

**这一步是全文的关键**：相依性没有消失，它被**搬进了目标本身**；剩下的偏差是一个鞅平均，可以用鞅的集中不等式/CLT 处理。

### 2.3 两个检验

**定理 3.2（有限样本，Hoeffding 型）**：

$$p_{H_j}=\exp\!\left(-\frac{2N\left(\alpha-\hat R_N(\theta_j)\right)_+^2}{B_j^2}\right)$$

只用到损失的确定性上界 $B_j$，有限样本有效，但**保守**——它按最坏情形归一化。

**定理 3.4（方差自适应）**：

$$p^{\text{SL}}_j=\Phi\!\left(\frac{\sqrt{N}\left(\hat R_N(\theta_j)-\alpha\right)}{\hat V_N(\theta_j)}\right)$$

其中 $V_N^2(\theta)=\sum_n \mathbb{E}[Z_n^2\mid\mathcal{F}_{n-1}]$ 是**可预测二次变差**。Bernoulli 损失下用插件估计 $\hat V_N^2=\sum_n \hat p_n(1-\hat p_n)$。

**这一步的工程含义**：需要一个**在线的、逐步更新的**一步风险估计 $\hat p_n$。它不是"跑完看总数"，是"每来一批就更新一次风险估计"。

### 2.4 从 p 值到认证域

每个策略的 p 值直接进 LTT 的多重比较层（Holm），得到 **FWER 控制下的同时认证域**。域内的策略可以后续再选，不需要重新认证。

## 三、技术细节

### 3.1 实验设置

| 项 | 设置 |
|---|---|
| 数据集 | **7 个**（Electricity / Appliances / Household Power / PEMS04 / PEMS08 / Beijing Weather / Jena Weather） |
| 划分 | 训练 20% / 验证 2% / **校准 8%** / **认证流 70%**（严格按时间） |
| 模型 | TCN，单步预测，冻结 |
| 风险 | **7 种**二值部署风险（见下） |
| 组合 | 7×7 = **49** 组 |
| 重复 | 每组 **2,000** 次独立重复 |
| δ | 0.10 与 0.20 |

### 3.2 七种风险的构造（Table 1）

| 风险 | 结构 | α |
|---|---|---|
| Interval miss | 逐点 | .10 |
| Lower-tail miss | 逐点 | .10 |
| Severe miss | 逐点 | .10 |
| Task-regime miss | **按运行体制** | .05 |
| Opposite direction | **时序** | .10 |
| Missed reversal | **依赖历史** | .10 |
| False reversal | **依赖历史** | .10 |

**"按体制"与"依赖历史"这两类是关键**——它们让"固定总体风险"这个假设**从设计上就不成立**。

### 3.3 对照方法

IID-LTT、LTT-HB-Holm（Hoeffding-Bentkus）、**HAC-CLT-Holm**（长程方差）、**Circular Block Bootstrap-Holm**（分块重采样）、EB-Howard-Bonferroni（序贯集中）。

**后两个是"已经认真处理了相依性"的强基线**，它们的存在让本文的结论变得锋利。

## 四、实验与结果

### 4.1 主结果：风险差距 α − R̄max（δ=0.10，越小越好）

| 方法 | 平均风险差距 |
|---|---|
| IID-LTT | 0.0302 |
| **HAC-CLT-Holm** | **0.0300** |
| **Circular Block Bootstrap-Holm** | **0.0300** |
| LTT-HB-Holm | ~0.03 |
| EB-Howard-Bonferroni | ~0.03（FWER 近 0） |
| **StreamLTT-A** | **0.0090** |

**这张表就是本轮的核心结论**：

> **两种专门为相依性设计的推断（HAC、block bootstrap）把差距从 0.0302 降到 0.0300——几乎没有变化。**

也就是说，"把检验做对"这件事，在**被认证的量本身错了**的时候，价值接近零。

### 4.2 数据级（Table 2，interval miss，α=.10）

| 方法 | Electricity | Appliances | Household | PEMS04 | PEMS08 | Beijing | Jena |
|---|---|---|---|---|---|---|---|
| IID-LTT | .051 | .046 | .048 | .051 | .044 | .047 | .045 |
| HAC-CLT | .051 | .046 | .048 | .051 | .044 | .047 | .045 |
| BlockBootstrap | .051 | .046 | .048 | .052 | .044 | .047 | .045 |
| **StreamLTT-A** | **.096** | **.096** | **.097** | **.096** | **.095** | **.096** | **.096** |

目标 α = 0.10，StreamLTT 落在 0.095–0.097；其余方法全部卡在 0.043–0.052。**这不是"好一点"，是"用满了预算 vs 用了一半"。**

### 4.3 假认证控制

| δ | StreamLTT-A 实测 FWER |
|---|---|
| 0.10 | **0.0902** |
| 0.20 | **0.1888** |

同时，δ 从 0.10 提到 0.20 时，基线只从 ~0.11 升到 0.1125 / 0.1217 / 0.1208——**它们对"放宽预算"几乎不响应**，说明多给的预算被浪费了。

### 4.4 消融：紧的前沿主要来自"换目标"，不是"换检验"

| 方法 | 风险差距（δ=.10） | 风险差距（δ=.20） | 认证比例 | FWER |
|---|---|---|---|---|
| StreamLTT-H（有限样本） | 0.0118 | 0.0112 | 75.3% → 75.7% | 0.0001 / 0.0006 |
| StreamLTT-A（方差自适应） | 0.0090 | 0.0078 | 76.7% → 77.1% | 0.0902 / 0.1888 |

**两行对比极干净**：只换成"可预测风险 + 有限样本检验"（H），前沿就已经到 0.0118——**离最优只差 0.0028**。方差自适应（A）主要贡献是**把 FWER 从 0.0001 提到 0.0902**，即"别再过度保守"。

⇒ **收益的 76% 来自"换定义"，24% 来自"换检验"。**

## 五、局限性

### 5.1 论文自述

- 需要 Assumption 3.3（可预测方差有稳定渐近尺度）才能用方差自适应版。
- 需要在线估计 $\hat p_n$——即需要**逐步更新的风险估计器**。
- 候选策略族必须**在认证前固定**。
- 只在预测任务上验，未在内容审核类任务上验。

### 5.2 本报告补充的四条

1. **"候选族固定"这条对我们是硬约束。** 我们的阈值是**按类目 × 分业务**下发的，候选族规模是 $O(\text{类目数}\times\text{档位数})$。若在认证后又加类目，整个认证失效。⇒ **类目树版本必须冻结**（与 11-08 的 PrefixCP 结论同源）。

2. **在线 $\hat p_n$ 是落地难点。** 我们现在的误杀/漏过是**周级批算**，不是流式。论文要求每一步都有一步风险估计。折中方案：用滑动窗口 + 指数平滑给出 $\hat p_n$，并显式声明这违反"一致性"假设，只用作近似。

3. **它不管"漏过"与"误杀"的联合优化。** LTT 是**单风险**认证：一个 α。我们的现实是两个约束（误杀 ≤5.2%、漏过 ≤3.42%）。要么分别认证、取交集（域会变小），要么构造一个复合损失 $L=\lambda L_{\text{block}}+(1-\lambda)L_{\text{miss}}$，但 $\lambda$ 一旦定了，就变成单目标。**论文没给这条路的建议。**

4. **7 个数据集全是时序预测，损失是"预测错没错"。** 我们的损失是"判定错没错"，二者结构同构（都是 Bernoulli），但**我们的"揭示"有延迟**（申诉回捞要几天），这会破坏 $\mathcal{F}_{n-1}$ 的可用性。**这是迁移时最容易被忽略的一条。**

## 六、复现指南

### 6.1 能直接搬的三件

1. **"换检验 vs 换定义"的对照实验范式**：同一批数据，跑 IID / HAC / bootstrap / 换目标 四种，看差距从哪儿来。
2. **认证域 + 认证比例**这个报告形式：不报单一最优点，报"哪些阈值同时被认证"。
3. **FWER 缺口** $(\delta-\widehat{\text{FWER}})$ 作为"预算有没有被用满"的指标。

### 6.2 最小可迁移实验（1 天，零训练）

**目标**：验证我们现在的阈值认证是不是在认证一个已经过时的分布。

1. 取最近 8 周的线上命中数据，按周切成 8 个"流段"。
2. 对某一档阈值 $\tau$，逐周算误杀率 $m_t$ 与漏过率 $r_t$。
3. 算三个数：
   - **边际值** $\bar m=\frac1T\sum m_t$（我们现在报的）
   - **可预测值** $\bar m^{\text{pred}}$：每周用**上一周**的信息预测本周（如用前三周滑动均值）
   - **两者的差距** $\lvert\bar m-\bar m^{\text{pred}}\rvert$，以及**周间方差**
4. 判据表：

| 观察 | 结论 |
|---|---|
| 周间方差 / 边际值 **> 30%** | 固定总体风险不成立，**现有认证口径失效**，必须改流式认证 |
| $\lvert\bar m-\bar m^{\text{pred}}\rvert$ **> 0.5 pp** | 分布漂移已大到影响阈值决策，PSI 应升为主要监控项 |
| 8 周内误杀率单调上升或下降 | 存在**策略反馈**（拦了什么，下一批就少了什么），必须建流式模型 |

### 6.3 数据构造要点

- **必须按时间切**，不能随机切。随机切会抹掉相依性，让所有方法看起来一样。
- 校准集与认证流要分开（论文 8% / 70%）。
- 候选族（阈值档位 × 类目）必须在看结果前固定。

### 6.4 评测要点

- **报"风险差距"而不是"风险值"**。0.0090 与 0.0302 的差别只有在 α 已知时才有意义。
- **报 FWER 缺口**。一个 FWER 近 0 的方法（EB-Howard）看起来"最安全"，实际是把 90% 的预算浪费了。
- **报认证比例**。76.7% 意味着 23.3% 的候选策略被排除——这个数决定了运营上还有多少余量。

## 附：与业务的三条硬对应

| 论文事实 | 我们的对应现状 | 可执行动作 |
|---|---|---|
| HAC / block bootstrap 只把差距从 0.0302 降到 0.0300 | 我们调阈值、调 α、换校准方法，误杀率长期在 5.2% 附近摆动 | 先做 8 周流段分析：若周间方差 > 30%，说明"调阈值"这条路的天花板已经到顶，该换成流式认证 |
| 认证的是"平均可预测风险"而非"固定总体风险" | 误杀 5.2% / 漏过 3.42% 都是历史批算值 | 建"逐步更新的风险估计"（滑动窗口 + 平滑），把误杀/漏过变成时间序列而非一个数 |
| 认证比例 76.7%，候选族必须事前固定 | 类目树仍在增量上线，阈值按一级/二级/叶子下发 | 认证前冻结类目树快照，阈值结论必须绑定快照版本（与 11-08 PrefixCP 同源） |
