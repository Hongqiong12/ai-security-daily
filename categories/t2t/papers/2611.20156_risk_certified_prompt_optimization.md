## 一、背景与问题

### 动机：护栏的两类错误天然不对称，但优化目标常是对称的平均性能

LLM-as-a-judge 护栏主要通过 **system prompt** 控制，而标准 prompt optimization 优化的是**平均性能**。论文指出这不匹配：

> 漏掉一次恶意请求会暴露系统，误挡一次良性请求只是降低可用性。两类错误的代价不对称，因此**约束必须显式写出来**，而不是塞进加权平均。

更现实的一层限制：部署态护栏往往**只暴露一个二值 flag 或粗粒度 severity**（论文引 Microsoft 2026b），很多托管 LLM 连连续分数都不给 ⇒ 需要连续分数的常规 conformal 方法用不上。

### 与本仓库主线的关系

- 「**能改则不拒**」的数学写法就是 `max 良性放行率  s.t. 漏过率 ≤ α` —— 本篇给了**有限样本统计控制**下的可执行版本，而不是口号；
- 「**误杀率 5.2% / 漏过率 3.42% 是运营约束基线**」「conformal prediction 与 risk-controlled operating point」「策略热更新 / 规则-策略分层 / 风险知识库与干预策略库注入」全部落在同一个框架里；
- CRISP 的 **hard example-guided rewriting** 与本项目「主动学习挑差异样本 / hard negative mining」是同一动作，只是用在护栏 prompt 而非训练样本上。

## 二、核心方法

### 2.1 约束形式

$$\max \ \text{benign pass rate} \quad \text{s.t.} \quad \text{missed-attack rate} \le \alpha$$

关键是把"选哪条 system prompt"变成 **risk-certified selection**：每个候选都要在留出集上通过**分布无关（distribution-free）的风险认证**，只有被认证可行的候选才参与效用比较。

### 2.2 两个过程

| 过程 | 做法 | 适用 |
|---|---|---|
| **CPS**（Optimize, then Certify） | 先由现有 prompt optimizer 生成**固定候选池**；再用 Learn-then-Test（LTT）+ Bonferroni 多重检验校正，对候选做 **Clopper–Pearson 上置信界**认证；在通过认证的候选中选良性效用最高者 | 候选池里本来就有高效用可行解 |
| **CRISP**（Risk-aware closed-loop） | 把风险反馈接进**自适应搜索**：**hard example-guided rewriting** + **reusable-holdout interface**，把生成推向可行效用前沿 | **固定池里没有可认证的高效用候选**（CPS 的结构性上限） |

CRISP 的两个动作分工明确：

- `ImproveUtility`：取已认证候选中效用最高者，**针对当前被过度拦截的良性样本**改写，让它放行更多；
- `ReduceRisk`：取未认证候选，针对风险样本改写降漏过。

搜索过程中把已探索 prompt 分成 **certified / uncertified 两个种群**（受 FI-2pop 启发），各自服务不同目标。

## 三、技术细节

1. **统计工具链**：Clopper–Pearson 上界给风险的 UCB；Bonferroni / union bound 控制 family-wise error；Hoeffding + union bound 给效用 near-optimality；Learn-then-Test 把"该候选是否违反约束"当零假设检验，从而**不要求单调损失假设**（这是相对 RCPS 的关键差别）。
2. **自适应下的有效性是本篇最硬的技术点**：CRISP 的新 prompt 由早先的认证结果生成 ⇒ 被检验的假设依赖校准数据，普通 holdout 复用会破坏保证。作者用 **reusable-holdout + Guess-and-Check（GnC）** 解决：CRISP **从不直接访问 holdout**，只能通过 GnC 的受限输出（Guess 阶段先算 UCB，超 α 直接拒绝、连 holdout 都不碰；Check 阶段才取受限信息）。作者明确区分这与 anytime-valid / e-process 式自适应 LTT（固定假设、顺序数据）不同：**这里是固定数据、生成假设**。
3. **Proposition 1 / 2** 分别给 CPS 与 CRISP 的风险控制与效用保证（附录 B 有证明）。
4. **三份互斥切分**：training（只用于 prompt 生成/改写）、certification（认证与选择）、test（仅最终评测）——不交叉。
5. **四个数据集**：BIPIA / Deepset（prompt injection）、SPL（system-prompt leakage）、SID（sensitive-information disclosure，BeaverTails privacy）。

## 四、实验与结果

### 4.1 论文可判定的结论口径

- **risk-certified selection 在留出测试上持续遵守目标 missed-attack level**；
- **效用随允许风险 α 放宽而提升**（约束与效用前沿是连续可调的，不是单点）；
- **CRISP 在固定池无法产出可认证高效用候选时尤其有用** —— 这正好是 CPS 的能力边界被实测出来，而不是靠架构分析推断；

## 五、局限性

1. **只在 LLM-as-a-judge 文本护栏上验证**：未涉及图像、多模态或 T2I 输入侧改写；迁移是结构同构。
2. **α 是用户指定的单一风险约束**：本项目是误杀率 5.2% + 漏过率 3.42% 的**双约束**，本篇框架需扩展为双约束（或把误杀放进效用项，但要显式声明）。
3. **认证依赖 certification split 的规模与代表性**：目标风险很低时，需要足够样本才能得到非空可行集；小样本叶子类目（L4）会退化。
4. **judge 本身是误差来源**：论文用 LLM-based judging，未建模 judge 的系统性偏差（与 11-02 批处理翻转、11-03 Prompt Lottery 的风险同类）。
5. **二值 flag 限制仍在**：框架绕开了"需要连续分数"，但也意味着**无法做 per-category 细粒度阈值**——这恰是本项目按一级/二级/叶子类目勾选下发的核心需求。

## 六、复现指南

**论文复现**
1. 四数据集各自切成互斥的 train / certify / test；固定 α。
2. CPS：生成固定候选池 → Clopper–Pearson UCB + Bonferroni（LTT）认证 → 选认证集中效用最高者。
3. CRISP：两种群 + `ImproveUtility` / `ReduceRisk` + Guess-and-Check + reusable holdout；记录搜索 horizon。
4. 在 test 上核验 missed-attack 是否 ≤ α，画"α 放宽 → 效用提升"前沿；做多次独立重划分（Table 7）。

**本项目迁移建议（零训练 / 轻推理，1 天）**

| 动作 | 做法 | 判据 |
|---|---|---|
| **把类目阈值下发改成约束式选点** | 对 L2_30 叶子类目，用固定良性样本集算 `误杀 ≤5.2% 约束下最小化漏过` 的认证阈值，报（阈值、规则、划分、α）四元组 | 与现有"最大 F1 选点"相比代价显著下降 ⇒ 换选点规则（延续 11-10 A7） |
| **改写策略候选池做认证再上线** | 把 SFT 线多个改写版本 / 多个 prompt 模板当候选，逐一做风险认证，只在通过认证的候选中比语义保真 | 出现"保真更高但认证不过"的候选 ⇒ **当前 AB 看板在用效用掩盖风险**（本篇 CPS 的直接用途） |
| **hard example-guided rewriting 对齐主动学习** | 把"当前被过度拦截的良性样本"与"漏过的高风险样本"分别喂给候选改写器，做两臂对照 | 只加难例不改善认证通过率 ⇒ 缺的是策略结构，不是数据量 |
| **与 Operating-Point Failure 成对部署** | 用两矩无标签检查触发"该重选了"，用本篇认证流程执行"怎么重选" | 触发后未重选而继续报旧阈值 ⇒ 版本对比作废 |
| **双约束扩展（必须自己补）** | 把 α 拆成 `漏过 ≤3.42%` 与 `误杀 ≤5.2%`，联合可行域；小样本叶子类目继承父类阈值 | 叶子样本 <200 时可行域为空 ⇒ 明确降级口径，不要硬给数字 |

## 附：对业务主线的三句话

1. **「能改则不拒」第一次有了带证书的数学形式**：`max 良性放行率 s.t. 漏过 ≤ α`，且用 LTT + Clopper–Pearson + Bonferroni 给有限样本保证，不依赖连续分数——适配只暴露二值 flag 的线上护栏。
2. **策略热更新有了完整闭环**：19216 告诉 you「冻结阈值会在版本更新后悄悄失效、且 AUROC 看不出来」，本篇告诉 you「重选时怎么认证、什么时候该用自适应搜索而不是固定池」 ⇒ **两篇必须成对落地**。
3. **边界要说清**：α 约束的是**风险率**，不是 conformal 的**覆盖率**；且框架只给单一 α、无 per-category 阈值，双约束与叶子类目降级口径都得自建——这正是"保证必须绑定它约束的是哪个量"这条判据的又一次应用。
