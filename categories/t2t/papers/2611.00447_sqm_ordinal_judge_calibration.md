# 校准只改尺度，不改排序——那它能救什么、救不了什么

**论文主页**: https://arxiv.org/abs/2611.00447
**领域**: LLM-as-a-Judge 事后校准 / 定序评分 / 分布匹配 / 小模型顶替

**发布日期**: 2026-10-30（v1，cs.AI）
**分类**: evaluation / calibration
**模态归属**: T2T 评测（迁移至 L1–L4 层级标签口径与多版本回归）

## 一、背景与问题

### 动机

LLM-as-a-Judge 的分数相对人工评分有**系统性分布偏移**。常见做法是事后校准：用一小批人工锚点，学一个映射把 LLM 分数搬到人工尺度。

论文的起点是一个立场转换：

> **LLMaJ 的分数不是孤立的点，是从一个分布里抽出的定序评分。**

从这立场出发，一个好的校准必须同时尊重两件事：**定序性**（人工锚点是有序的）和**分布**（两边的分数分布形状）。经典的分位数匹配（quantile matching）本来就是为此设计的，但从未在 LLMaJ 上做过系统 benchmark。

### 四条论断

1. 点式校准（仿射、Platt、温度）不尊重定序性，会在分布尾部出错。
2. 最优传输意义下的分位数匹配，是分布保真度的闭式解。
3. **校准只改尺度与分布，不改排序**——单调校准器按构造不可能重排样本。
4. 校准能缩小大/小 judge 的差距，但**不是均匀地缩**。

### 第 3 条为什么重要

如果"校准不改排序"成立，那么它对我们有两层含义：

- **好消息**：校准是安全的，不会把已经判对的样本判错（在排序意义上）。
- **坏消息**：**如果排序本身是坏的，校准一点忙都帮不上。** 误杀率高如果是排序问题（阈值切在混叠区），校准只能把整条 ROC 平移，不能把它变陡。

这正好给了我们一个判据：**先测"校准能改多少"，就能反推"问题是排序还是尺度"。**

## 二、核心方法

### （1）SQM 的构造

1. 取一小批人工锚点评分 H = {h₁..hₘ} 与对应的 LLM 评分 L。
2. 各自估经验 CDF：F_H, F_L。
3. 求最优传输映射 g = F_H⁻¹ ∘ F_L（L¹/EMD 目标下的闭式解）。
4. **流式**版本：不必等全量，每来一个锚点就更新运行中的分位数估计。

### （2）为什么不是参数化映射

| 方法族 | 形式约束 | 后果 |
|---|---|---|
| 仿射 / Platt / 温度 | 线性或 logistic | 只能整体拉伸平移，改不了形状 |
| 等渗回归 | 单调分段常值 | 定序对，但只对齐点，不管分布 |
| 交叉熵匹配 | KL 目标 | **距离盲**：错放的 massa 不论远近都同罚；且仿射约束限制整形 |
| 小批 sliced Wasserstein | 批内 1D OT | 只在固定批内解，没有持续细化的全局估计 |
| **SQM** | 非参数量纲到量纲 | 直接对齐两条经验 CDF，是 EMD 下的闭式解 |

### （3）评价框架

- 30% held-out，**每个设置跑 3 次**（覆盖 LLM 评分随机性与解析错误）。
- 指标：MAE、Wasserstein 距离、Exact Match。
- 对比 17 种校准方法。

## 三、技术细节

### 三个可验证的量

| 量 | 数值 | 含义 |
|---|---|---|
| 校准前后的排序相关性 | Spearman **0.494**、Kendall τb **0.450**，**完全不变** | 这是全文最硬的结论 |
| 进入 ±5% 带所需数据 | SummEval **第 1 百分位**、UPHELD **第 9 百分位** | 极省数据 |
| 单次校准耗时 | **< 10 ms**（MacBook Pro M5） | 工程上无成本 |

### 排序不变这件事，论文自己解释得很干净

> 对单调校准器（SQM、等渗、Platt、仿射）这件事按构造成立，因为非降映射不能重排样本。它对非单调方法也经验成立，说明事后校准修正的是 judge 的尺度与分布，而不是它对样本的排序。这与温度缩放降低校准误差而不改准确率是同一回事。

### 一个必须警惕的方法细节

SQM 的"预测分布变体"（用 token 概率分布而非单一分数）耗时约为单分数版的 **50 倍**，收益却只在 Wasserstein 上多 0.02。**工程上没必要。**

## 四、实验与结果

### Table 2：held-out 中位数（跨数据集/模型/prompt 汇总）

| 方法 | MAE ↓ | Wasserstein ↓ | Exact Match ↑ | Rank (W/L) |
|---|---|---|---|---|
| **SQM** | **0.53（+31.37%）** | **0.26（+27.87%）** | **0.55（+30.86%）** | **1（7W/0L）** |
| SQM（预测分布版） | 0.53（+30.81%） | **0.24（+33.80%）** | 0.55（+30.73%） | 6（2W/0L） |
| Sliced Wasserstein OT | 0.60（+22.45%） | 0.29（+20.52%） | 0.55（+30.82%） | 5（5W/0L） |
| Dawid–Skene EM | 0.54（+29.79%） | 0.35（+4.00%） | 0.57（+35.41%） | 2（1W/0L） |
| Few-shot exemplar | 0.52（+32.86%） | 0.31（+15.27%） | 0.56（+35.16%） | 3（5W/1L） |
| 交叉熵匹配 | 0.67（+13.36%） | 0.32（+11.47%） | 0.47（+13.49%） | 17（0W/3L） |
| Contrastive rollout | 0.65（+16.07%） | 0.34（+7.71%） | 0.48（+15.48%） | 15（0W/1L） |

17 种方法里 14 种相对原始 judge 有统计显著提升（配对 Wilcoxon，Holm 校正）。

### 模型规模：校准能救谁

| judge 档 | 相对 GPT-5 补掉的原始差距 | 相对 Kimi-K3 |
|---|---|---|
| 中（GPT-OSS-20b） | **83.9%** | 68.8% |
| 中（Qwen3-30b） | **70.1%** | 63.7% |
| 小（Llama3.1-8b） | 34.5% | 41.1% |
| 小（DeepSeek-R1-7b） | 41.7% | 45.5% |
| 小（Llama3.2-1b） | 43.2% | 44.5% |
| 小（Qwen3.5-2b） | **−140%（变差）** | −26.2%（变差） |

**这张表是本篇对我们的核心价值：校准能把"中等模型"拉到接近大模型，但拉不动"小模型"。**

而且不是单调的：Qwen3.5-2b 校准前是**最接近** GPT-5 的小模型（0.082），校准后变成 0.197，差距**扩大 140%**。作者自己指出它输出解析错误率高达 20%（其他 judge 都在 3% 以下），所以这一条可能是解析失败而非校准本身。

### 五个必须单独拎出来的数

1. **0.494 / 0.450 完全不变**：校准前后排序相关性一个数都没动。这是"校准不改排序"的实证。
2. **83.9% / 70.1%**：中等 judge 补掉的差距比例。**5 节点算力下的正确姿势是"中等模型 + 校准"，不是"大模型"。**
3. **34.5–45.5%**：小 judge 只能补三到四成。**再往下压模型规模就不划算了。**
4. **第 1 百分位 / 第 9 百分位**：进入收敛带所需的数据量占比。**校准几乎不要数据。**
5. **< 10 ms**：单次校准耗时。**这东西可以放进在线链路。**

### 一个反直觉的发现

> 校准成功最大的影响因素是**具体的数据集**，而不是方法。

也就是说：同一套校准在数据集 A 上效果好，在数据集 B 上可能无效。对我们意味着——**跨版本、跨类目的校准参数不可复用**，必须按类目/按版本重标。这与 PGuard 的阈值表"每配置块一套、不可搬迁"是同一个现象。

## 五、局限性

1. **纯文本 judge**：不涉及图像、不涉及多模态评分。图审的双模型 AB 能不能用 SQM，需要验证分数是否定序。
2. **只做单维分数**：我们的 L1–L4 是层级结构，不是单一有序轴。层级校准比一维分位数匹配复杂（每层都要保序，且层间要一致）。
3. **校准不改排序**是优点也是天花板：它明确声明自己解决不了排序问题。
4. **数据集依赖强**：作者自己说最大影响因素是数据集。
5. **人工锚点仍需要**：SQM 省的是 judge 调用，不是人工标注。锚点集的质量直接决定校准上限。
6. **未验证在类别不均衡下的行为**：分位数匹配假设两边分布可比；如果人工锚点里 PORN 只占 2%，尾部分位数估计会很不稳。

## 六、复现指南

### 最小复现路径（按对我们的价值排序）

1. **先做"校准能改多少"的诊断**（半天，零训练）。取评测集上"人工分 vs 模型分"，算校准前后的 Spearman。**如果不变（预期不变），那么接下一步。**
2. **用校准幅度当"排序是否可救"的探针**（半天）。对每个叶子类目单独做 SQM，看 MAE 降幅。判据：
   - 降幅大（>25%）⇒ 该类目是**尺度问题**，校准即可改善一致率；
   - 降幅小（<10%）⇒ 该类目是**排序问题**，必须改训练/改定义。

   这一步把"一级一致率 77.64%"拆成"尺度错"和"排序错"两部分，是目前最缺的分解。
3. **中等模型 + 校准，替代大模型做 judge**（有算力再做）。中模型补 70–84% 差距，小模型只补 34–46%。**5 节点下的合理配置是 20–30B 级 judge + SQM，不是 100B 级。**
4. **别用预测分布变体**：50 倍耗时换 0.02 Wasserstein。

### 关键超参

| 参数 | 取值 |
|---|---|
| 锚点集比例 | 论文用 30% held-out 做评测；校准本身用"小批量锚点" |
| 重复次数 | 3 次（覆盖 judge 随机性） |
| 变体 | 单分数 SQM（不要预测分布版） |

## 附：与业务的三条硬对应

1. **给"一级一致率 77.64%"提供了分解工具**：一致率低可能是尺度错（校准能救）或排序错（校准救不了）。逐类目做一次 SQM，就能把 77.64% 拆成两块，直接影响后续投入方向。
2. **给 5 节点算力下的 judge 选型定了边界**：中模型 + 校准 ≈ 大模型；小模型 + 校准不行。这是一条可以直接写进方案的数字边界。
3. **"校准参数不可跨数据集/跨版本复用"与 PGuard 阈值表互相印证**：两篇独立工作都发现"参数绑定具体配置"。**所以多版本回归看板必须按版本重标，不能拿 v1 的阈值跑 v2 的对比**——否则版本间差异里混着参数不匹配的噪声。
