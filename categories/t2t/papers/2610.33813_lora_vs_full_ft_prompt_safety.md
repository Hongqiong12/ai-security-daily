# LoRA vs 全量微调（prompt 安全分类）: 过拒的真因不是阈值，是"看起来有害"

**分类**: defense

## 一、背景与问题

### 动机

给语言模型做**安全分类**（safe / unsafe）时，有大量工程决策，但文献里大多被混在一起比：

- **适应方式（regime）**：LoRA vs 全量微调
- **架构**：encoder（分类头）vs decoder（生成判定词）
- **任务格式（task format）**：只训标签 / 训判定词 / 判定词 + 一句理由

作者指出：**已有 LoRA vs 全量的对比几乎全部被未控制的实验设置决定**（学习率没对齐、只跑一两颗种子、模型选择与报告用同一份数据）。而**任务格式作为独立因子，几乎没人研究过**。

### 核心科学问题

在**同等训练条件**下，LoRA 与全量微调的差距有多大？**任务格式**会不会改变这个差距？

### 为什么这篇对我们重要

三个直接命中：

1. **我们正在做安全分类 SFT**，且面临"LoRA 还是全量"的选择，同时**训练集群从 6 节点缩到 5 节点**——这篇给了同等条件下的定量答案。
2. 我们的格式是 `<tag><|reasoning|>reason...`（CoT tag-first）。这篇**专门测了"判定 + 理由"格式**，还做了三种替换消融——直接告诉我们 reason 的收益到底来自哪里。
3. 我们的核心痛点是 **PORN 过度预测 / VULG-HINT-EDGE 最差**。这篇给出了一个此前我们没测过的量：**"benign but harmful-looking" 的过拒率**，并证明它**不是阈值问题**。

## 二、核心方法

### 设计：交叉对照 + 预注册分析

| 控制项 | 做法 |
|---|---|
| **匹配的架构对** | Ettin 400M 的 encoder 与 decoder：**同一份 2T token 混合、同一套配方、同一 tokenizer、同为 28 层 hidden 1024**，只在注意力模式（双向 vs 因果）和目标函数（masked LM vs causal LM）上不同 |
| **LoRA 配置** | 全部注意力与 MLP 的线性投影都加 adapter，$r = 16$，$\alpha = 64$，用 **$\alpha/\sqrt{r}$ 秩稳定缩放**（而非原版 $\alpha/r$）；两侧 adapter 参数量均为 **8,114,176** |
| **全量微调** | 更新全部 **396M** 参数（含 embedding），约为 LoRA 的 **50 倍** |
| **学习率** | 每个 regime 的学习率由**同一套搜索**在验证集上选出（encoder 侧）；这是全文最关键的公平性控制 |
| **种子数** | 每个训练 cell **15 颗种子**；两个 reason cell 因生成理由昂贵，用 9 颗 |
| **等价性检验** | **事前固定** ±2pp 等价边界，要求 90% CI 落在边界内 |
| **预注册** | 分析与判据在跑之前按 hash 冻结 |

### 三种任务格式（由"损失算在什么上"定义）

| 格式 | 损失算在 | LoRA 下的实际约束 |
|---|---|---|
| **head** | 新初始化的二分类投影（1024→1024 GELU LN→2） | backbone 只需让特征可分 |
| **generated verdict** | 单个判定词（复用预训练 LM head） | 必须把概率质量在 ~50,368 词表上搬到判定词，**只能通过喂给固定 unembedding 的隐状态** |
| **verdict + reason** | 判定词 + 一句话 | 同上，但要拟合一段长续写 |

一个容易被忽略的点：**在 LoRA 下，生成式格式没有新增任何层**，所以它只能改变"喂给冻结输出头"的隐状态——这正是它比 head 格式更"难"的原因。

### 三种 reason 替换（本文最锋利的设计）

为了拆开"reason 的收益来自哪里"，作者把理由替换成三种东西（逐步剥离）：

| 替换 | 去掉了什么 | 保留了什么 |
|---|---|---|
| **fixed sentence**（34 token，每个判定后都同一句） | 内容、与标签的一致性、学完之后额外的损失 | 长度 |
| **reassigned, any label**（换成**另一条样本**的理由，不管标签） | prompt 专属内容 + 与标签的一致性 | 真实的语言形态 |
| **reassigned, same label**（换成**同标签**另一条样本的理由） | prompt 专属内容 | 语言形态 + 与标签一致 |

三种替换各自对应一个竞争假设：若收益来自**内容**，全部替换都会丢失；若来自**一致性**，只有同标签替换保留；若来自**额外的损失**，两种替换都保留。

## 三、技术细节

| 项 | 配置 |
|---|---|
| 训练语料 | 单一语料 **29,095 行**（最终预算） |
| 域内测试 | **Aegis 2.0**（平衡准确率，chance 50） |
| OOD ① | **WildJailbreak**（对抗越狱） |
| OOD ② | **OR-Bench**：15,000 条"看起来有害但无害"的 benign prompt（报**过拒率**，越低越好）+ 655 条 toxic（报**召回**，越高越好） |
| OOD ③ | **ToxicChat** |
| 第四条 | 15,140 条论坛 prompt（只报 ROC-AUC，标签是"是否越狱模板"而非"是否有害"） |
| 参考基线 | **Ministral 3 8B Instruct**（约 20× 大，仅 prompt，不训练），三种格式都跑 |
| 指标选择 | 用**平衡准确率**而非普通准确率：ToxicChat 上普通准确率 92.7% 但平衡准确率只有 50% |

## 四、实验与结果

### 主表（节选，最终预算 29,095 行）

| cell | 架构 / 格式 | regime | 种子 | Aegis 2.0 | WildJailbreak | ToxicChat | OR-Bench 过拒↓ | OR-Bench toxic 召回↑ |
|---|---|---|---|---|---|---|---|---|
| 3 | decoder / 判定词 | LoRA | 15 | 78.7 (2.0) | 55.7 | 76.8 | **66.0** | 81.8 |
| 4 | decoder / 判定词 | 全量 | 15 | 81.3 (1.3) | 57.7 | 77.8 | 45.7 | 73.9 |
| 5 | decoder / 判定+理由 | LoRA | 9 | **82.7 (1.3)** | 69.0 | 84.5 | 29.1 | 88.4 |
| 6 | decoder / 判定+理由 | 全量 | 9 | **82.6 (1.5)** | 68.7 | 86.3 | 34.2 | 93.0 |
| 7 | encoder / head | LoRA | 15 | 82.6 (2.0) | 63.8 | 79.1 | 37.9 | 89.0 |
| 8 | encoder / head | 全量 | 15 | **84.6 (0.4)** | 69.6 | 82.4 | 27.1 | 92.7 |
| 11 | **8B 判定词（不训）** | — | 1 | 76.8 | **77.7** | 80.2 | **2.6** | **94.7** |

### 结论一：在"标签只训标签"时全量领先 2–3pp，但**学习率一对齐就等价**

- encoder 上全量 84.63% vs LoRA 82.57%，**+2.06pp**，90% CI [1.17, 2.95]——区间排除 0，但**跨过事前定的 ±2pp 边界**，所以判定为"不确定"（作者明说：结论取决于边界，这是他们事前固定边界的原因）。
- **两个 regime 的学习率都由同一套搜索选出后，encoder 上二者等价**（落在 ±2pp 内）。
- 架构的影响比 regime 更大：**encoder 比 decoder 高约 4pp**。

### 结论二：reason 让 LoRA 追平全量，且**必须是自己那句话**

LoRA 从判定词格式加理由：**+4.00pp**（95% CI [2.56, 5.44]），全量只 +1.27pp（上界）。交互项 **2.73pp**（[0.88, 4.59]），Holm/Bonferroni 校正后仍存活。两个 reason cell 最终 **82.69% vs 82.60%**，差距 0.08pp——**等价**。

而替换消融（Table 4）给出了全文最有信息量的结果：

| target | 域内 | 4.00pp 增益保留了 | OR-Bench 过拒 |
|---|---|---|---|
| 只有判定词 | 78.7 (2.0) | 0% | 66.0% |
| **固定句子（34 token）** | **78.2 (3.8)** | **0%（还低 0.5pp）** | 58.1% |
| 换别条样本的理由（不管标签） | 80.3 (2.0) | 42% | 44.3% |
| 换同标签别条样本的理由 | 81.1 (0.9) | 60% | 40.7% |
| 自己那句话 | 82.7 (1.3) | 100% | 29.1% |

**三条竞争假设全部只被部分支持**：收益既不是纯内容、也不是纯一致性、也不是纯"长目标多算损失"。而**固定句子完全无效（甚至略低）**——训练损失曲线解释了原因：固定句子几百步就被学会，之后几乎不产生损失；而换来的理由无法从 prompt 预测，损失一直维持在 **1.55** 左右。

> **对我们最直接的一条**：**模板化的 reason 一点都不值钱，只有和这条样本绑定的那句话才有用。** 如果我们的 `<|reasoning|>` 里塞的是套话或按 tag 复用的模板，那 +4pp 拿不到，只有"占 token"。

### 结论三：过拒不是阈值问题，且 reason 能同时降过拒、升召回

- 域内：全量 encoder 领先 8B **7.81pp**（[3.49, 12.13]）。
- OOD：**WildJailbreak 上所有训练 cell 比 8B 低 8.1–23.2pp**。
- **OR-Bench 过拒：head cell 比 8B 的 2.65% 高 10–23 倍**（即约 27%–61%），toxic 召回 72.4–92.7% vs 8B 94.7%。
- **ROC-AUC 上，head cell 在三个安全语料上排序全部更差（差 0.026–0.343）** ⇒ **换个阈值救不回来**，是排序本身坏了。
- 但 **reason 目标把 LoRA 的过拒从 66.0% 砍到 29.1%（−36.94pp）**，同时 toxic 召回反而**升到 88.4%**（全量 93.0%）。**不是靠少报换来的**。

### 一个必须记的评测偏差
生成式 cell 只看每个 prompt 的**前 128 token**，而 **WildJailbreak 有 81.3% 的对抗 prompt 超过 128 token**（head cell 的 256 窗口只有 18.9% 超）。所以生成式 cell 在 WildJailbreak 上的劣势里，有相当一部分是**截断**造成的，不是能力。

## 五、局限性

1. **规模小**：400M、29K 训练行、单一语料。作者自己把 scope 限定得很清楚，结论不能直接外推到 5B 级。
2. **只在 T2T**。T2I 输入侧没有对应实验（这正是我们要自己补的）。
3. **等价性判定依赖边界**：主结论"全量领先 LoRA"的 p 值成立，但**跨过 ±2pp 边界**，所以作者把它判为"不确定"。读这篇时必须带着这个限定，不能引用成"全量更好"。
4. **reason cell 只有 9 颗种子**，且**没有在学习率也调好的条件下重跑**（作者明确承认这一点留空）。
5. **过拒的真实业务代价未量化**。OR-Bench 的"benign but harmful-looking"是合成的，与真实用户流量的分布不同。
6. **8B 参考可能见过这些语料**（预训练污染），作者承认这会偏向 8B。

## 六、复现指南

### 可复现部分
作者放了 harness、冻结的分析计划、逐次运行记录。Ettin 400M encoder/decoder 与 Ministral 3 8B Instruct 都是公开权重，语料（Aegis 2.0 / WildJailbreak / OR-Bench / ToxicChat）公开。**这篇的可复现性是本周最高的一篇。**

### 直接迁移到我们的三条（按性价比）

**① 立刻做：过拒率作为必报指标（半天，零训练）**

我们现在的评测只有"准/不准"，**从来没有单独测过"看起来有害但无害"的过拒率**。而这正是 PORN 过度预测的成因假设。

做法：
1. 从现有训练/回流数据里筛出 `reject_tag` 中"模型判 PORN、人工判安全"的样本，这就是我们的 OR-Bench benign 集；
2. 报**过拒率**（这些样本被判 PORN 的比例），并**同时报 ROC-AUC**；
3. **判据**：若 ROC-AUC 与基线相当而过拒率高 ⇒ **是阈值/校准问题，调阈值**；若 ROC-AUC 更差 ⇒ **是排序坏了，必须改训练目标**，此时按本文结论应优先加**样本专属 reason**，而不是加数据。

这一条能直接回答我们纠结了几周的"PORN 误报到底该调阈值还是改标签"。

**② 关键实验：reason 的"专属 vs 模板"对照（1 天，只跑推理+短训练）**

按 Table 4 的设计，在**现有模型**上做一个最小版：
- A 组：reason = 模型自己写的（现状）
- B 组：reason = 同 tag 下**另一条样本**的 reason（互换）
- C 组：reason = 固定套话（34 token 左右）

**判据**：若 C 组与 A 组无差异 ⇒ 我们的 reason 其实没在起作用，tag-weighted loss 加权的是一段无信息文本；若 B 组掉得比 A 组多 ⇒ 说明我们在依赖**样本专属**信息，那么 reject_tag 改写时必须**同步改写 reason**，不能只改 input_text 保留原 reason。**这一条直接影响我们正在做的标注修正流程。**

**③ 算力决策：5 节点下选 LoRA 还是全量（读论文即可，不必实验）**

- 本文：同为 400M 时，**全量领先 2–3pp；学习率对齐后 encoder 上等价**；**reason 格式能让 LoRA 追平**。
- 推论：**在我们 5 节点的约束下，优先 LoRA + reason 格式**，而不是砍数据去凑全量。因为"reason 带来的 4pp" 比 "全量的 2–3pp" 更大，而且二者叠加后 LoRA 已经追平。
- **注意**：这条推论的前提是 reason 必须是样本专属的（见②）。如果 reason 是模板，LoRA 就拿不到那 4pp，那时才需要重新考虑全量。

### 不能迁移的部分
它的"encoder 比 decoder 高 4pp"是在 400M 同等预训练下得到的；我们训 5B decoder，这个架构优势无法直接移植。

---

**一句话判断**：这篇最重要的不是"LoRA 还是全量"，而是两个我们一直缺的量——**模板 reason 一分不值**（固定句子 78.2%，还低于只有标签的 78.7%），和**过拒不是阈值问题**（ROC-AUC 排序本身就坏，换阈值救不回来，但样本专属 reason 能把过拒砍 37pp 而召回还升）。
