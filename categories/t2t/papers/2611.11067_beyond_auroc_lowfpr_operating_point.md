## 一、背景与问题

### 动机：安全价值由 operating point 决定，不由 AUROC 决定

模型内部越狱检测器（隐表示 / 梯度 / 内部信号）论文普遍报 AUROC。但线上系统只在**低误杀率的那个点**上工作：一条护栏如果误杀 20%，无论 AUROC 多高都不能上线。

论文把检测形式化成一个**数据依赖的决策过程**：

| 数据 | 作用 |
|---|---|
| **calibration data** | 决定检测阈值 |
| **reference data** | 影响检测器分数本身（不只是背景对照） |

这两个常被当作"固定配置"的东西，实际上是**检测器安全行为的一部分**。

### 与本项目的关系（这是本轮最直接对齐误杀率硬约束的一篇）

业务基线是 **误杀率 5.2% / 漏过率 3.42% / 一级一致率 77.64%**，且任务明确「误杀率是硬约束，改写强度应尽量下沉而非直接拒答」。这篇给出三条可证伪的检验：

1. 在构造评测集上校准出的 5%，到真实流量可能变成 11.6–27.2% ⇒ **5.2% 这个数字是在哪个分布上测的，必须写进看板**。
2. AUROC 高 ≠ 该 operating point 上抓得到 ⇒ **现有 AB 若只报 AUROC/AUC，不足以支撑阈值下发**。
3. 改善一个攻击族覆盖会**降低**其他族覆盖 ⇒ **按叶子类目调阈值/补参考样本必须报跨类目代价矩阵**。

## 二、核心方法

### 2.1 三层评测协议

1. **校准迁移检验**：在 curated benign 上按名义 FPR 预算 $\alpha$ 定阈值，在**不相交的真实用户 benign** 上测 realized FPR。
2. **重校准 + per-family TPR**：在真实流量上重校准把 FPR 拉回 $\alpha$，然后按攻击族分别报 TPR at explicit low-FPR operating point。
3. **参考集因果干预**：只改 reference bank 的组成，测 family-level 覆盖如何变化（Table IV）。

### 2.2 两个量的严格区分

$$\text{AUROC} \;\; \text{测排序能力（attack–benign ranking）} \qquad \text{TPR@}\alpha \;\; \text{测选定 operating point 上的覆盖}$$

论文明确：**AUROC 只配做补充排序指标，不能当主要安全度量**。这与本仓库 11-04「分级一致率和分层 AUROC 是两个量」、11-10「判定与信息必须分栏」是同一条判据的第三次独立加固。

### 2.3 参考集干预设计

| 干预 | 内容 |
|---|---|
| None | 原始参考集（对照） |
| Ordinary PKU | 换成同等规模的普通 benign，控制"换一批数据"本身 |
| **SAA-shaped** | 换成与 SAA 攻击族同形的参考样本 |
| SAA + shuffle / SAA + random | 打乱顺序 / 加随机样本，控制"就是多放了些样本" |

⇒ **配对对照 + 阴性对照齐备**，这正是 11-08 记下的「识破捷径靠配对对照，不靠更大测试集」。

## 三、技术细节

| 项 | 设定 |
|---|---|
| 检测器 | 4 个 model-internal detectors（MTK、supervised probe、GradSafe、HiddenDetect） |
| 模型 | 4 个 LLM（Llama-2、Llama-3、Mistral、Vicuna） |
| 攻击族 | 12 个 jailbreak families（SAA、Zulu、AutoDAN、DrAttack、nanoGCG 等） |
| 校准集 | Dolly（curated）、ToxicChat、WildChat（真实用户） |
| 主预算 | 名义 **5%** FPR（对齐已发布检测器评测），另测 **1%** 严预算 |
| 一致性检查 | Dolly 校准的 MTK 复现 nanoGCG 0.929 vs 论文 0.95 @5% |
| 控制 | ToxicChat 子集按 Dolly 校准集大小匹配，排除"样本数"解释 |
| 统计 | bootstrap 不确定度、50 个 release seeds |

## 四、实验与结果

### 4.1 校准不迁移（Table II）

名义 5% 预算在 Dolly 上定阈值，搬到 ToxicChat 真实用户流量：

> **MTK 的 realized FPR = 0.116 – 0.272（四个模型）**，即 **2.3–5.4 倍**超预算。supervised probe、GradSafe 等同样失效；WildChat 上同样超。

且**不是校准集大小问题**：把 ToxicChat 子集裁到与 Dolly 同规模，FPR 仍低于 Dolly 校准的结果 ⇒ 差异来自**校准分布本身**。

⇒ 对本项目最直接的读法：**"误杀率 5.2%"如果是评测集上的数字，不能直接当线上 SLO**；需要一份真实流量 benign 样本做 realized 口径。

### 4.2 高 AUROC / 低 TPR 的分离（Table III，名义 5%）

| 攻击族 | 模型 | AUROC | **TPR@5%** |
|---|---|---|---|
| **SAA** | Llama-2 | **0.942** | **0.114** |
| **SAA** | Llama-3 | **0.918** | **0.002** |
| SAA | Mistral | 0.981 | 1.000 |
| SAA | Vicuna | 0.850 | 0.026 |
| Zulu | Llama-2 | 0.902 | 0.034 |
| Zulu | Mistral | 0.958 | 0.688 |
| AutoDAN | Mistral | 0.925 | 0.108 |
| AutoDAN | Llama-3 | 0.984 | 0.956 |

**AUROC 0.918 而 TPR 0.002** ——排序几乎完美，但在这个 operating point 上等于完全没抓到。Table V 更极端：MTK/Llama-2 上 SAA 在 1% 预算 TPR **0.000**、5% 预算 **0.114**，而 12 族均值 1% 0.125 / 5% 0.570，realized FPR 0.014 / 0.054。

### 4.3 补一族会压掉其他族（Table IV，SAA TPR / 其余 11 族平均 TPR）

| 干预 | Llama-2 | Llama-3 | Mistral | Vicuna |
|---|---|---|---|---|
| None | .040 / .610 | .002 / .785 | .438 / .472 | .011 / .563 |
| Ordinary PKU | .000 / .555 | .002 / .789 | .357 / .417 | .009 / .559 |
| **SAA-shaped** | **.706** / .564 | **1.000** / .727 | .324 / **.095** | **1.000** / .492 |
| SAA + shuffle | .670 / .570 | 1.000 / .728 | .339 / .120 | 1.000 / .447 |
| SAA + random | .376 / .586 | 1.000 / .762 | **.000** / .138 | 1.000 / .421 |

三条结论：

1. **阴性对照成立**：换一批普通 benign（Ordinary PKU）几乎不动 ⇒ 效应不是"换了数据"。
2. **因果效应巨大**：Llama-3 上 SAA 0.002 → 1.000，Vicuna 0.011 → 1.000。
3. **代价会反噬，且方向依模型反**：**Mistral 上 SAA-shaped 干预把 SAA 从 .438 打到 .324/.339/.000，同时把其余 11 族均值从 .472 打到 .095–.138**（几乎全毁）；Llama-3 / Vicuna 上 SAA 升到 1.000 的代价是其余族 .785→.727–.762 / .563→.421–.492。

⇒ **"只补目标类目样本"不是免费动作**。这直接对应任务里的「误杀率-漏过率联合优化 / coverage churn / 分级处置」：按叶子类目调阈值或补参考样本，必须报一张跨类目代价表。

## 五、局限性

1. **是 LLM 越狱检测器，不是图审分类器**：迁移到 `sft_train.image_only` 的纯图分类需重做实验；尤其是「reference data」在纯图模型里没有直接对应物（可能对应检索库 / 校准集构成）。
2. **只测四个 detector + 四个模型**：Mistral 上方向反号这一发现没有给出机制解释，无法预测新模型会往哪边倒。
3. **12 个攻击族不是业务类目**：业务里是 L1–L4 层级 + PORN/VULG 边界 + 政治 L2_30，类目间有包含与重叠；论文的族是互斥的（重叠组的 conformal 处理见本轮 2611.10472）。
4. **FPR 是 prompt 级，不是请求级**：真实链路里一次请求可能含多轮/多图，误杀率的口径需再定义。
5. **未测改写方案**：论文没有「改写后放行」这一动作，因此「能改则不拒」的取向需要自己在链路上补，不能从这篇直接得出。

## 六、复现指南

**论文复现**

1. 复现四个 detector 在四个 LLM 上的分数（GradSafe / HiddenDetect 是作者移植版，不是官方）。
2. Dolly / ToxicChat / WildChat 三套 benign，按 5% 与 1% 名义预算分别定阈值。
3. 报 realized FPR on 每套真实流量 + 12 族 TPR at operating point + AUROC 三列并报。
4. 跑 Table IV 五组参考集干预，每组三次 bank 取均值，配 bootstrap。

**本项目迁移建议（零训练，半天到 1 天，优先级最高）**

| 动作 | 具体做法 | 判据 |
|---|---|---|
| **误杀率 5.2% 口径体检** | 用一份真实线上 benign 抽样（非评测集）重测误杀率，与 5.2% 并列报 | 差值 >3 点 ⇒ 现行 5.2% 是评测集口径，不能作为线上硬约束基线；看板加双口径 |
| **AB 加 per-family TPR 列** | 除 AUROC / 一级一致率外，按一级类目报「在 5.2% 误杀预算下的 TPR」 | 存在 AUROC >0.9 而 TPR@budget <0.3 的类目 ⇒ 该类目阈值/排序需单独处理 |
| **类目补样 / 调阈值报代价矩阵** | 每次只改一个类目的阈值或补参考样本，同时报其余类目的 TPR 变化 | 目标类目升而其余类目均值降 >5 点 ⇒ 拒绝对该配置，或改分组联合校准 |
| **配置指纹进 6 版本看板** | 每个版本记录校准集来源 / 规模 / 阈值规则 / reference 组成 | 校准集不同的两版本不进同一趋势线 |

### 附：对业务主线的三句话

1. **误杀率 5.2% 可能只是评测集口径**：名义 5% 上线变 11.6–27.2%，且不是样本量问题而是分布问题——这是本轮最该先做的一次半天体检。
2. **AUROC 不能作为主安全度量**（0.918 ↔ TPR 0.002）；阈值下发必须报 operating point 上的 per-category TPR。
3. **改善一族的覆盖会压掉其他族，且方向依模型反**（Mistral 上其余 11 族 .472→.095）⇒ 分级处置/类目阈值调优必须带跨类目代价表。
