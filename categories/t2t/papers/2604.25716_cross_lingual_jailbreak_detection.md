## 一、背景与问题

### 动机

跨语言越狱早就不是边缘问题。很多安全 guard 在英文 benchmark 上看起来效果不错，但一旦攻击者把 prompt 翻成中文、俄语、阿拉伯语，拒答行为就会明显变弱。本文瞄准的不是“如何重训一个全球多语安全模型”，而是更现实的问题：**如果目标模型是黑盒 API，我们能不能只靠外部过滤器做跨语言 jailbreak 检测？**

### 核心科学问题

恶意/越狱意图是否会在多语 embedding 空间里形成稳定的跨语言语义邻域，以至于一个**只用英文构建的危险 prompt codebook**，也能检测非英文攻击？

### 直觉洞见

作者的假设很直接：语言表面可以变，**越狱意图的语义几何位置未必完全变**。如果这个假设成立，那么就可以把“跨语言 guardrail”简化成一个 training-free 的 embedding 检索问题，而不必先做翻译、蒸馏或重训。

## 二、核心方法

### （1）构建英文 jailbreak semantic codebook

从 `jayavibhav/prompt-injection-safety` 训练集的 unsafe 部分出发，先做：
- 去重
- 去除极短和 malformed 样本
- 再用两个外部 guard 交叉确认

保留规则是：**至少一个 guard 判 unsafe 即保留**。最终得到：
- **13,811** 条唯一英文 jailbreak prompts

### （2）把检测问题改写成最近邻相似度检索

对任意输入语言查询 x：
1. 用多语 embedding encoder 得到向量 f(x)
2. 与 codebook 中所有英文危险样本向量做余弦相似度
3. 取最大值 s(x)
4. 若 s(x) ≥ τ，则拦截

本质上，这是一种**外部前置过滤器**，而不是内建于模型里的安全机制。

### （3）强调 deployment point：低误报优先

作者不是单看 AUC，而是把阈值选择明确压到**FPR ≤ 1%** 的约束下最大化 TPR。这个选择很关键，因为真正上线的 guardrail 最怕误报，而不是 benchmark 上 ROC 曲线看起来漂亮。

## 三、技术细节

### Codebook 构建

- 初始 unsafe 样本：**15,237**
- 最终 codebook：**13,811**
- 清洗 guard：
  - **Prompt-Guard-86M**
  - **Qwen3Guard-Gen-4B**

### 核心评分公式

设查询 embedding 为 f(x) ∈ ℝ^1024，且做 L2 normalization。  
给定 codebook C = {c_1, …, c_N}，分数定义为：

s(x) = max_(c ∈ C) f(x)^T c

判定规则：
- 当 s(x) ≥ τ → unsafe
- 否则 → safe

### 阈值策略

- 在验证集上 grid search
- 目标：**FPR ≤ 1%** 下最大化 TPR
- 论文同时给出一个便于部署的全局阈值：
  - **τ_final = 0.66**

### 语言与翻译设置

输入语言覆盖：
- 英语
- 俄语
- 中文
- 阿拉伯语

翻译管线两种：
- **Google Translate**
- **M2M100 (facebook/m2m100_418M)**

一个重要设计是：**不做 post-edit，也不做 back-translation**，故意保持现实攻击者会用的“粗暴翻译”条件。

### Embedding 模型

- **BGE-M3**
- **multilingual-e5-large**
- **jina-embeddings-v3**

## 四、实验设置与结果

### 数据集

共 4 个 benchmark：
1. `jayavibhav/prompt-injection-safety`
2. `xTRam1/safe-guard-prompt-injection`
3. `JailbreakBench/JBB-Behaviors`
4. `nvidia/Aegis-AI-Content-Safety-Dataset-2.0`

规模：
- Benchmark 1：**60,000**（safe 27,971 / unsafe 32,029）
- Benchmark 2：**10,300**（safe 7,150 / unsafe 3,150）
- Benchmark 3：**200**（safe 100 / unsafe 100）
- Benchmark 4：**33,416**（safe 13,773 / unsafe 19,643）

评测时：
- 大数据集统一抽样 **1000** 条平衡子集（500 safe / 500 unsafe）
- JBB-Behaviors 用 **全量 200**

### 主要结果 1：跨语言迁移确实存在，但只在“模板化攻击”上强

以 **BGE-M3** 为例：

| Benchmark | 英文 AUC | 翻译后 AUC（范围） | 结论 |
|------|---------:|-------------------:|------|
| Benchmark 1 | 0.829 | 0.765–0.806 | 有效但不算极强 |
| Benchmark 2 | 0.993 | 0.847–0.884 | 很强，说明 canonical 模板迁移成立 |
| Benchmark 3 | 0.618–0.703 | 同量级 | 明显变弱 |
| Benchmark 4 | 0.593–0.627 | 同量级 | 基本不够用 |

关键结论不是“跨语言失败”，而是：**它只对模板化、语义相对收敛的 jailbreak 家族有效；一旦进入行为多样、分布更野的 unsafe 数据，语义 codebook 很快失去分离能力。**

### 主要结果 2：在现实低误报部署点，只有 Benchmark 2 还算能打

看 **TPR @ FPR ≤ 1%**（BGE-M3）：

| Benchmark | 英文 | 非英文范围 | 结论 |
|------|-----:|-----------:|------|
| Benchmark 2 | 91.9% | 78.5%–87.7% | 真正能上线的水平 |
| Benchmark 1 | 20.1%–25.6% | 同量级 | 低误报下召回明显不够 |
| Benchmark 3 | 14.0%–23.0% | 同量级 | 明显不足 |
| Benchmark 4 | 3.3%–6.4% | 同量级 | 基本失效 |

这组数字是全文最硬的现实提醒：**AUC 好看不代表 guardrail 真能上线。**

### 主要结果 3：端到端缓解效果强依赖 benchmark 分布

平均减少成功 jailbreak 的相对比例：
- Benchmark 1：**96.2% ± 2.6**
- Benchmark 2：**50.0% ± 17.4**
- Benchmark 3：**43.7% ± 21.6**
- Benchmark 4：**18.6% ± 13.8**

这意味着：
- 对标准化 prompt-injection / jailbreak 套路，前置过滤器很有价值；
- 但对更异质、真实 world unsafe 行为，收益会快速塌缩。

### 主要结果 4：embedding 模型选择决定低误报性能

在 Benchmark 1 / 中文 (m2m) 上：
- **BGE-M3：TPR 21.6%**
- **multilingual-e5-large：TPR 4.8%**

这说明一个重要工程点：**embedding 选型在低误报区域的差异远大于 AUC 表面显示的差异。**

## 五、局限性分析

1. **静态英文 codebook 的覆盖有限**：对新型、非 canonical、语言特有表达的攻击鲁棒性不足。  
2. **对分布偏移高度敏感**：Benchmark 4 在 FPR ≤ 1% 下只有 **3.3%–6.4%** 的召回。  
3. **本质上仍是“已知模式近邻检索”**：更像第一道轻量 guard，而不是完整安全边界。  
4. **翻译噪声与语言距离仍会拉低效果**：尤其中文、阿拉伯语这类与英文距离更远的表达。  

我的判断是，这篇论文最有价值的不是“给出一个万能跨语种 detector”，而是把问题边界画得很清楚：**语义 codebook 可以做第一层，但绝不能把它误当成真实世界跨语言安全的最终解。**

## 六、复现指南

### 最小复现路径

1. 从 `prompt-injection-safety` 中抽取 unsafe 训练样本。  
2. 用 Prompt-Guard-86M 与 Qwen3Guard-Gen-4B 做清洗。  
3. 生成 **13,811** 条英文 codebook。  
4. 选用 **BGE-M3** 作为主 embedding encoder。  
5. 在验证集上做 grid search，选择满足 **FPR ≤ 1%** 的阈值。  
6. 在英/中/俄/阿四语 benchmark 上测 AUC 与 TPR@1%FPR。

### 最值得复现的部分

我建议优先复现两件事：
- **Benchmark 2 的高召回结果**，验证 canonical jailbreak 模板确实能跨语言迁移；
- **Benchmark 4 的崩塌结果**，验证低误报部署点下真实分布为什么不成立。

### 工程启示

这篇论文适合写进 T2T survey 的原因，不是它把安全问题解决了，而是它给出了一条非常干净的部署经验：
- **embedding codebook guard 适合挡“已知套路”**；
- **但面对更广义的 unsafe / misaligned 行为，它会迅速失效**。

这条边界判断，比单纯宣称“跨语言检测有效”更重要。
