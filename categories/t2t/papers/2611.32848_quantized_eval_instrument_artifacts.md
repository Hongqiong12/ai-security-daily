## 一、背景与问题

### 动机：把「基准分变化」记到量化头上，忘了尺子也在变

评测量化模型时，业界把「benchmark 分数的变化」直接归因于量化。本文把它写成两项：

$$\Delta_{\text{measured}} = \Delta_{\text{true}} + \Delta_{\text{inst}}$$

其中 $\Delta_{\text{inst}}$ 是**测量仪器的贡献**。作者给出一个关键区分：

- **在各精度下都相同的仪器误差**：只会缩小配对比较，**不能创造或反转**一个效应；
- **与量化发生交互的仪器误差**：既能凭空造出效应，也能反转真实效应的符号，并且会被当成「量化的效应」写进结论。

小模型尤其容易中招：拒答话术不被关键词表预期、接近 chance level、评分协议是为大模型设计的。

### 与本仓库主线的关系（三重命中，方法论迁移）

1. **用户方向 (5) 明确要求「fp8/fp4 量化后安全率与分层 F1 漂移」与「量化/加速前后安全率不劣化对比口径」**：本文是**唯一直接把「安全率变化」拆成真实变化 + 仪器项**的公开工作，且给出人工校准后的量级。
2. **误杀率 5.2% / 漏过率 3.42% 基线本身要先被审计**：11-25 的两篇（overlap 结构性下界、评测集重叠污染）给的是「读数被数据集污染」；本篇补第三种污染——**读数被测量工具污染**（拒答检测器只召回 33.3% 的拒答）。
3. **2B 以下模型 / 英文 ASR 飙升 / qwen3.5 Pro5000 两阶段迁移与 fp8/fp4 降本**：本文评测的正是 135M–1.7B 小模型在 float16 / LLM.int8() / NF4 三档的表现，且发现 **LLM.int8() 不是 batch-invariant** ——与 11-25 `2611.30545`「serving setup 决定出图」在判定侧互为佐证。

## 二、核心方法

### 2.1 固定模型与题目，只变仪器

8 个 instruction-tuned 模型、5 个家族、**135M–1.7B**，在 float16 / LLM.int8() / 4-bit NF4 三档，对**完全相同的 items** 做配对检验。逐一把四个「测量选择」当作自变量：

| 仪器 | 变体 |
|---|---|
| 拒答检测器 | baseline keyword detector vs 归一化引号 + 全文扫描的 corrected detector；再用 Llama Guard 3 (1B) / WildGuard 交叉验证 |
| 选择题评分 | mean-normalised cloze / summed cloze / lettered（原始顺序）/ lettered（两种顺序平均） |
| 批处理 | 重排 batch、加 padding、关闭 outlier decomposition、激活保持 float16 |
| 校准汇总 | ECE + discrimination-aware 分析（区分真实校准损失与 response-bias 位移） |

### 2.2 人工校准

两名标注者独立标 100 条回复（90 条 AdvBench + 10 条 XSTest 安全 prompt 专测 over-refusal），**只看 prompt 与 response**，四类 codebook（Cohen's κ = 0.380；refusal vs other κ = 0.425），分歧裁决。样本刻意含 20 条从基线输出里检出的两种失败模式。

### 2.3 tipping-point 分析

对「人工校准估计依赖主假设到什么程度」做敏感性分析，避免把校准后的数当成无条件的真值。

## 三、技术细节

### 3.1 拒答检测器审计（本轮最该搬进项目的一组数）

| 检测器 | 召回 | 精确率 |
|---|---|---|
| Baseline keyword detector（AdvBench items） | **33.3%**（95% CI 21.4–47.9） | 68.2%（47.3–83.6） |
| 上述样本去掉两种已知失败模式后 | 60.0%（40.7–76.6） | — |
| **Corrected detector**（归一化引号 + 全文扫描） | **80.0%**（66.2–89.1） | **80.0%**（66.2–89.1） |

两种失败模式：① 某模型族用**印刷体撇号**写拒答，词表匹配不上；② 拒答出现在**比检测器窗口更长的前言之后**。基线 detector 在全部 AdvBench 生成里只标出 corrected detector 所标拒答的 **91%**。

⇒ **「拒答率 / 误杀率」这类读数的误差不是随机噪声，是系统性的、与模型族和话术相关的**。

### 3.2 人工校准后的量化效应

- 4-bit 使 harmful compliance 上升 **+2.6 点**（换 WildGuard 为 +3.0）；
- 而 corrected keyword detector 记录的 refusal **下降 4.7 点**；
- ⇒ 前者约为后者的 **一半到三分之二**。
- corrected detector 下，4-bit 在 **8 个模型中的 4 个**显著抬升 non-refusal，最大 **+18.5 点**；单个模型（SmolLM2-1.7B）最多 **28% 的有害 prompt 改变结果**；8-bit 仅 SmolLM2-1.7B 显著，且 non-refusal **下降 10.2 点**（方向相反）。
- HaluEval 上 4-bit 逐项显著变化在 6 个模型（3 升 3 降）、BBQ 2 个（一升一降）、TruthfulQA 0 个 ⇒ **方向不一致，禁止只报聚合**。

### 3.3 同一模型同一精度，四种评分给出四种结论

2,000 条 HaluEval items，SmolLM2-1.7B 的 4-bit 准确率变化：

| 评分协议 | $\Delta$ | 显著性 |
|---|---|---|
| mean-normalised cloze | **+9.8 点** | 显著 |
| summed cloze | +0.8 点 | 不显著 |
| lettered（发布顺序） | **−13.6 点** | 显著 |
| lettered（两种顺序平均） | −7.3 点 | 显著 |

cloze 与 lettered 的 64 个变化估计相关性 **ρ = 0.10**，而噪声允许的「天花板」约 **0.77** ⇒ 分歧远超测量噪声。机制：NF4 会改变模型对**选项位置**的偏好，8/8 模型的 first-position rate 都显著变化（最多 11.0 点；SmolLM2-360M 在 ARC-Easy 上 +59.5 点）。

### 3.4 batch 依赖（与 11-25 生成侧非确定性配对）

- **LLM.int8() 是确定性的但不是 batch-invariant**：6 个模型中，重排 batch 改变的 8-bit 答案数是「float16 → 8-bit 量化所改变答案数」的 **57–119%**；**仅加 padding 就会改变答案**；8-bit 生成随 batch 顺序变化（3/3 模型）。
- 关闭 outlier decomposition 后依赖仍在，**激活保持 float16 时消失** ⇒ 8 位舍入本身就足以产生；**NF4 是 batch-invariant**（但仍改位置偏好）。
- ECE：80 个变化里 11 个未校正区间排除零（随机期望约 4 个），**方向不一致**；两个最大的「校准损失」其实是 response-bias 位移。

## 四、实验与结果

### 4.1 结果判读

- **「量化后安全率下降 X 点」这个句式，X 里混着尺子**：4.7 点的拒答下降里，人工校准后真实 harmful compliance 只涨 2.6 点。⇒ 本项目 1105 权重、qwen3.5 Pro5000 二阶段量化、fp8/fp4 降本的每一档，**安全率必须报「人工双盲校准后的估计 + 检测器版本 + tipping-point 区间」**，否则版本间比较的可能是检测器而不是模型。
- **与 11-24 judge 单向偏置、11-25 评测集重叠污染并列的第三种读数污染**：① 评测集重叠（乘性）→ ② 表示 overlap（结构性下界）→ ③ **测量仪器交互（可造出/反转效应）**。顺序应固定为：先审计评测集 → 再体检表示 → **再体检尺子** → 最后才做约束式选点。
- **8-bit 的 batch 依赖是判定侧的「serving setup」**：与 11-25 生成侧「同 prompt 同 seed 因 batch/GPU/精度出图不同」合成一条硬要求——**事件审计必须同时记录生成侧与判定侧的 batch / bit 宽 / 硬件**。
- **方向分列**：HaluEval 3 升 3 降、BBQ 一升一降 ⇒ 聚合准确率几乎不动而逐格换边，与 11-24「1.1–12.3% 成对翻转而聚合只动 0.03 点」同族。

### 4.2 迁移边界（必须写清）

原文是**小语言模型的文本可信度评测**，不是 T2I、不是图审、不是改写。可迁移的是**协议**（仪器项分解、检测器人工校准、评分协议对照、batch 依赖检查、tipping-point），**不可迁移**的是所有具体量级（2.6 点、4.7 点、33.3% 召回、ρ=0.10）。

## 五、局限性

1. **只有文本模型 135M–1.7B**：未覆盖 2B 以上、VLM 图审、T2I 生成模型；「2B 改写模型英文 ASR 飙升」只能借协议不能直接借结论。
2. **两名标注者 κ=0.380/0.425 偏低**：作者如实报告并做裁决，但人工标签本身的可靠性是估计的上限约束。
3. **100 条标注样本偏小且刻意含 20 条已知失败模式**：检出率数字不可直接当总体率；tipping-point 分析是必要的补充但不是替代。
4. **只测 bitsandbytes 的 LLM.int8() 与 NF4**：未覆盖 fp8/fp4 的其他实现、TensorRT/ vLLM/ SGLang 的 prefix caching / continuous batching，也未报 TTFT / e2e / TPOT。
5. **未测中文 / 中英混合**：全部英文基准（AdvBench / XSTest / HaluEval / BBQ / TruthfulQA / ARC-Easy）；跨语言改写鲁棒性无法互证。
6. **未做生成图的判定翻转率**：与本项目出图侧四层归因之间没有直接桥梁，需要自建「量化前后图审逐样本判定翻转」实验。

## 六、复现指南

### 6.1 论文复现

8 模型 × 3 精度 × 相同 items 配对；两名标注者 100 条（含 XSTest 过拒答检查）+ 裁决 + κ；四种评分协议 + 循环顺序平均；batch 重排 / padding / 关闭 outlier decomposition / 激活保 float16 四组消融；报告 ECE 与未校正区间。**必做**：tipping-point 分析与方向分列（不可只报聚合）。

### 6.2 本项目最小复现（零训练，半天～1 天，A4 / D3 最优先）

1. **先审计自己的拒答/误杀检测器**：抽 100 条改写/拒答输出，两人独立双盲标四类（含「假安全拒答」体感类），算 κ 与检测器召回/精确率。**判据**：召回 <80% ⇒ 误杀率 5.2% / 漏过率 3.42% 基线先按 corrected detector 重算，历史 AB 按版本重算。
2. **量化不劣化的仪器项分解**：1105 权重、qwen3.5 Pro5000 二阶段、fp8/fp4 每档报「测得变化 = 人工校准估计 + 检测器版本 + 区间」；同时报分层宏平均 F1 与逐样本判定翻转率（harmful / helpful 分列）。**判据**：任一叶子格翻转 >3% 或 `Δaggregate>0 而 Δmacro<0` ⇒ 判劣化，不管聚合是否微涨。
3. **评分/判定协议对照臂**：同一批样本跑「纯图 / 图+prompt / 换 judge 示例集 / 换判据描述」四版，报协议间相关性；远低于噪声天花板 ⇒ 现有 AB 比较的是装置不是模型。
4. **batch-invariant 体检（判定侧）**：重排 batch、加 padding、换 bit 宽各跑一遍，报逐样本判定变化率；把 **batch size / bit 宽 / GPU / 缓存方法 / 步数**作为 serving setup 指纹写进事件审计必填字段（与 11-25 生成侧要求合并）。
5. **跨语言补臂**：中 / 英 / 中英混合三档各跑 1–4，禁止只报聚合 ASR；2B 改写模型单独列脆弱窗口占用率，不与 8B 共用不劣化结论。

**上线口径**：shadow → canary → 全量只换流量比例，冻结评测单位、聚合口径、阈值规则、judge 配置指纹、batch/精度/硬件；观察模式（只记不拦）与生效模式分列；TTFT ≤110ms / e2e ≤160ms、TPOT、超时率、降级率按档留痕。
