## 一、背景与问题

### 动机

自动化审核在规模化地决定"什么是有害"，但决定得**不均匀**。三个已被反复测到的现象：

- 分类器把**非裔美国人英语（AAE）**标为冒犯的频率高达其它英语变体的 **2 倍**；
- 知名 drag queen 的账号可以被判得**比白人至上主义者更 toxic**；
- 在英语里成立的安全行为，到了低资源语言**直接崩塌**。

论文的主张是：**过度标记（over-flagging）与保护不足（under-protection）是同一个病因** —— 系统在根据**词汇与表层形式**判断有害，而不是根据**一条消息在做什么（function）**判断。

### 核心科学问题

如果"有害"被定义为**行为**（索要保密、索要付款、隔离某人、威胁），而不是**词**，那么：
- 同样的有害行为在**每种语言里都存在**，但**承载它的词不存在** → 行为是可跨语言迁移的目标，词不是；
- 一个按行为判断的系统，应该在各语言间**更均匀**；一个按形式判断的系统不会。

### 为什么这篇对我们重要

我们当前的两个核心痛点是：
1. **PORN / VULG 边界混淆**，VULG-HINT-EDGE 反复是最差类别；
2. **政治 L2_30 层级口径**难统一（地区/政治敏感度高度依赖语境）。

这篇给的诊断是：**这两件事可能是同一个病** —— 我们的标签判定在相当的程度上是**词表驱动**的（"暗示""擦边"这类概念没有可枚举的词，系统就退回到"出现了哪些敏感词"）。而它同时给了一个**我们必须警惕的统计事实**：**"最差类别"这个提法本身，在样本量不够时可以完全是噪声**（下面 6.1 详述）。这直接冲击我们"VULG-HINT-EDGE 是最差类别"的判断基础。

## 二、核心方法

### （1）七类失效模式（本文最可直接搬用的部分）

把已有证据整理成**七种"按形式判断"偏离"按功能判断"的方式**，每种标明主要误差方向：

| # | 失效模式 | 主方向 | 机制 |
|---|---|---|---|
| 1 | **方言惩罚** | 过度标记 | 方言的语法/词汇特征被当成有害标记 |
| 2 | **群体内语言被读成群体外攻击** | 过度标记 | 被回收的词（reclaimed terms）、玩笑式不礼貌、亲密脏话被判为辱骂 |
| 3 | **身份词当假信号** | 过度标记 | 命名群体的词因为"辱骂数据里常出现"而成为有害证据 |
| 4 | **标注者视角被焊进标签** | **双向** | 标注者的信念与身份变成了系统对"有害"的定义 |
| 5 | **低资源崩塌** | 保护不足 | 训练数据少的语言里检测与安全行为急剧退化 |
| 6 | **混合语言与混合文字** | 保护不足 | 语码混合/音译落在两种语言资源的缝里，评测集几乎不覆盖，错误率基本未知 |
| 7 | **有行为无词表** | 保护不足 | 由"消息在做什么"承载的伤害（要求别告诉父母、友好地给钱、逐步转到私聊）对词表系统完全不可见，**任何语言都是** |

**模式 3 是最反直觉的一条**：身份词同时是**假阳性来源**和**少数正确检出的来源**。实测里词表检出的隐式仇恨"很大程度上是通过身份词抓到的（gay、black、黑人、残疾人）——而正是这些词产生了它的误报"。

**模式 4 与模式 7 对我们最关键**：
- 模式 4 说**标签本身带标注者视角**。我们的 PORN/VULG 边界争议，一部分不是"标准不清"，是**标注者对该不该算的信念不同**，而这种信念被写进了标签，模型学到的就是这个信念而不是规范。
- 模式 7 说**"擦边/暗示"这类概念天然无词表**。VULG-HINT-EDGE 的全部难点就在这里：**它是行为（暗示、胁迫、以退为进），不是词。**

### （2）两个可证伪假设 + 一个诊断量

作者刻意把主张写成**可以失败的假设**，这点很值得学：

**H1（判别力）**：在"按功能配对"的测试集上，按行为判断的系统应当**在每个它服务的语言里**都把有害样本排在无害"形似样本"之上；按形式判断的系统不会。**测量在设阈值之前完成**（对比集上的 AUC），所以它是"功能 vs 形式"的直接检验。

**标准的锚不是数字，是人**：一个系统在某语言上"达标"，当且仅当它的排序能力**不显著差于该语言母语标注员的平衡准确率**。判"不达标"的条件：差值的 95% 区间（**按整个模板簇做 bootstrap 重采样**）完全在零之上。

**H2（稳定性）**：在判别力都好的系统里，按功能判断的**跨语言差异更小**。

**诊断量 —— 耦合（coupling）**：当一个**单一的每语言设置**在决定系统行为（词表覆盖多少、某语言的分数落在固定阈值的哪一侧），它对无害样本的误报率与对"无标记词的有害样本"的漏报率会**跨语言负相关**：这个设置决定了某语言是被消声还是被放任。**强负相关 = 覆盖度/校准在决定错误如何分布，而不是"消息在做什么"。**

### （3）评测协议：把"差距"当成头条结果

八条要求，核心是**同时报两个方向的误差 + 报最好与最差之间的差距**：

1. **母语作者撰写的平行测试集**（不是机器翻译——翻译测的是"系统处理翻译文本"，而人不是那样说话的）；
2. **按功能配对的对比样本**（同一个被回收的词，用于团结 vs 用于攻击；同一个请求，来自父母 vs 来自陌生人）；
3. **每个变体、每个方向都报**：无害样本误报率 + 有害样本漏报率，各带置信区间与样本量，外加**免阈值的排序度量**，并与母语标注员对照；
4. **差距作为头条数字**：固定操作点下最好与最差变体的差，**并且要报"若各变体被同等服务时预期的差距"**；
5. **把"无标记词的有害样本"单列一层**（否则词表系统能靠词汇通过测试）；
6. **混合语言与文字**要覆盖；
7. **标注来源要披露**（谁标的、与社群什么关系、分歧怎么解决）；
8. **留出并定期刷新**（承载伤害的词变得比它执行的功能快）。

**一条对我们极重要的操作纪律**：`A system whose average is good and whose gap is large is not a good system for the people at the bottom of that gap.` —— **平均分好 + 差距大 ≠ 好系统。**

## 三、技术细节

### 3.1 实验设置（一个"工作示例"，不是完整验证）

| 项 | 设置 |
|---|---|
| 被评系统 | **5 个**：关键词词表（HurtLex + wordfreq 频次过滤）、开源多语 toxic 分类器（XLM-R large）、**Qwen3Guard-Gen-0.6B**、**Qwen3Guard-Gen-8B**、**PolyGuard-Qwen**（17 语） |
| 语言 | **11 种**：英、普通话、西、意、荷、德、葡、法、波兰、阿拉伯、**罗马化印地语** |
| 测试集 | HateCheck / Multilingual HateCheck 的模板化用例 + HurtLex 词表 |
| 指标 | 两个方向的错误率 + 免阈值 **AUC**（隐式仇恨 vs 无害形似样本），对照母语标注员平衡准确率 |
| 统计 | 模板级 bootstrap（2,000 次重采样）；差距用 5,000 次模板级置换检验 |
| 生成量 | 未涉生成模型；纯判别评测 |

### 3.2 关键设计

- **AUC 与阈值的解耦**：AUC 衡量"排序"，不受操作点影响；因此"读不懂功能"与"在该语言上校准差"被分开了。**这是全文方法论的支点。**
- **模板级重采样**：同一模板生成的用例不独立，必须整簇重采样，否则区间被严重低估。
- **标注员基准随语言浮动**：法语标注员把 **55%** 的无害对比样本标成仇恨 —— 于是法语的"人类门槛"很低。**低门槛不是因为系统读懂了功能，是因为该语言的案例本身有争议。** 这个细节极其重要：**跨语言比"相对人类的表现"时，人类基准自身的可靠性必须一并报告。**

## 四、实验与结果

### 4.1 主结果：55 个"系统 × 语言"组合里，51 个显著不达标

| 系统 | AUC（隐式仇恨 vs 无害形似）区间 | 特点 |
|---|---|---|
| 关键词词表 | 平衡准确率 **0.43–0.53** | 覆盖越好的语言过度标记越严重（英语无害样本误报 **52.7%**、普通话 41.5%）；覆盖薄的语言几乎不保护（阿拉伯语误报仅 4.3%，但隐式仇恨漏 **100%**） |
| 开源 toxic 分类器 | AUC **0.52–0.64** | 误报 39–62%，漏报 19–54%；**英语 AUC 仅 0.52（接近抛硬币）** |
| Qwen3Guard-0.6B | **0.54–0.73** | 误报高且几乎均匀（10 个语言 40–50%），**保护能力随离英语的距离衰减**（英语漏 15%，罗马化印地语漏 72%） |
| Qwen3Guard-8B | **0.54–0.84** | 9 个语言漏 9–24%，**阿拉伯语漏 63%、罗马化印地语漏 77%** |
| PolyGuard | **0.54–0.87** | 全球过度标记 57–69%；阿拉伯语误报 **69.0%** + 漏报 **15.9%**，**同一种语言上两个方向同时最差** |
| 母语标注员（人类基准） | 平衡准确率 **0.70–0.99** | 英语 0.99 最高（该集只保留多数标注员一致的案例） |

**核心结论**：**没有任何系统在两个方向上同时服务好任何一种语言。** 55 个组合中 51 个显著低于"单个母语标注员"的标准，差距 **6–55 个百分点**。去掉英语（门槛最高）后，剩余 50 个组合里仍有 **46 个**不达标。

### 4.2 能力提升只抬高天花板，不抬地板

| 系统 | 9 个语言的 AUC 均值 | 跨语言**极差** | 阿拉伯 / 罗马化印地 |
|---|---|---|---|
| Qwen3Guard-0.6B | 0.65 | **0.20** | 0.55 / 0.54 |
| Qwen3Guard-8B | 0.81 | **0.29** | 0.59 / 0.54 |
| PolyGuard | 0.81 | **0.33** | 0.59 / 0.54 |

**这是全文最锋利的一刀**：**能力越强，跨语言的不平等越大。** 0.6B → 8B，均值从 0.65 涨到 0.81，但极差从 0.20 扩到 0.29；PolyGuard 的 **0.33 最大**，且阿拉伯语与罗马化印地语两个语言**几乎没动（0.54–0.59）**，尽管它们都在 PolyGuard 的 17 个训练语言里。

> **"By its average, the better model is here the more unequal one: the languages already served worst gain least."**

### 4.3 四种不同的错误分布形态

同样是"按形式判断"这一个病根，五个系统的错误分布完全不同：

| 系统 | 分布机制 |
|---|---|
| 词表 | 由**语言覆盖度**决定（$\rho=-0.91$，去印地语后 −0.88） |
| 分类器 | 由**每语言校准**决定（$\rho=-0.73$，p=0.01） |
| Qwen3Guard 两版 | **均匀高误报 + 保护力随离英语距离衰减**（0.6B 无耦合，$\rho=-0.23$，p=0.50） |
| PolyGuard | **两个失败集中在一个语言上**（阿拉伯语），跨语言正相关（$\rho=+0.65$，p=0.04） |

**对审计方法的含义**：**单一聚合分数同时隐藏了共同病根、系统间差异、以及"更强模型的增益绕过了最需要的语言"这三件事。** 只有"每语言 × 双向 + 免阈值排序"的报告能把它们分开。

### 4.4 罗马化印地语的示范（为什么必须双向报）

- 词表（Devanagari 条目）对拉丁转写**匹配不到** → 误报 **0.0%**（"看起来最公平"）+ 漏报 **100%**；
- 三个 guard 模型在这个语言上**误报最低**（22.7% / 19.9% / 56.7%）同时**漏报最高**（72.1% / 77.1% / 40.0%）；
- 只报一个方向，**所有系统都会让"它读得最差的语言"看起来被最公平地对待**。

## 五、局限性

1. **只有"工作示例"，没有完整验证**：H1 只在"现有系统是否达标"这一个方向上被测过；**H2 完全没测**；论文自己承认"针对 grooming / 胁迫 / 诈骗的对比测试集尚不存在"。
2. **绝大多数证据是仇恨言论与英语方言**。模式 7 在仇恨言论之外的适用性是**论证出来的，不是测出来的**。
3. **11 种语言没有一种是真正的低资源语言** → 本文很可能**低估**了它要讨论的不平等。
4. **测试集是合成的、模板化的**，且"按功能平行"而非"按翻译平行"，所以**每语言差异混合了系统行为与案例写法**。
5. **每个系统只测一个版本、一个操作点**。
6. **HateCheck 2021 年就公开**，可能与学习型系统的训练集重叠（对系统有利）。
7. **AUC 比较的是两组不同功能的用例，不是配对的最小差异对** —— 这是"两组比较"而非"逐对比较"。
8. **利益冲突**：三位作者都在做"行为式检测"产品，论文明确披露。

## 六、复现指南

### 6.1 复现要点

```
1. 系统：词表(HurtLex+wordfreq) / XLM-R toxic 分类器 / Qwen3Guard-0.6B / Qwen3Guard-8B / PolyGuard-Qwen
2. 数据：HateCheck + Multilingual HateCheck（11 语，含罗马化印地语）
3. 两个方向：无害对比样本误报率、隐式仇恨漏报率（各带 Wilson 95% 区间）
4. 免阈值：AUC（隐式仇恨 vs 无害形似），对照母语标注员平衡准确率
5. 统计：模板簇级 bootstrap（2,000 次）；差距用模板级置换（5,000 次）
6. 差距报告四件套：观察差距 / 等服务水平下的预期差距 / 超出量 / 置换 p 值
```

### 6.2 复现风险点

- **必须按模板簇重采样**，否则区间被低估（同一模板的用例不独立）。
- **必须报样本量与 Wilson 区间**，不能只报点估计。
- 标注员基准本身要审（法语 55% 的无害样本被判仇恨 → 门槛虚低）。
- 词表要固定频次过滤阈值（论文指出去掉频次过滤后英语误报升到 70.2%）。

### 6.3 对我们最有用的三件事

**（1）"最差类别"可能是统计噪声 —— 这条必须先算一遍再谈优化**

6.1 节的模拟结果直接打在我们的痛点上：

> 当**每个变体的真实错误率都是 10%**（即服务水平完全相同）时，**10 个变体各 100 例**的"最好减最差"差距，**期望值就有 9.2 个百分点**；每变体 400 例时仍有 **4.6** 个百分点。
> 而且**百分位 bootstrap 永远覆盖不到"真实差距为 0"**，因为"最大值减最小值"不可能是负数；它对"真实差距 10 点"的覆盖率只有 **64–76%**（名义 95%）。

**换算到我们身上**：如果 VULG 有 ~10 个二级类别、每类评估样本几百条，"VULG-HINT-EDGE 比最好类别低 8 个点"**完全可能只是极值统计的必然产物**。

**可落地动作（半天）**：
1. 拿现有评估集，按类别统计每类样本量；
2. **置换检验**：在"所有类别同水平"的零假设下（打乱标签后按类别重算），跑 5,000 次，得到"最好减最差"差距的**零分布**；
3. **判据**：若观察到的差距落在零分布的 95% 区间内 → **VULG-HINT-EDGE 不是真的最差，我们过去几周在追一个噪声峰值**。此时正确的动作不是"补边界 case"，而是**先把每类样本量提到能分辨 5 个点的水平（论文给的数字：基线 10% 时，检出 5 点差距需每类约 800 例）**。
4. **注意**：这个检验对所有"我们按类别看最差项"的分析都成立 —— 包括图审的分类别 FPR、改写的分风险类型保真度。

**（2）PORN / VULG 的边界争议，一半是模式 4（标注者视角）**

论文的模式 4 说：**标注者的信念被写进了标签**。我们对"暗示算不算 VULG"的长期争论，很可能不是"标准没写清"，而是**标注员之间对该不该算的信念本来就不同**，而这个分歧被压成了单标签。

**可落地动作**：
- 抽 500 条 VULG-HINT-EDGE 样本，**不做单标，做 3 人独立标 + 记录分歧**；
- 统计"三人一致 / 两人一致 / 全不一致"的占比；
- **判据**：若"全不一致"占比 > 20%，说明这个类别的**定义本身没有收敛**，此时训 tag-weighted loss 是在拟合噪声（不同标注员的信念互相抵消）。**正确动作是先做标注规范收敛（写正/反例），而不是加 loss 权重。**

**（3）政治 L2_30 的"地区差异"应该按"差距"报，而不是按"平均分"报**

论文的纪律对我们直接可用：**平均分好 + 差距大 = 对差距底部的人不好。** 政治 L2_30 各层级、各地区/议题的敏感度天然不均，用总体准确率汇报会掩盖"某些二级类完全不可用"。

**最小动作**：政治类按二级标签 × 关键议题维度做**双向报**（该拦没拦 / 不该拦拦了），并额外报"最好与最差二级类的差距 + 等服务水平下的预期差距"。**这比再训一版模型便宜得多，而且能直接回答"政治类到底能不能上线"。**

**（4）一个必须记住的反直觉结论**

> **能力越强，跨语言（跨类别）的不平等越大。**

0.6B → 8B，均值 0.65 → 0.81，极差 0.20 → 0.29。对我们的直译是：**如果我们的模型升级后总体指标变好但最差类别没动，这不是"还没调好"，这是"能力提升的收益绕过了最需要的部分"。** 遇到这种情况，继续 scale 或继续调 loss 都不会自动修复，**必须显式地针对最差类别做干预**。
