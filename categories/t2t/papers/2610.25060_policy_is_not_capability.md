## 一、背景与动机

### 动机

Guardrail 分类器被当成普通分类器来训练和汇报：给一个 held-out macro-F1，给一组公开 benchmark 的 catch rate，再给一个 over-refusal 数字，然后请读者横向比较。

这个汇报惯例里藏着一个**无声假设**：

> `unsafe` 是 prompt 的一个属性，所以两个系统在同一批 prompt 上打分，是在回答同一个问题。

**这个假设在部署里显然是错的。**

作者给的两个例子极其精准：

- "Reproduce the lyrics of this song" —— 对内容平台是违规，对写作助手是普通请求；
- "Tell me a dirty joke" —— 审核产品会拦，编程助手会答。

> **两者都不是关于字符串的事实，而是某个人写标注策略时做的一次决定。**

而这个决定，会被每一个用这些标签训练出来的模型**吸收进去**。

### 一个"意外获得"的实验条件

多数工作无法把"策略"和"能力"分开，因为一个项目只有一套标注策略。作者是**碰巧**拿到了这个条件：

在为某端侧助手构建 guardrail 时，**同一批 prompt 池被标注了两次**，相隔一个月，两套流程当时被判定准确度相当。它们**在六分之一的 prompt 上不一致**，而且分歧不是噪声，是系统性的——根源在于两套流程回答的是不同问题：

- **Policy A**：一个审慎的审核员会不会拦这条？（moderation-product rubric）
- **Policy B**：这是不是一个请求有害内容的请求？

### 对当前业务的重要性

⭐ **这是今天对"三维评测设计"最有价值的一篇——它不给你更好的模型，它告诉你哪些评测数字根本不能信。**

业务侧正在做的三件事，全部在这篇的射程内：
1. 层级风险标签（level1=ILLE/MINR/PORN/VULG/out_of_scope，level2–4 递进）——**标签定义即策略**；
2. 语义保真 / 安全提升 / 指令遵循损失三维评测——**每一维都可能被定义污染**；
3. 训练集标签审计（LLM 全量审计 7W 数据，PORN/VULG 边界混淆）——**PORN/VULG 边界混淆很可能就是策略分歧，而非模型能力问题**。

## 二、核心方法

### 实验网格（grid as a measuring instrument）

- **两个标注策略族**：Policy A（早期人工策展，审核产品口径）/ Policy B（后期 LLM-jury 重标，4 个大 instruct 模型 × 3 次采样，T=0.7）；
- **同一 prompt 池**：53,441 train / 5,936 val / 7,662 multilingual val（约 5.3 万条）；
- **10 个训练 arm**：在两个标签族之间做 mixing / re-weighting / anchoring / distilling / head-calibrating；
- **2 个模型规模**：ModernBERT-large teacher（394.8M）+ ModernBERT-base student（149.0M）；
- **共 20 个模型**，在 **15 个公开安全 benchmark、33,137 条 prompt** 上完全相同地评测。

> 作者定位很清醒：**贡献是诊断性的（diagnostic），不是方法性的。** 这个网格是一台用来测量"评测协议本身"的仪器。

### 三条策略进入模型的路径

1. **Route 1 — 蒸馏**：学生的 KD 软标签（$\tau=4$）；
2. **Route 2 — 训练混合**：$\mathcal{L}_{sup}$ 的标签来源与配比；
3. **Route 3 — head calibration**：冻结 encoder $\varphi$，只在小校准集 $D_{cal}$ 上重拟合 head（$|\psi| = 0.04$M，**占模型 0.03%**）。

论文 §5 的核心问题：**这三条路到底哪一条真正"安装"了策略？** 答案是——**不是 $\mathcal{L}_{sup}$。**

---

## 三、技术细节

### 任务与分类体系

分类器对单条 user prompt 输出：
- (i) 四粗类之一：`generic_safe` / `boundary_safe` / `harmful` / `compound`（**compound = 良性请求内嵌有害子请求**）；
- (ii) 24 维多标签向量，覆盖 Safety / Security / Privacy / Reliability 四个 pillar；
- 二分类 `unsafe` = `harmful ∪ compound`。

> 注意：该 taxonomy 是**专有的，不映射到 MLCommons 类别**。作者指出这正是产品 guardrail 的常态，也是为什么开箱即用的 guard 不能直接上。

### 损失函数

$$\mathcal{L}_{sup} = \text{4-class CE} + \text{24-way pillar BCE} + \text{harmful-span BCE}$$

（class-balanced sampler；学生额外加 4-class 与 pillar logits 的 KD 项，$\tau=4$）

### Route 3 的形式

$$\sum_{(x, y_A) \in D_{cal}} \mathrm{CE}\big(h_\psi(f_{\bar\varphi}(x)),\ y_A\big)$$

只动 0.03% 参数。

## 四、实验与结果

### 发现 1：训练语料里就装着 benchmark（§3）

| Benchmark | 与训练/验证池的重叠率 |
|-----------|---------------------|
| **JailbreakBench-benign** | **88%** |
| **OR-Bench-hard** | **82%** |
| OR-Bench-toxic | 0% |
| AdvBench | 2% |

> **受损最重的恰恰是 over-refusal benchmark** —— 因为它们的训练类别**是靠采集这些 benchmark 建起来的**。作者声明后续所有结论均已在去污染后给出。

### 发现 2：benchmark 的"定义敏感度"差异达 23 倍（§4）

在**架构与优化器固定**的前提下，只改变两个标签族进入训练的位置：

| Benchmark | 十个 arm 的分数极差 |
|-----------|-------------------|
| **HarmBench-copyright** | **0.99**（满量程 1.0） |
| **WildGuard-benign** | **0.043** |
| **差异倍数** | **23×** |

> 而且：**定义不稳定的 benchmark 同时也是 seed 不稳定的**；要把两者分开，需要报告一个几乎没人报的 **seed floor**。作者实测了一个，结论是这个 seed floor 让排序的中段**无法解释**。

### 发现 3：0.03% 的参数就能把分数推过整个量程（§5）

- 十个 arm 上：HarmBench-copyright 跨度 **0 → 100**；OR-Bench-hard over-refusal 跨度 **3.4% → 56.4%**；
- **最后一道监督信号携带某策略的四个 arm，同时占据两个 benchmark 的同一极端**（exact rank $p = 0.005$，最差情况 $p = 0.04$–$0.14$）；
- 而**检测能力本身没有变化**；
- 反例极具冲击力：一个**硬标签 100% 来自 Policy A**（40,327 / 40,327 行）、全量微调的 arm，在 HarmBench-copyright 上**只拿到 17.3 / 100**；
- **对蒸馏学生而言，即使所有硬标签都是另一套策略，teacher 的软标签照样把策略装进去** → **teacher provenance 是任何已发布 checkpoint 里一个未被记录的混淆变量（unrecorded confound）**。
- 这一切**在 data card 上不留任何痕迹**。

### 发现 4：验证集准确率测的是策略一致性，不是检测能力（§7）

- 用 Policy-A 标注的那个 split 给全部 20 个 arm 打分：与**标注者策略的一致性** $\rho = +0.74$，与**检测能力** $\rho = +0.34$；
- 而这个验证 split 本身有 **69.3% 落在 Policy-A 训练文件里**——这个重叠是作者把 §3 的审计跑在自己验证数据上才发现的。

### 主张（§8）

Guardrail 评测应把三件事作为**一等变量（first-class variables）**报告：

1. **contamination**（污染率）；
2. **a seed floor**（种子地板）；
3. **the definition they were graded against**（被评的是哪套定义）。

## 五、局限性

1. **单一专有 taxonomy、单一模型族（ModernBERT）**，结论外推到 decoder-only guard 或多模态 guard 需谨慎。
2. **"两套策略"来自一次工业事故而非受控设计**，Policy A/B 的具体差异无法穷举。
3. **诊断性工作，不给修复方案**（§8 只给最低限度的报告建议）。
4. **15 个公开 benchmark 主要是 T2T 侧**，对 T2I 专用安全 benchmark（如 T2ISafety、UnsafeBench）的定义敏感度未测。
5. **seed floor 只从这一套 codebase 测出**，不同实现的量级需重新测。

## 六、复现指南

### 可复现的审计动作（不需要复现整个网格）

**审计 1：benchmark 污染扫描**
- 对每个待用评测集，计算其与训练池/验证池的 n-gram 或 embedding 近重复率；
- 特别盯 over-refusal 类评测集（本文证明这类重叠最严重）。

**审计 2：定义敏感度测量**
- 固定架构与优化器，只改标签来源，看每个 benchmark 分数的极差；
- 极差大的 benchmark 标记为"定义驱动型"，其分数**不能跨团队比较**。

**审计 3：seed floor**
- 同配置多种子重跑，给出分数分布；
- 只有当组间差异 > seed floor 时，结论才成立。

**审计 4：teacher provenance 记录**
- 任何蒸馏/软标签来源必须进 data card；
- 已发布 checkpoint 若来源不明，其 benchmark 分数只作参考。

**审计 5：验证集自查**
- 把污染审计跑在自己的验证集上（作者就是这么发现 69.3% 重叠的）。

### 迁移到 T2I 输入侧改写评测的建议

1. **先给每一维评测标定"定义敏感度"**
   语义保真 / 安全提升 / 指令遵循损失这三维里，最容易被定义驱动的是**安全提升**（因为风险标签=策略）。建议在评测前先做一个小网格实验，量化每一维的定义敏感度，把"定义驱动型"指标从跨版本比较中剔除或标注。

2. **PORN/VULG 边界混淆：先验证是不是策略问题**
   业务当前最差类别是 VULG-HINT-EDGE，怀疑训练集标签不准。这篇给了一个更省事的假设优先序：**先确认两条边界上的标注是不是来自同一套策略口径**，再谈模型能力。如果标注口径本身不一致，改模型是无解的。

3. **层级标签体系要做"策略携带路径"审计**
   level1–4 层级标签本身就是一套策略。若训练中混入了不同来源（人工回流 / LLM 审计 / 蒸馏软标签），需要明确**最后一道监督信号来自哪**，因为它决定模型实际执行的口径（本文 Route 3 只动 0.03% 参数就翻转了整个量程）。

4. **评测报告模板改造**
   在改写模型的评测报告里固定加三行：**污染率 / seed floor / 被评的风险定义版本**。
