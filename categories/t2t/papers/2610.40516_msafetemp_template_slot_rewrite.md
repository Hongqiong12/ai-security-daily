# 把有害 prompt 拆成"框架 + 类型化槽位"，改写才做得动、评得全

## 一、背景与问题

### 动机

安全对齐严重偏向英语。已有公开多语言安全数据要么规模不够，要么**不遵循区域本地化的有害话题**——也就是说，对齐的覆盖面没有超出英语文化圈。

论文举的那个例子把问题说得很清楚：

> 拿一条模型稳定拒答的英语 prompt，翻译它，再按目标文化做本地适配（本地极端组织、历史暴行、社区特定污名词）——**同一个模型现在可能就照做了，即使有害意图完全没变。**

### 四条约束（这套 R1–R4 是全文的设计骨架）

论文把"要造出可用的多语言安全数据"拆成四条硬要求，每一条都对应一个具体的工程障碍：

| 编号 | 要求 | 对应的障碍 |
|---|---|---|
| **R1** | **危害保真**：每个变体都保留原始有害意图，合规回答仍然不安全 | 翻译/改写容易把危害洗掉 |
| **R2** | **语言正确性**：目标语言流利自然 | 否则测的是翻译质量不是安全 |
| **R3** | **文化真实性**：在合适处用本地实体，而不是只搬英语实体 | 纯翻译保留英语实体 |
| **R4** | **过度拒答控制**：每个有害模板必须产出配对的良性最小对 | 否则"低 ASR"可以靠"全部拒答"刷 |

### 真正卡住的地方（本文的方法论起点）

论文把 bottlenecks 列了四条，**第四条是全部方法的钥匙**：

1. 招母语者做敏感任务，贵且慢；
2. 人工 red-teaming 质量最高，但覆盖不到低资源语言；
3. **机器翻译产不出本地特定语境**；
4. **用其他语言模型做合成/翻译，会被生成器自身的拒答挡住**——因为内容按设计就是有害的。

第 4 条是关键：

> 请一个高度对齐的模型去翻译一条有害 prompt，结果很可能是**拒答**。文化适配、改写润色同理。于是扩增与本地化全被堵死。

**解法只有一条：把原始文本表示成一种"安全形式"。**

论文的表述极精确：

> **把"让 prompt 变得有害的那些词"抽出来，就把 prompt 分成了两个概念，而这两个概念单独看都不被视为有害**，从而允许后续的 prompt 修改。

⇒ **这就是"风险锚点外科替换"的形式化。** 不是重写整条 prompt，而是：

```
有害 prompt  =  框架（frame，中性）  +  类型化槽位（typed slot，承载风险）
```

槽位命名按其类型/意图，如 `<illicit_substance>`。**框架可以安全地翻译、改写、扩增；槽位可以独立重填。**

### 为什么这篇对我们要紧（三处直接命中）

**第一：它给了"改写模型自己拒答"这个实际卡点一个解法。**
我们的 T2I 安全改写模型（`safe_rewriter_online`）如果遇到"这条 prompt 太脏我不想处理"的情况，模板化路径可以绕开——**先抽锚点，再改写框架，最后重填槽位**。

**第二：它的良性最小对，正是我们 PORN/VULG 边界训练集该有的形状。**
"框架完全相同、只换槽位填充值" ⇒ **表面形式几乎一样、标签不同**。这是给边界类目造对照样本的正确做法，比"找更多同类样本"有效得多。

**第三：它给了政治 L2_30 层级口径一个零训练的检验方法。**
固定框架只换实体，看级别是否稳定。如果级别大幅漂移，说明层级判定绑的是实体而不是语义。

## 二、核心方法

### （1）四步模板构造管线

| 步 | 动作 | 校验 |
|---|---|---|
| **1. 抽取** | LM 抽出"让这条 prompt 真的有害"的单词或短语，替换成占位槽 | – |
| **2. 模板校验** | 第一个 judge 检查新模板**是否有效且自洽**（self-contained） | Judge #1 |
| **3. 翻译** | 用生成模型翻译**槽位标签周围的文本**（槽位本身不动） | – |
| **4. 翻译校验** | 第二个 judge 检查目标语言一致性、翻译质量、**槽位位置是否保留** | Judge #2 |

**英语作为目标语言时跳过第 3 步，但两个 judge 步骤都要走。**

**每个模板额外获得 2 个已验证的改述（paraphrase）⇒ 每个 seed × 每个语言有 3 个模板。**

### （2）三个填充分支（这是全文的核心设计）

模板准备好之后，槽位填充走三条路，各服务不同目标：

#### TR 分支 —— 通用有害变体（Translated / generic）

- 用多组槽位值的组合填充；
- 同时填**同一模板的两个已验证改述**，让同一有害意图有不同的措辞；
- judge 检查：**有害性、语言质量、连贯性、原始框架是否保留**。

#### OR 分支 —— 良性替代（Over-Refusal control）

这是最精巧的一处：**用相反方向填同一个槽位**。

> 一个模板可以产出一条"措辞像有害、但因为槽位值是良性的所以安全"的 prompt：**问句形式保留，意图变成普通用户请求**。

**两组良性对照（必须分开）：**

| 类型 | 定义 | 用途 |
|---|---|---|
| **direct controls** | 可以完整安全回答 | **过度拒答率只在 direct 上测** |
| **bounded controls** | 有用回答仍须保留可迁移的有害细节 | 只作为训练数据，**不进 OR 指标** |

这个 direct / bounded 的切分很重要：它避免了把"该部分拒答的样本"算成"过度拒答"。

#### PH 分支 —— 文化本地化（Post-Hoc localization）

- 为**每种语言**生成一张 **cultural card**：描述当地相关的群体、组织、事件、概念、机构；
- 用保守的 judge 标准检查"某个候选值是否合适作为槽位填充"；
- 填充后，**生成模型可以在实体周围做词形变化和改写**以保持语法与语言流畅——**judge 只检查结果**。

论文特别说明：cultural card 的生成 prompt 先在作者熟悉的几种语言上迭代精修，然后**全自动生成所有语言**。card 由 Gemma-4-31B-IT 生成、**Gemini Flash 3.6 验证**。

### （3）生成与判定的分离

| 角色 | 模型 |
|---|---|
| 生成（抽取/翻译/填充/改写/cultural card） | **Gemma-4-31B-IT** |
| 生成 judge | **GPT-OSS-120B** |
| 评测 judge | **GPT-OSS-Safeguard-120B** |
| cultural card 验证 | Gemini Flash 3.6 |

论文明确的设计原则：**`we separate generation from judging`**——生成者和判定者必须是不同模型族。并坦承 `model judges can fail systematically`，所以尽可能用显式检查，并报告剩余局限。

### （4）规模控制的两个经验值

| 旋钮 | 取值 | 论文的说法 |
|---|---|---|
| 每 seed×语言 的模板数 | **3**（1 主 + 2 改述） | – |
| 每模板的填充数 | **5** | 最多可得 **15** 个有害变体；`more paraphrases or more fills brought diminishing gains in diversity and quality` |

⇒ **15 是性价比拐点。** 这个数字对我们做改写评测的 K 值选择有直接参考价值。

## 三、技术细节

### 数据规模

| Track | Seed | 语言 | 模板（已验证/原始） | 有害 | 良性（direct+bounded） | Post-hoc |
|---|---|---|---|---|---|---|
| **WildGuard**（训练用） | 2,500 | **44** | 109,425 / 110,000 | **1,537,628** | 186,639 + 20,528 | 97,120 |
| **HarmBench**（仅评测） | 200 | **60** | 11,976 / 12,000 | 173,743 | 29,598 + 3,682 | 9,463 |

**种子来源：**

- HarmBench 的 200 条标准行为 → **held-out 评测集**。**丢掉了 contextual 与 copyright 两类**，理由是它们不由 prompt 本身定义、还需要额外信息，模板抽取效率低。
- WildGuardMix 的 2,500 条有害 prompt（`wildguardtrain` split）→ 扩成 44 种语言；**2,000 seed 及其全部后代进训练，剩余 500 做 held-out 测试**。

⇒ **provenance-tracking 的关键：按 seed 切分，保证测试 seed 的任何后代都不进训练。** 这是模板化扩增必须做的防泄漏。

### 多样性度量（这四个数说明扩增没塌成少数填充）

| 指标 | 值 |
|---|---|
| 有害槽位的**不同实体数** | **> 2.8M** |
| 有害槽位 distinct-to-total 比 | **≈ 0.70** |
| 良性槽位 distinct-to-total 比 | **0.94**（更分散） |
| 任一实体在某语言有害填充中的占比 | **< 1%** |
| 高资源 vs 低资源语言的多样性差异 | **不显著** |

重复集中在两类：**窄槽位类型的典型实体**（如 `<software_vulnerability>` 上的 EternalBlue）、以及 **post-hoc 槽位**（设计上就是从每语言的策展池里取）。

### 标签体系

源数据集没有共享的细粒度标签集，所以论文用 **LinguaSafe taxonomy** 给 prompt 分类：**一个 primary class + 一个更精确的 secondary class**。

⇒ 这个"一级 + 二级"的结构跟我们 L1–L4 的分层是同构的，而且只有两级——**说明两级在这个任务上够用**。

### 人工验证

IRB 批准的研究，安全专家 + 母语/流利使用者：**15 个独立评分、11 种语言、600 条判断**。评的是**自然度与文化贴合度**。规模有限（每种语言 1–2 位），论文自己列为局限。

## 四、实验与结果

### 英语单语评测会误判多语言安全

| 模型 | HarmBench Orig. ASR | TR | PH |
|---|---|---|---|
| Olmo-3.1-32B-Instruct | **0.0** | **13.7** | **11.9** |
| Apertus-70B-Instruct-2509 | 8.5 | **13.0** | 6.0 |
| Apertus-8B-Instruct-2509 | 8.5 | 10.1 | **12.2** |
| Gemma-4-31B-IT | 6.5 | 4.2 | 2.5 |
| Llama-3.3-70B-Instruct | **13.0** | 5.3 | 2.6 |
| Qwen3.5-27B | 0.5 | 0.4 | 0.1 |

**最刺眼的一行是 Olmo：英语 0.0% → 翻译后 13.7%。**

⇒ **一条在英语里 100% 被拒的 prompt，翻译一下就能打穿。** 论文的说法：`attacks that fail in English succeed once translated`。

在 held-out WildGuard 上：**翻译变体打穿 Olmo / Gemma / 两个 Apertus 的频率是原始英语 seed 的 2.4–4.4 倍。**

**Llama 是反例：它在英语里最容易被打穿（13.0%），翻译后反而降到 5.3%。** ⇒ **"英语评测低估风险"不是一个普适规律，方向依模型而定。** 这一点很重要——不能反过来假设"翻译一定更难"。

### 本地化 vs 翻译：打穿的**不是同一批行为**

这是本文对"覆盖度审计"最有价值的一条：

| 度量 | 值 |
|---|---|
| PH vs TR 打穿行为的 **Jaccard** | **0.40 – 0.45** |
| **只在本地化实体下出现的失败** | **约 45%** |
| PH 降低 ASR 的模型 | HarmBench 上 5/7；WildGuard 上 6/7 |
| PH 升高 ASR 的模型 | Apertus-8B、Olmo 指令版 |

**Jaccard 0.40–0.45 的含义极重：**

> **翻译版和本地化版打穿的行为，只重合不到一半。**

也就是说，**"危害程度相当"不等于"覆盖同一批失败"**。而且方向不一致（有的模型 PH 更高、有的更低），所以**不能用 PH 替代 TR，也不能只看总量**。

⇒ 直接推论：**任何"覆盖度"统计如果把"同一框架的不同实体填充"合并成一个簇，就会系统性高估覆盖。** 论文的数据是：合并之后看起来覆盖了，但打穿的行为只重合 40–45%。这一条直接打在"向量聚类查覆盖"这个做法上。

### 单 fill 评估会漏掉一半失败模板

> **只被部分填充打穿的模板，贡献了全部不安全回答的 60%–100%；每个模板只评一个 fill，会漏掉约一半被打穿的模板。**

⇒ **这是"评测样本量"最硬的一个论据。** 我们现在的改写评测如果每个 prompt 只做一次改写、只评一次，就会系统性低估失败率，误差量级是"漏一半"。

### 改述模板的影响依任务而定

- **WildGuard**：两个改述都比主模板更多地打穿全部 7 个模型（最多 **+3.7%**）；
- **HarmBench**：没有这个效应。

论文的解释：**HarmBench 的一条行为就是一条直白请求，改述基本只是复述；WildGuard 的 seed 是一个对抗性脚手架，改述会改变它的框架。**

⇒ **"改述"的效果取决于原始样本是不是一个"框架"。** 这对我们判断"该不该在改写里做改述"是个提示：如果原 prompt 是直白请求，改述无收益。

### 过度拒答：低 ASR 可以买

| 模型 | 良性对上的拒答率（OR） |
|---|---|
| GPT-OSS-20B | **31.8 – 45.1** |
| Qwen3.5-27B | 3.5（HarmBench）/ 17.0（WildGuard） |
| Apertus-v1.5-8B-IT | 25.1 / 29.6 |

⇒ **GPT-OSS-20B 在 ASR 上近乎完美（0.0–0.5%），代价是拒掉 32–45% 的无害请求。** 这就是为什么 R4 是硬要求。

论文还顺手指出：**OR-Bench 里约 20% 的样本其实是有害的、应该被拒** ⇒ **OR-Bench 上的最优表现本来就高于 0%**。这个观察对我们用自己的"过拒率"指标时很重要——分母里如果混了该拒的样本，指标本身有偏。

### 训练实验（SFT + DPO）

设置：一个 epoch，混合"拒答 + 良性回答"（Gemma-4-31B-IT 生成、GPT-OSS-120B 验证）+ 通用指令数据，**loss 只在 assistant token 上**，然后用**从微调模型自身采样的偏好对**做 DPO。

| 模型 | AyaRT ↓ | PolyTox ↓ | HB ASR ↓ | WG ASR ↓ | OR-Bench ↓ | MMLU ↑ | GSM8K ↑ |
|---|---|---|---|---|---|---|---|
| Apertus-8B IT | 0.7 | 4.7 | 10.3 | 10.5 | 82.6 | 61.6 | 63.3 |
| + SFT | 1.1 | 11.7 | 3.0 | 2.3 | **27.4** | 60.1 | 50.3 |
| + SFT + DPO | **0.1** | 5.8 | **1.4** | **0.5** | 34.6 | 61.7 | 51.4 |
| Apertus-v1.5-8B IT | 0.5 | 7.8 | 2.3 | 2.7 | 83.2 | 70.2 | 80.2 |
| + SFT + DPO | 0.2 | 6.1 | 1.3 | 0.5 | **38.4** | 64.0 | 72.4 |
| Olmo-3-7B IT | 2.1 | 7.0 | 21.5 | 15.1 | 52.5 | 67.1 | 83.0 |
| + SFT + DPO | 0.5 | 5.7 | **2.9** | **0.8** | 49.8 | 62.3 | 76.2 |
| Llama-3.1-8B IT | 0.8 | 4.4 | 15.9 | 10.5 | **4.6** | 72.0 | 84.0 |
| + SFT + DPO | 0.5 | 6.1 | **2.0** | **0.8** | 24.8 | 63.6 | 68.5 |

**四条读数：**

1. **ASR 普遍压到 1–3%（Olmo 21.5 → 2.9，Llama 15.9 → 2.0）。** 这是实打实的收益。
2. **能力有代价，且代价集中在数学上**：MMLU 降 1–8 点，但 **GSM8K 降 8–16 点**（Llama 84.0 → 68.5）。论文归因为"通用指令混合的质量"。
3. **过拒率变化依模型而定，且方向可以很糟**：Llama IT 的 OR-Bench 只有 **4.6**（本来极低），训完涨到 24.8；Olmo 从 52.5 到 49.8（几乎不变）。
4. **DPO 能收回过拒，但收不回能力**：Apertus 的 OR 从 27.4 回到 34.6（**反而更高**？注意这里是 OR-Bench 越低越好，Apertus-8B 的 SFT 是 27.4、DPO 后 34.6，是**变差**）；Apertus-v1.5 从 45.6 → 38.4（改善）。⇒ **DPO 对过拒的作用不稳定，依模型而定。**

⇒ 论文自己的结论比较克制：`MSafeTemp can help reduce existing ASR and OR in instruct models or help maintain optimal safety performance when used on top of base pretrained model`。

## 五、局限性

1. **管线高度依赖自动 LLM 判定。** 论文自己列为第一条。两个异构 judge 在 5,000 条样本上保住了结论方向，但**没有做完整的 judge 模型消融**。
2. **多元文化质量同样来自 LLM-as-a-judge。** 人工研究只有 15 个评分、11 种语言、600 条判断，**每种语言 1–2 位评审**。⇒ R3（文化真实性）基本上是自动判的。
3. **危害标签从英语 seed 继承给所有后代——这是最严重的一条。**

   > 论文原话：`a localized entity, such as an extremist group or a regional slur, can make a variant more severe than its inherited label suggests, so re-labeling a sample of localized variants remains future work.`

   ⇒ **本地化可以让一个变体比它继承的标签更严重。** 这是一个**标签层级漂移**问题，跟我们的 L1–L4 层级直接对应。

4. **训练消融只做了 SFT + DPO，RL 方法留作未来工作。** ⇒ 与我们 RL 改写线的直接可比性有限。
5. **SFT 性质激进**，论文自己说 `aggressive nature of SFT training and stronger weight editing` 导致了小幅度通用能力下降。
6. **全是单轮、固定模板的 prompt。** 多轮与迭代攻击未覆盖。
7. **只做了文本。** 完全没有图像，也没有讨论"槽位化的思路能不能迁移到图像描述"（这恰是我们最关心的迁移点，论文没做）。

## 六、复现指南

### 数据与代码

- 数据集：`https://huggingface.co/datasets/swiss-ai/MSafeTemp`（**需要接受内容警告才能访问**）
- 代码：`https://github.com/swiss-ai/msafetemp`
- 许可：宽松许可（permissive），含有害变体、jailbreak wrapper、良性对、拒答回答、管线 prompt、聚合结果
- cultural cards 全部语言公开

### 最小可复现路径（给我们自己用）

**实验一：模板化改写 vs 整段改写（1 天，零训练，最该先做）**

```
输入：100 条我们线上被判高风险、需要改写的 prompt
路径 A（现状）：整段改写 —— 直接让改写模型输出一条安全版
路径 B（模板化）：
   1. 抽风险锚点 → 替换成类型化槽位（<sexual_act> / <body_part> / <age_marker> ...）
   2. 只改写框架（用现有改写模型，输入是"框架 + 槽位标签"，不含风险原文）
   3. 重填槽位为安全值
输出对比：改写成功率 / 语义保真 / 风险下降
```

**判据（两条，任一条成立就该走 B）：**

| 判据 | 阈值 | 含义 |
|---|---|---|
| A 路径的**拒答率**（改写模型拒绝处理） | **> 5%** | 改写模型自身对齐在挡路，模板化能绕开 |
| A 路径的**语义坍缩率**（改写后意图丢失） | **> 15%** | 整段改写在做"过度清洗"，模板化能锁住框架 |

**实验二：良性最小对造边界样本（1 天，最直接可用）**

这是本文对 PORN/VULG 边界最直接的贡献：

```
对每个易混类目对，造三段式样本：
  样本 1（明确 PORN）：框架 F + 高风险槽位填充
  样本 2（边界 VULG）：同一框架 F + 中间态槽位填充
  样本 3（良性最小对）：同一框架 F + 良性槽位填充
```

**三段的框架完全相同，只有槽位填充值变。**

判据：
- 若模型在 1/2/3 上呈**单调**下降 ⇒ 边界学对了；
- 若在 2 上出现**非单调**（比 1 或 3 都高/都低）⇒ 模型在按表面形式判，不是在按锚点判；
- 若 2 与 1 的分数**几乎相同** ⇒ 中间态没有被表示，说明我们的类目表缺一个中间档。

⇒ **这比"去找更多边界样本"有效得多，因为它控制了框架这个混杂变量。**

**实验三：政治 L2_30 层级口径检验（半天，零训练）**

这是我认为本文最被低估的一个迁移：

```
Step 1  从 L2_30 相关训练样本里，把 prompt 拆成（框架, 实体）
        —— 实体 = 地区名 / 人物 / 事件 / 机构
Step 2  固定框架，只替换实体（同一 L2 子格内的不同实体，以及跨子格的实体）
Step 3  人工复判每条变体的 L4 级别（不看原标签）
Step 4  统计级别漂移
```

**判据表：**

| 漂移 > 1 级的比例 | 结论 |
|---|---|
| **< 10%** | 层级口径绑的是语义，稳。加权训练有意义 |
| **10–30%** | 轻度绑实体，需要补"实体无关"的判别维度 |
| **> 30%** | **层级口径绑的是实体不是语义。改标签无用，必须改定义** |

⇒ 这条判据能一次结束"L2_30 该调 alpha / 该改标签 / 该改定义"的三选一。

**实验四：单 fill 漏检率（半天）**

```
对 50 条高风险 prompt，各做 3 个改写变体（用同一模型、不同种子）
报两个口径：
  · "3 个变体里至少 1 个失败"   ← 真实风险
  · "3 个变体全部失败"          ← 我们现在的口径（如果只评一次）
```

判据：**前者 ≥ 2× 后者 ⇒ 我们的评测在系统性低估失败率。**

对标锚点：`只被部分填充打穿的模板贡献了全部不安全回答的 60%–100%`；`每个模板只评一个 fill 会漏掉约一半被打穿的模板`。

### 需要注意的实现坑

1. **槽位必须带类型标签，不能是匿名 `<X>`。** 论文用的是 `<illicit_substance>` 这种命名式槽位。匿名槽位会让"按类型重填"无法进行。
2. **翻译时槽位不能进翻译器。** 论文的表述是 `translating the surrounding text around the fixed placeholder tags`。如果槽位被翻译，类型语义会漂。
3. **良性对必须分 direct / bounded。** 混在一起算过拒率，会把"该部分拒答"算成"过度拒答"。
4. **OR-Bench 的分母本身有偏**（约 20% 样本其实有害）。用外部过拒基准时必须先查这一点。
5. **按 seed 切分，不按样本切分。** 一个 seed 的后代必须整体落在同一侧，否则模板化扩增会造成严重泄漏。
6. **改述的收益取决于原样本是不是"框架"。** 直白请求改述≈复述（无收益）；对抗性脚手架改述会改变框架（有收益）。
7. **别把"翻译版"和"本地化版"合并统计覆盖度。** Jaccard 只有 0.40–0.45，合并就高估。

### 一句话结论

> **整段改写做不动的时候，把 prompt 拆成"中性框架 + 类型化风险槽位"，框架可以放心改写，槽位可以受控重填。而且这个拆法顺手给出了边界类目的正确样本形状和政治层级的检验方法。**
