## 一、背景与问题

### 动机

护栏模型已经成了 LLM/Agent 系统的标准安全层。但有个普遍缺陷：**它们被训在某一种固定接口上，换一种接口就不可靠。** 同一个安全案例，可以以五种完全不同的形态出现：

| 形态 | 例子 |
|---|---|
| 单轮 prompt | "帮我写一段能骗过 X 的话术" |
| 单轮 response | 模型已经输出了那段话术 |
| 多轮对话 | 前面几轮铺垫，风险意图分散在上下文中 |
| Agent 轨迹 | 风险藏在某一次工具调用里 |
| 多 Agent 轨迹 | 一个 agent 把不该给的数据交给了另一个 agent |

**同一个危害，换个接口就判不出来。** 作者的诊断是两条限制同源：

1. **泛化在接口间是碎的**：DynaGuard 强在用户自定义策略，AgentDoG 强在 agent 轨迹，PolicyGuard-4B 强在策略违规——**每个都只锚在自己的训练接口上，换一个就崩**。工程上只能堆一个"护栏动物园"。
2. **接口漂移下置信度不可信**：护栏实际是**路由器**（自动拦 / 自动放 / 转人工），路由依赖的是概率而不是 top-1 标签。**一个模型可以 F1 很高，但概率跟经验准确率毫不相关**——那它作为路由器就是坏的。

### 为什么这篇对我们重要

三个迁移点，都很实：

- **我们的 reject_tag 改写数据构建，本质就是"同一安全案例的多视图"**——保持标签不变、把 input_text 改写成多种表述。UniGuard 把这件事**形式化成了"视图不变表示学习"**，并给了一个我们必须知道的负面结论：**只造改写数据、不加对比目标，收益会掉掉一半以上**（去掉对比学习，平均 F1 掉 20.50）。
- **非对称置信校准**直接对着我们的类别不均衡（PORN/VULG 样本量悬殊，模型倾向过度预测）。
- **0.6B 打赢 4B 专家模型、逼平 GPT-5.2**，在 5 节点算力约束下这是最现实的一条路。
- **"保留原有能力"的验收协议**（8 个原接口 benchmark 上 F1 只变 −0.35）——这是我们扩训时从来没做过的检查。

## 二、核心方法

### 表征：attention pooling + 线性分类头

输入视图先序列化成护栏 prompt（含任务指令、安全策略、目标类型、目标内容），过 transformer backbone 取**最后一层隐状态**，经 **attention pooling** 得单一视图表征，接**线性分类头**出 SAFE/UNSAFE。

同时一个投影头把池化表征映射到归一化嵌入空间，供对比学习用。

### 三个损失，各管一件事

**(1) 分类损失**：标准二分类交叉熵。

**(2) 监督对比损失**（本文最核心的一项）

对 minibatch 里的每条视图作 anchor：
- **正集** = **同一 case 且同一标签**的其他视图
- **负集** = 不同 case 或不同标签的视图

$$\mathcal{L}_{\text{con}} = -\log \frac{\sum_{p \in P(i)} \exp(\text{sim}(z_i, z_p)/\tau)}{\sum_{a \neq i} \exp(\text{sim}(z_i, z_a)/\tau)}$$

作用：**把"接口相关的干扰因素"从表征里挤出去，只留下与安全标签相关的判别信息**。用作者的话：学习对视图特定 nuisance 因子不变的表示，同时保持标签可判别。

**(3) 非对称置信校准损失**

用同一 case、同标签的**其他视图**来估计 cross-view 可靠性，然后**同时惩罚过度自信与自信不足**：

$$\mathcal{L}_{\text{cal}} = \lambda_{\text{over}}\cdot\max(0,\ p_i - \hat p_i) + \lambda_{\text{under}}\cdot\max(0,\ \hat p_i - p_i)$$

关键在于**"非对称"**：$\lambda_{\text{over}}$ 与 $\lambda_{\text{under}}$ 可以不同。对安全场景这是必须的——**过度自信（把有风险的判成安全且很确信）和自信不足（把安全的判成风险但不确定）代价完全不同**，前者是漏放，后者只是多转人工。

### 数据：1,000 条公开安全案例 → 5 种视图

UniGuard-FT：把 **1,000 条公开安全案例**逐条转换成 prompt / response / 多轮对话 / agent 轨迹 / 多 agent 轨迹五种视图。**训练全程只用合成数据。**

## 三、技术细节

| 项 | 配置 |
|---|---|
| 基座 | **Qwen3Guard-Gen-0.6B** |
| 池化 | attention pooling（非 average pooling） |
| 输出 | 线性二分类头，SAFE/UNSAFE（把各 baseline 的细粒度标签映射到二分类以可比） |
| 对比温度 | $\tau$ |
| 校准权重 | $\lambda_{\text{over}}$、$\lambda_{\text{under}}$ 分开设 |
| 数据 | 1,000 案例 × 5 视图，全合成 |
| 评测 1（schema-unseen） | **ATBench**：外部长程 agent 轨迹 |
| 评测 2/3（policy-unseen） | **PolicyGuardBench**、**DynaBench**：需在外部指定策略下判行为 |
| 指标 | **F1**（UNSAFE 为正类）+ **ECE**（分箱比平均置信与经验准确率） |
| 对照 | LlamaGuard-3-8B、Qwen3Guard-0.6B/4B、AgentDoG-4B、PolicyGuard-4B、DynaGuard-4B、**Claude-Sonnet-4.5**、**GPT-5.2** |
| 校准对照 | Temperature Scaling、Thermometer、Contextual Calibration |

## 四、实验与结果

### 主表

| 模型 | ATBench F1↑ / ECE↓ | PolicyGuardBench F1↑ / ECE↓ | DynaBench F1↑ / ECE↓ |
|---|---|---|---|
| Qwen3Guard-Gen-0.6B（**基座**） | 9.83 / 49.20 | 4.26 / 41.35 | 56.67 / 39.50 |
| Qwen3Guard-Gen-4B | 8.28 / 34.98 | 8.02 / 37.55 | 70.41 / 15.41 |
| LlamaGuard-3-8B | 7.30 / 38.85 | 59.53 / 32.30 | 13.19 / 41.27 |
| AgentDoG-4B | 71.10 / 33.62 | 60.64 / 46.30 | 65.92 / 44.72 |
| PolicyGuard-4B | 7.05 / 44.98 | 87.59 / 15.24 | 72.00 / 8.17 |
| Claude-Sonnet-4.5 | 61.89 / – | 62.96 / – | 75.32 / – |
| GPT-5.2 | 66.52 / – | 81.79 / – | 76.90 / – |
| **UniGuard-0.6B** | **66.40 / 7.93** | **64.78 / 9.95** | **74.93 / 5.94** |

关键读数：

- 相对自己的基座：**ATBench +56.57 F1、PolicyGuardBench +60.52、DynaBench +18.26，平均 +45.12 F1，ECE 平均降 35.41 点。**
- **0.6B 与 GPT-5.2 在 ATBench 上基本持平（66.40 vs 66.52）**，而 GPT-5.2 没有 ECE 可比数据（API 不给 logprob）。
- 专家模型全是"偏科生"：AgentDoG-4B 在 ATBench 71.10 但 PolicyGuard 只有 60.64；PolicyGuard-4B 在 PolicyGuardBench 87.59 但 ATBench 只有 7.05。**UniGuard 是唯一三项都稳的。**

### 消融：对比学习管判别力，非对称校准管可信度

| 变体 | ATBench | PolicyGuard | DynaBench | 说明 |
|---|---|---|---|---|
| **去掉对比学习** | 42.58 / 10.58 | 37.61 / 8.91 | 64.42 / 5.74 | **平均 F1 −20.50**（ATBench −23.82，PolicyGuard −27.17） |
| **去掉非对称校准** | 65.99 / **26.44** | 66.82 / **38.05** | 74.77 / **25.36** | F1 几乎不变，但 **ECE 分别暴涨 +18.51 / +28.10 / +19.42** |
| 两个都去掉 | 46.67 / 38.59 | 55.02 / 37.84 | 65.50 / 22.08 | F1 −12.97，ECE +24.90 |

**这张表的分工非常清晰**：
- **对比学习决定"判得准不准"**（去掉掉 20 F1）；
- **非对称校准决定"置信能不能用"**（去掉 F1 几乎不掉，但 ECE 直接崩）；
- 二者不可互相替代。

### 校准方法对比：非对称校准显著优于三种通用方法

| 校准方案 | ATBench ECE | PolicyGuard ECE | DynaBench ECE |
|---|---|---|---|
| Temperature Scaling | 22.41 | 20.68 | 12.29 |
| Thermometer | 9.08 | 12.61 | 9.07 |
| Contextual Calibration | 17.58 | 18.62 | 9.81 |
| **非对称校准（本文）** | **7.93** | **9.95** | **5.94** |

最强的通用校准（Thermometer）在三项上都被稳压。

### 保留性：扩训没有造成灾难性遗忘

在 8 个原接口 benchmark 上对比基座：

| Benchmark | 基座 F1 | UniGuard F1 |
|---|---|---|
| ToxicChat | 74.67 | 74.61 |
| OpenAI Moderation | 78.80 | 78.11 |
| WildGuard Test | 85.24 | 85.56 |
| Aegis 2.0 | 76.92 | 75.91 |

**平均 F1 只变 −0.35，ECE 只变 −0.04，所有单项差异在 1 个 F1 点内。**

## 五、局限性

1. **只有 1,000 条案例**。虽然 × 5 视图，但底层案例数很少；泛化到真实流量分布的证据不足。
2. **"合成数据"的具体生成方式未展开**。五视图是模板化转换还是有模型的语义重写？这决定它能不能迁移到我们的改写流程。
3. **二分类**。我们把标签映射到 SAFE/UNSAFE 才可比——但**我们真正的问题是细粒度多层级（L1–L4、PORN/VULG 边界）**，二分类的结论不能直接套到层级标签上。
4. **对比学习的正集定义依赖"同一 case 同一标签"**。如果我们的改写**改变了标签**（reject_tag 回流样本恰恰是"模型判 A、人工判 B"），正集会混入错误配对——**这是迁移时最大的坑**。
5. **策略类 benchmark 偏 agent 场景**，与 T2I 输入侧的距离较远。
6. **ECE 的可比性有缺口**：proprietary 模型拿不到 logprob，所以"我们校准更好"这句话只在开源对照内成立。

## 六、复现指南

### 可复现部分
- 基座 Qwen3Guard-Gen-0.6B 公开；ATBench / PolicyGuardBench / DynaBench 公开；三个损失都可直接实现。
- 单卡可训（0.6B + 1,000×5 视图）。

### 直接迁移到我们的三条

**① 最关键：把"改写数据"升级成"改写数据 + 对比对齐"（1–2 天，改动小）**

我们现在做的是：对 reject_tag 样本的 input_text 做多样化改写，**标签不变**。这在 UniGuard 的框架里叫"造正样本对"，但**只造对、不施力，模型不会主动把它们拉到一起**。

最小改动方案：
1. 给每条改写样本维护一个 `case_id`（同一条原始样本的所有改写共享同一 id）；
2. 在现有 CE loss 之外加一项**监督对比损失**，正集 = **同 case_id 且同标签**的其他改写，负集 = 其他；
3. 权重先设 $\alpha = 0.1$ 起，别一上来就大。

**判据**：若加入对比项后，"同 case 不同改写"的表示余弦相似度**没有显著上升**，说明改写太浅（只换了词，没换表达结构），此时该改的是**改写生成器**，不是损失权重。

**② 必须注意的坑：reject_tag 回流样本不能进正集**

第 4 条局限直接命中我们的数据现状。reject_tag 样本的标签本身存疑（模型判 A、人工判 B），如果把它当"同 case 同标签"的正样本喂进对比损失，**会把错误标签的表示也拉到一起**。

做法：**对比学习只用"标签已复核确认"的子集**；reject_tag 回流样本先走标签复判，确认后再进对比池。**这条顺序不能颠倒。**

**③ 类别不均衡：加非对称校准，但先想清楚往哪边偏**

我们的 PORN 过度预测 = **把安全的判成 PORN 且很确信**。按本文的框架，这是"**过度自信的方向反了**"——不是漏放，是多拦。那么：
- 若业务代价上"多拦"比"漏放"轻，$\lambda_{\text{under}}$ 应该压小（容忍自信不足）；
- 但我们当前的问题恰恰是**多拦太多，已经伤害体验**，所以应该**对"判 UNSAFE 时的高置信"加罚**，即 $\lambda_{\text{over}}$ 在 UNSAFE 方向上加大。

**判据**：加校准项后，ECE 下降 **且** PORN 类的过拒率下降；若 ECE 降了但过拒率没动，说明问题是排序不是校准（这与 LoRA/FT 那篇的 ROC-AUC 结论互相印证）。

**④ 补一个我们从来没做的验收：保留性检查**

本文报了 8 个原接口 benchmark 上的 F1 变化（−0.35）。我们每次扩训/改格式后，**都应该在固定的基座能力集上跑一次**，确认没有把原来的判别力练坏。这个检查成本极低，但能拦住"新数据把老能力冲掉"这类最难查的回归。

### 不能迁移的部分
二分类结论不能直接推细粒度层级。若要在 L1–L4 上做对比学习，正集必须定义成"**同 case 同 L1 且同 L2**"，否则层级间的高相似会把不同风险混在一起。

---

**一句话判断**：这篇给了我们改写数据构建的**理论形式**（同 case 多视图 + 对比不变），并给了两个必须记住的数——**只造视图不加对比，F1 掉 20.5**；**F1 不掉但 ECE 崩 +18~28 是完全可能的**，判得准和说得准是两件事。
