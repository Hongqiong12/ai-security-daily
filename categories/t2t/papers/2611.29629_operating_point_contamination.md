## 一、背景与问题

### 动机：部署点在极低误报区，而公开 benchmark 常与训练语料共享身份

人脸验证上线时选一个阈值使 **FMR ≤ 10⁻⁶**，再报对应的 FNMR。但广泛使用的 benchmark 可能与模型训练语料**共享身份**。先前工作（Wu et al., 2024）把由此产生的 optimistic bias 量成「10 折准确率上最多 +1.01 个百分点的**加性**小偏差」。

本文的判决：**偏差既不小、也不是常数，而是随 FMR 下降增长的乘性误差**。

### 与本仓库主线的关系

1. **误杀率 5.2% / 漏过率 3.42% 运营基线本身需要被审计**。用户把这两个数当硬约束；本篇说明若评测集与训练/参考集有身份或近重复重叠，**低误杀区的读数会虚高一个数量级**，而且越往「低误杀」调，偏差越大。
2. **per-category threshold tuning / precision-recall trade-off**：低 FPR 叶子格恰是最危险的地方；按叶子单独调阈值前必须先查该格的评测集重叠。
3. **conformal / risk-controlled operating point**：论文给出「最小可报告 FMR」概念（评测单位不够就别报该 operating point），直接对应 coverage / 分母口径纪律。
4. **评测集构建与多版本回归**：与 11-23「跨评测集泛化缺口」、11-24「固定分母」合流 —— **分母不干净，所有版本对比都不可信**。
5. **与 23685 配对**：一个证明误杀有表示决定的结构性下界，一个证明你读到的误杀率可能是污染的。⇒ 顺序应是「审计评测集 → 体检表示可判性 → 最后调阈值」。

## 二、核心方法

### 2.1 null-calibrated overlap audit（不用手调阈值）

把重叠检测器**校准到零分布**：在 masked-self null 上取 `(1−β)` 分位作切线，报告 `β = 0.1%`，即**构造性地把审计假阳性率钉在 0.1%**，而不是拍一个相似度阈值。这比「人工挑 0.7 余弦阈值」可复现得多。

### 2.2 2×2 干预设计（把「去重叠」与「去重复」分开）

固定模型权重不变，**只从测试集移除**被标为重叠的身份，配 **size-matched random removal** 对照，并做 deduplication（`T=0.70`）。⇒ 能把「少了难样本」与「少了重叠身份」分开，避免把子集规模/难度效应误读成污染效应。所有 FNMR 置信区间用 **B=2000 bootstrap**。

### 2.3 机制：impostor tail 变短 → 阈值左移

重叠身份让冒名分布尾部变短，于是同一 FMR 目标对应的阈值被推低，读出的 FNMR 被系统性压低。**这不是模型变好，是分母被换了**。作者还指出偏差**不会在模型间抵消**：把「本模型 vs 公开基线」的表观优势削掉一半。

### 2.4 最小可报告 FMR（resolvable-FMR floor）

`FMR` 需 `10/FMR` 量级独立比较才可报。作者首次直接测出 **IJB-C 在 FMR=10⁻⁶ 只有 2.7M 有效独立冒名比较**，低于通行报告规则；推导出 IJB-C 的最小可报告 FMR ≈ **6×10⁻⁵**。⇒ 低于该值的读数不是「准确」，是**不可解析**。

## 三、技术细节

### 3.1 重叠审计读数

| 项 | 值 |
|---|---|
| 相对 WebFace42M 标为 present 的 MS1MV3 身份 | **88.6%** |
| IJB-C subjects 标为 present | **14.3%**（510 / 3,567） |
| 尽管 WebFace260M 已发布 de-overlap 且点名 IJB-C | 仍残留 |
| 人工复核 100 个 flagged IJB-C subjects 确认率 | **69.2%** ⇒ 估计残留重叠 **~9.9%** |
| 审计假阳性率 | 构造性 **0.1%**（masked-self null, β=0.1%） |
| 100 个 flagged subjects 中 148 above（正文口径） | 按原文保留，不做外推 |

### 3.2 核心结果：固定模型，只删重叠身份，FNMR 抬升倍数

| FMR | 移除重叠身份后 FNMR 增幅 | 同规模随机移除 |
|---|---|---|
| 10⁻⁴ | **3.6×** | 无此效应 |
| 10⁻⁵ | **6.3×** | 无此效应 |
| 10⁻⁶ | **13.9×** | 无此效应 |

⇒ **operating point 越低，虚高越严重**（约一个数量级，10⁻⁴→10⁻⁶ 从 3.6× 到 13.9×）。与先前「最多 +1.01pp 的加性小偏差」直接冲突。

### 3.3 辅助数字

- 先前后作报 LFW 46.93% 身份重叠、published LFW accuracy 99.82%；Zhu et al. 报 `FNMR@FMR=10⁻⁵` 为 2.98%（WebFace42M）vs 9.88%（MS1MV2）。
- IJB-C naive 15.6M subject pairs / measured `N_eff` 6.2M / **FMR=10⁻⁶ 下有效独立比较仅 2.7M**；`10/FMR` 需 10⁷–10⁹ 比较；FMR=10⁻⁵ 仅 3.1 次匹配、10⁻⁶ 时 ~10 次误差、**±62% 不确定度**。
- 修复协议：固定一个训练语料已知的公开模型，构建 **audited zero-overlap** 的 real-face 协议，可解析到 **FMR=10⁻⁸**（44,722 subjects 覆盖 FMR=10⁻⁴…10⁻⁸）。

## 四、实验与结果

- **结论一**：低 FPR 区的性能读数对评测集重叠**极端敏感**，且敏感程度是 operating point 的函数。⇒ 本项目任何「把误杀压到 5.2% 以下」的结论，若不先审计评测集，无法区分「策略变好」与「分母被换」。
- **结论二**：偏差**不跨模型抵消**，会压缩模型间表观差距（本文把优势削掉一半）⇒ 6 个模型版本的迭代看板若共用一份被污染的评测集，**版本排序可能整体失真**，而不只是绝对值偏乐观。
- **结论三**：「能不能报这个 operating point」有硬下限（`N_eff`）。⇒ 与用户要求的 `coverage churn`、conformal 覆盖稳定性合流：**覆盖率不变不代表判定集合没换，也不代表该 operating point 可解析**。
- **与 11-24 主题的接续**：又是一次「代理量稳住、目标量换边」——FMR/FNMR 读数稳，实际泛化能力被评测集重叠整体换掉；但这次**代理量是被污染而不是被优化**，因此修法是「先修评测集」，不是「再换一个指标」。

## 五、局限性

1. **领域不是内容安全**：人脸验证的「身份重叠」在内容安全里对应 prompt 近重复 / 同源图片 / 参考集与训练集交叉，映射需要自建检测器，不能照搬余弦阈值。
2. **需要已知训练语料**：审计前提是训练 corpus 可见；闭源商用模型与多数线上分类器的训练数据不可得 ⇒ 只能做「近重复 + 参考集」侧审计，覆盖不全。
3. **只测一个公开模型 + 一个 real-face 协议**；未给多模型、多任务、多语言分档。
4. **未给内容分类的对应数字**：3.6×/6.3×/13.9× 不可直接当本项目误杀率的偏差量级，只能当**方向与审计协议**。
5. **de-overlap 不彻底是常态**：作者点名 WebFace260M 已发布去重叠仍残留；对应本项目「清洗过的数据集」也应复检，不能默认干净。

## 六、复现指南

### 6.1 论文复现

用训练语料已知的公开模型；null-calibrated 重叠检测器（masked-self null，β=0.1%）标出测试身份；人工复核抽样子集估残留重叠；2×2（de-overlap × dedup `T=0.70`）+ size-matched random control；按 FMR 网格 10⁻⁴…10⁻⁶ 报 FNMR 倍数与阈值位移；`B=2000` bootstrap 给 CI；算 `N_eff` 与最小可报告 FMR；最后用 audited zero-overlap 协议解析到 10⁻⁸。

### 6.2 本项目最小迁移（零训练，半天，**与 D3 合并最优先**）

**A. 评测集重叠审计（先于任何阈值调整）**

| 步骤 | 做法 | 判据 |
|---|---|---|
| ① 建近重复检测器 | 对 2000 条图生图评测集（1979 有效样本）、PSI 评测集、训练集、阈值参考集做 embedding 近重复 + 词面 n-gram 重合 | 用 masked-self null 把审计假阳性率钉在 0.1% |
| ② 抽样人工复核 | 抽 100 条 flagged 双盲确认 | 确认率 <70% ⇒ 先修检测器，不要急着删数据 |
| ③ 2×2 干预 | 只从测试集移除重叠样本 + 同规模随机移除对照，模型权重不动 | 移除后误杀率显著恶化而随机移除不变 ⇒ **基线 5.2% 被污染，历史 AB 按版本重算** |
| ④ 报最小可解析 operating point | 按每叶子类的有效独立样本数算 `N_eff` 与可报告 FPR 下限 | 某叶子样本不足以支撑目标误杀率 ⇒ 继承父类阈值并写明降级口径 |

**B. 与 23685 合起来的三步顺序（写进 D3）**：① 审计评测集（本篇）→ ② 算每类目 overlap 体检表示可判性（23685）→ ③ 才做约束式阈值选点与 conformal 认证。**任何一步没做就调阈值，结论不予进看板**。

**C. 多版本回归补一列**：6 版本看板增加「评测集版本 + 重叠审计版本号 + `N_eff`」三列；跨评测集时先钉死分母（eval_not_include / OOD 集另报），否则 `Δaggregate`/`Δmacro` 的符号不可解释。

**D. 灰度前后口径**：shadow → canary → 全量每一步冻结同一份评测集、同一份重叠审计结果、同一 `N_eff`；只换流量比例。若某阶段换了评测集或清洗规则，**登记为 calibration 事件**（11-23 纪律：证书不作废但 operating point 会作废）。

**上线口径**：新 ckpt / 新量化档 / 新硬件上线，除分语言安全率、分层宏平均 F1、逐对判定翻转率外，必须附「评测集重叠审计结果 + 最小可解析误杀率」；缺任一不可声称误杀率达标。
