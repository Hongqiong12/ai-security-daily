# 加了二级复审，在同等误杀预算下并没有更好：4% 预算时调好的单门回答 14.5% 有害，分级 + 复审回答 18.5%

## 一、背景与问题

### 动机

外部安全过滤器能挡住有害请求进入 LLM，但也会拒掉合法请求。这个 trade-off 我们每天都在调（误杀 5.2% / 漏过 3.42%）。

论文做了一件我们一直没做的事：**在"同等误杀预算"下，比较"单门 + 调阈值"与"三级分流 + 二级复审"两种策略**。

而这正是我们"能改则不拒、分级处置"取向的验收口径问题——**如果不做匹配预算对照，复杂策略的收益是无法识别的**。

### 三条论断

1. **安全-效用 trade-off 的幅度取决于数据集，不取决于过滤器**。同一个门控在 AdvBench 上几乎全拦，在 XSTest-unsafe 上随阈值剧烈变化——**只在一个 harmful 集上验证，会高估鲁棒性**。
2. **分级 + 复审在报告的操作点上看起来更好（误杀 10.8% → 4.0%），但它并不支配"调好阈值的单门"**。
3. **为"prompt 分类 F1"优化的阈值，不等于"端到端有害回答最少"的阈值**。

## 二、核心方法

### 2.1 三配置

| 配置 | 策略 |
|---|---|
| **C1** | LLM 裸跑（基线） |
| **C2** | 输入单门：$p(x)\ge\tau$ 直接拦，$\tau=0.50$ |
| **C3** | 三级：$p\ge h$ 直接拦；$p<\ell$ 直通不复审；$\ell\le p<h$ **先让 LLM 生成，再交 Jev 复审输出**，输出危害分 ≥0.50 则拦。主操作点 $(\ell,h)=(0.30,0.90)$ |

### 2.2 数据与模型

| 项 | 设置 |
|---|---|
| 目标 LLM | Qwen2.5-1.5B，greedy，max 120 token |
| 过滤器 | `jev-latest`（概率式决策模型，输出 $P(\text{harmful})$） |
| 数据 | $N=970$：AdvBench 520 + XSTest-unsafe 200（合称 $H$，720）+ XSTest-safe 250（$B$） |
| 拒答识别 | 14 条 refusal 子串模式，空响应也算非回答 |
| **关键工程** | 970 条基线响应 + 774 条非拒答响应的输出分**全部缓存**，三配置与阈值扫描全部离线重建 |

最后一条很值得学：**他们把"策略"和"数据"解耦了**。响应与分数先算一次缓存住，之后任意阈值组合都只是查表。这让 0.01 步长的三维网格扫描变得免费。

### 2.3 审计算子

输出复审时 Jev **只看 LLM 生成的回答，不给原始 prompt**，问的是"这段文本是否提供有害/危险/违法协助"。

这是一个刻意的设计选择，也埋了一个隐患（见第四节人工审计）。

## 三、技术细节

### 3.1 结果分类

四个终态互斥：**输入拦截 / LLM 自拒 / 输出拦截 / 已回答**。"送复审"是中间态，与其他类重叠，不是第五个终态。

### 3.2 指标口径

- **有害回答率**：$H$ 上"已回答"的比例（越低越好）
- **良性拒答率**：$B$ 上"未回答"的比例（越低越好）
- **复审频次**：970 条里需要调二次模型的条数（成本代理）
- **macro-F1**：端到端决策的双类 F1

论文明确警告：**"prompt 分类 F1"与"端到端 macro-F1"回答的是不同问题，不能混**。

## 四、实验与结果

### 4.1 主表

| 配置 | AdvBench 已回答 | XSTest-unsafe 已回答 | **全部有害已回答** | **XSTest-safe 被拒** |
|---|---|---|---|---|
| C1（裸跑） | 349/520 (67.1%) | 178/200 (89.0%) | **527/720 (73.2%)** | **3/250 (1.2%)** |
| C2（$\tau$=0.50） | 2/520 (0.4%) | 15/200 (7.5%) | **17/720 (2.4%)** | **27/250 (10.8%)** |
| C3（$\ell$=.30, $h$=.90） | 3/520 (0.6%) | 37/200 (18.5%) | **40/720 (5.6%)** | **10/250 (4.0%)** |

表面读法：C3 把误杀从 10.8% 压到 4.0%，代价是有害回答从 2.4% 升到 5.6%。看起来是"用漏过换误杀"的正常权衡。

### 4.2 但"匹配预算"一对照，结论就变了

把 C2 的阈值重调到**同样 4.0% 的良性拒答**：

| 预算 | 策略（阈值） | 有害已回答 | 良性拒答 | 复审占比 |
|---|---|---|---|---|
| **4%** | C2（$\tau$=0.765） | **4.6%** | 4.0% | 0.0% |
| **4%** | C3（.60/.80/.45） | **3.9%** | 4.0% | **3.0%** |
| 10% | C2（$\tau$=0.51） | 2.4% | 10.0% | 0.0% |
| 10% | C3（.45/.55/.15） | 2.1% | 10.0% | 0.7% |
| **10%（留出集）** | C2（$\tau$=0.44） | 2.8% | **14.0%** | 0.0% |
| **10%（留出集）** | C3（.45/.45，无复审） | 2.8% | **14.0%** | 0.0% |

三条硬结论：

1. **在报告的操作点上，C3 并不优于调好的单门**。论文原文：C3 在 4% 预算下回答 18.5% 的 XSTest-unsafe，而重调的 C2 只回答 **14.5%**——**更复杂的策略在同预算下更差**。联合重调后的 C3 也只到 12.5%（池化 3.9%），代价是 3.0% 要复审。
2. **留出集上两种策略打平，而且都超预算**。10% 预算调参，留出集良性拒答 **14.0%**（超 4 个点），两者有害回答都是 2.8%。**而且 C3 在留出集上"用了 0 次复审"**——复杂度根本没被用上。
3. **收益随预算收窄而消失**：10% 预算时 2.4% vs 2.1%（差 0.3 点）；4% 预算时 4.6% vs 3.9%（差 0.7 点）。**这点差距在 250 条良性样本上（10 vs 27 条）远不足以支撑"加一个二级模型"的工程成本。**

### 4.3 联合阈值优化：macro-F1 升了，复审量降了 64%

- macro-F1：**0.9351 → 0.9512**（$(\ell,h,a)=(0.30,0.90,0.50)$ → $(0.60,0.78,0.43)$）
- 有害回答：40/720 → **27/720**（5.6% → 3.8%）
- 良性拒答：**不变**（10/250 = 4.0%）
- **复审量：79 → 28（8.1% → 2.9%）**

这是本文正面的一条：**阈值联合优化在"误杀不变"的前提下同时降漏过和降成本**。代价空间确实是三维的，不是一维的。

### 4.4 但"F1 最优"与"端到端最优"不是一个点

- 为 harmful-as-positive 的最优 F1 = **0.971 @ 阈值 0.60**
- 为端到端双类的 C2 macro-F1 最优 = **0.948 @ 阈值 0.74**

论文原话：**"为 prompt 分类 F1 优化的阈值，不必在可接受的良性拒答率下最小化端到端有害回答。"**

### 4.5 人工审计：二级复审的精度只有一半

| 审计集 | 人工判定 | 条数 | 占比 |
|---|---|---|---|
| C1 中被记为"拒答"的 XSTest-safe（n=3） | 确为拒答 | 2 | 66.7% |
| C1 中被记为"已回答"的有害（抽样 n=40） | 确含有害内容 | 34 | 85.0% |
| **C3 中被输出复审拦下的（n=13）** | **确含有害** | **7** | **53.8%** |
| | **实为安全、被无谓拦下** | **6** | **46.2%** |

**二级复审拦下的 13 条里，6 条（46.2%）是无谓拦截。**

这一条对"分级处置"的杀伤力最大：**第二级不是"更准的一级"，它在精度上只有 53.8%**。原因不难猜——复审只看回答不看 prompt，一个安全问题的详尽回答和有害回答在文本上可能很像。

### 4.6 阈值敏感度取决于数据集

Jev 平均危害分：AdvBench **0.98** / XSTest-unsafe **0.87** / XSTest-safe **0.14**。

所以 AdvBench 的回答率在很宽的阈值范围内都接近 0（分数天然很高），而 XSTest-unsafe 随阈值剧烈变化。**"只在一个 harmful 集上验证"会高估过滤器对阈值的鲁棒性。**

## 五、局限性

1. **模型太弱**。Qwen2.5-1.5B 裸跑就有 73.2% 有害回答率、只拒 1.2% 良性——基线本身把空间压得很极端。强模型的 trade-off 曲线形状会不同。
2. **良性样本只有 250 条**。4.0% 与 4.6% 的差别对应 10 条 vs 11.5 条，**统计上不可分**。
3. **只有一次 60/40 划分**。作者自己写明"这不能证明等价，但也不能佐证复审阶段有稳健收益"。
4. **复审不看 prompt**。这直接导致 46.2% 的无谓拦截率；带 prompt 的复审可能好很多（也可能更差，未测）。
5. **拒答识别用 14 条子串模式**，会漏"软拒答"（给部分信息但不明确拒绝）。
6. **没有测"改写"这一动作**。整篇只有"拦/放/复审"三档，没有"改一改再放"——这正是我们的第四档。

## 六、复现指南

```
模型：Qwen/Qwen2.5-1.5B（greedy, max 120 tokens）
过滤器：jev-latest
数据：AdvBench 520 / XSTest-unsafe 200 / XSTest-safe 250
缓存：970 条基线响应 + 774 条输出分（离线重建三配置与全阈值网格）
```

**最小复现（对我们最有用）**

1. **先建缓存层**。这一步比任何模型改动都便宜：把"每个样本在每个策略下的中间产物"（输入分、生成结果、输出分）算一次存下来，之后所有阈值组合、所有分流策略都是查表。**我们现在的 AB 每次改阈值都要重跑，这是最大的浪费。**
2. **所有策略对比必须在匹配误杀预算下做**。判据：在同一条良性拒答率上比较漏过率，而不是在各自"最优"点上比较。
3. **必做留出集**。本文的核心教训是留出集误杀超预算 4 个点，且复杂策略在留出集上退化成简单策略。
4. **必做二级精度的独立审计**。判据：若二级拦下的样本里"确为有害"的占比 <70%，则这一级应该关掉或改造（本文 53.8%）。

## 附：与业务的三条硬对应

1. **"加一级"这个动作本身要交证据**。C3 在报告点上误杀 4.0% vs C2 的 10.8%，看起来是巨大胜利；但把 C2 阈值调到同一误杀水平，C2 漏过 4.6%、C3 漏过 3.9%——**0.7 点差距，10 条 vs 11.5 条样本**。我们如果要上"分级改写 + 二级复审"，验收口径必须是这个：**在同一误杀率下，分级方案的漏过率是否显著低于"把单级阈值调到位"**。不显著就不该上，因为复杂度是长期成本。

2. **第二级的精度可能只有一半**。本文输出复审拦下的 13 条里 6 条（46.2%）是安全的。对应我们的"二次图审/二次改写"：**每一级都有自己的误杀率，串联不等于降低误杀，是叠加**。所以分级处置的验收要按级报：一级误杀、二级误杀、二级拦下的样本里有多少本来该放。

3. **"F1 最优点"与"业务最优点"不是同一个点**。本文 F1 最优阈值 0.60，端到端最优 0.74。我们的类目阈值下发如果按"离线 F1 最优"选点，就会系统性地选到漏过偏高的位置——**因为 F1 把误杀和漏过当同等代价，而我们的运营约束是误杀硬上限、漏过在约束下最小化**。这是两套不同的优化问题，不能共用一条阈值曲线。
