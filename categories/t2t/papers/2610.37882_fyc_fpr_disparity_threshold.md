## 一、背景与问题

### 动机

深度伪造检测器有一个典型的"总体好看、分组难看"：

> 总体准确率很高，但**误报率在不同人群之间差两位数字**。

论文引的数：女性 vs 男性的 FPR 是 **14.0% vs 7.7%**（近两倍）；跨交叉子群的准确率差异可以超过 **40%**。

这个结构和我们的情况是同一个：

| 本文 | 我们的对应 |
|---|---|
| 总体准确率高 | 一级一致率 77.64% |
| 分组 FPR 差两位数 | 误杀率 5.2% / 漏过率 3.42% 在**不同类目**上分布不均 |
| 需要 per-group threshold | 接入台**按一级/二级/叶子类目勾选 + 阈值下发** |

**它要解的题，就是"能不能给每个组单独配一个阈值，而且不把别的东西搞坏"。**

### 我们为什么必须看这篇

因为我们在做的事，**这篇给出了一个明确的反例警告**：它证明了——

> **用错"公平指标"去做权重扰动，会随机地帮到一些模型、随机地毁掉另一些，而你事前无法知道是哪种。**

具体数字（四个架构）：
- Demographic Parity（DP）目标 → **2 个改善 / 1 个基本不变 / 1 个显著恶化**（PG-FDD，恶化集中在肤色轴）。
- 换成 **FPR-disparity（只在真实图上条件化）** → **四个架构全部同时改善公平性与 AUC，无例外**。

**同一个方法、同一个训练预算，只换了约束指标，结果从"看运气"变成"稳定收益"。**

这正是我们做"分业务粒度阈值管控"时最需要的判据：**你怎么定义"这个类目的阈值配得好不好"，决定了你调完会不会反噬。**

### 核心问题

1. 只有一版权重、没有人群标注，能不能做事后校准？
2. **用哪个差异指标**做约束，才能保证不反噬？
3. 分组阈值应该怎么定，代价是多少？

## 二、核心方法

两阶段，都不改架构、不全量重训。

### 阶段一：FPR 差异约束下的权重扰动

借 SAM（Sharpness-Aware Minimization）的形态：**先向最差分组的配置爬升，再带公平正则下降**。

- **上升步**：朝"组间差异最大"的方向扰动参数；
- **下降步**：在扰动点上最小化「标签平滑 BCE + 逆组频加权」；
- 惩罚项做 warmup（前若干 epoch 权重低）。

**关键改动只有一个：把差异指标从 DP 换成 FPR-disparity。**

而 FPR-disparity 的定义要点是：**只在"真实为负"的样本上算组间差异**。DP 则是无条件比较"正预测率"，不管真值。

论文对 DP 的批评很精准：

> *"parity satisfied by equalizing **positive-prediction rates** rather than correct predictions, without conditioning on the true label."*

翻译成我们的语言：**DP 相当于"让每个类目的拦截率一样"，而不管拦对没拦对。** 这个指标会把"某类目本来就该多拦"和"某类目被误杀"混在一起。

### 阶段二：Per-group Youden-J 校准（零成本）

对每个组 `g`，在**独立于阶段一的校准集**（50K 训练图，seed 99）上，找使 Youden 指数最大的阈值：

`J = TPR − FPR`

然后**以 logit 平移的方式施加**：把组 `g` 的 logit 整体平移 `Δ_g`，使默认 0.5 边界对齐到 `τ_g`。

**没有梯度更新。** 论文原话：*"No gradient updates are performed."*

### 三种校准模式（这张对照很关键）

| 模式 | 定义 | 论文评价 |
|---|---|---|
| **Youden-J** | 每组独立，最大化 TPR−FPR | **推荐** |
| eq-FPR | 共享一个全局最优 FPR 阈值 | 次优 |
| **eq-TPR** | 共享一个全局最优 TPR 阈值 | **退化（degenerate）** |

eq-TPR 为什么退化？论文一句话说穿：

> *"maximizing TPR alone with no FPR penalty trivially drives the threshold toward predicting every image fake."*

**只优化"漏过率"、不给"误杀率"任何惩罚，最优解就是把阈值推到"全部判违规"。**

这句话值得刻在我们接入台上。**任何只写"漏过率 ≤ X%"的阈值下发规则，最优解都是全拦。**

## 三、技术细节

### 数据与规模

| 项目 | 数值 |
|---|---|
| 数据集 | AI-Face v2：训练 **1.3M** / 测试 **329,309** |
| 分组 | **6 个交叉组**（性别 × 肤色：Light / Medium / Dark） |
| 评测架构 | Xception、EfficientNet-B4、DAG-FDD、PG-FDD |
| 单 epoch 训练图 | 270K / 250K / 130K |
| 校准集 | 50K，seed 99，与扰动微调不相交 |
| 硬件 | **单卡 A100**，bf16 |
| 时间 | Xception 实测 **39 min/epoch**；四架构合计 **6–15 h** |
| 对比基线 | AI-Face v2 上全部 **12 个**被基准过的检测器（含专用公平架构） |
| 指标 | FMEO、EO、FEO、FOAE、FPR、FDP；AUC / Acc / AP / EER |

### 一个必须记的细节：leveling-down 检查

> *"a method that reduces FMEO only by **globally reducing accuracy** would show Acc_cal < Acc_base."*

即：**如果公平性提升是靠"整体变差"换来的，那是作弊。** 必须显式对比校准后与基线的总体 Acc。

这条对应我们的场景就是：**如果某类目的误杀率降了，但总拦截率也降了，那不是调好了，那是关掉了。**

### 超参（可直接参考）

Adam，lr / wd 网格搜索，CosineAnnealingLR；penalty warmup 若干 epoch；label smoothing 0.05；grad clip max-norm；输入 Resize 到固定分辨率；**逆组频加权保证 6 个组在每 batch 里都出现**。

## 四、实验与结果

### （1）主结果：18/21 行全胜，3 行"输了但故意的"

| 检测器 | FPR | AUC | Inter-FMEO | Inter-FEO | Acc |
|---|---|---|---|---|---|
| Xception（基线） | **12.96** | 98.58 | 10.51 | 24.32 | 96.31 |
| PG-FDD（专用公平架构） | 10.97 | 99.17 | 9.58 | 18.35 | 96.17 |
| **Xception + FYC** | **1.50** | **99.85** | **8.24** | **10.36** | **98.88** |
| **DAG-FDD + FYC** | **1.31** | **99.91** | **3.22** | **6.11** | **99.03** |

三件事：

**① FPR 从 12.96% → 1.50%，降了 88%。** 同时 AUC 从 98.58 涨到 99.85、Acc 从 96.31 涨到 98.88。**没有 leveling-down。**

**② 打赢了"专用公平架构"。** PG-FDD 是专门为公平性设计、需要全量重训的架构（**7 h 20 min/epoch**）；FYC 只是在一个普通 Xception 上做 **39 min/epoch** 的事后调整。**投入差 11 倍，指标反而更好。**

**③ 输掉的三行，全部是 FDP（Demographic Parity gap）** —— 肤色、年龄、交叉三个轴。论文的解释是：

> *"This is not a regression: FDP (demographic parity) is the metric the objective we deliberately avoid would target... and instead wins every FEO (equalized odds) row."*

**它没输在"效果差"，它输在"没优化那个指标"。** 这是一个非常干净的因果归因：**你优化哪个指标，你就赢那一片、输另一片。**

### （2）DP vs FPR-disparity：同一方法，两种命运

| 架构 | DP 目标（原版权重扰动） | **FPR-disparity 目标** |
|---|---|---|
| 架构 1 | 改善 | **改善** |
| 架构 2 | 改善 | **改善** |
| 架构 3 | **基本不变** | **改善** |
| 架构 4（PG-FDD） | **显著恶化（肤色轴）** | **改善** |

论文的判决：DP 的原始阶段效果是 **architecture-dependent**，"a practitioner cannot vet without running the diagnostic itself"——**你没法事前知道你这个 checkpoint 会落在哪一格，只能自己跑一遍才知道。**

而 FPR-disparity **消除了这个不可预测性**。

### （3）四架构整体收益

| 指标 | 幅度 |
|---|---|
| 交叉 FMEO | **−38.0% ~ −70.1%** |
| 全局 FPR | **−78.2% ~ −91.5%** |
| AUC | 四个架构**全部提升** |

### （4）分轴结果：差异的来源不一致

看 Table 2 的分轴数字，有一条规律很清楚：

| 轴 | 基线 FMEO 跨度 | 校准后 |
|---|---|---|
| 肤色（Skin） | 2.58 – 19.94 | X+FYC **3.34** / D+FYC **1.24** |
| 性别（Gender） | 3.19 – 6.27 | **0.45 / 0.35** |
| **年龄（Age）** | **5.44 – 47.50** | **1.41 / 1.19** |
| **交叉（Inter.）** | **6.12 – 21.37** | **8.24 / 3.22** |

**年龄轴的基线差异最大（最差 47.50）**，校准后压到 1.19–1.41，是收益最大的一轴。而**交叉轴最难压**（X+FYC 仍有 8.24）——因为交叉组的样本量最小。

**对应我们的含义：类目层级越深（叶子类目）、样本越少，阈值校准的收益上限越低。** 这直接关系到"按叶子类目勾选阈值"这件事该不该做——**做得下去的前提是那个叶子类目有足够样本去估 Youden 点。**

## 五、局限性

### 论文自述的

1. **需要分组标签。** 虽然只需在**校准集**上有（50K），不是全量；但如果连校准集都没有组标签，方法不成立。
2. **组是固定的、离散的。** 6 个交叉组。真实场景里"组"可能是连续的、或高维交叉的。
3. **只评了 deepfake 检测一个任务。** 其他二分类安全任务未验证。
4. **阈值是按组独立定的，组间一致性没有约束。** 可能出现"两个语义相近的组拿到差别很大的阈值"这种业务上不好解释的情况。
5. **FDP 那一轴确实没优化。** 如果一个场景的合规要求是 DP（拦截面均衡），这套方法不适用。

### 我们迁移时的四条边界

**① "组"的定义要自己造。**

论文的组是人口属性（性别 × 肤色），天然有标签。我们做"按类目下发阈值"时，**"组"就是类目（一级/二级/叶子）**——但这里有个陷阱：

> 论文的组是**总体的一个划分**（互斥、穷尽）；我们的类目是**一条样本可能同时属于多个**（多标签）。

多标签场景下"Youden-J 每组独立优化"会有冲突：一条样本同时是 PORN 和 VULG，两个类目的阈值各自最优，但联合判定只有一个。**这一点论文没解决，我们必须自己处理**（最简做法：按"最终处置类目"定组，即先做单一归属再做阈值）。

**② 叶子类目上样本量是硬约束。**

年龄轴（样本多的轴）收益最大，交叉轴（样本少的轴）收益最小。照搬到我们的叶子类目上：**样本 < 数百的叶子类目，Youden 点估计的方差会大于它想修正的偏差。** 这类类目应该**继承父类阈值**，而不是自估。

**③ "误杀率 5.2% / 漏过率 3.42%" 这两个数不能同时当优化目标。**

eq-TPR 的退化结论就是警告：**只压漏过，最优解是全拦。** 我们的阈值下发规则必须写成**带约束的**形式：

> 在 误杀率 ≤ 5.2% 的约束下，最小化漏过率

而不是

> 最小化漏过率

后者数学上没有内点解。

**④ FDP 那一课：不要试图用一个阈值同时满足两套口径。**

论文赢了 18 行、输 3 行，输的全是它刻意不优化的那套。**我们的接入台如果既要求"各类目拦截率均衡"（对应 DP）又要求"误杀率达标"（对应 FPR），这两个要求在数学上会打架。** 必须选一个当主约束，另一个当监控项。

## 六、复现指南

### 最小可跑版本（半天，零训练，只做阶段二）

**阶段一（权重扰动）我们先不做**——它要重训，而且我们的模型不适用（我们的痛点是阈值分布，不是权重偏差）。**只做阶段二就已经能拿到大部分收益。**

1. **取现有分类器的打分**（不需要重训，只要有 logits/prob）。
2. **按类目分组**：一级 / 二级 / 叶子，三层各算一套。
3. **每类目在验证集上扫阈值**，算 `TPR − FPR` 曲线，取 `J` 最大的点。
4. **记录三个数**：该类目的 Youden 点、该点上的误杀率、该点上的漏过率。
5. **和现状对照**：

| 观察 | 判定 | 动作 |
|---|---|---|
| Youden 点上的误杀率 **已 ≤ 5.2%** 且漏过率更低 | 现状阈值**不在 operating point 上** | 直接下发，零训练收益 |
| Youden 点误杀率 **> 5.2%** | 约束与最优点冲突 | 改成**约束优化**：在 5.2% 约束下取最小漏过点 |
| Youden 点在**样本 < 200** 的类目上剧烈跳动（不同折差异 > 10 点） | 估不准 | 该类目**继承父类阈值**，不自估 |
| 某类目 AUC 本身很低（< 0.8） | **排序坏了，不是阈值偏了** | 调阈值无用，回去修模型/修标签 |

**最后一行最重要。** 它把"阈值问题"和"排序问题"分开——我们前几轮反复调阈值无效，很可能是因为某些类目根本是排序坏了。

### 实现坑

| 坑 | 处理 |
|---|---|
| 校准集与训练集混用 | 必须独立（论文：50K，seed 99，与扰动微调不相交） |
| 只优化漏过率 | eq-TPR 退化，最优解是全拦 |
| 不查 leveling-down | 必须同时报总体 Acc/一致率，防止"靠整体变差换公平" |
| 用 DP 当约束指标 | 论文实测：2 改善 / 1 不变 / 1 恶化，无法事前预测 |
| 叶子类目硬估阈值 | 样本不足时方差大于偏差，继承父类 |
| 多标签类目各自定阈值 | 联合判定只有一个，需要先做单一归属 |

### 一句话带走

**"按类目下发阈值"这件事的真正难点不在"每个类目算一个数"，而在"你用哪个指标判断这个数好不好"。选 DP 会随机反噬，选 FPR 条件化会稳定；只压漏过率则数学上无解。**
