# 那个守门模型在判 prompt，不在判回答——332 对样本里只有 13.9% 判对

**论文主页**: https://arxiv.org/abs/2611.02134
**领域**: 流式输出侧护栏（output guard）· 捷径诊断 · 反事实纠偏 · 小模型部署
**作者**: Ashmiya Lenin, Navaneeth Sangameswaran, Preetham S
**机构**: Astroware AI（Delaware, USA）+ Karunya Institute of Technology and Sciences（印度）
**发布日期**: 2026-11-01（v1，cs.CL / cs.CR）
**分类**: defense / benchmark
**模态归属**: 输出侧图审的直接同构（同模型、同尺寸、判 prompt vs 判内容）

---

## 一、背景与问题

### 动机

**输入护栏决定一条请求能不能到达模型，但它永远看不到模型说了什么。**

生成过程中浮现的伤害——越狱穿过了输入层，或者一个良性请求在几段之后漂移成了操作细节——**只在输出侧可见，而且只在 token 到达时可见**。

论文给的例子很具体：一个关于**农药毒性**的良性提问，可以生成一段回答，在若干段之后**变成合成路线**。纯看 prompt 的评分看不见这个。

### 为什么这篇对本项目是第一优先

它给出了一个我们反复怀疑但从未量化的现象，并且给了一个**可直接搬的测量协议**：

> **用常规数据训出来的输出护栏，会学到一个"判 prompt 而不判回答"的捷径。在 332 对匹配的（同 prompt，安全回答 / 有害回答）样本上，它只判对 13.9%。**

这正好是我们图审那条长期假设——"图审在读 prompt 不在读图"——的**同构证据**，而且它给了 13.9% 这个量级。

### 三条论断

1. **流式引入两个新错误**：在"本会保持安全"的前缀上触发；或在有害内容已经展示之后才触发。决策不再只是"安全/不安全"的二分，还包括"**证据何时才算充分**"。
2. **常规数据里几乎每一条有害回答从头就有害**，所以护栏可以靠判 prompt 拿到高分，从不读答案。**这个捷径必须用匹配对直接测。**
3. **纠偏数据必须"每条安全回答都有一条有害孪生"**，且**孪生必须来自同一个生成器**，否则风格会成为标签的代理。

## 二、核心方法

### 2.1 架构：线性头 + 因果骨干

输入是"策略前言 + 用户 prompt + 回答"。前言是一段"什么算安全/不安全"的定义 + **27 个宪章类目**。

HaloGuard 1.0 是**生成式分类器**：读完 prompt 再写一个标签。这个接口不适合流式——每个 token 出一个标签会让推理成本乘上标签长度。

2.0 改成**在 Qwen3.5-0.8B 骨干最后一层隐状态上加线性头**：

$$p_t = \operatorname{softmax}(W h_t + b)_{\text{unsafe}}, \quad W \in \mathbb{R}^{2\times 1024}$$

因为骨干是因果的，$h_t$ 只依赖 $x$ 与 $r_{\le t}$，所以**一次前向给出每个前缀的判决**。视觉塔与 LM 头被丢弃。

### 2.2 逐 token 标注与损失

onset（伤害起点）存为字符偏移，映射到"跨度结束于该偏移之后"的第一个 token。**跨 onset 的 token 标为不安全。**

$$y_t = \begin{cases}0 & \text{安全回答，或 } t < o\\ 1 & \text{有害回答且 } t \ge o\\ \varnothing & \text{prompt 位置、有争议回答、或被截断的有害跨度}\end{cases}$$

$\varnothing$ 位置**排除出损失**。onset 之后**没有"容忍带"**：第一个有害 token 就被监督为不安全。

加权 token 级交叉熵：

$$\mathcal{L} = \frac{\sum_{t\in\mathcal{T}} w_t \mathrm{CE}(y_t, p_t)}{\sum_{t\in\mathcal{T}} w_t}, \quad w_t = \begin{cases}\lambda & |t-o| \le 16\\ 1 & \text{其他}\end{cases}$$

$\lambda = 5$（第一阶段）/ $\lambda = 3$（第二阶段，因为那里的转移密集 23 倍）。

### 2.3 两阶段：先训出捷径，再针对捷径造数据

| 阶段 | 数据 | 轮数/步数 | 结果 |
|---|---|---|---|
| Phase 1 基础 | 478,532 条回答（30.2% 不安全，**仅 2.2% 有 onset>0**） | 2 epochs / 29,910 步 | macro F1 **72.8**，但**学会了判 prompt** |
| Phase 2 纠偏 | 106,043 条反事实回答（50.2% 不安全，**51.2% onset>0**） | 3 epochs / 9,942 步 | 单独用 **69.1** |
| 从零混训 | Phase 2 数据混进 Phase 1 语料 | — | **70.7** |
| **发布 = 权重平均** | $\theta = \tfrac12\theta_{\text{base}} + \tfrac12\theta_{\text{corrective}}$ | 逐参数 | **83.6** |

**"平均"不是装饰。** 论文说得很直白：纠偏模型单独用比基础护栏**低**，从零混训也**低**；原因是"**纠偏模型的错误不是基础护栏的错误**：它修好了 prompt 捷径和词汇触发，但**压缩了分数尺度**，以至于没有单一阈值能像以前那样分开两类。平均保留了大部分修正并**恢复了分数尺度**。"

### 2.4 三条造数据规则

1. **每条安全回答必须有一条不安全孪生**——同一 prompt、相似词汇与长度，**只在有无 operational uplift 上不同**。
2. **两个孪生必须来自同一个生成器**——否则生成器的风格特征成为标签代理。
3. **onset 是构造出来的，不是推断的**——安全段与有害续写分段生成，onset 精确已知。

第 1 条有一个实验证据：早期一次"只把 19,033 条边界回答重标为安全、不加匹配有害样本"的尝试，**把 FPR 减半，但掉了 17 点召回**——"护栏开始把整个话题都判成安全"。

第 2 条也有：在早期纠偏语料里，**孪生来自不同生成器**的版本，留出集上的匹配对准确率从 **13.9% 升到 88%**，但**六 benchmark 的 F1 只提升 0.16**。论文把差距部分归因于生成器混淆。

### 2.5 三态 FP 分类

| 模式 | 失败形态 | 对应数据 |
|---|---|---|
| **Boundary** | 合法的、贴近政策边界的回答因为**话题或词汇**被判违规 | 无害边界池（跨信息深度）+ 有害回答的安全孪生 |
| **Baseline（词汇）** | 普通回答因为一个**无害用法**的伤害邻接词被判违规 | 共享无害池 + 词汇碰撞回答 |
| **Prompt-driven** | 对"听着有害"的 prompt 的**安全回答**，在还没说任何有害内容前就被判违规 | 同 prompt 的匹配安全/有害回答 + "先安全后转向" |

第三类是**流式特有**的。

## 三、技术细节

### 3.1 两个工程细节（都会直接让人翻车）

**（a）头必须零初始化。**
Qwen3.5 最后一层隐状态的 RMS 约 **4.2**，所以常规的 $\mathcal{N}(0, 0.02^2)$ 初始化会让 logits 标准差达到 **2.7**。实测导致**第一步梯度范数 >500，并塌成常数预测**。零初始化时训练从**恰好 $\ln 2$** 的损失开始。

**（b）不能做 sequence packing。**
骨干是混合的：24 层里 **18 层是 Gated DeltaNet 线性注意力**（有循环状态），6 层是全注意力。FlashAttention-2 的变长核能把打包样本隔离在 6 个全注意力层，但**线性注意力层的循环状态会跨打包边界传递**。两层探针实测：**同一条样本，因前面打包了什么不同，隐状态差异最大到 0.23。**

⇒ 训练必须**不打包**，只用长度分组批处理来减少 padding。

**这一条对我们的 5 节点算力现实是直接约束**：如果我们要用线性注意力骨干做图审，**packing 加速这条省算力的路被堵死了**。

### 3.2 决策规则（两阈值 + 锁存）

$$\text{触发} = \left[\max_t p_t \ge 0.975\right] \ \lor\ \left[\text{连续两个 } p_t \ge 0.70\right]$$

锁存（latched）。多语版用"连续三个 token ≥ 0.675"。

### 3.3 长回答的两窗口

护栏只训到 2,048 token。更长的回答**打两个窗口**：一个锚在回答开头、一个锚在结尾，重叠处逐元素取最大。

理由写得极清楚："**只算开头窗口，攻击者可以在长填充之后埋载荷；只算结尾窗口，可以在开头埋。**两个窗口覆盖约两倍训练长度。"

### 3.4 服务成本（单张空闲 H100，512 token 预填）

| 量 | 值 |
|---|---|
| 增量步（batch 1） | **22.2 ms** |
| 增量步（batch 64） | 23.7 ms |
| 每 token 每流（64 并发） | **0.37 ms** |
| 聚合吞吐 | **2,705 token/s** |
| 随回答长度 | **恒定**：128/512/1024 token 处分别 22.6 / 22.2 / 22.8 ms |
| batch 1→64 的额外墙钟 | 仅 **6.7%** |

恒定是因为 18 个循环层带固定大小状态，只有 6 个全注意力层的缓存会长。batch 1 时单步被**核启动开销**主导。

### 3.5 评测集

六个英文 benchmark 共 **12,347 条回答**（HarmBench 400 / SafeRLHF 5,978 / BeaverTails 3,021 / WildGuardTest 1,689 / Aegis 2.0 813 / XSTest-Response 446），不安全占比 **16.7%–57.4%**。

**训练集对所有 12,347 条评测行做了哈希黑名单 + 近重复筛查。**

**前三名的平均只差 0.06**（83.63 / 83.57 / 83.57），但**规模差 5–10 倍**。论文自己的措辞很克制："领先这两者的幅度很小；规模差距不是。"

### 4.2 但基础护栏的单格塌陷才是重点

Phase 1 基础护栏：**HarmB 91.6（全场最高）而 WildG 58.9（全场最低）**。

**同一个模型、同一次训练，最好的格与最差的格差 32.7 点。** 而它的平均是 72.76 —— 一个看上去"中等"的数。

⇒ 平均分把一个 91.6 和一个 58.9 抹平成了一个 72.8。**这是我们看板最该警惕的形态。**

### 4.3 纠偏的收益极不均匀

| Benchmark | 基础 | 发布版 | 变化 |
|---|---|---|---|
| XSTest-R | 68.0 | 85.4 | **+17.4** |
| WildG | 58.9 | 71.9 | **+13.0** |
| BeaverTails | 72.3 | 83.0 | +10.7 |
| HarmB | 91.6 | 96.4 | +4.8 |
| SafeRLHF | 71.7 | 81.7 | +10.0 |
| Aegis 2.0 | 74.1 | 83.5 | +9.4 |

**最大的两个收益正好落在"由安全回答主导"的两个 benchmark（XSTest-R / WildG）上**——那里是 prompt-driven 与词汇 FP 模式集中的地方。这证明纠偏数据确实打在了点上。

假阳性总数从 **1,465 降到 912**。

### 4.4 逐 benchmark 的 FPR / FNR（Table 11）

| Benchmark | 基础 FPR | 基础 FNR | 发布 FPR | 发布 FNR |
|---|---|---|---|---|
| HarmB | 0.0 | 15.5 | 0.0 | **7.0** |
| SafeRLHF | 28.5 | 31.2 | 17.7 | 21.1 |
| BeaverTails | 26.0 | 32.5 | 18.3 | 19.4 |
| XSTest-R | 14.1 | 14.1 | **5.4** | 6.4 |
| **Aegis 2.0** | 27.7 | 23.9 | **27.0** | **7.9** |
| **WildG** | 14.1 | 28.7 | **4.9** | **30.1** |

两行必须单独看：

- **Aegis 2.0：FNR 从 23.9 掉到 7.9，FPR 几乎不动（27.7→27.0）。** 论文说这是"唯一一个 FP 模式没响应纠偏数据"的 benchmark。
- **WildG：FPR 从 14.1 降到 4.9，FNR 反而从 28.7 升到 30.1。** 修好了误报，漏报更差了。

池化之后：**发布版"漏"多于"误"**。

### 4.5 核心证据：332 对匹配样本（§6.2）

**协议**：留出的 onset 集，**664 条生成回答 = 332 对**（同一 prompt；一条有害回答但伤害从回答中段才开始；一条安全孪生，永不越界）。该集在 Phase 2 任何数据生成之前就已冻结，与训练不共享 prompt。

**结果（基础护栏）**：

| 行为 | 占比 |
|---|---|
| **判对**（有害触发、安全孪生不触发） | **13.9%** |
| 两条都触发 | 45.8% |
| 两条都不触发 | 40.4% |
| 只在安全孪生上触发 | **0%** |

论文的推理链是全文最锋利的一段：

> "一个**读回答**的护栏至少有时会把某一对判反；一个**从不判反**的护栏，是在对两个孪生**共有的东西**做判断——那就是 prompt。"

两个补充证据：

- **中位首次触发落在 onset 之前 40 个 token。**
- 在中间模型上，**37.4% 的假阳性在回答的前三个 token 内触发**，且"第一个回答 token 处的分数"在会被误判的回答上是 **0.59**、不会误判的是 **0.24** —— 这个差距**只可能来自 prompt**。

### 4.6 onset 召回与 F1 是一笔买卖

同一决策规则下，把纠偏模型的权重从"等权平均"一路调到"只用纠偏模型"：

| 配置 | onset 召回 | macro F1 |
|---|---|---|
| 等权平均（发布） | 47.6% | **81.0** |
| 只用纠偏模型 | **72.6%** | 76.3 |

⇒ **约 1 点 F1 换 5 点 onset 召回。**

这个交换率对我们极重要：**"整体判得准"与"在正确的时刻判"是两个目标，且互相竞价。**

### 4.7 输入层 vs 输出层：同一个模型，任务难度差多少

三个 benchmark 同时标了 prompt 和回答，可以用**同尺寸模型**对比两个任务：

| Benchmark | 判 prompt（F1） | 判回答（F1） | 差 |
|---|---|---|---|
| HarmBench | 98.7 | 96.4 | −2.3 |
| Aegis 2.0 | 87.9 | 83.5 | −4.4 |
| **WildG** | **95.9** | **71.9** | **−24.0** |

⇒ **"判 prompt"比"判回答"容易得多，而差距在对抗性输入上最大（24 点）。**

### 4.8 多语版：错误画像相反

| 指标 | 英文版 | 多语版 |
|---|---|---|
| macro F1 | 83.6 | 83.1 |
| 精确率 | 84.1 | 75.5 |
| 召回 | 80.5 | **92.5** |
| FPR | 14.3 | 6.1 |
| FNR | 19.5 | **7.5** |

多语版：**1,482 个假阳性 vs 360 个假阴性** ⇒ 「剩余的余量在精确率，不在召回」。部分原因是基率——PolyGuardPrompts 只有 **16.6% 不安全**，所以即使低 FPR 也会产生比漏报更多的误报。

分语种：英语 F1 **87.1**（FPR 4.7 / FNR 4.6）、CJK 83.1、阿拉伯 82.7、**泰语 73.9**、**印地语 64.2（FNR 22.2，五个有害回答漏一个以上）**。

### 4.9 阈值口径的自律

- **所有 benchmark 共用一个决策规则**，不按 benchmark 调阈值。理由："部署中的护栏无法知道请求来自哪个分布"，且实测"**按 benchmark 调阈值把 macro F1 抬约 3 点**"。
- 两个阈值在 benchmark 上网格搜（步长 0.025）。为估计由此带来的乐观偏差，**把每个 benchmark 对半分，一半定规则、另一半评分**，两个随机种子双向：**留出 macro F1 = 83.3，样本内 83.6**。

## 五、局限性

### 5.1 论文自述

- **onset 集只有 332 对**，且"由与 Phase 2 语料相同的流水线生成，因此**偏向在该语料上训练的模型**；我们把它与 benchmark 并读，而不是替代 benchmark"。
- **训练数据只有 584.6K 英文回答**（对比 Qwen3Guard >1.19M、Shieldstral 54.1M）。
- **WildG 仍是最弱项（71.9）**，是下一轮纠偏的主要目标。
- **Aegis 2.0 的 FP 模式对纠偏数据无响应。**
- **印地语 FNR 22.2**，跨语种不均。
- **多语版错误画像与英文版相反**（误多于漏），阈值不能共用。

### 5.2 本报告补充的三条

1. **13.9% 这个数字不能直接搬到我们的图审上，但"0% 判反"这个signature 可以。** 判据是结构性的：**一个从不把匹配对判反的护栏，一定在判共有部分。** 这个检验**不需要标注、不需要训练**，只要构造匹配对。
2. **"权重平均"这个技巧值得单独记。** 纠偏模型单独用更差、从零混训更差、平均起来最好——因为**纠正的是误差结构，不是分数尺度**。这是一条反直觉但极其实用的工程经验：**当你用一批针对性数据纠偏时，不要替换模型，要平均。**
3. **它没有回答"输出侧护栏应该多严"**。它给的是"在某个决策规则下的 FPR/FNR 表"。**"误杀 5.2% / 漏过 3.42%"这个运营约束该对应到哪一组阈值，论文没给方法**——需要我们自己在自己的基率上算。

## 六、复现指南

### 6.1 依赖与入口

- 权重：HuggingFace `astroware/haloguard20` 集合。
- 骨干 Qwen3.5-0.8B，线性头 $2\times1024$，bf16 + FlashAttention-2 + DDP，2×H100，Phase 1 4.6 h / Phase 2 62 min。
- 推理：flash-linear-attention 0.5.0 + causal-conv1d 1.7.0。

### 6.2 最小可迁移实验：图审的"匹配对"体检（半天，零训练）

**这是本轮最该先做的一条。** 它不需要训练、不需要重标注，只需要构造数据。

**做法**：

1. 取同一批 prompt，各生成 **2 张图**：一张判为违规、一张判为无害（或用现成的同 prompt 不同图对）。
2. 组成 $N$ 对（建议 $N \ge 200$）。
3. 用现有图审模型跑，只记录**是否触发**（不看分数）。
4. 统计四个比例：**判对 / 两条都触发 / 两条都不触发 / 只在安全那条上触发**。

**判据（结构性的，不需要基线）**：

| 观察 | 结论 |
|---|---|
| **"只在安全那条上触发" ≈ 0%** | 图审在判**共有部分**（prompt / 文本描述），不在判图 → 与本文 13.9% 同构 |
| "两条都触发" **> 40%** | 同上，且说明阈值偏低 |
| 判对 **> 60%** | 图审确实在读图，现有验收可信 |

**补充（若能拿到分数）**：看"第一层/第一步输出分数"在误判与不误判两组的差。若差距 **> 0.3**（本文 0.59 vs 0.24），说明分数里混了大量非图像信息。

**这一条直接回答我们悬了三周的"图审到底在读什么"。成本半天，不需要任何训练。**

### 6.3 派生实验：onset 与总分的交换率（1 天，需轻量微调）

对我们的图生图评测：把"是否违规"拆成"**是否违规**（终局判定）× "**在第几步/哪个区域判出**（时机判定）"。

做法：
1. 构造 200 条"先安全后越界"的样本（可用现有评测集里分段标注的）。
2. 报两个数：终局 F1、时机召回（在有害段之前或之内触发的比例）。
3. 扫一个权重（类似本文的 $\tfrac12$ vs 只用纠偏），画出交换曲线。

**判据**：若每 1 点终局 F1 要换 3–5 点时机召回 ⇒ 我们的评测与本文同构，**"总漏过率"这个 KPI 在鼓励"晚点判"**。

### 6.4 数据构造要点（若要训图审）

- **每条安全样本配一条有害孪生**，同一 prompt、只差"是否有 uplift"。
- **孪生必须同源**（同一生成器 / 同一编辑链），否则风格成为代理。
- **不要只重标不补对**：本文实测只重标 19,033 条 → FPR 减半但**召回掉 17 点**。
- 若用线性注意力骨干，**不要开 packing**（本文实测隐状态差异到 0.23）。

### 6.5 评测要点

- **一个全局决策规则**，不按子集调阈值（省下的 3 点是假的）。
- **报留出**，不报样本内（本文差 0.3 点，但仍要报）。
- **必须报"池化方向"**：池化后是"漏多于误"还是"误多于漏"，取决于基率，不能从 macro F1 推。
