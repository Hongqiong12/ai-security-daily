## 一、背景与问题

### 动机：探针冻结了，但它读的骨干被换掉了

部署方给护栏探针设一次阈值（目标是 **1% 良性 prompt 误报率**），然后把探针和阈值都冻结。之后上游骨干被一个**部署方没有排期的新版本**替换——探针仍在线性读那些 hidden states，但分数分布已经变了。

论文问的是：**阈值还停在原来那个 operating point 上吗？** 以及：**现有的"benchmark 是否 stale"判据能不能发现这件事？**

### 与本仓库主线的关系

这是「同一 Prompt 跨版本生成的风险漂移」「6 个模型版本迭代看板」「策略热更新」「误杀率 5.2% 为硬约束」四条业务线**第一次拿到完整的实测价码**：

- 它证明 **AUROC 不变 ≠ operating point 不变**（差 ≤0.0058 而 FPR 涨 14 点）；
- 它证明**"用存储良性 prompt 重设阈值"不需要新标注**就能恢复误杀率——这正是 5 节点算力现实下最便宜的动作；
- 它同时给出这个便宜动作的**攻击面**（1% 投毒就足以废掉检查），避免把"重设阈值"当成免费午餐。

## 二、核心方法

### 2.1 冻结阈值测量协议

| 项 | 设定 |
|---|---|
| 单元 | **18 个 cells**，覆盖 **16 次公开语言模型更新** |
| 分相 | Phase 1（9 headline cells）+ Phase 2（**预注册**的 9 cells），两相在**更新类型与输入格式**上不同 |
| 探针 | 线性分类器，读骨干 hidden states；每 seed 用 4,000 条 prompt（2,000 harmful + 2,000 benign），20% 留出，拟合 3,200 条 |
| 阈值 | 校准负例上使"≤1% 良性被打分过线"的最小 distinct 分数 |
| 校准集 | Phase 1 **1,000** negatives / Phase 2 **5,000** negatives ⇒ 阈值分别落在约第 10 高 / 第 50 高负例分数附近 |
| 重采样 | 把 pooled negatives 按原尺寸**重划分 1,000 次**，每次重设阈值后取平均 |

**"两相 + 预注册"** 是本篇最值得学的设计：Phase 2 不是拿 Phase 1 的结论再讲一遍，而是换了更新类型与输入格式后的独立检验，且提前登记。

### 2.2 三种检测手段与两种修复

| 手段 | 读什么 |
|---|---|
| benchmark staleness criteria | AUROC 等判据（现有做法） |
| 基于该判据的规则 | 是否标记"率翻倍/减半"的 layer cells |
| **label-free rate estimate** | **只读存储良性 prompt 分数的均值/方差（两矩）**，估计部署阈值下的实际 FPR |
| 修复 | 用存储或新采的良性 prompt **重设阈值**（无需新标签） |
| 反制 | 对参考集投毒 1%，看检查是否失效 |

## 三、技术细节

1. **operating point 不是概率校准**：论文特意声明，文中"calibrated"指的是**冻结阈值下的 FPR/TPR**，不是 ECE / 概率校准。⇒ 这与 11-05「SQM 校准前后 Spearman 0.494 不变」是同一个"排序 vs 决策"分栏，但更硬：这里排序几乎没动，决策崩了。
2. **阈值依赖划分**：1,000 负例时阈值≈第 10 高，5,000 负例时≈第 50 高；校准/评测怎么切会改变 operating point。所以作者重划分 1,000 次取平均，而不是报一次切分。
3. **两矩模型的解释力**：只用更新后同一批良性 prompt 分数的均值与标准差，就能在 **0.905（63 个预注册 cells）** 内把 FPR 变化解释到 1.5 倍因子以内；在真正发生漂移的 22 个 cells 里仍有 **0.773**。
4. **硬件对照**：按抽取记录，18 个 headline cells 里 14 个前后跑在同一 GPU 型号上（Phase 1 V100 / Phase 2 A100），另有 4 个单独在 VI-B 交代 ⇒ 排除"换卡导致分数漂移"的替代解释。
5. **攻击建模**：控制更新的攻击者可在 **3/5 seeds** 中把三个目标类目之一的检测压下来，而**两种无标签检查都没发现**，只有事后带标签检查发现 ⇒ 无标签监控有明确边界。

## 四、实验与结果（论文口径）

### 4.1 冻结阈值的失效规模

| 观察 | 数值 |
|---|---|
| 1% 目标下 Phase 1 「fail closed」 | **8 / 9** cells |
| Phase 2（预注册，descriptive） | 3 / 9 cells fail closed 或 fail open（其中 2 闭 1 开） |
| **最大 FPR 上升** | **1.01% → 15.12%**（约 15 倍） |
| 同批 cells 的 **AUROC 变化** | **≤ 0.0058** |
| benchmark staleness 判据 | **没有一个被判为 stale** |
| 由这些判据导出的规则 | 只标记出 **0.019** 的 layer cells（真正翻倍/减半的那些） |

> **这是全篇最该记住的一行**：`AUROC ≤0.0058` 与 `FPR 1.01% → 15.12%` 同时成立。任何只盯 AUROC / 排序指标的看板，都会把这次事故判为"模型没变化"。

### 4.2 无标签检查与修复

| 动作 | 结果 |
|---|---|
| label-free rate estimate | 标记 **0.918** 的受损 Phase 1 layer cells，清除 **0.898** 的未受损 cells |
| 两矩模型 | 在 **0.905 / 63** 预注册 cells 内把变化解释到 1.5 倍因子内；漂移的 22 cells 中 **0.773** |
| **重设阈值（存储或新采良性 prompt）** | 9 个 Phase 1 cells 全部把 FPR 拉回目标；均值 **0.96–1.02 × 目标**（无需新标签） |
| **参考集投毒 1%** | 最多只剩 **0.017** 的有害 prompt 被标记 ⇒ 检查被废 |
| 攻击者控制更新 | 在 **3/5 seeds** 中压低三个目标类目之一的检测；**两种检查均漏过**，post hoc 带标签检查才发现 |

### 4.3 迁移到业务的三个直接结论

1. **误杀率必须按"实际 FPR"监控，不能按 AUC/排序代理**；
2. **版本升级是一次独立的 calibration 事件**，不是"模型换了但阈值可以不动"；
3. **无标签重设很好用，但参考集必须防投毒/防污染**，且要保留一条带标签的事后检查通道。

## 五、局限性

1. **只在语言模型激活探针上验证**：不是图审 / 多模态分类器；迁移到 image-only 图审 SFT 是**结构同构**，不是已验证结论。
2. **更新类型与输入格式在两相间不同**，作者自己把 Phase 2 标为 descriptive，不做因果归因。
3. **1% 目标是单一 operating point**：本项目误杀率 5.2% / 漏过率 3.42% 是双约束，论文没做双约束联合优化。
4. **两矩模型是近似**：在漂移 cells 上只有 0.773 落入 1.5 倍因子，不能当精确预测器。
5. **无标签检查对"定向压低某一类目"的攻击失效**：这正好对应本项目 L2_30 叶子类目——**聚合 FPR 正常不代表某个类目没被压掉**（与"整体 F1 微涨而 L3 宏 F1 回退"同源）。

## 六、复现指南

**论文复现**
1. 固定探针与阈值（1% 目标），冻结；对 16 次公开 backbone 更新逐一代入，记录 FPR / TPR / AUROC。
2. 分两相（换更新类型与输入格式），Phase 2 预注册；做 1,000 次重划分平均。
3. 三种检查并列：staleness criteria / 由其导出的规则 / label-free rate estimate（两矩）。
4. 用存储良性 prompt 重设阈值并复测 FPR；再对参考集投毒 1% 复测。
5. 加硬件对照与"攻击者控制更新"的定向类目攻击。

**本项目迁移建议（零训练，半天—1 天，最优先）**

| 动作 | 做法 | 判据 |
|---|---|---|
| **6 版本看板补"实际 FPR"列** | 每个 ckpt 在**同一批冻结良性样本**上算部署阈值下的实际误杀率，与 AUROC/macro-F1 并列 | 出现"AUROC 变 ≤0.01 而 FPR 翻倍" ⇒ **历史 AB 结论需按版本重算**（本篇 1.01→15.12%） |
| **把版本升级登记为 calibration 事件** | 每次图审/改写模型版本变更，强制落一条：`冻结阈值 / 重设阈值 / 未重设` 三态 + 校准集指纹 | 未重设而 FPR 已漂 ⇒ 该版本指标不可与前一版直接比（对应"配置指纹"纪律） |
| **两矩无标签体检** | 用存储良性样本分数的均值/方差估计当前实际 FPR，不需新标注 | 估计值与实测差 >2 点 ⇒ 分布形状已变（两矩不够），需带标签复核 |
| **参考集防污染** | 对存储良性 prompt 做来源审计 + 抽样人工复核；保留一条 post hoc 带标签检查 | 参考集里混入 ≥1% 有害样本即判该次重设作废（本篇 ≤0.017 检出率） |
| **分层宏平均背离检测** | 除全局 FPR 外，按 L1 × L2_30 叶子逐格报 FPR | 全局 FPR 稳而某叶子类目 FPR 翻倍 ⇒ 命中"定向类目攻击/子类劣化"，聚合口径掩盖了它 |

## 附：对业务主线的三句话

1. **"排序没变"不等于"决策没变"**：AUROC ≤0.0058 与 FPR 1.01% → 15.12% 同时发生，现有 staleness 判据一个都没报 ⇒ 多版本回归看板必须把 operating point 当一等公民。
2. **最便宜的修法也最有边界**：用存储良性 prompt 重设阈值无需新标注、9/9 恢复（0.96–1.02× 目标），但 1% 投毒就把检出压到 ≤0.017，且定向类目攻击两种无标签检查都漏 ⇒ **零成本不等于零风险**。
3. **对"整体指标微涨而 L3 宏 F1 回退"给出了机制解释**：聚合 FPR 是稳定的，被压掉的是某一个类目；按 L1×L2_30 逐格监控是唯一能看见它的口径。
