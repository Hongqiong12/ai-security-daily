**论文主页**: https://arxiv.org/abs/2611.06476

## 一、背景与问题

### 动机

DPO 在长度归一化奖励下，隐式奖励间隔会涨得很大（本实验到约 7 个 β 单位）。IPO 一路的工作认为这个无界增长本身是病理，Razin 等指出"似然位移"（chosen 的概率下降，质量流向分布外），Cal-DPO 观察到绝对似然普遍下沉并给了校准修法。

但这些分析主要建立在**大模型全参微调 + judge 评测**上。论文问的是一个更贴地的组合：

> 小模型 + LoRA + 长度归一化奖励 + 严格的格式任务，间隔涨上去，下游能力会**均匀**退化，还是**选择性**退化？

### 三条论断

1. **对齐税是分级且任务选择性的**：抽取任务 −0.55（等价）、JSON 任务 −3.52（小但真实）、路由任务 **−30.16**（灾难）。
2. **退化的来源极不对称**：chosen 奖励几乎不动（保持项锚住了），**≥96% 的间隔增长来自压制 rejected**。rejected 奖励被压到 **−14.2**。
3. **一个严格的字符串匹配评分器把"表面形式变化"报成了"能力崩塌"**：0.550 vs 0.981。

第 3 条是本文对本项目最有价值的部分。

## 二、核心方法

论文明确声明：**这是刻画性研究（characterization study），不提新方法、不做方法对比。** 这条自我限定值得尊重——它的贡献全在"怎么测"。

### 2.1 训练配方

| 项 | 设置 |
|---|---|
| 基座 | Qwen3.5-4B |
| 微调 | **稀疏 LoRA，8/32 层，0.034% 参数** |
| 目标 | 长度归一化 DPO + **SFT 保持项（权重 0.5）**，等价于 RPO |
| 后端 | nf4 训练；另在未量化的 fp16 基座上复测 |
| 任务 | 3 个结构化金融申报任务：extraction / json / router |
| 种子 | 8（seed 0/1 是 pilot 的确定性重跑） |
| 预注册 | 是。6 个假设在看结果前冻结 |

### 2.2 评测协议（这是方法主体）

**打分器 v2 的四层分类**，按顺序判定：

| 层 | 定义 |
|---|---|
| `FORMAT_BREAK` | 输出过不了解析门（如 router 必须以固定格式开头） |
| `PASS` | 与 gold 严格匹配 |
| `SURFACE_FORM` | 严格不匹配，但**规范化后**匹配（如 "Item 1" 写成 "1"） |
| `SEMANTIC_ERROR` | 规范化后仍不匹配 |

主指标 = **语义准确率 = PASS + SURFACE_FORM**。`FORMAT_BREAK` 单独追踪。

**规范化规则在看确认性结果之前冻结**（只对 extraction 有：section id 走 `\d+[A-Z]?`、case-fold、忽略附加标题）。

### 2.3 主检验：预注册 TOST 等价检验

零假设不是"没有差异"，而是"差异超出 ±5 点"：

$$H_0:\ \lvert\Delta\rvert\ge 5 \quad\text{vs}\quad H_1:\ \lvert\Delta\rvert<5$$

两套区间：seed 级 90% CI（$n=8$）+ item 级 bootstrap 90% CI。**必须两套都过才算等价**。

## 三、技术细节

### 3.1 为什么用 TOST 而不是"没有显著差异"

论文的原话值得抄：

> "Studies sometimes report 'no significant difference' without the power to distinguish 'preserved' from 'underpowered to detect a real drop.'"

**"没显著差异"是"没证据说有差异"，不是"有证据说没差异"。** 我们的改写 A/B 里，"改写后帮助性未显著下降"这句话目前就是这个毛病。

### 3.2 间隔的账

| 项 | 值（nf4） |
|---|---|
| 最终隐式奖励间隔 | ~7 β 单位（fp16 基座上测约 3） |
| rejected 奖励 | **−14.2** |
| chosen 奖励 | **−0.072 ~ +0.052**（几乎不动） |
| 间隔来自压制 rejected 的比例 | **≥96%** |

### 3.3 量化敏感性

QLoRA 的奖励间隔在 **nf4 训练**与**fp16 未量化测量**之间最多差 **3.4×**，且**差距依轴而异**。⇒ 用 nf4 的间隔读数去解释 fp16 的行为，会系统性地错。

## 四、实验与结果

### 4.1 主表：TOST（Table 2，±5 点，语义准确率，step 180 vs 基线）

| 任务 | 基线 | 最终 | Δ | seed 90% CI | item 90% CI | 落在 ±5 内的种子 | 判定 |
|---|---|---|---|---|---|---|---|
| extraction | 97.50 | 96.95 | **−0.55** | [−2.07, +0.98] | [−1.80, +0.86] | **8/8** | 等价 |
| json | 98.75 | 95.23 | **−3.52** | [−4.56, −2.47] | [−5.31, −1.95] | 7/8 | **不等价**（点估计在 ±5 内但区间越界） |
| router | 93.75 | 63.59 | **−30.16** | [−35.65, −24.66] | [−34.92, −25.47] | **0/8** | 灾难 |

**json 这一行是本表最有教学价值的一格**：点估计 −3.52 **落在了 ±5 以内**，如果照常规做法只看点估计，结论会是"没超阈值，通过"。但 item 级区间下界 −5.31 **越过了 5**。⇒ **"点估计达标"与"等价成立"是两件事。**

### 4.2 评分器伪影：0.550 → 0.981

| 打分方式 | extraction 在 margin 3 的准确率 |
|---|---|
| 严格字符串匹配（seed 0） | **0.550** |
| 规范化后（scorer v2，seed 0） | **0.981**（69/72 = 96%） |
| 严格匹配（8 seed 均值） | 0.616 |
| 规范化（8 seed 均值） | **0.988** |

**翻转的 69 个条目全部是 section 标识符的表面形式变体**：模型输出 "1" 而 gold 是 "Item 1"，输出 "7A" 而 gold 是 "Item 7A"。语义全对。

论文的措辞：
> "This is the difference between 'catastrophic collapse at margin ≈ 3' and 'capability preserved with a transient register shift.'"

**同一批输出，两把尺子，一个说崩了 44 点，一个说只掉了 1 点。**

### 4.3 非单调：损伤窗口在 margin 1–3（Table 3，router，8 seed 均值）

| 检查点 | 间隔 | 语义准确率 | `FORMAT_BREAK` 率 | 内容错误率 |
|---|---|---|---|---|
| step 20 | 0.75 | 0.852±0.015 | 0.001±0.002 | 0.148±0.016 |
| margin 1 | 1.09 | 0.816±0.030 | 0.007±0.010 | 0.177±0.038 |
| **margin 3** | 3.12 | **0.587±0.061** | **0.196±0.089** | 0.217±0.071 |
| margin 5 | 5.13 | 0.626±0.049 | 0.133±0.096 | 0.241±0.083 |
| final | ~7 | — | 0.106（回落） | 0.258（继续升） |

**两个失效模式走两条路**：`FORMAT_BREAK` 在 margin≈3 冲到 0.196 后回落；**内容错误率单调上升**。

⇒ 最终准确率在 margin 3 之后的"部分恢复"，**是格式断裂退潮，不是内容变对了**。这是"总分先跌后回"这种曲线最典型的误读来源。

### 4.4 三处被证伪的预注册假设

论文的预先注册被证伪三次，每次都改了结论：

1. **"有界零假设"这个头条**（json 与 router 都没过 ±5）→ 撤掉。
2. **"style 轴在每个检查点都大于 tool 轴"** → fp16 下 0/4 检查点成立，nf4 下 2/4。**final 检查点的逐对排序依后端而定。**
3. **"gold 完全稳定"**（nf4 下 $\lvert\Delta\rvert\le0.01$）→ fp16 复测显示 **json −1.04、router −1.47**，改为"gold 被选择性保护但任务选择性地下沉"。

## 五、局限性

### 5.1 论文自述（写得非常清楚）

- **不研究安全/拒答任务**——而 Razin 等正是在那里展示了灾难性位移。
- 单一 4B 模型，稀疏 LoRA（8/32 层，非全参），长度归一化 + 保持项（0.5），**偏好对是易分的合成数据**。
- 三个结构化任务，两个（json/router）本质是"格式"任务。
- 无 no-retention 对照组，因此**不归因**行为损伤到任何单一梯度通道。
- 格式对齐度**未直接测量**（只是与观测共变）。

### 5.2 本报告补充的四条

1. **"不研究安全任务"这条限制，恰好是我们最需要的部分。** 它的 −30 点在 router 上，而安全/拒答任务的位移可能更大（Razin 的结论）。⇒ **不能把 −0.55 / −3.52 这两个"温和"数当成安全改写的预期损失。**

2. **规范化规则是"事后写、事前冻"的**。论文诚实披露：pilot 发现严格匹配崩了，才写了规则，然后冻结，再跑确认实验。**这个顺序是对的，但它意味着规则是针对"已看到的现象"设计的。** 迁移时若照搬，可能会漏掉别的形式变体。

3. **"任务选择性"的机制解释只是共变，不是因果。** 论文说"退化排序跟随格式对齐度"，但格式对齐度没测。⇒ 这条只能当**假设**用。

4. **8 个种子撑不住 item 级结论。** 论文在 json 上用 item 级区间推翻了点估计结论——这个做法是对的，但 item 级 bootstrap 假设条目可交换，而条目来自同一批生成，**存在聚类**。论文自己提到"clustered item-level interval"，但没给聚类校正。

## 六、复现指南

### 6.1 能直接搬的四件（零训练）

1. **四层打分器**（格式断裂 / 严格通过 / 表面形式 / 语义错误），**把"看起来错了"分成"格式错"和"语义错"**。
2. **规范化规则事前冻结**的纪律。
3. **TOST 等价检验**替代"没有显著差异"。
4. **两套失效模式分列**（格式断裂率 vs 内容错误率），不要只报总分。

### 6.2 最小可迁移实验（半天，零训练，直击"改写是否损伤帮助性"）

**目标**：验证"改写后帮助性下降"这个结论有多少是尺子造成的。

1. 取 200 条"需改写"的 prompt，各跑：原 prompt / 改写后 prompt，各生成 4 张。
2. 人工或强 VLM 判"这张图是否满足了用户的**主要意图**"。
3. 用**两把尺子**各算一遍"意图满足率"：
   - **严格尺子**：要求主体、动作、风格、构图四项全部命中 checklist 才记 1
   - **宽容尺子**：只要主体 + 主要动作命中就记 1
4. 报三个数：① 两把尺子下的满足率；② 两把尺子的**差值**；③ 改写前后差值的变化。

**判据**：

| 观察 | 结论 |
|---|---|
| 严格尺子下改写掉 > 20 点，宽容尺子下掉 < 5 点 | **"帮助性退化"主要是尺子造成的**（表面形式/细节差异被记成失败），先修评分器再谈改写策略 |
| 两把尺子都掉 > 10 点 | 真实退化，改写确实改了需求 |
| 严格尺子下**原 prompt 本身**就只有 60% | 尺子太严，任何 A/B 都无分辨率 |

### 6.3 数据构造要点

- 必须有"易分"与"难分"两档偏好对：论文用的是易分合成数据，这限制了结论外推。
- 必须有 no-retention 对照组才能谈归因。我们的改写 RL 同理：**必须有一个"不加载改写、只做安全判定"的对照臂。**

### 6.4 评测要点

- **点估计达标 ≠ 等价成立**，必须报区间。
- **同时报格式断裂率与内容错误率**，否则"先跌后回"的曲线会被读成"恢复了"。
- **量化后端必须注明**：nf4 与 fp16 的间隔读数差 3.4×。

## 附：与业务的三条硬对应

| 论文事实 | 我们的对应现状 | 可执行动作 |
|---|---|---|
| 严格匹配 0.550 vs 规范化 0.981 | 我们判"改写后图是否还满足需求"没有统一评分器，靠人看 | 建四层打分器（格式/严格/表面/语义），并冻结规范化规则 |
| 帮助性退化 −0.55 / −3.52 / −30.16，任务选择性 | 我们只有一个"帮助性"总分 | 按叶子类目 × 任务类型分列，报"退化最重的那一格"而不是总分 |
| 点估计 −3.52 在 ±5 内但区间越界 | 我们用"未显著下降"当通过 | 改 TOST：$H_0:\lvert\Delta\rvert\ge\delta$，双向区间都过才算等价 |
