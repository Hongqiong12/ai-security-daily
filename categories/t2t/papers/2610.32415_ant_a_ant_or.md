# 单标签基准把"合法分歧"判成了"标注错误"：Fleiss κ 38.77 的那个类目，才是我们的处境

## 一、背景与问题

### 动机

LLM 标注已经能规模化替代人工，但**评测这套标注的标准本身是失真的**。现有 LLM 标注基准有两个系统性简化：

1. **不给标注规范文档**。而真实标注任务几乎都由一份冗长、任务特定的 guideline 管着，规范**本身就带有解释空间**；
2. **每样本只给一个 gold label**。而真实标注里，不同标注者会给出**发散的但都合理**的判断，尤其在有争议的边界样本上。

后果是：**单标签基准把"标注者分歧"和"标注错误"压成了同一个数**。一个模型在边界样本上"和某一个人不一样"就被判错——但它可能和另外三个人一样。

作者的原话点得很准：*"disagreement among annotators may reflect valid alternative interpretations rather than annotation errors."*

### 核心科学问题

**如果一件事本来就没有唯一答案，怎么判断自动标注器"达到人类水平"了？**

答案是：**不比"和 gold 一不一致"，比"和人的标注分布一不一致"**——用 **Fleiss' κ**。

### 为什么这篇对我们要紧

我们的标签审计当前在做的事，正好落在这个陷阱里：

- `full_check.py` 让 LLM 复判每条样本，然后**与现有单标签比对**，不一致就标成"疑似错标"；
- 但 PORN / VULG 边界、VULG-HINT-EDGE 这类**本来就靠解释**的类目，一个 LLM 判"和原标签不同"**根本不能推出原标签是错的**。它只能推出"这个 LLM 的解读和标注者不同"。

这篇给了我们两样东西：

1. **一个外部刻度**：Fleiss κ 在七个真实任务上从 **38.77 到 83.50**。我们的边界类目如果落在 40–60，那它就不是"数据脏"，而是**和"医疗隐私判定"同级的定义二义**——这两个诊断的治疗方案完全相反。
2. **一套可用的方法**：ANT-OR 用 3 标注员 + 1 验证员 + **判别维度池**（从"2 正 1 负"三元组蒸馏出区分混淆类目的决策规则），不用训练，accuracy +4.5，与人类 κ 差距收进 2 点。

而且它是**蚂蚁集团**的工作——同类业务体量下的落地经验，比学术基准更有参考价值。

## 二、核心方法

### （0）ANT-A 基准的构造

三步（Fig.2）：

1. **选领域相关样本**：7 个数据集 × **各 1,500 条**；
2. **建立标注规范**：先做 **pre-annotation pilot（预标注试点）** 才定稿——规范不是凭空写的，是从试点里收出来的；
3. **每样本收 5 份独立人工标注**，用来量标注者间一致性。

### （1）七个数据集与 κ 分布（全文信息密度最高的一张表）

| 数据集 | 领域 | 模态 | 样本 | 类数 | **Fleiss κ** |
|---|---|---|---|---|---|
| Disease Privacy Assessment | 医疗 | 文本 | 1,500 | 2 | **38.77** |
| Billing Scenario Classification | 电商 | 文本 | 1,500 | 31 | **83.50** |
| Medical Entity Extraction | 医疗 | 文本 | 1,500 | 22 | **82.09** |
| Social Text Classification | 通用 | 文本 | 1,500 | 15 | **44.62** |
| Image Attribution Recognition | 通用 | **视觉-语言** | 1,500 | 3 | **58.59** |
| Image Classification | 电商 | **视觉-语言** | 1,500 | 24 | **81.27** |
| Image Text Relevance | 通用 | **视觉-语言** | 1,500 | 3 | **56.37** |

读法（这张表的排序不按类数，按"定义清晰度"）：

- **κ 最高的两组都是"有客观锚"的**：账单场景（类多但边界靠规则）、医疗实体抽取（实体边界可核）。即便 31 类，κ 也有 83.50——**类多不等于分歧大**。
- **κ 最低的两组都是"判定型"的**：医疗隐私评估 κ=**38.77**（只有 2 类！）、社会文本分类 κ=44.62。**2 类任务的 κ 比 31 类还低 45 点**——这一个对比就足以推翻"类目多所以难"的直觉。
- **三个视觉-语言任务**：58.59 / 81.27 / 56.37。判"图里有什么"（Image Classification，24 类）κ=81.27 很高；判"图文是否相关"（3 类）只有 56.37。**又是"判定型"低、"识别型"高。**

**这条规律可以直接搬到我们的类目上**：PORN 的明确类（识别型：有没有裸露）应当是高 κ；VULG-HINT-EDGE（判定型：这个暗示算不算越线）应当低 κ。**如果我们测出来不是这个形状，说明标注流程本身有问题，而不是类目有问题。**

### （2）ANT-OR：三个池 + 一个归因

架构是 **annotator–verifier**：三个标注员各自独立出标签 + 理由（prompt 分别优化），一个验证员比对三方理由后定终局。作者刻意选了这套而不是 debate（多轮开销大）或 planner–worker（计划错误会传播）。

组件一：**对比样本池（contrastive sample pool）**

对每个 agent $a$ 维护正池 $S_a^+$ 与负池 $S_a^-$，每条实例带一个**质量分** $w$（初始 1）。判定"正"的口径是：**与 5 份人工标注中的至少 2 份一致**。

检索打分：

$$\text{Score}(q, s_i) = \text{sim}\big(E(q), E(s_i)\big)\cdot w_i$$

每次检索后按预测对错更新质量分：

$$w_i \leftarrow w_i + \Delta w_i,\qquad \Delta w_i = \alpha\cdot\begin{cases}1-\rho, & \text{正确}\\ -\rho, & \text{错误}\end{cases}$$

$\rho$ 是当前全局准确率，$\alpha$ 是步长。⇒ **检索不只按语义相关，还按历史可靠度**。贡献过正确预测的样本被抬高，导致错误的被压。

组件二：**判别维度池（discriminative dimension pool）** ← 本文最该抄的部件

当一个 agent 判错时，先构造错误样本 $s^-$，再检索**两个语义相近的正确样本** $s_1^+, s_2^+$，组成三元组 $(s_1^+, s_2^+, s^-)$，让 LLM 从中蒸馏出一条**判别维度** $d$：

$$d = \text{LLM}_{\text{Mine}}(s_1^+, s_2^+, s^-)$$

$d$ 是一个**结构化文本单元**：含"从对比案例里萃取的类目特定决策准则" + "该准则适用的场景"。

去重与融合：新维度 $d$ 先检索池中语义相近的 $d_{\text{old}}$，命中则融合：

$$d := \text{LLM}_{\text{Refine}}(d_{\text{old}}, d)$$

每个维度带一个 **support count**（被融合过几次），作为"有多少个推理错误共享了同一判断模式"的估计。**只保留 support count ≥ 2 的维度**——用来压掉偶发模式。

并维护"维度 ↔ 源样本"的双向多对多映射，保证可追溯。

组件三：**维度–样本耦合注入**

取 top-$K$ 高分样本 + 与它们关联的判别维度，**同时注入 prompt**。作者的批评点：现有方法要么只注例子、要么只注规则，**ANT-OR 两者都给**——具体证据 + 抽象准则。

组件四：**错误归因驱动的 agent 级优化**

判错时（同样以"未达 5 份中 2 份"为触发），把 query、交互历史 $H$、多数标签 $g$ 一起喂给归因模型：

$$M_{\text{attr}}:(q, H, g)\to\{(a_i, r_i)\}_{i=1}^n$$

识别"哪些 agent 该负责 + 错误原因"（内在失误 vs 上游误导信息）。然后只对**被点名的 agent** 优化它的 prompt：

$$p_a^{\text{opt}} = \text{LLM}_{\text{Opt}}\big(p_a;\{(q^-, r)\}, s^+, d\big)$$

⇒ 把"具体失败 + 对比支撑 + 判别维度"三者一起塞进优化。**这正是把"改标签靠人读标准文档"这一步自动化。**

---

## 三、技术细节

- **不训练任何模型**，纯 prompt 层优化——对我们 5 节点的算力约束是友好的；
- 报告口径是 **agreement@≥2 accuracy**（与至少 2 份人工标注一致即算对）和 **Fleiss κ**（与人类标注分布的吻合度）；
- 对比基线包括单 agent、静态多 agent 工作流（采样 / 对话 / 生成-验证流水线）等；
- 代码与基准开源于 `https://github.com/Krueske/ANT-OR`。

## 四、实验与结果

| 指标 | 结果 |
|---|---|
| agreement@≥2 准确率 | 比最强基线 **+4.5 点** |
| Fleiss κ 与人类的差距 | 平均**收进 2 点以内**（七数据集上最优） |
| 需要训练？ | **不需要**，纯 prompt 优化 |
| κ 跨度（人类） | **38.77 — 83.50** |

**"+4.5 点"要和"κ 收进 2 点"一起看才有意义**：准确率提升是"更常和多数人一致"，κ 收敛是"整体分布更像人"。后者才是分布感知评测的本来目的。只报前者会掩盖"模型全押在多数类"的可能。

## 五、局限性

1. **每个数据集只有 1,500 条**，且是精选的领域样本。真实业务里 7W 量级的分布更杂，κ 可能更低。
2. **5 份标注不等于真值**，"至少 2 份一致即算对"是个操作化定义，不是正确性证明。若 5 个人**集体错**（规范本身误导），ANT-OR 会把错的方向学得更牢——**它优化的是"像人"，不是"对"**。
3. **验证员是 LLM**。三方理由比对由模型做，模型自身的偏好会进入终局判定。论文没有对验证员做独立校准。
4. **判别维度的 support count ≥ 2 是个硬阈值**，没有敏感性分析。对长尾类目，这个门槛可能直接把稀有但正确的规则全过滤掉——**这正好是我们 VULG-HINT-EDGE 的风险**。
5. **（补充）不含安全/内容审核任务**。七个数据集里没有一个是内容安全类目。⚠️ 这很重要：**内容安全类目的 κ 很可能低于 38.77**，因为类目定义本身带政策判断，不只是语义歧义。
6. **（补充）成本没报**。三 agent + 验证员 + 归因 + 优化，一次标注至少 5 次模型调用。7W 条全量跑的成本需要自己估。

## 六、复现指南

### 我们可以直接做的三件事（按性价比排序）

**第一件｜先测我们自己的 κ（半天，最该先做）**

这一步把"该改标签 / 该改定义 / 该补数据"的三选一变成可判定的。

做法：
1. 从 7W 训练集里按 **L1 × L2_30** 分层抽 **1,000 条**（每格尽量 ≥20）；
2. 找 **3–5 人**独立标注（不需要专家，需要的是"按现有规范文档判"的人）；
3. 算 **Fleiss κ**，按一级类目和层级切片报；
4. 手边没有 5 个人？**退一步用 3 个异构 LLM + 1 人仲裁**，虽不等价但能出量级。

判据（这张表直接决定路线）：

| 我们的 κ | 对标 | 结论 |
|---|---|---|
| **≥ 80** | 账单分类 83.50 / 医疗实体 82.09 | 定义清晰，**错在标注执行** → 继续清洗 + 补 case |
| **60–80** | 图像分类 81.27 / 图文相关 56.37 之间 | 轻度二义 → **补模型卡 + 边界 case 集**即可 |
| **40–60** | 图像归因 58.59 / 社会文本 44.62 | 中度二义 → **必须写判别维度**（见下一件） |
| **< 40** | 医疗隐私 38.77 | **定义本身有问题** → 改类目定义，改标签无用 |

**特别注意**：如果 VULG-HINT-EDGE 的 κ < 40 而 PORN 明确类 κ > 80，那"VULG-HINT-EDGE 最差"这个结论就该从"模型不行"改写成"**这个类目目前不可判**"。这是完全不同的一句话，也是过去几周一直在绕的那个弯。

**第二件｜把"判别维度池"灌进 `full_check.py`（1 天）**

这解决的是 `full_check.py` 里"LLM 判断逻辑没真实生效"的根因——**单次 LLM 判断没有可依赖的判据，只能靠模型自己的先验**。改成：

1. 准备种子：每个易混类目对（PORN vs VULG、VULG vs out_of_scope）各准备 **2 条规范正例 + 1 条混淆负例**；
2. 让它蒸馏判别维度：`"这三条里，前两条属于 A，第三条被标成 A 但其实是 B。请写出区分 A 与 B 的判别维度，格式：{准则, 适用场景, 反例特征}"`；
3. 每个新维度与已有维度做语义去重 + 融合，累计 support count；
4. **只保留 support count ≥ 2 的维度**（这是压偶发规则的关键）；
5. 判每条样本时，把 top-K 相关维度 + top-K 对比样本**一起**放进 prompt（不要只给例子，也不要只给规则）。

判据：改前 vs 改后，在**人工确认过的 200 条边界样本**上的 agreement。若 < +3 点，说明判别维度没抓到东西，回去补种子。

**第三件｜把 AB 评测口径从 accuracy 换成分布一致性（2 小时）**

我们做图审双模型 AB 时用的是 accuracy / F1。这篇指出这在边界样本上是失真的。改成：

- 同一批样本分别由模型 A、模型 B 判；
- 对**有争议的样本子集**（人工 κ 低的那部分）单独报 **与人工分布的 κ**，而不只是 accuracy；
- 主表两列并列：`accuracy` + `κ_vs_human`。

判据：若 A 的 accuracy 高但 κ 低 ⇒ A 在"押多数类"，**上线后会在长尾类上崩**。

### 三个可以立刻写进规范文档的判定原则

1. **"判定型"任务和"识别型"任务的验收标准必须分开**。识别型（图里有没有裸露）看 accuracy；判定型（这算不算越线）看 κ + 边界 case 集的召回。
2. **分歧不是错误**。规范文档里要明写哪些格子允许合法分歧，以及分歧时按谁的口径定（ANT-OR 用"5 份中 2 份"，我们要定自己的）。
3. **判别维度是活的资产**，不是一次性文档。每轮审计都应该往池子里加维度，而不是重写规范。

### 不建议照搬的

- **不要**用"单次 LLM 复判 ≠ 原标签 ⇒ 疑似错标"这条规则。这篇的核心论点就是它无效。
- **不要**给长尾类目套 support count ≥ 2 的硬门槛。对 VULG-HINT-EDGE 这类样本本来就少的格子，这个门槛会过滤掉所有正确但少见的规则。**长尾格子应该降到 ≥ 1，并单独记录。**
