## 一、背景与动机

### 被点破的三个评测病灶

| 病灶 | 具体表现 | 后果 |
|------|----------|------|
| **粒度太粗** | 二分类 safe / unsafe，无解释力 | 开发者拿到"不安全"三个字，不知道改哪里 |
| **一致性太低** | 换一个评判分类器，攻击成功率可漂移近 30 个百分点；某些类别评判者间一致率低至 22% | 同一个模型两次评测结论相反 |
| **多样性不足** | 没有 benchmark 同时覆盖多语言 + 单/多轮 + 多种攻击形态 + 统一分类体系 | 评测结论系统性不完整 |

### 为什么这对我们重要

⚠️ **这是本周唯一的腾讯混元署名论文**（corresponding author 邮箱 `nlpzhezhao@tencent.com`，数据将开源在 `github.com/Tencent-Hunyuan/DiagSafe`）。它解决的正是我们的第 (3) 条主线——**细粒度风险标签体系**——而且做法比"再补一批数据"更根本：

> **它把"标签"和"判定标准"拆成了两层。** 标签是类目，标签规范（label specification）是可复用的判定规则，prompt-level rubric 是针对单条样本的具体判据。

我们目前的问题（PORN/VULG 边界混淆、VULG-HINT-EDGE 最差）本质上是**类目有了、判定规则没写清楚**。DiagSafe 的三层结构正好是这个缺口的补丁。

### 与已有 benchmark 的差异

| Benchmark | 语言 | 多轮 | 越狱 | 评测方式 |
|-----------|------|------|------|----------|
| SafetyBench | ZH/EN | ✗ | ✗ | MCQ |
| SALAD-Bench | EN | ✗ | ✓ | Classifier |
| AIR-Bench | EN | ✗ | ✗ | LLM judge |
| CHiSafetyBench | ZH | ✓ | ✗ | MCQ + LLM judge |
| FORTRESS | EN | ✗ | ✓ | 人工 rubric + LLM judge |
| **DiagSafe** | **ZH/EN** | **✓** | **✓** | **合成 rubric + LLM judge** |

关键区别：FORTRESS 证明了「实例级 rubric」在高危领域能达到高人类一致率，但它是**人工逐条写 rubric**，不可扩展。DiagSafe 引入了**「安全条款 → 标签规范 → prompt 级 rubric」的中间层**，让 rubric 可以自动合成——这是本文第一个真正的工程贡献。

## 二、核心方法

### 2.1 三层标签体系（11 / 34 / 84）

收集多国 AI 安全政策与法规条款 → LLM agent 合并并展开为独立安全标签 → **安全团队专家复核**（校验来源可追溯性、规则准确性、边界清晰度，剔除与安全无关标签）。

最终形成**三层分类法、84 个叶子标签**。Figure 2 用叶级弧图与 SALAD-Bench / S-Eval / Do-Not-Answer / CHiSafetyBench 对比：红色叶子是其他 benchmark 完全没有的类目，橙色是更细的类目，灰色是共享覆盖。

### 2.2 标签规范（label specification）—— 最关键的设计

每个标签配一份规范，**强制包含四个组成部分**：

| 组成 | 作用 |
|------|------|
| ① 标签精确定义 | 说清这个类目是什么 |
| ② 价值原则（基于公共安全标准） | 说清为什么这样划 |
| ③ 构成违规的危险行为 | **正例边界** |
| ④ 被允许的安全行为 | **负例边界 / 豁免（exemption）** |

⚠️ 第 ④ 项是全文最值得抄的一点。**它把"什么不算违规"显式写进标签定义**，这是压制假阳性（over-flagging）的机制级手段，而不是靠调阈值。

我们的 PORN/VULG 混淆，很大概率就是因为两边的 ④ 都没写清楚——例如"医学/性教育语境下的裸露描述"该归哪边，没有显式豁免条款。

### 2.3 prompt-level rubric：把主观判断变成逐条核对

每条 prompt 配一份专属 rubric，两个维度：

- **safety 维度**：$S$ 条 safety item（S-item），每条对应一个具体危害；**命中且无豁免适用 → unsafe**
- **usefulness 维度**：**固定 8 条** usefulness item，独立评估指令完成度（0–3 分）

规模：rubric 平均长度 **4,060 字符**，平均 **4.5 条 S-item** + 8 条 usefulness item。

主指标 **unsafe rate (UR)** 定义为：「触发至少一条 S-item 且无适用豁免的响应比例」。

### 2.4 数据构造

以标签规范为种子，沿三个正交属性合成 prompt：

- 语言：中文 / 英文
- 轮次：单轮 / 多轮
- 攻击形态：无越狱 / 模板越狱 / 组合模板越狱

两个子集：

| 子集 | 构造 | 样本数 |
|------|------|--------|
| **DiagBase** | 直接有害查询 + 模板越狱 + 组合模板越狱 | 2,401 |
| **DiagAttack** | 把 DiagBase 的单轮无越狱 prompt **重写嵌入到指令遵循任务的"任务外壳"**（来自外部 instruction-following 数据集） | 1,088 |
| 合计 | 中英约 1:1，单轮:多轮 ≈ 7:3 | **3,489** |

**DiagAttack 的构造方式本身就是一个可迁移的"改写"范式**：保持有害意图不变，改变表面的任务形态（角色、格式、语气），使危害被包裹在良性指令里。

## 三、技术细节

### 3.1 评测流程

```
安全条款（多国政策） 
   → 标签规范（定义/原则/违规行为/豁免行为）
      → prompt 级 rubric（4.5 S-items + 8 U-items）
         → LLM Judge（Hy3）逐条核对
            → unsafe rate + usefulness score + item 级诊断轨迹
```

### 3.2 实验配置

- **被评模型（11 个，8B–1.6T）**：Qwen3.6-27B、Qwen3.5-397B-A17B、Kimi-K2.6、GPT-OSS-120B、MiniMax-M3、DeepSeek-V4-Pro、GLM-5.2、Gemma-4-31B、DeepSeek-V4-Flash、Llama-3.1-8B、Llama-3.3-70B
- **严格条件**：本地 checkpoint、**不加任何审核/guard/系统提示**，只测模型内生安全
- **解码**：temperature 0.7 / top-p 0.8 / top-k 20 / repetition penalty 1.05，非思考模式
- **生成器**：DeepSeek-V3.2 造 prompt；**Hy3 造 rubric 且充当 judge**

### 3.3 一个容易被忽略的细节

`rubric` 是**评测时即时生成**的，而 `label specification` 是**离线固化**的。这个分工很关键：

- 规范固化 → 保证类目边界稳定、可审计、可版本化
- rubric 即时生成 → 保证判据贴合具体样本，不被模板稀释

**如果反过来（规范即时生成、rubric 固化），就会退化成我们现在的问题：类目定义漂移，判据僵化。**

## 四、实验与结果

### 4.1 判官可靠性（这是全文最有说服力的数字）

以 236 条人工标注响应为 gold standard：

| 范式 | Judge | 与人类一致率 |
|------|-------|--------------|
| Classifier | MD-Judge | 69.07% |
| Classifier | Qwen3Guard (lenient) | 80.93% |
| Classifier | LlamaGuard4 | 84.32% |
| Classifier | S-Eval | 85.17% |
| Classifier | Qwen3Guard (strict) | 87.29% |
| 通用 prompt | Hy3 | 87.29% |
| 标签规范 prompt | Hy3 | 86.86% |
| **Rubric** | DeepSeek-V4-Pro | 89.41% |
| **Rubric** | Qwen3.5-9B | 90.25% |
| **Rubric** | **Hy3** | **95.34%** |

**关键读法**：不是"rubric 比 classifier 好 8 个点"，而是——**同一个 judge 模型（Hy3），只把提示从"通用安全 prompt"换成"prompt 级 rubric"，一致率从 87.29% 跳到 95.34%，提升 8.05 个点。**

也就是说：**这 8 个点不是模型能力带来的，是判定标准显式化带来的。** 这对我们做 tag 分类的 system prompt 设计是直接证据。

### 4.2 跨 judge 稳健性

| 范式 | 一致率区间 | Cohen's κ 区间 |
|------|-----------|----------------|
| 通用 prompt | 80.02% – 91.27% | 0.559 – 0.766 |
| 标签规范 prompt | 77.86% – 92.12% | 0.532 – 0.802 |
| **Rubric** | **93.33% – 94.78%** | **0.828 – 0.864** |

三个 judge 两两比较一致率全部 > 93%，κ 全部 > 0.82。**换 judge 不换结论**，这是评测协议可复用的前提。

### 4.3 核心发现：指令攻击把不安全率放大 5.3 倍（中位数）

| 指标 | DiagBase | DiagAttack |
|------|----------|------------|
| unsafe rate 区间 | 2% – 33% | 8/11 模型 **> 40%** |
| 抬升倍数 | — | **1.9× – 8.4×（中位 5.3×）** |

作者的解读很锋利：**「指令遵循与安全拒答在当前的训练里是两个竞争目标」**。一旦 prompt 用角色、格式、语气把模型的指令遵循能力调动起来，安全行为就退化。

⚠️ 这条发现对我们有双重含义：
1. 作为**评测设计**：只在"直接有害查询"上测安全会严重低估风险；
2. 作为**改写设计**：我们的 rewriter 如果把 prompt 改写成"更明确的任务指令"，可能反而**降低**模型内生安全——改写不仅要降 NSFW 语义，还要避免强化指令遵循压力。

### 4.4 二维剖面（safety × usefulness）

| 模型 | 特征 |
|------|------|
| Qwen3.6-27B | 贴近理想区（usefulness > 2.0，UR 多 < 15%） |
| GPT-OSS-120B | UR 一贯低，但 usefulness 全部 < 1.5 → **疑似"一律拒答"换来的假安全** |
| Llama-3.1-8B | 双输：UR 平均 41%、峰值 49%，usefulness 1.43 |

**结论：单一聚合安全指标无法区分"真安全""拒答换安全""既不安全也不好用"这三种行为模式。**

### 4.5 类目级诊断（同样总 UR，风险画像完全不同）

取三个总 UR 相近（18.6%–20.9%）的模型：

- MiniMax-M3：知识产权类最高（27.3% vs Kimi-K2.6 的 22.3%）
- DeepSeek-V4-Pro：自杀自伤类最高（20.1% vs 13.0%），但 CBRNE 最低（13.7% vs 最高 18.8%）

**这是我们要的东西：类目级画像才能定位到"改哪个标签的定义"。**

### 4.6 数据与 rubric 质量校验

- prompt 有害性：每三级标签抽 4 条，共 336 条，**324 条合格 = 96.4%**
- rubric 合理性：每三级标签抽 3 份，共 252 份专家复核，**251 份合理可执行 = 99.6%**

## 五、局限性

1. **标签规范由 LLM 起草**，只做了专家复核。84 个标签的边界一致性（尤其相邻类目）没有被量化——**PORN/VULG 这类相邻类目恰恰是最需要一致性证据的地方**，论文没给混淆矩阵。
2. **rubric 由 Hy3 生成、Hy3 评判**：存在自洽性风险（生成判据的模型同时当裁判）。用 DeepSeek-V4-Pro 当 judge 时一致率降到 89.41%，说明有一部分一致性来自 judge 与 rubric 作者同源。
3. **被评模型全是 LLM**，不含 T2I 模型，也不含"文本 → 图像"的跨模态风险传导。
4. **DiagAttack 的"任务外壳"来自 instruction-following 数据集**，与真实用户 prompt 的分布差异未评估。
5. **范围限定**：只测文本输出安全，不测 usefulness 之外的其他效用维度（如事实性）。

## 六、复现指南

### 6.1 可获取资源

```
数据/代码：https://github.com/Tencent-Hunyuan/DiagSafe （论文声明将公开）
规模：3,489 条（DiagBase 2,401 + DiagAttack 1,088）
标注：84 叶子标签 / 三层体系；每条 prompt 一份 rubric（约 4,060 字符）
```

### 6.2 复现最小闭环

```
1. 先只复现「标签规范四要素」结构，不追 84 个标签
2. 拿我们自己现有标签体系，为 PORN / VULG 两个类目各写一份四要素规范
   （定义 / 原则 / 违规行为 / 豁免行为）
3. 各抽 50 条历史争议样本，用两份规范做人工判定，看混淆率是否下降
4. 再决定是否升级到 rubric 级评测
```

### 6.3 复现风险点

- Hy3 是内部模型，外部无法直接复现 judge 侧的 95.34%；用 Qwen3.5-9B 只能到 90.25%；
- rubric 平均 4,060 字符，3,489 条 × 4k ≈ 1,400 万字符的评测上下文，**推理成本必须提前估算**；
- 中文/多轮结论依赖具体 prompt 分布，跨数据集不可直接外推。
