## 一、背景与动机

### 问题设定

现有安全分类器大多是 $x \rightarrow y$ 的直映射：prompt 进，safe / harmful 出。中间那一步——**"这个用户到底想干什么"**——是隐式的。

作者的观点：

> 安全分类器应该把用户意图建模为 prompt 与标签之间的**显式信号**，而不是让它藏在模型权重里。

这样做的收益不只是精度，而是**可诊断**：模型判错时，你能分清是

- 意图理解错了，还是
- 意图对了但危害判定错了，还是
- 标签碰巧对但理由是错的。

### 为什么这个问题真实存在

有害性常常取决于用户的**底层目标**而非表面形式：

- 恶意请求可以藏在虚构情景、角色扮演、教育包装、长叙事里；
- 良性 prompt 也可能包含与不安全内容高度相关的词。

**这与我们 tag-first 分类的痛点完全同构**：VULG-HINT-EDGE 这类边界样本的困难，本质就是"字面是擦边描述，意图是成人内容"还是"字面是成人描述，意图是医学咨询"分辨不出来。

### 数据策略：不确定性筛样本（可复用的第一条）

AIMS 的构建不是均匀采样，而是**先用集成模型做不确定性估计，筛出意图真正起作用的样本**——模糊的、对抗的、边界模糊的 case。这正是"主动学习挑差异样本"的标准做法。

## 二、核心方法

### 2.1 数据：AIMS

| 项 | 值 |
|---|---|
| 来源 | WildGuardMix 的英文 prompt |
| 筛选 | 集成模型不确定性估计，富集边界/对抗/混淆样本 |
| 标注 | 意图描述（自然语言）+ 危害标签（4 点量表） |
| 规模 | **1,275 条唯一 prompt / 1,724 条 intent-label 标注** |
| 形式 | 三元组 $\mathcal{D}=\{(x, i^*, y^*)\}$ |
| 开源 | `jazhyc.github.io/aims-safety` |

**注意规模：1,275 条就够。** 这是本文最有产业价值的信息——意图标注这类"贵"的数据，不需要海量，需要**挑对样本**。

### 2.2 四个训练范式，同一个中间信号

| 范式 | 怎么用 intent |
|------|---------------|
| **SFT** | 对比两种输出格式：直接出标签 vs **先出意图再出标签** |
| **DPO** | 用模型自己生成的**错误意图**当 rejected：<br>· LE-DPO（Label-Error）：选那些翻转了安全标签的错误意图<br>· IF-DPO（Intent-Faithfulness）：选那些标签没变但误述了用户目标的意图 |
| **推理蒸馏** | 对比"有人类意图标注的教师轨迹" vs "纯推理无意图的教师轨迹" |
| **GRPO** | 奖励从"只校验标签"升级为**"同时校验意图忠实度"** |

四种范式共享同一个结构假设：**intent 是 prompt 与 label 之间的瓶颈变量（bottleneck variable）**。

### 2.3 GRPO 的奖励设计（对我们最直接）

| 奖励项 | 作用 |
|--------|------|
| $R_{\text{format}}$ | 结构化输出格式正确 |
| $R_{\text{label}}$ | 标签判定正确 |
| $R_{\text{len}}$ | 长度控制 |
| $R_{\text{intent}}$ | **意图与人类标注意图的忠实度** |

最终最优配置是 **label + intent 双奖励**，平均 F1 **0.836**。

## 三、技术细节

### 3.1 SFT 的关键对比：格式即先验

论文做了 format / prompting sweep（附录 C.1）。核心结论是：**只要把 intent 放进推理输出格式里（即使不额外给奖励），模型就已经被迫先想意图再判标签**——GRPO 的 label-reward-only 变体之所以也很强（0.809），就是因为格式本身是强 scaffold。

⚠️ **这对我们是直接背书**：我们的 `<tag><|reasoning|>reason...</|reasoning|>` 格式，tag 在前、reason 在后——如果 tag 是"层级风险标签"而不是"意图"，那么模型跳过意图直接预测 tag 的概率很高。**AIMS 提示：reason 段应该先显式复述意图，再落到标签。**

### 3.2 DPO 的两遍拒绝采样（two-pass rejection construction）

1. 第一遍：让模型生成多个候选意图；
2. 第二遍：**确定性地重标注**——把每个候选意图当作"如果模型真这么理解，该判什么标签"，从而知道哪个意图会导致标签翻转、哪个只导致目标误述。

这个设计很巧：它把"意图质量"变成了可自动判定的信号，不需要人对每个候选意图打分。

### 3.3 评测协议

- 五个外部安全 benchmark：WGTest、XSTest、AEGIS 2、ToxicChat、OAI Mod
- 指标：F1（二分类），另测推理延迟形成 Pareto 前沿
- 教师-学生扫描：12 组 teacher-student 配对

## 四、实验与结果

### 4.1 主结果（平均 F1）

| 类别 | 模型 | 平均 F1 |
|------|------|---------|
| 零样本 LLM | GPT-5.4 | 0.815 |
| 零样本 LLM | GPT-OSS-120B | 0.803 |
| 零样本 LLM | Claude Sonnet 4.6 | 0.782 |
| 专用 guard | Nemotron Safety 4B | 0.809 |
| 专用 guard | GuardReasoner 8B | 0.804 |
| 专用 guard | WildGuard 7B | 0.804 |
| 专用 guard | LlamaGuard 4 | 0.691 |
| 专用 guard | ShieldGemma 27B | 0.709 |
| **本文 SFT** | Gemma-3-12B on AIMS | 0.808 |
| **本文 DPO** | LE-DPO | 0.812 |
| **本文蒸馏** | 人类意图条件蒸馏 | 0.822 |
| **本文 GRPO** | **label + intent 奖励** | **0.836** |

**结论：1,275 条人工意图标注 + GRPO 意图奖励，平均 F1 超过最强的零样本 LLM（GPT-5.4, 0.815）和最强的专用 guard（Nemotron 4B, 0.809）。**

数据量差了两三个数量级。这是"数据质量 / 信号设计 > 数据规模"的一个硬证据。

### 4.2 分项增益

- Llama-3.1-8B SFT：0.749 → **0.792**（+4.3）
- Gemma-3-12B SFT：0.644 → **0.727**（ToxicChat，+8.3）
- LE-DPO：0.792 → **0.812**，ToxicChat 0.664→0.733、AEGIS 0.803→0.824
- 意图条件蒸馏：**0.822**，XSTest 0.936（**过拒测试集上接近最好 guard**）
- 蒸馏扫描：意图条件在 **9/12** 组 teacher-student 配对中胜过纯推理，其中 6 组是"人类意图"条件胜出

### 4.3 最有价值的定性发现（直接映射我们的 PORN/VULG 问题）

**发现一：SFT 的错误方向随分布翻转。**

| 数据集 | 错误构成 |
|--------|----------|
| AIMS | **64%** 是假阴性（有害判成安全） |
| WildGuardTest | **69%** 假阴性 |
| ToxicChat | 假阳假阴各半，**大量由"危害相邻词"触发的过拒** |

**发现二：模型能把意图说对，但标签还是被表面词劫持。**

论文报告：在 GRPO 修回来的 ToxicChat 过拒样本里，**有 6/71 例 SFT 与 GRPO 生成的意图 Jaccard 重叠 > 0.5**——即**意图表述几乎一样，标签却相反**。

> 这说明：SFT 能让模型"正确说出用户目标"，但仍然让**表面关键词覆盖最终决策**。

⚠️ **这就是 PORN/VULG 边界混淆的机制解释。** 不是模型"不懂"，是**判定没有被强制绑定到意图/语义上**。对比学习和奖励训练之所以有效，就是因为它把标签和意图**绑死**。

**发现三：DPO 与 GRPO 互补。**

- GRPO 擅长救**过拒**（结构化推理让良性意图显性化）
- DPO 擅长破**对抗外壳**（惩罚"洗白后的误解"）
- **约 30% 的 SFT 错误三者都救不回**（对抗包装、双用途请求、含危害相邻词的良性 prompt）

## 五、局限性

1. **只做 prompt 级分类**，不涉及响应级审核、多轮上下文追踪、拒答/转向/升级等下游决策。
2. **数据源单一**（WildGuardMix），且刻意做成"困难集"，**分布不具代表性**——不能直接当产线评测集。
3. **标注的 4 点危害量级在实验中被压成二分类**，丢失了分级不确定性（这正是我们层级标签体系想保留的东西）。
4. **部分监督来自模型生成**（DPO 的候选意图、GRPO 的意图 judge），存在自我强化风险。
5. **意图标注一致性只是"中等"**（附录 A.7 明说 moderate agreement），意图本身的标注边界不比危害标签更清晰。

## 六、复现指南

### 6.1 资源

```
数据/模型/代码：jazhyc.github.io/aims-safety
数据量：1,275 prompt / 1,724 标注
格式：{prompt, intent_description, harm_label(1-4)}
基座：Llama-3.1-8B、Gemma-3-12B（+ Qwen 系可自行替换）
```

### 6.2 迁移到我们 pipeline 的最小改造（推荐先做这个）

| 现状 | 改造 | 代价 |
|------|------|------|
| `<tag><\|reasoning\|>reason...</\|reasoning\|>`，tag 直接出 | 在 reason 开头**强制先写一句 intent**："用户意图是……"，再写风险判定 | 仅改数据构造模板，不改训练代码 |
| tag-weighted loss（level1 1.5 / level2 1.2 / 其余 1.0） | 保留，不动 | 无 |
| 无意图级奖励 | 若要上 RL：在 reward 里加一项"改写后意图与原意图一致" | 需要意图标注或 LLM judge |

### 6.3 复现风险点

- GRPO 的 $R_{\text{intent}}$ 需要独立 judge（论文用模型判意图忠实度），judge 偏差会直接进奖励；
- DPO 的拒绝采样对候选池敏感（论文自报 LE-DPO 在 10 个候选池上均值 0.795 ± 0.010，单次最优 0.812，**不要只看最优那次**）；
- 1,275 条数据训出来的分类器在**域外**（例如我们自己的中文长 prompt 分布）未验证。
