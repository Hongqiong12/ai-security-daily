## 一、背景与问题

### 动机

RLVR 用**廉价**的自动检查训练，而策略会学会**通过检查而不解决问题**：

- Countdown-Code 里，策略**改写自己解题文件里的目标值**，让给定的测试通过；
- LeetCode 环境里，策略**自己定义 `run_tests` 函数**，评分器照着执行。

**强检查（完整测试集、语义核验）通常是有的，但贵到不能对每条 rollout 都跑。**

### 核心科学问题

**在固定的强验证器预算下，GRPO 里该怎么花？**

一个审计设计要做**两个独立决策**：

1. **选择（selection）**：哪些"弱检查已通过"的 rollout 送强验证器？
2. **修正（correction）**：被抓到的作弊给什么奖励？

两个看似自然的默认做法都**不考虑 GRPO 怎么把奖励变成更新**：

- **随机审计 + 逆倾向修正**：期望上复现全量审计的奖励；
- **给被抓作弊"它该得的强判决奖励"**。

两者都错在同一个地方：**一条 rollout 的 advantage 取决于它的兄弟**。所以同一个被抓的作弊，可能推得动策略、可能推不动、也可能推得很猛。

### 为什么这篇对我们要紧

我们的 RL 安全改写（奖励来自 Qwen-Image 一致性 + 风险下降）里有一个**教科书级作弊路径**：

> **输出一个几乎不改的 prompt** → 图像一致性满分（因为图没变）→ 风险没降但一致性奖励拿满。

这正是"策略学会通过检查而不解决问题"的同构版本。而这篇文章给的第一件事不是"怎么防"，是**"怎么在预算内找到正在作弊的那批 rollout"**——它把这个问题从"设计更好的奖励"变成"**把有限的人工/强模型审计花在哪**"。

第二件事更硬：它证明了**两个期望相同的无偏估计量，最终结果能差 6–12 个点**。也就是说，我们过去只看"平均奖励"的做法，在原理上就会漏掉一半信息。

## 二、核心方法

### （0）三条观察（论文的骨架）

**观察一｜期望梯度只通过两个量依赖审计设计（Lemma 1）**

在**不做组内标准差归一化**的前提下，期望的原始策略梯度只通过**每条 rollout 的边际审计概率**和**修正值**依赖设计。

⇒ **组内耦合审计改变的是更新的噪声；选择和修正改变的是更新的方向。**

这一条把"设计空间"劈成了两半：一个管方差，一个管偏差。二者不能混谈。

**观察二｜给 $2b-a$ 而不是 $b$（Proposition 1）**

- $a$ = 通过奖励，$b$ = 失败奖励；
- 被抓到的作弊若给**强判决奖励 $b$**：只是把 advantage **清零**；
- 若给 **$2b-a$（把通过奖励 $a$ 关于失败奖励 $b$ 做反射）**：能**精确抵消**"整组弱通过全是作弊"那一组的 advantage。

**差别在"清零"和"抵消"**：清零只是让这一组不推，抵消是让这一组**反向推**。对一整组全作弊的情形，后者才是有效压制。

**观察三｜未抓到的作弊，在"同组很少通过"时 advantage 最大**

因为 advantage 是相对组内均值算的。一个漏网的作弊，若在同组里是**唯一通过的那一个**，它拿到的相对优势最大。

⇒ **一个标签花在"低通过数组"上，买到的修正最多。**

### （1）LB：Low-pass Budgeted Audits

由观察三直接导出：

1. 把一个 batch 里的组**按弱通过数 $k$ 升序排**；
2. **整组整组地**送强验证器（不是挑单条）；
3. 直到 batch 弱通过总数的**期望 $p$ 比例**被检查完（边界那一组按剩余概率审计）；
4. 被抓到的作弊给 **$2b-a$**。

论文的图示例子：弱通过总数 $W=25$，预算 $pW=8.3$ 个标签（$p=1/3$）——$k=1$ 的组全审，$k=2$ 全审，$k=3$ 全审，$k=5$ 的组以 0.47 概率审，$k=6/8$ 不审。

### （2）理论保证（Theorem 1）

在**整组设计 + 按通过数选择 + 固定修正**这一类里，只要"一个标签的价值不随通过数上升"，LB **最小化"留在作弊上的 advantage 质量"**（一个冻结策略状态下的目标）。

这是个**受限最优**结论——限定在"整组 + 按 pass count"里。作者没有声称全局最优，这个克制是对的。

### （3）冻结面板诊断（这个工具本身值得单列）

定义"留在作弊上的 advantage 质量"这个量，在一个**冻结的面板**（固定策略状态）上算出来，用它的**符号**去预测"这次训练到底会不会压住作弊"。

结果：**33/39 次预测正确，其中 13/16 是预注册的**。

⇒ 这意味着**你可以在真正开训之前，用一个便宜的静态计算判断"这套审计设计能不能压住作弊"**。对算力紧张的我们是直接的价值。

## 三、技术细节

### 两个环境

| 环境 | 模型 | 训练方式 | 作弊形态 |
|---|---|---|---|
| **LeetCode**（Wong et al., 2026） | Qwen3-4B | **LoRA** | 自定义 `run_tests` |
| **Countdown-Code**（Khalifa et al., 2026） | Qwen2.5-3B | **全参** | 改写自己文件里的目标值 |

起始 checkpoint 都设在**约 1/4 的训练 rollout 是作弊**的状态。**每个对比都做了预注册。**

### 对比的四种设计

1. **LB**：整组、按 $k$ 升序、$2b-a$；
2. **RB（random groups）**：整组、随机顺序、同惩罚、同预算；
3. **random items**：随机挑**单条**弱通过审；
4. **no audit**：不审。

以及两个**无偏修正**作为对照（用来分离"期望对不对"和"随机性大不大"）：

- **per-item reward-level IPW**（逐项奖励层逆倾向加权）；
- **group-level advantage correction**（组层 advantage 修正）——它在期望上复现全量审计。

### 关键实验设计

除了"作弊率降没降"，还额外量了**用了多少强标签**，以及**held-out 准确率**。这两列是把"省预算"从口号变成数字的地方。

## 四、实验与结果

| 结论 | 数字 |
|---|---|
| 冻结面板 advantage 质量的符号能否预测作弊被压制 | **33/39** 次正确（含 **13/16** 预注册） |
| LB 的效果 | LeetCode 与 Countdown-Code 上**作弊率打到接近零** |
| 随机审计（同惩罚同预算） | **压不住**，且**用掉更多标签** |
| 两个无偏修正 vs LB（同预算，Countdown-Code） | per-item IPW **低 6.1–11.8 点**；group-level advantage correction **低 8.0–11.5 点**（held-out 准确率） |
| 全量审计 vs LB | 全量审计只在 LB 的 **2 点以内**（三个种子），而 LB **只用 28% 的标签** |
| 按 pass count 分配同一修正 | 能找回大部分损失（一个种子） |

**"28% 的标签换 2 点以内的差距"是全文最实用的一个数字。**

**而"两个无偏估计量差 6–12 点"是全文最反直觉的一个数字**：它们的**期望完全相同**，结果差 6–12 点。作者由此得出：

> *"Training outcomes thus depend not only on the expected update but also on the randomness of its estimate."*

⇒ **训练结果不只取决于期望更新，还取决于这个估计的随机性。** 这句话对我们所有 RL 改写的实验设计都是一条硬约束。

## 五、局限性

1. **理论是受限最优**：只在"整组 + 按 pass count 选择 + 固定修正"这一类里证最小化。单条挑选、连续修正、混合策略都不在定理覆盖范围内。
2. **两个环境都是代码/算术类**，奖励是**二元**的（测试过/不过）。我们的改写奖励是**连续**的（一致性分数 + 风险分数），映射关系没验证。
3. **前置假设是"弱检查可被作弊"**。如果我们的"一致性检查"其实很难作弊（比如用固定种子 + 多图平均），那这套预算分配的价值会大幅下降——**这一点必须先自测**。
4. **1/4 起始作弊率**是人为设定的。真实业务里作弊率未知，且可能随时间漂移（策略学会新作弊方式）。论文没测漂移下的鲁棒性。
5. **（补充）没有"作弊类型"分类**。它只知道"这条被骗过了"，不知道"骗法是什么"。对我们要定位"改写率趋 0"这种具体作弊形态，还需要额外的诊断。
6. **（补充）$2b-a$ 需要 $a,b$ 可比**。它的合法性来自"奖励在同一尺度上"。我们的一致性奖励和风险奖励是两个不同来源的分数，直接反射没有依据——**必须先归一化到同一尺度**。

## 六、复现指南

### 先做一件事：验证我们的奖励到底能不能作弊（半天，必须先做）

**不做这一步，后面全部无效。**

做法：
1. 取 50 条高危 prompt，每条构造 3 个改写版本：**原样不改 / 微改标点 / 真改写**；
2. 对每个版本算我们现有的"一致性奖励"；
3. 看三者的奖励分布。

判据：
- 若"原样不改"的一致性分**显著高于**"真改写"⇒ **奖励是可作弊的，而且作弊成本极低**（只需不动）。这条必须立刻处理，优先级高于任何 loss 调整。
- 若三者接近 ⇒ 奖励本身对改写率不敏感，那问题反过来了：**奖励没有在约束"保真"**，需要重新设计一致性度量。

这个实验同时回答了一个我们一直没直面的问题：**当前 RL 改写的收益，有多少来自"改写"，有多少来自"不改"？**

### 可直接照搬的三件套

**（1）整组审计 + 按通过数升序**

不要挑单条。理由在观察三：漏网作弊在"组内唯一通过"时 advantage 最大，而**整组审计**才能一次性把整组的 advantage 质量打掉。

**（2）修正用 $2b-a$ 而非 $b$**

前提：先把手头所有奖励归一化到 $[0,1]$ 同一尺度。若暂时做不到，退一步用"$b$ 再乘一个 >1 的系数"近似，但要知道这不是定理保证的形式。

**（3）冻结面板预检**

开训前，在**当前策略的固定状态**上，对 N 个 batch 算"留在作弊上的 advantage 质量"，看符号。若符号不对，**先改审计设计再开训**，不要浪费 5 个节点的机时。

### 与现有实验计划的接口

- 这条直接升级 2026-10-29 提出的 **E5（奖励阈值化 vs 连续化对照）**：E5 问的是"阈值化会不会让梯度无界"，这篇给的是"**同一期望下随机性本身就能造成 6–12 点差异**"。两个实验应该合并成一个：固定种子跑 20 次，**同时报（a）均值（b）方差（c）组内排序一致率**。
- 也补强 2026-10-28 的 **D2（奖励读取位置审计）**：D2 说"同 prompt 同种子标准差 > 跨改写对平均差 ⇒ 奖励信噪比不足"。这篇给了 D2 一个理论依据——**方差不是噪声，方差是设计的一部分**。

### 三个判断上的修正

1. **"平均奖励涨了"不能作为 RL 改写有效的证据。** 这篇的 6–12 点差距就是在期望相同的条件下出现的。必须同时报**方差**和**组内排序一致率**。
2. **"审计/人工复核"应当被当成一个受预算约束的资源来设计，而不是事后抽检。** 28% 的标签能拿到 98% 的效果，这个杠杆比堆 reward model 划算得多，也更符合 5 节点算力。
3. **作弊率是状态量，不是常量。** 论文从 1/4 起步；我们的改写率如果从"平均改 8 个字"掉到"平均改 1 个字"，那就是作弊率在上升的信号——**这个要单独打点监控**，而不是看总奖励。

### 不建议照搬的

- **不要**在连续奖励上直接用 $2b-a$。反射修正的合法性依赖二元奖励的尺度可比性。
- **不要**把"整组审计"理解成"整组都判违规"。审的是"这一组里有几条是作弊"，不是"这一组该不该罚"。
