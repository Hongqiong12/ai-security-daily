## T2I / T+I2I 论文（核心主线）

### 1. PixJail: Self-Evolving Paper-to-Pipeline Reproduction for Text-to-Image Jailbreak Evaluation

**本地精读**: `categories/t2i/papers/2606.24081_pixjail.md`

- **论文定位**: T2I jailbreak benchmark / paper-to-pipeline reproduction / pipeline-level evaluation
- **时间信号**: 2026-06-23，属于过去 7 天内最新强相关工作
- **核心贡献**:
  - 提出 **PixJail-Attack + PixJail-Eval** 两阶段框架，把论文自动转成攻击模块与评测管线；
  - 定义统一契约 **C = (X, Θ, Y, A)**，让 prompt、采样器、judge、过滤器与工件显式可审计；
  - 用 memory bank 持续积累论文摘要、模板、失败案例与版本化工件；
  - 在统一协议下重跑 11 个代表性 T2I 越狱方法。
- **关键数据**:
  - 覆盖 **11** 个方法（7 个有代码，4 个无代码）；
  - **平均复现误差 2.1%**，中位数 **0%**；
  - 平均复现时间 **778 秒**；
  - 标准化评测里，SDXL 平均 ASR **74.7%**，而 GPT-image-2 大多 **<4%**。
- **我的判断**:
  - 这是今天最值得你重视的 benchmark 基建论文。它直接提醒：**输入侧 rewrite 的评测对象不是改写文本，而是 rewrite→生成→过滤→judge 的整条链。** 如果你后面要做三维评测或 A/B 实验，PixJail 的 contract 思路几乎可以直接照搬。

### 2. Safe Few-Step Generation via Velocity Editing

**本地精读**: `categories/t2i/papers/2606.23267_vesflow.md`

- **论文定位**: T2I safety alignment / flow matching / few-step generation / training-free defense
- **时间信号**: 2026-06-22，属于过去 7 天内最新强相关工作
- **核心贡献**:
  - 提出 **VESFlow**，直接在 flow matching 的 velocity field 上做安全编辑，而不是继续改 prompt embedding；
  - 提出 **VESFlow+**，同时拉近安全方向并推远不安全方向；
  - 加入 **risk score gating**，只在高风险 prompt 上启用重干预；
  - 明确服务少步生成场景。
- **关键数据**:
  - MeanFlow 4-step 上 Ring-A-Bell ASR：**70.9% → 6.3%**；
  - MMA-Diffusion ASR：**41.7% → 6.8%**；
  - FID：**24.71 → 24.59**，基本不伤保真；
  - CLIP：**0.262**，与基线持平。
- **我的判断**:
  - 它不是输入侧 rewrite，但对你的 routing 设计非常有价值：**并非所有风险都必须靠 rewrite 消解，可以先做 risk gating，再决定是否进入 heavier rewrite 或生成侧控制。** 这是一个很强的工程抽象。

### 3. ForceForget: Reinforcement Concept Removal for Enhancing Safety in Text-to-Image Models

**本地精读**: `categories/t2i/papers/2606.14351_forceforget.md`

- **论文定位**: T2I/I2I concept removal / safe semantic preservation / RL-based erasure
- **核心贡献**:
  - 用 **双奖励 CER** 同时优化安全性与语义保真；
  - 引入 **Safe Adapter**，在 cross-attention 中只局部调节文本条件；
  - 用 **BLIP + 过滤词典 + CLIP** 显式抽取“应该被保留的安全语义”；
  - 论文特别验证了 **I2I** 场景迁移性。
- **关键数据**:
  - I2P 上 **NRR = 97.96%**；
  - Ring-A-Bell / P4D / MMA 上分别达到 **100% / 100% / 99.63% NRR**；
  - COCO-30K 上 **CLIP = 30.53**，接近原模型 **30.63**；
  - I2I 场景下：裸露初始图像 **96.4% NRR**，干净初始图像 **100% NRR**。
- **我的判断**:
  - 这是本月最像“风险锚点外科替换”思想的一篇 model-side 论文。它给你的关键启发不是 LoRA 本身，而是：**先抽出该保留的安全语义，再做风险消解。** 这和输入侧 rewrite 非常同构。

### 4. SafetyBPO: Bidirectional Preference Optimization for Safe Text-to-Image Generation

**本地精读**: `categories/t2i/papers/cvpr2026_safetybpo.md`

- **论文定位**: T2I safe prompt rewriting / preference optimization / safe-yet-semantic-consistent generation
- **机构线索**: Westlake AGI Lab
- **核心贡献**:
  - 构建 **2.5K** 高质量 **BPO-Bench**，显式配对 unsafe prompt 与 safe-yet-semantically-consistent rewrite；
  - 用 **Bidirectional Preference Optimization** 联合学习正向安全偏好与反向风险压制；
  - 同时引入 **prompt-level + image-level** 双视角偏好；
  - 即便 training-free 版本，仅靠 prompt rewriting + CFG 也能达到 SOTA 级表现。
- **关键数据**:
  - BPO-Bench 规模 **2.5K**；
  - 官方仓库显式提供 **InPro / FID / CLIP** 三类评测接口；
  - 公开摘要强调 training-free 版本已达多项 unlearning benchmark SOTA。
- **我的判断**:
  - 这是今天和你业务最贴的一篇。因为它几乎已经把“**unsafe prompt → safe rewrite → image preference**”这条链条做出来了。它最大的价值不是某一个模型结果，而是它给了你一套**可直接拿来造数据和造评测的 pair 设计**。

### 5. PromptEnhancer: Taming Your Rewriter for Text-to-Image Generation via Fine-Grained Reward

**本地精读**: `categories/t2i/papers/2509.04545_promptenhancer.md`

- **论文定位**: T2I prompt rewriting / fine-grained reward / failure taxonomy-aware rewriter
- **机构线索**: Tencent Hunyuan
- **核心贡献**:
  - 提出独立于生成器的 **CoT Rewriter**；
  - 用 **AlignEvaluator** 提供细粒度 reward，而非只依赖 CLIP / ImageReward；
  - taxonomy 覆盖 **24 个 key points**；
  - 通过 **SFT → GRPO** 两阶段训练，让 rewriter 真正对生成执行性负责。
- **关键数据/信号**:
  - 官方材料明确其在 **HunyuanImage 2.1** 上验证；
  - 24 key points 覆盖 T2I 常见失败模式；
  - 配套人类偏好 benchmark。
- **我的判断**:
  - 这篇论文不是 safety paper，但它是**工业界公开方法里最值得你借的 rewrite 训练框架之一**。它给出的最强启发是：**rewrite judge 应该按 failure taxonomy 输出，而不是给一个 overall score。** 这对你的三维评测设计尤其关键。

### 6. Seeing is Believing: Aligning Prompt Rewriting with Visual Anchors for Text-to-Image Generation

**本地精读**: `categories/t2i/papers/2606.08492_faithrewriter.md`

- **论文定位**: intent-preserving rewrite / visual-anchor verification / semantic fidelity
- **核心贡献**:
  - 先让 T2I 模型把初始改写真的画出来，再把失败外化成视觉锚点；
  - 用六类失败（空间逻辑、属性绑定、物理动力学、计数几何、否定缺失、隐性概念）做结构化诊断；
  - 通过“修复验证 + 意图保留 + 反向回归”三项硬约束过滤训练样本；
  - 用 DPO 蒸馏得到轻量文本 rewriter。
- **关键数据**:
  - FaithT2I-Test 上，Gemini VQA：**68.78 → 74.80**（相对纯文本基线）；
  - Qwen3VL VQA：**75.65 → 78.91**；
  - SpatialGenEval 整体：**63.09 → 70.83**；
  - 跨模型泛化：FLUX-dev / HunyuanImage / Qwen-Image 均提升约 **12 个点**。
- **我的判断**:
  - 如果你现在最担心的是“safe rewrite 会不会脑补过头”，那 FaithRewriter 是今天最该仔细看的论文之一。它证明：**semantic fidelity 最终得靠视觉闭环，不靠文本相似度。**

## 业务对齐研究板块

### 1. 直接可迁移方法

今天真正可以直接迁到你当前业务里的，有四类东西：

#### A. Safe rewrite pair 数据结构（最直接）
来自 **SafetyBPO**。

建议直接迁成：
- 原始高风险 prompt
- safe rewrite prompt
- winner image / loser image
- 风险下降 / 语义保持 / 指令遵循理由标签

这比只存“原句 + 改写句 + 人工总体分”更适合后续做偏好学习或 judge 训练。

#### B. Failure-taxonomy-aware rewriter（很直接）
来自 **PromptEnhancer**。

最值得借的是 24 key points 的思路：
- rewrite 不按词改；
- rewrite 按 failure mode 改；
- judge 也按 failure mode 出结构化反馈。

#### C. Visual-anchor 验证闭环（直接）
来自 **FaithRewriter**。

对模糊高风险 prompt，最该补的一层不是“更多 rewrite 模板”，而是：
- rewrite 后真实出图；
- 看终态到底保没保住原意；
- 用 visual failure 来回修 rewrite。

#### D. Pipeline-level benchmark（非常直接）
来自 **PixJail**。

你的系统后面如果要做 A/B 对比，建议直接采用：
- 原始 prompt
- rewrite 输出
- 生成图像
- 安全过滤结果
- MLLM judge 输出
- 可审计工件

否则不同实验的结果无法真正复现。

### 2. 风险锚点处理启发

今天这批论文对“风险锚点怎么处理”给了三条非常实用的启发：

1. **风险锚点要和可保留语义一起建模，而不是单独做删除**（ForceForget）  
   不能只问“删掉了没有”，还要问“安全的主体/动作/场景/构图是不是还在”。

2. **风险锚点最好按 failure mode 和视觉约束建模，而不是只按敏感词建模**（PromptEnhancer + FaithRewriter）  
   真正会把 rewrite 做坏的，常常不是危险词没删干净，而是属性绑定、空间关系、否定约束、隐性概念被脑补坏了。

3. **风险锚点治理需要和 routing 联动**（VESFlow）  
   不是所有 prompt 都要进重写器。更合理的系统是：
   - 先做 risk gating；
   - 低风险 prompt 直接过；
   - 高风险或灰区 prompt 再进入 rewrite / 生成侧双重控制。

### 3. 三维评测设计启发

今天最清楚的进展，是你的三维评测已经有了更完整的参考骨架：

| 维度 | 对应论文 | 可落地定义 |
|------|----------|------------|
| **安全提升** | SafetyBPO / ForceForget / VESFlow | 改写后高风险出图率是否下降；是否仍能被 alias / wrapper / 组合语义绕回危险区 |
| **语义保持** | FaithRewriter / ForceForget | 主体、动作、风格、布局、关键约束是否保留 |
| **指令遵循** | PromptEnhancer / FaithRewriter | 改写后模型是否仍按用户想要的终态出图，而不是“安全但失真” |
| **系统一致性** | PixJail | 在不同生成器 / 过滤器 / judge 配置下，评测是否稳定可复现 |

我建议你在这三维之外，再强制加两个辅助指标：
- **Overrewrite Rate**：语义被过度美化、过度脑补、过度保守的比例；
- **Judge Stability**：同一 prompt 的多 rewrite 版本在不同 judge / seed 下结论是否稳定。

### 4. 下一步实验建议

#### 实验 1：补一套 rewrite-to-image pipeline benchmark
直接学 **PixJail**，把你现在的评测改成工件化流水线：
- 原始 prompt
- rewrite prompt
- 图像
- 安全过滤结果
- 多模态 judge 输出
- 错误标签

目标：让每次实验都可回放、可比较。

#### 实验 2：做 failure-taxonomy-aware judge v1
结合 **PromptEnhancer + FaithRewriter**，先别追求大而全，先做 8–12 个最关键 failure types：
- 风险未降
- 主体丢失
- 场景漂移
- 属性绑定错位
- 否定约束失效
- 构图漂移
- 文本/OCR 元素丢失
- 过度改写

目标：先把“改坏在哪里”看清楚。

#### 实验 3：做一批 safe rewrite pair + winner/loser image 数据
直接参考 **SafetyBPO**：
- 抽 100–300 条模糊高风险 prompt；
- 对每条生成 2–4 个 rewrite 版本；
- 真正出图，再标注 winner / loser；
- 标签围绕风险下降、语义保持、指令遵循。

目标：为后续偏好学习或 judge 蒸馏准备第一批高质量数据。

#### 实验 4：先做 risk gating，再做 rewrite
参考 **VESFlow** 的 risk score gating 思路：
- 明确低风险、灰区、高风险三档；
- 只对灰区和高风险 prompt 走重写链路；
- 低风险 prompt 避免无谓改写。

目标：降低 overrewrite 和无效延迟。

## 当日趋势信号

### 趋势 1：输入侧 rewrite 正在从“润色 prompt”升级为“控制面”
`SafetyBPO`、`PromptEnhancer`、`FaithRewriter` 共同说明，rewrite 的研究重点已经不是文本更流畅，而是：**如何安全、可控、可解释地保留原意。**

### 趋势 2：semantic fidelity 的可靠评测必须走向视觉闭环
`FaithRewriter` 直接证明，文本相似并不等于视觉保真。对你的业务来说，这意味着 semantic fidelity judge 终究得看图，而不是只看改写文本。

### 趋势 3：新的 benchmark 不再是 prompt list，而是 pipeline infrastructure
`PixJail` 把这一点说透了：T2I 安全评测的核心资产正在从“数据集”迁到“管线契约 + 工件治理 + judge 协议”。

### 趋势 4：安全-效用 trade-off 正从静态口号变成结构化优化目标
`ForceForget` 与 `VESFlow` 都表明，现在更强的方法不再是单纯压风险，而是**同时压风险、保 fidelity、保 benign prompt 能力**。这和你当前业务完全同频。

### 趋势 5：工业公开方法开始与学术主线汇合
腾讯混元的 `PromptEnhancer` 与微软公开的 `prompt transformation` 文档说明：工业界已经把 prompt rewrite 当成正式模块，只是公开论文与产品控制面还没完全打通。你现在做的事情正好落在这个交汇点上。

## 今日结论

如果把今天的 6 篇论文压成一句执行建议，那就是：

> **别再把 T2I 安全改写理解成“改一段更安全的 prompt”了；它已经是一条需要数据、taxonomy、视觉验证和 pipeline benchmark 支撑的系统工程。**

更具体一点，今天最值得推进的顺序应该是：

1. **先补 pipeline benchmark**：学 PixJail，把 rewrite 评测变成整链评测；
2. **再补 failure taxonomy**：学 PromptEnhancer，把 judge 做成结构化输出；
3. **再补 visual fidelity 闭环**：学 FaithRewriter，真实出图看 semantic drift；
4. **再补 pair 数据**：学 SafetyBPO，做 winner/loser image 偏好数据；
5. **最后再补 routing**：学 VESFlow，把 risk gating 接进生产链路。

今天这批工作没有直接给出一个“工业可上线的 T2I 安全重写器”，但已经把它最关键的五块底座拼出来了：
- **rewrite data**
- **failure taxonomy**
- **visual fidelity verification**
- **pipeline-level benchmark**
- **risk-aware routing**

这五块一旦补齐，你现在的输入侧 NSFW 风险改写工作就不再只是 prompt engineering，而会变成真正可验证、可优化、可迭代的控制系统。
