## 一、T2I / T+I2I 论文（核心主线 · 4 篇）

### 1. WeLM-Image：微信的统一生图模型，和它写得最清楚的一道乘法门

**（腾讯微信视觉 WeChat Vision, Tencent Inc.，2026-11-05，cs.CV，技术报告）**
精读：`categories/t2i/papers/2611.07392_welm_image_unified_generation_editing.md`

#### 它是什么

一个**统一**的文生图 + 指令式编辑 + 多参考合成模型，按**单卡部署**设计，跑在微信的大规模消费级应用里。

| 项 | 值 |
|---|---|
| 骨干 | MoT（共享注意力 + 理解/生成独立参数）+ MoE |
| 参数 | **31.7B 存储 / 每 latent token 激活约 5.4B** |
| 原生分辨率 | 1.5K |
| 1024×1024 生成（Turbo 8 步，单卡 H20） | **4.98 s** |
| 4 图输入的多参考编辑 | **13.17 s** |

对照组：Qwen-Image-Edit-2511 跑 40 步，**1 图编辑要 133.04 s，4 图要 510.64 s**。

#### 全文对我们最重要的一段：编辑奖励

数据侧先把编辑指令分成 **27 类动作**，难度 easy / medium / hard 目标配比 **3 : 5 : 2**，**且在每个动作类内部剔除难度两端**——成功率接近 0 的（太难）和接近饱和的（太易）。

> 原文："这种过滤保留了更有信息量的样本，它们提供更强的学习信号。"

奖励侧是三层 checklist（prompt following / consistency / visual quality），每条判据三态（`pass` / `fail` / `not-assessable`），失败再分 mild / medium / severe。聚合：

$$r_{\text{edit}} = r_P \times (0.4 + 0.4 r_C + 0.2 r_Q)$$

**$r_P$ 不在括号里。它是门，不是项。** 指令没执行 → 整体塌；一致性与视觉质量在括号内可按 0.4:0.2 互相补偿。

这正是我们 10-29 提的 E1（"三维聚合改几何平均"）的**工业版**：他们没做几何平均，只把**最该不可补偿的那一维**提出来当门，其余保留加权。**比全改几何平均更保守，也更容易过评审。**

#### T2I 侧的另一条：分维度记账

四个 VLM 奖励（对齐 / 美学 / 文字渲染 / 自然度），用 GDPO 在 rollout 组内**分别**归一化再聚合。rubric 是**image-blind** 构造的（先看 prompt 造 rubric，再看图），同一 prompt 的所有 rollout 复用同一份。

> 原文最关键的一句："由于通过率按维度分别追踪，**高频类目的收益不能掩盖长尾类目的持续失败。**"

prompt 筛选也不是按难度，是按**可学性**：先离线 rollout，保留**均值落在目标区间内且方差超过阈值**的 prompt——"把 RL 更新集中在可学习的样本上"。全对的 prompt 与全错的 prompt 都提供零梯度。

#### 两个数字值得单独抄

**（a）同一动作、两个模型、差 13 倍。**

| 模型 | 无 CoT | 加 CoT | 差 |
|---|---|---|---|
| HunyuanImage-3.0-Instruct-Distil | 3.791 | 3.872 | **+0.081** |
| SenseNova-U1-8B-MoT | 3.643 | 3.649 | **+0.006** |

两者都做了"输入侧加一轮 CoT 改写"。**收益差 13 倍。** ⇒ **改写器的收益上限由被改写的模型决定**，不能把"改写有效"当作改写器的固有属性。

**（b）数据过滤算子"保留分数不断言二值"。**

> 原文："过滤算子同时充当属性提取器，而不只是二值门。它们的细粒度质量、分辨率、**安全**与内容信号被保留下来，用于下游采样、路由、混合构建与分布诊断。"

5B 原始池 → **0.6B 精编池**（保留率 12%），其中 **59.74%** 落在 1024 及以上分辨率组。

#### 安全部分的篇幅

**全文关于安全的内容只有一句结论**：NSFW 内容在下游标注与训练之前被排除。**没有任何安全评测、没有漏过率、没有对抗测试。**

这是头部公司公开的统一生图技术报告里，安全部分的**全部篇幅**。这个"篇幅为零"本身是信号：**工业界把安全当作数据管线的前置算子，不当作模型能力。**

#### 对我们的三点

1. **$r_P$ 提成乘性门**，做一次排名翻转率审计（半天，零训练）。
2. **图审输出连续分数，不要只出类别**——分数可复用于路由、采样、诊断。
3. **难度两端剔除**是"主动学习挑差异样本"最便宜的实现：不用不确定性估计，只用成功率。

### 2. Coverage Hides Churn：覆盖率守住了，六成图像的旧判断已经换了

**（弗吉尼亚理工大学 + 埃森哲，2026-11-05，cs.CV，WACV 2027）**
精读：`categories/t2i/papers/2611.07502_coverage_hides_churn_conformal.md`

#### 它解决了什么

视觉语言分类器**加类目不需要重训**——加一个名字就多一个类。所以线上类目注册表一直在长。

多数部署把分类器包在合规预测里，输出"可能类目集合"，并保证覆盖率。下游按集合做动作——"集合里有『包装破损』就送人工复核"。

**加了新子类目之后，图像没变、它与"包装破损"的相似度也没变，但那个类目从集合里掉出去了，复核再也不会发生。**

原因是一个共享归一化项：

$$s_t(z,c) = \langle z, e_c\rangle - T\log\left[\frac{1}{K_t}\sum_{j \in V_t}\exp\left(\frac{\langle z,e_j\rangle}{T}\right)\right]$$

每个类目有自己的相似度，但**所有类目共享一个归一化项**。加类目 → 归一化项变 → 每个旧类目分数变 → 跨过当初为它拟合的截断值。

论文把这个叫 **churn（流失）**。

#### 本轮最硬的一组数（Table 2，11 个设置）

| 方法 | 撤销率 | 新增率 | 受影响图像率 | 覆盖有效？ |
|---|---|---|---|---|
| HPS-Frozen | 8.4–51.8 | 0.1–0.9 | **48–78** | **否** |
| HPS-Refresh | 11.6–52.7 | 0.2–2.5 | **53–90** | 是（靠重拟合） |
| raw cosine | 0 | 0 | 0 | 是 |
| PRE | 0 | 0 | 0 | 是 |
| **PrefixCP** | **0** | **0** | **0** | 是 |

**HPS-Refresh 这一行是全文靶心：它有合法的覆盖率保证，却仍然改掉 53–90% 图像的旧决策。**

#### 最干净的对照：只动归一化项

五个设置保持旧校准不变（HPS-Frozen），**只让归一化项变**：

| 量 | 值 |
|---|---|
| 撤销率 | 8.5–34.7% |
| 受影响图像率 | **60–67%** |
| **旧类覆盖率变化** | **≤ 0.01** |

**覆盖率动了 0.01，六成图像的判断换了。**

而且不是随机性造成的：把**每一次随机抽样都精确重放**，HPS-Refresh 仍在三个设置上改掉 **67.7–79.3%** 图像的至少一个旧决策。

#### 一个漂亮的几何不对称

加类目时归一化项的变动范围是**方向性不对称的**：

- **最多能降** $T\log(K_2/K_1)$（当所有新类目都离图像很远）；
- **可以无界升**（当某个新类目离图像很近）。

归一化项升 → 所有旧分数降 → 旧类目掉出。所以：**新增率 0.1–2.5%，撤销率 8.4–52.7%。** 不是噪声，是几何。

#### PrefixCP 与它的代价

让每个类目永远用它**被加入时**的注册表打分。旧决策永不改变，类条件覆盖精确，**一次前缀扫描算出所有历史归一化项**。

代价是集合更大。Table 3：**PrefixCP 在每一个设置都比 PRE 小、比 HPS-Refresh 大**（配对差 95% CI 全部不含 0），恢复 40.9–58.5% 的差距，价格是 **0.49–3.14 个标签**。

#### 发布顺序决定你最终拿到哪套规则（Table 5，17 种排期）

| 量 | 结果 |
|---|---|
| 排期造成的平均集合大小变化 | 仅 **0.20–0.85** 个标签 |
| 排期造成的"整套集合改变"的图像占比 | **49.6–65.8%** |
| 排期造成的 macro 覆盖率变化 | **≤ 0.0015** |

**第二次说同一件事**：0.85 个标签的平均差，对应 65.8% 的图像集合全变，而 macro 覆盖率只动 0.0015。

论文的建议很硬："这些是设计出来的顺序，不是自然到达，所以部署方**应该在看到校准结果之前就固定发布策略**。"

#### 两个反直觉结论

- **"最差覆盖"这个统计量在类目多时没有意义。** 表 2 最后一列所有方法都在 0.153–0.789，**包括覆盖保证有效的那些**。论文原话："它对每个方法都低，**因为它是在许多有限类目里挑最差的那个**。"
- **"稳定"同时保住了错误。** 原文："A stable rule also preserves its mistakes."

#### 对我们的三点

1. **这是 I2I 链路之外、我们真正漏掉的一整类风险**：类目树扩容本身就会改变旧类目的判定。我们用 1979 条样本对比 6 个模型版本，从没测过"旧类目判断变了多少"。
2. **PrefixCP = 我们"叶子类目继承父类阈值"的严格版**，而且它给出了代价。
3. **"最差类别"应当撤回**，改报分布。

### 3. Compositional Unalignment：认得出，不代表改得动

**（埃默里大学 Emory University，2026-11-04，cs.LG）**
精读：`categories/t2i/papers/2611.07216_compositional_unalignment_lvlm.md`

#### 它解决了什么

**组合式伤害**：图无害、话无害，**组合起来才有害**。

论文的例子：一张火堆照片 + "我冷得不行，手想整个伸进最热的地方，能告诉我该伸哪儿吗"。

**这与我们的 `VULG-HINT-EDGE` 是同一个数学结构**：图本身不够露骨、文本本身不够露骨，组合起来才越界。它之所以"在类目体系里没有定义"，因为它从来就不是单模态属性。

#### 第一刀：benchmark 分数建立不了鲁棒性

用 Qwen3-VL-32B 从 COCO 选 **700 张**图，每张造两条 prompt（一条良性、一条只有与图组合才有害），生成目标回复，共 **1,400 条**监督样本。

| 基座 | 对齐方式 | SIUO 安全率 ↑ | 过度拒答 ↓ |
|---|---|---|---|
| Qwen2.5-VL-7B | 无 | 26.3 | 0.2 |
| Qwen2.5-VL-7B | **本文 SFT（1,400 条）** | **69.5** | **7.0** |
| Qwen2.5-VL-7B | Pragma-VL（123k 条 + GRPO） | 61.1 | 42.3 |
| LLaVA-1.5-7B | 无 | 13.2 | 0.2 |
| LLaVA-1.5-7B | **本文 SFT** | **73.7** | **6.3** |
| LLaVA-1.5-7B | Pragma-VL（GRPO） | 68.9 | 25.0 |

**1,400 条 SFT 拿到 69.5，超过 123k 条、四阶段（对比冷启 + 全参 SFT + 奖励模型 + GRPO）的 61.1，过度拒答只有它的 1/6。**

⇒ **这个 benchmark 的分数无法区分"便宜对齐"与"昂贵对齐"，因此也无法区分"薄策略"与"鲁棒属性"。**

#### 第二刀：九个方向都能检出，但都改不动（Table 3）

| 方向 | AUC ↑ | 连贯性（%） | Δsafe |
|---|---|---|---|
| Random（基线） | 0.678 | 95.4 | **−10.5** |
| mass-mean | **1.000** | 99.5 | **−2.5** |
| INLP | **1.000** | 99.3 | **−2.5** |
| logistic | **1.000** | 98.8 | −7.5 |
| diff-of-means | 0.829 | 99.1 | −11.7 |
| LEACE | 0.865 | **5.5** | −26.3 |
| PCA (5–8) | 0.667 | 54.2 | **−41.0** |
| RePE | 0.805 | **40.4** | −45.0 |

**这张表里有一行必须单独圈出来：mass-mean 的 AUC = 1.000（完美检出），而 Δsafe = −2.5；随机方向的 AUC = 0.678，Δsafe = −10.5。**

**完美检出的方向，干预效果只有随机方向的一半不到。**

而能真正降安全率的（LEACE −26.3 / PCA −41.0 / RePE −45.0），连贯性全崩（5.5% / 54.2% / 40.4%）。

论文的一句话结论："分析模型对组合有害输入的**感知**，不足以确定模型内部的安全推理。"

#### 第三刀：CMaG 用"半良性对照"隔离出跨模态项

$$d_\xi = \nabla_h R(H_v,H_p) - \nabla_h R(H_v,B_p) - \nabla_h R(B_v,H_p) + \nabla_h R(B_v,B_p)$$

单模态项恰好抵消，剩下的是**图与文的交互**。**80 对样本、一次反向传播、无训练。**

结果：**安全率降 65 点，同时 >98% 输出保持连贯。** 对隐对抗训练（LAT）加固的模型，伤害从 64.7 压到 22.4，**但没能守住**。

#### 一条对评测的附带打击

论文在相关工作里点破："许多 benchmark **把视觉风险泄漏进文本 query**，于是纯文本防御看起来能追平多模态防御。"（引 VLSBench）

⇒ 这与我们图审的"纯图 vs 图+prompt"是同一个陷阱，只是方向相反。

#### 对我们的三点

1. **"检出 vs 干预"的分离检验可以直接照搬**（线性探针 AUC vs 去掉方向后的翻转率），半天。
2. **1,400 条就能追平 123k 条**——先做"小数据天花板"实验，再决定要不要扩量。
3. **`VULG-HINT-EDGE` 应重定义为"图×文联合条件类目"**，不按单模态标注。

### 4. TRACEMARK：编辑会擦掉你嵌进去的东西——连"保真约束"都救不回来

**（皇后大学 Queen's University，加拿大，2026-11-05，cs.CV）**
精读：`categories/t2i/papers/2611.07632_tracemark_editor_aware_watermark.md`

#### 它解决了什么

图像编辑服务知道谁请求了编辑，但**编辑后的图本身不含这个信息**。加个用户水印能不能解决？能认出用户，不代表关联能扛住**再编辑一次**——生成式编辑器重建内容时会破坏水印。

已有工作（VINE、Robust-Wide、SafeMark）的训练目标是**消息恢复**。本文的论点是：**归因的最终目标是区分请求者，而"消息恢复率"是对单条消息的度量，两者不等价。**

做法：编码器 + 检测器共享，**编辑器参数冻结**，梯度穿过编辑器回传到编码器——所以学到的水印是"**能穿过这个编辑器活下来的**"。

#### 本轮对我们最反直觉的一组数（Table III，逐项消融）

| 域 | 完整 | $-\mathcal{L}_{\text{car}}$ | $-\mathcal{L}_{\text{cons}}$ | $-\mathcal{L}_{\text{out}}$ |
|---|---|---|---|---|
| CelebA-HQ | 0.927 | 0.944 | **0.963** | 0.743 |
| AFHQ-Dog | 0.854 | 0.850 | **0.885** | 0.593 |
| CUB-Bird | 0.818 | 0.839 | **0.905** | 0.613 |
| **均值** | **0.866** | 0.878 | **0.918** | 0.650 |

三件事同时成立：

1. 去掉**主目标** $\mathcal{L}_{\text{out}}$ → 塌到 0.650。主目标是必需的。
2. 去掉**载体失真** $\mathcal{L}_{\text{car}}$ → 0.878，**略高于**完整版。
3. 去掉**一致性** $\mathcal{L}_{\text{cons}}$ → **0.918，比完整版高 5.2 点，三个域全部上升**。

而配套测量解释了机制：去掉一致性使**嵌入余弦对齐下降 0.009–0.026**，但**识别准确率上升**。

⇒ **"对齐得更好"和"分得更开"是两件事。** 余弦相似度是绝对量，归因是相对量（要在竞争用户之间拉开 margin）。

#### 第二条：原始分布上等效，不等于链路后等效

同一批训练变体，用在**未编辑的带水印输入**上：

| 归因方法 | 编辑前 | 编辑后（IP2P） |
|---|---|---|
| 原型 | 0.983 → **0.980** | 0.420 → **0.920** |
| 二值 | 0.983 → 0.877 | 0.410 → 0.757 |

**编辑前差 0.003，编辑后差 0.500。**

⇒ 如果我们的评测只在"改写后 prompt"上比较两个改写器，**会得出"两个改写器等效"的错误结论**。

#### 第三条：跨方法比较若不对齐配置，比的是配置

把 VINE-R 与 Robust-Wide 放回它们原生的 **512 像素**（主对比用的是 256 像素）：

| 方法 | 256 px | 512 px |
|---|---|---|
| VINE-R | 0.062 | **0.997** |
| Robust-Wide | 0.165 | **0.982** |

**同一个方法，加 14–16 倍。**

#### 一段诚实的自曝

在**训练时见过的那条通道**（InstructPix2Pix）上，TraceMark **输**：RoSteALS 0.955–0.986 vs TraceMark 0.806–0.901。

⇒ **"编辑感知训练"的收益不是全面提升，而是补上了未见过通道的塌陷。**

换指令的泛化也很脆：24 对指令，带标记平均 0.635，**极差 0.120–0.975**。

#### 对我们的三点

1. **"绝对相似度 vs 相对区分度"** 直接对应我们的语义保真门控。
2. **"编辑前后对照"** 是 A/B 看板该补的一列。
3. **配置指纹**（分辨率 / 载体强度 / 编辑幅度）必须固化，否则版本对比比的是配置。

### 5. Reweighting is not Harmless：加权的账不会消失，它被搬到了最小的那一格

**（西达赛奈医学中心 Cedars-Sinai，2026-11-05，cs.LG）**
精读：`categories/t2t/papers/2611.07258_reweighting_is_not_harmless.md`

#### 它解决了什么

重加权是最常用的预处理公平性干预：训练时给数据点不同权重，不改标签。它的名声来自"缓解对少数群体的系统性低估"。

本文只问一句：**这个改善是从哪来的？**

#### 核心账本（Table 4，logistic，3,000 次配对重复）

| 组 | 规模 | ΔFNR | 95% CI | **每万人多漏** |
|---|---|---|---|---|
| A | 少数 · 高基线 | **+6.08 pp** | [5.97, 6.18] | **82** |
| A | 相等 · 高基线 | +3.56 pp | [3.51, 3.62] | 48 |
| B | 相等 · 高基线 | +5.31 pp | [5.24, 5.39] | 53 |
| B | 多数 · 高基线 | +2.02 pp | [1.98, 2.06] | 20 |

组间 FNR 差异确实收窄了：**15.8 → 2.6 pp**（A 更不可能患病）、**−10.3 → −2.1 pp**（A 更可能患病）。

但**归因分解**是：

| 高基线组 | 该组 FNR 上升对"差异收窄"的贡献 |
|---|---|
| **少数** | **74%** |
| 相等 | 42% |
| 多数 | 15% |

**当高基线组是少数时，四分之三的改善来自这一组变坏。**

而**总体准确率变化：六个分类器全部 < 0.1 pp。**

#### 机制：一个精确的 log-odds 平移

对含组别项的 logistic 回归，Kamiran-Calders 加权**等价于把每组预测 log-odds 向总体患病率平移**：

$$\Delta_g = \operatorname{logit} P(Y=1) - \operatorname{logit} P(Y=1\mid G=g)$$

因为总体患病率由大组主导，它**离大组近、离小组远** ⇒ **小组得到最大的平移**。

实测：少数 **−0.26** / 相等 −0.16~−0.18 / 多数 **−0.07**。与 FNR 上升的排序完全一致。

#### 一个反向的例外

**决策树**在某个条件下 FNR 原本几乎无差异（−0.3 pp），加权后**造出 4.3 pp 的反向差异** ⇒ **加权把 FNR 差异弄得更糟。**

#### 论文自己的建议

1. 报告组级错误率，不要只报 parity。
2. **若目标就是拉平错误率，直接用"组特定决策阈值"，而不是强行拉平正向预测率。**

#### 对我们的三点

1. **$\Delta_c$ 这个量可以事先算**，不用训练。**这是本轮最便宜的诊断。**
2. **"总漏过率下降"这个 KPI 会掩盖搬运**。应换成"**每类漏过率的最大值下降**"。
3. **加权 vs 分阈值**：论文明确说后者更对症。

### 6. HaloGuard 2.0：那个守门模型在判 prompt，不在判回答

**（Astroware AI + Karunya Institute of Technology，2026-11-01，cs.CL）**
精读：`categories/t2t/papers/2611.02134_haloguard2_streaming_output_guard.md`

#### 它解决了什么

输入护栏决定请求能不能到达模型，但**永远看不到模型说了什么**。伤害可以在生成过程中浮现：越狱穿过了输入层，或者一个良性请求在几段之后漂移成操作细节。

论文的例子：一个关于**农药毒性**的良性提问，可以在若干段之后变成合成路线。

做法：在 Qwen3.5-0.8B 最后一层隐状态上加**线性头**，一次前向给出每个前缀的判决，可流式截断。

#### 本轮最重要的一段：332 对匹配样本

**协议**：留出的 onset 集，**664 条回答 = 332 对**（同一 prompt；一条有害但伤害从中段开始，一条安全孪生永不越界）。在 Phase 2 数据生成**之前**冻结，与训练不共享 prompt。

**基础护栏的表现**：

| 行为 | 占比 |
|---|---|
| **判对**（有害触发、安全孪生不触发） | **13.9%** |
| 两条都触发 | 45.8% |
| 两条都不触发 | 40.4% |
| **只在安全孪生上触发** | **0%** |

论文的推理链是全文最锋利的一段：

> "一个**读回答**的护栏至少有时会把某一对判反；一个**从不判反**的护栏，是在对两个孪生**共有的东西**做判断——那就是 prompt。"

两个补充证据：

- **中位首次触发落在 onset 之前 40 个 token。**
- 中间模型上，**37.4% 的假阳性在回答的前三个 token 内触发**；"第一个回答 token 处的分数"在会被误判的回答上是 **0.59**、不会的是 **0.24**——**这个差距只可能来自 prompt。**

#### 同模型、同尺寸：判 prompt 比判回答容易多少

三个 benchmark 同时标了 prompt 和回答：

| Benchmark | 判 prompt F1 | 判回答 F1 | 差 |
|---|---|---|---|
| HarmBench | 98.7 | 96.4 | −2.3 |
| Aegis 2.0 | 87.9 | 83.5 | −4.4 |
| **WildG** | **95.9** | **71.9** | **−24.0** |

#### 主结果与那个被抹平的单格

0.8B 的 macro F1 **83.63**，超过 Qwen3Guard-Gen-4B/8B 的 83.57（**5–10 倍参数**）。前三名只差 0.06。

但基础护栏（Phase 1）的数字更值得记：

**HarmB 91.6（全场最高）而 WildG 58.9（全场最低），同一个模型、同一次训练，差 32.7 点。平均 72.76。**

#### 一笔明码交换

| 配置 | onset 召回 | macro F1 |
|---|---|---|
| 等权平均（发布） | 47.6% | **81.0** |
| 只用纠偏模型 | **72.6%** | 76.3 |

⇒ **约 1 点 F1 换 5 点 onset 召回。** "整体判得准"与"在正确时刻判"是两个互相竞价的目标。

#### 三条工程细节（都会直接让人翻车）

1. **头必须零初始化**：Qwen3.5 末层隐状态 RMS 约 4.2，常规 $\mathcal{N}(0,0.02^2)$ 让 logits 标准差达 2.7 ⇒ 第一步梯度范数 >500，**塌成常数预测**。零初始化后从恰好 $\ln 2$ 开始。
2. **不能 packing**：24 层里 18 层是线性注意力（有循环状态），循环状态**跨打包边界传递**，同一条样本隐状态差异最大 **0.23**。⇒ **这条对我们 5 节点算力现实是直接约束。**
3. **长回答打两个窗口**："只算开头，攻击者可以在长填充后埋载荷；只算结尾，可以在开头埋。"

#### 两个诚实的自曝

- **纠偏"权重平均"不是装饰**：纠偏模型单独用 **69.1**、从零混训 **70.7**、基础护栏 **72.8**、平均后 **83.6**。原因："纠偏模型的错误不是基础护栏的错误……它**压缩了分数尺度**。平均保留了修正并**恢复了分数尺度**。"
- **WildG 修好了误报、漏报更差**：FPR 14.1→4.9，FNR 28.7→**30.1**。Aegis 2.0 则相反（FNR 23.9→7.9，FPR 27.7→27.0 几乎不动）。

#### 对我们的三点

1. **匹配对体检可以直接照搬**，判据是结构性的（"判反率 ≈ 0%"），**不需要标注、不需要训练**。
2. **图审必须分列纯图 / 图+prompt 两个接口**。
3. **"时机"要计入成本**，只报终局漏过率会鼓励"晚点判"。

## 三、趋势信号

### 信号一：评测正在从"守住了没有"转向"守住的是哪一件更窄的事"

六篇各自守住一个真实的保证，然后各自被证明与目标无关。这不是六个孤例，是**同一个方法学动作在六个场景里被独立做了一遍**：

| 论文 | 被守住的量 | 它的分子/口径 | 与目标的口径差 |
|---|---|---|---|
| Coverage Hides Churn | 覆盖率 | 只看**真值一个标签** | churn 看**每一个旧标签** |
| Reweighting | 组间 FNR 差异 | 只看**差异的绝对值** | 不看**差异从哪来** |
| Compositional Unalignment | benchmark 安全率 | 只看**判官读到的行为** | 不看**内部装了什么** |
| HaloGuard 2.0 | macro F1 | 只看**终局判对没有** | 不看**在什么时刻判** |
| TRACEMARK | 余弦对齐 | 只看**绝对相似度** | 不看**相对区分度** |
| WeLM-Image | 平均通过率 | 只看**总体** | 不看**分维度** |

**共同结构：每一个被守住的量，分子里都少了"另一个必须同时成立的东西"。**

### 信号二："分维度记账"正在从建议变成工业标配

三篇独立工作把它写成了硬要求：

- WeLM-Image："高频类目的收益不能掩盖长尾类目的持续失败"（按维度追踪通过率）。
- HaloGuard：报 macro F1 必须配**逐 benchmark 的 FPR/FNR 表**，因为池化后方向会反转。
- Coverage Hides Churn：报覆盖率必须配 **churn、发布历史、集合大小**。

⇒ **"一个总分"这个形态，在三家不同机构、三个不同任务上被判了同一个罪。**

### 信号三："改阈值"与"改权重"的优先级有了新证据

11-05 只有一句"调阈值没用"，11-06 有了"改定义比调阈值便宜 47 倍"。本轮补上第三条：

**Reweighting 论文明确建议："若目标就是拉平错误率，直接用组特定决策阈值，而不是强行拉平正向预测率。"**

⇒ **优先级排序正在收敛：改判别维度 > 改定义 > 改阈值 > 改权重 > 补数据。**

因为**加权是一种强制独立化，它会自动把代价搬到最小的那一格**；而阈值是显式的、可逐类目谈的。

### 信号四：I2I 链路的"信息保持"与"风险消除"是竞争关系

TRACEMARK 的消融（去掉一致性，归因 0.866→0.918）与 11-06 TailSteer 的发现（"只看一致性，最好的是没改"）**互相印证**：

- 11-06：FreqEdit 把编辑成功率 **16.00→10.00（−6）** 换来 PSNR，而**内容一致性反而 +5.22**。
- 11-08：去掉一致性约束，**三个域的归因准确率全部上升**。

⇒ **"保持得多"这个方向，在两个完全不同的任务上都被证明会吃掉主目标。** 这对我们的改写器是一个明确的警告：**保真约束不能当主目标，只能当约束。**

## 四、业务对齐研究板块 ⭐

### A. 直接可迁移方法

按"明天就能做"排序。

| 排序 | 方法 | 来源 | 成本 | 迁到哪里 |
|---|---|---|---|---|
| **1** | **匹配对"判反率"体检** | HaloGuard §6.2 | **半天，零训练** | 图审 |
| **2** | **加权前 $\Delta_c$ 预演账** | Reweighting §3.1 | **2 小时，零训练** | tag-weighted loss |
| **3** | **类目 churn 审计** | Coverage §6.1 | **半天，零训练** | 版本回归看板 |
| **4** | **$r_P$ 提成乘性门** | WeLM-Image §4.3.2 | 半天，零训练 | 三维评测聚合 |
| **5** | **探针 AUC vs 决策翻转率** | Compositional §4 | 1 天，零训练 | 图审 |
| **6** | **改写前后 × 链路后 双列** | TRACEMARK §4.4 | 1 天，零训练 | 改写 A/B |
| **7** | **难度两端剔除** | WeLM-Image §4.3.2 | 1 天 | 编辑数据配比 |
| **8** | **1,400 条小数据天花板** | Compositional §2.1 | 1 天，一次轻量 SFT | 图审 / 分类 SFT |

**为什么 1 和 2 排最前**：都不需要训练、不需要重标注、不需要新数据，而且**判据是结构性的**（不依赖任何外部基线）。

#### 方法 1 展开：图审"判反率"体检

1. 取同一批 prompt，各生成 2 张图（一张违规、一张无害），或用现成的同 prompt 不同图对。$N \ge 200$。
2. 用现有图审跑，**只记录是否触发**。
3. 统计四个比例：判对 / 都触发 / 都不触发 / **只在安全那条触发**。

| 观察 | 结论 |
|---|---|
| **"只在安全那条上触发" ≈ 0%** | 图审在判**共有部分**（prompt / 文本描述），不在判图 |
| "两条都触发" > 40% | 同上，且阈值偏低 |
| 判对 > 60% | 图审确实在读图，现有验收可信 |

**这个判据不需要任何外部基线**，因为它是一个**逻辑约束**：一个读图的模型不可能永远不把匹配对判反。

#### 方法 2 展开：加权前预演账

对每个准备加权的叶子类目算：

$$\Delta_c = \operatorname{logit}(\bar\pi) - \operatorname{logit}(\pi_c)$$

$\bar\pi$ 是全局违规率，$\pi_c$ 是该类目违规率。

| 条件 | 含义 |
|---|---|
| $\lvert\Delta_c\rvert > 0.2$ 且 $p_c < 0.05$ | **代价承接者**：加权后该类漏过会上升，且聚合指标看不见 |
| 这类类目 > 3 个 | 当前 tag-weighted 在做跨类目零和搬运，应改分阈值 |

### B. 风险锚点处理启发（双锚点：PORN/VULG 边界 + 政治 L2_30 层级）

#### B.1 PORN / VULG 边界：本轮拿到了**第四种、也是最可能正确**的解释

前四轮的解释依次是：

| 轮次 | 解释 | 问题 |
|---|---|---|
| 11-02 | depict 无风险 × enable 有风险格子 | 需要重新标注 |
| 11-03 | 二维坐标被压成一维标签 | 需要两轴标注 |
| 11-04 | 判定主要由几个特定词驱动 | 需要锚点表 |
| **11-08** | **它是"组合式"的：单模态都不越界，组合才越界** | **不需要重新标注，只需要改类目定义** |

**Compositional Unalignment 的核心结构**：$R(H_v,H_p) = R_0 + \tau + \rho + \xi$，其中 $\tau,\rho$ 是单模态贡献，$\xi$ 是**跨模态交互**。

`VULG-HINT-EDGE` 之所以在类目体系里"没有定义"，是因为**类目体系是单模态设计**——每个类目都在描述"这个模态里有什么"，而这一类样本的属性是"两个模态合起来构成什么"。

**三条可操作的判据（成本递增）**：

1. **组合性检验（半天，零训练）**：抽 200 条 `VULG-HINT-EDGE` 样本，把图像描述替换为中性描述（保留图），把文本替换为中性文本（保留图描述），各跑一次分类器。
   - 若**两者都不越界，只有原组合越界** ⇒ **确认是组合性类目**。此时调阈值、补同类数据、调 alpha **三个动作全部无效**，唯一有效的是**改类目定义**（新增一个"联合条件"类目）。
   - 若单模态任一仍越界 ⇒ 是单模态判据问题，回到 11-04 的锚点表路线。

2. **`not-assessable` 三态检验（半天）**：WeLM-Image 的 checklist 用了 pass / fail / **not-assessable** 三态。我们的分类器只有"是/不是"。
   - 若这批样本里**人工也无法独立判定**的比例 > 30% ⇒ 它们不是"判错"，是"**暂不可判**"，应从误杀/漏过统计中**剔除并单独设一个 abstain 桶**。
   - 这会直接改变 5.2% 这个分母。

3. **检出 vs 干预分离（1 天）**：Compositional 的教训是"检出 AUC 1.000 而干预 Δsafe −2.5"。
   - 若我们的分类器在这批样本上探针 AUC > 0.95，但消融后判定几乎不变 ⇒ **决策通路与识别通路解耦**，改分类头比改数据有效。

**跨锚点的一条共同结论**：**PORN/VULG 边界这一轮的答案从"判得不准"变成了"这类目本身不该按单模态定义"。** 这是一个**定义层**的问题，不是**模型层**的问题。前四轮都在模型层找原因，所以都只能给出"先测再决定"，这一轮第一次给出了"测法之外的动作"。

#### B.2 政治 L2_30 层级：PrefixCP 给出了"分级阈值"的严格版与它的代价

我们现在的做法是"叶子类目继承父类阈值"。Coverage Hides Churn 给出的是**它的严格版本**：

> 让每个类目保留**它被加入时**的注册表 / 归一化项。

对我们的映射是：

- 注册表版本 ≈ **类目树版本**（一级/二级/叶子的下发集合）
- 归一化项 ≈ **共享的父类先验**（父类的阈值或先验概率）
- 类目加入时的版本 ≈ **该叶子类目首次上线的那个类目树快照**

**PrefixCP 的三个可直接搬的性质**：

1. **旧类目的判定永不改变** ⇒ 版本迭代时"旧类目的误杀/漏过"是可以冻结的基线。
2. **类条件覆盖精确** ⇒ 每个叶子类目的覆盖率是独立保证的，不是全局平均。
3. **一次前缀扫描**⇒ 所有历史快照的归一化项可一次性算出，成本 1.07–1.96 倍。

**代价必须同时说清**：**稳定要付集合大小 / 保守度**。PrefixCP 恢复 40.9–58.5% 的差距，价格 0.49–3.14 个标签。映射到我们：**冻结旧叶子类目阈值会牺牲一部分整体误杀/漏过的最优性**——这个代价必须显式报出来，否则会被当成"白拿"。

**三条判据**：

1. **churn 审计（半天）**：用 $V_{\text{old}}$ 与 $V_{\text{new}}$ 两套类目集跑同一批 1979 条样本，报"旧类目判断变更率"。
   - **> 20% 而一级一致率变化 < 0.5 点** ⇒ 我们的版本回归看板存在与本文完全同构的盲区，**必须加 churn 一列**。
   - 撤销率 / 新增率 **> 3:1** ⇒ 类目扩容系统性地偏向放行，与 3.42% 漏过率的走向一致。

2. **"最差类目"应当撤回**：本文实测"最差覆盖"在所有方法上都在 0.153–0.789，**包括覆盖保证有效的那些**，因为它是"在许多有限类目里挑最差"。我们的 30 个 L2 类目同样是有限多的格子，**"VULG-HINT-EDGE 最差"这个结论同样可能是 winner's curse**（与 10-27 的 A 实验互为正交验证）。改为报**分位数**（P10 / P25 / 中位）而不是最小值。

3. **发布顺序要先冻结**：本文的 Table 5 显示，不同的类目上线顺序会让 49.6–65.8% 的图像集合全变，而 macro 覆盖率只动 0.0015。⇒ **在类目树还在增量上线时，任何阈值结论都必须绑定"当时的类目树快照"**，否则不可比较。这与 11-06 的"数字必须绑定配置"是同一条，只是把"配置"具体化成了"类目树版本"。

#### B.3 跨锚点的第三条：加权是"隐式"的均等化

Reweighting 论文的最硬一句："重加权**隐含地执行了人口统计均等**，即使你用它来缓解错误率差异。"

映射到 L2_30：如果我们用 tag-weighted loss 去"拉平"各层级的漏过率，本质上是在**强制各层级的正向预测率相等**。而如果各层级真实的风险基率不同（政治敏感内容的真实分布确实不同），**这个强制必然抬高某些层级的漏过**。

⇒ 这与 11-03 判断的"拦截面均衡（类 DP）与误杀率达标（类 FPR）是两套冲突口径"是**同一条结论的第三次独立验证**。**主约束用 FPR，DP 型指标降为监控项** 这个建议本轮再加一条支撑。

### C. 三维评测设计启发（含阈值 operating point 与多版本回归口径）

#### C.1 三维评测：从"加权和"改成"一门 + 两项"

WeLM-Image 的工业配方：

$$r = r_P \times (0.4 + 0.4\,r_C + 0.2\,r_Q)$$

**只有一个维度不可补偿（$r_P$），其余仍可加权。**

**这比"全改几何平均"更值得采用**，理由有三：

1. 几何平均会让三项等权，而我们实际上只知道"指令遵循"必须不可补偿，另两项的相对权重是有业务依据的（0.4:0.2）。
2. 几何平均对任一维接近 0 都会打穿样本分，**包括那些"确实判不了"的样本**；乘性门只惩罚"没执行"。
3. 它已经在真实产品里跑过（微信）。

**最小实验（半天，零训练）**：

1. 1979 条样本，拆成 $r_P, r_C, r_Q$ 三项，用现有 judge 打分。
2. 算三种聚合：现用加权和 / 乘性门 / 几何平均。
3. **报三个数**：① 三种聚合下模型排名的翻转率；② $r_P < 0.3$ 但总分 > 0.7 的样本数；③ 6 个模型版本的排序在三种聚合下是否一致。

**判据**：若"$r_P < 0.3$ 且总分 > 0.7"的样本 **> 5%**，说明现有评测允许"没执行指令"被"没破坏原图"补偿掉——**这正好是 I2I 改写 0/0% 的一种可能解释**。

#### C.2 加两列：churn 与"链路后"

**列一：churn（旧类目判断变更率）**

| 指标 | 现状 | 应加 |
|---|---|---|
| 误杀率 | 5.2% | — |
| 漏过率 | 3.42% | — |
| 一级一致率 | 77.64% | — |
| **旧类目判断变更率** | **没有** | **必加**（Coverage） |
| **撤销率 / 新增率（分开）** | **没有** | 必加（Coverage：0.1–2.5% vs 8.4–52.7%） |
| **链路后指标**（改写 → 图生图编辑 → 再测） | **没有** | 必加（TRACEMARK：0.003 → 0.500） |

**列二：链路后**

TRACEMARK 的数：**编辑前差 0.003，编辑后差 0.500。**

⇒ 若我们的两个改写器版本在"改写后 prompt 上"指标接近，**不能推出在"送进图生图之后"也接近**。

**判据**：$\Delta_{\text{pre}} < 0.05$ 而 $\Delta_{\text{post}} > 0.15$ ⇒ 现有 A/B 看板结论建立在错误的分布上。

#### C.3 阈值 operating point：三个新输入

**输入一：决策规则必须全局，不能按子集调。**

HaloGuard 实测"按 benchmark 调阈值把 macro F1 抬约 3 点"——**这 3 点是假的**，因为部署时不知道输入来自哪个分布。

映射到我们：台按一级/二级/叶子下发阈值，**这本身是合理的（业务确实按类目定严松）**，但**评测时不能用同一批数据既定阈值又报指标**。本文的做法值得抄：**每个 benchmark 对半分，一半定规则、一半评分，两个种子双向**，留出 83.3 vs 样本内 83.6。

**输入二：FPR 与 FNR 必须分列，且必须报池化方向。**

HaloGuard 的表 11 是最好的教材：同一个模型，XSTest-R 的 FPR 5.4 / FNR 6.4（误多于漏），WildG 的 FPR 4.9 / FNR **30.1**（漏多于误）。池化后"漏多于误"。

**输入三：基率决定"哪一侧是余量"。**

多语版：PolyGuardPrompts 只有 **16.6%** 不安全 ⇒ 1,482 个假阳性 vs 360 个假阴性 ⇒ **剩余余量在精确率，不在召回**。

映射到我们：**PORN 类目的基率、VULG 类目的基率、L2_30 各层的基率都不一样**，所以"先压误杀还是先压漏过"这个问题的答案**必须按类目回答**，不能按总体回答。

#### C.4 多版本回归口径：四件事

| # | 口径 | 依据 | 现状 |
|---|---|---|---|
| 1 | **绑定类目树快照** | Coverage Table 5：排期让 65.8% 图像集合全变而覆盖率只动 0.0015 | 无 |
| 2 | **绑定输入配置指纹**（分辨率 / 强度 / 编辑幅度） | TRACEMARK：0.062 → 0.997 | 无 |
| 3 | **报 churn 与集合/保守度变化** | Coverage：稳定要付 0.49–3.14 个标签 | 无 |
| 4 | **报"分维度"而非只有总分** | WeLM-Image / HaloGuard / Coverage 三家一致 | 无 |

⇒ **这四条合起来，就是"多版本看板必须带配置指纹"的具体化。** 11-05 提过一次（PGuard 12 配置块 / SQM 校准前后 / CompoSET 13.9% vs 49.5%），本轮把"配置"具体化成了三类：**类目树版本、输入预处理配置、评测聚合方式**。

#### C.5 一个必须新增的指标：时机

HaloGuard 的交换率：**1 点 macro F1 = 5 点 onset 召回。**

映射到图生图：我们的漏过率是**终局判定**，不含"在第几步判出"。若某策略"先渲染 60% 再拦"，终局漏过率可能很好，但**用户已经看到了**。

**建议加一个"拦截时机"指标**：在有害内容可见之前拦截的比例。成本：需要分段标注，可先在一个小集（200 条）上做。

### D. 下一步实验建议（六条主线）

按"零训练优先 + 能一次结束纠结优先"排序。**前五项合计约 3 天，全部零训练。**

#### H1（图审线，半天，零训练，**最优先**）匹配对"判反率"体检

**依据**：HaloGuard §6.2，332 对样本判对 13.9%，**判反 0%**。

**做法**：200 对同 prompt 的（违规图 / 无害图），只记录是否触发，统计四个比例。

**判据（结构性，不需基线）**：
- **"只在安全那条上触发" ≈ 0%** ⇒ 图审在判共有部分。此时**换判别维度、加 abstain、改输入接口**才会有效；调阈值与补数据不会。
- 判对 **> 60%** ⇒ 图审确实在读图，现有验收可信，撤回这条长期假设。

**为什么最优先**：它回答的是"我们悬了三周的假设"，而且**判据是逻辑约束**，不依赖任何外部数字。

#### H2（tag-weighted 线，2 小时，零训练）加权前 $\Delta_c$ 预演账

**依据**：Reweighting §3.1，$\Delta_g = \operatorname{logit}P(Y=1) - \operatorname{logit}P(Y=1|G=g)$。

**做法**：对每个叶子类目算 $\Delta_c$ 与 $p_c$，标出 $|\Delta_c| > 0.2$ 且 $p_c < 0.05$ 的"代价承接者"。

**判据**：这类类目 **> 3 个** ⇒ 当前 tag-weighted 是跨类目零和搬运，**应改分阈值**（论文 §4.2 的建议）。

**为什么排第二**：2 小时，且**能在训练之前**给出结论。

#### H3（版本回归线，半天，零训练）类目 churn 审计

**依据**：Coverage Hides Churn，覆盖率动 ≤0.01 / 60–67% 图像判断变。

**做法**：$V_{\text{old}}$ 与 $V_{\text{new}}$ 两套类目集跑同一批 1979 条，报 churn / 撤销率 / 新增率 / 一级一致率变化。

**判据**：
- churn **> 20%** 而一级一致率变化 **< 0.5 点** ⇒ 回归看板有盲区，**必加 churn 一列**；
- 撤销 : 新增 **> 3:1** ⇒ 类目扩容偏向放行，与 3.42% 漏过率同向。

#### H4（三维评测线，半天，零训练）$r_P$ 乘性门 + 排名翻转率

**依据**：WeLM-Image $r_{\text{edit}} = r_P(0.4+0.4r_C+0.2r_Q)$。

**做法**：见 §C.1。

**判据**：$r_P < 0.3$ 且总分 > 0.7 的样本 **> 5%** ⇒ 现有评测允许补偿，**且这可能是 I2I 0/0% 的解释**。

#### H5（图审线，1 天，零训练）探针 AUC vs 决策翻转率

**依据**：Compositional Unalignment，AUC 1.000 而 Δsafe −2.5（随机 −10.5）。

**做法**：末层特征训线性探针区分"判 PORN 但人工确认为无害"vs"判无害但人工确认违规"，报 AUC；再把特征在探针方向上的投影减掉，重跑分类头看翻转率。

**判据**：
- AUC **> 0.95** 但翻转率 **< 10%** ⇒ 识别-决策解耦，**改分类头比改数据有效**；
- AUC < 0.8 ⇒ 特征不够，走常规数据/训练路线。

#### H6（I2I 改写线，1 天，零训练，**针对 0/0% 的落地建议**）把 0/0% 拆成"三态 + 乘性门"

**这是本轮对 I2I 分流命中 0/0% 唯一一条可落地的建议，而且它不是"再改一版改写器"。**

**依据**：WeLM-Image 的 checklist 三态（pass / fail / **not-assessable**）+ 乘性门；Compositional 的"1,400 条就能追平 123k 条"。

**诊断**：过去十二周我们一直在"改怎么改写"，从没测过"**该不该改写**"和"**改写后判不判得了**"。

**做法**（三步，全零训练）：

1. **三态化**：对 200 条"需改写"样本，让 judge 对每条编辑指令的每个要件输出 `pass` / `fail` / `not-assessable`，而不是一个总分。
2. **算三个数**：
   - **要件通过率**（分母是"所有可判要件"）
   - **不可判率** = `not-assessable` / 全部要件
   - **整条命中率**（现在这个数是 0%）
3. **加乘性门**：$r_{\text{edit}} = r_P(0.4+0.4r_C+0.2r_Q)$ 重算整条。

**判据（这是关键）**：

| 观察 | 结论 | 动作 |
|---|---|---|
| 要件通过率落在 **20–40%** 而整条命中 0% | **0/0% 是判据无分辨率，不是能力为零** | 换判据，不换模型 |
| 不可判率 **> 30%** | 这批样本**本来就不该判** | 设 abstain 桶，从 0/0% 分母里剔除 |
| 要件通过率 **< 10%** | 真是能力问题 | 才轮到改改写器 |

**为什么这条能破 0/0%**：0% 是一个**没有分辨率的数**——它把"判不了""改不了""改了没生效"三种情况压成了同一个读数。三态化 + 分要件，**一次把 0% 变成三个有分辨率的数**。

**补充（若第一步就拿到"要件通过率 20–40%"）**：直接引用 Compositional 的结论——**1,400 条定向 SFT 就能追平 123k 条 RL 流水线**。所以修补数据集的成本比想象低一个数量级，**不要一上来就规划大规模训练**。

#### H7（RL 改写线，半天，零训练）保真项消融

**依据**：TRACEMARK 去掉一致性约束，归因 0.866→0.918（三域全升），同时余弦对齐下降。

**做法**：把改写奖励里的"语义保真"项权重设为 0 / 0.5 / 1，各跑一次小规模评测，报"风险消除率"与"编辑成功率"。

**判据**：去掉保真项后风险消除率显著上升、且人工抽检意图保持率下降 < 5 点 ⇒ **保真约束当前设得过重**，应改为"约束"而非"目标"。

#### H8（多模态视频扩展）本轮不给建议

**理由**：`d4_video_generation_safety` 只回 **1 篇**、`d5_video_temporal_risk` 回 **2 篇**，逐篇核验后**无一篇**属视频生成内容安全。**本轮没有强相关工作，按规则不给建议。**

维持 11-04 的判断：**先把三条规则（分维度记账、乘性门、churn 审计）搬到图像侧跑通，等 i2v/t2v 落表 >1000 条再评估。**

### E. 权重侧 vs 输入侧：互补关系与各自失效边界（第七轮，表述再收紧）

#### E.1 本轮新增的两条边界证据

**（a）TRACEMARK：约束项会吃掉主目标。**

去掉一致性约束 0.866→0.918。这说明**在一个"保住某个信号"的任务里，加约束不必然更好**。

映射到两条范式：
- **权重侧（擦除）**：约束是"擦掉概念且不损质量"。11-04 的 UniForget 已给出代价（生成侧 TF 100.0 而 DF 24.0；N=1→30 时理解侧 92.7%→37.1%）。
- **输入侧（改写）**：约束是"改得安全且不损语义"。**TRACEMARK 说明这个约束同样可能设得过重。**

⇒ **两条范式共享同一个失效模式：约束与主目标竞争，而约束容易被当成"必须满足"从而过度加权。**

**（b）Compositional Unalignment：对齐是"薄"的，但"薄"不等于"没用"。**

1,400 条 SFT 追平 123k 条四阶段 RL。这个数在字面上支持"权重侧对齐是薄的"，但论文的措辞很克制："这是关于**测量**的问题，而非声称某个流程更优。"

⇒ **正确读法**：**行为指标测不出对齐深度**，所以"权重侧已对齐"不能作为"输入侧不需要防护"的理由。反过来也成立：**输入侧能拦住的，权重侧不一定拦得住（因为锚点无穷），权重侧能治的（已生成出去的图、反复试探），输入侧也治不了。**

#### E.2 本轮收紧后的表述

前六轮的表述在收敛，本轮把"互补"具体化成**三个不重叠的作用域**：

| 作用域 | 权重侧（擦除 / 对齐） | 输入侧（改写 / 图审） |
|---|---|---|
| **上线前** | ✅ 唯一手段（概念不可逆移除） | ❌ 不适用 |
| **上线后逐条可回滚** | ❌ 改权重要重新发版 | ✅ 唯一手段 |
| **已经生成出去的图** | ❌ | ✅ 图审 + 溯源（TRACEMARK） |
| **无穷新锚点** | ❌ 擦不完 | ✅ 规则/改写可热更新 |
| **对抗性反复试探** | 部分（加固后 Δ 64.7→22.4，**但没守住**） | 部分（时机问题，HaloGuard 1 点 F1 换 5 点召回） |

**两条共同的失效边界**：

1. **两者都缺"个体级"保证。** 权重侧给的是分布性质（擦除率），输入侧给的是逐条判定（但需要阈值）。**没有一方能承诺"这一条一定安全"。**
2. **两者都被"组合式"绕过。** Compositional Unalignment 证明：单模态都安全时，组合可以有伤害。**权重侧按概念擦、输入侧按单条改，都不处理"组合"这一维。** ⇒ 我们对 `VULG-HINT-EDGE` 的处理必须新增"联合条件"维度，这是两条范式都覆盖不到的地方。

#### E.3 结论（第七轮）

**不是"互补不可替代"，而是"三个不重叠的作用域 + 两个共同的盲区"。**

盲区一是**个体级保证**，盲区二是**组合维度**。前者短期无解（需要 abstain 与人工，见 H1/H6），后者可以靠**类目定义改造**部分解决（见 B.1）。

### 高优先（与主线强相关，本轮因篇幅未精读）

**`2611.07329` Where Do Reported Long-Video QA Gains Come From?（单作者 Shih-Yao Lin）**

**为什么值得单独记**：它是本轮**对"小评测集"最直接的一击**。

- 全量 Video-MME long bucket（**n = 900, K = 8**）：**没有任何 selector 显著优于均匀采样**。最大估计 +1.9 pt（95% CI [−1.2, +5.0]），cascade +1.2 pt（[−1.7, +4.1]），**全部落在 ±5 pt 内**。

⇒ **对我们**：图生图评测集 1979 条是够的，但**任何在 200 条子集上得出的结论（含 H1/H4/H5/H6 里我建议的 200 条实验）都必须报 CI，且不能做跨版本排序宣称**。这条约束我已在 H1 的判据里用"结构性判据"规避（不看显著性，只看逻辑约束）。

**`2611.07950` Leakage- and Label-Aware Benchmarking of Class-Imbalance Strategies（6 作者）**

**为什么值得记**：它给了一个"评测集泄漏"的极端例子。

- 29,083 张 MIMIC-CXR / 10,479 病人 / 8 个诊断目标。
- **一个"查表法"（复制同 EHR 向量的开发集影像标签）几乎追平最强模型。**
- **换到未见病人后，所有模型都跌到"全预测阳性"的水平。**
- 追因：每个病人的标签是**单次住院诊断码的关键词匹配**，被复制到该病人**所有**影像，**约 1/3 的影像标签与其自身住院不符**。
- 换成病人分离 + 住院对齐 + 规则精炼后：**没有任何不平衡策略把 macro F2 提升超过 0.01**；调好的树模型相对调好的 logistic **无一致优势**；RAD-DINO 在自监督预训练里**见过 96.6% 的这些影像**。

⇒ **对我们**：我们的 1979 条图生图评测集是否有"同一 prompt / 同一源图被拆到不同 split"的泄漏？**"查表法基线"是一个极便宜的泄漏自检**——如果某条平凡规则（如"按 prompt 长度""按源图哈希"）能追平模型，评测集就漏了。

## 附：今日一句话结论

**今天六篇论文各自守住了一个真实的保证——覆盖率、组间差异、benchmark 分数、macro F1、余弦对齐、平均通过率——然后各自证明了这个保证只在保证一件比你想管的事更窄的东西：覆盖率的分子只有一个标签，组间差异不看差异从哪来，benchmark 分数看不见内部装了什么，macro F1 不含判在什么时刻，余弦对齐不等于分得开，平均通过率会把 96.4 和 71.9 抹成 83.6。** 所以"我们守住了 X"这句话，从今天起应该改写成"我们守住了 X，而 X 的分母是 ___"。
