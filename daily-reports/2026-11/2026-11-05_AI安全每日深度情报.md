### 今日主题：没有可比性的数字，不是证据

六篇各自在证明同一件事，但从六个不同的位置：

| 论文 | 它证明了哪个数字"不可比" |
|---|---|
| **CompoSET** | 旧 benchmark 的分数不可比——因为配对图有 **97%** 的像素在变，模型只要看出"整张图不一样"就能答对 |
| **PGuard** | 阈值不可跨配置搬——同一模型 12 个配置块，阈值从 **10% 到 97%**；图-文输入 29 个阈值里 **24 个压在下限 10%** |
| **ODC** | 单一指标不可代表整体——CLIP **+1.47** 的同时 UniDet **−20%** |
| **DeCoRL** | 奖励数字不可跨奖励模型比——vanilla VLM 奖励 7.21，训过的 8.16，差 **7 倍于** SFT 的增益 |
| **GOAL** | 阈值不可救排序——如果深层表示已重叠，阈值只能在混叠的轴上切 |
| **SQM** | 校准参数不可跨数据集复用——作者自己说"最大影响因素是数据集"，且校准**完全不改排序**（Spearman 0.494 前后不变） |

**一句话**：这些论文都在拆同一颗雷——**我们汇报的每个数字，都绑定在产生它的那个配置上。换模型、换变体、换数据集、换评测协议，数字就作废。**

对当前业务最直接的后果：**6 个模型版本的迭代看板，如果每个版本的阈值/校准参数/评测集各自不同，那"版本 A 比版本 B 好"这个结论本身是不可信的。** 今天的技术主线就是把这个前提补上。

### 六篇各自最该记住的一个数

| 论文 | 一个数 | 含义 |
|---|---|---|
| **CompoSET** | 像素变化 **97% → 8%** | 把对照组的差异压到 8%，22 个 dual-encoder **全部低于随机线**（最高 13.9% vs 随机 16.67%） |

| **ODC** | **+1.47 / −20%** | 嵌入空间方向手术能让 CLIP 涨 1.47，同时 UniDet 掉 20%。**表征层干预的天花板就在这** |

## 一、T2I / T+I2I 论文（核心主线 · 4 篇）

### 1. CompoSET：编辑评测的对照组设计错了，87% 的信号是"整张图不一样"

**Caltech（Perona 组）**，2026-10-30，cs.CV。代码与数据均已开源。

**这是本轮唯一一篇直接命中 T+I2I 编辑评测的工作，而且它给的是一把尺子，不是一个方法。**

#### 它量了什么

既有组合性 benchmark 的配对图，**平均 97% 的像素在变**。场景、布局、内容、风格全变了。模型只要捕捉到"整张图不一样"就能答对，根本不需要理解"改的是哪一个属性"。

CompoSET 把配对差异压到 **8%**：

| 维度 | 取值 |
|---|---|
| instance | **1,776** |
| base 场景 | **80** |
| 每 base 的 foil 数 | **~22** |
| 编辑类型 | **16 种**，4 个语义类别 |
| caption 档位 | 3 档（短/中/长） |
| base–foil 像素变化 | **8%**（旧 benchmark 97%） |

#### 结果有多狠

| 模型 | **CompoSET** | BiVLC | ColorSwap | MMVP | SugarCrepe |
|---|---|---|---|---|---|
| 随机线 | 16.7 | 16.7 | 16.7 | 50.0 | 50.0 |
| CLIP B/32 | **4.4** | 47.2 | 8.7 | 8.1 | 68.1 |
| SigLIP B/16 | **10.2** | 59.6 | 30.7 | 23.0 | 74.7 |
| SigLIP-2 SO400M/14（最好） | **13.9** | 49.5 | 39.7 | 31.1 | 79.4 |
| NegCLIP B/32（文本侧硬负样本） | **7.0** | 55.3 | 14.0 | 12.6 | 83.4 |
| DreamLIP B/16（稠密重描述） | **13.7** | 53.9 | 61.0 | 16.3 | 74.4 |

**22 个 dual-encoder 全部低于随机线 16.67%，最高的 13.9%。** 按 80 个场景聚类 bootstrap 后，22 个上界仍全部低于随机（最大 15.55%）。

同模型在 BiVLC 上 49.5%，在 CompoSET 上 13.9%。**这不是"模型变差了"，是"尺子换了"。**

#### 三条对我们直接有用的结论

**（1）配对差异必须被控制到"单点"**
一条 base 配 ~22 个 foil，是为了把"场景难"与"编辑难"分开。一条 base 只配一个 foil 的 benchmark 做不到这个分离——分不清是这条指令难，还是这个编辑类型难。

**（2）文本侧硬负样本不迁移到图像侧**
NegCLIP 用文本侧硬负样本微调，在 CompoSET 上 **7.0%**，比它的 base（CLIP B/16 LAION 7.8%）**还差 0.8 点**。

对我们的含义很硬：**I2I 改写的 hard negative 如果只在指令文本上做扰动（换词、换语序），大概率同样不迁移。hard negative 必须在图像侧构造——同一指令、不同源图、同一源图、不同指令。**

**（3）双向评分是必须的**
论文要求 image→text 与 text→image 两个方向都对才算过。因为单向分数里混着巨大的先验偏置：

> CLIP-B/32 把 `on` 认对的 92.2%，把 `under` 认对只有 **22.3%**。

**单向评分测的是"模型偏好哪个介词"，不是"模型懂不懂空间关系"。**

#### 与 0/0% 的直接关系

我们的 I2I 评测集是 2,000 条 / 1,979 有效。**先量一件事：这批样本的 base 与目标图，像素变化中位数是多少？**

如果中位数在 80–95% 区间，那它和"97% 的旧 benchmark"是同一类，**当前 0/0% 的命中率里，有一半是评测集设计造成的**——因为在这种评测集上，方向对不对根本读不出来，只能读出"图变了没有"。

这一步几十分钟，不需要任何模型。**它应该排在所有 I2I 实验之前。**

### 2. PGuard：一份真实工业阈值表，29 个子类目，阈值从 10% 到 97%

**阿里巴巴 AAIG**，2026-11-02，cs.CL。代码/模型已在 GitHub + HuggingFace + ModelScope 放出。

**这是本轮唯一一篇头部公司公开"按类目下发阈值"完整表的工业工作，而且它把表放在附录里，可以逐行读。**

#### 它做了什么

原生流式护栏：直接读 backbone 中间层 residual stream 做 **token 级**安全检测，**不改推理路径、不改生成行为**。

| 组件 | 设计 |
|---|---|
| 隐状态抽取 | 固定 3 层（Qwen3.5-9B → 20/24/28；122B-A10B → 32/36/40 或 36/40/44） |
| 层聚合 | **动态层门控**，权重随训练演化，不同 backbone 落在不同层子集 |
| 表征建模 | 三变体：stateless(last-token) / EMA-attention / GRU |
| 判定 | 逐 token 风险分 + verdict，**每 10 token 采样一次** |
| 部署 | **两级级联**：原生变体全流量打分 → 只有被标记的升级到外部推理护栏 |
| 系统 | SGLang 0.5.11，四个协同优化 |

**开销 0.82–2.26%**（Qwen3.5-122B-A10B + SGLang）。文本平均 F1 **0.836**。

#### 阈值表：本文最该被逐行读的部分

附录 B 表 19 按 **(变体, backbone, 阶段 Q/R, 输入 T/VL)** 分块，每块给 **9 个风险维度**（A Crimes / B Hate / C Health / D Ethics / E Privacy / F Cyber / G Extremism / H Inappropriate / I Minors）× 各自子类目的阈值。**共 12 个配置块，每块 29 个阈值。**

同一 backbone（Qwen3.5-9B）、同一个 EMA 变体：

| 配置 | 29 个阈值的范围 | ≤11% 的个数 | 恰为 10%（下限） |
|---|---|---|---|
| **Q-T（文本 query）** | 10 – 74 | 4 | 2 |
| **Q-VL（图-文 query）** | 10 – 39 | **25** | **24** |

**图-文输入的 29 个阈值里，24 个恰好压在下限 10%，最高只有 39。** 同模型文本 query 的阈值中位在 40 以上、最高 74。

阈值被压到下限，只有两种可能：

1. 该模态下模型的风险分**整体偏低**，必须降到地板才够召回 → **分数分布被系统性压低**；
2. 该模态下分数**区分度差**，任何高于下限的阈值都会让召回崩 → **排序不好**。

无论哪一种，结论是同一句：**图-文这一侧的 operating point 不能从文本侧平移，也不能用共享阈值。**

#### 一个必须指出的内部张力

论文同时报了两个方向相反的事实：

- 图-文 query 阈值**几乎全压下限**（说明极敏感）
- 多模态真实流量拦截率**只有 0.11–0.60%**（说明极不敏感）

合起来说明：**图-文侧的风险分是"低分密、高分少"——大多数样本挤在低位，给出高分时几乎确定有问题，但中间没有可用区间。** 阈值只能压地板，压了地板也没拦多少。

**这是校准问题 + 排序问题叠加，不是阈值问题。** 这一条与我们正在纠结的"误杀 5.2% 该不该调阈值"直接相关。

#### 误杀数据（最接近线上的一条）

| 模型 | query 侧 XSTest / OR-Bench / Avg |
|---|---|
| Qwen3Guard-Gen-8B | 12.88 / 7.71 / 10.29 |
| WildGuard-7B | 1.07 / 8.64 / 4.86 |
| SIREN (Llama-3.1-8B) | 25.75 / 19.07 / **22.41** |
| NExT-Guard (Qwen3-8B) | 18.51 / 16.24 / **17.38** |
| PGuard-lasttok (Qwen3-8B) | 14.55 / 16.15 / 15.35 |
| **PGuard-ema (Qwen3-8B)** | 10.06 / 2.18 / **6.12** |
| PGuard-ema (Qwen3.5-9B) | 14.49 / 12.77 / 13.63 |

**同方法不同变体，query 侧误杀从 6.12% 到 16.09%，差 2.6 倍。** 这不是模型好坏，是**表征建模方式**（保不保留时序）决定的。

真实良性流量：文本 query **3.69–5.05%**、response **2.32–2.80%**；多模态 query **0.11–0.60%**、response **0.07–0.18%**。

#### 早拦截与稳定性

| 项 | 结果 |
|---|---|
| 前 10% token 内首次标记 | **86.3%** |
| 前 20% token 内首次标记 | **92.3%** |
| EMA 变体：命中样本中连续 20 token 超阈值 | **>95%** |
| EMA 变体：连续 50 token 超阈值 | **~93%** |
| stateless 变体：连续 50 token 超阈值 | **60–69%** |

**stateless 有 30–40% 的"命中"只是单点抖动。用 stateless 做早拦截会大量误停。** 这条对任何"流式拦截"设计都成立。

#### 边界

PGuard 是 MLLM 护栏，**不覆盖扩散模型的生图输出**。图审侧能迁的是"读中间表征 + 按类目下发阈值 + 两级级联"这套**工程范式**，不是把模型搬过去（扩散模型没有 token 流）。另外它的 A–I 九维**没有 PORN/VULG 这种边界混淆对，也没有政治 L2_30 的层级口径**。

### 3. ODC：输入侧还有第二条路——不改文字，改嵌入

**墨尔本大学**，2026-10-31，cs.CV。

**这篇名义上做"语义漂移修正"，但它的机制恰好是我们做风险锚点外科替换想要的那套东西。**

#### 立场转换

所有输入侧干预都默认一个前提：**要改就改文字**。ODC 说：文字一个字不动，改的是这条 prompt 在文本编码器里的**嵌入**。

六步流程：

| 步 | 做什么 |
|---|---|
| 1 | 用原 prompt 生成初始图 I₀ |
| 2 | 在共享 VLM 空间算 I₀ 与 prompt 的**漂移向量** v_drift |
| 3 | 取 v_drift 对 v_text 的**向量拒绝**（正交分量）v_orth，词表检索 top-k 词集 |
| 4 | 检索词重嵌入 + softmax 加权池化 |
| 5 | **自适应秩缩减概念移除**：QR 分解，保留相对幅值 > ζ=1% 的主方向，从原嵌入中剔除 |
| 6 | 用修正嵌入重新生成 |

核心公式就一行：

$$\mathbf{v}_{orth} = \mathbf{v}_{drift} - \underbrace{\left(\frac{\mathbf{v}_{drift}\cdot\mathbf{v}_{text}}{\|\mathbf{v}_{text}\|^2}\right)\mathbf{v}_{text}}_{\mathbf{v}_{proj}}$$

#### 为什么"先取正交"这个设计值得抄

不是把漂移向量整个减掉——那样会把 prompt 本身要求的内容一起减掉。**减去投影，等于只减"prompt 没要求的部分"。**

一比一搬到风险锚点上：**风险方向 = 整条 prompt 嵌入里与"意图子空间"正交的那部分。减去正交部分，等于保留用户意图、只去掉风险增量。**

这比词表替换稳健，因为它不依赖同义词库是否覆盖。

#### 结果与天花板

| 方法 | COALBench SDXL CLIP | PartiPrompts SDXL CLIP | T2I-CompBench 3-in-1 | UniDet |
|---|---|---|---|---|
| Vanilla | 30.33 | 30.83 | 0.3294 | **0.025** |
| Negative Prompt BoT | 31.19 | 31.74 | – | – |
| A&E（注意力引导） | 29.54 | 30.15 | 0.3259 | 0.023 |
| **ODC** | **31.80** | **32.50** | **0.3572** | 0.020 |
| ODC BoT | **32.29** | **32.99** | – | – |

**四个必须记住的数：**

1. **+1.47 CLIP**（30.33 → 31.80）：这是"嵌入空间方向手术"能达到的幅度。在 0–100 的 CLIP 分上是 1.5 个点。
2. **UniDet 0.025 → 0.020（−20%）**：空间检测**反向**。语义对齐涨了，空间关系掉了。
3. **A&E 29.54 < Vanilla 30.33**：一个专门做注意力引导的方法，**比不改还差**。"更用力地对齐"不等于"更对齐"。
4. **ODC BoT 32.29 > ODC 31.80**：单次嵌入手术有方差，best-of-two 还能涨 0.5——**说明这个干预本身不稳定**。

#### 它给出的边界

表征层干预的**天花板很低**：能精准去掉一个方向，但去不掉整条链路上的损失。而且它需要先跑一次生成（成本 ×1.5，BoT ×2 以上）。

对我们的直接含义：**嵌入修正可以作为改写的对照/补充，但不能作为改写的替代。** 它更像一个"精度手术刀"，改写更像"整体换句"。

### 4. DeCoRL：把"一致性"拆成物体级奖励，然后看见它拿什么换了什么

**小红书**，2026-10-29，cs.CV。

**这篇是本轮唯一给出"RL 用一致性奖励换指令遵循"完整价码表的工作，而且价码与昨天 Kling 那篇可以对上。**

#### 起点是一个很硬的退化

多图合成（2–6 张参考图），参考图一多就崩：

| 参考图数 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|
| Qwen-Image-Edit2511 | 8.41 | 6.99 | 7.09 | **4.98** | **3.64** |

#### 核心判断：整体一致性标量不可学

**SFT 只能给隐式监督。** 整体图的一致性是一个标量，模型不知道"是哪个物体没保住"。所以论文把一致性**拆到物体级**：

1. 从指令 + 参考图解析"必须保住"的物体标签
2. 参考侧开放词表 grounding
3. 生成侧 Grounding DINO 按同一标签取 top-1 框并裁剪
4. 单物体一致性奖励模型打分（**CoT 训练过的 VLM**）
5. **物体在参考图有、生成图检不到 → 奖励记 0**
6. 聚合 S = (1/N) Σ s_ij（**算术平均**）

#### 结果

## 二、方法论迁移论文（2 篇）

### 5. GOAL：误杀不是阈值问题，是梯度耦合问题

**合肥工业大学 + NUS**，2026-10-29，cs.AI。

#### 两个观察

**观察一（表示层）**：有害样本与过度拒答样本的表示，在**某些中间层可分**，但在**深层越来越重叠**。

**观察二（梯度层）**：有害样本梯度有**高类内相似度**、集中在**低秩子空间**；且在 over-refusal prompt 上，这些梯度**与"拒绝"目标的梯度对齐强度高于与"有用"目标的梯度**。

推论：这种不均衡的梯度耦合把过度拒答样本往"拒绝"侧推；深层表示分离度下降让模型更难维持边界。

**对我们的冲击**：我们线上误杀 5.2%，长期被当作"阈值偏了"。这篇的立场是——**如果误杀样本与有害样本在深层表示上本来就重叠，任何阈值都无法把它们分开。**

#### 方法

1. 取有害样本，算**逐样本** SFT 梯度，堆成矩阵 G
2. 对 G 做 SVD，用 CER(k) = Σσⱼ² / Σσᵣ² 判断能量集中度，取前 k 个右奇异向量 V_k
3. 投影矩阵 **P = V_k V_kᵀ**，即"拒绝子空间"
4. 对 over-refusal 梯度做正交投影：**g^⊥ = (I − P) g**
5. 加安全感知对比学习，在"安全相关层"上显式加大两类表示间距

#### 结果

| 项 | 结果 |
|---|---|
| Llama-2-13B-Chat OKTest | 0.9400 → **0.9700** |
| Llama-2-13B-Chat CoCoNot | 0.8496 → **0.8892** |
| Gemma-7B-it JBB 安全分 | 0.90 → **0.97** |
| Gemma-7B-it STL 安全分 | 0.9748 → **0.9884** |
| 15 个 over-refusal 设置 | **13 个最好/并列最好，2 个第二** |
| 通用能力最大下降 | **0.0071** 绝对准确率 |

人工 + GPT-5.1 双评：

| 方法 | 自动拒答率 | 人工拒答率 | Useful Compliance |
|---|---|---|---|
| SFT | 19.5% | 21.5% | 66.5% |
| ACTOR | 14.5% | 15.0% | 70.0% |
| **GOAL** | **9.0%** | **10.0%** | **76.0%** |

**拒答率砍一半以上，同时 Useful Compliance 涨 9.5 点**——说明降误杀不是"把拒答换成敷衍"。

#### 它与"加 abstain 类"的关系

| 路线 | 改什么 | 前提 |
|---|---|---|
| abstain 类（10-30 G1） | 输出空间 | 误杀样本在表示上**可分** |
| GOAL 式正交化 | 优化动态 | 有害梯度**低秩** |

**如果深层表示已重叠（观察一成立），abstain 类在深层特征上找不到可分空间，加类无效。**

三条独立证据指向同一结论：本篇的"深层重叠" + 11-04 的 2611.01512（弃权追踪局部标签方差而非新颖度）+ 10-30 的 G1 判据。**加弃权类大概率不是正确方向。**

#### 边界

纯 T2T，无图像；逐样本梯度成本高（7B 可以，百亿级撑不住）；CER/k 的选择偏启发式；**未给"表示重叠"的逐层量化曲线**（只有可视化）。

### 6. SQM：校准只改尺度，不改排序——那它能救什么、救不了什么

**Upwork Inc.**，2026-10-30，cs.AI。

#### 立场转换

> LLMaJ 的分数不是孤立的点，是从一个分布里抽出的**定序评分**。

从这立场出发，好的校准必须同时尊重**定序性**与**分布形状**。分位数匹配（quantile matching）本来就是为此设计的，但从没在 LLMaJ 上系统 benchmark 过。

#### 方法

SQM 求 LLM 分数分布与人工分数分布之间的**最优传输映射**：g = F_H⁻¹ ∘ F_L。流式版本每来一个锚点就更新运行中的分位数估计。

对比 17 种校准方法，30% held-out，每设置跑 3 次。

#### 结果

| 方法 | MAE ↓ | Wasserstein ↓ | Exact Match ↑ | Overall Rank |
|---|---|---|---|---|
| **SQM** | **0.53（+31.37%）** | **0.26（+27.87%）** | **0.55（+30.86%）** | **1（7W/0L）** |
| Sliced Wasserstein OT | 0.60 | 0.29 | 0.55 | 5 |
| Few-shot exemplar | 0.52 | 0.31 | 0.56 | 3 |
| 交叉熵匹配 | 0.67 | 0.32 | 0.47 | 17 |

#### 最硬的那个数：排序完全不变

> 校准前后，中位数 **Spearman ρ = 0.494、Kendall τb = 0.450，完全一样**（跨方法、跨数据集汇总）。

论文自己解释得很干净：对单调校准器（SQM、等渗、Platt、仿射）这件事**按构造成立**，因为非降映射不能重排样本；对非单调方法也经验成立，说明**事后校准修正的是尺度与分布，不是排序**。这与温度缩放降低校准误差而不改准确率是同一回事。

**两层含义：**

- **好消息**：校准是安全的，不会把判对的判错（排序意义上）。
- **坏消息**：**如果排序本身是坏的，校准一点忙都帮不上。**

#### 校准能救谁（对 5 节点算力最有用的一张表）

| judge 档 | 补掉相对 GPT-5 的原始差距 | 相对 Kimi-K3 |
|---|---|---|
| 中（GPT-OSS-20b） | **83.9%** | 68.8% |
| 中（Qwen3-30b） | **70.1%** | 63.7% |
| 小（Llama3.1-8b） | 34.5% | 41.1% |
| 小（DeepSeek-R1-7b） | 41.7% | 45.5% |
| 小（Llama3.2-1b） | 43.2% | 44.5% |
| 小（Qwen3.5-2b） | **−140%（变差）** | −26.2%（变差） |

**校准能把"中等模型"拉到接近大模型（70–84%），拉不动"小模型"（35–46%）。**

而且不是单调的：Qwen3.5-2b 校准前是**最接近** GPT-5 的小模型（0.082），校准后差距扩大到 0.197（+140%）。作者自己指出它输出解析错误率高达 20%（其他 judge 都在 3% 以下），所以这一条可能是解析失败而非校准本身——**这也是个提醒：judge 的解析失败率要单独监控。**

#### 一个操作上的数

| 项 | 值 |
|---|---|
| 进入 ±5% 收敛带所需数据 | SummEval **第 1 百分位**、UPHELD **第 9 百分位** |
| 单次校准耗时 | **< 10 ms**（MacBook Pro M5） |
| 预测分布变体 | 耗时 **50×**，Wasserstein 只多 0.02 —— **没必要** |

#### 反直觉的发现

> 校准成功最大的影响因素是**具体的数据集**，而不是方法。

这与 PGuard 的"12 个配置块各一套阈值、不可搬迁"是同一个现象：**参数绑定具体配置，不可复用。**

对我们意味着：**多版本回归看板必须按版本/按类目重标校准参数。拿 v1 的阈值跑 v2 的对比，版本间差异里混着参数不匹配的噪声。**

## 三、趋势信号

### 信号一：整个领域在把"信号来源"往模型内部搬

PGuard 读 backbone 的 residual stream，不是外挂一个模型。它的理由写得很直白：

> 外部护栏的判定与 backbone 内部表征脱节。

同一条思路在扩散侧是 ODC：不在文字层改，直接在文本编码器的嵌入上做方向手术。

**两个不同模态、两个不同任务，同时把干预/检测点从"模型外面"搬到"模型里面"。**

对我们的判断：**这不是巧合，是成本与精度双向挤压的必然。** 外部模型要付两次推理，而且判定与内部表征不同步。但搬进去的代价是**可解释性与可审计性下降**——PGuard 用 "per-category threshold" 补回了可配置性，ODC 用 "把方向检索回词集" 补回了可读性。

**结论：往里搬可以，但必须自带一个"翻译回人类可读"的接口，否则线上归因会断。**

### 信号二："参数绑定配置"成了跨论文的共同发现

| 论文 | 绑定的东西 | 不可复用的证据 |
|---|---|---|
| PGuard | 阈值表 | 12 个配置块，阈值 10–97；图-文 24/29 压下限 |
| SQM | 校准参数 | "最大影响因素是数据集" |
| CompoSET | 评测分数 | 同一模型 13.9% vs 49.5%，尺子换了 |
| DeCoRL | 奖励分 | vanilla 7.21 vs 训练过 8.16 |

**四篇独立工作，四个不同的量，同一个结论：数字只在产生它的配置里有效。**

**这对"6 个模型版本迭代看板"是一个结构性警告。** 如果看板上每个版本的阈值/校准/judge 各自不同，那么版本间比较的可信度取决于"这些参数是否等价"。而今天的四篇都在说：**它们不等价。**

### 信号三：评测正在从"打分"转向"控变量"

CompoSET 的全部工作就是**控制配对差异**，把一个"打分 benchmark"变成一个"受控实验"。它证明：不控变量时，22 个模型的分数**全部高于随机看起来还行**；控了变量，**全部低于随机**。

ODC 的 UniDet 反向（0.025 → 0.020）是同一件事的另一面：**单一指标的改善可能以另一个维度退化为代价**，只有分开报才看得见。

DeCoRL 的 Table 3 是第三面：把 RL 的净效果拆成四个指标，才看见"−0.8% PF / +9.0% SR"这个交换比。**如果只报 Overall 8.16，什么都看不见。**

**结论：评测设计的第一性原则正在从"分数高不高"变成"变量控住了没有"。**

### 信号四：误杀治理的重心从"阈值"移向"表示与梯度"

GOAL 说深层表示重叠让阈值失效。PGuard 说图-文输入 24/29 阈值压地板意味着没有可用 operating point。SQM 说校准不改排序。

**三条独立证据，同一个方向：阈值只能在已经足够分开的轴上切。轴没分开，切哪儿都不对。**

**这直接改变了我们"误杀 5.2%"的归因假设。** 之前默认是"阈值偏了"，现在有三个理由怀疑是"排序/表示坏了"。**而这两种情况的处置完全不同**：前者调阈值，后者改训练。

### B. 风险锚点处理启发（双锚点：PORN/VULG 边界 + 政治 L2_30 层级）

**以误杀率 5.2% / 漏过率 3.42% 为运营约束基线。**

#### B1. PORN/VULG 边界：从"两个类"改成"一个方向 + 一个门槛"

PGuard 的阈值表给了一个可操作的形式：**每个子类目一个独立阈值，不共享。** 它的表里同一维度下的子类目阈值差异极大（如 Qwen3-8B lasttok 的 F 维度 Cyber：87 / 62 / 25 / 62 / 10）。

但更值得注意的是 GOAL 给的机制解释：**如果 VULG 与 PORN 的梯度子空间高度重合，那么"在训练时区分它们"从一开始就注定失败。**

所以 PORN/VULG 边界的处理应该分两步，**顺序不能反**：

1. **先测方向是否重合**（半天）。取 PORN 确认样本与 VULG 确认样本，各算逐样本梯度（或退一步，只用最后层特征的类均值差方向），算两个平均方向的余弦相似度。
   - **cos > 0.8** ⇒ 两类在优化方向上不可分。**这时候调阈值、加权、加数据全部无效**，只能改类目定义（把边界样本归到一个"待人工复审"的灰度类）或改判别维度（引入新的判别特征）。
   - **cos < 0.5** ⇒ 方向可分，问题在阈值/数据覆盖，按 A2 逐类目校准。
2. **再决定是"改类目"还是"改阈值"**。这一步的判据是硬数字，不是讨论。

**这与我们 10-30 提的"VULG-HINT-EDGE κ<40 而 PORN 明确类 κ>80 ⇒ 撤回最差类别结论、改成该类目暂不可判"是同一条逻辑的两种验证路径**（一条走标注一致性，一条走表示几何）。**两条都指向同一结论时，才敢改定义。**

#### B2. 政治 L2_30 层级：阈值不能跨层继承

PGuard 的表按 **9 个维度 × 各自子类目** 组织，**每个子类目独立阈值**。它没有做"顶层一个阈值、子层继承"的设计，这是个值得注意的选择：**层级结构是组织方式，不是阈值共享的理由。**

对我们的 L1–L4 递进体系：

| 层 | 阈值该怎么定 | 不能怎么做 |
|---|---|---|
| L1 | 按业务可接受的整体误杀率反推 | 不能用 L1 阈值直接切 L2 |
| L2（含 L2_30 政治/敏感地区） | **每个 L2 独立标定**，尤其 L2_30 内部的地区分组要分开 | 不能把 L2_30 当一个整体 |
| L3/L4 | 只在**样本量够**的格子上单独标定 | 饿格子（样本 < 阈值）不许单独标定，必须向上合并 |

依据：PGuard 的 12 个配置块里，**同一维度在不同配置下阈值从 10 到 97**；SQM 说校准参数不可跨数据集；我们 10-29 的 E4 已经指出"存在饿格子 ⇒ 先补数据再上联合头"。

**一句话：层级是标签体系的结构，不是阈值的继承结构。**

#### B3. 误杀 5.2% / 漏过 3.42% 的联合约束怎么落

单阈值不可能同时压两个指标。PGuard 的两级级联给了工程载体：

```
全流量 ──[一线：宽阈值，低误杀]──┬── 放行
                                └── 标记 ──[二线：严阈值/重模型，低漏过]──┬── 放行
                                                                        └── 处置
```

- **一线**照 5.2% 误杀率标定（宁可多标记）
- **二线**只对一线标出的做严判，照 3.42% 漏过率标定
- **整体漏过** ≈ 一线漏过 × 二线漏过（若两级独立），**整体误杀** ≈ 一线误杀 × (1 + 二线在一线标记集上的误杀率)

**这个结构的关键性质：整体误杀主要由一线决定，整体漏过主要由二线决定。** 于是两个指标可以**分别**优化，不用在同一根阈值上拔河。

**判据**：如果一线标记率 > 30%，两级级联没有意义（二线成本爆掉）——那说明一线排序太差，回到 B1 第 1 步。

### C. 三维评测设计启发（含阈值 operating point 与多版本回归口径）

#### C1. 三维的定名要改

现在的"语义保真 / 安全提升 / 指令遵循"三维，在今天的四篇证据下需要一次精确化：

| 维度 | 现在大概率在测什么 | 应该测什么 | 依据 |
|---|---|---|---|
| 语义保真 | 整图相似度（CLIP/BLIP） | **锚点级覆盖**：主体 / 操作 / 目标区域三个锚点各一个 0/1，缺失记 0 | DeCoRL：整体标量学不到"丢了一个" |
| 安全 | 分类器分（单点） | **分类器分 + 校准后分（SQM）**，两者都报 | SQM：校准改尺度不改排序，两个数才能分开诊断 |
| 指令遵循 | 单向相似度 | **strict 双向**（指令方向 + 反向指令） | CompoSET：单向混着介词先验（on 92.2% vs under 22.3%） |

#### C2. 聚合方式：从加权和改几何平均

延续 10-29 的 E1：$u = v_{sem}^{w_1} \cdot v_{safe}^{w_2} \cdot v_{instr}^{w_3}$。

今天的 DeCoRL **给了这条建议一个实证支撑**：它的奖励是**算术平均**，一个物体丢失在 N=6 时只掉 16.7%，模型可以"5 个极好 + 1 个丢掉"换高分。这正是加权和允许补偿的具体形态。**几何平均或 min 聚合会把这种补偿堵死。**

#### C3. 阈值 operating point 的选择口径

**不能只要一个 operating point，要一条 PR 曲线 + 一个可行域判断。**

对每个叶子类目：

1. 在验证集上扫阈值，画 PR 曲线
2. 标出误杀 = 5.2%、漏过 = 3.42% 两条约束线
3. 判三种情况：

| 情况 | PR 曲线与约束域的关系 | 处置 |
|---|---|---|
| **可行** | 曲线穿过可行域 | 直接取交点（可能是一个区间，取区间中点最稳） |
| **不可行，但曲线"贴边"** | 曲线在可行域外，但距离很近 | 补数据/调类目权重，可能挪进去 |
| **不可行，且曲线整体远离** | 曲线整个在外侧 | **不是阈值问题，是排序问题** → 进标签审计 / 表示诊断 |

**第三种情况是我们现在最可能的状态，也是最容易误判的**——因为看单个阈值不动，很自然会继续调阈值，而实际上调不动。

**PGuard 的图-文 24/29 压地板，就是"第三种情况"的工业实例**：模型把阈值一路压到下限 10%，还是不行。

#### C4. 多版本回归口径：三件事必须固定

今天的证据表明，"版本 A 比版本 B 好"要成立，必须固定三件事：

| 必须固定的 | 为什么 | 依据 |
|---|---|---|
| **评测集（含像素差异分布）** | 尺子换了分数就作废 | CompoSET：13.9% vs 49.5% |
| **judge + 校准参数** | 中模型+校准 ≈ 大模型，混着比等于比校准 | SQM：中模型补 70–84% |
| **阈值来源** | 阈值吸收各配置的分数分布偏移 | PGuard：12 块阈值 10–97 |

**具体落法（6 版本看板改造）：**

1. 看板上**每个版本自带一套"配置指纹"**：评测集版本号 / judge 型号 / 校准参数版本 / 阈值表版本。
2. 跨版本对比时，**先检查指纹是否一致**；不一致的格子标灰，不给结论。
3. 想比"模型进步"，就必须**用同一套指纹重跑**——这意味着每出一个新版本，历史版本要用新指纹**重算一遍**（回归重跑）。
4. 报数时**必须同时报 operating point**。只报"一致率 77.64%"没有意义，要报"在误杀 5.2% 的 operating point 下，一致率 77.64%"。

**这一条是今天最该落地的东西**：不是新方法，是**给现有看板加一列"配置指纹"，并把"跨指纹比较"标为无效**。

### D. 下一步实验建议（六条主线）

#### D1. tag-weighted loss 线

**D1-a（半天，零训练，最该先做）：把加权对象从"标签"换成"方向"。**

依据：GOAL 说有害梯度集中在低秩子空间；如果 PORN/VULG 边界共享子空间，那么给这两个类加权只是**在同一个方向上加大力度**，不会让它们分开。

做法：取 PORN 与 VULG 各 100–200 条确认样本，算两类梯度的主方向（或退一步：最后层特征均值差方向），算余弦相似度。

**判据**：cos > 0.8 ⇒ **tag-weighted 在这两个类上注定无效**，停掉这条线的加权尝试，转去改类目定义或加判别维度；cos < 0.5 ⇒ 加权有空间，继续。

**这条能一次解释"为什么 tag-weighted 上线后 PORN/VULG 边界没改善"**（10-30 G10 的另一个解释路径）。

**D1-b（半天）：因子化前置检查**（沿用 10-29 E4）。统计 L1 × L2_30 × L3 × L4 每格样本数，标出饿格子。存在饿格子 ⇒ 先补数据。顺序反了就是 −0.360。

#### D2. RL 改写线

**D2-a（半天，前置必做）：奖励可学性检查，用 banned prompt count。**

依据：DeCoRL 的 vanilla 奖励 banned 数恒为 0，训练过的才上升。这是一个"奖励有没有被学进去"的直接读数。

做法：在我们现有 RL 改写训练里，每 N 步统计"奖励已饱和（高且组内方差小）的 prompt 数"。

**判据**：长期为 0 ⇒ **奖励不可学，别调 loss/超参，先查奖励定义**。这与 10-30 的 G7（验证奖励能不能作弊）是**两个互补的前置检查**：G7 查"能不能作弊"，D2-a 查"能不能学会"。

**D2-b（半天）：把"用一致性奖励换指令遵循"的价码量出来。**

依据：Kling 保真 4.45→4.38；DeCoRL PF −0.8% / SR +9.0%。**两篇都是别人的任务，我们的价码未知。**

做法：现有 RL 改写模型，报"改写前后"四件事：语义保真（锚点级）、安全分、指令遵循（strict 双向）、改动字符数（Levenshtein）。

**判据**：如果指令遵循掉 > 2%，说明我们的价码比 DeCoRL 贵 2.5 倍以上——**那不是奖励设计的锅，是奖励里根本没有指令遵循项**。

**D2-c（半天）：banned + 改动字符数双监控**（沿用 10-30 G8）。平均改动字符数从 8 字降到 1 字 = 模型在学"不改"，从总奖励看不出来。

#### D3. 标签审计与阈值校准线

**D3-a（半天，最该先做）：逐类目 SQM 探针，把 77.64% 拆成"尺度错"和"排序错"。**

做法：对每个一级类目（样本量够的）单独做 SQM 校准，报校准前后 MAE 降幅。

**判据**：
- 降幅 > 25% ⇒ **尺度问题**，校准即可改善一致率，投入产出比极高
- 降幅 < 10% ⇒ **排序问题**，必须改训练/改定义，校准无效

**这一步把"77.64% 该怎么提升"从讨论变成查表。**

**D3-b（半天）：表示重叠体检（GOAL 的零成本版）。**

做法：取图审模型最后层特征，三类样本（确认有害 / 确认无害 / 被判 PORN 但人工确认无害），算"无害 vs 误杀"的二分类 AUC，逐层重复。

**判据**：AUC ≈ 0.5 ⇒ **表示层就分不开，阈值调整上限为 0**；AUC > 0.7 ⇒ 表示可分，问题在阈值/校准，走 A2。

**D3-c（1 天）：按叶子类目画 PR 曲线 + 可行域判断**（C3 的落地）。输出三分类表：可行 / 贴边 / 远离。**"远离"的类目直接进"暂不可判"清单，不再投人力。**

#### D4. 输出侧图审线

**D4-a（半天）：把双模型 AB 的"一致性"拆成"共同偏置"与"真一致"。**

依据：昨天候选观察里的 VoirDire（2611.00491）——judge 一致性可能来自共同偏置（啰嗦/格式/流畅），必须用受控干预识别 nuisance 方向。**两个模型都同意，可能同意在偏置上。**

做法：构造"只改无关属性、保持目标标签"的干预对（每张原图 3 个变体），看两个图审模型在干预对上的**判定翻转率**。

**判据**：翻转率 > 15% ⇒ **两个模型的一致性不可信**，AB 结论作废，先修稳定性（这与 10-30 的 E2 是同一件事的两个版本，可以合并做）。

**D4-b（半天）：纯图 vs 图+prompt 接口对照**（沿用 10-26 D4）。报 ECE 涨幅。**判据**：纯图接口 ECE 涨 > 15 点 ⇒ 图审在读 prompt 不在读图。

**D4-c：加"两级"结构**（沿 A5）。一线宽、二线严，分别标定，报整体误杀/漏过。**这是唯一能同时满足 5.2% / 3.42% 的结构。**

#### D5. I2I 改写链路（**针对当前分流命中 0/0%**）

**这是本轮最需要给可落地建议的一条。0/0% 不是"效果差"，是"读不出来"——四步把它拆成四个数。**

**D5-a（半小时，最该先做）：量评测集的像素变化中位数。**

依据：CompoSET 的核心发现——配对图 97% 像素变化时，模型只要看出"整张图不一样"就能答对；压到 8%，22 个模型全部低于随机。

做法：对我们的 1,979 条 I2I 有效样本，算 base 图与目标图的像素变化中位数（归一化后）。

**判据表**：

| 像素变化中位数 | 含义 | 处置 |
|---|---|---|
| > 80% | 评测集测不了"方向"，只能测"变没变" | **0/0% 有一半是评测集造成的**，先改造评测集再谈模型 |
| 30–80% | 混杂 | 分层：只在高相似子集（<30%）上算方向命中 |
| < 30% | 评测集是受控的 | 那 0/0% 是真问题，进 D5-b |

**这一步只要半小时，但它决定了后面所有 I2I 实验该不该做。**

**D5-b（半天）：换集合覆盖，把 0/1 变成 K 分之一。**

依据：CompoSET 的"每 base 配 ~22 个 foil"——多 foil 才能把"场景难"与"编辑难"分开。

做法：不要"一条指令一个目标图"的 0/1 判定。改成**一条指令配 K=4~8 个候选目标**（其中 1 个正确、其余是最小改动的单点 foil），报"方向覆盖数"。

**判据**：K=4 时 1 个方向成立就是 25%，**指标立刻从 0/1 变成 0–100%，分辨率恢复**。如果 0/0% 在 K=4 下变成 25%+，那说明原来的 0 是**度量分辨率**造成的，不是能力。

**D5-c（半天）：锚点级覆盖分档**（替代按 Operation 分档）。

依据：DeCoRL 的物体级奖励——缺失记 0，才能定位"丢了哪个"。

做法：把每条 I2I 指令拆成三锚点（主体 / 操作 / 目标区域），改写后在输出图核**锚点保留率**，按"读出几个锚点"分档：

| 读出锚点数 | 归因 |
|---|---|
| 0 个 | **改写把意图抹掉了** → 改写的锅 |
| 部分（1–2 个） | 改写部分保留，下游编辑没执行 → **下游能力的锅** |
| 全部 3 个但图不对 | **下游编辑能力不足**，改写无责 |
| 全部读出且图对但被判不安全 | **风险判定过严**，走阈值线 |

**这一步把 0/0% 从一个数变成四个可归因的数。**

**D5-d（规则实现，半天）：分流输出加"三类理由"。**

依据：现在分流输出是二值（改写 / 不改写）。二值判定在样本级方差极大时天然失败（10-27 的 EditJev 结论）。

做法：分流输出改成带分数 + 理由三分类：

| 理由 | 该不该触发改写 |
|---|---|
| 风险高 | 应该 |
| **我看不懂（歧义/双解读）** | **不应该**——该走澄清路径 |
| 与安全无关 | 不应该 |

**判据**：如果"我看不懂"占比 > 30%，说明 0/0% 的主因是**缺澄清路径**，不是缺改写能力。修改写器没用。

**D5-e（对照，1 天）：hard negative 必须在图像侧构造。**

依据：CompoSET 的 NegCLIP（文本侧硬负样本）7.0% < base 7.8%——**文本侧负样本不迁移**。

做法：如果现在 I2I 改写的 hard negative 是"换词/换语序"造的，全部作废重造。正确造法：**同一指令 + 不同源图**（测指令是否稳定）、**同一源图 + 不同指令**（测改写是否过度）。

#### D6. 多模态视频扩展

**本轮相关供给：0 篇。** 检索路由 `d4_video_generation_safety` 命中 2 篇（均为已收录的旧作），`d5_video_temporal_risk` 命中 1 篇（离题）。

**按任务约定，本轮不给视频扩展建议。** 唯一值得记的一条间接线索：PGuard 的 **prefix stability**（EMA 变体 ~93% 的命中能连续 50 token 超阈值 vs stateless 60–69%）说明——**时序建模不是可选项**。如果后续做 i2v/t2v 的落表，帧级判定必须带时序聚合，不能逐帧独立判。

### E. 权重侧 vs 输入侧：互补关系与各自失效边界

任务要求明确指出二者是**互补而非替代**。今天的四篇给了三条新的边界证据：

| 范式 | 代表 | 今天的新证据 | 失效边界 |
|---|---|---|---|
| **输入侧热更新**（自研路线） | 改写器 / ODC 式嵌入修正 | ODC：嵌入手术 CLIP 只 +1.47，UniDet −20%，天花板很低 | 改不了已经生成出去的图；改不了模型内部的语义绑定错误；单调干预会在另一维度退化 |
| **权重侧擦除**（ESD/UCE/SAFREE 类） | UniForget（10-30 已读） | 单概念 DF 92.7% → 30 概念 37.1%，**随概念数线性崩塌** | 管不住新出现的锚点词；概念一多就崩；FID 崩 |

**新增的第三条边界证据（本轮）**：

GOAL 的"拒绝子空间"与 ODC 的"正交漂移分量"在数学上是**同一个操作**——都是"把梯度/嵌入里某个子空间的分量投影掉"。

- ODC 做在**输入嵌入**上 → 热更新、单样本生效、不可持久
- GOAL 做在**参数梯度**上 → 需要重训、全局生效、持久

**所以二者不是两条路，是同一个算子的两个作用位置。** 这解释了为什么它们互补：

| 需求 | 该在哪一层做 |
|---|---|
| 新锚点词今天出现，今晚要拦 | **输入侧**（权重侧来不及） |
| 某个概念类要长期不再生成 | **权重侧**（输入侧每次都要拦，成本线性叠加） |
| 已经生成出去的图要追溯 | **都不行**，需要输出侧过滤 + 水印溯源 |
| 边界类目（PORN/VULG）分不开 | **两层都无效**，必须改类目定义（见 B1） |

**最后一行是今天最值得写进方案的一条**：如果 PORN/VULG 在表示/梯度上不可分，那么在输入侧改写会把 VULG 改写成"看起来像 PORN 的安全版本"，在权重侧擦除会把两类一起擦掉。**两层都救不了"定义本身有问题"。**
