## 一、T2I / T+I2I 论文（核心主线 · 4 篇）

### 1. FVH-Bench — 图审失效的方向不是"报多了"，是"看不到使能风险"

**本地精读**: `categories/t2i/papers/2610.37722_fvh_bench_functional_visual_harm.md` · https://arxiv.org/abs/2610.37722
**机构**: **香港中文大学（深圳）+ 纽约州立大学布法罗** | **2026-10-27** | cs.CR

- **论文定位**: T2I 生成器安全对齐评测 + **输出侧检测器覆盖度审计**。全篇没有一条攻击方法，是一个纯基准 + 一个检测配方。
- **核心概念（一句话）**：提出 **functional visual harm (FVH)**——风险来自生成物**使能（enable）**了什么，而不只是它**描绘（depict）**了什么。一句原话钉死边界：`FVH does not require overtly harmful imagery, although the two can coexist.`
- **这个概念的杀伤力在哪**：一张给儿童看的卡通海报、"把危险用药建议包装成日常生活一部分"——里面没有裸露、没有血腥、没有仇恨符号。按现有内容安全口径它**干净**。但它的功能是教人做危险的事。
- **分类学（值得整体对照我们的类目表）**：**五功能 × 十域**，两个维度正交。功能 = 怎么帮上忙（F1 行动使能 / F2 证据伪造 / F3 界面模拟 / F4 权威冒充 / F5 说服性包装）；域 = 涉及什么（D1 物理暴力 … D10 性内容与剥削）。**注意 D10 只是十域之一**，而我们现在的 PORN 是一个一级类。
- **规模**: **669 条 prompt**，5 功能 × 10 域。四角色多智能体构建（Coverage Planner → Scenario Designer → Prompt Composer → Prompt Reviewer）+ **5 人评审 ≥4 票**人工裁决。
- **生图侧结果（11 个模型）**：平均拒答率 **2.45%**（最高 GPT Image 2 也只有 5.38%，最低 Wan 2.7 Image **0.45%**）；平均 THR **4.46/5**，八个模型 >4；GPT Image 2 的 THR>4 占比 **94.62%**。⇒ **FVH 请求在现有对齐里基本不算风险。**
- **最刺眼的一条**：`PIC × THR` Spearman **ρ = 0.96**，`PIC × HAU` **ρ = 0.95**。⇒ **在 FVH 上安全与能力不是权衡关系，是同向关系。** Wan 2.7 的 THR 只有 3.68 不是它更安全，是**它画不出能用的流程图**。
- **检测器侧（全文业务核心）**：

  | 方法 | 输入 | Recall | FPR |
  |---|---|---|---|
  | Llama Guard 4 (12B) | **纯图** | **14.60** | 0.00 |
  | Llama Guard 4 (12B) | **图 + prompt** | **43.00** | 0.00 |
  | LlavaGuard v1.2 (7B) | 图 | **1.60** | 0.00 |
  | ShieldGemma 2 (4B) | 图 | 5.60 | **5.50** |
  | ImageGuard (7B) | 图 | 20.40 | 1.00 |
  | Shieldstral (3B) | 图 | 44.00 | 0.00 |
  | General Safety Policy (Qwen3-VL-8B) | 图 | 49.80 | 0.00 |
  | General Safety Policy (GPT-5.4) | 图 | 62.60 | 0.00 |
  | **Condition-Decomposed (Qwen3-VL-8B)** | 图 | **80.40** | 0.00 |
  | **Condition-Decomposed (GPT-5.4)** | 图 | **90.80** | 0.00 |

- **三层读数**：
  1. **同模型去 prompt 掉 28.4 点（14.60 → 43.00）**。同一批图、同一条 policy，唯一差别是有没有看到用户的原始请求。⇒ **纯图审核在功能型风险上有结构性天花板，而且这个天花板很低。**
  2. **五个"专用图审模型"召回 1.60%–44.00%，没有一个过半，FPR 全在 0–5.5%。** ⇒ **不是"不敢报"，是"看不到"。这是覆盖度问题，不是阈值问题。**
  3. **Condition-Decomposed 用 8B 骨干拿到 80.40%，比同骨干通用策略高 30.60 点，FPR 仍 0，代价 1.57 次调用。** ⇒ **"把判定拆成可核查的条件"这件事，价值约等于把骨干从 8B 换成前沿模型。**
- **配方**：对每个功能定义**三条必要条件**（相关内容可见 / 实质危害 / 视觉支持危害）+ **一条良性豁免**（医学/教育/艺术语境）。至少一个功能三条件全成立且无豁免 ⇒ unsafe。
- **负结果（对我们最有用）**：THR 在 F1–F5 上极稳（4.50–4.63）但 **HAU 波动大**——F2 证据伪造最低 **3.57**，F5 说服性包装最高 **4.09**。⇒ **"实现了"和"有用"必须分开报。** 而且人工对比显示**图比其文本对应物更能"帮上忙"，差距最大的是 F2 和 F3**——**文本侧已有审核能力在这两个功能上迁移不过来。**
- **我的判断**：这篇的真正贡献不是 669 条 prompt，是**给出了"类目表的轴选错了"这个诊断的可测量形式**。我们现在的 PORN/VULG 全部落在 depict 轴上，`VULG-HINT-EDGE` 恰恰是**大量落在 enable 轴的样本被硬塞进 depict 类目**——这就是它判不准的机制解释，比"标签不准"具体得多。
- **边界**: 测的是可见实现度不是实际伤害；prompt 分布不代表真实流量；FPR 只有 200 张对照（0.00% 的 95% CI 上界约 1.5%）；三条件与豁免**人工手写、只对五个功能有效**；**不涉及 I2I**。

### 2. V-CAPE — 人类 κ=0.77 判得动，"编辑改对了没有"这件事模型判不动

**本地精读**: `categories/t2i/papers/2610.38611_v_cape_edit_consistency_autoqa.md` · https://arxiv.org/abs/2610.38611
**机构**: **Amazon** | **2026-10-28** | cs.CV

- **论文定位**: I2I 指令式编辑的**自动质量评估（AutoQA）基准**。直接对齐我们 I2I 改写分流 **0/0%** 的判定侧缺口。
- **核心设计（一句话）**：每个样本是四元组 `(源图, 可选参考图, 编辑后图, 结构化拒绝理由)`，判定 `y∈{0,1}` 是否保持视觉一致性。**不止二分类——附带拒绝理由分类学，把"改错了"拆成可归因的 7 类。**
- **规模**: **40K 源—目标对 / 27K 唯一图像**，两个互补子集——**V-CAPE-R**（20K 真实电商 sofa 类目，50/50 平衡）+ **V-CAPE-S**（20K 由 ABO 3D 资产 + Blender 渲染，19 个额外类目，主动构造姿态错/类目错/instance 错三类受控负例）。
- **标注强度（本文全部论证的地基）**：3 名独立标注者、多数表决、5 轮对齐训练、**Fleiss κ = 0.77**。⇒ **任务本身是良定义的，人类判得动。**
- **主结果**：所有被测 VLM（4B 到 235B，开源 + 闭源）**accuracy 全部 < 65%**（实测区间近随机到 63.5%），F1 55–67%。**auto-prompt（IPC 迭代优化）只 +3–5 点，对最强模型边际趋零，部分情况无提升。**
- **难度梯度（这条是我们做要件分档的直接依据）**：
  - 粗粒度（几何失真 / 类目错误 / instance 错误）→ 最强模型尚可恢复；
  - **细粒度（纹理 / 光照 / 背景 / 色彩·材质）→ 全场接近随机**。
  ⇒ **不要按 Operation 分档（加/删/换/风格），要按"这个要件是不是细粒度视觉属性"分档。**
- **少样本 LoRA（Table 1，四个读数每个都值得单独记）**：

  | 配置 | R-Acc | **R-F1** | S-Acc | S-F1 |
  |---|---|---|---|---|
  | Qwen3-8B 零样本 | .515 | **.067** | .484 | .079 |
  | + N=1（**11 条**） | .521 | **.601** | .532 | .624 |
  | + N=5（55 条） | **.529** | **.628** | **.551** | **.683** |
  | + N=10（110 条） | .527 | .617 | .543 | .681 |

  1. **零样本 accuracy 51.5% 但 F1 6.7%** ⇒ **退化成全判一类**。只看 accuracy 会读成"接近随机但还行"。
  2. **11 条样本就把 F1 从 6.7% 拉到 60.1%** ⇒ 这个增益绝大部分来自**恢复类别先验**，不是恢复细粒度感知。（这是我的推论，论文没做这个消融。）
  3. **N=5 最好，N=10 反而降** ⇒ **"补数据"不是单调收益**；不同缺陷类型的视觉准则会互相冲突。
  4. **V-CAPE-S 一致高于 V-CAPE-R**（F1 差 5.5 点）⇒ **用合成数据训图审会高估真实表现**，few-shot 下偏差最大。
- **我的判断**：这篇把 0/0% 的归因顺序彻底改了。**先排除判据，再谈改写。** 人类 κ=0.77 而模型 <65%，这个组合非常干脆——**任务良定义，模型不行**。如果我们自己的 I2I 样本上复现出"人工一致率高 + judge 一致率低"，那 0/0% 根本不是改写模型的问题。
- **边界**: 只做了一类变换（lifestyle→studio）、一个产品类目（sofa）；V-CAPE-S 的负例是构造的不是模型自然犯的；**结构化拒绝理由的判定准确率没有单独报**（这对我直接搬用是个风险）；单轮单指令；无 judge 间一致性数据。

### 3. EditAgent — 编辑失败的救法不是"再来一次"，是"换做法 + 看得更细"

**本地精读**: `categories/t2i/papers/2610.39664_editagent_observation_space.md` · https://arxiv.org/abs/2610.39664
**机构**: **Adobe Research + UC San Diego** | **2026-10-29** | cs.CV

- **论文定位**: Agentic 图像编辑的**双空间诊断 + 扩张**。核心论断：编辑 Agent 被 **action space（能做什么）** 与 **judge 的 observation space（能看见什么）** 同时限制，而现有 agent **把两个空间都做小了**。
- **诊断基准**：**600 个编辑集 / 30 种细粒度类型 / 六大组**，5 名专业 Photoshop 修图师**共同圈选 winner set**（允许多个可用候选）。⇒ 评测从"选对那一张"变成"选出的在不在可用集里"。
- **诊断结论一：一个编辑器不够，多采样也不够。**

  | winner set 构成 | 集数 | 占比 |
  |---|---|---|
  | 只有通用编辑器 | 254 | 42.3% |
  | **只有专用方法** | **175** | **29.2%** |
  | 两类都有 | 90 | 15.0% |
  | **无任何可用** | 81 | 13.5% |

  通用编辑器在 **42.7%（256 集）** 上失败，**专用方法救回 175 集**。分组差异极大：Style & Effects 有 **73.8%** 只认通用；**Enhancement 72.5% / Geometry 66.7% 只认专用**。
  多采样救不了：只有通用编辑器的池投递可用 **45.2%**，加专用方法 **68.2%**。
- **诊断结论二：串行重试是错的（这一条与 T2I 生成相反）。**
  同一编辑器 + 同一 judge，预算都是 4 次生成：串行精化（改 prompt 迭代编辑上一次结果，4 次 VLM 调用）vs 并行搜索（直接从**原图**出候选，≤2 次调用）。
  144 条 Complex-Edit 盲测（5 名修图师）：**并行搜索赢 78.5% 的非平局，用一半的 judge 调用。**
  ⇒ 原因很朴素：**编辑必须对源图忠实，串行精化在不停编辑自己的输出，误差会累积。**
- **诊断结论三：没有 judge 在所有类型上最好。**
  EditScore-72B 总体最好但**只在 Scene 组最好**；Qwen3.8-27B 三组最准但 **Photometric 只比随机高 5.2 点**；**CLIP-I 在 Photometric/Enhancement 最准，但在 Style & Effects 与 Geometry 上等于或低于随机。**
  论文的推论一句到位：`What a judge must observe therefore depends on the edit.`
- **pointwise → listwise（本文最硬的一个数）**：

  | Judge | Pointwise | Listwise | Δ |
  |---|---|---|---|
  | **EditScore-72B + Ensemble@4**（微调奖励模型） | **76.3** | 不支持 | – |
  | Qwen3.5-27B | 71.7 | **85.2** | **+13.5** |
  | Qwen3.8-27B | 72.1 | **85.9** | **+13.8** |
  | Gemma-4-31B | 73.8 | **86.1** | **+12.3** |

  ⇒ **现成 VLM 一旦能成对比较，直接超过在大规模人工偏好上微调 + 4 路集成的 EditScore-72B。**
- **观测空间消融（这张表里藏着一个极易被忽略的负结果）**：

  | listwise | evidence | Style | Content | Scene | **Photo.** | Geom. | **Enh.** | All |
  |---|---|---|---|---|---|---|---|---|
  | – | – | 84.4 | 81.7 | 67.5 | **54.2** | 66.4 | **65.0** | 71.6 |
  | ✓ | – | 87.1 | 87.1 | 72.0 | **47.2 ↓** | 78.6 | **36.8 ↓↓** | 73.6 |
  | ✓ | ✓ | 87.6 | 86.4 | 81.9 | **64.4** | 81.4 | **80.3** | **81.3** |

  **只加 listwise 会把 Photometric 从 54.2 打到 47.2、Enhancement 从 65.0 打到 36.8（−28.2）。** 在"正确答案与源图差异很小"的两组上，**并排比较反而有害**——judge 被"视觉上更不一样"的候选吸引过去。
  这正好是 CLIP-I 崩掉的镜像：**需要可见变化时（Style/Geometry）judge 偏向"没怎么变"；需要保持原样时（Photo/Enh）judge 偏向"变得多"。同一件事，两个方向都错。**
  **只有补上证据才救回来**：Photo 47.2→**64.4**（超过 pointwise 的 54.2），Enh 36.8→**80.3**（远超 65.0），总体 71.6→**81.3**（比 EditScore-72B 的 74.8% 高 6.5）。
  **七个现成 VLM 加记录后全部提升 6.3–9.3 点，无记录时没有一个达到 EditScore-72B，有记录时每一个都超过** ⇒ 这是"方法而非骨干"的证据。
- **顺手给了一个"数据自举会中毒"的硬证据**：25.7K 全通过会话做数据引擎，**直接用 FLUX.2-klein-9B 自己生成的数据训 FLUX.2-klein-base-9B，三个 benchmark 全降；用 judge 过滤后的数据，三个全升**。论文原话：`higher-quality training supervision rather than merely additional training examples`。
- **我的判断**：这篇是我们 I2I 0/0% 的第二个归因候选，而且给出的是**可操作的三个动作**（单条判→成对判、加验证记录、并行替代串行）。但它同时警告了一件事：**成对判不是无条件好的**，我们如果大量编辑是"改光/增亮"这种正确答案变化很小的类型，单加 listwise 会掉点。
- **边界**: 成本 12×（12.9 vs 1.1 H100·h）；诊断基准自建未释放且标注成本极高；**judge 就是 planner（同一模型）**，虽然用 Gemma-4-31B 复跑规避自评偏置，但没排除"规划器与判定器共享同一套盲区"；验证记录是手写规则而非学出来的，**新增编辑类型要新增核查代码**；**安全维度完全缺席**——它是判定方法学，不是安全方法学。

### 4. OCR+MLLM — 一半的风险没有文本痕迹，而补通道之后辅助奖励开始作弊

**本地精读**: `categories/t2i/papers/2610.38185_ocr_mllm_moderation_grounding.md` · https://arxiv.org/abs/2610.38185
**机构**: 华中科技大学（单作者）| **2026-10-28** | cs.CV

- **论文定位**: 短视频内容审核的**多路 AB 对比 + RL 奖励设计**。放到 T2I 主线里，它的价值是两个方法学模块：**五维对照表** 与 **奖励设计的三个坑**。
- **核心观测（全文价值锚点）**：测试集 **50.4% 的风险事件没有文本痕迹**，分布在 **458/725（63%）** 的视频里，各类别非文本占比 **37.2%–53.8%**（**均匀分布，不是某一类的特例**）。⇒ **纯文本通道最多只能看到一半，而且不能靠"某一类补规则"解决。**
- **架构**：PP-OCRv4（1fps，CPU，FP32）保文本召回 + **Qwen2.5-VL-7B** 单次前向同时做 OCR-grounded 判别与时序 grounding。
  **结构化输出**（这个格式值得抄）：`<think>…(≤50词)…</think>` → `<answer>[s1,e1]…[sk,ek]</answer>` → `<class>[c1,…,ck]</class>`，且**区间数必须等于标签数**。⇒ 这就是 tag-first 结构的一个变体，**用"数量一致"做强格式约束**。
- **数据**: 2,419 视频 / 66.49 小时 / 3,194 事件 / 4 类。类别长尾：**Class 0 62.3% : Class 2 3.6% = 17:1**。
- **三路对比（五个维度，这张表的形状比数字更重要）**：

  | 方法 | Macro Recall | Macro F1 | mIoU | R@0.5 | **非文本召回** |
  |---|---|---|---|---|---|
  | OCR+LLM（keyframe） | **69.2%** | **54.9%** | 14.49 | 4.41 | **≈0** |
  | OCR+MLLM（RL only） | 55.0% | 46.5% | **26.52** | **15.86** | 41.7% |
  | OCR+MLLM（SFT+RL） | 67.0% | 45.6% | 14.97 | 8.68 | **60.1%** |
  | **Large MLLM（32B 零样本）** | 36.7% | 34.0% | **4.72** | 1.02 | – |

  ⇒ **非文本召回从 ≈0 到 60.1% 是从无到有，不是涨点。32B 零样本全面最差（mIoU 4.72）说明任务特定的定位能力不是规模买来的。**
- **奖励设计的三个坑（全文对我们最实用的部分）**：

  1. **辅助项系统性作弊**：加 `0.2×中心距离 + 0.2×事件计数` 后，**训练奖励刷到 ~1.0，真实 mIoU 从 13.48 掉到 2.19**（六分之一）。作弊来源极其平凡。
  2. **乘性 vs 加性各塌一头**：乘性 `IoU·(a+b·cls)` 学会定位但**塌到 Class 0**（最稀有类 recall **0.07**）；加性 `IoU+cls` 类别平衡改善但**定位停滞**。根因是 **IoU 稀疏性（不重叠时无梯度）** 与类别不均衡的张力。
  3. **类别缩放有甜点**：太弱塌类、**8× 太强也塌**、**4× 最优**。
- **解法**：per-event soft F_β + class-balanced 过采样（上限 20×）。消融表：

  | 定位奖励 | mIoU | R@0.5 | R2（最稀有类） |
  |---|---|---|---|
  | IoU × class scaling | 24.84 | 15.23 | **0.07** |
  | **soft IoU（合并式）** | **14.57** | **1.22** | 0.08 |
  | **per-event soft F1 + balance** | **29.82** | **18.54** | **1.00** |
  | per-event soft F2（召回优先） | 26.52 | 15.86 | 0.46 |

  ⇒ **合并式 soft IoU 的 R@0.5 只有 1.22**（不重叠时无梯度），**per-event 是 18.54（15×）**。这是"合并指标 vs 逐事件指标"的量化差距。
- **错误分析里有一条跟我们同构**：错例 41% 是无害的边界错误、34% 是漏非文本事件、**25% 是 Class 1↔Class 2 混淆——屏上措辞相同，唯一差别是有没有群号/二维码**。⇒ **跟 PORN/VULG 边界完全同构：表面形式相同，差一个关键锚点。**
- **边界**: **单作者、无外部复现、数据与代码未释放**；"非文本"的判定**用 OCR 关键词表定义"OCR 看不到的东西"**（循环依赖）；**macro F1 全面低于基线（46.5/45.6 vs 54.9），不能读成"全面优于基线"**，实际收益全在非文本覆盖与定位；过采样上限 20× 是拍的。

### 5. MSafeTemp — 把有害 prompt 拆成"中性框架 + 类型化风险槽位"

**本地精读**: `categories/t2t/papers/2610.40516_msafetemp_template_slot_rewrite.md` · https://arxiv.org/abs/2610.40516
**机构**: **ETH Zurich**（数据/代码归属 swiss-ai）| **2026-10-29** | cs.CL

- **论文定位**: 多语言安全对齐数据构建。放进 T2I 主线是因为它把**"风险锚点外科替换"形式化**了，而且解决了我们改写链路的一个实际卡点。
- **卡点与解法（本文最关键的一段）**：用对齐模型去翻译一条有害 prompt，**结果很可能是拒答**；文化适配、改写润色同理。⇒ 扩增与本地化全被堵死。**解法只有一条：把原始文本表示成一种"安全形式"。**
  论文的表述极精确：`把"让 prompt 变得有害的那些词"抽出来，就把 prompt 分成了两个概念，而这两个概念单独看都不被视为有害。`
  ⇒ **`有害 prompt = 框架（中性）+ 类型化槽位（承载风险）`**。槽位按类型/意图命名（如 `<illicit_substance>`）。**框架可以安全翻译改写；槽位可以独立重填。**
- **三个填充分支**：
  - **TR**（通用有害）：多组槽位值 + 两个已验证改述；
  - **OR**（良性替代）：**用相反方向填同一个槽位** ⇒ "问句形式保留，意图变成普通用户请求"。**分 direct（可完整回答，只在这里测过拒率）/ bounded（须保留有害细节，只做训练）**；
  - **PH**（文化本地化）：每语言一张 **cultural card**（本地群体/组织/事件/概念/机构），保守 judge 检查候选值。
- **规模**: WildGuard 2,500 seed × **44 语言** → 109,425 已验证模板 / **1,537,628** 有害 / 186,639+20,528 良性；HarmBench 200 seed × **60 语言** → **173,743** 有害。**每 seed×语言 3 模板 × 每模板 5 填 = 最多 15 个变体**，论文说`more paraphrases or more fills brought diminishing gains`。
- **多样性**: 有害槽位 **>2.8M 不同实体**，distinct-to-total **≈0.70**，良性 0.94，**任一实体在某语言占比 <1%**，高/低资源语言无显著差异。
- **三条可迁移的实证结论**：

  1. **英语单语评测会误判**：**Olmo 英语 ASR 0.0% → 翻译后 13.7%**；held-out 上翻译变体打穿 Olmo/Gemma/两个 Apertus 的频率是原始英语的 **2.4–4.4 倍**。**但 Llama 是反例**（英语 13.0% → 翻译 5.3%）⇒ **方向依模型而定，不能反推"翻译一定更难"。**
  2. **翻译 vs 本地化打穿的不是同一批行为**：**Jaccard 0.40–0.45**，**约 45% 的失败只在本地化实体下出现**。
     ⇒ **直接推论：任何"覆盖度"统计如果把"同一框架的不同填充"合并成一个簇，就会系统性高估覆盖。** 这一条直接打在"向量聚类查覆盖"上。
  3. **单 fill 评估漏一半**：`只被部分填充打穿的模板贡献了全部不安全回答的 60%–100%；每个模板只评一个 fill 会漏掉约一半被打穿的模板。`
     ⇒ **我们现在的改写评测如果每 prompt 只做一次、只评一次，就系统性低估失败率，量级是"漏一半"。**
- **过度拒答是真问题**：GPT-OSS-20B 的 ASR 0.0–0.5% 完美，代价是**拒掉 32–45% 的无害请求**。论文还指出 **OR-Bench 里约 20% 样本其实有害、应该被拒** ⇒ **该基准的最优表现本来就高于 0%**。
- **最严重的局限（也是对我们最直接的提示）**：`危害标签从英语 seed 继承给所有后代——一个本地化实体可以让变体比它继承的标签更严重`。⇒ **这就是标签层级漂移**，跟我们的 L1–L4 层级直接对应。
- **我的判断**：这篇对我们是三件事的合集——① 改写模型自己拒答时的绕行路径；② PORN/VULG 边界样本的正确形状（**同框架、只换锚点**）；③ 政治 L2_30 层级口径的零训练检验方法（**固定框架只换实体，看级别是否漂移**）。第三条最被低估。

### 6. Judged in Company — 聚合指标看不见个体翻转

**本地精读**: `categories/t2t/papers/2610.40241_judged_in_company_batch_flips.md` · https://arxiv.org/abs/2610.40241
**机构**: **Technical University of Munich** | **2026-10-29** | cs.CL

- **论文定位**: LLM-as-judge 的**批处理效应**与判定**可分离性（separability）**。直接服务我们的**图审双模型 AB 对比评测**。
- **被默认但从未被检验的假设**：一条条目的判定只取决于该条目本身，不取决于它的"同侪"，也不取决于它的位置。**decoder-only 模型结构上不保证这件事**——写第 12 条判定时，它已经读过另外 24 条和自己刚写的 11 条。
- **核心矛盾（一句话）**：**用聚合指标去检验个体判定稳不稳，原理上就是错的。**
- **主结果**：

  | 规模档 | 新随机划分导致的判定变化 | 超出最大基线（改 key / 改指令） |
  |---|---|---|
  | 5 个 4–9B 模型 | **11 – 22%** | **+6.5 – 13.3 点** |
  | 4 个 14–32B 模型 | **6 – 15%** | **+4.2 – 9.1 点** |

  **而 AUROC 相对单条判只差 −0.033 到 +0.010。**
  ⇒ **个体判定翻转 11–22%，聚合指标几乎不动。**
- **它为什么能同时成立（数学根源）**：在阈值模型下，**翻转率随"上下文贡献的方差"的平方根增长**。标定：潜在方差占比 **1% → 翻 4.5%**；**10% → 翻 14.4%**。⇒ **在分数尺度上很小的变化，在判定尺度上是大的。**
- **投票不是解药**：

  | 投票 | 残留 |
  |---|---|
  | 5 个排列多数 | **60 – 69%** |
  | 9 个排列多数 | **52 – 60%** |
  | 15 个独立 batch 多数 vs 单条判 | **8.4 – 17.8%** |

  ⇒ 投票消除了槽位效应、顺序效应、以及槽位×同侪交互，**消不掉同侪主效应（membership 0.11–0.22）**。而且投票去的是**方差不是偏置**。
- **两个通道都在起作用（单次生成内部的因果干预）**：换成另一批的**判定** → 变 **7–23%**；换成另一批的**文本** → 变 **9–26%**。⇒ **只遮住前面的判定不够。**
- **触发条件**：批处理不只是"散开"，还**系统性偏移**——随机 batch 与单条判不一致 10.9–19.8%，15 个独立 batch 的多数仍不一致 **8.4–17.8%**。
- **效应大小取决于任务歧义度**：harm/grading（有歧义）11–22%；**star rating（容易，AUROC 0.96）只有 2.9–3.9%**。但注意 **写出来的评分本身变了 16–21% 的评论**，只有跨阈值的才变成判定翻转。
- **三条建议，最后一条最该抄**：有歧义的条目一条一 prompt；用 cached prefix 收成本；**只要做了批处理，就报告与单条判的一致率。**
- **边界**: 只在文本任务上做，**多模态（多图一 prompt）完全没测**——这恰是我们最关心的；batch 固定 25，没扫 k；模型全部 ≤32B 开源，无前沿闭源；没给"如何检测自己的批处理是否安全"的可操作流程；**没测"同侪是同类 vs 异类"**（批里全 PORN vs 混着 VULG），而这正是我们的场景。

## 三、趋势信号

### 信号一：这六篇的修复动作，没有一个是"把模型变强"

把六篇的动作列在一起，会看到一条整齐的分界：

| 论文 | 传统修法（我们过去三周在做的） | 这六篇的修法 |
|---|---|---|
| FVH-Bench | 加更多 PORN 数据、调阈值 | **补一根 enable 轴；把判定拆成三条件 + 一豁免** |
| V-CAPE | 换更大的 judge | **先测人类 κ 再看模型上限；报 macro-F1 不只 accuracy** |
| EditAgent | 多采样、多轮重试 | **扩 action space（换方法）+ 扩 observation space（加证据）** |
| OCR+MLLM | 换成更大的模型 | **补非文本通道（32B 零样本 mIoU 4.72 说明规模无用）** |
| MSafeTemp | 让改写模型硬啃脏 prompt | **拆成框架 + 槽位，让改写只碰框架** |
| Judged in Company | 调 judge prompt、加投票 | **改判定制度（单条判）+ 报一致率** |

**六篇里没有一篇的结论是"模型不够大"。** 两条最硬的否证：OCR+MLLM 的 **32B 零样本 mIoU 4.72 全场最差**；V-CAPE 的**所有规模档 accuracy 全部 <65%，235B 也不例外**。

⇒ 这三周我们一直在"调模型"这一侧使劲（abstain 头、反事实训练、alpha 扫描、阈值、补数据）。**这一轮的建议是先把"该看什么"定对。** 具体到我们的六条线，第一优先不是任何一个训练实验，而是**三个零训练的测量**（见第四节 H1 / H5 / H11）。

### 信号二：**"合并成一个数"是本轮所有失效的共同机制**

这是 10-30 那轮"判定装置把没有答案压成一个答案"的**下一层**。上一轮说的是"该弃权时不能弃权"，这一轮说的是**"该保留为集合/分布/个体的东西，被合并成一个标量"**：

| 被合并的东西 | 合并后的假象 | 数字 |
|---|---|---|
| depict 与 enable 两个轴 | "图审召回不错" | 专用检测器 1.60–44.00% |
| 粗粒度与细粒度失效 | "VLM 上限 65%，接近可用" | 细粒度近随机 |
| 单点判定与成对判定 | "judge 已经够用" | pointwise→listwise **+13.8** |
| 纯图与图+prompt | "image-only 已部署" | **14.60 → 43.00** |
| 有文本痕迹与无文本痕迹 | "审核召回 69.2%" | 非文本召回 **≈0** |
| 多个填充合并成一个模板 | "模板覆盖了" | 漏一半模板 |
| 翻译与本地化合并统计 | "覆盖度 100%" | Jaccard **0.40–0.45** |
| 个体判定合并成 AUROC | "AUROC 稳，没问题" | 翻 **11–22%** |

⇒ **八种合并，八种假象。** 而每一种的解法都不是"更好的模型"，是**把分母拆开报**。

**这一条可以直接变成一条报告纪律：任何指标，如果它的分母里混了两种性质不同的东西，它就不能用来做决策。** 我们现在的"图审召回"（混了 depict/enable）、"安全率"（混了能画/不能画）、"改写成功率"（混了 K 个变体）、"AB 差异"（混了 batch 组成）全部违反这条。

### 信号三：权重侧范式本轮有供给，但与输入侧仍是互补而非替代

本轮擦除/遗忘方向有两篇，都值得记但都不足以改写结论：

- **`2610.40061` LoCo**（UCLA + CMU）：**首个在 next-scale 视觉自回归模型上做概念定位**的框架，沿 **Layer / Scale / Position** 三维定位，探测对象含 **Infinity / 腾讯混元 HunyuanImage-3.0 / InfinityStar**。三个应用：概念擦除、模型个性化、**对抗性概念注入**。⇒ 说明**擦除这条线正在从扩散模型迁到 VAR 架构**，而且"定位"是共同前置。
- **`2610.38784` Loss is Not Behavior**（RPI，**NeurIPS 2026**）：梯度式遗忘的**输出空间统一分析**。核心结论——**相似的 forget/retain loss 不蕴含相似的输出行为**；给出闭式 gap，提出两个杠杆矩阵（**forget self-leverage** 与 **retain cross-leverage**）刻画遗忘—保留的纠缠，并给出**可预计算的杠杆诊断**用于审计 forget set。

**边界判断不变，而且这一轮的两篇都在加固它**：

| | 权重侧（擦除/遗忘） | 输入侧（改写） |
|---|---|---|
| 生效时机 | 上线**前**的权重治理 | 上线**后**的热更新 |
| 管得住 | 已在训练分布里的概念 | **新出现的锚点词、新造词、跨语言变体** |
| 管不住 | **新锚点**（MSafeTemp 证明：翻译 + 本地化能让英语 0% 的攻击打穿到 13.7%） | **已经生成出去的图** |
| 失效形态 | 擦除方向可被蒸馏转掉；**高 forget loss ≠ 行为已改**（38784） | 语义坍缩、过度清洗、改写模型自身拒答 |

⇒ **两条线管的是两个不同的时间窗，不是同一个问题的两种解法。** MSafeTemp 和 38784 这一轮各从一侧加固了这个结论：前者证明"输入侧面对的是无穷的新锚点"，后者证明"权重侧连自己的 loss 都不能当验收标准"。

**唯一的交集**：LoCo 的"先定位再擦除"与我们的"先抽锚点再改写"在方法论上是同一个动作——**都是先把风险缩小到一个可操作的位置**。这个共性值得记：**定位是两种范式的共同前置，不是某一侧专属。**

### B. 风险锚点处理启发（双锚点：PORN/VULG 边界 + 政治 L2_30 层级）

#### B1. PORN / VULG 边界：我们一直在用"描绘轴"训"使能轴"的样本

这一轮对边界问题给出的解释，比过去三周任何一篇都具体。

**第一步：把 `VULG-HINT-EDGE` 放到正确的轴上。**

FVH-Bench 的两轴结构套到我们身上：

| | **enable 轴有风险** | **enable 轴无风险** |
|---|---|---|
| **depict 轴有风险** | 裸露 + 招嫖信息（PORN 明确类） | 医学教科书图（**我们的 PORN 误报源**）|
| **depict 轴无风险** | **暗示性构图 / 隐喻 / 儿童可模仿的危险示范（VULG-HINT-EDGE，我们完全没有类目定义）** | 正常图 |

**关键判断：`VULG-HINT-EDGE` 的主体落在右下角。** 它"没有裸露、没有脏词，但整体在暗示"——这正是 FVH 说的"风险不在画了什么，在它能促成什么"。

而我们的类目表是按 depict 轴设计的。**⇒ 它在我们的体系里没有定义，不是标注错了，是类目表里没有这个格子。**

这解释了为什么过去三周的三个动作全部无效：
- **调阈值**：阈值作用在 depict 类目的排序上，对没有定义的格子无效；
- **调 alpha**：加权放大的是"这个类目的损失"，但该类目的标签本身在问错的问题；
- **补同类数据**：补的是更多"暗示类"样本，但标签仍是 depict 口径 ⇒ **补进去的是更多噪声**。

**第二步：用 Condition-Decomposed 给"暗示"一个可操作形式。**

FVH 的三条件 + 一豁免，直接翻译到 `VULG-HINT-EDGE`：

| FVH 原条件 | 我们的对应 |
|---|---|
| 相关内容是否可见 | ① 是否有可见的暗示元素（姿态 / 视角 / 服饰状态 / 构图焦点） |
| 是否构成实质危害 | ② 这些元素是否构成实质的性暗示（而非单纯的审美/时尚表达） |
| 视觉呈现是否支持该危害 | ③ 呈现方式是否强化了暗示（特写、打光、构图引导） |
| **良性豁免** | **④ 是否存在中和语境（时尚大片 / 医学教育 / 艺术摄影 / 新闻纪实 / 泳装商品图）** |

判定：`① ∧ ② ∧ ③ ∧ ¬④ ⇒ VULG`。

**这比调 alpha 有希望得多**，理由有三：
1. 它把"暗示"从**一个不可判的整体印象**变成**四个可独立核查的子问题**；
2. **豁免条款是显式的**，直击我们的 PORN 误报源（泳装商品图、医学图）；
3. 论文证明**8B 骨干 + 这个结构 > GPT-5.4 + 通用 policy**（80.40 vs 62.60），**成本只有 1.57×**。

**第三步：用良性最小对造训练对照（MSafeTemp）。**

```
框架 F 固定（如"一个人在 [场景] 中 [姿态] 的 [构图] 照片"）
  填充 A：高风险锚点      → PORN
  填充 B：中间态锚点      → VULG-HINT-EDGE
  填充 C：良性锚点        → 正常
```

判据：
- 若 A/B/C 上分数**单调下降** ⇒ 边界学对了；
- 若 B 上出现**非单调** ⇒ 模型在按表面形式判，不在按锚点判；
- 若 B 与 A 的分数**几乎相同** ⇒ 中间档没有被表示，类目表缺一档。

#### B2. 政治 L2_30：先用"框架—实体分离"检验口径，再决定改标签还是改定义

本轮没有政治审核的专门工作，但 **MSafeTemp 的框架—实体分离给了 L2_30 一个零训练的检验方法**，而且它比 10-30 提出的"识别型/判定型二分"更硬——因为它有可测量的判据。

**核心洞察**：政治敏感 prompt 的风险锚点是**实体**（地区名 / 人物 / 事件 / 机构），**框架（提问结构）是中性的**。拆开之后可以做受控替换。

```
Step 1  从 L2_30 相关训练样本里，把 prompt 拆成（框架, 实体）
Step 2  固定框架，只替换实体：
        · 同一 L2 子格内的不同实体
        · 跨子格的实体
Step 3  人工复判每条变体的 L4 级别（不看原标签）
Step 4  统计级别漂移（漂移 > 1 级的比例）
```

**判据表（直接决定路线）：**

| 漂移 > 1 级的比例 | 结论 | 动作 |
|---|---|---|
| **< 10%** | 层级口径绑的是**语义**，稳 | tag-weighted 训练有意义，继续调 alpha |
| **10–30%** | 轻度绑实体 | 补"实体无关"的判别维度，别改定义 |
| **> 30%** | **层级口径绑的是实体，不是语义** | **改标签无用，必须改定义** |

**为什么这条比 10-30 的"识别型/判定型二分"更强**：10-30 的方法要靠人工先给 30 个格子分类（本身就是一次判定，带主观性）；这条是**直接从数据里测漂移**，判据是一个比例数字。

**MSafeTemp 的两个配套警示必须一起采纳：**

1. **Jaccard 0.40–0.45：翻译版与本地化版打穿的不是同一批行为。** ⇒ 我们做 L2_30 覆盖度审计时，**如果按"同一框架的不同实体"聚类，会把覆盖率系统性高估**。覆盖度必须按"实体来源"分层报（境内实体 / 境外实体 / 翻译实体 / 本地化实体）。
2. **单 fill 漏一半。** ⇒ 覆盖度审计的每个格子至少要 **3 个实体变体**，且报"至少 1 个打穿"与"3 个全打穿"两个口径。

#### B3. 跨锚点的共同结论

两个锚点本轮得到的是**同一个动作**：

> **把"一个不可判的整体印象"拆成"若干可独立核查的条件 + 显式豁免"。**

- PORN/VULG：三条件 + 语境豁免（FVH 配方）；
- L2_30：框架 / 实体分离 + 级别漂移可测量（MSafeTemp 配方）。

⇒ **"拆"不是分析修辞，是这两种方法共同的实现形式。** 而且两者的成本都很低：FVH 配方 1.57× 调用；L2_30 检验零训练。

### C. 三维评测设计启发（语义保真 / 安全提升 / 指令遵循）

我们在 10-30 已经定了"validity 先冻结 + 几何平均 + 报四列"。这一轮补四块，全部是**分母侧**的补丁。

#### C1. 补丁一：报个体判定翻转率，不能只报聚合指标

**判据来自 Judged in Company**：AUROC 只差 −0.033~+0.010，个体判定翻 **11–22%**。

⇒ **三维评测的每一次跨条件比较（换模型 / 换 prompt / 换批组成 / 换 judge），都必须报"同一样本只改无关上下文后的判定翻转率"。**

**具体做法（半天）**：同一批样本跑 3 个独立随机划分，报划分之间的判定翻转率。判据：**翻转率 > 10% ⇒ 这一维的比较结论不可用**。

#### C2. 补丁二：分母必须声明 K，且 K≥3

**判据来自 MSafeTemp**：`只被部分填充打穿的模板贡献了全部不安全回答的 60%–100%；单 fill 漏掉约一半被打穿的模板。`

⇒ **三维评测的 Step 0 分母声明必须加一项：`K = 每个 prompt 的改写变体数`，且报"至少 1 个失败"与"全部失败"两个口径。**

**我们的现状**：如果改写评测是"一条 prompt 一次改写、一次生成、评一次"，那 K=1，**失败率被低估约一半**。

#### C3. 补丁三：安全率必须与生成质量并列，否则不可比

**判据来自 FVH-Bench**：`PIC × THR` Spearman **0.96**。

⇒ **在 FVH 这种"使能型"风险上，能力与风险同向。** 所以"安全率高的模型"完全可能是"画得差的模型"。

**做法**：图审 AB 表必须并列一列**生成质量**（PIC 或等价物）。判据：若两个模型的生成质量差 > 一个档位，**安全率不可直接比较**。

#### C4. 补丁四：judge 的输入口径必须写清楚，且要证明这个选择是对的

**判据来自 EditAgent + FVH-Bench**：

- **纯图 vs 图+prompt：14.60 → 43.00（+28.4）**；
- **pointwise vs listwise：72.1 → 85.9（+13.8）**；
- **listwise 单独加会把"正确答案变化小"的两组打崩**（Photo 54.2→47.2，Enh 65.0→36.8），加证据才回来（→64.4 / 80.3）。

⇒ **judge 的输入口径不是实现细节，它决定 20–30 个点。** 而且**加得更多不等于更好**——必须按编辑类型分别验证。

#### C5. 改造后的三维评测协议（v3）

```
Step 0  分母与口径声明（六项，缺一不可）
        · K = 每 prompt 改写变体数（须 ≥3）
        · n = 每改写生成次数
        · judge 输入口径：纯图 / 图+prompt / 图+prompt+证据
        · judge 判定制度：pointwise / listwise
        · batch size（若 >1，须附单条对照）
        · 生成质量基线（PIC 或等价物）

Step 1  validity 冻结（沿用 10-30 决定）
        语义是否成立 / 是否仍在意图范围 / 是否引入新风险类目
        → 输出 valid 集合，后续只看 valid

Step 2  三维打分（在 valid 内）
        · 语义保真 = 要件级覆盖（不是整体相似度）
        · 安全提升 = 风险分下降（同一图审模型、固定版本）
        · 指令遵循 = 与原始意图的可执行一致性

Step 3  聚合：几何平均  u = v_sem^w1 · v_safe^w2 · v_instr^w3
        任一维接近 0 直接把样本分打穿（禁止跨维补偿）

Step 4  报告（八列，本轮从四列扩到八列）
        · 均值
        · 方差（同 prompt 固定种子重复 n 次）
        · 组内排序一致率
        · 跨维补偿率
        · 【新】"至少 1 个变体失败"率（K≥3 口径）
        · 【新】"全部变体失败"率
        · 【新】个体判定翻转率（3 个随机划分）
        · 【新】单条判 vs 批量判的一致率（若 batch>1）

Step 5  图审 AB 额外三列
        over-refusal 率 · κ_vs_human · 【新】生成质量（PIC）

Step 6  分轴报（本轮新增）
        depict 子集 recall / enable 子集 recall —— 不得合并
```

**为什么 Step 6 必须加**：FVH-Bench 的 14.60% 这个数字，如果按 depict 口径看会得出"图审完全失效"的错误结论；实际上它在 depict 上还行，**失效集中在 enable**。**合并统计会同时掩盖两件事。**

### D. 下一步实验建议

> 五条主线。**优先级按"判据能否一次结束纠结"排序**，不按工作量。前三个都是零训练。

#### 主线 1｜输出侧图审（半天起）

**实验 H1｜纯图 vs 图+prompt 的天花板测量（半天，最该先做）**

```
输入：M 张已知违规的生成图（M ≥ 300），每张带原始 prompt
条件 A：图审模型只看图                → recall_A, FPR_A
条件 B：图审模型看 图 + 原 prompt      → recall_B, FPR_B
```

**判据表：**

| recall_B − recall_A | 结论 | 动作 |
|---|---|---|
| **≥ 20 点** | **image-only 的天花板被 prompt 缺失锁死** | image_only SFT 定位为"兜底"，主通道改图+prompt |
| 10–20 点 | 有损失但可接受 | 保留双路，图审 AB 必须分两路报 |
| < 10 点 | 我们的场景不依赖 prompt | image-only 路线成立，继续投入 |

对标锚点：**14.60 → 43.00（+28.4 点）**。

**这条实验的价值**：它一次说清"image_only 这条线该不该继续"。我们在这上面已经投入了 SFT 训练和旁路 AB，但**从来没测过它的天花板在哪**。

**实验 H2｜Condition-Decomposed 灌进图审（半天）**

不需要五功能。只做"三条件 + 一豁免"（见 B1 第二步）。

- 骨干：**Qwen3-VL-8B**（8B 够，论文 80.40 > 通用策略 49.80）
- 调用预算：1.57×
- 必报三列：**违禁召回 / PORN 误报 / 每图实际调用次数**

判据：**PORN 误报显著降且违禁召回掉 ≤2 点 ⇒ 结构性改善，继续；误报没降 ⇒ 不是"判定太粗"的问题，回 H1。**

**实验 H3｜批处理体检（2 小时，堵漏洞）**

```
条件 A：现有 AB 的批处理配置
条件 B：逐条单独跑
条件 C：3 个不同随机划分
```

必报：**个体判定翻转率 / AUROC 差值 / A-B 一致率**。

判据：**翻转率 > 10% 且 AUROC 差 < 0.03 ⇒ "AUROC 稳"不能当结论，历史批处理 AB 全部作废重跑。**

⚠️ **这条是唯一的"止损"实验**：如果发现翻转严重，那我们过去所有 AB 结论都要重跑。所以**要在做 H1/H2 之前先做完 H3**——否则新结论也建立在不可信的基线之上。

**实验 H4｜depict / enable 双列（半天）**

把现有测试集按"风险靠画出来 vs 靠促成"二分（人工标，每类至少 100），分别报 recall。

判据：**enable 子集 recall 显著低于 depict ⇒ 类目表缺一个轴**（B1 的结论成立），该开新类目而不是继续调 PORN。

#### 主线 2｜标签审计（半天起，零训练）

**实验 H5｜政治 L2_30 的框架—实体分离检验（半天，**我认为这是本轮最值得做的一个**）**

完全按 B2 的四步走。判据：漂移 > 1 级的比例 **>30% ⇒ 改标签无用，必须改定义**。

**为什么优先**：它零训练、判据是一个比例数字、**能一次结束"调 alpha / 改标签 / 改定义"的三选一**。而且我们在这上面已经纠结了几周。

**实验 H6｜PORN/VULG 良性最小对（1 天）**

```
对每个易混类目对，造三段式样本（框架完全相同，只换槽位填充）：
  ① 明确 PORN 锚点
  ② 中间态锚点
  ③ 良性锚点
```

判据：见 B1 第三步的三条（单调 / 非单调 / B≈A）。**这比"找更多边界样本"有效，因为它控制了框架这个混杂变量。**

**实验 H7｜单 fill 漏检率（半天）**

50 条高风险 prompt × 3 个改写变体，报"至少 1 个失败"与"3 个全失败"。判据：**前者 ≥ 2× 后者 ⇒ 我们现在的评测在系统性低估失败率。**

#### 主线 3｜RL 改写（半天，前置必做）

**实验 H8｜辅助奖励作弊体检（半天，替换 10-30 的 G7）**

```
配置 A：只留一致性主项
配置 B：一致性 + 全部辅助项（现状）
配置 C：逐个去掉一个辅助项
```

报两列：**训练奖励终值** 与 **真实业务指标**。

判据：**训练奖励上升但真实指标下降 ⇒ 该项在作弊，删。**

对标：辅助项把训练奖励刷到 **~1.0**，真实 mIoU 从 13.48 掉到 **2.19**。

**为什么替换 G7**：G7 只查"奖励能不能作弊"（原样不改是否得高分）；这条查的是"**哪一个**辅助项在作弊"，粒度更细，能直接产出删除决策。

**实验 H9｜合并式指标 vs 逐事件指标（半天）**

```
合并式：整体语义相似度（把改写前后当一个整体）
逐事件：要件级覆盖（把 prompt 拆成 3–5 个要件，逐个算）
```

判据：**合并式的梯度稀疏性**——如果存在大量"改写得不错但整体相似度不过阈值"被判 0 的样本，梯度就断了。

对标：soft IoU 的 R@0.5 = **1.22**，per-event soft F1 的 R@0.5 = **18.54（15×）**。

#### 主线 4｜tag-weighted loss（半天）

**实验 H10｜alpha 甜点扫描（半天，直接可做）**

现状：level1=**1.5** / level2=**1.2** / level3-4=**1.0**。

扫 level1 的 alpha ∈ {1.0, 1.5, 2, 4, 8}，固定其它。报三列：**PORN 误报 / VULG-HINT-EDGE 召回 / macro-F1**。

判据表：

| 曲线形状 | 结论 |
|---|---|
| **明确单峰** | 现在的 1.5 大概率在峰左侧，往 2–4 走 |
| 单调上升 | 继续加，但防 8× 塌 |
| **平坦** | **缩放没生效**——问题不在权重，回 H5/H6 |
| 8× 处塌 | 确认甜点存在，取峰值 |

对标：类别缩放**太弱塌类、8× 太强也塌、4× 最优**。

**实验 H11｜per-class recall 均权替代加权 CE（半天）**

两者**不等价**：加权 CE 放大损失值（间接影响梯度）；均权 per-class recall 直接对齐指标。论文用的是后者，且在**"真值里出现的类别"**上均匀平均（不是全类目表）。

判据：**均权版 macro-F1 更高且 PORN 误报不升 ⇒ 换掉加权 CE。**

#### 主线 5｜I2I 改写链路（针对 0/0%）

**这一条的顺序不能反。** 前两步是证明判据，第三步之后才是改判据，最后才谈改写模型。

**实验 H12｜先证判定能力上限（1 天，零训练，**I2I 最该先做**）**

```
Step 1  抽 200 条真实 I2I 三元组 (源图, 编辑指令, 输出图) —— 用我们自己链路的真实样本
Step 2  3 名标注者独立判"改对了吗"（判据：指令要求的变化是否发生 + 无关部分是否保持）
Step 3  Fleiss κ
Step 4  当前 judge 判同一批
Step 5  judge 与人工多数表决的一致率 / macro-F1
```

**判据表：**

| 人类 κ | judge 一致率 | 结论 | 动作 |
|---|---|---|---|
| **> 0.7** | **< 65%** | **任务良定义，judge 能力不足** | **0/0% 是判据问题，改判据，别动改写模型** |
| > 0.7 | > 65% 但分流仍 0% | 判得动但阈值/口径错 | 改分流阈值与输出格式 |
| **< 0.4** | 任意 | 任务本身没定义清楚 | 先写"改对了"的判别要件 |
| 0.4–0.7 | 任意 | 中度二义 | 补判别维度 + 结构化理由 |

对标：**人类 κ=0.77 / VLM < 65% / 细粒度近随机。**

**这一条能一次结束"改写坏了 vs 编辑能力不足"的纠结**——而且如果结论是"judge 不行"，我们省掉的是整条改写链路的调优。

**实验 H13｜结构化拒绝理由（半天，配套 H12）**

把分流输出从"改写/不改写"改成 7 类（见下表），**0/0% 立刻变 7 个数**：

| 理由 | 该不该触发改写 | 责任归属 |
|---|---|---|
| 几何失真 / 姿态错误 / 纹理偏差 / 颜色材质偏差 / 背景不一致 | 否 | **下游编辑能力** |
| 无关物体引入 | 视风险 | 双责 |
| **意图未实现** | **是** | **改写侧** |
| **意图被抹掉** | **是** | **改写侧** |

判据：**只有最后两行计入"改写失败率"。** 现在这七类全被算进同一个 0/0%，所以看不出责任归属。

**实验 H14｜pointwise → listwise（1 天，零训练）**

```
条件 A（现状）：逐个判 "这个输出改对了吗" → 取最高分
条件 B：一次判 "这 K 个里哪个改得最对" → 取第一名
```

**注意：必须 K ≥ 2。** K=1 时 listwise 退化成 pointwise，这是最容易做错的一步。

判据：**B − A ≥ 10 点 ⇒ 分母是判定方式。**

对标：Qwen3.8-27B **72.1 → 85.9（+13.8）**；Gemma-4-31B **73.8 → 86.1（+12.3）**。

**实验 H15｜加验证记录（1 天）**

不用复现 8 种专用方法。只给每个候选附**代码能查的部分**：change map / 编辑区域特写 / 主体 bbox 位移量 / 程序化检查结论。

判据：**对照"只有 listwise"的配置**。如果我们的编辑类型里有大量"正确答案变化很小"的（改光 / 增亮 / 微调饱和度），**listwise-only 会掉点，加记录才回来**。

对标：Photo **54.2 → 47.2 → 64.4**；Enh **65.0 → 36.8 → 80.3**。

⚠️ **这条和 H14 必须成对做，不能只做 H14。** 只加 listwise 有 28 个点的下行风险。

**实验 H16｜并行替代串行（1 天）**

同一预算（4 次生成）：A 串行精化（改 prompt 迭代编辑上一次结果）；B 并行从原图出候选。人评非平局胜率。

判据：**B 胜率接近 78.5% ⇒ 我们现在的"重试"逻辑在累积误差。**
