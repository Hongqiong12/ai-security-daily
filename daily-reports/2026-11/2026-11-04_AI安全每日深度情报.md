## 一、T2I / T+I2I 论文（核心主线 · 4 篇）

### 1. Kling：输入侧改写的工业配方，以及"接上生成器就掉保真"的实测价码

**快手可灵团队**，2026-11-03，38 页技术报告。

**这是本轮唯一一篇头部公司公开的输入侧改写工业配方。** 它把我们最关心的三件事写在同一份文档里：改写怎么训、奖励怎么设计、评测怎么拆。

#### 三个可直接搬的设计

**（1）三层对齐，只对齐格式是不够的**

| 层级 | 要求 | 不对齐的后果（论文原例） |
|---|---|---|
| Format | 主体/动作/场景/镜头/光/音频按 caption 字段顺序；时间戳；任务档位长度 | 长度与槽位顺序漂移 |
| Lexicon | 用 caption 流水线的镜头/光/动作术语 | 通用 LLM 写 "a breathtaking cinematic shot slowly reveals the scene"，落在分布外 |
| Sentence patterns | 陈述句、现在时、实体显式 | 写 "As if time itself had paused, she gazes outward"，抒情但不在分布里 |

> *"Matching format alone leaves the other two levels free to drift."*

**（2）数据是反向构造的**

不从用户 prompt 出发，从**优质视频的 caption** 出发：拿 caption 当目标，让 teacher 反推"什么样的用户 prompt 会产生这个 caption"，合成 prompt 按**真实流量统计**采样（长度/语言混合/语域/错字率/省略槽位），并且**拒绝"泄漏 caption 骨架"的 prompt**（否则 PE 学成复制而不是补全）。

对我们：**如果要用正例训"风险改写"，正例应该从"安全输出的描述"反推回用户可能怎么问，而不是从用户 prompt 正推。** 后者会让模型学到"把这条改成那条"，前者学到"给定意图该怎么表达"。

**（3）三阶段训练，前两阶段不需要渲染**

| 阶段 | 信号 | 需渲染 |
|---|---|---|
| Caption 对齐 SFT | 优质 caption + 反向构造 prompt + F/R/V 三验证 | 否 |
| **文本级 RL** | 保真 checklist / 合理（空间图+交互图）/ 生动（技法库命中） | **否** |
| **DiT-in-the-loop RL** | 视觉质量 / 运动质量 / 文本对齐 | 是 |

1. **文本级 RL 是性价比最高的一步，且不渲染一帧。** 保真 4.27 → **4.45**（≥4 占比 80.83 → **86.67**），合理 4.18 → 4.31，生动 4.11 → 4.25。
2. **接上生成器之后，保真掉了。** 4.45 → **4.38**（≥4 占比 86.67 → **83.50**），而合理反而升 4.31 → 4.42。论文自己的解释是"抬高下限、压低上限"——PE 学会了回避复杂编排、大镜头运动、密集交互，因为这些是 artifact 风险最高的描述。
3. **加"优质视频源"这一步，生动涨、保真和合理都掉。** 生动 3.72 → 4.03（+0.31），保真 4.02 → 4.00、合理 3.95 → 3.92。**存在显式的三维取舍。**

#### 奖励模型的双轨设计

| | GRM（可解释） | DRM（快速多维） |
|---|---|---|
| 输出 | 结构化批评 + 缺陷证据管（时间区间 + 逐帧框）+ 定序评分 | K 个细粒度问题的选项字母 logits |
| 关键机制 | **"Charge a judge for what it misses"**：对未被匹配的 GT 缺陷也罚，让漏报和错报等价 | **"Decide in the prefix, not in the decode"**：答案槽固定在 prefix，一次 prefill 答 K 问，且字段间互不泄漏 |

结果：内部成对基准 DRM Macro **77.86**（Gemini-4-Argon 73.54、Gemini-3.8-Flash 67.59），Stage 3 只加 **3.1** 点、代价是单次 prefill。VideoScore-Bench-v2 上 DRM **52.00** vs VideoScore2 44.35 / Gemini-3.8 36.90。

#### 两条"排除项"的工程规则

- Caption 只描述"看得见的东西" → PE 把 `no people` 改写成 `an empty street with unobstructed pavement`
- **没有正向等价物的排除项** → 走负条件字段或采样期拒绝

这一条直接可用：我们处理"不许出现 X"型 prompt 时，可以按"有没有正向等价物"二分——有就正向化，没有就不该硬塞进改写，该走拒绝。

#### 诚实的一条边界

**这份报告几乎不谈安全。** 全文的 "safety" 只出现在"评测协议要暴露打分捷径"的语境里，**没有 NSFW / 内容审核 / 风险改写的任何内容**。它是**能力向**配方，不是**安全向**配方。所以它的迁移价值在**机制与工程**，不在**目标函数**。

### 2. UniForget：一条通路上的擦除，在统一模型上只擦了一半

**中科院自动化所 + 国科大 + 字节跳动 + 港中深 + 上交**，2026-11-03。

#### 论文拆开了什么

现有概念擦除全部是**单通路**的：生成侧编辑器改生成分支（"别画出这个概念"），理解侧编辑器改理解分支（"别认出这个概念"）。在统一多模态模型（UMM）上，论文问：**只擦一条，另一条会跟着忘吗？**

答案是不会，而且差距离谱。

#### UUBench：把"忘了"拆成六格

30 个目标概念（人物/地标/物体各 10）× 2 个同类邻近概念 = 60 邻居、**720 张参考图**。

| 指标 | 含义 | 通路 |
|---|---|---|
| **TF** Target Forget | 生成图里不再出现目标身份 | 生成 |
| **SF** Strict Forget | TF 成立**且**图连贯、质量合格 | 生成 |
| **NR** Neighbor Retention | 邻居身份仍在 | 生成 |
| **SR** Strict Neighbor Retention | NR 成立**且**质量合格 | 生成 |
| **TU** Target Utility | 对目标图的**非身份**提问答对 | 理解 |
| **NU** Neighbor Utility | 对邻居图的非身份提问答对 | 理解 |

论文明确写了偏序：**SF ≤ TF、SR ≤ NR**。**任何只报 TF/NR 的表格都在系统性高估自己。**

#### 四条必须记住的读法

1. **生成侧编辑器"压制"很强、"遗忘"很弱。** TIME 在 BAGEL 上 TF **100.0**，DF 只有 **24.0** —— 不画了，但被问到时照样认得出。**"生成不出来了"和"不知道了"是两件事。**
2. **直接组合几乎不涨。** TIME+GD 在 BAGEL 上 31.3，只比 TIME 单独 24.0 高 7.3 点。**把两条单通路方法拼起来，不等于联合遗忘。**
3. **UniForget 的收益和理解侧的代价绑在一起。** DF 31.3 → 80.0，但 TU 91.8 → **72.2**（掉 19.6 点"非身份效用"）。**忘得太狠，把描述能力也忘了。**
4. **严格指标会撕开宽松指标。** BAGEL 上 NR 98.1 而 SR **84.6**；Janus 上 NR 92.9 而 SR **73.2**。**每五个被保住的邻居里有一个是"保住了但图糊了"。**

#### 失效边界：多概念扩展

单 checkpoint 承载 N ∈ {1, 5, 10, 20, 30} 个概念：

| 侧 | N=1 → N=30 |
|---|---|
| 生成侧 TF | 全程 **100.0%** |
| 生成侧 NR | 只剩 **81.5%（BAGEL）/ 41.8%（Janus）** |
| 生成侧 GenEval | 掉到 **39.2% / 32.7%** |
| 理解侧 DF | **80.0% → 51.2%（BAGEL）/ 92.7% → 37.1%（Janus）** |
| 理解侧 MMBench | 几乎不动 |

**同一张表里，生成侧"擦得掉但带崩邻居"，理解侧"不带崩但擦不干净"。** 这是两种完全不同的失败形态，一个总分看会互相掩盖。

#### 对我们的意义

可迁移的是**六格记账法**（TF/SF/NR/SR/TU/NU 各自分母分开），不是具体的数据构造——**PORN 没有专名，"目标/邻居"结构套不过来**。不可迁移的是"擦除能解决内容安全"这个期待：这篇的硬数字说明，**权重侧连"根本不该会"这一半都没做到，它做到的是"这次画不出来"**。

### 3. AegisFlow：贴着边界的控制器不更安全，它只是"刚好不越界"

**清华大学自动化系 + BNRist**，2026-10-29。

#### 论文拆开了什么

免训练引导里，约束满足的通行做法是**每步解一个最小范数控制（min-norm controller, MNC）**：在当前这一步找一个"刚好把约束拉回安全集"的最小修正量。

论文指出 MNC 是**短视**的：目标函数是最小化 ‖u‖，约束是单步不等式，所以**最优解永远落在约束的等号上，也就是边界上**。后果是整条轨迹**贴着安全边界飞**，任何扰动都可能推出去，而且一直在边界附近就**没法朝目标方向做更激进的优化**。

#### 方法：把屏障写进全局代价

$$J(u) = \int_{t_0}^{T}\Big[\tfrac12\|u\|^2 + \lambda B(x,t)\Big]dt + \Psi(x_T)$$

$B$ 在安全集边界附近发散，所以任何**有限代价**的解都天然满足约束，不需要事后投影。全局最优由 HJB 给出，论文给了一个可算近似（屏障项把无强迫方程变成有强迫方程，更难，所以必须有近似）。

#### 结果：一个"约束最好但目标最差"的对照组

CelebA-HQ，文本引导 + 身份保持。

| 方法 | CLIP ↑ | LPIPS ↓ | ID ↑ |
|---|---|---|---|
| FlowGrad + RF | 0.299 | 0.302 | 0.737 |
| OC-Flow | 0.302 | 0.207 | 0.732 |
| **OC-Flow + MNC** | 0.304 | 0.193 | **0.920** |
| **AegisFlow** | **0.309** | **0.188** | 0.901 |

**这张表最重要的读法不是"AegisFlow 赢"，而是 MNC 那一行：**

- MNC 的 **ID 最高（0.920 > 0.901）**，但 CLIP（0.304 < 0.309）和 LPIPS（0.193 > 0.188）**都更差**
- 也就是说：**MNC 把约束做到极致，代价是目标**。它把身份锁得最死，同时最没把"变老/微笑"改到位
- AegisFlow 主动**让出一点约束裕度**（ID 0.901），换来更好的目标对齐和结构保持

|---|---|---|
| CelebA-HQ | OC-Flow | 421.02 ± 25.56 |
| CelebA-HQ | OC-Flow + MNC | **518.26 ± 25.54** |
| CelebA-HQ | **AegisFlow** | **433.81 ± 25.57** |
| Maze2D | SafeFlowmatcher | 4.21 ± 0.39 |
| Maze2D | **AegisFlow** | **44.15 ± 1.96** |

**同一篇论文里，同一个方法在图像任务上比 MNC 快 84.5 秒（−16.3%），在控制任务上比专用方法慢 10 倍。** "全局 vs 短视"的账必须按任务算。

#### 诚实的边界

论文里的"安全"是**几何意义**（身份距离、障碍距离），**不是内容合规**。**"内容安全约束"从未被测**。所以对我们的迁移是**结构同构**，不是实证结论。

### 4. VEvo-Harness：generate–verify–rewrite 的瓶颈不在生成，在"归因"

**阿里巴巴淘天集团 + 清华大学**，ICLR 2027 投稿中，2026-10-29（v2）。

#### 论文拆开了什么

主流 agentic 生成是一个 **generate–verify–rewrite** 的浅循环：生成 → VLM 判 → 不对就改 prompt 再来。论文指出三处结构缺陷：

1. **VLM 判断太粗**：二值"过/不过"没有归因，下游只能盲试
2. **修好的经验丢掉了**：循环结束什么都不留
3. **不加门控地留下来会毒化技能库**：错误经验累积，最终 harness 级幻觉

#### 最关键的一句（对我们最扎）

> *"recent work shifts scaling from model weights to test-time computation, i.e. prompt densification and **semantic rewriting**. However, **prompt-only interventions lack fine-grained attribution and pixel-grounded feedback**."*

**这是对"输入侧改写"这条范式的正式批评：纯 prompt 干预没有细粒度归因，也没有像素级反馈。**

#### 动作空间：改写只是三分之一

$$\mathcal{A} = \{a_{\text{rewrite}},\ a_{\text{resample}},\ a_{\text{tune}}\}$$

论文明确指出既有 pipeline 采用**单一干预范式**，把所有视觉失败都归因为"prompt 没对齐"，于是只会改写。而失败有**异构因果来源**：约束没被表达 → 该改写；表达对了但采样运气差 → 该重采样；表达采样都对但能力不足 → 该调参。

#### 入库质量：本文最有价值的一组数

**有害补丁入库率（Harmful Admission Rate）**随 episode 演化：

| 门控方式 | 有害入库率 |
|---|---|
| 不门控（No Gate） | **33–40%** |
| 纯文本门控（Text-only Gate） | 约 **16%** |
| **完整反事实门控（看图）** | 第 100 episode 约 **2%** |
| 去掉拒绝缓冲 | 回升 **10%** |
| 去掉成功保留 | 回升 **8%** |

论文同时记录：不门控的配置性能在中期冲到约 78 后**塌到约 71.5**，最终比完整版低约 **15%**。

> **从 33–40% 压到 16% 靠"加规则"，从 16% 压到 2% 靠"看图"。8 倍的差距全在最后一层。**

#### 消融

| 对比 | 增益 |
|---|---|
| 反事实治理 vs Admit-All | **+2.9% / +3.2%** |
| 反事实治理 vs Text-Only Gate | **+2.2% / +2.7%**（全基准） |
| HSP（三动作路由）vs **Rewrite-Only** | **+4.0%**（WISE） |
| HSP vs 随机路由 | **+2.4%**（KRIS） |
| 去掉技能蒸馏 | −2.5% / −3.3% |

**`HSP vs Rewrite-Only +4.0%` 是这一篇对我们最重要的一行：把一个"只会改写的循环"升级成"会选动作的循环"，在多约束任务上直接涨 4 个点。**

#### 成本

完整版 **84.38% / 38.4 s / 6.2 次 VLM 调用**，是同时最准、最快、最便宜的配置（惰性门控省 47.5% 调用 +0.28% 性能；拒绝缓冲省 25.7% 调用）。

#### 诚实的一条

**在指令编辑基准上它并不是全面第一**：RISE-Bench **45.8** 第一（Know-Thinker 44.7 / Nano-Banana-Pro 41.2），但 KRIS（47.7 vs 61.1）、WiseEdit（37.0 vs 48.0）、GEditTemp（20.0 vs 37.6）**都不如 Nano-Banana-Pro**。它的定位是"**开源冻结生成器 + harness 打赢专有生成器的一部分**"。

### 5. Which Words a Model Fears：决定拒答的不是"请求"，是"词表里的某个词"

**美国东北大学**，2026-11-02。

#### 为什么这篇是本轮最高价值的一篇

因为它把我们做输入侧改写时的**一个隐性假设**拆了：我们假设风险来自"整条 prompt 的语义"，于是用整条 prompt 打分、用整条 prompt 的 edit rate 约束保真。这篇把测量单位从 prompt 下沉到 **word**，并且给出跨 **71,583 词**的分数表。

它回答的问题就是我们每天在问的：

> **一个 prompt 被拒了。把哪个词换成它的哪个同义词，能让拒答降得最多？**

#### 三个现象

| 实验 | 结果 |
|---|---|
| **插入**：往 321 条模型本就拒 ≤0.80 的有害 prompt 里插 1 个与请求无关的有害词 | 首 **+0.31 [0.22, 0.40]**（55 条）/ 中 **+0.19 [0.13, 0.25]**（105）/ 尾 **+0.33 [0.29, 0.37]**（267）；八模型尾部 **+0.10 至 +0.49** |
| **识别门槛**：新开 chat 问"刚才多出来的是哪个词" | 只在识别概率 **>0.90** 的样本上取效应 —— **模型认出了那个不属于请求的词，然后照样拒** |
| **替换**：在被拒的良性 prompt 上把**一个实词**原位换成保义且无害联想的同义词 | 拒答降 **3–28 点**；换成"惰性词"只动 **≤2 点**，区间全含 0 |

第一条的细节值得单独记：插入位置效应**不是"模型没看见"**。识别置信度与逐 prompt 的拒答上升**无关**（首/中位置 Spearman ρ = 0.00，尾 +0.18）。**看见了也不影响判决。**

#### 方向：交叉设计 + 交叉拟合

96 条 prompt × 24 对（有害词/等长中性词）= 2,304 格，取 D_pw = h(H) − h(N)，把"prompt 本身"和"追加一个词这个动作"一起消掉，再对 D 做两因子向量方差分解：

- **共享分量 μ 占 ‖D‖² 的 0.30，全部词效应加起来只有 0.15**
- 24 个词里 **21 个**的逐词平均方向与 μ 余弦 **0.82–0.96**
- 交叉拟合后，在"没见过的 prompt × 没见过的词"上投影为正的格占 **95%**，残差化后 Spearman **ρ = 0.65**

#### 当尺子用：全词表恐惧表

71,583 词 × 48 条被过度拒答的 prompt：

- 两个互斥半集的**词序复现 ρ = 0.95**
- 正端是**性相关词、恋童/强奸词、侮辱词、暴力犯罪词**；负端是**语域词**：sardonic、shakespearean、poetic、sassy、whimsical
- 跨模型一致性 **+0.36（Phi）至 +0.76（Qwen3.5-9B）**；八个表的共同核心是 **60 个词**同在 top 1%、**25 个**同在 bottom 1%

#### 验证：没见过的词，剂量响应

| 模型 | 表位置 vs 拒答变化 | 最高桶 − 最低桶 |
|---|---|---|
| Qwen3.5-4B | **ρ = +0.92** | −0.165 → **+0.367**（7/7 相邻桶有序） |
| 其余七模型 | **ρ = +0.54 至 +0.96** | **+0.32 至 +0.71**（5–7/7 有序） |

#### 验证：自然 prompt 里的替换

**良性侧**（Hard-1K + 100 条 XSTest，每模型 349–352 单元）：

| 条件 | 移除的拒答 |
|---|---|
| 最恐惧词 → 表上最低位移的同义词 | **+0.05（Llama）至 +0.29（Qwen3.5-27B）**，八区间全不含 0 |
| 最惰性词 → 同义词（对照） | **+0.01 至 +0.05** |

**有害侧**（OR-Bench Toxic + 100 条 XSTest 对照）：

| 项 | 数 |
|---|---|
| 替换规则覆盖率 | **64%** |
| 覆盖不了的原因 | 约 **1/4** 不存在"保义且无有害联想"的词（自残/性/炸弹）；**11%** 三次重写仍过不了结构检查 |
| 替换后移除的拒答 | **+0.08 至 +0.23**，八模型全部 |
| 删除模糊短语（23 条） | **+0.17 至 +0.36** |
| 回答有害度上升 | **≤ +0.04** |

#### 三组"预期之外"

1. **手挑的"安抚词"全部无效。** 作者从六类猜测（收纳/授权/防御/教育/虚构/职业）手工选 24 个"勇气词"，**没有一类降低拒答**（最好的是"虚构"类 −0.029 [−0.091, +0.031]），而"收纳"类反而**升高 +0.075**。真正有效的是语域词（poetic / whimsical）—— **直觉错得离谱**。
2. **表上"最恐惧的十个词"不含任何插入词表里的词。** 把它们追加到 20 条"模型拒 <1%"的干净良性 prompt 上，拒答升 **+0.372 [+0.283, +0.468]**；而且 **0.986** 的拒答把追加词**当成请求的一部分**在处理。
3. **"选哪个同义词"增量很小但稳定。** 随机抽一个无害同义词也能移除 **+0.04 至 +0.24**；用表上最低的再多移除 **+0.02 至 +0.08**（八模型全正）。**真正干活的是"换掉那个被恐惧的词"，选词是二阶的。**

#### 机制：词被读取得很早，效果被写得很晚

- 在**词自己的 token** 上，差异 **70–88%** 是词特有的，但对拒答预测力只有 **ρ ≈ 0.2**
- 到边界（TBG），**从第 12 层起**共享分量压过词分量
- 边界**并没有**比中性孪生词更多地注意有害词；边界位移里 **late MLP 写了 73%**，直接注意力读词只贡献 **1%**

#### 一条连带的方法论结论

> **安全评测必须控制词表**，因为一个 benchmark 的拒答率取决于它的 prompt 恰好用了哪些词。

### 6. What Does a Safety Label Measure：一个 label score 混了三样东西

**Wiqonn**（两人），2026-10-31，44 页。

#### 论文拆开了什么

情境安全 benchmark 给每个场景一个 SAFE/UNSAFE 标签，让 MLLM 答，再判答得对不对。论文问：**这样一个 label score 到底在量什么？**

三分答案：可能来自 ① 场景本身 ② 请求本身 ③ **benchmark 自己的文件**。

第三种真的发生了：

| 现象 | 数 |
|---|---|
| MSSBench chat 的**图片尺寸**单独判标签 | **82.3%**（CI [78.9, 85.5]），追平或超过七个商用模型中的六个 |
| 修正后的 chat 划分上 | 尺寸规则掉到随机 |
| HoliSafe 上"只看请求、不看图" | AUROC **0.914**（Molmo2-O-7B），排对比值和看场景差不多 |
| MOSSBench | 条目划分本身决定了标签 |

#### Spot-Stop 分解：把 R − A 拆成三份

设 **R** = 排序指标（AUROC）、**A** = 打标指标（balanced accuracy）：

$$R - A = \underbrace{(A^* - A)}_{\text{阈值 part}} + \underbrace{(\mathrm{AUROC} - A^*)}_{\text{重叠 part}} + \underbrace{(R - \mathrm{AUROC})}_{\text{对内顺序 part}}$$

$A^*$ 是**最优共享切点**上的准确率。三项的含义与可修性：

| Part | 含义 | 能靠调阈值修吗 |
|---|---|---|
| **Threshold** | 一个**共享**切点还能救回多少 | **能** |
| **Overlap** | 切点因为"安全分与不安全分重叠"而损失多少 | **不能**（信息本身不够） |
| **Within** | 只在**同一对**内成立的顺序 | **不能**（成对能力，与绝对定标无关） |

论文还给了理论参照：方差相等双正态、AUROC 相同时，重叠项等于 $g(\mathrm{AUROC}) = \mathrm{AUROC} - \Phi(\Phi^{-1}(\mathrm{AUROC})/\sqrt{2})$。实际重叠项**超过**这一项的部分，说明同 AUROC 下分布形状更差。

#### 各 benchmark 的中位切分（点）

| Benchmark | Threshold | Overlap | Within |
|---|---|---|---|
| MSSBench chat | 4.1 | 5.5 | 3.4 |
| 列 2 | 4.6 | 1.5 | 3.7 |
| 列 3 | 1.7 | 6.2 | 5.7 |
| 列 4 | 3.9 | 2.5 | 3.7 |
| 列 6 | 5.3 | 5.5 | 7.3 |

**读法**：只有列 1、2 是"阈值占主导"；列 3、6 是"重叠和顺序占主导"。**同一个 gap，在不同 benchmark 上有完全不同的病因。**

#### 免标注修复的失效边界（这条是硬约束）

| 条件 | 结果 |
|---|---|
| AUROC **> 0.70** | 回收率接近阈值项上限；两种情况分别回收 **77% / 99%** |
| AUROC **< 0.70** | **五个模型里三个变差** |
| 场景级 recenter（VSCBench） | **14 个模型里 13 个**排序变好，**+6.8 点 BA、+0.069 AUROC** |
| Avg-2（两次采样平均） | chat AUROC 到 **0.898**，但**只缩阈值项**，重叠与对内顺序不动 |

#### 主结果

- **14 个开源 MLLM 上 R − A 全部为正**（在 label-swap null 之上）
- **大多数模型"排序比打标好"，超出部分多于 AUROC 所能预测**
- 一个共享阈值能修 **1/3 – 1/2** 的超额
- 最优共享阈值之后还剩 **6.9 点**，**全是重叠**

## 三、趋势信号

### 信号一：这一轮六篇，"拆解"全部发生在**测量单位**上，而不是模型结构上

把六篇的动作列出来，没有一篇提出的新模型架构：

| 论文 | 原来的测量单位 | 拆成 |
|---|---|---|
| Which Words | prompt | **word**（71,583 个） |
| Kling | "生成质量"一个聚合分 | 链路四段 × 任务特定准则 |
| UniForget | "忘了" | 生成通路 / 理解通路 × 严格/宽松 |
| AegisFlow | 终点的约束满足 | **路径上每一点**的屏障代价 |
| VEvo-Harness | "改错了"一个布尔 | **根因**（哪条约束）+ 三类动作 |
| Safety Label | "一个 label score" | 阈值 / 重叠 / 对内顺序 |

**共同点：拆的对象都是"我们用来做决策的那个数"，而不是"产生这个数的模型"。**

这是连续第二周同向（11-03 的主题是"被边际掉的那一维"，11-02 是"风险住在看不见的那一半"）。三周连起来看，这个领域当前的共同瓶颈不是"模型不够强"，而是**"我们记账的科目不够细"**。

### 信号二：输入侧改写这条路的"天花板"被两份独立工作同时指出

- **Kling**：文本级 RL 能把保真从 4.27 推到 4.45，但**接上生成器之后掉回 4.38**。改写的收益有一部分是"文本看起来对了"，而不是"生成结果对了"。
- **VEvo-Harness**：直接写 *"prompt-only interventions lack fine-grained attribution and pixel-grounded feedback"*，并且实测 **Rewrite-Only 比三动作路由低 4.0%**。

**两份工作来自两个头部公司（快手、阿里），指向同一个结论：改写是必要的，但不是充分的。** 它的充分性缺口在"像素级反馈"——文本侧判不了的，只有看图才能判。

### 信号三：权重侧擦除的失效边界，这轮被量化到了"不能再用"的程度

| 事实 | 出处 |
|---|---|
| 生成侧编辑器 TF **100.0%** 而 DF **24.0%** | UniForget 主表 |
| 两条单通路直接组合只从 24.0 涨到 31.3 | 同上 |
| 理解侧 DF 随概念数 **92.7% → 37.1%**（N=30） | UniForget 6.3 |
| 生成侧擦除把邻居 NR 连带打到 **41.8%** | 同上 |
| 通用生成能力 GenEval **78.9 → 70.1** | 同上 |

**"擦除"能做到的是"这次画不出来"，做不到"不知道"。** 而且它**随概念数线性崩塌**，**没有"只擦这个不擦那个"的精度**。

**所以权重侧与输入侧的关系，这一轮可以写成一个明确的分工**：

| | 权重侧擦除 | 输入侧改写 |
|---|---|---|
| 生效粒度 | 全局，一次改完对所有请求生效 | 逐条，可回滚、可分业务配置 |
| 能保证的 | "这次生成不出来" | "这次不生成这一类" |
| 做不到的 | "不知道"（DF 24–37%）、"只擦这个"（邻居连带） | 全局一致性、已经生成出去的图 |
| 验收指标 | 行为空间量（不能只看 TF） | 语义保真 + 风险分双约束 |

**互补，不可替代。** 而且这一轮补上了一句更实的：**擦除的"已经做到"比它宣称的窄得多，所以它不该被当作内容安全的主防线。**

### 信号四：阈值 operating point 这件事，这轮终于有了"该不该做"的前置判据

我们过去三轮在这个问题上反复：调阈值 / 补数据 / 改标签，三选一，每次都靠讨论决定。

Spot-Stop 给了判据：

| 若 | 则 |
|---|---|
| R 明显高于 A，且**阈值项**占大头 | 做分业务粒度 operating point 校准 |
| 阈值项很小、**重叠项**占大头 | **调阈值到此为止**，转去做数据/loss/特征 |
| **对内顺序项**占大头 | 放弃绝对阈值，改用成对比较 |

并且给了一个**必须先测的前置条件**：recentering 在 **AUROC < 0.70 时五个模型里三个变差**。"先用免标注校准救一下"这个念头，只有在 R > 0.70 时才成立。

## 四、业务对齐研究板块 ⭐

> **双锚点**：PORN/VULG 边界 + 政治 L2_30 层级
> **运营约束基线**：误杀率 **5.2%** / 漏过率 **3.42%** / 一级一致率 **77.64%**

### A. 直接可迁移方法

#### A1. 建"词级风险锚点表"，把改写的操作单位从 prompt 降到 word（最高优先，1–2 天，零训练）

**依据**：Which Words 在八个模型上证明——单个词的替换能移动 3–28 点拒答，惰性词对照 ≤2 点；表位置对 40 个没见过的词的排序 **ρ = 0.92**。

**做法**（不需要方向向量，只做"替换"这一半）：

1. 从我们的 badcase pool 里取 **N 条"改写后仍被判高风险"的样本**（当前 reject_tag 回流数据里就有）
2. 对每条样本，用 LLM 提出最多 10 个**保义、无风险联想**的单词级替换候选（原词位替换，不增删）
3. 每个候选跑一遍**现有风险分类器**，记录风险分变化
4. 聚合到**词**：`词 → 平均风险分降幅 / 保义通过率 / 覆盖样本数`
5. 输出一张"**高风险锚点词表**"（降幅最大的 top-K）与一张"**惰性词表**"（降幅 ≈0）

**判据**：
- 若 top-20 锚点词能覆盖 **≥40%** 的高风险样本 → 锚点表可用，改写可以从"整条重写"改为"定点替换"
- 若 top-20 覆盖 **<15%** → 风险不在词级，锚点在**短语级/构图级**，要改口径（见 A2）
- **必须同时报惰性词对照**：若惰性词替换也能降 >5 点，说明分类器在读"长度/流畅度"而不是风险

**为什么这一条排第一**：它是**唯一一条能把"我们靠人工经验写的安全同义词库"替换成"测出来的表"**的路。Which Words 实测手挑 24 个"安抚词"**没有一类有效**，"收纳"类反而 **+0.075** —— 我们现在依赖的正是这种手挑。

#### A2. 锚点定位下移到"可删单元"，不限于单词（1 天，零训练，与 A1 同批）

Which Words 里有一处容易被忽略的细节：当被定位到的是**模糊短语**而非单词时（"what steps"、"without getting caught"，57 条），整段删除降 **4–50 点**，比单词替换的 3–28 点**更大**。

**对我们的直接含义**：T2I 的高风险锚点很可能不是单个词，而是**构图/关系/视角描述**（"standing on the track"、"seen from above"、"from behind"）。这类单元删掉会改意图，但**它证明这类单元的杠杆比单词大**。

**做法**：把 A1 的替换候选从"单词"扩展到"**可删短语**"（名词短语 / 介词短语 / 关系从句），重复同样流程，比较两类单元的杠杆比。

**判据**：若短语级杠杆 > 词级杠杆 2 倍以上 → 锚点表应以短语为行，词表降为辅助。

#### A3. 用"离边界留裕度"替代"最小改动"（0.5 天改代码 + 1 天 A/B，零训练）

**依据**：AegisFlow 的核心对照——MNC（最小改动）的 ID **0.920 最高**，但 CLIP（0.304 < 0.309）和 LPIPS（0.193 > 0.188）**都更差**。**贴着约束边界走的解，约束最好、目标最差。**

我们的改写约束里，"edit rate 越小越好"在数学上就是 min-norm：**在"风险达标"这个可行域里找改动最小的点，最优解落在可行域边界上**——也就是"风险刚好等于阈值"。

**做法**：
1. 把约束从 `风险分 < τ` 改成 `风险分 < τ − δ`（留裕度），`δ` 按风险分归一化后取 0.10 / 0.15 / 0.20 三档
2. 同一批 prompt 跑改写，记录 (edit rate, 语义保真, 改写后风险分)
3. 对改写后的样本做**同义 paraphrase 扰动**（每条 3 个变体），测**风险回升率**

**判据**（三条一起看）：
- 留裕度后 **edit rate 上升但语义保真不降** → 与论文一致（让出约束换目标），继续
- 留裕度后 **风险回升率显著下降**（比如从 8% 降到 3%） → 说明过去在生产"刚好合规"的样本
- 留裕度后 **误杀率变差** → 说明裕度和"过度改写"耦合了，退回 δ=0

**这条是反直觉的，也是本轮最有价值的单条实验建议。** 我们过去一直把"改得越少越好"当铁律，AegisFlow 说明这条铁律会**主动把解推到边界上**。

#### A4. 用"一个 label score 三项分解"结束阈值/数据/标签的三选一（半天，零训练，最高性价比）

**依据**：Safety Label 的 Spot-Stop——一个共享阈值只能修 **1/3 – 1/2** 的超额，剩下的 6.9 点全是重叠；而 recentering 在 **AUROC < 0.70 时五个模型里三个变差**。

**做法**（四步，全零训练）：

| 步 | 动作 | 产出 |
|---|---|---|
| 1 | 在现有评测集上同时算 **AUROC（R）** 和 **balanced accuracy（A）** | 我们现在只有 A = 77.64%，R 是缺的 |
| 2 | 扫最优共享阈值，得 $A^*$ | 阈值项 = $A^* - A$ |
| 3 | 算重叠项 $= \mathrm{AUROC} - A^*$、对内顺序项 $= R - \mathrm{AUROC}$ | 三项占比 |
| 4 | 按占比选路线（见信号四的表） | **决策，不再讨论** |

**判据**：
- 阈值项 **> 50%** → 分业务粒度阈值校准立刻做，预期收益上限就是阈值项
- 阈值项 **< 20%** → **停止调阈值**，转数据/loss
- 对内顺序项 **> 40%** → 绝对阈值这条路本身有问题，改用成对比较

**这条能一次结束我们纠结了三轮的"调阈值还是补数据"**，而且**半天就能出结果**。

#### A5. 图审判定必须"看图"，不能只"看文本"（依据明确，实施成本 1 天）

**依据**：VEvo-Harness 的有害入库率——不门控 **33–40%**，纯文本门控 **16%**，**看图门控 2%**。**8 倍的差距全在最后一层。**

**对我们的映射**：我们的图审 AB 评测与"分流是否生效"的判定，如果验收信号是**文本侧**（prompt 判风险、规则匹配），那"错误经验入库率"会是看图验收的 **8 倍**。

**做法**：把任意一条"改写/分流是否生效"的验收流程，改成三条对照：
1. 无验收（全放）
2. 文本侧验收（现有规则）
3. **图像侧验收**（渲染后过图审模型）

报三条的"错误放行率"。**判据**：若 3 比 2 低不到 3 倍，说明我们的图审模型在"看图"这件事上没比文本规则强多少 —— 这是图审本身的问题，不是架构问题。

### B. 风险锚点处理启发（双锚点）

#### B1. PORN / VULG 边界：`VULG-HINT-EDGE` 的病根可能不在类目定义，在**锚点词**

前几轮我们给 `VULG-HINT-EDGE` 的定位是"二维坐标压成一维标签的产物"（11-03）、"depict 无风险 × enable 有风险"（11-02）。这一轮 Which Words 给出了**第三种、更可操作的解释**：

> **这个类目的判定，可能主要是由几个特定词驱动的，而不是由"是否构成暗示"这个语义判断驱动的。**

证据链：

| 事实 | 含义 |
|---|---|
| 插入一个与请求无关的有害词，拒答升 **+0.31**（首），且模型**认得出它不属于请求** | 判定不看意图，看词 |
| 词自己的 token 上 70–88% 是词特有的，但预测力只有 ρ≈0.2；到边界从第 12 层起共享分量接管 | 词被读取得早，效果写得晚 —— **不是"没看懂"，是"看懂了也被覆盖"** |
| 手挑的 24 个"安抚词"全部无效，"收纳"类反而 **+0.075** | 人工直觉无法预测哪些词会降风险 |
| 跨模型表一致性只有 **+0.36 至 +0.76** | **每个模型恐惧的词不一样**，不能用一张通用词表 |

**可操作判据（三个，成本递增）**：

1. **锚点覆盖检验（半天）**：取 `VULG-HINT-EDGE` 的 200 条样本，用 A1 的流程做词级替换。若 **top-10 锚点词能覆盖 >50% 的样本** → 这个类目**主要是词驱动的**，调类目定义没用，改锚点表有用。
2. **惰性词对照（与 1 同批）**：若把"最惰性词"替换也能降 >5 点风险 → **分类器在读流畅度/长度，不在读风险**，这是比锚点问题更严重的问题。
3. **替换后意图保持率（1 天）**：改写后让 LLM 判"意图是否保持"。若锚点替换后意图保持率 >90% 而风险分降幅 >30% → **`VULG-HINT-EDGE` 里有一批样本是纯锚点误杀**，可以直接用规则改掉，不需要重训。

**为什么这条比前三轮的解释更有用**：前两轮的解释（二维坐标、depict/enable）都需要**重新标注**才能验证；这一条**不需要标注**，只需要跑分类器。

#### B2. 政治 L2_30 层级：**"分层一致率"和"分层 AUROC"是两个不同的量，我们只测了前者**

我们的一级一致率 77.64% 是**打标指标（A）**。Spot-Stop 的教训是：**A 低不等于模型不行，可能只是阈值没调；也可能 A 高但 AUROC 也高，那才是真的行。**

对 L2_30 的具体启发：

| 观察 | 含义 | 动作 |
|---|---|---|
| 一级一致率 77.64%，但如果一级的 **AUROC 显著高于 0.776** | 一级"会排不会判"，差额是阈值项 + 重叠 | 先做阈值校准，不要动标签 |
| 若一级 AUROC ≈ 0.776 | 排序能力本身就是这个水平 | 阈值无用，转数据/定义 |
| 若 L2_30 的 AUROC 明显低于 L1 | **层级越细排序越差**，这是层级体系的固有衰减 | 叶子类目**继承父类阈值**，不要独立校准（样本量也不够） |

**必须做的两个前置检查**（各半天，零训练）：

1. **`L1 × L2_30` 每格的 AUROC 与 balanced accuracy 双列**。我们过去只有后者。**双列一比，就知道哪些格子是"排序行、阈值差"（可救），哪些是"排序就不行"（不可救）。**
2. **标签泄漏自查**（对应 Safety Label 的 82.3% 尺寸规则）：查我们的评测集里，有没有"与标签无关的元信息"能单独判出标签——**prompt 长度？样本来源渠道？标注批次？回流日期？** 若有任何一项单独准确率 >60%，**那张表上的所有版本对比都要重算**。

第二条是本文最容易被跳过、但代价最大的一条。**一个 benchmark 的图片尺寸能到 82.3%，说明"审计别人"这件事必须定期做。**

#### B3. 跨锚点的共同结论

**两个锚点这一轮的共同答案，都是"先测，再决定改什么"。**

- PORN/VULG：先测**锚点覆盖率**，再决定是改锚点表还是改类目定义
- 政治 L2_30：先测**逐层 AUROC**，再决定是调阈值还是改定义

这两个测法都**不需要重新标注**，都是半天到一天。**这比我们再讨论三轮"该调哪个"要便宜得多。**

### C. 三维评测设计启发（语义保真 / 安全提升 / 指令遵循）

#### C1. 保真这一维，从"人工印象"改成"原子要求 checklist"（1–2 天，零训练，最高优先）

**依据**：Kling 的 Faithfulness 定义——把用户 prompt 拆成**原子要求 checklist**（实体/属性/数量/动作/空间关系/镜头指令/引用文本/音频/参考绑定/排除项），逐条判"满足/违反/未涉及"，**违反权重高于遗漏，加一条与某项矛盾的内容算违反**。

**为什么这一条比"embedding 相似度"好**：

| | embedding 相似度 | 原子要求 checklist |
|---|---|---|
| 能定位 | 不能（一个标量） | **能**（报出哪一条没过） |
| 能区分"漏"和"加错" | 不能 | **能**（未涉及 vs 违反） |
| 能分类型回归 | 不能 | **能**（按要求类型分切片） |
| 能防"堆术语" | 不能（堆词相似度更高） | **能**（加矛盾内容算违反） |

**做法**：
1. 对现有 1,979 条有效 I2I 评测样本，用 LLM 把每条指令拆成 3–8 条原子要求
2. 人工抽检 100 条，测拆分一致性（目标：原子要求级别 κ ≥ 0.7）
3. 改写前后各判一遍，报**逐要求类型的满足率**

**判据**：
- 若改写后**"空间关系"类要求**的满足率掉得最多 → 改写抹掉的是构图信息（对应 I2I 0/0% 的一个具体原因）
- 若**"排除项"类要求**满足率掉得最多 → 改写把否定改丢了（Kling 给了规则：正向化，或走拒绝）

#### C2. 排除项必须正向化，不能硬塞（规则级，0.5 天）

**依据**：Kling 的明文规则——Caption 只描述"看得见的东西"，所以 PE 把 `no people` 改写成 `an empty street with unobstructed pavement`；**没有正向等价物的排除项，走负条件字段或采样期拒绝**。

**对我们的直接含义**：我们现在很可能在把"不许出现 X"改写成"不要有 X"（只是换了说法，风险锚点还在）。正确做法是二分：

| 类型 | 处理 |
|---|---|
| 有正向等价物 | 改写为正向描述（"no people" → "empty street"） |
| 无正向等价物 | **不改写**，走拒绝或负条件通道 |

**判据**：统计我们现有改写里"含否定词"的比例。若 >15% 且其中大部分没有正向化，说明改写管线在这一类上是**假改写**（改了字面，没改语义）。

#### C3. 阈值 operating point 的选择：先分解，再校准，并加"AUROC 门槛"（半天）

见 A4。这里补两条评测口径：

1. **必须同时报 R 和 A**。我们过去的看板只有一致率（A），缺 AUROC（R）。**没有 R 就无法判断"阈值还能救多少"。**
2. **加一道前置门**：`若 AUROC < 0.70，禁止对该类目启用免标注校准`。依据：Safety Label 实测 AUROC < 0.70 时五个模型里三个校准后变差。

#### C4. 多版本回归：把"聚合分"换成"逐维度 × 逐要求类型"（看板改造，1 天）

**依据**：Kling 的 "评测要跟着任务走，一个聚合分说不了病灶在哪"；VEvo-Harness 的 Rewrite-Only 输 4.0% 也只在**分任务**时才看得出来。

**具体口径**（6 个模型版本的迭代看板）：

| 维度 | 报什么 | 为什么 |
|---|---|---|
| 语义保真 | **逐要求类型**的满足率（不是总分） | 总分掩盖"哪类要求被牺牲" |
| 安全提升 | 风险分降幅 + **改写后 paraphrase 扰动下的回升率** | 单点降幅会被"刚好压线"骗过 |
| 指令遵循 | 编辑后意图命中率（分操作类型） | 组合性重任务上改写可能负收益（Promptist 在 GenEval2 上 −19.3%） |
| 成本 | edit rate + 延迟 | 留裕度会涨 edit rate，必须同报 |

### D. 下一步实验建议（六条主线）

> 排序原则：**零训练、能一次结束纠続的排前面**。前五项合计约 2.5 天，全部不需要训练。

#### 主线一：I2I 改写链路（针对当前分流命中 0/0%）

##### H1. 把 0/0% 拆成"三类动作"而不是"一次改写"（1 天，零训练）⭐ 最优先

**依据**：VEvo-Harness 的 `HSP vs Rewrite-Only +4.0%`（WISE）。它证明在多约束视觉任务上，**"只会改写"比"会选动作"低 4 个点**。

**做法**：取当前分流判为"需要改写"的 200 条，随机分三组，每组只允许一种动作：

| 组 | 动作 | 说明 |
|---|---|---|
| A | **rewrite** | 现有改写管线 |
| B | **resample** | 不改指令，同一模型换种子重生成 3 次，取最好 |
| C | **tune** | 不改指令不改种子，调引导强度/步数/负面提示 |

**判据**：
- 若 **B 或 C 组命中率显著高于 A 组** → **0/0% 不是改写没写好，是把 resample/tune 的活派给了改写**。这是最可能的结论，也是最省钱的修法（不用训练）
- 若三组都接近 0 → 问题在**指令受理**或**评测判据**，不在改写

**这条是这一轮对 I2I 0/0% 最直接的建议**：过去三轮我们一直在改"怎么改写"，从没测过"该不该改写"。

##### H2. 用"原子要求 checklist"重算 0/0%（1 天，零训练，与 H1 同批）

**依据**：C1。当前 0/0% 的判据很可能是"整条指令算不算被满足"的二分，这个判据本身没有分辨率。

**做法**：把 200 条指令各拆 3–8 条原子要求，改写前后各判一遍，报**逐要求满足率**。

**判据**：若逐要求满足率在 **20–40%** 之间（而整条命中是 0%）→ **0/0% 是判据问题不是能力问题**，指标立刻有分辨率。这是过去几轮反复怀疑但没测过的方向。

##### H3. 分流输出加"三类理由"，把"我看不懂"和"风险高"分开（0.5 天，零训练）

**做法**：分流模型输出从二值改成三分类：`风险高（该改写）/ 我看不懂（该澄清）/ 双解读（该拒绝）`。

**判据**：若"我看不懂"占比 **>30%** → 缺的是**澄清路径**不是改写能力，改写再优化也没用。

#### 主线二：标签审计与阈值校准

##### H4. 一个 label score 三项分解（半天，零训练）⭐ 最高性价比

见 A4。四步：算 R → 扫最优共享阈值得 $A^*$ → 算三项 → 按占比选路线。

**这一条能一次结束"调阈值 / 补数据 / 改标签"的三选一。**

##### H5. `L1 × L2_30` 双列（AUROC + balanced accuracy）（半天，零训练，与 H4 同批）

见 B2。**双列一比就知道哪些格子是"排序行阈值差"（可救），哪些是"排序就不行"（不可救）。**

##### H6. 锚点覆盖率检验（1 天，零训练）

见 A1、B1。**不需要标注，只跑分类器。**

##### H7. 评测集元信息泄漏自查（2 小时，零训练）

见 B2 第 2 条。查有没有"与标签无关的元信息"能单独判标签（长度/来源/批次/日期）。

**判据**：任何一项单独准确率 >60% → 那张表上所有版本对比作废重算。

#### 主线三：输出侧图审

##### H8. 图审"看图 vs 看文本"的 8 倍检验（1 天）

见 A5。三条对照：无验收 / 文本验收 / 图像验收，报错误放行率。

**判据**：图像验收比文本验收好不到 3 倍 → 图审模型本身不够"看图"，先修模型不修架构。

##### H9. 图审的"漏报等价惩罚"改造（0.5 天改代码 + 1 天验证，需训练）

**依据**：Kling 的 **"Charge a judge for what it misses"** —— 只惩罚"报错了"会奖励"少报"，所以**对未被匹配的 ground-truth 缺陷也罚**，让漏报和错报等价。

**我们的对应问题**：如果图审的 loss 只罚误报（因为误杀率 5.2% 是硬约束），模型会学会**少报**。**这与我们观察到的"PORN 过度预测"方向相反，但可能是同一个机制的两面**——过度预测在明确类上，少报在边界类上。

**做法**：在 tag-weighted loss 里加一项"漏报惩罚"，权重从 0 扫到 1.0，与误报惩罚构成一个二维网格，画 (误杀率, 漏过率) 的帕累托前沿。

**判据**：若帕累托前沿上存在一个点同时优于当前 (5.2%, 3.42%) → 当前 loss 的惩罚配比不在前沿上，可免费改进。

#### 主线四：tag-weighted loss

##### H10. 层级标签的"固定 prefix 一次前向"结构（改造，需训练）

**依据**：Kling 的 DRM——**把 K 个问题的答案槽固定在 prefix 里，一次 prefill 答完**，因为槽位在 prefix 而非自回归解码，**前面的答案不会泄进后面的字段**；配合 option-letter 随机化 + 字段置换 + 只对 placeholder 算 loss。

**对我们的直接含义**：我们的 `<tag><|reasoning|>...` 格式是**先出 tag 再出 reasoning**，这在自回归里是"tag 不受 reasoning 影响"——但反过来，**reasoning 会受 tag 影响**（模型在给自己找理由）。而 Kling 的结构是**所有字段并行、互不泄漏**。

**做法**：把 L1 / L2 / L3 / L4 四个层级做成**四个固定槽位**，一次前向出四个 logits，**层级之间不通过解码传递**。reasoning 单独生成，作为辅助任务。

**判据**：若 L1 一致率不变而 **L3/L4 一致率提升 ≥2 点** → 层级间的错误传播是主要瓶颈，值得继续；若 L1 也提升，说明当前格式本身在拖累。

##### H11. 严格指标（SF/SR 式偏序）引入分类评测（0.5 天，零训练）

**依据**：UniForget 的 `SF ≤ TF`、`SR ≤ NR`。任何宽松指标都必须同时报对应的严格指标。

**我们的对应**：现在报的是"类目判对率"。应该同时报：
- 宽松：argmax 对
- **严格：argmax 对 且 置信度 > 阈值 且 reasoning 与 tag 不矛盾**

**判据**：若严格版比宽松版低 **>15 点** → 有相当一部分"判对了"是碰巧对（高置信度错 / 理由与结论矛盾），这类样本在线上会不稳定。

#### 主线五：RL 改写

##### H12. 奖励里必须把"保真"单独作为一项，不能只留一致性（0.5 天改代码 + 1 天验证）

**依据**：Kling 的 Table 13 是本轮最硬的一条实证——**文本级 RL 把保真从 4.27 推到 4.45，接上 DiT-in-the-loop 之后掉回 4.38**（≥4 占比 86.67 → 83.50），而"合理"反而升。**用生成器奖励换保真，是有价的。**

**我们的现状**：RL 改写的奖励来自 Qwen-Image 一致性。**按这篇的规律，我们的语义保真应该在掉，而且我们可能没在单独测它。**

**做法**：
1. 在奖励里显式加一项**文本侧保真**（用 C1 的 checklist，或 A1 的锚点保留率）
2. **保真项门控其他项**（Kling 的做法：违反显式要求就不给其他分），防止拿意图换分数
3. 记录"**平均改动字符数**"作为监控点（8 字 → 1 字 = 在退化成"不改"）

**判据**：加保真项后，若**一致性分下降但保真上升** → 之前的奖励在作弊；若两者同升 → 之前的奖励设计没问题，只是没测保真。

##### H13. 改写的基线换成"多采一次"（1 天，零训练）

沿用 11-03 的 H2，未做。RetryRoute 的数字仍然有效：**同模型重试成功率只有首次的 17%–53%**；blind retry 相对同模型重试 **−0.92 / +0.69**；**改写作为路由内一个动作最多 +2.2 点**。

**判据**：若改写收益 ≤ blind retry 收益 → 当前改写没有制造新信息，只是在赌运气。

#### 主线六：多模态视频扩展

##### H14. 视频通道的先决条件已具备，但仍不建议现在做（半天评估）

**依据**：这一轮出现了强相关工作 —— Kling 技术报告（38 页）系统讲了视频生成的输入侧改写（PE）、双奖励模型、分级评测分类体系，而且**它的很多结论在图像上同样成立**（三层对齐、排除项正向化、checklist 保真）。

**建议**：**不要另起一条视频线**，而是把 Kling 的三条规则**先用到图像上**（C1 checklist、C2 排除项正向化、H10 固定槽位）。理由：

| 理由 | 依据 |
|---|---|
| 视频的额外复杂度（时间戳、多镜头、音频）对图像是**纯负担** | Kling Table 19 的任务分类里，视频专属的评测项占了一半 |
| 图像侧的收益还没吃干净 | 我们连"保真"这一维都还没有可归因的量 |
| Kling 自己也没谈安全 | 全文的 safety 只在"评测要暴露捷径"语境里 |

**判据**：等 H1/H2 出结果、且 i2v/t2v 落表数据积累到 **1000 条以上**，再评估是否独立建线。
