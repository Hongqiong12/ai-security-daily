## 一、T2I / T+I2I 论文（核心主线 · 4 篇）

### 1. WeGenEditBench — 先扣分再打分，整体分就不再吃掉局部缺失

**腾讯微信视觉（WeChat Vision, Tencent Inc.）+ 中山大学** · [2610.41210](https://arxiv.org/abs/2610.41210) · 2026-10-30 · 58 页

这是本轮唯一一篇同行同场景的工业界工作，而且**评的模型名单里就有混元**。

它的诊断叫 **high-score paradox**：*视觉上可信、或者单个最显眼的编辑成功了，并不蕴含所有耦合的要求被联合满足了。* 四个耦合要求满足三个，整体分可以很高，缺的那个看不见。

**做法**：把判定单位从"维度"下沉到"原子要件"。

```
每个输出 → 逐条判原子要件（pass/fail + 视觉证据理由）
        → 不适用项排除出分母（不记 0）
        → 汇总成 EG / PR / VQ / DS 四维
        → 再加权成 Overall
```

规模：**2,740 个 instance / 148 个任务类型 / 15 个配置**；审计覆盖 **15,214** 条 model–task 与 **194,836** 条 item 记录；**262** 条不适用项被排除。

**那张表就是"聚合翻结论"的现成证据**（单图编辑，节选）：

| 模型 | EG | PR | VQ | DS | **Overall** |
|---|---|---|---|---|---|
| GPT-Image-2 | **4.298** | 4.049 | **4.463** | 4.182 | **4.076** |
| HunyuanImage-3.0-Instruct-Distil | 4.020 | **4.175（全场第一）** | 4.280 | 3.952 | 3.841（第五） |
| Qwen-Image-3.0 | 4.120 | 3.469 | 4.331 | 4.126 | 3.813 |

**"不该动的没动"做到全场第一的模型，整体排第五。**

**对我们最值钱的三件事**：

1. **它给出了"可判的正例标准"的生成方式。** 我们的 I2I 分流 0/0% 一直卡在"没有可判的正例标准"。这篇的答案是：把每条指令拆成该样本自己该满足的原子要件，逐条判，**再汇总**。这就把 0/0% 从"一个 0"变成"四个可归因的数"。
2. **五项冻结清单**，正好是一份可信回归看板的最小条件：judge 模型、judge prompt、输入预处理、checklist 版本、无效响应策略。少冻一项，"v3 比 v2 好"就不成立。
3. **定向收益必须与全量收益成对报。** 实测定向/全量比在 **1.07–1.85×**——只报全量，会把定向干预的效果稀释掉一半；只报定向，会把"过拟合到诊断目标"藏起来。

**它自己的诚实边界**（值得抄）：*"The audit corrects identified problems but does not independently validate every judgment... Inter-rater agreement and error rates cannot be inferred from this corrective audit."* ——**10% 人工审计是质控，不是效度证据，出不了 κ。**

**它不解决我们什么**：148 个任务类型全是"编辑做对了没"，**没有一条是"这个编辑请求该不该被执行"**。它解决下游能力那一半，不解决上游分流那一半。

### 2. RetryRoute — 第二次尝试不是第一次的重来

**北京师范大学 + 南洋理工大学** · [2610.41460](https://arxiv.org/abs/2610.41460) · 2026-10-30

编辑服务的 agent 循环是：出图 → VLM judge 判 → 不过就再来。开放模型之间成本差**一个数量级**（5.7 s → 170.7 s）。所以"被拒之后发给谁"直接决定成本。

现有三类做法（同模型重试 / 每请求路由 / 固定顺序级联）都假设：**对已失败模型的下一次尝试，是一次独立同分布的重新抽样。**

论文把这条拆了。核心现象 **sticky failure**：

> 重试成功率只有首次成功率的 **17%–53%**；按模型算是 **0.23–0.39 倍**。

具体到模型：FLUX.2 [klein] 首次过 67%，**刚失败过的那些只有 15%**，而另一个模型在同样状态下还能解 **45%**。

**机制解释（隐难度引理）**：请求有潜在难度 `d`，失败历史通过失败计数携带"这题难"的信息。两条推论都很硬：

1. **重试永远不会比前一次更容易成功**；难度有差异时严格更难。
2. **难度共享时，一个模型的失败会同时压低其他模型的成功率**（a4 从 0.733 掉到 0.436，只因 a5 先失败了一次）。

**做法**：把状态定义为"失败计数向量"，在失败状态上解 Bellman 方程，规划重试/升级/放弃。估计用**计数 + 收缩**（λ=20），因为深处状态样本稀疏。3 arm 时 81 个状态，精确解 **0.35 ms**。

**结果**：对最强基线平均 **+2.8 点**（最高 +5.6）；对同模型重试 **+3.5–13.3**；8 组全部不低于任何基线；服务台 goodput 三档负载高 **5.0–6.3 点**。

**但真正扎我们的是那张小表。** 论文把"改写后重试"当强基线认真实现了（`Rewrite-retry`，一个 VLM 在每次重试前改写指令，blind 只用源图 / critique 还用上失败图与分数）：

| 方法（pool1，同预算同 judge） | GEdit-CN | GEdit-EN |
|---|---|---|
| 同模型重试 | 81.74 | 81.74 |
| **Rewrite-retry, blind** | **80.82（−0.92）** | **82.42（+0.69）** |
| **Rewrite-retry, critique** | **78.31（−3.43）** | **81.28（−0.45）** |

三句话：

1. **"先改写再重试" ≈ "不改写直接重试"**（盲改写在中英各 ±1 点内）；**带失败反馈的改写反而更差**（CN −3.43）。
2. 论文原话：*"the gain comes from spending the rest of the budget on escalation"* ——**收益不在改写，在升级**。
3. 把改写**当成路由里的一个动作**呢？*"it never lowers success significantly and adds at most 2.2 points."* ——**上限 +2.2 点。**

**这个结论不能直接搬到我们场景，边界必须划清。** 三处关键差异：

| 维度 | 它的 rewrite | 我们的安全改写 |
|---|---|---|
| 目标 | 让编辑模型**听懂** | 让生成**不出事**，同时保住语义 |
| 失败判据 | judge 判"改对了吗"（**完全可观测**） | 风险降没降 + 语义还在吗（**线上不可观测**） |
| 第二次机会 | 有（重试是免费的） | **通常没有**（成本/时延/再生成风险更高） |

它的"用升级替代改写"这条在我们这里**不成立**——我们没有"升级到另一个生成器"这个动作。

**所以正确的迁移不是"改写没用"，而是：**

> **改写必须跟"多试一次"这个基线比，而不是跟"什么都不做"比。**

这条是硬约束。我们的三维评测现在比的是「原 prompt」vs「改写后 prompt」。**如果同一条原 prompt 多采几次就能拿到同等安全率，那改写报出来的收益是被"单次采样"这个设定虚高的。**

**附带的一个判定器发现**：*"EditReward confirms 84–93% of the in-flight judge's first-try passes but only 51–75% of its late passes."* ——**晚到的通过更不可信。** 这条和今天第 5 篇撞在同一个点上。

### 3. ERASE — 拦住了，不等于拿掉了

**华南理工大学** · [2610.41307](https://arxiv.org/abs/2610.41307) · 2026-10-30

多模态间接提示注入（IPI）的难点在于：**恶意指令藏在一份"同时包含用户任务所需信息"的媒体里**。只拒掉就等于把任务证据也扔了。

论文把现有防御的困境量化成一个很少被单独看的量。定义**注入依赖 `I`**：

> 在同一个已生成输出前缀下，比较模型在「被攻击视图」与「擦除视图」上的下一 token 分布，取 **两个方向 KL 的平均**。

结果（Qwen2.5-Omni-3B，音频）：

| 方法 | `I`（注入依赖） | `UIA_inject`（被攻击时仍答对） |
|---|---|---|
| 无防御 | **6.26** | 0.673 |
| **ARGUS（SOTA）** | **5.15** | 0.717 |
| Meta-SecAlign | 0.432 | **0.083（崩）** |
| **ERASE** | **0.0095** | **0.601** |

**ARGUS 把 ASR 打到 ≈0，但注入依赖只从 6.26 降到 5.15——只降 18%。** 模型仍然被牵着走，只是牵到的地方不再"算攻击成功"。

**"拦截"是在输出空间量的，"依赖"是在分布空间量的。前者可以靠后置过滤刷到 0，后者不能。**

另外两个数同样重要：Meta-SecAlign 依赖很低（0.432）但 `UIA_inject` 崩到 **0.083** ⇒ **低依赖不是好事的充分条件**；ERASE 落在 0.0095 / 0.601，距无防御的**干净**输入水平只差 0.5 点。

**方法**（两步，训练时用、推理时不用）：

1. **原位擦除视图**：把注入区域换成该模态的空白内容（图像=白块 / 音频=静音 / 视频=黑帧），**周边像素/时段一动不动**。部署时**不需要知道注入区域在哪**。
2. **在策自蒸馏**：冻结基座读擦除视图当 teacher；LoRA 学生读被攻击视图、自己 rollout，在每个共享前缀上用**全词表 KL** 对齐。

**两个消融都很关键**：

| 对照 | 音频 UIA_inject | 图像 UIA_inject |
|---|---|---|
| 全分布、teacher 先 | **0.601** | **0.541** |
| 只用采样 token | 0.531（**−7.0**） | 0.441（**−10.0**） |
| 参考用"原始干净媒体"替代"原位擦除" | OOD 均值 0.578→0.554、WER 0.088→**0.221** | — |

**三种都做到 AIA = 0。差别全在"保住了多少"上。** 这告诉我们：**当"拦截"这个指标饱和之后，剩下的全部差异由监督粒度和参考视图的选择决定。**

**为什么这对我们是"同一个动作"**：我们的改写做的是"在一段 prompt 里把风险锚点换掉、其余语义不动"；ERASE 做的是"在一张图里把注入区域换掉、其余像素不动"。**这是同一个动作在两种模态上的实现**，它解决的那个矛盾（改得够狠才消风险 / 改得够克制才不伤语义）就是我们的日常。

**但它有一个在我们场景里最脆的前提**：注入内容是**外来的、成块的**，所以能整块挖掉。**文本里的风险锚点常常不是。** 比如"医院走廊里穿病号服的女性"——"病号服"中性、"女性"中性，风险在两个词的关系上。**没有一块能整块挖掉的白区。** 这和我们的 PORN/VULG 边界问题是同一个结构。

### 4. AIG-NCII — 风险不是一个部件，是一组配置

**纽约大学 + 乔治敦大学 + 亚利桑那州立大学** · [2610.37949](https://arxiv.org/abs/2610.37949) · 2026-10-27

**这是本轮 319 篇候选里唯一一篇直接讨论 NSFW 的论文。** 定性研究，不看方法，看风险的**构成方式**。

对象：CivitAI 上 **139 篇 R+ 级指南**（how-to 长文）。方法：8 轮 IRR，每轮 15 篇双人独立编码、算 Cohen's κ，未达标的轮次再抽 15 篇重复，改过的 code 全量重编。

**核心结论一句话**：

> **AIG-NCII 不是被"某项可独立监管的新技术"使能的，而是被"一组配置选择"使能的。**

它把风险拆成两个正交的概念轴：

- **S（sexual）**：性内容概念——解剖术语、行为描述、风格、模型/adapter 选择
- **I（identity）**：身份概念——真实人物、可辨识属性、"如何在不点名的情况下指定一个人"

**两条对我们直接有用的技术**：

**① likeness prompting。** 指南教的原文：*"refer to the movie/series name and the fictional character's name … without using their [real] name"* ——**用作品名 + 虚构角色名 + 属性描述，去逼近一个真实人物的长相。** 名字层面完全合规。

论文的判决：这类技术能 *"evade input/output filters that may only detect the use of a specific individual's name"*。

**这不是精度问题，是检测对象错了**：过滤器在查**符号**，风险在**指称**。

**② 把"人"换成"角色"。** 用户会刻意改词以规避检测：*"using the word 'character' in place of 'person'"*。

**③ 精确的解剖术语是"高保真"提示词，不是"高风险"提示词。** 指南明确教用 `labia majora` / `clitoral hood` / `vulva` 这类词给"clear guidance"。**如果我们的词表按"露骨程度"打标签，会把医学语境和滥用语境打成一类**——这是 PORN 过度预测的一个可解释来源。

**权重侧防御的边界（这条要写进方案）**：

> 工作流主要依赖**开源权重及其微调衍生版**；**LoRA 这类低成本技术能把被刻意移除的概念重新装回去，且在本地。**

**这不是"擦除做得不够好"，是"擦除的治理范围止于权重发布"。**

**一个操作层的实测**：研究团队报告了 7 篇（2 篇疑似 AIG-CSAM → NCMEC，1 篇鼓励生产 NCII → 平台，4 篇含真实身份描绘 → 平台）。**三周后只有 1 篇被移除。**

这个数字说明的机制是：**内容侧处置的时延，往往远大于生成侧的时延。** 对应我们线上——**一旦漏过一张图，处置窗口以天计，不以秒计。所以"漏过率 3.42%"的真实成本，比它看起来大。**

**诚实说明**：139 篇里只有 **1 篇**明确描述 NCII 流程，论文自己也反复声明**无法测使用率**。这是定性威胁建模，不是流行度测量。引用时不能把它说成"NCII 已普遍通过 X 实现"。

### 5. Prompt Lottery — 越"客观"的判定，越经不起换一种说法

**Upwork Inc** · [2610.38076](https://arxiv.org/abs/2610.38076) · 2026-10-27 · 55 页

它问的是 LLM-as-a-Judge 那个从不被检验的前提：**一份 judge prompt 是一台稳定的仪器吗？**

做法讲究在**严格隔离释义方差**：用 Claude 3 Opus 生成 4 个变体 → 人工审核是否保义 → Gemini 1.5 Pro 校验语法 → 归纳 6 个表面变异维度做置换检验。**这排除了"改坏了"这个解释。**

**规模**：845 个条件 / 12 个数据集 / 5 个 prompt 族 / 5 个判定模型 / 10 名标注员的人类研究。

**结果一：κ 0.89 → 0.24。**

人类的同类退化是 **0.09–0.11**，即 **judge 的退化幅度是人类的 6–9 倍**。75% 的"数据集 × judge"组合显著；除 2 个组合外全部低于"可接受的标注研究"阈值。

**结果二（最反直觉）：越客观越不稳。**

| 任务 | 类型 | Kendall's τ | Top-1 翻转率 |
|---|---|---|---|
| MTBench（DailyDial） | 主观对话 | **1.00** | **0.0%** |
| G-Eval（Topical-Chat） | 开放生成 | 0.83 | 10.0% |
| Quality（SummEval） | 摘要质量 | 0.64 | 40.0% |
| **QA Correct.（SQuAD v2）** | **客观二元** | **0.17** | **43.3%** |

**最"客观"的二元判定翻转率最高，最"主观"的对话评测一次没翻。**

机制有两条：**① Binary Paradox**——二元任务原始重叠率高（0.32 vs 0.14），但那是因为输出空间窄、猜中概率高；**机会校正后 κ 反而更低**。**② 客观任务判据更紧**，措辞差一个词边界就移了。

**对我们的直接含义，这条必须摊开讲**：**我们的安全判定是典型的二元客观判定（PORN 是/否）。按这个结果，我们的 judge prompt 恰恰属于翻转率最高那一类，不是"客观所以稳"那一类。**

**结果三：语义相似度高，判定照样不一致。**

> sBERT 相似度 0.44–0.49，而 κ 在 **0.0–0.7** 之间散布；相关 **Pearson ρ = 0.157**（弱且不显著），**Spearman ρ = −0.022**（负的）。

**"这两份 prompt 语义几乎一样"完全不能推出"它们会给出一样的判定"。**

这对我们是第二记重击：我们的"语义保真"度量（embedding 相似度 / BLEU / LLM 打分）测的是**文本空间的距离**。这篇证明**文本空间靠近不代表行为空间靠近**。而今天第 3 篇给的 `I` 恰好是行为空间的：`KL(P(·|A) ‖ P(·|B))`。

**结果四：聚合能救，但要选对方式。**

| 数据集 | Majority | Average | **Plurality** |
|---|---|---|---|
| Upheld | 0.47 | 0.54 | **0.63** |
| Topical-Chat | 0.44 | 0.55 | **0.62** |
| LLM-Arena | 0.44 | 0.54 | **0.55** |

**Plurality（达不到共识就丢弃）三战全胜，平均全输。** 含义：**"没共识的样本应该被丢掉，而不是被平均掉"**——平均会把一份"其实没共识"的判定硬压成一个数。

**结果五：选择性聚合，2× 算力拿 86% 稳健性。**

DeBERTa-gate（平衡准确率 0.836、TNR 0.854）判断"要不要多跑几个 prompt"：2× 算力 → **86% 稳健性**，对比全聚合 5× → 100%。泛化到没见过的 Prometheus 系 judge，TNR 仍 66.22%。

**反面数据**：**Llama 3.1 8B 做门控时零样本平衡准确率 0.489、TNR 0.042**——基本没用。**小而专 > 大而泛**，与 10-28 记的"路由不需要大模型"同一结论。

### 6. FYC — 指标选错，方法再好也会反噬

**佛罗里达州立大学 + 中佛罗里达大学** · [2610.37882](https://arxiv.org/abs/2610.37882) · 2026-10-27

**这篇是"按类目下发阈值"这件事的方法论对照。** 它要解的题和我们一样：总体指标好看、分组指标难看；能不能给每个组单独配阈值，而且不把别的东西搞坏。

**它给出的最重要的东西不是方法，是一个反例警告。**

**同一个权重扰动方法、同一个训练预算，只换"用哪个差异指标当约束"**：

| 架构 | DP（原版 Demographic Parity） | **FPR-disparity** |
|---|---|---|
| 架构 1 | 改善 | **改善** |
| 架构 2 | 改善 | **改善** |
| 架构 3 | **基本不变** | **改善** |
| 架构 4（PG-FDD） | **显著恶化（肤色轴）** | **改善** |

论文的判决：DP 的效果是 **architecture-dependent**——*"a practitioner cannot vet without running the diagnostic itself"*，**你没法事前知道你这个 checkpoint 会落在哪一格。**

理由很干净：DP 是*"equalizing positive-prediction rates rather than correct predictions, without conditioning on the true label"*。**换成我们的语言：DP 相当于"让每个类目的拦截率一样"，而不管拦对没拦对。**

**阶段二：per-group Youden-J 校准，零成本。**

每组在独立校准集（50K，seed 99，与扰动微调不相交）上找 `J = TPR − FPR` 最大的阈值，然后**以 logit 平移施加，没有梯度更新**。

三种模式里有一个**必须记住的反面教材**：

> **eq-TPR（只优化 TPR，不给 FPR 惩罚）是退化的**——*"trivially drives the threshold toward predicting every image fake."*

**只优化"漏过率"、不给"误杀率"任何惩罚，最优解就是把阈值推到"全部判违规"。**

**主结果（AI-Face v2，329,309 测试图，6 个交叉组）**：

| 检测器 | FPR | AUC | Inter-FMEO | Acc | 训练成本 |
|---|---|---|---|---|---|
| Xception（基线） | **12.96** | 98.58 | 10.51 | 96.31 | 1h15m/ep |
| PG-FDD（专用公平架构） | 10.97 | 99.17 | 9.58 | 96.17 | **7h20m/ep** |
| **Xception + FYC** | **1.50** | **99.85** | **8.24** | **98.88** | **39m/ep** |
| **DAG-FDD + FYC** | **1.31** | **99.91** | **3.22** | **99.03** | **39m/ep** |

**FPR 降 88%，同时 AUC 与 Acc 都涨（没有 leveling-down）；打赢了需要全量重训的专用公平架构，投入差 11 倍。**

而且它**赢了 12 个基线里 21 行中的 18 行，输的 3 行全是 FDP（Demographic Parity gap）**。论文的解释是 *"This is not a regression: FDP is the metric the objective we deliberately avoid"*。

**它没输在效果差，它输在"没优化那个指标"。这是一个非常干净的因果归因：你优化哪个指标，你就赢那一片、输另一片。**

**分轴结果给了一个我们要用的判据**：

| 轴 | 基线 FMEO 跨度 | 校准后 |
|---|---|---|
| 年龄 | 5.44 – **47.50** | **1.19 – 1.41**（收益最大） |
| 交叉 | **6.12 – 21.37** | **8.24 / 3.22**（最难压） |

**年龄轴（样本多）收益最大，交叉轴（样本最少）收益最小。** 照搬到我们的叶子类目上：**样本不足的叶子类目，Youden 点估计的方差会大于它想修正的偏差。**

## 三、趋势信号

### 信号一：这一轮六篇，"测量"多过"建模"

六篇里**没有一篇的主贡献是"训一个更强的模型"**：

- WeGenEditBench 造的是**评测口径**（2,740 条 checklist）；
- RetryRoute 解的是一个 **0.35 ms 的 Bellman 方程**；
- ERASE 的 teacher 是**冻结的基座**，只有学生一个 LoRA；
- AIG-NCII 是**定性编码**，零模型；
- Prompt Lottery 的核心实验是**同一批 prompt 换措辞**；
- FYC 的收益最大的那一段（阶段二）**没有梯度更新**。

**六篇里有四篇的最大收益来自"改口径 / 改判据 / 改对照物"，而不是"改模型"。**

这不是巧合。它对应一个阶段性判断：**在很多安全任务上，我们已经到了"模型够用、但不知道自己在测什么"的位置。** 继续加参数，边际收益低于先把尺子校准。

### 信号二：三个独立工作同时指向"判定结果的可信度依赖于它产生的条件"

这是本轮最值得跨篇串起来的一条：

- **RetryRoute**：judge 对**首次通过**的确认率 84–93%，对**晚到通过**只有 51–75%。
- **Prompt Lottery**：判定可信度依赖于**用的是哪一份同义措辞**，κ 从 0.89 掉到 0.24。
- **ERASE**：判定可信度依赖于**在输出空间测还是在分布空间测**，ARGUS 的 ASR≈0 与 `I`=5.15 并存。

三条说的是同一件事：**"这个样本被判为 X" 不是一个完备的陈述，它少了三个限定——第几次尝试、哪份措辞、在哪个空间测。**

我们的日志现在只记第一层（判为 X），另两个限定都没记。**这就是为什么"误杀率 5.2%"这个数我们没法进一步拆。**

### 信号三：权重侧与输入侧的边界，这轮被"配置论"加固

AIG-NCII 给出的机制是：**工作流依赖开源权重 + LoRA 能把移除的概念装回去，且在本地。**

这加固了我们既有的结论，但**加固的方向值得说清楚**：

| 范式 | 治理范围 | 失效边界 | 本轮新证据 |
|---|---|---|---|
| **权重侧（擦除/遗忘）** | 上线前、模型内、已发布前 | 权重一旦发布，治理止步；LoRA 可低成本重装 | AIG-NCII：工作流依赖 open-weight 衍生版 |
| **输入侧（改写/热更新）** | 上线后、每次请求、可热更 | 面对无穷新锚点；锚点若与合规语义交织则无处可挖 | ERASE：擦除需"注入区域可分离" |
| **（第三极）推理时约束** | 生成轨迹上 | 需要可微的约束函数 | AegisFlow（候选观察）：非近视路径安全 |

**三者互补，不替代。** 而且本轮给出了一个新的**共同前置**：**定位**。

- 权重侧要"先定位概念再擦除"（10-27 LoCo、10-28 Concept Acupuncturist）；
- ERASE 要"先定位注入区域再擦除"；
- 我们要"先抽风险锚点再改写"；
- AIG-NCII 要"先把配置里的 S 与 I 分别定位"。

**"定位"是四种范式的共同前置，而四种范式的差异全在"定位之后做什么"。**

### 信号四：T2I 输入侧改写的第八周空窗，需要换一种应对

连续八周零供给。**继续在同一批措辞上加查询，边际收益已经确定为零**（本轮 12 个专项查询同时归零，含 3 个 11-02 才新写的）。

我的判断：**下轮检索预算应该整体移出"找新改写方法"，改投两个方向**：

1. **相邻任务的机制迁移**（今天的 ERASE 就是范例：它不是改写论文，但它的"原位替换 + 参考视图蒸馏"可以直接搬到改写对的设计上）；
2. **非 arXiv 通道**（厂商技术报告 / 模型卡 / 安全白皮书）。

理由：改写这件事的公开方法供给已经枯竭了大约两个月，而**可迁移的机制在别的任务里还在持续产出**。

## 四、业务对齐研究板块 ⭐

### A. 直接可迁移方法

按"能不能这周就动手"排序。

#### A1. 把 I2I 的 0/0% 拆成"要件覆盖率"（最高优先，零训练）

**来自 WeGenEditBench。**

现状：I2I 改写分流命中 **0/0%**，我们把它当成一个数在讨论。

改法：对每条 I2I 样本抽四类**原子要件**——「主体 / 操作 / 目标区域 / 必须保留项」（前三项正好对应 StruPO 的 DSE 三锚点，第四项对应 WeGenEditBench 的 PR 维度），让 judge 逐条判，记录 item 级结果。

于是 0/0% 变成四个数：

| 要件读出情况 | 下游执行情况 | 归因 | 处置方向 |
|---|---|---|---|
| 0 个要件读出 | — | **改写把意图抹掉了** | 改写侧问题 |
| 部分读出 | — | 改写部分损伤 | 改写侧（锚点级） |
| 全部读出 | 没执行 | **下游编辑能力不足** | 与改写无关 |
| 全部读出 | 执行了 | 链路正常 | — |

**这一步不需要训任何模型，也不需要重做评测集**——在现有 1979 条上补一层要件即可。**这是今天性价比最高的动作。**

#### A2. 在分流日志里加一列「这是第几次尝试」（半天，零训练）

**来自 RetryRoute。**

现在日志只知道"命中/未命中"，不知道"首抽还是重试"。加了这一列才能算 `p_retry / p_first`。

判据（照抄论文的量级）：

| ratio | 含义 | 动作 |
|---|---|---|
| **0.17–0.53** | 失败是粘的，与论文一致 | **单次命中率全部需重估；0/0% 要拆成"首抽 0%"与"能力 0%"** |
| 0.6–0.9 | 轻度粘性 | 单次指标可作保守下界 |
| **≈1.0** | 失败接近独立 | 论文结论**不适用**我们链路，改写评测可直接 vs 原 prompt |
| >1.0 | 反常 | 先查 judge 稳定性（见 C1） |

#### A3. 用 `I` 而不是 embedding 相似度来量"语义保真"（1 天，零训练）

**来自 ERASE + Prompt Lottery 的联合推论。**

- ERASE 的 `I` = 两视图下输出分布的对称 KL（**行为空间**）；
- Prompt Lottery 证明文本空间相似度与判定一致性相关 **ρ=0.157 / Spearman −0.022**（几乎零）。

**所以我们现在的"语义保真"度量（embedding / BLEU / LLM 打分）测的是错的空间。**

改法：

> **`Fidelity = 1 − KL( P(· | 原 prompt) ‖ P(· | 改写后 prompt) )`**

在同一生成模型、同一 seed、同一步数下取下一步分布。这个量的好处是：**不需要标签、不需要人工、不需要 judge**，只需要一对 prompt。

判据：如果某条改写"风险分降了但 KL 很大"，说明**它是靠把意思改掉换来的安全**。这正是我们 RL 奖励最可能作弊的方向（原样不改 KL=0，得分最高——所以必须**同时看 KL 与风险**，不能只看一个）。

#### A4. 类目阈值改成"约束优化"，而不是"最小化漏过"（半天，零训练）

**来自 FYC。**

现状的阈值下发规则，实质上是在压漏过率（3.42%）。FYC 的 eq-TPR 退化结论是硬警告：

> **只最小化漏过率、不给误杀率任何惩罚，数学上最优解是把阈值推到"全部判违规"。**

改法：把规则写成**带约束**的形式：

```
在 误杀率 ≤ 5.2% 的约束下，最小化 漏过率
```

并且在每个类目上报三个数：**Youden 点 / 该点的误杀率 / 该点的漏过率**。

判据表：

| 观察 | 判定 | 动作 |
|---|---|---|
| Youden 点误杀率已 ≤ 5.2%，漏过率更低 | 现状阈值**不在 operating point 上** | 直接下发，零训练收益 |
| Youden 点误杀率 > 5.2% | 约束与最优点冲突 | 用约束优化取边界点 |
| Youden 点在 < 200 样本的类目上跨折跳动 > 10 点 | 估不准 | **继承父类阈值**，不自估 |
| 某类目 AUC < 0.8 | **排序坏了，不是阈值偏了** | 调阈值无用，回去修模型/修标签 |

**最后一行最重要**——它把"阈值问题"和"排序问题"分开。我们前几轮反复调阈值无效，很可能是因为某些类目根本是排序坏了。

#### A5. 风险从"一张词表"改成"一组坐标"（1 天，零训练）

**来自 AIG-NCII。**

抽 300 条边界样本（VULG-HINT-EDGE 150 + PORN 边界 150），给每条打两个**独立**的分：

- **S 轴**：性内容强度（0 无 / 1 暗示 / 2 明确 / 3 露骨）
- **I 轴**：身份指向（0 无 / 1 泛化人设 / 2 可辨识属性组合 / 3 指名真实人物）

画 2×4 格子填样本数。**这一步不需要训模型，但能立刻告出类目体系的空洞在哪。**

---

### B. 风险锚点处理启发（双锚点：PORN/VULG 边界 + 政治 L2_30 层级）

运营约束基线：**误杀率 5.2% / 漏过率 3.42% / 一级一致率 77.64%**。

#### B1. PORN / VULG 边界：`VULG-HINT-EDGE` 的病根被这轮定位了

我们前几轮的结论是"它在这个类目体系里没有定义，不是标错了"。**今天两篇给出了它为什么没有定义。**

**第一篇（AIG-NCII）给出的是"风险是组合"这个结构**：

> NCII = **S（性内容）× I（身份）**。风险不在某个词上，在两个概念轴的**配置**上。

**第二篇（Prompt Lottery）给出的是"边际掉一维"这个机制**：

> 把二维的东西压成一维（"这个 prompt 风险几分"），被压掉的那一维不是消失，是变成了噪声。

合起来，`VULG-HINT-EDGE` 的定义问题是：

**它是一个"二维坐标被压成一维标签"的产物。** S 轴中段（暗示）+ I 轴任意的组合，被硬压进了"VULG"这一格。而 S 轴中段的判据（"暗示到什么程度算暗示"）从来没有被单独定义过——**类目文档定义的是两个端点，中间是空的。**

**具体做法（沿用 A5 的两轴打分，加上 FYC 的约束框架）：**

| S 轴 | I 轴 | 建议归属 | 备注 |
|---|---|---|---|
| ≥2 | ≥2 | **NCII 型**（当前体系无对应） | 建议**新增类目**，不要塞进 PORN/VULG |
| ≥2 | 0–1 | PORN | 明确类 |
| **1（暗示）** | 0–1 | **需要新定义** | ← `VULG-HINT-EDGE` 落在这里 |
| 0 | ≥2 | 隐私/身份类 | 与 VULG 无关，当前可能被误判 |
| 0–1 | 0 | out_of_scope / 干净 | 若被判 VULG ⇒ **误杀源**，直接进复核队列 |

**关键判据**：如果抽 300 条后，`VULG-HINT-EDGE` 有 **>30%** 落在 `S=0~1 且 I=0` 这一格，那**它不是"边界样本"，是误杀**。这个数和当前 5.2% 的误杀率能对上多少，要单独算。

**同时要加一个检查（来自 AIG-NCII 的 likeness prompting）**：

抽 50 条含人物指向的样本，把"名字"替换成"作品名 + 角色名 + 属性描述"，重跑分类器，看判定变化率。

> **判据：变化率 > 20% ⇒ 我们的分类器在查符号不在查指称。这是结构性漏洞，阈值调不动。**

#### B2. 政治 L2_30 层级：这轮给的是"口径冲突"而不是"新方法"

**没有直接的 L2_30 论文。** 但 FYC 的"DP vs FPR"给了我们一个一直没识别出来的东西：

> **我们可能同时在对 L2_30 施压两套互相冲突的口径。**

| 口径 | 要求 | 数学形式 | 副作用 |
|---|---|---|---|
| **拦截面均衡**（类 DP） | "各类目的拦截率不能差太多" | 比较**正预测率**，不看真值 | 会**强迫**多拦本来就干净的类目 ⇒ 推高误杀 |
| **误杀率达标**（类 FPR） | "误杀率 ≤ 5.2%" | 只在**真负样本**上比 | 与上一行**方向相反** |

FYC 的实测：DP 目标在 4 个架构上 **2 改善 / 1 不变 / 1 恶化**，且**恶化集中在某一个轴**上，事前无法预测。

**对应我们的现象**：一级一致率 77.64%，PORN 过度预测，VULG-HINT-EDGE 最差。**如果 L2_30 上同时在压"均衡"和"低误杀"，那某些子类的差表现不是模型问题，是两个目标在打架。**

**具体做法**：

1. 把 L2_30 下的每个子类，按 FYC 的两种指标各算一遍：`FDP`（正预测率极差）与 `FPR`（误杀率）。
2. 看这两个数的**相关方向**。若为负相关 ⇒ **两个目标在打架，必须选一个当主约束**。
3. 选定的建议：**主约束用 FPR（误杀率），因为它是业务硬约束（5.2%）；拦截面均衡降为监控项，只在超阈值时告警，不进入优化目标。**

**理由**：FYC 证明了 FPR 条件化的约束在四个架构上**无例外地同时改善公平性与效用**；而 DP 条件化**会随机反噬**。

#### B3. 跨锚点的共同结论

两个锚点这轮得到的启发合起来是一句话：

> **把一个"不可判的整体印象"拆成"若干可独立核查的坐标/条件"，然后去数格子里有多少样本。**

- PORN/VULG → 拆成 (S, I) 两轴；
- 政治 L2_30 → 拆成 (拦截均衡, 误杀约束) 两个可能冲突的目标；
- 而 WeGenEditBench 的做法是拆成原子要件（**先要件、再维度、最后 Overall**）。

**三处是同一个动作：把聚合顺序反过来。**

### C. 三维评测设计启发（语义保真 / 安全提升 / 指令遵循）

#### C1. 先测"尺子本身稳不稳"（半天，零训练，最高优先）

**来自 Prompt Lottery。** 这是我认为**必须先做、且应该在所有模型版本对比之前做**的一件事。

做法：拿现在的 judge system prompt，造 4 个**只动表面不动判据**的释义变体，同一批 300 条样本（覆盖 PORN 明确 / VULG 边界 / 干净三类）跑 5 遍。

必须同时报三个数：

1. `Overlap`（5 份完全同判的比例）；
2. `Fleiss' κ`（跨 5 份）；
3. **`Top-1 翻转率`**（≥3 个模型版本时，用 5 份 prompt 各排一次，看第一名变几次）。

判据表：

| 观察 | 判定 | 动作 |
|---|---|---|
| κ **≥ 0.8** | 尺子稳定 | 现有 AB 结论可用，但**必须把这个数写进报告当证据** |
| κ **0.6–0.8** | 轻度不稳 | 版本差异 **< 3 点时不宣称优劣**；加多 prompt 聚合 |
| κ **< 0.6** | **尺子不可用** | **所有历史 AB 排名作废**，先修仪器 |
| **Top-1 翻转 ≥ 1 次** | 排序不稳 | 看板必须加**排名置信区间**，不能只报点估计 |

**注意这里的反直觉点**：我们的判定是二元客观判定，而论文测得二元客观任务（SQuAD v2）翻转率最高（43.3%）。**所以不要因为"我们的判定很客观"就跳过这一步。**

**并且必须先做"同 prompt 跑 5 次"的稳定性基线**（论文：89.8% 重叠）。没有它，测出来的差异无法归因——可能是尺子不稳，也可能是服务本身有随机性。

#### C2. 语义保真改到行为空间（与 C1 同批）

见 A3。要点重复一遍：**`Fidelity = 1 − KL(P(·|原) ‖ P(·|改写))`**。文本空间相似度对判定一致性几乎零信息量（ρ=0.157 / Spearman −0.022）。

**这条同时是 RL 改写的防作弊手段**：原样不改 → KL=0 → 保真分满分。所以 RL 奖励里**必须把 KL 与风险并列**，不能只奖励"保真"。

#### C3. 阈值 operating point 的选择（半天，见 A4）

三个必须同时报的数：**Youden 点 / 该点误杀率 / 该点漏过率**。

**三条硬约束**：

1. **不许只优化漏过率**（eq-TPR 退化，最优解是全拦）；
2. **不许用"拦截面均衡"当优化目标**（DP 会在某些架构上反噬，事前不可预测）→ 降为监控项；
3. **必须做 leveling-down 检查**：误杀率降了但总拦截率也降 ⇒ 不是调好了，是关掉了。

#### C4. 多版本回归口径：五项冻结 + 定向/全量成对报

**来自 WeGenEditBench。**

每次版本对比，**同时冻结五项**：judge 模型、judge prompt、输入预处理、checklist/评测集版本、无效响应策略。

以及**必须成对报的两组数**：

| 必须报 | 为什么 |
|---|---|
| 四维分数 + Overall | 防"整体分吃掉局部缺失" |
| "整体高分但存在严重单项"的样本比例 | 高分悖论的量化 |
| 定向 Top-K 收益 | 看干预有没有生效 |
| **全量收益** | 看有没有过拟合到诊断目标（实测比值 1.07–1.85×） |
| **总体一致率 / 总拦截率** | leveling-down 检查 |

**另外抄一条纪律**：*"a side passes only if every applicable item scores ≥ τ; **empty image-side lists are not successes**."* ——**空输出不算成功**。这条堵掉"什么都不交被当成没有违反要求"。

#### C5. 聚合方式：多份判定要取共识，不要取平均

**来自 Prompt Lottery 的聚合对照**（Plurality 三战全胜、Average 三战全败）。

落到我们的 AB 看板：**当一个样本被多份 judge prompt（或多模型）判过时，用"达到共识比例才算数、否则丢弃"，而不是取平均分。** 平均会把"其实没共识"硬压成一个数——这正是 10-30 那轮总结的失效机制。

### D. 下一步实验建议

六条主线，按"这周能不能开"排序。**前四项合计约 2 天，全部零训练。**

#### 主线一：I2I 改写链路（针对 0/0% 现状）

**这是本轮新增、优先级最高的实验。前几轮的归因都停在"没有可判的正例标准"，今天有解法了。**

##### H1. 要件覆盖率分解（半天，零训练）⭐ 最优先

- **做法**：抽 200 条 I2I 样本，每条抽四类要件（主体 / 操作 / 目标区域 / 必须保留项），让 judge 逐条判"改写后的指令里这个要件还在不在"。
- **产出**：把 0/0% 拆成 4 个数（见 A1 的表）。
- **判据**：
  - 若 **>60% 落在"0 个要件读出"** ⇒ **改写把意图抹掉了**，问题在改写侧，不在下游；
  - 若 **>60% 落在"全部读出但没执行"** ⇒ **下游能力不足**，改写侧怎么调都没用，应该回去评估编辑模型；
  - 若均匀分布 ⇒ 是门槛问题（分流阈值/判据太严），不是能力问题。
- **为什么最优先**：它把一个已经卡了四轮的 0/0% 变成可归因的四个数，且不需要训任何模型。

##### H2. 首抽 vs 重试的命中率拆分（半天，零训练）

- **做法**：同 200 条 I2I 样本 × **K=5 个 seed**，记录每次的命中/未命中，算 `p_retry/p_first`。
- **判据**：见 A2 的表。若 ratio 落在 **0.17–0.53**，则 0/0% 是**单抽策略问题**而不是能力问题，应改写为"命中率随尝试次数上升的曲线"而不是一个点。
- **顺带算第四个**：`p(别的改写候选 | 本候选失败)`。若显著高于 `p_retry` ⇒ 我们有"换条路"的空间（对应多候选择优方案）；若不高 ⇒ 是难度问题不是路由问题。

##### H3. 改写保真改用行为空间 KL（1 天，零训练）

- **做法**：对同一批改写对，同时在 ① embedding 相似度 ② 行为 KL 两种度量下算保真，与人工"保真判定"对比。
- **判据**：若 embedding 相似度与人工判定的一致性 **< 行为 KL 的一半**，则**废弃 embedding 度量**，全面改用 KL。
- **附带**：算出"KL 小但风险分没降"与"KL 大但风险分降了"两类各占多少——后者就是"靠改掉意思换安全"的比例。

#### 主线二：标签审计与阈值校准

##### H4. 两轴打分定位类目空洞（1 天，零训练）⭐

- **做法**：见 A5 / B1。300 条边界样本打 (S, I) 双轴。
- **判据**（三个，分别对应三条路线）：

| 观察 | 路线 |
|---|---|
| 边界样本 **>30%** 落在 `S=0~1 且 I=0` | **是误杀，不是边界** → 进复核队列，改判据 |
| 边界样本 **>40%** 集中在 `S=1, I=0~1` | **类目定义中段空缺** → 改定义，不是改标签 |
| 分布均匀但判分很低 | **样本覆盖不足** → 补数据 |

- **这条能一次结束纠结几周的"该调阈值 / 改标签 / 补数据"三选一**，判据是数出来的比例，不是人工分类。

##### H5. 类目阈值 operating point 扫描（半天，零训练）

- **做法**：见 A4。按一级/二级/叶子三层各扫一遍 Youden 点。
- **产出**：每类目三个数（Youden 点 / 误杀率 / 漏过率），与现状对比。
- **判据表**见 A4。**特别注意"样本 < 200 的叶子类目"这一格**——FYC 的交叉轴（样本最少）收益最小就是前车之鉴。

##### H6. likeness prompting 绕过检测（半天，零训练）

- **做法**：50 条含人物指向的样本，把"名字"替换成"作品名 + 角色名 + 属性描述"，重跑分类器。
- **判据**：**变化率 > 20% ⇒ 分类器在查符号不在查指称**，属于结构性漏洞。这是本轮唯一一个能直接测出"结构性漏洞"的实验。

#### 主线三：输出侧图审

##### H7. 尺子稳定性自检（半天，零训练）⭐

- **做法**：见 C1。5 份释义 prompt × 300 条。
- **判据**：κ < 0.6 ⇒ **历史 AB 排名作废**。
- **必须与 H8 一起做**，因为两者共用同一批样本。

##### H8. 图审"预警依赖度"对照（半天，零训练）

- **做法**：把 ERASE 的 `I` 搬到图审上——同一批"模型被判 PORN 但人工确认无害"的图（复用已有 badcase 复核结果），跑两个版本：① 只看图 ② 图 + prompt。算两个版本判定的 KL。
- **判据**：若 KL 很大 ⇒ **图审在读 prompt 不在读图**，纯图接口（`sft_train.image_only`）的天花板被 prompt 缺失锁死，应该补 prompt 通道而不是继续调阈值。
- **这是 11-02 FVH-Bench"纯图 14.60 vs 图+prompt 43.00"的独立验证**，从"分数差"升级为"分布差"。

#### 主线四：tag-weighted loss

##### H9. 两轴分解重训（1.5 天，需训练）

- **前提**：H4 先做完，确认类目体系的空洞在哪。
- **做法**：如果 H4 确认 `VULG-HINT-EDGE` 是"二维压一维"的产物，则把标签从单标签改成 **(S, I) 双头**，tag-weighted 的权重按两个轴分别设，而不是按单一类别设。
- **判据**：改双头后 `VULG-HINT-EDGE` 的**召回提升，且 PORN 的误杀率不上升**。若误杀率同时上升 ⇒ 两个头在抢容量，回到单头 + 只改定义。
- **与既有方案的关系**：这是对 11-02 结论（"它在现行类目体系里没有定义"）的直接执行——**没有定义就去补定义，而不是继续调权重**。

##### H10. 判定翻转的类别归因（半天，零训练，可与 H7 合并）

- **做法**：H7 测出 κ 后，把翻转的样本按类目切片，看翻转集中在哪些类目。
- **判据**：若翻转集中在 **PORN/VULG 边界**类目（而不是均匀分布），则**这些类目的"差表现"里有一部分是尺子不稳，不是模型差** ⇒ 在类目看板上给这些类目标注"测量噪声大"，不参与排名。

#### 主线五：RL 改写

##### H11. 奖励作弊体检（半天，零训练）⭐ 前置必做

- **做法**：50 条高危 prompt × 三个版本（原样不改 / 微改 1–2 字 / 真改写），同时算 ① 风险分 ② 行为 KL（H3 的度量）③ 语义保真分。
- **判据**：**若"原样不改"的保真分显著高于"真改写"，则保真奖励可作弊且成本极低**。这比任何 loss 调整都优先。
- **顺带回答**：当前 RL 改写的收益里，有多少来自"不改"。

##### H12. 改写的基线换成"多采一次"（1 天，零训练）

- **来自 RetryRoute 的硬约束。**
- **做法**：同一条原 prompt 采 K=5 次，取"任一次安全"作为"多采基线"；与"改写后采 1 次"对比。
- **判据**：若改写相对原 prompt 的收益（比如 +8 点）**小于**多采相对原 prompt 的收益（比如 +6 点），则**改写的净增益不到 2 点**，需要重新论证它的价值。
- **这是今天我们最该做、也最不想做的一个实验。** 但它决定我们后续所有 RL 投入的方向对不对。

##### H13. 保真与风险必须并列进奖励（0.5 天，改代码）

- **做法**：奖励从"保真分 + 风险分"改成**几何形式**（任一维接近 0 则整条打穿），或至少加一条硬约束"KL ≤ 阈"。
- **依据**：算术加权允许"保真满分"补偿"风险没降"，而这正是 KL=0（原样不改）最容易刷到的方向。

#### 主线六：多模态视频扩展

**本轮有强相关工作，给建议**：`2610.40191`（Video Generation Meets Agent Harness，综述性报告）与 `2610.41307`（ERASE 视频模态）。

##### H14. 视频通道的时机（半天评估，非全量）

- **仅在 ERASE 的框架下评估**：ERASE 在视频上把 `I` 从 3.41 降到 0.011，做法是"黑帧替换注入时段"。这提示视频侧的关键不是"逐帧判"，而是"定位风险时段"。
- **建议先做一件事**：在现有 i2v/t2v 落表数据里，统计**风险在时间上的分布**——是集中在少数时段，还是均匀铺满。
- **判据**：若 **>60% 的风险事件集中在 <20% 的时长里**，则逐帧判是浪费，应该做"时段定位 + 段级判定"，架构和 ADTGuard/ERASE 一致；若均匀铺满，则逐帧判是唯一选项，成本要按帧算。
