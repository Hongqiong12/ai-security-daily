## 今日概览

先说结论：**过去 7 天里，没有出现一篇真正“正中靶心”的 T2I 输入侧 Prompt Rewrite / Safety Rewriting 新论文。** 这不是坏事，反而说明你现在做的“模糊高风险 prompt 的语义保真安全改写”仍然处在明显的工业先行区。学术侧这周真正靠近你业务主线的，不是直接的 rewrite 方法，而是四块更底层、但更关键的拼图：

1. **怎样定义一个可靠的 semantic fidelity verifier**——`Edit-R1` 把 image editing reward 从黑盒打分器升级成逐项验收式 verifier；
2. **怎样把复杂生成任务拆成可解释的多维评测**——`CoBench` 把 text alignment 与 layout alignment 分开测，再统一汇总；

4. **怎样用强攻击者视角反推 provenance 防线真实上限**——`FMDiffWA` 说明 watermark defense 已经不能只和 JPEG、noise 这类弱攻击比。

所以今天这批工作虽然不直接输出“安全改写算法”，但它们一起补齐了你当前业务最缺的三块底座：
- **底座一：判别器**——如何判断 rewrite 后到底有没有过改写、漏改写；
- **底座二：评测协议**——如何把安全、语义、执行性拆成多维指标；
- **底座三：真实终态**——如何把文本渲染、版式控制、传播链路与 provenance 风险纳入同一套工业评测视野。

一句话总结今天：**T2I 输入侧安全改写的下一阶段，不是再堆更多 rewrite prompt，而是先把 verifier、三维评测、OCR-rich 终态和强攻击者基线搭完整。**

## T2I / T+I2I 论文（核心主线）

### 1. Leveraging Verifier-Based Reinforcement Learning in Image Editing

**本地精读**: `categories/t2i/papers/2604.27505_edit_r1.md`

- **论文定位**: T+I2I / verifier-based reward / semantic fidelity judge / image editing RL
- **机构线索**: 香港大学 + ByteDance Seed
- **核心贡献**:
  - 提出 **Edit-R1**，把图像编辑 reward model 从整体打分器改造成 **verifier-style reasoning reward model**；
  - 用 **Keep / Follow / Quality** 三类 principle 拆解编辑需求；
  - 提出 **GCPO**，把 pairwise preference data 用于训练带 reasoning 的点式奖励模型；
  - 再把该 verifier reward 接入 **GRPO / Flow-GRPO**，优化下游 image editing 模型。
- **关键数据**:
  - 冷启动数据约 **200 万** quadruples；
  - 偏好数据约 **1 万**对；
  - 内部 benchmark 上，**Edit-RRM 7B** 达到 **82.2%** 准确率；
  - 在 **EditRewardBench** 上，**78.2%**，显著强于 EditScore-7B + inference scaling 的 **72.7%**；
  - FLUX.Kontext 的 Overall 从 **5.77 → 6.24**，Semantic Consistency 从 **6.27 → 6.86**。
- **我的判断**:
  这是今天离你业务最近的一篇。它没有直接做 safety rewrite，但它给了一个非常像样的答案：**先把“改写是否合格”变成 verifier 问题，再谈训练和优化。** 对你现在的四路由改写系统，这几乎就是可以直接照抄的抽象层——把 `Keep / Follow / Quality` 换成 `Risk Reduced / Semantics Preserved / Follow Preserved`，就得到一套更像上线评测器的 judge taxonomy。

### 2. Benchmarking Layout-Guided Diffusion Models through Unified Semantic-Spatial Evaluation in Closed and Open Settings

**本地精读**: `categories/t2i/papers/2604.25358_cobench.md`

- **论文定位**: T2I benchmark / semantic-spatial evaluation / unified score / layout-grounded generation
- **机构线索**: University of Padova
- **核心贡献**:
  - 提出 **C-Bench**（闭集、自动化、可控）和 **O-Bench**（开集、真实、泛化）双 benchmark；
  - 分别测 **Text-Alignment** 与 **Layout-Alignment**，再用 **Unified Score** 汇总；
  - 对 6 个 layout-guided diffusion models 做大规模统一评估。
- **关键数据**:
  - C-Bench **3,328** 条样本，O-Bench **3,319** 条；
  - 总计生成并评测约 **319,086** 张图；
  - C-Bench 上 **MIGC = 0.7082**，BoxDiff = **0.6537**；
  - O-Bench 上 **MIGC = 0.7548**，GLIGEN = **0.7517**。
- **我的判断**:
  这篇论文不是 safety paper，但对你的业务异常重要，因为它示范了**不要用单个 overall score 糊过去**。当前 prompt rewrite 最危险的工程误区就是“judge 给了个 8 分，看起来还不错”，但没拆清：到底是安全升了、还是语义掉了、还是生成可执行性没了。CoBench 给出的可迁移思想很直接：**先拆维度，再做 harmonic aggregation。**

### 3. TextGround4M: A Prompt-Aligned Dataset for Layout-Aware Text Rendering

**本地精读**: `categories/t2i/papers/2604.24459_textground4m.md`

- **论文定位**: T2I dataset / text rendering / prompt-grounded supervision / OCR-rich benchmark
- **机构线索**: 中南大学 + 浙江大学 + Microsoft Research
- **核心贡献**:
  - 构建 **4.1M** 规模、prompt 对齐、span 级、带 bbox 的文本渲染数据集；
  - 提出训练时追加 **text span tokens + bbox tokens**、推理时保持原接口不变的轻量监督方式；
  - 设计 **TextGround-Bench**，按 Easy / Medium / Hard 难度分层评测；
  - 强化 `Prompt Coverage` 与 `Layout IoU` 这类真实终态指标。
- **关键数据**:
  - 原始图文对 **11.7M**，最终保留 **4.1M**；
  - Easy 场景 Acc 从 **10.85 → 34.10**，PC 从 **7.22 → 30.80**；
  - Medium 场景 F1 从 **5.52 → 27.75**；
  - Hard 场景 PC 从 **1.07 → 6.09**，仍很难；
  - GPT-4o 在 Hard 上仍远强于开源模型，Hard PC 达 **83.53**。
- **我的判断**:
  这篇论文对“真实高风险 prompt 的终态长什么样”很关键。你现在的改写业务如果只在裸体/性暗示这类视觉概念上做评测，还是太窄。真实风险 prompt 越来越会落到**海报、卡片、说明图、带文字的传播型内容**。所以 future-proof 的 rewrite 评测里，应该有一层专门看：**改写后原 prompt 的关键文本/布局要素还在不在。**

### 4. Breaking Watermarks in the Frequency Domain: A Modulated Diffusion Attack Framework

**本地精读**: `categories/t2i/papers/2604.22220_fmdiffwa.md`

- **论文定位**: T2I security attack / watermark removal / diffusion-based attack / frequency-domain modulation
- **机构线索**: 齐鲁工业大学 / 大连海事大学 / 南京理工大学 / 山东建筑大学
- **核心贡献**:
  - 提出 **FMDiffWA**，把去水印攻击直接训练成条件扩散框架；
  - 用 **FWM** 频域调制模块分别处理 magnitude 与 phase；
  - 用 **两阶段训练** 在 removal effectiveness 与视觉保真之间找平衡；
  - 展示对多种 watermark 方案的统一攻击能力。
- **关键数据**:
  - CelebA 上 PSNR 多数在 **42–45 dB**，同时 BER 保持较高；
  - ImageNet 上也稳定 **40 dB+**；
  - 在 HiDDeN_MP 上，ImageNet BER 可到 **0.4562**；
  - 消融显示只有 `FWM + PTS` 同时开启，才能兼顾去水印与保真。
- **我的判断**:
  这篇论文和输入侧 rewrite 不是同一条线，但它对工业评测非常有价值：**安全防线要按“强攻击者会专门训练 remover”来设计，而不是按弱攻击者会随手加点噪声来设计。** 这提醒你后续在 rewrite 评测里也别只测弱对手，要考虑“用户会不会系统性学会绕过你的 rewrite 规则”。

## 业务对齐研究板块

### 1. 直接可迁移方法

今天真正能直接迁到你当前业务里的，不是“现成 rewrite 算法”，而是三种底层能力：

#### A. Verifier-style 三维 judge（最直接）
来自 **Edit-R1**。

可直接迁成：
- `risk_reduced`
- `semantic_preserved`
- `follow_preserved`

再做组合评分，而不是让单个 LLM 一把梭给总分。

#### B. 多维分解后再统一汇总（很直接）
来自 **CoBench**。

你现在最需要的不是更多 prompt，而是更硬的评测协议。CoBench 已经给了成熟范式：
- 先分别测各维度；
- 再用 harmonic / unified score 汇总；
- 保证某一维塌掉时，总分不会假装还不错。

#### C. Prompt Coverage / OCR-rich 终态评测（直接）
来自 **TextGround4M**。

对于海报、说明图、宣传卡片这类真实高风险场景，改写后必须验证：
- 原 prompt 关键文本意图还在不在；
- 关键文本有没有被误伤；
- 布局与传播终态有没有漂。

### 2. 风险锚点处理启发

今天这批论文虽然不直接做 NSFW safety rewrite，但对“风险锚点如何处理”仍有三点实用启发：

1. **锚点不要只按词分，应该按原则分**（Edit-R1）  
   把锚点拆成：
   - 必须保留的主体/关系/构图；
   - 必须削弱或替换的风险意图；
   - 必须维持的可生成质量。

2. **锚点不要只看文本，要看终态承载形式**（TextGround4M）  
   高风险意图可能最终体现在：
   - 文本内容本身；
   - 文本位置与视觉组织；
   - 带文字的宣传/传播形态。

3. **锚点治理要按强攻击者假设设计**（FMDiffWA）  
   未来绕过 rewrite 不一定只是换词，而可能是系统性学会一套稳定的伪装表达方式。也就是说，risk anchor codebook 不能只抓显式词面，而要抓可复用的语义策略。

### 3. 三维评测设计启发

今天最清楚的一条结论是：**你的三维评测终于有比较像样的外部参照物了。**

建议把当前业务评测重写成：

| 维度 | 对应启发来源 | 你这边可落地的定义 |
|------|--------------|--------------------|
| **安全提升** | FMDiffWA / 强攻击者思路 | 改写后高风险生成率是否下降；是否仍能被 wrapper / alias / 组合语义拉回危险区 |
| **语义保持** | Edit-R1 verifier | 主体、动作、风格、构图、画幅等 anchor 是否保留 |
| **指令遵循** | CoBench / TextGround4M | 改写后模型是否仍能产出用户想要的可执行终态，尤其是 OCR-rich / layout-rich 场景 |

进一步建议新增两个辅助指标：
- **Prompt Coverage**：关键语义槽位保留率；
- **Consistency Gap**：同一原始 prompt 的多个 rewrite 版本之间，judge 是否稳定。

### 4. 下一步实验建议

#### 实验 1：把现有 judge 改造成 verifier taxonomy
先别急着训新模型。先在现有判别链路上把输出结构改成：
- `risk_reduced`
- `semantic_preserved`
- `follow_preserved`
- `notes`

目标：先把“哪里改坏了”看清楚。

#### 实验 2：补一层 OCR-rich / poster-like fidelity set
从现有高风险 prompt 中抽一小批容易落到：
- 海报
- 卡片
- 说明图
- 带文字宣传图

的样本，专门测改写后：
- 文本元素是否丢失；
- 视觉组织是否乱掉；
- prompt 关键文本槽位是否还在。

#### 实验 3：做 unified score，但只在多维单项已稳后启用
先分别测：
- 风险下降；
- 语义保持；
- 指令遵循；
- Prompt Coverage。

只有这四项单独可靠后，再做 harmonic aggregation。别反过来。

## 当日趋势信号

### 趋势 1：T2I 输入侧安全改写的真正瓶颈，正在从“怎么改”转向“怎么验”
`Edit-R1` 很清楚地说明，复杂生成任务的控制面最终都会回到 verifier。你现在的 rewrite 业务也是一样：没有可靠 verifier，改写器再聪明也只是黑盒拍脑袋。

### 趋势 2：真实工业终态越来越偏 OCR-rich、layout-rich、传播型内容
从 `TextGround4M` 到前一天的 `GPT-Image-2 in the Wild`，这条线越来越稳：高价值、也高风险的 T2I 场景，不再只是“画一张 NSFW 图”，而是“生成可传播、可读、可布局的视觉内容”。这会直接改变 prompt rewrite 的风险定义与评测对象。

### 趋势 3：评测协议正在从单分数走向结构化、多维、可审计
`CoBench` 与 `Edit-R1` 虽然一个是 benchmark、一个是 reward model，但抽象上做的是同一件事：**把复杂生成任务拆维度，再统一汇总。** 这对 prompt rewrite 业务非常关键，因为“安全升了但语义塌了”这种坏结果，只有在多维评测里才会暴露。

### 趋势 4：provenance / watermark 主线已经进入强攻击者时代
`FMDiffWA` 说明 watermark defense 不能继续用弱攻击者当假想敌。对应到你的业务，也意味着 rewrite 防线最终也要按更强对手建模：不仅要防显式词面，还要防稳定的语义伪装与分布外包装。

## 今日结论

如果把今天的 4 篇论文压成一句执行建议，那就是：

> **别急着再发明一个新的 safety rewrite prompt；先把 verifier、三维评测、Prompt Coverage 和强攻击者基线补齐。**

更具体一点，今天最值得推进的工程顺序应该是：

1. **先做 verifier taxonomy**：Risk Reduced / Semantics Preserved / Follow Preserved；
2. **再做多维评测协议**：不要让单个 overall score 继续掩盖问题；
3. **补 OCR-rich 终态样本**：让 rewrite 评测更接近真实传播内容；
4. **引入强对手思维**：按“用户会系统性学会绕过 rewrite”来设计评测与数据。

这批论文本身没有直接给出 T2I safety rewriting 的标准答案，但它们已经把答案的骨架拼得很清楚了：**输入侧改写要走向工业可用，核心不只是 rewrite 本身，而是 verifier + benchmark + 终态评测 + 强对手建模的完整控制面。**
