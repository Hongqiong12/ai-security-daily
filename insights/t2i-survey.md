## 摘要

文生图（Text-to-Image, T2I）安全研究以扩散模型为核心战场，形成了三个相互缠绕的研究主线：**越狱攻击**（如何绕过内容安全过滤器生成违禁图像）、**概念擦除/机器遗忘**（如何从模型参数中移除有害概念的表示）、**水印与溯源**（如何标记并追踪模型生成的内容）。本 Survey 基于本项目持续收录的 T2I 论文，完整梳理了从 GAN 时代到扩散模型时代的 T2I 安全演进，揭示了概念擦除技术从全局擦除向精准定位神经元、解析几何投影、**图文协同精准擦除**与运行时优化多路分化的演进路线，以及攻击方法从人工设计向 LLM 辅助自动化、**组合语义风险评测**与现实场景鲁棒评测的转变。

## 1. 研究背景：为什么 T2I 安全独特

### 1.1 扩散模型的安全特殊性

与 LLM 安全相比，T2I 安全具有三个独特性：

**① 隐式知识存储**：LLM 的知识以 token 概率分布的形式存储，可以通过 RLHF 显式训练拒绝有害输出。而扩散模型的"知识"（概念、风格、人物等）以分散的权重模式存储，**没有直接的"拒绝"输出机制**，只能通过修改潜空间来影响生成。

**② 语义-视觉 Gap**：图像内容的有害性判断比文本更模糊——同样的图像内容在不同语境（医学教育 vs. 色情内容）下有害性完全不同。这使得基于规则的内容安全过滤在视觉领域更难泛化。

**③ 开放生态的挑战**：Stable Diffusion 系列模型完全开源，用户可以自由下载并在本地运行，这使得基于 API 的内容安全过滤完全失效。**T2I 安全的核心战场在于模型参数本身**，而非接口层。

### 1.2 研究规模与分布

截至 2026-05-01，本 Survey 锚定本项目已收录的 **83** 篇 T2I 安全论文。当前 T2I 安全版图已经不再是“越狱 vs 过滤器”的单线叙事，而是至少分裂成四条强主线：

- **概念擦除 / 机器遗忘**：从权重微调走向 closed-form projection、depth-aware removal 与 activation-level intervention；
- **现实世界评测**：从 clean setting 转向 robustness-in-the-wild、near-duplicate 传播链、质量退化与伪造链路；
- **模型生命周期治理**：后门检测、身份验证、水印鲁棒性、开源再微调稳定性开始一起进入主战场；
- **上游控制与 provenance**：推理时 embedding editing、增量 attribution 与双通道 watermark/provenance 开始形成独立治理层。

从时间分布看，研究主体仍高度集中在 **2022–2026 的扩散模型时代**；而 2026 年的新论文尤其突出三个趋势：一是 concept erasure 的解析化/结构化，二是 AIGC 检测开始真正面向真实分发链路而非实验室 clean benchmark，三是 fairness / attribution / provenance 正逐步前移到 inference-time control 与 deployment-time verification。

## 2. 越狱攻击：突破 T2I 内容安全过滤器

### 2.1 攻击面分析

T2I 系统的内容安全防线通常由两层构成：
1. **提示词过滤器**（Text Safety Filter）：在文本进入扩散模型前过滤有害词汇
2. **图像安全分类器**（NSFW Classifier）：在图像生成后检测违禁内容

越狱攻击的目标是同时绕过这两层过滤，或利用两层之间的"语义不一致"。

### 2.2 基于强化学习的语义绕过

**SneakyPrompt**（[2305.12082](https://arxiv.org/abs/2305.12082)）是 T2I 越狱研究的开创性工作之一。其核心思想是**用强化学习搜索能绕过安全过滤器的替代词**：

```python
# SneakyPrompt 核心逻辑（概念示意）
def search_bypass_prompt(harmful_intent, safety_filter, t2i_model):
    env = T2IEnvironment(t2i_model, safety_filter)
    
    # 奖励：绕过安全过滤器 + 图像语义与 harmful_intent 相关
    reward = bypass_reward + semantic_similarity
    
    # RL 搜索替代词（如 "explicit" → "anatomical", "naked" → "unclothed")
    policy = RLAgent(state=prompt, action=replace_word)
    return policy.optimize(env, harmful_intent)
```

**FLIRT**（[2308.04265](https://arxiv.org/abs/2308.04265)）将 In-Context Learning 应用于越狱，通过少量示例（few-shot）引导攻击模型生成有效越狱提示。

### 2.3 感知层越狱

**Perception-guided Jailbreak**（[2408.10848](https://arxiv.org/abs/2408.10848)）提出了一种独特的攻击视角——**利用人类感知与扩散模型理解之间的差异**：

- 构造对人类无害但对扩散模型触发有害生成的提示词
- 利用扩散模型对某些词汇的独特理解方式（训练数据偏见）
- 攻击效果对人类审核员不易察觉

### 2.4 纯黑盒查询攻击

随着越来越多的 T2I 服务只提供 API（不暴露梯度），**无梯度黑盒攻击**成为重要方向：

**DiffZOO**（[2408.11071](https://arxiv.org/abs/2408.11071)）基于**零阶优化（Zeroth Order Optimization）**，在仅有模型输出（图像）的情况下估计梯度方向，实现黑盒对抗样本构造：

```
优化过程：
  x_{t+1} = x_t - η · Ĝ(x_t)
  其中 Ĝ(x_t) 是通过有限差分估计的梯度：
  Ĝ(x_t) ≈ [f(x + δe_i) - f(x - δe_i)] / (2δ)  ∀i
```

### 2.5 LLM 辅助 T2I 攻击（2024–2026 的主流）

2024 年之后，利用 LLM 自动化生成越狱提示成为 T2I 攻击的主要趋势：

**JailFuzzer**（[2408.00523](https://arxiv.org/abs/2408.00523)）：
- 将软件模糊测试与 LLM Agent 结合
- LLM 负责生成语义连贯的"变异提示"，模糊测试框架负责系统化探索

**Jailbreaking T2I via LLM**（[2503.01839](https://arxiv.org/abs/2503.01839)）：
- 直接用 LLM 的语言理解能力构造语义攻击
- LLM 分析安全过滤器的拒绝模式，自适应调整攻击策略

**Reason2Attack**（[2503.17987](https://arxiv.org/abs/2503.17987)）：
- 利用多模态 LLM 的**推理能力**来设计 T2I 攻击
- 模型通过推理"哪种描述方式能使扩散模型生成 X"来构造攻击

**GenBreak**（[2506.10047](https://arxiv.org/abs/2506.10047)）：
- 通用破解框架，针对多个主流 T2I 服务的统一黑盒攻击

**MMA-Diffusion**（[2311.17516](https://arxiv.org/abs/2311.17516)）：
- 多模态对齐攻击，同时利用文本和图像模态绕过安全过滤

### 2.6 动态注意力后门

**Dynamic Attention Backdoor**（[2504.20518](https://arxiv.org/abs/2504.20518)）代表了一类独特的攻击——**不是在推理时越狱，而是在训练时植入后门**：
- 在扩散模型的注意力机制层植入触发器
- 特定触发词（trigger token）出现时，注意力图发生特定变化，激活隐藏的有害生成行为
- 在没有触发器的情况下，模型表现完全正常，难以被安全评估发现

**PromptSAN**（[2506.18325](https://arxiv.org/abs/2506.18325)）：
- 基于提示词的自适应 T2I 攻击，根据目标模型的防御策略动态调整

### 2.7 文本渲染能力带来的新攻击面：铭文式越狱 (2026-04-08 新增)

随着 DALL·E 3、Flux 等模型在渲染清晰文本方面的巨大进步，T2I 模型出现了被称为 **"铭文式越狱" (Inscriptive Jailbreak)** 的全新攻击面。

**Etch**（[2604.05853](https://arxiv.org/abs/2604.05853)）首次系统化了这一类别：
- **攻击区别**：传统越狱生成"有害的视觉画面"（如色情、暴力），而铭文式越狱生成"视觉无害的画面，但包含有害的渲染文本"（如欺诈传单、假公文、钓鱼链接）。
- **防御盲区**：目前的内容安全分类器（如 NudeNet 或其他 NSFW 过滤器）完全无法检测渲染文本的语义。
- **攻击框架**：通过将 prompt 拆分为"语义伪装层、视觉锚定层、排版编码层"，结合 VLM（视觉语言模型）的反馈循环进行零阶优化。
- **意义**：这意味着 T2I 防御体系必须在未来集成 OCR（光学字符识别）与文本语义审查管道，但这将带来极大的延迟和计算成本挑战。

## 3. 概念擦除与机器遗忘：防御的核心范式

### 3.1 概念擦除的研究动机

T2I 模型的有害生成能力来源于训练数据中大量 NSFW 内容的表示被嵌入模型权重。**概念擦除（Concept Erasure）**的目标是在不重新训练模型的前提下，从参数中"遗忘"特定有害概念，同时最小化对无害生成能力的损伤。

这是一个典型的**约束优化问题**：
```
minimize  L_erase(c)     # 擦除目标概念 c 的生成能力
subject to  L_retain(C') ≤ ε  # 保留其他概念 C' 的生成质量
```

### 3.2 第一代：文本引导的权重调整（2022–2023）

**Safe Latent Diffusion (SLD)**（[2211.05105](https://arxiv.org/abs/2211.05105)，CVPR 2023）：
- 在扩散过程中引入安全引导信号，无需修改模型权重
- 通过负向 Classifier-Free Guidance 抑制 NSFW 特征方向
- **局限**：推理时增加计算成本，且不修改模型参数（攻击者可绕过引导信号）

**SEGA: Semantic Guidance**（[2301.12247](https://arxiv.org/abs/2301.12247)）：
- 通用的语义引导框架，可用于安全控制
- 允许多个引导信号叠加，实现复杂的概念控制

**ESD: Erasing Concepts from Diffusion Models**（[2303.07345](https://arxiv.org/abs/2303.07345)）：
- **直接修改模型权重**的概念擦除先驱
- 使用对比式微调：最小化目标概念的生成概率，同时保留其他概念

**Forget-Me-Not**（[2303.17591](https://arxiv.org/abs/2303.17591)）：
- 针对特定主题（如个人面孔）的遗忘学习
- 应用场景：GDPR 合规的"被遗忘权"实现

**Concept Ablation**（[2303.13516](https://arxiv.org/abs/2303.13516)）：
- 通过消融（ablation）训练移除特定概念
- 将目标概念的生成重映射到锚点概念

### 3.3 第二代：精确化与鲁棒化（2023–2024）

第二代概念擦除工作的核心问题是：**第一代方法擦除的概念可以通过对抗性提示词恢复**（即擦除后仍然可越狱）。

**UCE: Unified Concept Editing**（[2308.14761](https://arxiv.org/abs/2308.14761)）：
- 统一多个概念的同时擦除
- 引入"保留集"机制：在优化擦除目标的同时，显式保护相关无害概念

**R.A.C.E.: Robust Adversarial Concept Erasure**（[2405.16341](https://arxiv.org/abs/2405.16341)）：
- 在擦除过程中加入**对抗训练**：同时模拟攻击者的最优越狱策略
- 目标：擦除后的模型对已知越狱方法保持鲁棒

**Receler**（[2407.12383](https://arxiv.org/abs/2407.12383)）：
- "可靠且高效"的概念擦除
- 引入**知识蒸馏**保持无关概念的生成质量
- 实验显示：在概念擦除后对下游任务的性能损失最小

### 3.4 第三代：神经元精准定位（2024–2026）

第三代工作从"调整全局权重"转向"定位并修改负责有害概念的特定神经元/特征"：

**TRCE**（[2503.07389](https://arxiv.org/abs/2503.07389)）：
- 精确追踪有害概念在扩散模型中的"表示路径"
- 通过概念追踪定位关键层和注意力头

**Concept Corrector**（[2502.16368](https://arxiv.org/abs/2502.16368)）：
- 不仅"擦除"，还将有害概念"重定向"到无害替代概念
- 保持模型在相关语义空间的生成连贯性

**SPEED**（[2503.07392](https://arxiv.org/abs/2503.07392)）：
- 速度优先的概念擦除，专注于降低擦除的计算成本
- 提出高效的参数更新方案（稀疏更新，只修改最关键的参数）

**SAEUron**（[2501.18052](https://arxiv.org/abs/2501.18052)）：
- 利用**稀疏自编码器（Sparse Autoencoder, SAE）** 分析 T2I 模型中的特征表示
- 定位负责特定视觉概念的**单个神经元**（monosemantic features）
- **意义**：首次将 Anthropic 的机制可解释性技术（Toy Models of Superposition）应用于 T2I 安全

**Concept Pinpoint Eraser (CPE)**（[2506.22806](https://arxiv.org/abs/2506.22806)）：
- 以"外科手术式"精度定位并擦除概念神经元
- 理论上可实现零副作用的概念移除（仅修改与目标概念关联的少数神经元）

**Z-Erase**（[2603.25074](https://arxiv.org/abs/2603.25074)）：
- 专为**单流扩散 Transformer（如 Flux）** 设计的概念擦除方法
- 现有大多数擦除方法为 U-Net 扩散架构设计，Z-Erase 填补了新一代架构的研究空白
- 利用单流架构中的统一注意力机制实现更精确的概念定位


### 3.6 精细化区域安全控制与 DPO（2026-04-09 新增）

**SafeCtrl**（[2604.03941](https://arxiv.org/abs/2604.03941)）：
传统的全局遗忘往往造成无害上下文的保真度损失。
- 核心方法：基于“先检测后抑制（Detect-Then-Suppress）”范式的区域感知（Region-Aware）安全控制。
- 创新点：使用注意力引导检测有害区域掩码，随后在掩码区域内利用图像级直接偏好优化（DPO）专门中和有害语义，实现图像局部安全替换（如给违禁物品“打马赛克”或替换为无害物品），而不影响背景。

### 3.9 新兴范式：推理时能量引导概念擦除 (2026-04-13 新增)

**EGLOCE**（[2604.09405](https://arxiv.org/abs/2604.09405)）提出了概念擦除的**第三条路径**：

```
擦除技术路线图:
  路线一: 权重微调 (ESD, UCE, MACE) → 需训练，改参数，泛化代价高
  路线二: 激活操纵 (ActErase, SafeCtrl, FlowGuard) → 不训练，操作中间层
  路线三: 潜空间能量优化 (EGLOCE) → 不训练，直接优化采样轨迹 ⭐ NEW
```

**核心方法**:
- **排斥能量 E_repel**: 在潜空间通过梯度下降将采样推离目标概念区域
- **保留能量 E_retain**: 用 CLIP 相似度保持与原始 prompt 的语义对齐
- **联合优化**: 每个 denoising step 内执行 K 次（3-10次）梯度更新

**关键意义**: 标志着概念擦除从"改参数时代"正式进入"优化轨迹时代"。但这也意味着：
- 攻击者可用同样的**潜空间优化思路来恢复被擦除的概念**
- 双能量框架的理论保证（收敛性、全局最优性）仍待建立
- 与 LoRA 擦除秩亏分析的关系值得深入研究（潜空间维度 vs 能量地形）

- **优势**: 即插即用、不修改权重、对抗鲁棒性强
- **局限**: 推理延迟增加 2-5x、超参数需按目标调节、依赖特征中心预计算

### 3.10 新兴范式：闭式双投影擦除（Closed-Form Double Projections） (2026-04-15 新增)

**DP / Closed-Form Concept Erasure**（[2604.10032](https://arxiv.org/abs/2604.10032)）把概念擦除再次推进了一步：

- **核心机制**：不再做 retraining 或 iterative optimization，而是把擦除重写成两个解析可解的投影步骤——先把目标概念投影到安全子空间，再在 preserved concepts 的**左零空间**中求闭式更新。
- **关键结果**：在 SD 1.5 上，DP 将 mean erased accuracy 压到 **0.7%**，同时把 preservation drop 控制在 **1.8%**；对一般 ImageNet 非目标类的平均 accuracy drop 仅 **0.43%**，显著优于 UCE 的 **4.43%**。在 FLUX 上 preservation drop 也从 UCE 的 **23.9%** 降到 **6.6%**。
- **意义**：这标志着概念擦除正式进入“**训练自由 + 显式 preservation 约束**”时代。相比早期方法只是把 preservation 当作软惩罚项，DP 把“保留无关概念”直接写成线性硬约束，更贴近你关注的最小覆盖与结构性保真目标。

### 3.8 新兴范式：线性子空间移除 (Linear Subspace Removal)

在概念擦除的演进中，**线性子空间移除 (ISP, Identity Sanitization Projection)** [2604.05296](https://arxiv.org/abs/2604.05296) 代表了一种直接针对潜空间（Latent Space）进行代数操作的防御范式。该方法的核心逻辑在于：
1. **子空间提取**：通过提取同类概念（如不同视角的同一身份）在表征空间中的协方差主成分，定义概念所占据的线性子空间。
2. **正交投影**：构建投影矩阵 $P = I - U U^T$，将潜变量强制投影到与概念子空间正交的互补空间中。
3. **理论意义**：这为研究“模型参数空间中的线性干预”提供了一个基准。我们正在推进的“概念流形的非满秩不完备性”研究，正是以上述此类基于线性映射（或 LoRA 的低秩线性扰动）的防御范式为靶标，从流形曲率的角度指出其根本性弱点。

### 3.11 新兴范式：深度感知类遗忘（Depth-Aware Class Unlearning）(2026-04-17 新增)

**DAMP**（[2604.15166](https://arxiv.org/abs/2604.15166)）把 class unlearning 从“删输出头”推进到“逐层删方向”：
- **核心机制**：先在每一层估计 forget-specific directions，再用 depth-aware projection 逐层移除，而不是只在最后几层或 logits 端做 mask；
- **关键结果**：论文报告在绝大多数设置下都能把 Forget Accuracy 压到接近 **0**，同时把保留类性能损失压在较低水平，说明 class-level forgetting 可以不再依赖大规模重训；
- **意义**：这条线本质上把 concept erasure 进一步细化成“**层深相关的方向清除**”，与 Closed-Form DP 的解析投影路线形成互补，也和你长期关注的低秩/子空间弱点问题直接相关。

### 3.12 图文协同精准擦除：从“删掉概念”走向“少误伤地删掉概念” (2026-04-20 新增)

**TICoE**（[2604.15829](https://arxiv.org/abs/2604.15829)）把概念擦除推进到了一个很关键但此前经常被忽略的目标：**精确保留相近无害概念**。
- **核心机制**：文本侧用 CCCM 在 prompt bank 的凸包内采样，覆盖目标概念的语义变体；视觉侧用 HVRL 汇聚多尺度 latent token，区分真正的目标概念与只是形态相近的对象；
- **关键结果**：在 gun 擦除上做到 **ASR 0.00 / UDA 0.02 / P4D 0.04**，同时把 camera 的 MCP 保到 **92.06%**；
- **意义**：它说明 T2I 防御开始从“能不能擦除”转向“能不能在图文双模态约束下擦得准、擦得稳、少误伤”。这对你持续关注的 concept erasure 主线非常关键，因为它把 preservation 从软目标提升成了一等研究对象。

### 3.13 抗概念复活加固：概念擦除开始进入生命周期防线 (2026-04-27 新增)

**Projected Gradient Unlearning / PGU**（[2604.21041](https://arxiv.org/abs/2604.21041)）把 concept erasure 从“删掉某个概念”继续推进到了“**删完以后能不能守住**”的问题：

- **核心机制**：先用视觉相近但语义应保留的 retain concepts 构建 **Core Gradient Space (CGS)**，再在后续训练中把梯度投影到其正交补空间，避免模型沿恢复被删概念的方向更新；
- **关键结果**：在 **ESD-U + Van Gogh** 上，基线会在 **C6** 发生 revival，而 PGU 可将其压到 **No revival**；在 **Golf Ball** 这类更难概念上，也能把 revival 从 **C1** 推迟到 **C4**；
- **意义**：这释放出一个非常关键的信号——T2I 安全不该只问“擦除时成没成功”，还必须问“后续 fine-tuning 会不会把它学回来”。也就是说，**post-unlearning hardening** 已经成为 concept erasure 主线的新分支。

### 3.14 定位粒度决定擦除精度：SAE 只造监督、不进推理链路 (2026-10-27 新增)

**Concept Acupuncturist**（[2610.32059](https://arxiv.org/abs/2610.32059)，中科院信工所 + 波士顿大学 + NUS）把"该改哪里"从一个经验选择变成了可测量的定位问题：

- **核心机制**：SAE **不作为推理时外挂模块**，只用相关度打分 `r(b,f)` 定位最相关的单一 cross-attention block，把特征抑制后的解码结果投影回该 block 输出空间，作为"概念已擦除"的监督目标，再做**单 block 局部微调**（单次前向缓存全部时间步，不跑完整去噪轨迹）。
- **关键结果**：SDXL-Turbo T1 平均 FSR **80.02**（最强基线 SAEUron 43.68），训练成本 **−46.4%**，推理开销 **0**（对照：SAFREE +14.4% / SAEUron +73.3% / TraSCE +125.8%）。
- **两个必须记住的判据**：
  1. **只报 FSR 的擦除结果不可信**——SDXL 上 ConceptPrune FSR 77.90 但 FID **197.32**，SD v1.4 上 SAEUron FSR 97.40 但 FID **266.78**；高 FSR 可以靠把图彻底搞坏来换。
  2. **概念的可擦性由表示结构决定**——down.2.1 的单个 feature #4913 就能去掉裸露，但 Church 抑制 top-5 任一特征都不够；逐概念 FSR 从 Nudity **94.16** 到 Parachute **45.60**。
- **意义**：这与 SELECT 的"因果弥散度"是**两个独立证据指向同一件事**——概念表示越弥散，越难干净处理。对我们的直接用途是**给出"哪些概念该走权重侧擦除、哪些只能走输入侧改写"的判据**。

### 3.15 擦除的验收标准本身定错了：从参数不可区分到输出风险上界 (2026-10-28 新增)

`Risk-Aware Output Control Should be the Focus of Machine Unlearning`（[2610.35052](https://arxiv.org/abs/2610.35052)，南洋理工大学，cs.LG）是一篇**立场文**，但它把"擦除到底该怎么验收"这个我们一直含糊的问题拆干净了。

**它批判的对象**：MU 领域几乎被"**参数空间不可区分性**"统治——遗忘后的模型要尽量接近"用保留数据从头重训"的参考模型（RT）。这个目标从差分隐私借来，干净、可证、可度量，于是成了事实标准。

**四条反驳**：

1. **缺下游保证**——与 RT 参数接近（甚至可证不可区分）**不转化出任何输出行为保证**；参数或输入的微小扰动即可造成输出的巨大偏离。业务真正关心的是"遗忘后还多频繁输出有害内容/泄露隐私"，而这与参数距离无单调关系。
2. **可伪造**——已有工作证明**理想遗忘的证明本身可被构造**：出示完整的参数更新历史与批次对应关系，让人相信数据没被用到，而实际上用到了。
3. **黄金标准不可靠（对我们最致命）**——**生成模型被证明能在从未被显式训练过的内容上复现受版权素材**；采用保形预测的分类器，预测集里**仍可能包含被遗忘的点**。⇒ **"与 RT 不可区分"并不蕴含"不再产生不期望输出"**。当模型能力泛化到遗忘集上，输出层保证不可或缺，且**无法从参数层不区分性推导出来**。
4. ⇒ 主张：以**部署模型输出上的统计保证**定义与认证遗忘，并给出**分布无关风险控制框架**，把**保形预测恢复成其规范特例**。关键工程性质：**摆脱对 RT 的依赖**（而 RT 恰恰最贵、部署后最常拿不到）。

**对我们最有用的一层**：如果擦除的正确目标本来就是"输出空间风险控制"，那么**输入侧改写天然就是输出空间控制**，而权重侧擦除是"要绕一大圈才可能达到输出控制"的手段。二者不是两条平行路线，而是**"目标"与"一种代价高昂、且证不到目标的实现方式"**——比"互补"更准确。

**两个必须承认的隐式假设**：(a) 风险事件 $E$ 的构造被当成已知，但在生成任务上 $E$ 本身需要判定器，**判定器误差会吃进覆盖率保证**；(b) "分布无关"假设**可交换性**，而安全场景的新锚点词/新话术恰恰破坏它。

**对我们的验收改法**：把"擦除率 / FSR / FID"这套**机制声明**，换成"在风险水平 $\alpha$ 下，留出集上风险事件实测发生率与上界是否匹配"的**风险声明**——并且用同一 $\alpha$ 让权重侧擦除与输入侧改写直接可比。

### 3.16 蒸馏把擦除方向转掉了：权重侧失效的机制首次被量化 (2026-10-29 新增)

`Haste Makes Waste? Towards Safe Few-Step Text-to-Image Models`（[2610.36665](https://arxiv.org/abs/2610.36665)，**Tel Aviv University，IEEE S&P 2027**）把"少步蒸馏"从一个纯加速手段，变成了一个**必须被安全评审签字的参数**。

**两条现象**：

1. **学生比教师更不安全**。SD3.5 Large → Turbo，NudeNet **0.2432 → 0.3232**（相对 +33%）、SD-Checker **0.5416 → 0.6646**；FLUX Dev → SCFM（作者自蒸的受控对），**0.2562 → 0.3282** / **0.6108 → 0.7074**。**@5 指标（5 个种子里任一张不安全即算）下差距依然存在** ⇒ 加速不只抬平均，还让"至少一次出问题"更可能。SD-Checker 的连续严重度分布显示影响集中在**上尾**：严重度 > 0.25 的图里 **77%** 来自少步学生。
2. **步数本身是安全旋钮**。FLUX Dev 50 → 8 步，与 "nudity" 的 CLIP 余弦 **0.239 → 0.261（+9%）**；SD3.5 Turbo 8 → 1 步 **0.231 → 0.248（+7%）**。降到 16 步时，**已经做过擦除的模型** NudeNet 平均 **+10%**。⇒ **"降步数省算力"本身就是一次安全回退，且对已防御模型一样生效。**

**机制诊断（三路独立证据指向同一原因，这是本文最有价值的部分）**：

| 证据 | 量 | 结果 |
|---|---|---|
| 速度场敏感性 | 配对 Lipschitz 比（学生/教师） | FLUX Schnell/Dev **4.78（$z$）/ 4.37（$\theta$）**；SD3.5 Turbo/Large **1.81 / 2.32**；轻蒸馏 SCFM 仅 1.01 / 1.07。且**高噪声端最敏感**，与全步模型趋势相反 |
| 擦除方向 | $\cos(\delta, \delta^*)$ | SD3.5 Turbo **0.30**；FLUX Schnell **0.07**；SCFM 0.64。幅值膨胀 1.2–5×，但**四个速度场范数相近** ⇒ 膨胀来自"条件/无条件项抵消变差"，不是"预测变大" |
| 归因 | CFG 扫描 | FLUX Dev guidance 1.0→3.5，$\|\delta\|$ **17.8 → 64.1（约 3.6×）**；FLUX SCFM 1.0→5.0：**18.6 → 90.2** |

**机制解释很干净**：少步模型（ADD/LADD）把 CFG **烘焙进条件分支**，于是 $v(z,c) \approx v^*(z,\varnothing) + \omega(v^*(z,c) - v^*(z,\varnothing))$ 而 $v(z,c) \not\approx v^*(z,c)$；而**无条件分支在 LADD/SCFM 里根本没被直接训练**。$\delta = v(z,c) - v(z,\varnothing)$ 的两条分支被改得不一样，**而 ESD 恰恰假设两者一起被优化**。

**修法 DICE**：$\mathcal{L} = \mathcal{L}_{\text{esd}} + \lambda_1\mathcal{L}_{\text{attn}} + \lambda_2\mathcal{L}_{\text{gen}}$，两个关键改动 —— **① 直通路径重加噪**（$z = x_0 + \sigma_t(x_1-x_0)$，$\sigma_t$ 在 $[0,1]$ 均匀采，与推理调度解耦，因为一步 on-policy 采样永远只采到纯噪声端点）；**② 对擦除前 checkpoint 自蒸馏**（不用原始 FM 目标——它在少步模型上**初始就非零**，一优化就是大梯度把权重推出蒸馏轨迹）。

**结果**：SD3.5 Turbo 上 NudeNet **0.3232 → 0.0324**（既有最好 ESD 仅 0.1504）；FLUX Schnell **0.046**（既有方法 ≥0.161）；Ring-A-Bell 攻击下 FLUX Schnell **0.847 → 0.319**。

**一个必读的反向消融**：FLUX SCFM 上去掉"直通路径重加噪"，NudeNet 反而**更低**（0.0134 < 0.0526），但 HPSv2 也掉（0.2056/0.2650）。⇒ **单看安全率会得出反向结论，必须配质量指标读。** 这一条是本 Survey 收录的所有擦除工作里最容易被误读的一类表格。

**对"权重侧 vs 输入侧"这条边界的意义**：这篇第一次把失效**量化到方向层面**（cos 0.07–0.30），而不是"效果差一点"。⇒ **输入侧改写不碰权重、不改 $v(z,c)$ 与 $v(z,\varnothing)$ 的抵消关系，因此结构上不受这个失效模式影响。** 同时它也划出输入侧的边界：**改写管不住已经生成出去的图，也管不住用户反复试探**——@5 这个指标正是为此设计的。

### 3.17 「生成侧擦得掉，理解侧擦不干净」：跨通路遗忘随概念数线性崩塌 (2026-11-04 新增)

**UniForget / UUBench**（[2611.04467](https://arxiv.org/abs/2611.04467)，**中科院自动化所 + 国科大 + 字节跳动 + 港中深 + 上交**）。统一多模态模型（BAGEL-7B-MoT / Janus-Pro-7B）上的**跨通路**概念擦除。

**核心问题**：只擦一条通路（生成侧或理解侧），另一条会跟着忘吗？答案是**不会**。

**UUBench 六格记账**（30 目标 × 2 邻居 = 60 邻近概念 / 720 图）：TF 目标遗忘（生成）· SF 严格遗忘（TF 且图连贯）· NR 邻居保留（生成）· SR 严格邻居保留 · TU 目标非身份效用（理解）· NU 邻居效用（理解）。**论文明确写死偏序 `SF ≤ TF`、`SR ≤ NR` ⇒ 任何只报宽松指标的表格都在系统性高估自己。**

| 骨干 | 方法 | TF | DF | Joint |
|---|---|---|---|---|
| BAGEL-7B-MoT | TIME（生成侧） | **100.0** | **24.0** | 24.0 |
| BAGEL-7B-MoT | GD / KL（理解侧） | 0.0 | 0.7 / 0.0 | 0.0 |
| BAGEL-7B-MoT | TIME + GD（直接组合） | 100.0 | 31.3 | 31.3 |
| BAGEL-7B-MoT | **UniForget** | 100.0 | **80.0** | 80.0 |
| Janus-Pro-7B | **UniForget** | 100.0 | **92.7** | 92.7 |

**四条硬数字**：
1. **生成侧编辑器"压制"很强、"遗忘"很弱**：TF 100.0 而 DF 只有 24.0 ⇒ **"画不出来"和"不知道"是两件事**。
2. **直接组合几乎不涨**：TIME+GD 在 BAGEL 上 31.3，只比 TIME 单独高 7.3 点 ⇒ **把两条单通路方法拼起来不等于联合遗忘**。
3. **收益与代价绑在理解侧**：DF 31.3 → 80.0，但 TU 91.8 → **72.2**（掉 19.6 点非身份效用）。
4. **严格指标撕开宽松指标**：BAGEL 上 NR 98.1 而 SR **84.6**；Janus 上 NR 92.9 而 SR **73.2** ⇒ 每五个被保住的邻居里有一个"保住了但图糊了"。

**失效边界（多概念扩展 N=1→30）**：生成侧 TF 全程 100.0% 但 NR 只剩 **81.5% / 41.8%**、GenEval 掉到 **39.2% / 32.7%**；理解侧 DF **80.0% → 51.2%**、**92.7% → 37.1%**，而 MMBench 几乎不动。⇒ **生成侧"擦得掉但带崩邻居"，理解侧"不带崩但擦不干净"，两种失败形态互相掩盖。** 通用能力：GenEval 72.7 → 63.4 / 78.9 → 70.1，DPG-Bench 83.4 → 79.9 / 83.1 → 74.2。

**对"权重侧 vs 输入侧"边界的意义（第四轮加固）**：**擦除连"根本不该会"这一半都没做到 —— 它做到的是"这次画不出来"。** 而且它**随概念数线性崩塌**、**没有"只擦这个不擦那个"的精度**（邻居连带 41.8%）。⇒ 权重侧应定位为**上线前的权重治理 + 不可逆的极少数概念**，**不该被当作内容安全的主防线**；输入侧改写负责逐条、可回滚、可分业务配置的那一层。二者互补，不可替代。

⚠️ 不可迁移处：30 个目标概念**全是"有专名的实体"**（人物/地标/物体），**风险概念没有专名**，"目标/邻居"结构套不过来。可搬的是**六格记账法**，不是数据构造。

## 4. 前处理防御：过滤器与提示词检测

### 4.1 基于文本过滤的防御

**SafeGen**（[2404.06666](https://arxiv.org/abs/2404.06666)）：
- 文本输入的安全检测，在提示词进入扩散模型前过滤有害内容
- 多标签分类器，覆盖多种有害内容类别

**PromptGuard**（[2501.03544](https://arxiv.org/abs/2501.03544)）：
- 专门针对绕过安全过滤器的对抗性提示词检测
- 基于大规模对抗样本数据集训练，对已知越狱变体具有鲁棒性

**MacPrompt**（[2601.07141](https://arxiv.org/abs/2601.07141)）：
- 利用提示词语义的多维分析检测潜在有害提示
- 特别关注语义绕过（用无害词汇描述有害内容）的检测

### 4.2 潜空间防御

**LatentGuard**（[2404.08031](https://arxiv.org/abs/2404.08031)）：
- 在扩散模型的**潜空间（Latent Space）** 中检测有害概念
- 相较于文本过滤，潜空间防御对语义绕过攻击更鲁棒（攻击者无法预测潜空间表示）

**SAFREE: Training-Free and Adaptive Guard**（[2410.12761](https://arxiv.org/abs/2410.12761)，ICLR 2025）：
- **无训练**的自适应安全守卫，适用于 T2I 和 T2V（文生视频）
- 在推理时动态调整扩散过程的去噪方向，无需修改模型参数
- **优势**：即插即用，不影响模型基础性能

**Safeguider**（[2510.05173](https://arxiv.org/abs/2510.05173)）：
- 结合文本过滤和生成过程引导的混合防御
- 可配置的安全级别，适应不同部署场景

### 4.3 多视觉检查防御

**GuardT2I**（[2403.01446](https://arxiv.org/abs/2403.01446)）：
- 专门针对 T2I 生成结果的安全检测器
- 多维度视觉分析（内容、风格、隐含语义）

**UPAM**（[2405.11336](https://arxiv.org/abs/2405.11336)）：
- 使用视觉检查器（visual checker）进行后处理安全验证
- 可集成到任意 T2I 生成流水线的末端

**ART: Automatic Red-teaming**（[2405.19360](https://arxiv.org/abs/2405.19360)）：
- 自动化红队工具，用于持续发现 T2I 过滤器的漏洞
- 兼顾对良性用户的误拒率（false positive rate）控制

**Modular LoRA**（[2412.00357](https://arxiv.org/abs/2412.00357)）：
- 模块化安全适配器，可无损地为现有扩散模型添加安全能力
- LoRA 格式，可独立更新安全模块而无需重训完整模型

### 4.4 主动响应扰动式后门检测（2026-04-17 新增）

**Scaling Exposes the Trigger / SET**（[2604.12446](https://arxiv.org/abs/2604.12446)）把 T2I 后门检测从“等异常自己暴露”改成“主动去戳交叉注意力”：
- 在 U-Net 早期 denoising steps 中，对 cross-attention score 施加受控 scaling，观察响应偏移轨迹；
- 再用单类边界学习拟合 benign response space，把后门样本看成被 scaling 放大的异常点；
- 在 5 类主流后门攻击上取得 **95.1% AUROC / 84.8% ACC**，对 IBA 这种隐式触发器仍保持 **92.9% AUROC**，明显优于依赖表面异常的旧方法。

### 4.5 重建式检测器的对抗脆弱性：检测器也会成为攻击目标 (2026-04-18 新增)

**Fragile Reconstruction**（[2604.12781](https://arxiv.org/abs/2604.12781)）把 AIGC 检测研究又往前推了一层：
- **核心机制**：统一攻击 DIRE、LaRE2、AEROBLADE 三类 reconstruction-based detector，直接针对其“输入 → 重建误差 → 分类”链路做可微对抗优化；
- **关键结果**：白盒下大多数设置的 robust accuracy 几乎压到 **0%**，跨生成器 / 跨方法迁移后准确率也常塌到 **≈50%**，基本等于随机猜；
- **意义**：这说明 T2I 安全的真实问题已经不只是“有没有 detector”，而是**detector 自身是否足够抗攻击**。如果检测器赖以判别的重建残差信号本身低信噪比，那么整个 AIGC 治理链路会被系统性击穿。

### 4.6 输入侧 Prompt Rewrite 正在成为工业控制面 (2026-04-30 新增)

基于当前论文库与 2026-04-30 这批新工作，可以看到一个很明确但仍未完全论文化的工业趋势：**T2I 安全的上游控制点正在前移到输入侧 prompt 理解、风险路由与语义保真改写**。

- **现实驱动**：`GPT-Image-2 in the Wild`（[2604.25370](https://arxiv.org/abs/2604.25370)）说明真实世界主场景大量转向**图文排版、可传播海报与 OCR-rich 内容**，这意味着只靠下游 NSFW classifier 已经不足以覆盖真实风险终态；
- **现有基础**：PromptGuard、MacPrompt 代表了“先检测再放行”的前处理路线，但它们更偏**风险识别**，还没有真正解决“如何在保留用户意图的前提下做安全重写”这一工程问题；
- **工业启发**：对实际系统，更可落地的架构不是单点 blocklist，而是 **semantic risk routing → prompt rewrite / safe rephrasing → context-trigger re-eval → 结果一致性审计** 的分层控制面；
- **研究空白**：当前 T2I 论文仍缺少一套标准化 benchmark，来同时衡量 **风险下降、安全-效用 trade-off、语义保持（semantic fidelity）与指令遵循损失**。这也解释了为什么输入侧 rewrite 目前更像工业系统设计问题，而不是已经收敛的学术子领域。

**5 月 1 日新增信号**：`Edit-R1`（[2604.27505](https://arxiv.org/abs/2604.27505)）与 `CoBench / TextGround4M`（[2604.25358](https://arxiv.org/abs/2604.25358), [2604.24459](https://arxiv.org/abs/2604.24459)）进一步把这条主线从“理念判断”推向“评测底座”。前者说明复杂生成任务的控制点正在前移到 **verifier-style reward / principle-based judging**，后两者则说明真实工业场景需要把 **semantic fidelity、layout fidelity、prompt coverage、OCR-rich 终态执行性** 拆成独立维度再统一汇总。共同信号是：**T2I 输入侧 prompt rewrite 想真正走向工程可用，下一步关键不是再堆 rewrite 规则，而是先把 verifier taxonomy 与三维评测协议补齐。**

### 4.7 从 prompt rewrite 到 pipeline benchmark：T2I 输入侧安全改写进入系统工程阶段 (2026-06-24 新增)

6 月这一批论文把 T2I 输入侧安全改写从“是否应该做”推进到了“应该如何做成系统”的阶段，且路线已经明显分成四层：

- **rewrite 数据层**：`SafetyBPO` 明确把 unsafe prompt 重写成 **safe-yet-semantically-consistent** 版本，并用 **2.5K** 规模的 BPO-Bench 同时连接 prompt preference 与 image preference；
- **rewriter 训练层**：腾讯混元的 `PromptEnhancer` 不再把 reprompt 当作普通语言润色，而是用 **24 key points** 的 failure taxonomy 训练 CoT rewriter，说明工业 rewriter 的核心资产是**细粒度失败建模**；
- **语义保真验证层**：`FaithRewriter` 通过 visual anchor 把 rewrite 的隐性错误外化成可见图像，再用“修复验证 / 意图保留 / 反向回归”三重约束做 DPO 蒸馏，证明 **semantic fidelity 不能只在文本层判断**；
- **评测基建层**：`PixJail` 进一步指出，真正需要统一的不是单条 prompt，而是 **rewrite / generation / safety filter / MLLM judge / artifacts** 的完整 pipeline contract。

共同信号非常清楚：**T2I 输入侧 prompt rewrite 已经不再是一个“加几条规则”的前处理模块，而是一个需要数据、taxonomy、视觉终态验证和评测基础设施共同支撑的控制面。** 对当前业务而言，下一步最值得优先补齐的不是更多 rewriting heuristics，而是：
- 风险下降 / 语义保持 / 指令遵循的三维 judge；
- winner/loser image 配套的 safe rewrite pair 数据；
- 可回放的 rewrite-to-image benchmark pipeline。

### 4.8 「安全控制状态依赖化」：从条件依赖走向生成态驱动 (2026-10-22 新增)

10 月这一批工作出现了一个此前没有被显式命名的跨方法共识：**安全控制动作不应由一个先验固定的不安全条件直接决定，而应由"当前状态"决定。** 来自三个不同子领域的工作同时指向这一点：

- **输入侧 gate（CSTI，[2610.26452](https://arxiv.org/abs/2610.26452)）**：不再在文本层判风险，而是读 CFG 原生就算好的**条件分支与无条件分支激活之差**。在 step 5/10/15 取通道统计量 + 线性头即可判定，step 15 单次决策；命中则终止生成，未命中则**采样轨迹完全不变**。5 个生成器、4 个对抗集合、2 个 NSFW 数据集上，matched 5% FPR 下优于 6 个基线，拦截路径延迟降 60%+。关键工程性质：**不需要攻击样本拟合、不需要中间图重建、不改生成器**，阈值在独立安全集上标定。
- **生成侧控制链（DSC，[2610.21569](https://arxiv.org/abs/2610.21569)，NeurIPS 2026，腾讯署名）**：指出 training-free 引导普遍存在**耦合安全控制链**——同一个 unsafe condition 同时兼任"避什么 / 当前信号 / 干预量 / 持续多久"四职。一旦有害与良性语义纠缠，必然二选一（留残留 or 伤保真）。解法是拆成 runtime evidence → control-state → intervention routing → update construction → phase-aware execution 五段显式环节，全部由当前生成态驱动，实例化在 SLD 与 SAFREE 上。
- **改写选择（AMEND，[2610.23183](https://arxiv.org/abs/2610.23183)，T2T 迁移）**：用 **constraint-first selection** 取代无约束加权和，让语义保真对表面安全拥有**否决权**；并证明开放式多轮辩论仅 +0.0061 且置信区间跨零，**有界单轮修复 > 无限迭代**。

**这条主线的业务含义**：输入侧改写当前也处在"耦合链"状态——一个风险标签同时决定了"要不要改 / 改哪里 / 改成什么 / 改到什么程度"。DSC 给出的解耦模板（六段映射见日报）是现阶段最可直接尝试的结构改造。

### 4.9 Rewriter 训练层：语义 span 取代 subword 成为信用分配单元 (2026-10-22 新增)

`SCOPE`（[2610.22264](https://arxiv.org/abs/2610.22264)）点破了 T2I prompt rewriter 的 RL 训练中长期存在的**结构性错配**：图像级单一奖励被平摊到 subword token，但真正的语义单元是**连贯 span**（物体 / 数量 / 属性 / 关系）。

- 机制：rewriter **联合输出**增强 prompt 与其 semantic partition；span 内池化 policy log-prob 偏移得到**共享系数**加权该 span 内 token loss；**保留 completion 级单一 advantage**。
- 成本：**不需要额外 span 奖励，不需要额外图像渲染**——纯目标函数层改动。
- 效果：Qwen-Image / SD3 / FLUX.1-dev 上，GeneVal **+9.48%**、T2I-CompBench **+7.62%**（vs vanilla GRPO）。
- 定位：它把"语义结构"确认为 **prompt engineering with RL 的实用归纳偏置**，而不是新 RL 算法。

对输入侧安全改写的直接含义：**"语义保真"本质就是"不要在错误的语义单元上分配信用"**。若把"性感 → 优雅"学成**一个 span 的替换**而非一堆 token 各自漂移，正是这条归纳偏置要解决的问题。

### 4.10 保真度量正在被重新发明：相对比值取代绝对差 (2026-10-22 新增)

`PPAA`（[2610.27719](https://arxiv.org/abs/2610.27719)，ECCV 2026 Spotlight）在概念擦除里做了一件对输入侧改写同样重要的事：

- **相对相似度比取代绝对差**：自适应阈值因此表示"**保留百分之多少语义**"，**单一阈值可跨层统一适用**（绝对差需逐层调参）。
- **第一次明确定义了"同域近邻保留"这一空白**：现有方法能保住宽泛通用域概念（MS-COCO），但保不住同域近邻（擦 Obama 时能否保住 Will Smith）。而通用域指标（FID on COCO）**对同域近邻损伤不敏感**——这等于在质疑既有"保留性"评测口径本身。
- 实现：cross-attention 空间 push（位移目标表示）+ 有界余弦相似度 anchor（锚定擦除尺度）；SD v1.4 主实验 + FLUX 验证；覆盖 celebrities / artistic styles / nudity / IP。

**共同信号**：本周四篇（PPAA 的相对比值、SCOPE 的语义 span、AMEND 的硬门槛、Policy 的定义敏感度）都在做同一件事——**旧的那把尺子量不出我们真正关心的东西**。保真度量正在从"标量强度调参"转向"有语义的无量纲量"。

### 4.11 改写收益的归因：锚点定位精度，而不是改写能力，决定上限 (2026-10-23 新增)

`IMPLICIT-Bench`（[2609.24228](https://arxiv.org/abs/2609.24228)）做了一件此前没人做的干净消融：**在场景固定、只改一个变量的条件下，测 prompt rewriting 到底靠什么起效。**

- 设计：1,831 组「中性 / 刻板 / 反刻板」prompt 三元组，每组一个 KG unit（head, stereotype, anti-stereotype）作为**语义锚点**；改写器分三种信息条件——**无锚点 / 检索锚点 / oracle 锚点**。
- 结果（Qwen-Image，联合分 $\Delta S$）：**无锚点 −0.8**（偏置降 0.38，但对齐率掉 11.1 点，净负）→ **检索锚点 +2.9**（top-1 命中率仅 40%）→ **oracle +8.6**。
- 最强的负结果：**把本 prompt 自己的 unit 从库里删掉后，12 种配置全部低于 baseline** → 锚点**不跨 prompt 迁移**。
- 过改的断崖：LLM-pair steering 把偏置压到全场最低 1.01，但对齐率从 87.5% 崩到 **23.2%**，联合分 **−12.6**（全场最差）。

**这条主线的业务含义**：改写一直被视为"改写器能力问题"。这篇给出的是**归因顺序**——先查锚点定位（检索/span 定位），再查改写能力。若锚点命中率只有 40%，再强的 rewriter 也只能拿到 oracle 收益的 1/3。

同时它给了一个可直接复用的**乘性联合指标**：

$$S = 100 \cdot \mathrm{mean}_i\big[\,Y_i \cdot (1 - b_i/5)\,\big]$$

画对了才拿分、且越不刻板分越高 → 天然惩罚"把 prompt 改得面目全非来降风险"。

### 4.12 输出侧图审：审核器架构本身就是安全边界 (2026-10-23 新增)

`Mirage`（[2610.30348](https://arxiv.org/abs/2610.30348)）把攻击面从输入端移到了**生成后审核器**：只对输入图像加 $\le 8/255$ 不可感知扰动，**文本 prompt 完全不动**，在替代 CLIP 编码器的共享空间中同时"拉近恶意目标 + 推离 NSFW 概念簇"，靠**语义分离的跨空间迁移**规避未知审核器。

- 审核器差异（NSFW 图像目标集，$\epsilon=8/255$）：**CLIP Checker bypass 0.800 / NudeNet 0.435 / ViT Checker 0.185** —— 相差 **4.3 倍**。
- **bypass ≠ ASR**：I2P/CLIP 上 bypass 1.000 但 ASR 0.840，16 个百分点的样本"被放行却没有生成目标内容"。
- 扰动预算几乎无影响：$\epsilon$ 从 4/255 到 12/255，I2P/CLIP bypass 0.980 → 1.000 → 0.980。**最小扰动已足够绕过多数审核器。**
- 成本：I2P 上 2.4–3.8 次黑盒查询（SneakyPrompt 需 36–40 次）→ 可规模化。

**这条主线的业务含义**：图审 AB 评测有两个必须改的口径——① **异构集成**而不是单模型上线（架构差异比阈值调优重要一个数量级）；② **放行率必须拆成 bypass 与"放行且确实含风险内容"**，否则会系统性高估漏放。

### 4.13 图审基座开始给"配方"：用模型自己的混淆定义判别任务 (2026-10-26 新增)

`Yuvion VL`（[2606.25034](https://arxiv.org/abs/2606.25034)，**阿里巴巴安全 AGI Lab**）是本期最重要的工业工作。它把图审（内容安全判别）当作**对抗性问题**来建模，而不是分类问题，并给出完整三段配方：

**数据六分区**（按训练阶段分工）：通用多模态（防遗忘）· 领域知识（敏感人脸/旗帜符号/logo/场景）· **大规模真实安全业务数据（层级标签 + 证据归因 + 政策引用 + 结构化输出）** · 对抗数据（小字水印规避、logo 变异、AI 生成图、上下文掩护）· 纯文本（谐音/结构混淆）· 领域 CoT。

**训练三段**：CPT（冻结 ViT，只训 connector + LLM）→ Instruct 后训练（SFT + **C2FT**，全参数）→ Reasoning 后训练（SFT + RLVR/GSPO）。

**C2FT 的两个巧思**：

1. **Confuse**：混淆集不是人工列的，是**模型当前自己搞混的类** —— $S_{\text{confuse}}(c|x_a) = \mathrm{Sim}(e_{\text{pred}}, e_{\text{gt}}^c)$；困难负样本再用 Teacher Forcing 校验 $|P_{TF}(y_a|x_{neg}) - P_{TF}(c|x_{neg})| < \tau$，只保留"模型确实分不开"的负样本。
2. **Contrast**：把混淆对拼成多图指令 $X = [V_1; V_2; \dots; V_K; T]$，自注意力天然允许跨图 attend；总损失 $L = \rho L_{CE} + (1-\rho)L_{\text{contrast}}$，$\rho = 0.3$。**PAT** 再做随机图序打乱 + 单/多图混合，防位置捷径。

**关键数字**：8B 相对骨干在 12 集公开安全均分 **+12.4 ~ +12.6**、21 集内部业务均分 **+11.3**、AI 生成图检测 Macro-F1 **+17.8**（73.6 vs 55.8）；通用能力代价 2–3 点（Level 1 设 ≤3 点退化 gate）。消融：C2M 换随机对比采样掉 **4.28** 点，去掉 PAT 掉更多。

**两个可复用的工程件**：① **双生成器仲裁做标签复判** —— 两个生成器**都**与 reference 不一致 ⇒ 原始标注错；两个生成器**彼此**不一致 ⇒ 样本本身难（认知不确定），重采样而非改标；② **RL 用拒样代替随机采样** —— N=5 算奖励不一致度，只取边界样本，**6% 数据达到全量水平**。

### 4.14 三维评测的第三维：reliability 该和 safety/utility 平级 (2026-10-26 新增)

`Omni-UBench`（[2610.31713](https://arxiv.org/abs/2610.31713)，**浙江大学 + 阿里巴巴集团**）是第一个系统性的全模态护栏基准（**183,977** 样本 / 37 个来源 / 4 模态 / 15 个模型），但它的价值不在规模，在**第三维的构造方式**。

**三维定义**：Safety（不安全抓得住，越狱样本占全库 > 50%）· Utility（良性放得过）· **Reliability = 100(1 − FPR)**，含两个探针：

- **Over-sensitivity**：越狱**文本模式** × 通用**良性媒体**随机配对（两者都无害），测"对话术形状过敏"；
- **Guardrail Hallucination**：**等长掩码** —— 文本→重复 [MASK]、图→同尺寸空白、音频→等长静音、视频→同帧率空白，测"无证据时是否还判危"。

**硬证据**：把有害语义全部替换成无意义内容后，Qwen2.5-Omni-3B 仍保持 **1.00 / 0.99 / 1.00 / 0.50** 的召回（T / T-I / T-A / T-V），平均 **FPR 0.87**；MultiGuard 平均 **0.77**。**判定与内容无关。** 另两个发现：高 safety 可能是滥杀换来的（某模型 safety 80.3 但 reliability 11.7/12.8、utility 34.5）；隐式意图是普遍盲区（组合不安全 SIUO 召回仅 **0.39**，加密文本 0.41/0.43）。

**业务含义**：图审评测必须加**第四维"判定依据"** —— 掩码后 FPR > 0.3 说明图审在读 prompt 而不是在读图，此时任何 prompt 分布变化都会让线上表现不可预测。

### 4.15 锚点不是终点：锚点距离定义了擦除边界 (2026-10-26 新增)

`SELECT`（[2510.16342](https://arxiv.org/abs/2510.16342)，北邮，v2）把"选什么锚点"从实现细节升级为**语义擦除边界构造**问题。两个诊断：

1. **因果弥散度预测锚点敏感度**：用 cross-attention 单元的 restoration intervention 算因果效应分布，归一化熵 $D_c$。**$D_c$ 大 ⇒ 目标残留高、擦除强度低、锚点失败率高**（类内也成立：Dog 弥散/敏感 vs Corgi 集中/稳定）。
2. **锚点类型决定连带损伤范围**：**边界概念受损 >> 随机无关概念**（损伤是局部的）。太近压不住；**太远压得住但边界 + 全局损伤最大**。

**BCTS**（可复用的联合分形式）：$\mathrm{BCTS}(c,a) = \phi_c(S(c,a)) \cdot (1 - \tilde{D}(c,a))$，其中 $\phi_c$ 是"**达到阈值后不再奖励更激进擦除**"的整形函数 —— **先卡安全底线，达标后只比保真**。五类锚点中 **Sibling Exclusive（同父类 + 核心属性互斥）BCTS 最高**。

**NSFW 的现成模板**：保留人物/活动/场景，把敏感属性换成互斥属性 —— 裸露 → **全覆盖职业装**，性内容 → **职业/教育性活动**；锚点实例 "a gardener in overalls and long sleeves"、"a gardener planting flowers in a public park"。名人擦除 $H_c$ **81.99 → 87.99**（SPEED）；NSFW 用 I2P + NudeNet(0.6)，暴露部位检出数远低于固定锚点。

**另一条机制发现**：**关联语境会激活残差**（擦掉 {blood} 后，{red, wound, stain} 仍触发血迹）。用 $CRR = A_{rel}/A_{neu}$ 可预测再出现率 —— 这解释了"改写没改干净"的真实原因：不是残差没擦净，是**关联词把风险带回来了**。

### 4.16 偏好奖励的偏置不只让分数变脏，它会删除能力 (2026-10-26 新增)

`Attractive Faces Skew`（[2610.28195](https://arxiv.org/abs/2610.28195)）建立了五段因果链：人 → 榜单 → 奖励模型 → 生成 → **能力删除**。

- **人**：47 有效参与者、400 图（一半真实一半生成，但被告知全是 AI 生成）。"保真度"措辞 p=**0.0018**、"审美"措辞 p=**0.0006**；两措辞差异 p=**0.028**（"审美"更严重）。
- **榜单**：10,000 次 Elo 模拟，好看的 AI 队（吸引 67.9）领先不好看的真实图队（34.1）**≈ +124 Elo**。**决定胜负的是相对吸引力，不是图像来源。**
- **奖励模型**：DiffAE 逐属性编辑 40 属性 × 4 强度 × 100 底图 = **16,000** 图；**5 个偏好模型里 4 个的 top-1 相关属性是 "attractive"**（PickScore / MPS / HPSv2.1 / HPSv3）。非偏好控制组行为不同（LAION-Aesthetics 无主导属性、CLIP 走女性关联属性）⇒ **这是偏好对齐引入的**。
- **排除混杂**：真实图上 HPSv3 仍是 r=**0.35**；LASSO 路径里 attractive 保留到 $\lambda_L = 0.63$。
- **删除能力**：ReNO + HPSv2.1 优化 prompt **"a photo of an unattractive face"**，20 步后**反而更漂亮**。奖励语义是图文对齐，实际行为是变好看。AlignProp / DRaFT 微调后生成人脸**变年轻、更偏女性**。

**我们的风险**（论文未提）：年轻化 + 女性化恰是 NSFW 风险画像的已知相关因子 —— **用偏好奖励做安全对齐，可能同时把生成分布推向更高风险的人像。**

**可复用的审计五步法**：单属性编辑 → 相关系数排序 → LASSO 正则化路径 → 真实图对照 → 引导生成验证因果。

### 4.17 输入侧改写的工业配方终于公开了——但目标里没有"安全" (2026-10-28 新增)

**Qwen-Image-PE**（[2610.33472](https://arxiv.org/abs/2610.33472)，Qwen Team / 阿里 + 北大）是本期唯一一份公开的、完整可复现的**工业级 T2I 输入侧改写训练范式**。它的意义不在"prompt enhancement"，而在**它证明了输入侧改写可以训到工业可用，并给出了完整结构**——而这个结构与我们的安全改写两阶段**完全同构，差别只在目标函数**。

**两阶段**：

1. **CRD（Caption-Based Reverse Distillation，反向蒸馏）**——不走 `请求 → 扩写`，而是 `好图 → 稠密描述 → 当作改写目标`，**把监督信号的方向反过来，从图像侧获得**，绕过语言模型先验。证据：改写后 prompt 嵌入与真实 T2I caption 分布的 MAUVE **0.290**（正向扩写仅 **0.032**，约 9×）。
2. **GDR（Groupwise Design Reward，组内设计奖励）**——同一请求采样 $G$ 个改写 → 各出一图 → **拼成网格**交多模态 judge，在显式 rubric 下逐候选打分，**每个候选的分数以整组为条件**；生成器全程冻结。

**三个可抄的设计决定**：
- **网格化**：$G$ 张图放同一画布，judge 视觉上下文强制对齐，消掉"逐张评时绝对分数受呈现顺序影响"的问题。
- **组内条件化**：judge 答"这一组谁更好"而非"这张值几分"——**把奖励从绝对尺度换成相对排序**。
- **两个奖励各管一件事**：设计分（组内相对）管"能不能区分好坏"，对齐分（绝对）管"有没有跑题"，**不混进一个标量**。

**关键数据**：397B 相对原始请求 **+7.81** Overall（Qwen-Image-Bench，固定 Qwen-Image-2.1 主干）；9B 超过**全部**对比 PE 基线；泛化到 4 个额外主干，并在 **HunyuanImage-2.1** 与 **FLUX 3 Image Klein** 上**超过这两个主干的原生 enhancer**。规模化三轴为数据 / 模型 / **信息密度**，且**信息密度是前提**。

**唯一但致命的空白**：四个设计 rubric（Lighting / Composition / Layout / Detail）**没有安全这一维**。结合前四周的连续空窗，这是一个结构性事实——**头部公司在 T2I 输入侧改写上公开发表的全部是 enhancement，没有一篇 safety**。

### 4.18 I2I 编辑安全的真机制是注意力竞争：软改写等于取消编辑 (2026-10-28 新增)

**Copying As Defense**（[2610.35566](https://arxiv.org/abs/2610.35566)，Adobe Research + 普林斯顿）做的是图像侧主动防护，但产出了**编辑链路为什么会失效**的机制解释——**直接关系我们 I2I 改写分流 0/0% 的缺口**。

**它的核心反转**：主流防护（DeContext）的思路是"让模型忘掉原图"——压掉 target→reference 注意力。这篇指出：**softmax 注意力行和恒为 1，压掉参考图等于把概率质量送给文本和画布**，而那两条正是"指令遵循"与"生成"的通路。正确方向是**反号**：强制它在少数早期 double-stream block 里**抄原图**。

**两个失效机制（本文最重要的概念产出）**：

- **Mass redistribution（注意力质量重分配）**：被成功"去上下文化"的编辑器**输出不再贴原图，但恶意指令照样执行**。论文 Fig.3 给了教科书式例子：DeContext 保护后原主体身份已不见，无条件下生成的内容照样出来。
- **Token coverage**：图像级平均抑制对主体占 token 少的图不管用。**面部特写主体占 92% token → 抑制有效；全身照只占 31% → 抑制失效**（"愤怒"与"红色比基尼"两项编辑都成功）。

**关键数据**（$\epsilon = 12/255$，ESR 越低防护越强）：

| 编辑器 / 数据集 | 未防护 | DeContext | Diff-PGD | **CaD** |
|---|---|---|---|---|
| FLUX Kontext / InpaintGuard | 0.820 | 0.210 | 0.520 | **0.160** |
| FLUX Kontext / BodyBench | 0.816 | 0.249 | 0.442 | **0.051** |
| FIBO Edit / InpaintGuard | 0.800 | 0.597 | 0.527 | **0.183** |

平均 **81.4% → 24.0%**（相对降 70.6%），相对最强基线再降 **44.3%**；单步 **0.647 s vs 1.232 s**，总防护 **10.78 min vs 16.43 min**（**1.8–2.0×**）；扰动可感知性相当（LPIPS 0.31–0.39 vs 0.34–0.43）——**没有用更大扰动换效果**。

**一条可抄的评测纪律**：ESR 不是"看起来变了没有"，而是**四条件联合判定**（变换达成 × 无关内容保留 × 身份保持 × 无伪影）。

**对我们 I2I 改写链路的直接推论（论文未提，是本 Survey 的推断）**：编辑成立与否是"参考图注意力"与"文本注意力"的**零和分配**。那么——

- 指令改写得**越软越模糊**（为了安全）→ 文本侧 grounding 变弱 → 注意力回流参考图 → **模型直接复制原图，编辑不成立**；
- 改写得**越硬越具体** → 文本侧 grounding 变强 → 但很可能把风险内容重新指定出来；
- 这个 trade-off 的斜率**取决于主体在参考图里占多少 token**。

⇒ **软改写 = 取消编辑**，这很可能是 0/0% 的结构性原因，而不是改写器能力不足。修法不是"改得更软"，而是**只替换风险属性词、强制保留"主体+动作+区域"三元组的 per-token 锚点**。

### 4.19 奖励的误差是后验协方差：在最该判的地方最不准 (2026-10-28 新增)

**VaLoP**（[2610.35607](https://arxiv.org/abs/2610.35607)，GIST）是奖励引导扩散采样里的梯度精度工作。方法本身搬不到我们的策略优化场景，但它给了一个**可检验的误差结构**。

**核心发现**：两种主流价值梯度估计——DPS（在一步去噪估计 $s=0$ 上读）与 StitchVM（在当前噪声态 $s=t$ 上读）——**其误差本质上是同一个东西：后验协方差，随"对干净样本的不确定性"增长，也就是随噪声升高而变大**。因此二者**都在高噪声处最不准，而高噪声处恰恰是粗结构被决定的阶段**。

**方法结构很干净**：$s=t$ 与 $s=0$ 是**同一族的两端**（分别对"精确价值模型"和"线性奖励 + 精确去噪器"精确），**中间 $s$ 需要额外一项穿过生成器的修正**，用一次 VJP 算出；默认 $s = 0.6t$。VaLoP-Fast 用小 head 摊销修正，**一个 head 跨所有奖励复用**——因为 head 学的是"$g_s \to \xi_t$"的映射，**这个映射属于生成器不属于奖励**。

**两个方法学细节值得记**：
- **幅度匹配**：所有方法每步位移范数对齐到 StitchVM。**不做这一步，任何"更强引导"的方法都会因为实际走得更远而看起来更好。**
- **反向证据**：基线在把目标奖励推高的同时**牺牲 held-out 指标**——aesthetic 与 CLIP 两个奖励下，除一项外**全部低于未引导模型**。即"奖励涨了，图整体变差了"。

**对我们奖励链的推论**：我们的一致性奖励读在**终局像素**上（等价 $s\approx0$），而终局读数已被高噪声阶段的粗结构定型——**读到的很可能不是"意图保真"，而是"去噪过程的随机性"**。可检验的做法：对同一对 `(原 prompt, 改写 prompt)` 固定种子跑 20 次，**若同 prompt 同种子的分数标准差 > 跨改写对的平均差，则奖励信噪比不足**，任何 RL 都在学噪声。

### 4.20 结构表示既是条件也是奖励，且动作空间本身在保真 (2026-10-29 新增)

**StruPO**（[2610.36146](https://arxiv.org/abs/2610.36146)，**浙江大学 + 腾讯 AI Lab + 中国电信 AI**；HTML 无 affiliation，据 PDF 首页作者块确认）是目前**最接近我们安全改写问题的同构工作**——它要的是"改风格但不改场景"，我们要的是"降风险但不改意图"，**两者都是"在保结构的前提下做局部改写"**，且都被同一个坑坑过：**用全局相似度当保真指标，会漏掉局部语义漂移**。

**核心设计（一句话）**：**标定过的场景图同时当条件与奖励**。同一个表示既告诉策略"这些锚点不能动"，又拿来核"锚点还在不在"。论文的定性很克制——**"同一批结构化意图，既用于条件化编辑器，也用于评估其后果"**。

**DSE 的非对称规则（对我们最直接可用的一条）**：解析出的元素分 **text-core**（显式句法中心词、参与关系的实体）与 **auxiliary**（风格/相机/介质的歧义名词短语）；**auxiliary 需要视觉证据才能留下，text-core 即使图里没画出来也强制保留**。

> 论文的原例：*"a girl photographed with a Leica lens"* —— "Leica lens" 会被纯文本解析器当成可见物体，其实它是拍摄条件。
> 一句话概括这条规则：**图只能否掉"你以为用户要的"，不能否掉"用户真要的"。**

**动作空间**：改写形式化成 **删除 → 重排 → 插入** 三个 token 对齐的原子操作（前两个非自回归 + beam search，插入自回归）。作者自己说这是"**朝向保守编辑的归纳偏置，不是保真的硬保证**"。

**奖励整形（Theorem 3.1，可直接搬的数学结论）**：常用的离散结构分 $\mathbb{E}_{z}[\mathbb{1}(P(z|i_y) \ge u)]$ 的问题是**阈值附近的微小置信度变化会翻转某个约束的贡献，而远离阈值的改进拿零分**。改成连续平均 $R_s = \frac{1}{K}\sum_k p_k$ 后可得有限 Lipschitz 界：

$$\|\widehat{\nabla}J(\theta;I) - \widehat{\nabla}J(\theta;I')\| \le \|\Psi(\theta;I) - \Psi(\theta;I')\| + \frac{\|\Psi(\theta;I)\|}{K}\|p(I)-p(I')\|_1$$

⇒ **"策略分变化"与"grounding 置信度变化"被分离**；固定编辑时第一项消失。**我们的一致性奖励如果是阈值化的，就有同一个病。**

**环境感知 GRPO**：渲染本身随机，所以**先对 $M$ 次渲染求平均，再做组内归一化**（$\bar{r}_i = \frac{1}{M}\sum_j r_{i,j}$，再算 $\widehat{A}_i$）。**"$M$ 次渲染先平均再比"这个设计把'运气好的一张图'和'确实更好的改写'分开了，且几乎零成本。**

**关键数据（SD v1.5）**：Lexica 上 **RR 69.64（比最好基线 +7.96）**、SGR **80.74**、AESΔ **+0.63**、Gemini-VQA **82.4**；COCO（OOD）上 AESΔ **+1.02**。跨主干不重训：FLUX.1-dev 上 **RR 62.43 vs Promptist 53.41**、AESΔ **+1.14**。人类评测 15 人 × 2K prompt：一致性优势对三个基线 **+9 / +10 / +7** 点，且**关系越多优势越大**（$|V_x|$ 1→≥3，+6→+16）。

**消融——本文最有信息量的部分**：

| 变体 | SGR | 相对完整版 |
|---|---|---|
| StruPO | 80.74 | — |
| w/o DSE（用未标定解析图） | 73.69 | **−7.05** |
| w/o MHE（编辑器看不到图结构） | 75.33 | −5.41 |
| **w/o EAG（换自由生成，图条件+奖励+GRPO 全保留）** | 73.68 | **−7.06** |
| w/o RL（只 SFT） | 74.04 | −6.70 |
| w/o $r^{\text{con}}$（只留美学+CLIP） | 75.14 | −5.60（美学反升） |

⇒ **w/o EAG 这一行是重点**：把局部编辑换成自由生成，**其他一切都还在**，SGR 依然掉 7.06。也就是说——**保真不只是靠奖励逼出来的，动作空间本身就是一种保真机制。**

**边界（作者自己列的，且恰好是我们的战场）**：计数、遮挡、否定、情绪、隐喻、抽象意图**全在它的表示之外**。而"暗示性""擦边""隐喻式冒犯"全在这个区域。**它是输入侧改写方法学的最优参照，但不是安全改写的现成方案。**

### 4.21 「抽象语义脚手架等于零收益」：结构化分解必须以可执行力为界 (2026-10-30 新增)

**Grounded Exploration**（[2610.33810](https://arxiv.org/abs/2610.33810)，**Georgia Tech + Pinterest**，NeurIPS 2026 Workshop VLM4RWD）做的是开放式图像编辑的**意图分解**，但给出了 T2I/T+I2I 输入侧改写领域**最强的负结果之一**。

**问题设定**：开放式请求（"让我的卧室更温馨一些"）**天然允许多个合法答案**。两种常见做法都失效——直接重复采样会**塌缩到同一个高层解读**（8 个变体全在加植物）；显式要求"给我 8 个不同的"只带来**表层差异**（颜色/材质/摆件）。

**两阶段**：Stage 1 只决定**"可以在哪里动、能动多大"**（提示词明令禁止决定风格/材质/物体/配色），Stage 2 再把每个范围落成**自包含的可执行编辑指令**。

**关键设计——把"探索装在哪一层"拆成六组对照**，其中 `High-level exploration` 与完整方法**共用同一个 Stage 2**，唯一差别是 Stage 1 抽象层级。这一刀排除了"是不是只要有两阶段结构就行"。

**主表（300 任务 × 8 候选，GPT-5.5 judge）**：

| 方法 | IF | Grounded | Valid@8 | DirCov@8 | DistReal@8 | Dispersion |
|---|---|---|---|---|---|---|
| **Region-level（本文）** | 3.74 | **3.90** | **6.05** | 4.00 | 5.65 | **0.532** |
| Realization only（无 Stage 1） | **3.77** | 3.73 | 5.83 | **4.17** | 5.63 | 0.504 |
| **High-level exploration（抽象语义）** | 3.70 | 3.77 | 5.80 | 4.16 | 5.63 | **0.504** |
| Prompted Diversity | 3.57 | 3.33 | 5.33 | 3.66 | 5.20 | 0.427 |
| Qwen（纯换种子） | 2.98 | 3.26 | 4.04 | 2.46 | 3.63 | 0.242 |
| Gemini（纯换种子） | **3.93** | 3.45 | 5.74 | 2.18 | 4.56 | 0.424 |
| Flux（纯换种子） | 3.77 | **3.95** | 5.71 | **1.49** | 2.85 | 0.300 |

**三条结论**：

1. **抽象语义 Stage 1 ≈ 无 Stage 1**：DirCov / Dispersion / Valid@8 **三列全部在误差内重合**（4.16 vs 4.17、0.504 vs 0.504、5.80 vs 5.83）。⇒ **"在语义层面加一层结构化抽象"等于零收益。**
2. **Stage 1 的作用不是制造多样性，是上锁**：落到"可行区域 + 改动幅度"后 Groundedness **+0.17**、Valid@8 **+0.22**，代价是 DirCov **−0.17**。多样性几乎全由 Stage 2 驱动。
3. **单点指标可以完全反向**：Gemini IF **3.93 全场最高**但频繁结构性幻觉，DirCov 只有 **2.18**；FLUX Grounded **3.95 全场最高**但 5.71 个有效输出塌成 **1.49 方向 / 2.85 实现**。

⇒ **对我们**：这直接**否掉了"在改写 prompt 前面加一段安全说明"这类做法的理论依据**——抽象说明落在语义层，与不加等价。而且它给出了 I2I 改写 0/0% 的一个候选解释：**单点判定必然趋零，必须换成集合级"方向覆盖数"**（详见当日日报第四节主线 5）。

### 4.22 softmax 归一化本身就是过度预测的结构性根源 (2026-10-30 新增)

**SafeSteer**（[2610.35017](https://arxiv.org/abs/2610.35017)，**USC + UCSB**）表面上是对文本操控视觉编码器做人脸偏差审计，实质是**一篇关于 softmax 结构的论文**——**与我们图审分类器（`sft_train.image_only`）的失效同构**。

**核心命题**：模型输出是对 patch 的 softmax，**和恒为 1**，所以无论 prompt 多离谱，它**必须**把概率质量放在某处。作者一句话钉死：*"Its patch softmax must place its mass somewhere."*

**最实用的切分——把拒答拆成两类**：

| 类型 | 定义 | confidence 信号能否处理 |
|---|---|---|
| **referential** | 指称对象物理上不在（"the pizza" 而图里没披萨） | **能**（隐藏 logit AUC 0.880） |
| **fairness** | 对象**就在图上**，但问题是"不该问"（"the criminal"、"the Muslim"） | **不能**（同 logit 只有 0.757；CLIPSeg 0.480 = 随机） |

**Table 4（一张表说清所有路线的边界）**：

| 方法 | point/abstain | absent/present | **sensitive/role** | held-out | over-refusal ↓ |
|---|---|---|---|---|---|
| 已发布 heatmap 平坦度 | 0.517 | **0.310** | 0.611 | 0.522 | – |
| 已发布隐藏 max logit | 0.860 | 0.880 | **0.757** | 0.921 | – |
| CLIPSeg | 0.685 | 0.883 | **0.480** | 0.712 | – |
| SAM 3 | 0.903 | 0.938 | 0.852 | 0.906 | **0.341** |
| Qwen2.5-VL | 0.751 | 0.721 | 0.655 | 0.797 | **0.279** |
| **SafeSteer（+1 null logit，23M 参数）** | **0.997** | 0.995 | **0.998** | 0.998 | **0.000** |

**三条边界**：① 已发布模型 absent/present 只有 **0.310（低于随机）**——"什么都没匹配上"时 softmax **必须更集中**；② **专门做 presence 的方案全靠过度拒绝换分数**（SAM 3 拒掉 43% visible roles；Qwen2.5-VL 拒 51%）；③ **弃权是图像条件的**：同词表文本探针只有 0.748，文本门 + logit 的流水线最多 0.934。

**机制定位**：偏差不在文本编码器（crime 词与 "Black" 距离 $d=-0.04,p=0.55$）、不在主干无操控 saliency（$\omega=0$ 时 "the person"→woman **54.5%**，公平），而在**操控适配器 zero-shot 造出来的**——逐层零门定位到最后两层（零掉 block 9，crime−occupation **0.092→0.005**）。最反直觉的一条：**同预算下用真值 mask 微调，定位准确率反而从 0.826 掉到 0.793**（保住能力的是**蒸馏**）。

⇒ **对我们**：PORN 过度预测有**第四类**原因，与"调阈值/改标签/补数据"正交——**模型不该给任何 tag，但没有"不给"这个选项**。而我们过去调的阈值**只作用在 referential 那一半上**（fairness 型靠阈值解决不了），这解释了为什么调阈值对 VULG-HINT-EDGE 无效。作者那句 *"The policy is set by the training labels, not the method."* 也要记住：**机制好装，边界还是要靠标注定义。**

### 4.23 「图审失效的方向不是报多了，是看不到使能风险」(2026-11-02 新增)

**FVH-Bench**（[2610.37722](https://arxiv.org/abs/2610.37722)，**香港中文大学（深圳）+ 纽约州立大学布法罗**）提出 **functional visual harm（FVH，功能型视觉危害）**——风险来自生成物 **使能（enable）** 了什么，而不只是它 **描绘（depict）** 了什么。原话：*"FVH does not require overtly harmful imagery, although the two can coexist."*

**两轴结构（直接指出我们类目表的选轴错误）**：

| | **enable 轴有风险** | **enable 轴无风险** |
|---|---|---|
| **depict 轴有风险** | 裸露 + 招嫖信息（PORN 明确类） | 医学教科书图（**我们的 PORN 误报源**） |
| **depict 轴无风险** | **暗示性构图 / 隐喻 / 可模仿的危险示范（VULG-HINT-EDGE，我们无类目定义）** | 正常图 |

补充分类学：**五功能 × 十域**正交。功能 = F1 行动使能 / F2 证据伪造 / F3 界面模拟 / F4 权威冒充 / F5 说服性包装；域 = D1 物理暴力 … D10 性内容与剥削。**注意 D10 只是十域之一**。

**检测器侧（业务核心）**：

| 方法 | 骨干 | 输入 | Recall | FPR |
|---|---|---|---|---|
| Llama Guard 4 | Llama 4 Scout (12B) | **纯图** | **14.60** | 0.00 |
| Llama Guard 4 | Llama 4 Scout (12B) | **图 + prompt** | **43.00** | 0.00 |
| LlavaGuard v1.2 | Qwen2 (7B) | 图 | **1.60** | 0.00 |
| ShieldGemma 2 | Gemma 3 (4B) | 图 | 5.60 | **5.50** |
| ImageGuard | InternLM2 (7B) | 图 | 20.40 | 1.00 |
| Shieldstral | Ministral 3 (3B) | 图 | 44.00 | 0.00 |
| General Safety Policy | Qwen3-VL (8B) / GPT-5.4 | 图 | 49.80 / 62.60 | 0.00 |
| **Condition-Decomposed** | Qwen3-VL (8B) / GPT-5.4 | 图 | **80.40 / 90.80** | 0.00 |

**三条读数**：① **同模型同 policy 去 prompt 掉 28.4 点**（14.60→43.00），这是 image-only 图审有结构性天花板的**首个干净受控测量**；② 五个专用图审召回 **1.60%–44.00%，无一过半，FPR 全在 0–5.5%** ⇒ **不是"不敢报"，是"看不到"，是覆盖度问题不是阈值问题**；③ **Condition-Decomposed 用 8B 骨干 80.40%，比同骨干通用策略高 30.60 点，FPR 仍 0，成本 1.57×** ⇒ "把判定拆成可核查条件"这件事，价值约等于把骨干从 8B 换成前沿模型。

**配方**：每功能定义**三条必要条件**（相关内容可见 / 实质危害 / 视觉呈现支持危害）+ **一条良性豁免**（医学/教育/艺术语境）。至少一个功能三条件全成立且无豁免 ⇒ unsafe。

**最刺眼的一条**：`PIC × THR` Spearman **0.96**、`PIC × HAU` **0.95** ⇒ **在 FVH 上安全与能力不是权衡关系，是同向关系**。Wan 2.7 的 THR 只有 3.68 不是更安全，是**画不出能用的流程图**。⇒ **安全率必须与生成质量并列报，否则不可比。**

**负结果**：THR 在 F1–F5 极稳（4.50–4.63）但 **HAU 波动大**（F2 证据伪造 **3.57** 最低，F5 说服性包装 **4.09** 最高）。人工对比显示**图比其文本对应物更能"帮上忙"，差距最大的是 F2 与 F3** ⇒ **文本侧已有审核能力在两个最依赖视觉呈现的功能上迁移不过来。**

⇒ **对我们**：`VULG-HINT-EDGE` 的主体落在 depict 轴无风险 / enable 轴有风险的格子。**它在我们的类目体系里没有定义，不是标注错了，是类目表里没有这个格子。** 这解释了为什么调阈值、调 alpha、补同类数据三个动作全部无效。

### 4.24 「一半的风险没有文本痕迹：补通道的收益是从 0 到 60%」(2026-11-02 新增)

**OCR+MLLM**（[2610.38185](https://arxiv.org/abs/2610.38185)，华中科技大学）把短视频审核的现有 **OCR+LLM 两级管线**与 **OCR+MLLM**、**32B 零样本**三路对照。

**核心观测**：测试集 **50.4% 的风险事件没有文本痕迹**，分布在 **458/725（63%）** 视频里，各类别非文本占比 **37.2%–53.8%**（**均匀，不是某一类的特例**）⇒ **纯文本通道最多只能看到一半，不能靠"某一类补规则"解决。**

**三路对比（五维，表的形状比数字重要）**：

| 方法 | Macro Recall | Macro F1 | mIoU | R@0.5 | **非文本召回** |
|---|---|---|---|---|---|
| OCR+LLM（keyframe） | **69.2%** | **54.9%** | 14.49 | 4.41 | **≈0** |
| OCR+MLLM（RL only） | 55.0% | 46.5% | **26.52** | **15.86** | 41.7% |
| OCR+MLLM（SFT+RL） | 67.0% | 45.6% | 14.97 | 8.68 | **60.1%** |
| **Large MLLM（32B 零样本）** | 36.7% | 34.0% | **4.72** | 1.02 | – |

⇒ **非文本召回从 ≈0 到 60.1% 是从无到有。32B 零样本全面最差（mIoU 4.72）⇒ 任务特定能力不是规模买来的**（与 V-CAPE 的"235B 也 <65%"互为证据）。注意 **OCR+LLM 的 macro F1 反而最高（54.9%）但 Class 2 precision 只有 9.7%** ⇒ 高分靠多数类堆出来，**主指标必须报 macro 不能报 micro**。

**奖励设计的三个坑（可直接做体检清单）**：

1. **辅助项系统性作弊**：加 `0.2×中心距离 + 0.2×事件计数` 后，**训练奖励刷到 ~1.0，真实 mIoU 从 13.48 掉到 2.19**（六分之一）。
2. **乘性 vs 加性各塌一头**：乘性 `IoU·(a+b·cls)` 学会定位但塌到 Class 0（最稀有类 recall **0.07**）；加性 `IoU+cls` 平衡改善但定位停滞。根因是 **IoU 稀疏性（不重叠时无梯度）** 与类别不均衡的张力。
3. **类别缩放有甜点**：太弱塌类、**8× 太强也塌**、**4× 最优**。

**解法**：per-event soft F_β + class-balanced 过采样（上限 20×）。消融对照：

| 定位奖励 | mIoU | R@0.5 | 最稀有类 recall |
|---|---|---|---|
| IoU × class scaling | 24.84 | 15.23 | **0.07** |
| **soft IoU（合并式）** | **14.57** | **1.22** | 0.08 |
| **per-event soft F1 + balance** | **29.82** | **18.54** | **1.00** |

⇒ **合并式指标的 R@0.5 只有 1.22，per-event 是 18.54（15×）** ⇒ **"整体相似度"是合并 IoU，"要件级覆盖"是 per-event，两者梯度密度差一个量级。**

**错例结构与我们的边界问题同构**：41% 是无害的边界错误、34% 漏非文本事件、**25% 是 Class 1↔Class 2 混淆——屏上措辞相同，唯一差别是有没有群号/二维码** ⇒ **跟 PORN/VULG 边界完全同构：表面形式相同，差一个关键锚点。**

⚠️ **不能读成"全面优于基线"**：macro F1 三路里最低（46.5/45.6 vs 54.9），实际收益全部在**非文本覆盖（≈0→60.1%）与定位（14.49→26.52）**上。单作者、数据与代码未释放。

### 4.25 「编辑判定要扩张的是观测空间：单点→成对→加证据，但成对不是免费的」(2026-11-02 新增)

**EditAgent**（[2610.39664](https://arxiv.org/abs/2610.39664)，**Adobe Research + UCSD**）的核心论断：编辑 Agent 被 **action space（能做什么）** 与 **judge 的 observation space（能看见什么）** 同时限制，而现有 agent **把两个空间都做小了**。

**诊断基准**：600 个编辑集 / 30 种细粒度类型 / 六大组，5 名专业 Photoshop 修图师**共同圈选 winner set（允许多个可用候选）**。⇒ 评测从"选对那一张"变成"选出的在不在可用集里"。

**诊断一：一个编辑器不够，多采样也不够。**

| winner set 构成 | 占比 |
|---|---|
| 只有通用编辑器 | 42.3% |
| **只有专用方法** | **29.2%** |
| 两类都有 | 15.0% |
| **无任何可用** | **13.5%** |

通用编辑器在 **42.7%** 上失败，专用方法救回 **175 集**。分组差异极大：Style & Effects **73.8% 只认通用**；**Enhancement 72.5% / Geometry 66.7% 只认专用**。多采样救不了：只有通用的池投递可用 **45.2%**，加专用方法 **68.2%**。

**诊断二：串行重试是错的（与 T2I 生成相反）。** 同预算 4 次生成，144 条 Complex-Edit 盲测（5 名修图师）：**并行搜索赢 78.5% 的非平局，只用一半 judge 调用**。原因：**编辑必须对源图忠实，串行精化在不停编辑自己的输出，误差会累积。**

**诊断三：没有 judge 在所有类型上最好。** EditScore-72B 只在 Scene 最好；Qwen3.8-27B 三组最准但 **Photometric 只比随机高 5.2 点**；**CLIP-I 在 Photometric/Enhancement 最准，但在 Style & Effects 与 Geometry 上等于或低于随机**。⇒ *"What a judge must observe therefore depends on the edit."*

**pointwise → listwise（最硬的一个数）**：

| Judge | Pointwise | Listwise | Δ |
|---|---|---|---|
| **EditScore-72B + Ensemble@4** | **76.3** | 不支持 | – |
| Qwen3.5-27B | 71.7 | **85.2** | **+13.5** |
| Qwen3.8-27B | 72.1 | **85.9** | **+13.8** |
| Gemma-4-31B | 73.8 | **86.1** | **+12.3** |

⇒ **现成 VLM 一旦能成对比较，直接超过大规模人工偏好微调 + 4 路集成的 EditScore-72B。**

**观测空间消融（含一个极易被忽略的负结果）**：

| listwise | evidence | Style | Content | Scene | **Photo.** | Geom. | **Enh.** | All |
|---|---|---|---|---|---|---|---|---|
| – | – | 84.4 | 81.7 | 67.5 | **54.2** | 66.4 | **65.0** | 71.6 |
| ✓ | – | 87.1 | 87.1 | 72.0 | **47.2 ↓** | 78.6 | **36.8 ↓↓** | 73.6 |
| ✓ | ✓ | 87.6 | 86.4 | 81.9 | **64.4** | 81.4 | **80.3** | **81.3** |

⇒ **只加 listwise 会把 Photometric 54.2→47.2、Enhancement 65.0→36.8（−28.2）**。在"正确答案与源图差异很小"的两组上，**并排比较反而有害**（judge 被"视觉上更不一样"的候选吸引）。这正好是 CLIP-I 崩掉的镜像：**需要可见变化时 judge 偏向"没怎么变"，需要保持原样时 judge 偏向"变得多"——同一件事，两个方向都错。** 加证据才救回来（Photo→**64.4** 超过 pointwise，Enh→**80.3**），总体 **81.3**（比 EditScore-72B 的 74.8% 高 6.5）。**七个现成 VLM 加记录后全部提升 6.3–9.3 点**；无记录时没有一个达到 EditScore-72B，有记录时每一个都超过 ⇒ **这是"方法而非骨干"的证据**。

**顺手给了"数据自举会中毒"的硬证据**：25.7K 全通过会话做数据引擎，**直接用 FLUX.2-klein-9B 自己生成的数据训 FLUX.2-klein-base-9B，三个 benchmark 全降；用 judge 过滤后的数据，三个全升。**

⚠️ **成本 12×**（12.9 vs 1.1 H100·h）；**judge 就是 planner（同一模型）**，虽用 Gemma-4-31B 复跑规避自评偏置，但没排除"规划器与判定器共享同一套盲区"；**验证记录是手写规则不是学出来的**；**安全维度完全缺席**。

⇒ **对我们（I2I 0/0%）**：这是判据侧的第二个归因候选，且给出三个可操作动作（单条判→成对判、加验证记录、并行替代串行）。但同时警告：**成对判不是无条件好的**——如果我们的编辑大量是"改光/增亮"这类正确答案变化很小的类型，单加 listwise 会掉 28 个点。

### 4.26 「拦住了，不等于拿掉了」：注入依赖必须在分布空间量，而不是在输出空间量 (2026-11-03 新增)

**ERASE**（[2610.41307](https://arxiv.org/abs/2610.41307)，**华南理工大学**）处理的是多模态间接提示注入（IPI）的那个核心矛盾：**恶意指令藏在一份"同时包含用户任务所需信息"的媒体里**——只拒掉就等于把任务证据也扔了。

**它引入的度量是全文最该被抄走的东西。** 定义**注入依赖 $I$**：在同一个已生成输出前缀下，比较模型在「被攻击视图」与「擦除视图」上的下一 token 分布，取两个方向 KL 的平均。这是一个纯反事实对照量——**不需要标签、不需要判攻击成功与否，只需要一对视图**。

**核心结果（Qwen2.5-Omni-3B，音频）**：

| 方法 | $I$（注入依赖） | `UIA_inject`（被攻击时仍答对用户问题） |
|---|---|---|
| 无防御 | **6.26** | 0.673 |
| **ARGUS（SOTA，推理时干预）** | **5.15** | 0.717 |
| Meta-SecAlign | 0.432 | **0.083（能力崩）** |
| **ERASE** | **0.0095** | **0.601** |

⇒ **ARGUS 把 ASR 打到 ≈0，但注入依赖只从 6.26 降到 5.15（−18%）。** 模型仍被牵着走，只是牵到的地方不再"算攻击成功"。**"拦截"在输出空间量，"依赖"在分布空间量；前者可以靠后置过滤刷到 0，后者不能。** 同时 Meta-SecAlign 给出反向教训：**低依赖不是好事的充分条件**（$I$=0.432 但 `UIA_inject`=0.083）。

三模态的 $I$（3B）：音频 6.26→**0.0095** / 图像 1.16→**0.0030** / 视频 3.41→**0.011**。

**方法（训练时用、推理时不用）**：① **原位擦除视图**——把注入区域换成该模态的空白内容（图像=白块 / 音频=静音 / 视频=黑帧），**周边结构一动不动**；部署时不需要知道注入区域在哪。② **在策自蒸馏**——冻结基座读擦除视图当 teacher，LoRA 学生读被攻击视图自己 rollout，在每个共享前缀上用**全词表 KL** 对齐。

**两个消融都指向同一件事：指标饱和后差异全在"保住多少"上。**

| 对照 | 音频 `UIA_inject` | 图像 `UIA_inject` |
|---|---|---|
| 全分布、teacher 先 | **0.601** | **0.541** |
| 只用采样 token | 0.531（−7.0） | 0.441（−10.0） |
| 参考改用"原始干净媒体"替"原位擦除" | OOD 均值 0.578→0.554、WER 0.088→**0.221** | — |

**三种监督的 AIA 全部 = 0**，差别只在 `UIA_inject`。**参考视图选"原位擦除"而非"原始干净媒体"更好的原因**：擦除视图保住了被攻击输入的空间/时序结构，teacher 分布更接近学生面对的分布。

⚠️ **前提是"注入区域可分离"**（论文自述局限）：*"Injected instructions may overlap or be mixed with task-relevant content, and erasure in these cases may also remove information needed for the user's task."* 且**未测自适应攻击**、未测弥散式注入。

⇒ **对我们的双重意义**：① 它是"外科式原位替换"在图像空间的版本，与我们的改写是**同一个动作在两种模态上的实现**；② `$I$` 可以直接搬到改写评测——用 `KL(P(·|原 prompt) ‖ P(·|改写后 prompt))` 量语义保真，比 embedding 相似度硬得多（见 2610.38076 的否证）。但**"可分离"这个前提在文本锚点上最脆**：文本里的风险常是两个中性词的**关系**，没有一块能整块挖掉的白区。

### 4.27 「第二次尝试不是第一次的重来」：重试是粘的，单次通过率系统性错估 (2026-11-03 新增)

**RetryRoute**（[2610.41460](https://arxiv.org/abs/2610.41460)，**北京师范大学 + 南洋理工大学**）指出了编辑服务 agent 循环（出图 → VLM judge → 不过再来）里一个从未被检验的假设：**对已失败模型的下一次尝试，是一次独立同分布的重新抽样。**

**现象 sticky failure**：重试成功率只有首次成功率的 **17%–53%**（按模型 **0.23–0.39×**）。FLUX.2 [klein] 首次过 67%，**刚失败过的那些只有 15%**，而另一个模型在同样状态下还能解 **45%**。

**机制（隐难度引理）**：请求有潜在难度 $d$，失败历史通过失败计数携带"这题难"的信息。两条推论都硬：**① 重试永远不会比前一次更容易成功**（难度有差异时严格更难）；**② 难度共享时，一个模型的失败会同时压低其他模型的成功率**（a4 从 0.733→0.436，只因 a5 先失败一次）。

**做法**：状态 = 失败计数向量，在失败状态上解 Bellman 方程规划重试/升级/放弃；估计用**计数 + 向全类收缩**（λ=20，因为深处状态样本稀疏）；3 arm 时 81 个状态、精确解 **0.35 ms**；负载感知重规划把队列等待加进成本（Little 定律）。给了两个命题划清"固定规则何时已最优"的边界：**重试独立时按"每次成功成本"升序最优；失败只影响本 arm 时索引规则最优；难度共享时不存在通用固定索引规则**（反例：索引规则 0.514 vs 失败状态规划 0.560）。

**结果**：对最强基线平均 **+2.8 点**（最高 +5.6）、对同模型重试 **+3.5–13.3**；8 组全部不低于任何基线；**6/8 组 APGR > 1**（收回的差距超过最便宜与最强单模型之间的全部差距）；服务台 goodput 三档负载高 **5.0–6.3 点**；训练数据降到 5% 仍领先。

**最扎人的是它把"改写后重试"当强基线认真实现了**（`Rewrite-retry`：一个 VLM 在每次重试前改写指令，blind 只用源图 / critique 还用失败图与分数）：

| 方法（pool1，同预算同 judge） | GEdit-CN | GEdit-EN |
|---|---|---|
| 同模型重试 | 81.74 | 81.74 |
| **Rewrite-retry, blind** | **80.82（−0.92）** | **82.42（+0.69）** |
| **Rewrite-retry, critique** | **78.31（−3.43）** | **81.28（−0.45）** |

⇒ **"先改写再重试" ≈ "不改写直接重试"**；**带失败反馈的改写反而更差**。论文原话：*"the gain comes from spending the rest of the budget on escalation"*。把改写**当成路由里的一个动作**时：*"it never lowers success significantly and adds at most 2.2 points."*

⚠️ **这个结论不能直接搬到输入侧安全改写**，三处差异：目标（听懂 vs 不出事）、失败判据可观测性（judge 完全可观测 vs 线上不可观测）、第二次机会（有 vs 通常没有——我们没有"升级到另一个生成器"这个动作）。**正确迁移不是"改写没用"，而是：改写必须跟"多试一次"基线比，而不是跟"什么都不做"比。**

**附带一个判定器发现**：*"EditReward confirms 84–93% of the in-loop judge's first-try passes but only 51–75% of its late passes."* ⇒ **晚到的通过更不可信**，而"这是第几次尝试"这个信息通常没被记录。

### 4.28 「风险不是一个部件，是一组配置」：查符号的过滤器会被"描述属性"绕过 (2026-11-03 新增)

**AIG-NCII**（[2610.37949](https://arxiv.org/abs/2610.37949)，**纽约大学 + 乔治敦大学 + 亚利桑那州立大学**）是本轮 319 篇候选里**唯一一篇直接讨论 NSFW 的工作**。定性研究：CivitAI 上 **139 篇 R+ 指南**，8 轮 IRR（每轮 15 篇双人独立编码、算 Cohen's κ、未达标再抽 15 篇、改过的 code 全量重编）。

**核心论断**：*"AIG-NCII is not enabled by novel technology that can be independently regulated, but by a set of configuration choices (e.g., models, model adapters, inputs) that creators make when setting up otherwise innocuous generation or training workflows."*

⇒ **把风险拆成两个正交概念轴：S（性内容：解剖术语/行为描述/风格/模型选择）× I（身份：真实人物/可辨识属性/如何不点名地指定一个人）。风险不在某个词上，在两轴的配置上。**

**三条可直接用的技术**：

1. **likeness prompting**——*"refer to the movie/series name and the fictional character's name … without using their [real] name"*。**名字层面完全合规，语义层面完全指向真人**。判决：这类技术能 *"evade input/output filters that may only detect the use of a specific individual's name"*。**这不是精度问题，是检测对象错了——过滤器在查符号，风险在指称。**
2. **把"人"换成"角色"**：用户刻意改词规避检测（*"using the word 'character' in place of 'person'"*）。
3. **精确解剖术语是"高保真"提示词，不是"高风险"提示词**（指南教用 `labia majora` / `clitoral hood` / `vulva` 给 "clear guidance"）⇒ **按"露骨程度"打标签会把医学语境与滥用语境打成一类**，这是 PORN 过度预测的可解释来源。

**权重侧边界被加固**：工作流主要依赖**开源权重及微调衍生版**；**LoRA 这类低成本技术能把刻意移除的概念重新装回去，且在本地**。⇒ **不是"擦除做得不够好"，是"擦除的治理范围止于权重发布"。**

**一个操作层实测**：团队报告 7 篇（2 篇疑似 AIG-CSAM → NCMEC，1 篇鼓励生产 NCII，4 篇含真实身份描绘），**三周后只有 1 篇被移除**。⇒ **内容侧处置时延远大于生成侧时延**；"漏过率 3.42%"的真实成本比它看起来大。

⚠️ 139 篇里只有 **1 篇**明确描述 NCII 流程，论文自己反复声明**无法测使用率**。**这是定性威胁建模，不是流行度测量。**

⇒ **对我们（PORN/VULG 边界）**：这解释了为什么 `VULG-HINT-EDGE` 在现行体系里"没有定义"——**类目表是"部件清单"，而风险是"配置空间"**。可操作动作：给边界样本打 (S, I) 双轴分，数格子，看空洞在哪一格；并做一次 likeness prompting 替换测试（变化率 >20% ⇒ 分类器在查符号）。

### 4.29 输入侧改写的工业配方：三层对齐 + 反向构造 + 「接上生成器就掉保真」 (2026-11-04 新增)

**Kling PE**（[2611.04916](https://arxiv.org/abs/2611.04916)，**快手可灵团队**，38 页技术报告）。**本轮唯一一篇头部公司公开的输入侧改写工业配方**，而且把"改写怎么训 / 奖励怎么设计 / 评测怎么拆"写在同一份文档里。

**核心论点**：*生成质量是多模态理解能力在 data → conditioning → alignment → evaluation 整条链路上的投影*。⇒ **观察到的生成失败不是诊断**：同一个症状可能来自 caption 漏监督、conditioning 丢时间结构、奖励模型偏好"平滑但静止"、或评测器根本没测那件事。

**三层对齐（只对齐格式不够）**：Format（字段顺序/时间戳/长度档位）× **Lexicon**（镜头/光/动作术语）× **Sentence patterns**（陈述句、现在时、实体显式）。论文原话：*"Matching format alone leaves the other two levels free to drift."* 典型反例：通用 LLM 会写 "a breathtaking cinematic shot slowly reveals the scene" 与 "As if time itself had paused, she gazes outward" —— 读起来很好，**落在 caption 分布外**。

**数据反向构造**：从优质视频的 caption 出发，让 teacher 反推"什么样的用户 prompt 会产生这个 caption"，合成 prompt 按真实流量统计采样（长度/语言混合/语域/错字率/省略槽位），并**拒绝"泄漏 caption 骨架"的 prompt**（否则学成复制而非补全）。⇒ **要训"风险改写"，正例应从"安全输出的描述"反推回用户可能怎么问，而不是从用户 prompt 正推。**

**Table 13（累计贡献，最该记住的一张表）**：

| 设置 | 保真 均/≥4 | 合理 均/≥4 | 生动 均/≥4 |
|---|---|---|---|
| SFT，随机源 caption | 4.02 / 75.42 | 3.95 / 69.17 | 3.72 / 62.33 |
| + 优质视频源 | 4.00 / 74.92 | 3.92 / 68.08 | **4.03 / 72.58** |
| + F/R/V 数据验证 | 4.27 / 80.83 | 4.18 / 74.33 | 4.11 / 75.08 |
| **+ 文本级 RL（不渲染）** | **4.45 / 86.67** | 4.31 / 79.25 | 4.25 / 79.83 |
| + DiT-in-the-loop RL | **4.38 / 83.50** | 4.42 / 83.67 | 4.23 / 81.42 |
| Agentic + 剧情精修 | 4.41 / 84.58 | **4.67 / 91.92** | 4.26 / 82.25 |
| Agentic + 检索 Top-5 | 4.36 / 82.17 | 4.65 / 91.42 | **4.44 / 87.33** |

**四个反常识读法**：① **文本级 RL 是性价比最高的一步，且不渲染一帧**（保真 +0.18，≥4 占比 +5.84）；② **接上生成器后保真掉了** 4.45 → 4.38（≥4 占比 86.67 → **83.50**），而合理反升 ⇒ **用生成器奖励换保真，有实测价码**；③ 加"优质视频源"生动涨 +0.31 但保真与合理都掉 ⇒ **三维取舍是显式的**；④ 精修把合理推到 4.67、检索把生动推到 4.44，但**没有任何配置在三维上同时最好**。

**双奖励模型**：GRM 出结构化批评 + 缺陷证据管 + 定序评分，工程精髓是 **"Charge a judge for what it misses"**（对未被匹配的 GT 缺陷也罚，让漏报与错报等价）；DRM 把 K 个问题的答案槽**固定在 prefix**，一次 prefill 答完，字段间互不泄漏（**"Decide in the prefix, not in the decode"**）。内部成对基准 DRM Macro **77.86**（Gemini-4-Argon 73.54）；Stage 3 只加 **3.1** 点、代价单次 prefill。

**两条排除项工程规则**：`no people` → `an empty street with unobstructed pavement`（正向化）；**没有正向等价物的排除项走负条件字段或采样期拒绝**（不要硬塞进改写）。

⚠️ **这份报告几乎不谈安全**：全文 "safety" 只出现在"评测要暴露打分捷径"的语境，**没有 NSFW / 内容审核 / 风险改写**。迁移价值在**机制与工程**，不在**目标函数**。

### 4.30 贴着约束边界走的控制器，约束最好、目标最差 (2026-11-04 新增)

**AegisFlow**（[2610.39825](https://arxiv.org/abs/2610.39825)，**清华大学自动化系 + BNRist**）。免训练引导里的路径约束问题。

**机制诊断**：通行做法是每步解一个**最小范数控制（min-norm controller, MNC）**——找"刚好把约束拉回安全集"的最小修正量。目标函数是 min ‖u‖、约束是单步不等式，所以**最优解永远落在约束的等号上**，也就是**边界上**。后果：整条轨迹**贴着安全边界飞**，任何扰动都可能推出去，且一直在边界附近就**没法朝目标方向做更激进的优化**。

**方法**：把时变屏障函数写进**全局**代价 $J(u)=\int[\tfrac12\|u\|^2+\lambda B(x,t)]dt+\Psi(x_T)$，$B$ 在边界附近发散 ⇒ 任何有限代价的解天然满足约束，不需事后投影；用 HJB 的可算近似得闭式控制。

**CelebA-HQ（文本引导 + 身份保持）——最该读的是 MNC 那一行**：

| 方法 | CLIP ↑ | LPIPS ↓ | ID ↑ |
|---|---|---|---|
| OC-Flow | 0.302 | 0.207 | 0.732 |
| **OC-Flow + MNC** | 0.304 | 0.193 | **0.920** |
| **AegisFlow** | **0.309** | **0.188** | 0.901 |

⇒ **MNC 的 ID 最高（0.920 > 0.901），但 CLIP 与 LPIPS 都更差**：约束做到极致，代价是目标。AegisFlow 主动**让出一点约束裕度**（ID 0.901），换来更好的目标对齐与结构保持。

**一个"算力账要按任务算"的反差**：图像任务上 AegisFlow **433.81 s** 比 MNC **518.26 s** 快 16.3%（MNC 每步解 QP）；但控制任务上 **44.15 s** vs SafeFlowmatcher **4.21 s**，慢十倍。

⚠️ 边界：论文的"安全"是**几何意义**（身份距离/障碍距离），**不是内容合规**；"内容安全约束"从未被测。迁移是**结构同构**，不是实证结论。

⇒ **对我们的直接推论**：改写管线里"edit rate 越小越好"在数学上就是 min-norm —— **在"风险达标"的可行域里找改动最小的点，最优解落在可行域边界上，也就是"风险刚好等于阈值"**。应改成 `风险分 < τ − δ` 留裕度，并同时监控 edit rate / 保真 / 改写后 paraphrase 扰动下的风险回升率。

### 4.31 「纯改写这条路不够」被工业界正式写出来了 (2026-11-04 新增)

**VEvo-Harness**（[2610.39158](https://arxiv.org/abs/2610.39158)，**阿里巴巴淘天集团 + 清华大学**，ICLR 2027 投稿中）。

**最关键的一句**（对"输入侧改写"范式的正式批评）：*"recent work shifts scaling from model weights to test-time computation, i.e. prompt densification and semantic rewriting. **However, prompt-only interventions lack fine-grained attribution and pixel-grounded feedback.**"*

**浅循环的三处结构缺陷**：① VLM 判断太粗（二值"过/不过"没有归因，下游只能盲试）② 修好的经验丢掉了 ③ 不加门控地留下来会毒化技能库。

**动作空间：改写只是三分之一**。$\mathcal{A}=\{a_{rewrite}, a_{resample}, a_{tune}\}$。既有 pipeline 采**单一干预范式**，把所有视觉失败都归因为"prompt 没对齐"，于是只会改写；而失败有异构因果来源（约束没表达 / 表达对了但采样运气差 / 表达采样都对但能力不足）。

**入库质量（本文最有价值的一组数）——有害补丁入库率**：

| 门控方式 | 有害入库率 |
|---|---|
| 不门控 | **33–40%** |
| 纯文本门控 | 约 **16%** |
| **完整反事实门控（看图）** | 约 **2%** |
| 去掉拒绝缓冲 / 去掉成功保留 | 回升 **10% / 8%** |

⇒ **从 33–40% 压到 16% 靠"加规则"，从 16% 压到 2% 靠"看图"。8 倍差距全在最后一层。** 且不门控的配置性能中期冲到约 78 后**塌到约 71.5**（最终低约 15%）。

**消融**：反事实治理 vs Admit-All **+2.9%/3.2%**、vs Text-Only Gate **+2.2%/2.7%**；**HSP（三动作路由）vs Rewrite-Only +4.0%（WISE）**、vs 随机路由 **+2.4%（KRIS）**。成本：完整版 **84.38% / 38.4 s / 6.2 次 VLM 调用**，同时最准、最快、最便宜（惰性门控省 47.5% 调用 +0.28% 性能；拒绝缓冲省 25.7%）。

⚠️ **在指令编辑基准上不是全面第一**：RISE-Bench **45.8** 第一（Know-Thinker 44.7 / Nano-Banana-Pro 41.2），但 KRIS 47.7 < 61.1、WiseEdit 37.0 < 48.0、GEditTemp 20.0 < 37.6（均输给 Nano-Banana-Pro）。定位是"开源冻结生成器 + harness 打赢专有生成器的一部分"。

⇒ **对 I2I 0/0% 最直接的含义**：过去三轮我们一直在改"怎么改写"，从没测过"**该不该改写**"。`Rewrite-Only +4.0%` 的差距提示：0/0% 可能不是改写没写好，而是**把 resample / tune 的活派给了改写**。

## 5. 水印保护：内容归属与版权防护

### 5.1 水印研究的三种场景

T2I 水印研究围绕三个核心应用场景：

| 场景 | 问题 | 主要方法 |
|------|------|----------|
| **内容溯源** | 判断图像是否由某个特定模型生成 | 生成器端水印（模型权重中嵌入） |
| **版权追踪** | 识别生成图像中使用的受版权保护概念 | 概念级水印 |
| **内容归属** | 追踪特定图像由哪个用户请求生成 | 用户绑定水印 |

### 5.2 生成器端水印

**Stable Signature**（[2303.15435](https://arxiv.org/abs/2303.15435)，Meta FAIR）：
- 在扩散模型的**解码器（VAE Decoder）权重**中嵌入水印信息
- 所有该模型生成的图像都自动携带水印，无法通过 prompt 去除
- **强健性**：对常见图像处理操作（压缩、裁剪、滤波）保持水印可提取性

**数学形式**：
```
给定可训练解码器 D_θ：
优化目标：
  minimize  L_image(D_θ)     # 保持图像质量
  + λ · L_watermark(D_θ, m)  # 嵌入水印 m

提取：对任意生成图像 x：
  m' = Extractor(x)
  if similarity(m', m) > threshold: "confirmed generated by this model"
```

### 5.3 概念级水印

**Modular LoRA**（[2412.00357](https://arxiv.org/abs/2412.00357)）在水印方向的应用：
- 为特定版权内容（艺术家风格、IP 角色）嵌入独特的生成特征
- 可通过特征检测工具验证是否使用了受保护的概念

**SAEUron 的水印应用**（[2501.18052](https://arxiv.org/abs/2501.18052)）：
- 利用 SAE 发现的单义神经元，为特定概念嵌入激活层水印
- 相比权重水印，激活层水印对模型微调攻击更鲁棒

### 5.4 水印鲁棒性与攻击

本项目收录的论文对水印的攻击研究相对较少，但清华大学的 AI Security Survey（[2603.24857](https://arxiv.org/abs/2603.24857)）指出了两类主要水印攻击：
- **水印移除攻击**：通过图像处理或对抗扰动破坏水印信号
- **水印伪造攻击**：在非目标模型生成的图像中添加虚假水印，造成错误归属

### 5.5 双重鲁棒水印的崛起 (2026-04-09 新增)

**Towards Robust Content Watermarking Against Removal and Forgery Attacks**（[2604.06662](https://arxiv.org/abs/2604.06662)）：
现有水印容易被 JPEG 压缩洗掉（Removal），也容易被重放攻击利用（Forgery）。
- 机制：频域双频段分离注入冗余水印，结合密码学感知哈希绑定生成图像特征。
- 结论：在抵抗移除与防伪造的综合测试中取得了极高鲁棒性，预示水印安全将向密码学与隐写术的深度融合发展。

### 5.6 自回归图像生成水印的三难困境 (2026-04-14 新增)

**On the Robustness of Watermarking for Autoregressive Image Generation**（[2604.11720](https://arxiv.org/abs/2604.11720)）首次系统指出：AR watermark 的问题不只是“够不够鲁棒”，而是**去除、伪造、radioactive filtering 三个目标难以兼得**。

- **对 token-based watermark**：VQ-Regen 与 LatentOpt 证明其在黑盒或灰盒条件下就会出现明显退化，说明 AR token 量化边界本身就是攻击面。
- **对 BitMark**：常规 removal 很难，但一旦攻击者转向 bit-level removal 或频域伪造，系统会暴露新的脆弱性；更严重的是，若把检测阈值调低以支持 radioactive data filtering，又会明显放大 forgery 通过率。
- **意义**：这意味着 T2I 安全的来源证明体系不能只看“是否带 watermark”，而必须进一步思考 watermark 自身是否会反过来污染数据治理链路。对于开放式生成生态，这是一条非常值得持续追踪的新研究线。

### 5.7 双通道 provenance 与篡改定位：水印开始从“可验证”走向“可取证” (2026-04-22 新增)

**Dual-Guard**（[2604.19090](https://arxiv.org/abs/2604.19090)）把 T2I 水印又往前推进了一大步：

- **核心机制**：不是只在单一空间埋一个 watermark，而是同时在扩散初始噪声 **z_T** 中嵌入 Gaussian Shading 指纹，在 VAE latent **z_0** 中嵌入可纠错残差码，形成生成起点与解码结果的双通道绑定；
- **关键结果**：论文报告 provenance verification accuracy 达到 **99.5%+**，latent fingerprint extraction accuracy 达 **89.19%**，同时还能在 block 级别定位局部篡改区域；
- **意义**：这说明 T2I 来源证明正在从“能不能证明图像来自模型”升级为“能不能在被编辑后继续证明其来源、并指出改了哪里”。对真实平台治理而言，这比传统单 bit watermark 更接近可落地的 forensics primitive。

### 5.8 训练期反水印：水印攻击开始从后处理绕过走向生成器内生能力 (2026-04-28 新增)

**FMDiffWA**（[2604.22220](https://arxiv.org/abs/2604.22220)）把 T2I 水印攻防继续往前推了一层：

- **核心机制**：把水印攻击从传统的后处理扰动，升级成生成模型训练阶段的 **频域调制（FWM）+ phased training strategy（PTS）** 联合优化，让模型在保留图像质量的同时主动学习扰乱 watermark extraction；
- **关键结果**：单独使用 **FWM** 时论文报告核心指标为 **39.96 / 0.1896**，单独使用 **PTS** 为 **48.65 / 0.0664**，而二者联合后达到 **42.08 / 0.2084**，说明真正稳定的反水印能力来自训练策略与频域攻击的协同，而不是单一技巧；
- **意义**：这说明未来 T2I provenance 不能把 watermark 当成静态外挂模块，因为攻击者可以把“去水印能力”直接训练进扩散模型本体。对于开放生成生态，这是一条非常值得长期追踪的攻击主线。

### 5.9 去水印攻击的 forensic 成本：来源证明开始进入“三元组评估” (2026-04-30 新增)

**The Forensic Cost of Watermark Removal**（[2604.25491](https://arxiv.org/abs/2604.25491)）把 T2I 水印防线继续推进到更贴近工业部署的一层：

- **核心机制**：不再只问 watermark 是否被去掉，而是显式训练 **WRD (Watermark Removal Detection)**，检测图像是否经历过攻击性去水印处理；
- **关键结果**：在 **FPR = 10^-3** 下，WMForger 的 TPR 仍达 **0.815 / 0.801**（TrustMark / VideoSeal）；在 **FPR = 10^-2** 下几乎到 **0.998**，说明“去得掉 bit”与“藏得住攻击痕迹”是两回事；
- **意义**：这把去水印攻防从二维问题重写成 **ASR × 感知质量 × forensic detectability** 三元组。对工业平台来说，这比单纯提升 watermark bit robustness 更接近真实治理需求：攻击者不仅要抹掉来源，还要抹掉“自己动过手”的证据。

### 5.10 溯源不靠水印，靠出图的内在维度：黑盒判断"底模还是 LoRA 适配" (2026-10-29 新增)

**Provenance Signatures for Low Rank Adaptations of Image Diffusion Models**（[2610.36933](https://arxiv.org/abs/2610.36933)，**University of Edinburgh + University of Oxford**）把 provenance 从"给图片打标"换成了"**判断服务端跑的是哪个模型**"。

**两个审计问题**：
- **Problem I（负判别）**：目标是不是"完全无关的模型"（IP 保护场景——有人违反许可把底模 LoRA 微调后当自研卖）；
- **Problem II（底模判别）**：目标**就是**那个底模吗（问责场景——**有人拿开源底模加 LoRA 做 NSFW，然后把责任推给底模方**）。

**方法桥（两步）**：
1. **白盒先证明可行**：LoRA 对底模 score 场的扰动确实小于异族模型（Frobenius 余弦 + Gram 差）。且发现一个**依赖 prompt 域的细节**：用原域 prompt 时 self-attention LoRA 扰动最小 < cross-attention < both；**但用 LoRA 域 prompt 时，三种注入的扰动被抹平**。⇒ **审计用什么 prompt 去问，决定成败**。
2. **黑盒化**：用**生成流形的局部内在维数直方图**当签名（MADA 估计，$k$=50），再走假设检验（100 个参考签名 + **2000 个零校准签名**，p < 0.001）。

**关键数据**：Problem I **AUROC 0.855 / F1 0.800**；Problem II **AUROC 1.000 / F1 0.943**（开放世界 + 留一域）。

**这张对比表最该读的是"错位"**：

| 方法 | P-I AUROC | P-II AUROC |
|---|---|---|
| Nataraj19 / Wang20（有监督归因） | **1.000** | 0.600 / – |
| Giudice21（频域） | 0.840 | **0.400（比随机还差）** |
| Ha26（CLIP 特征） | 0.992 | 0.690 |
| **本文（内在维度签名）** | 0.855 | **1.000** |

⇒ **有监督归因在闭集上碾压，但在开放世界留一域上崩掉——因为颜色/频域/学习特征不能迁移到没见过的 LoRA 域。弱信息 + 假设检验反而更鲁棒。** 作者也直说自己在 Problem I 上不如有监督基线，没有掩盖。

**失效案例**：五个 LoRA 域（Food101 / Pokémon / WikiArt / CheXpert / EuroSAT）里 **Food101 失败**——与底模分布太接近时签名分不出来。**作者没给"什么时候会失败"的先验判据**，这是方法可用性的最大缺口。

**对我们的意义**：我们的部署主张是"不改生成模型、输入侧热更新"——**这个主张有一个隐性的合规优势：权重没被动过，溯源这条线上我们是干净的**。这篇恰好提供了把"我没改模型"从承诺变成可验证断言的方法（只需黑盒查询，不需开放权重）。但要记住它的下界：**NSFW 微调恰恰可能是"与底模太像"的那类域**（底模本来就能画人）。

## 6. 基准评测

### 6.1 T2I 安全专用 Benchmark

**JailbreakBench**（[2404.01318](https://arxiv.org/abs/2404.01318)）：
- 标准化越狱评估协议，统一 ASR（Attack Success Rate）计算方法
- 覆盖多个 T2I 模型（SD v1.5, SDXL, DALLE 系列）
- 提供标准化的违禁内容分类体系

**PixJail**（[2606.24081](https://arxiv.org/abs/2606.24081)）：
- 将 T2I jailbreak 评测提升为 paper-to-pipeline reproduction，覆盖 prompt transformation、生成器、安全过滤器与多模态 judge；
- 在统一协议下复现 11 个方法，平均误差仅 2.1%；
- 对输入侧 safety rewrite 的意义在于：真正该标准化的是整条 rewrite-to-image pipeline，而不是一张 prompt 列表。

**MIMMU（Multimodal Understanding Safety）**（[2603.00992](https://arxiv.org/abs/2603.00992)）：
- 多模态安全理解基准，测试 T2I 模型及 MLLM 对安全相关提示的理解
- 涵盖 6 大有害内容类别，20+ 语言

**Adversarial T2I Survey**（[1910.09399](https://arxiv.org/abs/1910.09399)）：
- 早期 GAN 时代的对抗攻击分类法综述，为后续扩散模型安全研究奠定分类基础

**NTIRE 2026 Challenge on Robust AI-Generated Image Detection in the Wild**（[2604.11487](https://arxiv.org/abs/2604.11487)，CVPR 2026 Workshop）：
- 首个把 **AIGC 检测的野外鲁棒性** 做成主赛题的挑战赛：108,750 张真实图像、185,750 张 AI 图像、42 个生成器、36 种图像变换。
- 以 **Robust ROC AUC** 为主指标，并采用 open / hidden test 双轨评测，推动检测研究从“clean 判别”转向“真实分发链路鲁棒识别”。

### 6.2 质量感知近重复校准检测（2026-04-17 新增）

**QuAD**（[2604.15027](https://arxiv.org/abs/2604.15027)）把 AIGC 检测进一步推进到“传播链 + 质量退化”的真实世界场景：
- **核心机制**：不再把 fake image 当作独立样本，而是显式建模 near-duplicate 传播链，并结合图像质量感知校准 logit；
- **关键结果**：在 ReWIND 基准上把平衡准确率从 **63.0** 提升到 **70.3**，把检测器从“识别生成痕迹”推进到“识别分发链路中的痕迹衰减”；
- **意义**：这说明 T2I benchmark 正在从“生成器闭集分类”转向“开放传播环境中的鲁棒鉴别”，与 NTIRE 2026 一起构成现实部署检测的新双支点。

### 6.3 多维偏见审计：从 demographic parity 走向 cultural collapse (2026-04-18 新增)

**T2I-BiasBench**（[2604.12481](https://arxiv.org/abs/2604.12481)）把 T2I benchmark 的边界明显拓宽了：
- **核心机制**：不再只测“某类人出现比例是否均衡”，而是用 **13 个指标** 同时审计 demographic bias、元素遗漏、文化准确性与文化广度；
- **关键发现**：SD v1.5 在 Beauty prompt 上 White 占比 **74%**、Fair skin 占比 **97%**、Bias Amplification **>1**，而 Gemini 虽缓解了部分 demographic 偏差，却仍出现明显 cultural collapse；
- **意义**：这说明未来的 T2I 安全基准不能只围绕 NSFW / jailbreak / AIGC detection 展开，还必须把**偏见与文化治理**纳入同一套可量化评测框架。

### 6.4 组合语义不安全：Benchmark 开始进入 Multi-Concept 风险区 (2026-04-20 新增)

**TwoHamsters**（[2604.15967](https://arxiv.org/abs/2604.15967)）把 T2I benchmark 又往前推进了一步：
- **核心机制**：不再只问“单个危险概念能否被拦住”，而是形式化 **MCCU（Multi-Concept Compositional Unsafety）**，研究“两个单独安全的概念组合后是否会产生不安全语义”；
- **关键结果**：在 **17.5k prompts / 5.8k 高风险场景 / 51 个概念对** 的基准上，FLUX 的 MCCU 成功率高达 **99.52%**，LLaVA-Guard 的 Recall 仅 **41.06%**，SD Safety Checker 近乎 **0.00**；
- **意义**：这说明未来 T2I 安全不能再把风险理解成“显式违禁词或显式 NSFW 图像”，而要把**组合语义关系**本身纳入 benchmark 与防御设计。

### 6.5 奖励模型偏置：评分函数本身正在成为安全治理对象 (2026-04-21 新增)

**Bias at the End of the Score**（[2604.13305](https://arxiv.org/abs/2604.13305)）把 T2I 评测的控制点进一步往上游推了一层：
- **核心机制**：不只比较生成结果，而是直接审计 reward models 在优化层和评分层是否稳定偏向特定 race / gender，并观察 reward-guided optimization 是否会诱发 demographic drift 与 hypersexualization；
- **关键结果**：PickScore 会让女性主体的 NSFW rate 平均增加 **19%**（男性仅 **7%**），ImageReward / HPS 会让非 White 主体向 White 的转移比例达到 **76.1% / 89.2%**；
- **意义**：这说明未来 T2I 安全不能只审计生成器，还必须审计**评分器是否中立**。如果 reward model 本身带偏，那么任何 best-of-N、RLHF-style optimization 或 post-filtering 都可能把偏见系统性放大。

### 6.6 公平性操作化：从 fairness claim 走向 threshold-level benchmark (2026-04-21 新增)

**Operationalizing Fairness in Text-to-Image Models**（[2604.16516](https://arxiv.org/abs/2604.16516)）则从综述和框架层面重写了 fairness benchmark 的验收逻辑：
- **核心机制**：把现有文献统一进 **Demographic Parity / Proportional Representation / Performance Parity** 三类目标，并提出 **Target Fairness vs Threshold Fairness** 区分；
- **关键结果**：作者梳理文献后指出，在职业分布对齐实验里，只有 **8/43** 个 occupations 落在现实统计的 **±5%** 容忍带内，而大量工作根本没有定义 acceptance threshold；
- **意义**：这说明 T2I fairness 研究下一步的关键不是再报更多 gap，而是把 fairness 变成**带容忍带、带不确定性、可做 pass/fail 判断**的部署级 benchmark。

### 6.7 推理时嵌入算术去偏：fairness 治理开始进入 inference-time control (2026-04-22 新增)

**Embedding Arithmetic for Fairer T2I Generation**（[2604.18167](https://arxiv.org/abs/2604.18167)）提供了一条和重训完全不同的公平性治理路线：

- **核心机制**：先在文本编码空间中估计 gender / race / age 等属性方向，再通过 embedding arithmetic 直接编辑 prompt representation，而不改模型权重；
- **关键指标**：论文重点报告 **H_g / H_r / CCS** 三类指标，分别刻画性别熵、种族熵与 cross-category consistency，用来衡量“去偏后是否只是把偏见换了一种形式藏起来”；
- **意义**：这说明 T2I fairness 开始从“训练一个更公平的模型”扩展到“在推理时做最小侵入控制”。对于 FLUX、SD3.5-Large 这类闭源或难以重训的主线模型，这条路线尤其现实。

### 6.8 增量归因与开放集生成器识别：AIGC attribution 开始贴近真实生态 (2026-04-22 新增)

**IncreFA**（[2604.17736](https://arxiv.org/abs/2604.17736)）把 T2I attribution 从静态闭集问题改写成持续演化问题：

- **核心机制**：随着新生成器不断出现，归因模型不能每来一个模型就从头训练；IncreFA 用 replay + fine-grained / coarse-grained constraints + open-set regularization 保持旧知识并接纳新模型；
- **基准贡献**：配套提出 **IABench**，同时报告 **Avg. Acc. / Auth. Acc. / Unseen Acc.**，把“已知生成器识别”和“未知生成器拒识”放到同一张成绩单上；
- **意义**：这说明 T2I benchmark 正从“闭集模型分类”转向“开放生态中的 attribution lifecycle management”。在真实平台里，这比单次闭集识别更接近治理需求。

### 6.9 目标声明式公平控制：从“研究者默认公平”转向“用户显式目标” (2026-04-27 新增)

**Target-Based Prompting**（[2604.21036](https://arxiv.org/abs/2604.21036)）把 fairness 治理推进到一个更贴近真实产品控制面的层级：

- **核心机制**：不再默认某个均匀分布就是“公平”，而是先由用户或场景声明目标分布 q，再把原始 prompt 扩展成多个 demographic-specific 子 prompt，并按目标比例分配生成预算；
- **关键结果**：在 **SD Realistic Vision v5.1** 上，平均 Alignment Error 从 **0.129** 压到 **0.030**；在 **SDXL Turbo** 上进一步压到 **0.013**，改善 **91.1%**；
- **意义**：这说明 T2I 公平性治理的关键变量开始从“如何训练一个更公平的模型”，转向“如何让公平目标可声明、可审计、可在推理时被稳定执行”。对实际平台来说，这种 **target-explicit control layer** 比抽象 fairness claim 更像可部署能力。

### 6.10 知识密集型 visual correctness：Benchmark 开始从“画得像”转向“画得对” (2026-04-28 新增)

**KVBench / KE-Check**（[2604.22302](https://arxiv.org/abs/2604.22302)）把 T2I benchmark 明确推进到知识可视化场景：

- **核心机制**：作者构建 **1800** 个双语教材级样本、**5158** 条 checklist，把图像 correctness 拆成实体、属性、空间关系、标签与推理结果等原子约束，并进一步提出 **KE-Check**，通过 knowledge elaboration + checklist-guided refinement 显式修正 violation；
- **关键结果**：在 Table 3 中，baseline 仅 **20.09 / 25.74**（中 / 英），而 **KE-Check** 提升到 **47.67 / 30.24**；自动评测与人工标注对齐达到 **80.26% accuracy、κ = 0.7447**；
- **意义**：这释放出一个很重要的新信号——T2I 安全评测正在从传统 NSFW / jailbreak / bias 指标，扩展到 **knowledge-intensive correctness**。这对后续多模态安全 benchmark 与教育/科研场景部署尤其关键。

### 6.11 工业模型野外数据集：真实部署分布开始反过来塑形 benchmark (2026-04-30 新增)

**GPT-Image-2 in the Wild**（[2604.25370](https://arxiv.org/abs/2604.25370)）把 T2I benchmark 明确往“真实分发链路”推了一步：

- **核心机制**：围绕 Twitter/X 首周公开贴文，构建 **10,217** 张高置信 GPT-image-2 图像数据集，并通过规则 + Playwright badge 检查恢复“真实部署里用户到底在怎么用模型”；
- **关键结果**：原始 image records **27,662** 条，最终 confirmed **10,217** 张；**53.7%** uncertain 页面样本带有 **Made with AI** badge；**33.2%** 内容属于文字/图文排版，且 **82.0%** 图像含可 OCR 文本；
- **意义**：这说明未来 T2I 评测不能只看实验室 prompt set，而必须把**平台传播、metadata 剥离、文本渲染主场景、重采样后的野外分布**纳入 benchmark 设计。对于工业界 prompt rewrite / safety evaluation，这类真实部署数据集比 clean lab benchmark 更接近最终落地问题。

### 6.12 verifier + 版式文本 benchmark：rewrite 三维评测底座开始成形 (2026-05-01 新增)

**Edit-R1**（[2604.27505](https://arxiv.org/abs/2604.27505)）、**CoBench**（[2604.25358](https://arxiv.org/abs/2604.25358)）与 **TextGround4M**（[2604.24459](https://arxiv.org/abs/2604.24459)）共同把 T2I benchmark 又往前推了一层：

- **核心机制**：`Edit-R1` 用 **Keep / Follow / Quality** 原则把复杂编辑任务重写成 verifier-style reward；`CoBench` 把 layout-guided generation 拆成 **Text-Alignment + Layout-Alignment + Unified Score**；`TextGround4M` 则把 **Prompt Coverage / Layout IoU / OCR 正确率** 拉进真实文本渲染终态；
- **关键结果**：Edit-R1 在内部 benchmark 上达到 **82.2%** verifier 准确率、在 EditRewardBench 上达到 **78.2%**；CoBench 对 **319,086** 张生成图像做 semantic-spatial 统一评测；TextGround4M 构建 **4.1M** 样本，并把 Easy 场景的 Prompt Coverage 从 **7.22** 提升到 **30.80**；
- **意义**：这对 T2I 安全尤其关键，因为输入侧 prompt rewrite 迟迟缺的不是“会不会重写”，而是**如何把风险下降、语义保持、终态执行性拆成可测维度**。这三篇论文共同说明，未来工业 rewrite benchmark 很可能要同时包含 **verifier taxonomy、harmonic aggregation、OCR-rich 终态 fidelity** 三层。

### 6.13 三维分列、加权与乘性联合：评测开始拒绝"单一总分" (2026-10-23 新增)

`HealBench`（[2610.27516](https://arxiv.org/abs/2610.27516)，AAAI'27）、`LogicVal`（[2610.24051](https://arxiv.org/abs/2610.24051)）与 `IMPLICIT-Bench`（[2609.24228](https://arxiv.org/abs/2609.24228)）从三个角度共同否定了"单一聚合分"的合法性：

- **HealBench：三维分列 + 目标维度 1:2:1 加权。** `Score = s_sem + 2·s_heal + s_qual`，论文明确说明加权不是为了让总分好看，而是"在诊断解释时**不掩埋失效的维度**"。同时给出一个极重要的对照：通用 scorer（PickScore / LAION Aesthetic / CLIPScore / HPSv3）在目标维度上的偏好排序准确率只有 **0.50–0.56**（近随机），而任务专属 scorer（THS）达 **0.8527**（τ 0.774）。**结论：通用一致性指标不能当目标维度的奖励。**
- **LogicVal：把指令遵循变成可判定问题。** prompt → ASP 约束（9 类 C1–C9 / 71 模板），图像 → 场景图，`clingo` 判 $\widehat S(I)\models C$，**布尔答案、无需参考图**。关键数据：单对象-属性 98%，复杂条件多对象关系 53%，单约束 84% → **多约束同时满足仅 20%**，UNSAT 识别仅 23%。工程细节中"**反空真条款**"（全称约束必须附"至少一个对象满足前件"）直接可迁移到"改写保真核验"，防止"该属性没出现所以没违规"的假通过。
- **IMPLICIT-Bench：乘性联合分取代加权和。** $S=100\cdot\mathrm{mean}[Y_i(1-b_i/5)]$，保真不通过则整项归零，天然惩罚过改；并**先报指标自身与人类的一致性**（Acc 0.8012 / τ 0.4487），再报模型分数。

**这条主线的业务含义**：三维评测（语义保持 / 安全提升 / 指令遵循损失）的正确形态是 **① 分维度报告（禁止只给总分）→ ② 目标维度加权 → ③ 联合分用乘性而非加性 → ④ 先报指标自身的人类一致性**。任何只给单点总分的评测报告应视为无效。

### 6.14 评测维度与指标

基于本项目论文收录，T2I 安全评测主要使用以下指标：

| 指标 | 用途 | 计算方式 |
|------|------|----------|
| **ASR（Attack Success Rate）** | 衡量越狱攻击效果 | 成功生成违禁图像的比例 |
| **FID（Fréchet Inception Distance）** | 衡量擦除后图像质量 | 擦除前后生成图像分布差异 |
| **CLIP Score** | 衡量文-图对齐度 | 生成图像与提示词的语义相似度 |
| **Nudenet Score** | NSFW 内容检测 | 专用 NSFW 分类器的评分 |
| **Preservation Rate** | 衡量无关概念保留 | 擦除后无关概念生成质量保留比例 |

### 6.15 从"模型评模型"到"验证发生了什么"：评测范式正在换底座 (2026-10-27 新增)

这周的三篇工作（ABACUS / EditJev / AdvFidelity）在三个不同任务上做了同一件事：**把"好不好"换成一个有外在锚的可复现量**，而它们共同否掉的东西也一致——**让一个模型去评价另一个模型的输出**。

**ABACUS**（[2610.28316](https://arxiv.org/abs/2610.28316)，CEA List，WACV 2027）是指令式图像编辑的 **judge-free** 评测基准 + 协议：

- **构造**：10,944 条指令 / 3,845 张 COCO 图（80 类，72 个 change 配对）；全景真值经**双检测器可删性审计**（原图 ≥1、非生成式 inpaint 后 =0）确认，每条样本两人复核 + 仲裁。
- **协议**：SAM3（presence-gated）分割 → 复合几何分（IoU×包含×尺度比×Hu 矩轮廓，带质心距离门控）+ **匈牙利一对一匹配** → 非生成式 inpaint 造干净图 → **RF-DETR/Co-DETR 双表决** → 极少数（约 6%）走约束式 VLM 是非题（只确认类别，不计数）。
- **评分是乘积**：`Score = CF × SC × OC`（数量保真 × 场景一致 × 原类保留）。**用均值时"什么都不做"的编辑器几乎追平最好的模型**；乘积直接把它踢出去。
- **关键数字**：与人类计数一致性 **0.82**（纯 VLM 0.55 / 单检测器 0.28）；跨 7 个编辑器 **σ=0.013**（纯 VLM σ=0.065）；七个 SOTA 编辑器 Overall **最高仅 0.31**（Seedream 4.0）；最致命消融是**去掉一对一匹配 0.82→0.36**。
- **一条评测纪律**：人工真值标"编辑图里实际有几个目标物"，**不是 prompt 里要求的 N**——否则等于奖励"鹦鹉学舌报出 N"的评测器。

**EditJev**（[2610.32635](https://arxiv.org/abs/2610.32635)，北大 + 清华）则从"选哪个编辑器"这一侧证明**排序优于分类**：MLLM 末 token 隐状态 → 定长偏好头，pairwise ranking 消融 4.6002 vs MSE 4.5545 vs MCQ 4.5491；路由开销 94 ms，端到端 56.90 s → 22.33 s（2.55×）。两个负结果值得记：**路由骨干 2B/4B/32B 得分 4.5898/4.6002/4.5898（32B 没有更好）**，**去掉图像输入只掉 0.029**。

**AdvFidelity**（[2610.29380](https://arxiv.org/abs/2610.29380)，阿里淘天 + 上交）的附录给出了一组**奖励指标审计**：在 1,000 组"内容相同、只差伪影"的配对上，正样本胜出率 **Aesthetic 95.60% / PickScore 83.30% / HPSv2 79.90%（但平均配对差分为负）/ ImageReward 48.20% / CLIPScore 40.30% / HPSv3 38.30%**。**HPSv3 在 61.7% 的配对上偏好带伪影的图。**

**共同的信号**：评测的技术门槛已经从"用没用 judge"变成"**judge 之外有没有一个可独立核验的锚**"。ABACUS 的锚是检测器共识 + 全景真值，EditJev 的锚是离线跑满候选后的相对偏好，AdvFidelity 的锚是"内容匹配重建"这一构造本身。

### 6.16 操作 × 目标二维分解 + 几何聚合：编辑任务的分数不该是一个标量 (2026-10-29 新增)

**MoI-Bench**（[2610.37599](https://arxiv.org/abs/2610.37599)，**UCL + 南京大学 + 香港理工大学 + 华东师范大学**）不是"又一个编辑 benchmark"，而是把"**编辑任务到底怎么判**"这件事工程化了。**它是目前对我们 I2I 改写 0/0% 缺口最直接可用的评测框架。**

**任务空间：Operation × Target 稀疏矩阵**
- **16 个操作单元 × 8 类目标**，只取**适用组合**（不是机械笛卡尔积：`Addition × Body & Limbs` 标 N/A，`Camera-view × Documents` 改写成透视矫正）；
- 五个操作组：**Generation / Local Editing（加删换调）/ Global Editing（风格化、背景、修复、视角）/ Understanding Editing（语义编辑、inpainting、outpainting）/ Reference Editing（单参考、底图+1、2–3 参考）**；
- 四组目标：General Objects（具体/抽象）、Animals、**Portraits（身体四肢/面部头发/服饰配件/多主体）**、Text & Documents；
- 最终 **64 子任务 / 1150 样本**，任务范围来自 **1000 人问卷**（最高频：人像修图、物体移除、照片修复、文字编辑）。

**四条可直接抄的评测纪律（这才是本文真正可迁移的部分）**：

1. **稀疏 rubric 立方体** $(o,t,c)$，每条目标人工标 **always / sample-dependent / N/A** 三态。文生图时三个 DP 判据全 N/A；物体编辑时 Identity 是 sample-dependent（只在输入含需保身份的人时适用）。
2. **条件先写后跑**：每题的"完整 / 部分 / 失败"三档条件**在看不到模型输出之前**构造好，且**问题与条件在所有被测模型与 judge 间共享**。这是防评测泄漏的关键。
3. **加权几何平均**聚合：$u_s = \prod_k v_{s,k}^{\widetilde{w}_{s,k}}$。理由原文是"**限制某一判据组的高分去补偿另一判据组的低分**"。⇒ **这正好命中我们三维评测（语义保持/安全提升/指令遵循）用加权求和时的作弊路径。**
4. **能力缺失记 0，不移除样本**：不支持的任务 $u_s=0$ 但**留在集合里**。生成专用模型因此落 Q1，作者明说"反映的是它是编辑 benchmark 的覆盖缺口，不是生成质量本身"。

**判据组**：IF（指令遵循）/ VQ（视觉质量）/ **DP（细节保持，含 Structure 与 Identity）**。Identity 显式检查**未被指令针对的人身份**，而"保持要求明确排除用户要求改的东西"（换发型要保人脸身份、不保原发型）。

**双 judge 数据（AB 评测最该看的一组）**：总分排名 **Spearman ρ = 0.968**；人类与模型分 **ρ = 0.904**；**但作者自己写明"档位一致性不算独立验证"，因为阈值是用跨 judge 一致性反向校准的**。⇒ **"两 judge 排序高度一致"是强证据，"两 judge 给出同样档位"不是。**

**一个反直觉结论**：Ovis-U1-3B 总分更高（0.66 vs 0.62），但 **DreamLite 的任务覆盖更高**（$C_{0.6}$：0.64 vs 0.59 / 0.42 vs 0.38）⇒ **"平均质量"与"过的任务数"必须一起看。**

**定性上区分了两种失败**：DreamLite 在"改成头像"指令下**保留了全身构图**（没听指令）；Ovis-U1 给出了要求取景**但改了人的外观**（听了指令没保身份）。**这正是 DP 两个子判据分别要抓的东西——也是我们做 I2I 改写时最需要分开度量的两件事。**

**空白**：三组判据里**没有"安全"**；多语言只是零散案例（中文书名翻译失败）；1150 样本 / 64 子任务密度不高（每子任务约 18 样本）；Deployability 只在两台特定机型上测。

### 6.17 编辑「改对了没有」的正例标准：人类 κ=0.77，模型上限 65% (2026-11-02 新增)

**V-CAPE**（[2610.38611](https://arxiv.org/abs/2610.38611)，**Amazon**）把指令式编辑的正确性验证形式化成 **AutoQA**：给定源图与编辑后图，判定变换是否保持视觉一致性。

**规模**：**40K 源—目标对 / 27K 唯一图像**。两个互补子集：

| 子集 | 规模 | 来源 | 用途 |
|---|---|---|---|
| **V-CAPE-R** | 20K（50/50 平衡） | 真实电商 sofa 类目 + 生成式编辑管线 | 真实性 |
| **V-CAPE-S** | 20K（50/50） | **ABO 3D 资产 + Blender 渲染**，19 个额外类目 | 可控性（主动构造姿态错 / 类目错 / instance 错三类负例） |

**标注强度（本文全部论证的地基）**：3 名独立标注者、多数表决、**5 轮对齐训练**、**Fleiss κ = 0.77** ⇒ **任务良定义，人类判得动。**

**主结果**：所有被测 VLM（4B–235B，开源 + 闭源）**accuracy 全部 < 65%**（实测近随机到 63.5%），F1 55–67%。**auto-prompt（IPC 迭代优化）只 +3–5 点，对最强模型边际趋零，部分情况无提升。**

**难度梯度（要件分档的正确依据）**：**粗粒度（几何失真 / 类目错误 / instance 错误）最强模型尚可恢复；细粒度（纹理 / 光照 / 背景 / 色彩·材质）全场接近随机。** ⇒ **不要按 Operation 分档（加/删/换/风格），要按"该要件是不是细粒度视觉属性"分档。**

**少样本 LoRA（每档训练集仅 11 / 55 / 110 条）**：

| 配置 | R-Acc | **R-F1** | S-Acc | S-F1 |
|---|---|---|---|---|
| Qwen3-8B 零样本 | .515 | **.067** | .484 | .079 |
| + N=1（11 条） | .521 | **.601** | .532 | .624 |
| + N=5（55 条） | **.529** | **.628** | **.551** | **.683** |
| + N=10（110 条） | .527 | .617 | .543 | .681 |

四个读数：① **零样本 accuracy 51.5% 但 F1 6.7%** ⇒ **退化成全判一类**，只看 accuracy 会读成"接近随机但还行"；② **11 条样本把 F1 从 6.7 拉到 60.1** ⇒ 增益绝大部分来自**恢复类别先验**而非恢复细粒度感知（**本篇推论，论文未做此消融**）；③ **N=5 最好、N=10 反降** ⇒ **"补数据"不是单调收益**，不同缺陷类型的准则会互相冲突；④ **V-CAPE-S 一致高于 V-CAPE-R**（F1 差 5.5 点）⇒ **用合成数据训图审会高估真实表现**，few-shot 下偏差最大。

**结构化拒绝理由分类学（可直接移植到 I2I 分流输出）**：

| 子集 | 拒绝理由 |
|---|---|
| V-CAPE-R（6+1） | 几何失真 · 姿态错误 · 无关物体 · 背景不一致 · 纹理偏差 · 颜色/材质偏差 ·（accept） |
| V-CAPE-S（3+1） | 姿态错误 · 类目错误 · instance 错误 ·（accept） |

⇒ **把分流输出从"改写/不改写"二分改成这 7 类，0/0% 立刻变 7 个数，且能看出责任归属**（几何/姿态/纹理/材质/背景 = 下游编辑能力；意图未实现/意图被抹掉 = 改写侧）。

⚠️ 局限：只做一类变换（lifestyle→studio）、一个产品类目（sofa）；负例是构造的不是模型自然犯的；**结构化拒绝理由的判定准确率没有单独报**；单轮单指令；无 judge 间一致性数据。

### 6.18 「先扣分再打分」：把聚合顺序反过来，整体分就不再吃掉局部缺失 (2026-11-03 新增)

**WeGenEditBench + WeGenEvoStudio**（[2610.41210](https://arxiv.org/abs/2610.41210)，**腾讯微信视觉（WeChat Vision, Tencent Inc.）+ 中山大学**，58 页）是本轮唯一一篇同行同场景的工业界工作，评的模型名单里直接包含 `HunyuanImage-3.0-Instruct-Distil-CoT`、`GPT-Image-2`、`Seedream-5.0-Pro`、`Qwen-Image-Edit-2511`、`FLUX.2 [dev]`。

**病症命名：high-score paradox**——*"visual plausibility or success on a single salient edit does not establish that all coupled requirements have been jointly satisfied"*。四个耦合要求满足三个，整体分可以很高，缺的那个看不见。

**做法：把判定单位从"维度"下沉到"原子要件"，并且先把顺序反过来。**

```
每个输出 → 逐条判 applicable 原子要件（pass/fail + 视觉证据理由）
        → 不适用项排除出分母（不记 0）
        → 汇总成 EG（Edit Goal）/ PR（Preservation）/ VQ（Visual Quality）/ DS（Domain-specific）
        → 最后加权成 Overall
```

**三条容易被忽略的纪律**：

1. **checklist 预生成 + 跨模型共享**——同一道题所有被评模型用同一张表，排除"judge 看模型下菜"。这是它能跨 15 个配置比较的前提。
2. **"一侧通过"= 每一条适用要件都过**：*"A side passes only if every applicable item scores ≥ τ; **empty image-side lists are not successes**."* ⇒ **空输出不算成功**，堵掉"什么都不交被当成没有违反要求"。
3. **"高分输出"与"严重项"分开统计**——不只看均值，还看"整体分很高但存在严重单项"的比例，这才是高分悖论的量化。

**规模**：2,740 instance / **148** 任务类型（单图 / 文字密集 / 多参考）/ 15 个配置；审计覆盖 **15,214** 条 model–task 与 **194,836** 条 item 记录；**262** 条不适用项被排除；文字编辑同题对比用**同一批 920 个任务**；每 benchmark **随机 10%** 由 **3 名受训专家**审。

**单图编辑主表（这张表本身就是"聚合翻结论"的现成证据）**：

| 模型 | EG | PR | VQ | DS | **Overall** |
|---|---|---|---|---|---|
| GPT-Image-2 | **4.298** | 4.049 | **4.463** | 4.182 | **4.076** |
| Seedream-5.0-Pro | 4.207 | **4.084** | 4.434 | **4.206** | 4.029 |
| Nano-Banana-Pro | 4.159 | 3.752 | 4.370 | 4.050 | 3.882 |
| HunyuanImage-3.0-Instruct-Distil-CoT | 4.071 | 4.065 | 4.265 | 4.008 | 3.862 |
| HunyuanImage-3.0-Instruct-Distil | 4.020 | **4.175（全场第一）** | 4.280 | 3.952 | 3.841（第五） |
| Qwen-Image-3.0 | 4.120 | 3.469 | 4.331 | 4.126 | 3.813 |
| Qwen-Image-Edit-2511 | 3.963 | 3.567 | 4.095 | 3.708 | 3.588 |
| FLUX.2 [dev] | 1.964 | 3.418 | 3.555 | 2.154 | 1.967 |

⇒ **"不该动的没动"做到全场第一的模型（PR 4.175，高于 Overall 冠军的 4.049），整体排第五。** Qwen-Image-3.0 的 EG（4.120）高于两个混元版本（4.020 / 4.071），Overall 却更低（3.813 vs 3.841 / 3.862），因为 PR 只有 3.469（倒数第二）。**整体分把局部第一吃掉了。**

**版本管理与重评协议（可直接抄成全套回归看板的最小可信条件）**：

1. **先改 checklist，不是先改分数**；
2. 所有被比较模型在**同一份修订后 checklist**上重评受影响 case；
3. 每版本**同时冻结五项**：judge 模型、judge prompt、输入处理、checklist、无效响应策略。

| Qwen-Image-Edit-2511 | WeGenEditBench-Single | **+0.373（+13.2%）** | — | — |
| FLUX.2 [dev] | WeGenBench | **+0.230** | +0.124 | 1.85× |
| FLUX.2 [dev] | GEdit | **+3.944** | +3.009 | 1.31× |
| FLUX.2 [dev] | ImgEdit | **+1.362** | +1.269 | 1.07× |

⇒ **定向收益普遍是全量的 1.07–1.85 倍。只报全量会把定向干预稀释掉一半；只报定向会把"过拟合到诊断目标"藏起来。**

**跨维度权衡的硬证据**：Qwen 适配后 Overall +0.373，但同表内出现 **−0.128** 与 **−0.343** 两个子项跌幅；FLUX.2 的 Overall 从 1.083→3.517（+2.434），分维度增量跨度 **−0.343 ~ +4.524**。论文把这一节直接命名 *"Backbone-dependent adaptation and cross-dimensional trade-offs"* ⇒ **适配是换了一组能力，不是整体变强。**

**一条来自跨 benchmark 的观察**：FLUX.2 在五个 GEdit 类目上训 2,346 步后，**ΔSC（语义一致性）涨 3.7–5.7，而 ΔPQ（感知质量）只有 0.05–0.85**。⇒ **诊断驱动的数据合成能大幅拉起"做对没做对"，几乎动不了"好不好看"。**

**论文自述的边界（值得抄）**：*"The audit corrects identified problems but does not independently validate every judgment or quantify accuracy gains over holistic evaluation. **Inter-rater agreement and error rates cannot be inferred from this corrective audit.**"* ⇒ **10% 人工审计是质控动作，不是效度证据，出不了 κ。**

**并且它明确说**：*"The weights define an operational rubric."* ⇒ **权重是一份运营口径，不是客观真值。**

⚠️ **它不解决我们什么**：148 个任务类型全是"编辑做对了没"，**没有一条是"这个编辑请求该不该被执行"**。它解决下游能力那一半，不解决上游分流那一半。且 checklist 的生成过程正文被压缩（谁写的、多少条、校准到什么程度），要复用必须自己标定。成本口径也未给：194,836 item / 2,740 任务 / 15 配置 ⇒ **每配置每题约 4.7 条要件**，离线可接受、线上不可接受。

⇒ **对我们（I2I 0/0%）**：这是"可判的正例标准"的生成方式。把 0/0% 拆成「要件全没读出 / 部分读出 / 全读出但下游没执行 / 全读出且执行」四个数，**不需要训模型也不需要重做评测集**——在现有 1979 条上补一层要件即可。

## 7. 2026 新兴挑战：多模态与单流 Transformer

### 7.1 单流扩散 Transformer（DiT）带来的架构安全挑战

2024–2025 年，以 **Flux** 和 **Stable Diffusion 3.0** 为代表的**单流扩散 Transformer（Single-Stream DiT）** 开始取代传统 U-Net 扩散架构。这一架构变化给 T2I 安全研究带来了根本性挑战：

**架构差异**：

| 特性 | 传统 U-Net 扩散 | 单流 DiT（Flux/SD3） |
|------|----------------|---------------------|
| 特征提取 | 分离的 encoder/decoder | 统一的 Transformer 流 |
| 概念存储 | 分层存储，有明确的语义层 | 混合存储，难以定位 |
| 注意力机制 | 空间注意力为主 | 全局 + 局部联合注意力 |
| 擦除可行性 | ESD、UCE 等方法适用 | 需要专用方法 |

**Z-Erase**（[2603.25074](https://arxiv.org/abs/2603.25074)）是目前针对单流 DiT 的**第一个专用概念擦除方法**，在架构层面做出了以下适配：
- 利用单流架构中文本和图像特征**共享同一注意力空间**的特性
- 在联合注意力空间中定位有害概念的表示向量
- 通过针对 DiT 的梯度更新策略实现概念遗忘

**DTVI**（[2603.22041](https://arxiv.org/abs/2603.22041)）：
- 专门研究新型 T2I 架构的安全漏洞
- 发现单流 Transformer 相比 U-Net 在某些越狱场景下更脆弱

### 7.2 MLLM 引入的新 T2I 攻击面

**When Understanding Becomes a Risk: MLLM Safety**（[2603.24079](https://arxiv.org/abs/2603.24079)，CVPR 2026）：

核心论断：**多模态 LLM（MLLM）的图像理解能力本身就是一个安全漏洞**。

攻击机制：
1. MLLM 能理解图像中的隐含语义（如不完整的/模糊的 NSFW 图像）
2. MLLM 将这些隐含语义转化为文字描述
3. 该描述被用作 T2I 模型的 prompt，生成完整的 NSFW 图像

```
模糊/不完整的违规图像
    → MLLM 理解并描述图像语义
    → 描述文字 → T2I 模型
    → 完整违规图像生成
```

这意味着：当 MLLM 与 T2I 模型结合使用时，MLLM 的"帮助性理解"能力可以成为 T2I 安全过滤器的旁路。

**Janus**（[2603.21208](https://arxiv.org/abs/2603.21208)）：
- 提出了多模态安全的"双面神"问题——模型的多模态理解和生成能力是同一枚硬币的两面

### 7.2 T2I 模型生命周期安全（2026-03-30 新增）

本期出现了两篇关注 T2I 安全**全生命周期管理**的重要工作（均被 CVPR 2026 接收），标志着 T2I 安全研究从单纯的内容过滤走向更广泛的模型治理：

**Verify Claimed T2I Models via Boundary-Aware Prompt Optimization**（[2603.26328](https://arxiv.org/abs/2603.26328)，CVPR 2026 Findings）：

解决"T2I API 身份验证"问题——第三方平台可能谎称使用某知名 T2I 模型。BPO（边界感知提示优化）通过挖掘目标模型在**语义决策边界**处的独特行为，生成模型特异性验证提示，无需多参考模型即可完成高精度验证。

```
核心洞察：不同 T2I 模型在"语义边界区域"（概念过渡区）行为差异最大
→ 利用此差异生成"仅目标模型会不稳定响应"的验证提示
→ 验证准确率显著优于 4 种基线方法（5 个主流模型测试）
```

**SALMUBench: A Benchmark for Sensitive Association-Level Multimodal Unlearning**（[2603.26316](https://arxiv.org/abs/2603.26316)，CVPR 2026）：

首个针对多模态对比学习模型（CLIP 类）的**关联级遗忘**评测基准：
- 6 万条合成"人物-属性"敏感关联数据集
- 受损模型 vs 干净模型的双模型对照设置（精确隔离遗忘效果）
- 关键发现：现有遗忘方法均陷入"遗忘不足 vs 过度泛化"的二元困境

两篇论文共同指向 T2I 安全的新前沿方向：**模型可信度验证 + 知识可控遗忘**。



### 8.1 五大关键发现

**发现一：概念擦除方法均面临"擦除-保留 trade-off"且尚无最优解**

从 ESD 到 Z-Erase 的七年演进，核心张力始终未得到根本性解决：**擦除目标概念必然影响邻近无害概念**。SAEUron 和 CPE 代表了"精准手术"方向的最高成就，但其计算成本和对新架构的适配性仍是瓶颈。

**发现二：对抗鲁棒的概念擦除仍是开放问题**

RACE 和 Receler 等工作在已知攻击上获得了鲁棒性，但面对 DiffZOO、Reason2Attack 等新型攻击，擦除效果仍会退化。概念擦除和越狱攻击之间存在持续的军备竞赛。

**发现三：开源生态使所有服务端防御失效**

Stable Diffusion 完全开源意味着用户可以：(a) 使用未擦除的旧版本模型，(b) 对擦除后的模型进行再微调恢复有害能力。**模型参数级别的安全才是唯一根本性的解决方案**。

**发现四：单流 Transformer 架构的安全研究严重滞后**

Flux 和 SD3 已经成为 2025–2026 年的主流 T2I 架构，但截至本 Survey 写作时，针对该架构的安全研究论文仍极少（Z-Erase 和 DTVI 是先驱）。现有安全基准几乎全部基于 SD v1.5 和 SDXL，评估结果在新架构上的泛化性存疑。

**发现五：MLLM 理解能力带来的 T2I 旁路攻击是 2026 年最重要的新威胁**

论文 [2603.24079]（CVPR 2026）揭示的 MLLM-assisted T2I 旁路攻击，打破了"只需保护 T2I 模型本身"的假设。当 MLLM 和 T2I 模型在同一系统中协作时，安全边界需要重新划定。

### 8.2 三大研究空白

**空白一：单流 DiT 架构的系统性安全评估**

需要建立专门针对 Flux/SD3 架构的安全基准、越狱数据集和概念擦除方法，不能直接套用现有 U-Net 方法。

**空白二：开源模型再微调的安全稳定性**

类似于 T2T 的 Internal Safety Collapse，T2I 概念擦除后的模型在用户微调（LoRA fine-tuning）后安全性如何变化，目前研究几乎空白。

**空白三：视频生成（T2V）的安全研究**

本项目收录的 SAFREE 覆盖了 T2V，但整体而言，T2V 的越狱攻击和概念擦除研究远少于 T2I，而 Sora/Gen-3 等视频生成模型的普及使这一方向的重要性快速上升。

## 9. 未来方向

### 9.1 近期（1–2 年）

**A. Flux/SD3 安全专项研究**：建立针对单流 DiT 架构的完整安全评测体系，包括攻击方法、概念擦除技术和防御过滤器。

**B. 多模态安全边界重定义**：在 MLLM + T2I 协作系统中，建立跨模态的安全评估框架，解决 MLLM 理解能力带来的 T2I 旁路问题。

**C. LoRA 微调后的安全保持**：研究如何在允许用户 LoRA 微调的同时，保证安全对齐特性不被破坏（可参考 T2T 的双目标优化对齐思路）。

### 9.2 中期（3–5 年）

**D. 生成内容的可验证归属体系**：建立从水印嵌入到法律认可的完整内容归属技术链，与版权法规对接（Stable Signature 是技术先驱，但法律框架尚不成熟）。

**E. 统一多模态安全框架**：覆盖 T2I、T2V、I2I、MLLM 的统一安全评估框架，支持跨模态攻击的一体化检测和防御。

### 9.3 长期（5+ 年）

**F. 生成式 AI 伦理合规的技术保障**：随着生成式 AI 进入广泛的社会应用场景，技术安全研究需要与法律、伦理、监管框架紧密结合，构建"技术合规即服务（Compliance as a Service）"的基础设施。
